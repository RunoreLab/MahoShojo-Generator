# AI 输出格式异常（缺字段/夹带解释/校验失败）

> 作者：[Colanns](https://github.com/colasama) / [末伏之夜](https://github.com/notuhao)  
> 更新时间：2026-02-03

有时生成不会直接报“服务器错误”，而是表现为：**生成完成了，但结果无法被系统解析/校验**，于是你会看到类似：

- `魔法少女格式验证失败: ...`
- `残兽格式验证失败: ...`
- `情景格式验证失败: ...`
- `JSON 解析失败` / `Unexpected token ...`
- `未能识别 MAHOSHOJO_*_META 块（marker 缺失或格式不匹配）`

这通常意味着：**模型输出没有严格遵循我们需要的结构**（例如多写了说明文字、漏了必填字段、或 JSON 不完整）。  
这不一定是你输入“错了”，更多是模型在当次生成里“没按格式来”。

## 常见原因

- **输出夹带解释**：比如“下面是 JSON：……”再跟一段 JSON，导致解析失败
- **输出被截断**：内容过长/超时/波动导致只生成了半截
- **缺字段/类型不对**：必填字段缺失，或数组/字符串写成了别的类型
- **语言/格式跑偏**：你选了不稳定的模型或高峰期波动，模型遵循格式能力下降

## 自救建议（按优先顺序）

1. **直接重试 1～2 次**：格式跑偏经常是偶发
2. **缩短输入与目标**：把一次要生成的东西拆成几步；减少超长设定/要求
3. **避免“让 AI 解释它做了什么”**：解释性文字会增加结构出错概率
4. **更换模型/供应商（若使用自备通道）**：优先选择“结构化输出更稳定”的模型
5. **如果你是手动导入/粘贴 JSON**：确认只粘贴纯 JSON，去掉代码块标记与多余文字（另见：`/encyclopedia/data-card-errors`）

## 关于 MAHOSHOJO_*_META（角色更新元数据）

在部分页面（例如战报/竞技场）里，系统会让 AI 在正文末尾追加一个 `MAHOSHOJO_*_META` 块，用于“角色更新/历战记录/当前状态摘要”等结构化信息。  
当你看到 `未能识别 MAHOSHOJO_*_META 块`，通常意味着：**正文可能已经生成成功，但元数据块没按约定格式输出，或被截断/未闭合**。

你可以尝试：

1. **先确认正文是否正常**：如果战报正文完整，问题一般只影响“角色更新”部分，不影响阅读。
2. **若诊断显示“解析成功”但角色未写入，点“重试角色更新”**：系统会用同一场战报在服务器冻结的元数据重新对账，不会再次调用 AI，也不会重复消耗生成冷却。
3. **在提示词里明确约束最后一行格式**（如果你在自定义提示词/情景卡里改过输出要求）：  
   - 建议要求：最后一行输出 `<!-- MAHOSHOJO_ARENA_META { ... } -->`（并确保 `-->` 闭合）。
4. **若诊断显示“解析失败”**：重新生成战报；也可换模型/供应商（结构化输出能力差异很大），或缩短一次生成的内容量避免截断。
5. **需要收集更多线索**：若是流式战报，可加 `?debugSse=1` 重试，然后在控制台查看是否下发了 `meta` / `meta_error`（以及 `phase: "meta_start"`）相关调试事件。

## 与“AI 拒答”有什么区别？

- **拒答**：输出出现「身为语言模型…」「安全策略…」等模板语（见：`/encyclopedia/ai-refusal`）
- **格式异常**：输出看起来像正常内容，但结构不合格/被截断，导致校验失败（本页）
- **空对象/空白**：输出几乎没有信息（`{}` / `[]` / 空白），见：`/encyclopedia/ai-empty-output`
