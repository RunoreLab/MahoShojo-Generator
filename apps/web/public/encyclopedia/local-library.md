# 本地库：属于你自己这台设备的数据

> 作者：MahoShojo Generator 管理组  
> 更新时间：2026-09-30  
> 适用版本：v0.10.0+

本地库是**保存在你自己浏览器里**的一份数据，不需要登录，不会上传，也不会跟着账号走。

它现在装两种东西：

- **数据卡**：你在站内看到的任何一张卡，都可以复制一份到本地库
- **Web 包**：你导入的本地 ZIP Web 包，也可以保存在本地库

---

## 1. 三条必须先知道的边界

这三条是硬边界，不是可以绕过的设置：

1. **只在这台设备上。** 换电脑、换浏览器、换一个浏览器配置文件，都看不到本地库里的东西。
2. **不会跨设备同步。** 登录同一个账号也不会把本地库同步过去——账号同步的是云端数据卡，不是本地库。
3. **清除本站数据会一并删除它。** 浏览器「清除缓存 / 站点数据」、隐私模式窗口关闭、无痕窗口退出，都可能让本地库消失。

> ⚠️ 如果某张卡**只**存在于本地库，清掉站点数据就找不回来了。本地库**没有整库备份功能**（见 §6）。

---

## 2. 在哪里能看到它

所有**数据卡选择弹窗**里都有一个「本地库」页签，和「我的」「公开库」并列：

- `/arena`（和旧入口 `/battle`）选择参战者
- `/details`、`/canshou`、`/creator` 选择角色或情景
- `/sublimation` 选择升华对象
- `/character-party` 组队、`/pvp` 对局、`/magic-tea-party` 选卡
- 竞技场内的历史战报、问卷面板

本地库页签的右上角会显示库里的总数，页签上方还有一行**存储状态提示**（见 §5）。

Web 包的选择入口不在这个弹窗里，而是在竞技场的「Web 包」区块 →「选择 Web 包」→「本地库」页签。

---

## 3. 怎么把东西放进去

一共三个入口，任选其一：

### 3.1 从数据卡详情弹窗「存到本地库」

选中任意一张数据卡 → 打开**详情** → 「存到本地库」。这会把卡的正文复制一份到本机，**不会影响线上那张卡**。

这是最明确、最可控的方式：你想存哪张就存哪张。

### 3.2 导入时勾选「同时保存到本地库」

数据卡和 Web 包各有一个**「同时保存到本地库」**的勾选框，出现在导入区域里。

这是一个**设备偏好**：一旦勾选，之后在这台设备上导入的内容都会自动存进本地库，不需要每次再勾。取消勾选同样随时可用——即使本地库当前不可用，这个偏好也还能改。

> 默认是**不勾选**的。也就是说，普通导入默认仍然只上传到云端，不会自动往本地库里塞东西。

### 3.3 竞技场分队上传处的同一个偏好

在竞技场上传参战者时，也会看到「同时保存到本地库」。勾选后本次上传的内容会一并落到本地库，并回显新增 / 更新的张数。

---

## 4. 去重：内容相同就更新原卡

本地库用**卡正文的摘要**判断「是不是同一张卡」：

- 只改标题、改签名、改简介——**都算同一张卡**，不会堆出一堆近似重复项
- 命中已有记录时**整卡替换**，不会做字段级合并（合并会产生你没写过的第三态）
- Web 包用包的摘要（canonical manifest 的 SHA-256）作为身份，同一个包重复导入也只会更新原记录

一旦本地库开始堆积「似曾相识」的条目，你就再也分不清哪条是真的——所以这里刻意选择「宁可更新，不要新增」。

---

## 5. 存储状态与空间占用

本地库页签上方会显示三件事：

| 显示 | 含义 | 该做什么 |
| --- | --- | --- |
| 已获得持久化存储 | 浏览器在空间紧张时通常不会自动清理它 | 正常 |
| 尚未获得持久化存储 | 空间紧张时浏览器**可能**清理它 | 点「申请持久化存储」 |
| 浏览器无法提供空间估计 | 当前环境不支持 `StorageManager` | 本地库仍然可用，只是看不到占用 |
| 存储状态未知 | 既没拿到也没拒绝 | 一般刷新一次即可 |

持久化存储**被拒绝也不影响本地库可用**——它只影响「被自动清理的风险」这一句话的措辞强度。

后面还会跟一个 `已用 / 配额` 的读数。注意这是**浏览器给整个站点**的配额，不是本地库独占的额度。

## 6. 删除与导出

### 删除

本地库卡片上的**「删除」**是独立于「取消选择」的不可逆操作，会先弹一次确认，并说清：

- 只从这台设备移除
- 不影响任何线上数据卡
- 不会同步到其他设备
- 删除后如需再次使用，需要重新导入该文件

Web 包的删除还会一并清掉它的会话暂存、同源授权记录和陈旧引用。删除后**引用了这个包的历史战报会退化为纯文本结果**，无法再原样重放。

> 目前本地库**没有回收站**。删掉就是删掉了。真要留退路，请先导出。

### 导出

本地库卡片上的**「导出」**会把这张卡的 JSON 存成一个文件（`<卡名>.json`），这是**单卡导出**。

⚠️ **这不是整库备份。** 目前站点**没有**提供「把整个本地库打包导出 / 从备份恢复」的功能。把单张卡的 JSON 留一份，是你目前唯一的退路。

## 7. 它和别的数据的关系

| | 存放位置 | 需要登录 | 参与严格排位 | 进入多人房间共享配置 |
| --- | --- | --- | --- | --- |
| 云端数据卡 | 服务器 | 是 | 是 | 是 |
| **本地库数据卡** | 你的浏览器 | 否 | **否** | **否** |
| Web 包（本地） | 你的浏览器 | 否 | — | **否** |

本地库里的卡**不参与严格排位**，也不会被带进多人房间共享给其他成员——它是设备自有数据，不能冒充服务器权威实体。

在多人房间里，本地库页签**不会**出现；Web 包也只支持内置预设，本地 ZIP 不能进入房间配置。

## 8. 遇到问题

| 现象 | 说明与处理 |
| --- | --- |
| 本地库页签显示 `—` 或读不出内容 | 顶部会有红色提示条和「重试」按钮；先重试，再检查浏览器是否允许本站使用本地存储 |
| 提示「本地库仅支持在浏览器端使用」 | 某些环境（如禁用脚本的 WebView）无法使用，这是预期行为 |
| 提示「无法打开本地库数据库」 | 可能是隐私模式或存储被禁用；这种情况下本地导入只对**本次会话**有效 |
| 提示「本地库数据库被其他标签页占用」 | 关闭本站的其它标签页后重试 |
| 保存时提示「可能超出浏览器存储配额」 | 空间确实不够了。删掉不再需要的条目，或先申请持久化存储；Web 包通常比数据卡占得多得多 |
| 找不到刚才导入的 Web 包 | 导入**默认不落盘**，只对本次会话有效且会标注「仅本次会话」；想留下来就勾选「导入时保存到本地库」后重新导入 |
| 换设备后本地库空了 | 符合预期。本地库不跨设备，也不随账号同步 |

更一般的排障顺序见：`/encyclopedia/troubleshooting-faq`

---

## 9. 目前还没做的

写清楚比事后误解好。以下是**尚未实现**、不要按已支持来规划的：

- **整库导出 / 备份 / 恢复**（`LIB-007`）。底层契约已经具备，但打包、覆盖前备份、恢复冲突策略都还没做。半成品的导出比没有导出更危险——用户会以为有备份。
- **本地库回收站**。仓储层已经支持软删后的恢复，但界面上没有恢复入口，删除即删除。
- **Installed APP（桌面/移动端 SQLite 存储）**（`LIB-004`）。
