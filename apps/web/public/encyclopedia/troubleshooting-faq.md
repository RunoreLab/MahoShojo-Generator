## 30 秒症状速查

| 看到的现象 | 先做什么 |
| --- | --- |
| 第一次下载成功，连续下载后面的文件没反应 | 检查浏览器是否拦截了本站的“自动下载/多个文件下载”，见下方“浏览器下载与复制”。 |
| 点击复制提示失败，或剪贴板没有内容 | 确认当前页面有安全连接并允许剪贴板权限；仍失败时手动选中文本复制。 |
| 刷新、换浏览器或换电脑后本地记录不见了 | 先不要清除网站数据；确认使用的是原来的浏览器和站点，再查找导出文件或备份。 |
| 显示“正在恢复同一场战报生成”或“正在重新连接” | 不要再次点击生成，先等待当前服务器任务恢复。 |
| Web 战报空白、按钮失效或外部图片不显示 | 先重新加载 Web 战报，再切换到普通战报查看最终内容。 |
| PVP 一直停在 resolving/advancing，或房间没有进展 | 刷新；房主可使用“强制重试”；仍无变化时退出并重新进入房间。 |
| 看到 `Failed to fetch`、429、5xx、AI 输出或数据卡错误 | 直接查看本文末尾的专题入口，不要在同一个页面反复提交。 |

## 先做这些安全排查

按下面的顺序操作，通常不会破坏本地会话：

1. 普通刷新一次，确认问题是否只是短暂的网络或页面状态异常。
2. 页面显示旧样式、按钮错位或更新后行为异常时，再做一次强制刷新。
3. 用无痕窗口或另一浏览器测试一次，用来区分缓存、扩展和浏览器权限问题。无痕窗口只适合诊断，不适合保存长期会话。
4. 记录完整提示文字、出现时间和当前路由；不要只写“坏了”或连续点击同一个按钮。
5. 涉及本地记录时，先导出或备份，再考虑清理任何网站数据。

**不要把“清缓存/清除网站数据”当作万能修复。** 普通缓存和网站数据不是一回事；清除网站数据可能删除当前浏览器保存的 IndexedDB、Local Storage 或会话。除非已经确认本地数据不需要保留，否则不要把它作为第一步。

## 浏览器下载与复制

### 为什么只能连续下载一个文件？

如果表现为“第一个文件能下载，随后点击其他文件没有反应，刷新后又能下载一个”，最可能是浏览器的连续下载保护，而不是页面只允许下载一次。

请检查地址栏附近的下载提示或站点权限，将本站允许“自动下载”或“多个文件下载”。不同浏览器的名称可能不同；允许后重新点击各个下载按钮即可。若仍不行，再用无痕窗口测试，并暂时排除下载管理器、隐私扩展或企业浏览器策略的影响。

预设角色、在线数据卡和“修正版 JSON”可能使用不同的下载方式，但它们都仍受浏览器下载权限影响。请先确认浏览器没有拦截，再反馈具体是哪个页面、哪个按钮和哪一个文件失败。

### 为什么复制 JSON、房间链接或提示词失败？

复制功能会受到浏览器剪贴板权限、安全连接、当前页面焦点以及扩展程序的影响。可以依次尝试：

1. 直接在用户手势中再次点击复制按钮，并检查地址栏的剪贴板权限。
2. 暂停可能接管剪贴板的扩展，或在无痕窗口中测试。
3. 如果仍然失败，使用页面提供的文本区域或详情面板，手动全选后复制。

复制失败不等于内容已经丢失；反馈时请说明是复制后剪贴板为空，还是浏览器明确提示被拒绝。

## 本地数据、刷新与“清缓存”

### 哪些数据只在当前浏览器里？

服务器数据和浏览器本地数据要分开看：

- 连续战报会话保存在当前浏览器的 IndexedDB 中；详细边界见：`/encyclopedia/continuous-battle-story`
- 魔法茶会的会话与草稿也有本地保存内容，使用前应先导出；详细排查见：`/encyclopedia/magic-tea-party-troubleshooting`
- 当前浏览器的本地数据不会因为登录而自动同步到另一台电脑、另一个浏览器或另一个站点来源。

因此，换设备后看不到本地会话不一定表示服务器数据损坏；也可能只是没有迁移本地导出文件。隐私模式关闭后，本地数据也可能被浏览器清理。

### 刷新后内容不见了怎么办？

先确认：

- 是否回到了原来的站点地址、账号和浏览器配置；
- 是否刚刚清理过网站数据、关闭过隐私窗口或更换过浏览器；
- 是否有之前导出的 Markdown、JSON、ZIP 或其他备份。

如果数据仍在服务器侧，刷新通常不会删除它；如果是本地会话，优先从导出文件恢复，不要反复刷新或清理数据。连续战报的导出和恢复说明见：`/encyclopedia/continuous-battle-story`。

## 竞技场一直“恢复”或“重新连接”

竞技场的生成任务由服务器负责。浏览器短暂断网时，连接可能中断，但服务器上的生成不一定已经停止。

- **“正在恢复同一场战报生成”/“正在重新连接”**：正在寻找并接回原来的任务。不要再次点“生成”，避免创建重复任务。
- **“正在请求服务器停止生成”**：停止请求已经发出，先等待服务器确认。
- **“未能确认服务器已收到停止请求”**：停止结果未知，后台任务可能仍在运行；不要马上再次生成，稍后刷新确认状态。
- **“生成进程已丢失”/“连接恢复次数已耗尽”**：当前任务无法安全自动恢复。记录提示和时间，刷新后确认没有可恢复任务，再决定是否重试。

多人竞技场还涉及房间和提案状态。网络中断后的正确动作通常是等待重连，不要重复点击生成；详见：`/encyclopedia/arena-multiplayer`。普通网络连接错误则见：`/encyclopedia/network-errors`。

## Web 战报异常

Web 战报是在页面内受安全沙箱约束的 AI 生成 HTML。它和普通战报使用不同的显示路径，因此出现下面情况时不一定代表生成内容损坏：

- 生成页面依赖外部图片、字体、脚本或样式，但当前网络无法访问；
- 页面内的下载、新窗口或弹窗能力被浏览器沙箱限制；
- Web 战报加载后空白、卡住或样式异常。

建议按这个顺序处理：

1. 点击“重新加载 Web 战报”。
2. 仍然异常时切换到普通战报，先确认最终正文和结果是否完整。
3. 只有普通战报也失败，或错误提示明确指向生成/网络时，才按对应专题继续排查。

下载出来的 HTML 会脱离站内沙箱，外部资源仍可能需要联网；Web 页面在 iframe 内的临时交互进度不会自动保存，重新加载会重置该页面状态。

## PVP 或房间卡住

### 一直停在 resolving/advancing 怎么办？

先刷新页面一次。房主可以点击“强制重试”；如果仍长时间没有变化，退出房间后重新进入。不要连续点击推进、结算或生成按钮，以免把短暂延迟变成重复请求。

如果同时出现 Cloudflare 502/5xx，请先按：`/encyclopedia/cloudflare-errors`；明确是 524 超时则看：`/encyclopedia/cloudflare-524-timeout`。

### 为什么观战者没有“确认已阅读”按钮？

这是角色权限差异：该按钮只给需要推进流程的玩家，观战者不需要确认，也不能在当前 reviewing 阶段临时切换为玩家。等待下一回合，或请房主重新开始合适的流程即可。

## 明确错误应该看哪里？

如果错误文字已经明确，优先阅读对应专题：

- `Failed to fetch`、连接中断：`/encyclopedia/network-errors`
- Cloudflare 5xx、520/522/523：`/encyclopedia/cloudflare-errors`
- Cloudflare 524 超时：`/encyclopedia/cloudflare-524-timeout`
- 429 Too Many Requests：`/encyclopedia/rate-limit-429`
- AI 拒答、空输出、格式或生成失败：`/encyclopedia/ai-errors`
- 数据卡导入、解析、校验或签名：`/encyclopedia/data-card-errors`
- 魔法茶会登录、解析或本地会话：`/encyclopedia/magic-tea-party-troubleshooting`

## 仍未解决：反馈模板

请尽量一次提供以下信息，方便复现和区分浏览器问题：

```text
出现时间（含时区）：
页面/路由（例如 /arena、/pvp）：
浏览器及版本：
操作系统：
完整提示文字：
最短复现步骤：
无痕窗口或禁用扩展后是否仍复现：
供应商/模型（不要填写 API Key）：
安全的生成 ID/请求 ID（如果页面提供）：
截图或录屏：
```

反馈前请移除密码、API Key、Cookie、`Authorization` 请求头、私有数据卡内容和其他私人提示词。不要为了排查问题把凭据粘贴到工单、Issue 或聊天中。
