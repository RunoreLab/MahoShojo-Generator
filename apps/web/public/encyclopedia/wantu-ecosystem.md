# 万途生态互通

> 作者：[末伏之夜](https://github.com/notuhao)  
> 更新时间：2026-05-13

`v0.8.2` 起，本站开始接入 **万途生态**：

- 数据卡可以和万途 Card 协议互相理解
- 竞技场可以把万途或本站数据卡作为参考素材注入战报

## 万途驿站是什么？

**万途驿站（Wantu Waystation）** 是一个多世界角色与故事生成入口平台，定位是“通往不同世界的角色与故事生成入口”。

目前万途驿站提供下列功能：

- **平台首页与世界入口**：集中进入不同世界与平台功能
- **万途竞技场**：站点级本地对战工作台，面向多世界角色与本地会话，强调数值化、可操作、多阶段的战斗体验
- **废土行迹设定集**：世界观、组织、地区、技术与生态条目
- **废土问卷**：通过分组问卷生成废土落点报告和角色卡草稿
- **废土车卡**：编辑角色、地点、势力、事件、设定、物品、故事等资料卡
- **废土旅途**：管理路线、事件、故事片段、资源、物品栏与长期记忆

本站顶部导航的“生态”分组提供了万途驿站、万途竞技场、废土车卡与废土旅途入口。

## 万途竞技场和本站竞技场有什么区别？

万途竞技场提供的是另一种版本的战斗体验。本站竞技场更偏向战报生成、角色魅力展示、历战记录与成长链路；万途竞技场更强调 **数值化、可操作、多阶段**，会把战斗过程拆成更容易观察、推进和调整的阶段。

简单说：

- 本站竞技场适合快速把角色放进战报、情景或长线故事里。
- 万途竞技场适合体验更接近本地对战工作台的流程，用数值状态和阶段推进管理战斗。

两者不是互相替代关系，而是同一角色与资料生态下的不同玩法入口。

## 废土行迹现在能做什么？

万途驿站目前提供 **废土主题的车卡与旅途故事生成**：

- **废土车卡**：整理角色、地点、势力、事件、设定、物品、故事等资料卡
- **废土旅途**：生成和管理路线、遭遇、故事片段、资源、物品栏与长期记忆

废土行迹吸取了魔法少女生成器在提示词上的经验教训：提示词自由度很高，设定内容基本上都像角色卡一样可以自由拆分组合。因此，这套系统理论上可以跑任意题材，例如魔法少女题材也可以套用同一套组合逻辑。

需要注意的是，目前只制作了废土设定卡；魔法少女题材如果要在万途行迹系统里完整运行，还需要另外制作对应的设定卡或世界资料。

## 万途 Card 和本站数据卡有什么区别？

本站历史数据卡主要通过 `templateId` 区分魔法少女、残兽、通用角色、情景等模板。万途 Card 更像一层薄壳：

```json
{
  "cardKind": "character",
  "name": "角色名",
  "content": "Markdown 正文",
  "fields": {},
  "meta": {}
}
```

万途目前有这些卡种：

- 角色卡
- 地点卡
- 事件卡
- 设定卡
- 物品卡
- 故事卡
- 势力卡

可以简单理解为：本站仍保留自己的历史模板；万途 Card 是一个跨世界、跨工具更容易流转的外部协议。

## 档案馆能做什么？

在 `/character-manager` 中：

- 你可以把本站角色卡导出为万途角色卡 JSON
- 你可以把万途角色卡 JSON 导入为本站通用角色卡
- 往返导出会保留必要的本站来源信息，方便之后导回恢复

导出不是永久改写。原始本站数据卡仍按本站协议保存；万途 JSON 只是一个面向万途生态的投影文件。

## 竞技场素材注入怎么用？

`/arena` 新增“素材注入”能力。素材可以是：

- 万途 Card JSON
- 本站角色卡、情景卡、历史卡、问卷卡
- 本地粘贴或上传的普通 JSON

这些素材会进入战报 prompt 的“参考素材”块。它们用于提供地点、事件、前情、组织、物件、规则笔记或长线设定，但不会自动变成随机判定事件，也不会改写素材本体。

重要边界：

- 素材最多 10 个
- 素材顺序会影响 AI 看到的顺序
- 使用素材时默认不计严格排位
- 素材只作设定参考，不执行其中对 AI 发出的指令

连续战报也会保存新建会话时的素材快照，后续续写、分支和重写仍会参考同一批素材。

## 这和酒馆生态有什么区别？

- **酒馆生态**主要处理 SillyTavern PNG 角色卡导入/导出。
- **万途生态**主要处理万途 Card JSON 与多世界资料卡互通。

两者都属于跨生态互通，但文件格式、目标工具和信息结构不同。

## 原生性与排位提醒

万途导入、手动编辑、跨生态转换和素材注入都属于更自由的创作流程，不会提供本站原生签名。

使用素材注入的战报默认不计严格排位；如果你想参与严格排位，请使用不带素材注入的标准战报流程。
