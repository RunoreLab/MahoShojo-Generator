# 魔法茶会：错误排查与 FAQ

> 作者：[末伏之夜](https://github.com/notuhao)  
> 更新时间：2026-01-18

本条目汇总魔法茶会最常见的问题与自救步骤。  
如果你是第一次用茶会，建议先读：`/encyclopedia/magic-tea-party`。

## 1) 进不去 / 提示需要登录

魔法茶会仅对已登录用户开放：

- 前往 `/character-manager` 完成登录
- 登录后刷新 `/magic-tea-party`

如果已登录仍无法进入：

- 先尝试退出再重新登录
- 再尝试强制刷新页面
- 仍不行再反馈（附带截图与时间）

## 2) 提示“请先配置模型与 API Key” / “API Key 不能为空”

茶会仅支持自备 Key：

1) 左侧找到「自备 API Key（必填）」  
2) 选择供应商与模型  
3) 填写 API Key（注意不要带多余空格）

如果提示 `system` 被禁用：

- 这是正常行为：茶会不提供官方 Key 兜底，请改用自备 Key。

## 3) JSONL 模式输出不解析 / 变成一大段文本

优先按这个顺序排：

1) **换模型**：不同模型对“严格 JSONL”遵循度差异很大。  
2) **关掉合并输出计划**：先把“选项/摘要/更新草案”都设为 `off`，只让模型输出正文。  
3) **切到 Markdown 模式**：如果你主要写长文，Markdown 反而更稳。

如果你看到提示码 `jsonl_side_channel_parse_error`：

- 意味着模型输出了“疑似 summary/updates/notice 的行”，但格式解析失败，已被忽略。  
- 建议：先关闭合并输出计划，或让模型只输出严格 JSON（不要写 `summary text=...` 这种松散格式）。

## 4) 为什么“选项”不出现？

常见原因：

- 你在 **Markdown 模式**（Markdown 不保证稳定解析选项）
- 左侧关闭了「启用选项」
- 合并输出计划里“选项”被设为 `off`

自救：

- 切回 JSONL 模式
- 点击右侧输入框上方的「生成选项」按钮（手动生成）
- 或把合并输出计划的“选项”设为 `auto/on`

## 5) 触发敏感词 / 跳转逮捕页 / 输出被截断（blocked）

魔法茶会沿用站内安全机制：

- **输入阶段命中敏感词**：可能直接跳转 `/arrested`（并保存输入备份）
- **输出阶段命中敏感词**：当轮输出会被软拦截/截断，消息可能标记为 `blocked`

自救建议：

- 先把草稿复制到本地（避免丢稿）
- 用更中性的表达改写，再继续
- 配合屏蔽词降低误伤（见下方链接）

相关条目：

- 敏感词与逮捕：`/encyclopedia/sensitive-words`
- 屏蔽词（和谐替换）：`/encyclopedia/shield-words`

## 6) Token 预算提示变黄/变红，继续对话容易失败

茶会会估算“提示词总 Token”，当接近上限时会提示你：

优先做这些：

1) 生成/更新摘要（会话摘要面板）  
2) 减少角色数量 / 减少情景与世界书内容  
3) 降低“读取历战记录”的条数（不要开不限条数）

## 7) “角色更新”相关问题（草案为空 / 写入失败 / 写入后变非原生）

### 写入后为什么会变成“非原生”？

这是设计行为：茶会写入会移除 `signature`，并标记为非原生（因为内容已被改写过）。

### 点“生成更新草案”提示“请先开启写入…”

你需要在左侧「资料读写」开启：

- 写入历战记录 或 写入当前状态（至少开一个）

### 自动写入/撤销怎么用？

- 左侧「写入策略」设为“自动写入”时，生成草案后会自动写入，并生成可回滚快照。
- 在“会话摘要 → 角色更新”里可以执行“撤销上次自动写入”。

如果你想更稳：

- 写入策略先用“确认写入”（先看草案是否靠谱再写入）

## 8) 导入/导出相关问题

### 会话丢了怎么办？

茶会会话保存在浏览器本地，建议定期：

- 导出单会话 JSON
- 或导出全部会话归档（JSON/ZIP）

### 角色卡导入失败（PNG/JSON）

多数是格式或内容问题，建议先看：

- 数据卡问题：导入/解析/格式校验/签名：`/encyclopedia/data-card-errors`
- 酒馆生态联动（SillyTavern）：`/encyclopedia/tavern-ecosystem`

## 9) 为什么会看到“该条消息已被更新替换”？（分支/合并相关）

当你在茶会里使用了「编辑并分支」并「合并到原会话」时：

- 原会话从分支锚点开始的旧内容会被标记为“已被更新替换”（灰色提示）
- 分支内容会作为新的后续写回原会话

这是设计行为：用于保留“原时间线”供你回溯对比，不影响继续对话。

## 10) 立绘/缓存太大，浏览器变卡

在左侧「全局设置」里可以：

- 调整缓存上限（单会话/全局/空间）
- 一键“清理超限 / 清理过期 / 清空全部”

另外，会话清理也只影响本地数据：清理前建议先导出归档。
