# 魔法茶会：设置与参数说明

> 作者：[末伏之夜](https://github.com/notuhao)  
> 更新时间：2026-01-20

本条目解释魔法茶会里各类设置的含义与推荐用法：**输出模式/合并输出计划/选项/摘要/资料读写/写入策略**等。  
如果你只想快速开局，请先读：`/encyclopedia/magic-tea-party`。

## 1) 输出偏好（左侧：输出偏好）

### 你的称呼（`{{user}}`）

- 作用：决定提示词中“用户”的显示名（例如：旅人 / 记者 / 观众），会影响对白归属与叙事口吻。
- 建议：写一个**角色化**的称呼（≤20 字），能明显提升沉浸感。

### 输出模式：JSONL / Markdown

- **JSONL（推荐）**：模型按“旁白/对白/选项”分行输出，前端会解析为结构化片段，阅读与后续工具（选项/更新）更稳定。
- **Markdown**：模型输出更自由的正文，但不会稳定解析选项/角色分段；当“合并输出计划”设为**强制**时，会改为额外调用补生成（更耗 Token）。

什么时候用 Markdown？
- 你就是想写长文、随笔式叙事，不太在意“选项/更新草案”的结构化。
- 你的模型不擅长 JSON 输出，JSONL 经常跑格式。

### 合并输出计划（`outputPlan`：选项 / 摘要 / 更新草案）

**JSONL**：在一次生成里同时产出“正文 +（可选）choices +（可选）summary +（可选）updates”。  
**Markdown**：仅当设为 **on（强制）** 时，会在正文生成后改为**额外调用**补生成（成本更高）；`auto` 在 Markdown 下等同关闭。

每一项都有 3 个档位：

- `off`：关闭（需要时手动点按钮生成）
- `auto`：自动（模型判断“需要时”才输出）
- `on`：强制（每轮都输出）

推荐：
- 选项：`auto` 或 `off`
- 摘要：长线 `auto`，短线 `off`
- 更新草案：通常 `off`（确定要写入时再生成）

成本提醒：合并输出会让每轮输出更长、更贵；模型也更容易因输出过长导致格式漂移。

### 语言

- `zh-CN` / `ja-JP` / `en-US` 会影响系统提示词的输出语言要求。
- 角色卡与情景卡仍以你提供的文本为准（例如中文设定配中文输出更稳定）。

### 启用选项 & 选项数量

- **启用选项**：Markdown 下需要配合“合并输出计划 → 选项 = on”才会自动补生成；也可手动点“生成选项”。
- **选项数量**：2~16。数值越大：
  - 优点：可玩性强，更像视觉小说
  - 风险：更耗 Token，且选项文本容易变水或撞车

建议：默认 3~4，跑团/群像可以 5~6，别一上来拉满 16。

## 2) 资料读写（左侧：资料读写）

> 重要：茶会写入会移除签名并标记为**非原生卡**（这是设计行为，不是 bug）。

### 读取历战记录

- 作用：把角色卡的 `arena_history` 注入提示词，让角色“记得过去发生过什么”。
- 读取条数：
  - 越多越连贯，但越贵、越容易挤爆上下文
  - “不限条数”会显著增加 Token 压力，除非你确认模型窗口足够大且卡片很短

建议：先用 **3**，只有在明确需要长线继承时再加。

### 读取当前状态

- 作用：把角色卡的 `current_state` 注入提示词，适合维持“最近状态/关系/心情”的连续性。
- 建议：长线对话可开启；若你的卡没有 `current_state`，开启也不会报错。

### 写入历战记录 / 写入当前状态

- 作用：允许“角色更新”面板生成草案并写入到角色卡。
- 写入位置：
  - `arena_history`：新增一条 `type="tea-party"` 的历战记录（标题默认用会话标题），并写入本次影响（impact）。
  - `current_state`：写入 `summary`（状态摘要）与 `updated_at`（更新时间）。
- 重要：只要发生写入，系统会移除 `signature` 并将角色标记为**非原生**（这是设计行为）。

### 写入策略（`updateApplyMode`）

- **自动写入（auto）**：生成草案后自动写入，并生成可回滚快照（可在“角色更新”里撤销）。
- **确认写入（confirm）**：先生成草案 → 你确认无误后再点“确认写入”。
- **仅草案（draft）**：只生成并保留草案，不修改角色卡（适合先审稿或只当笔记）。

建议：先用“确认写入”，熟悉质量后再切“自动写入”。

## 3) 会话摘要（全局设置 + 会话摘要面板）

### 启用自动摘要（全局设置）

- 开启后：当上下文接近上限、或历史丢弃过多时，会自动触发摘要。
- 关闭后：只保留你手动点击“生成/更新摘要”的能力。

重要差异：

- **自动摘要**：会在生成摘要后，删除较早的历史消息（仅保留最近一段原文 + 摘要），以控制本地存储与上下文压力。  
  如果你想保留完整聊天记录：建议先导出会话，或关闭自动摘要。
- **手动摘要**：只写入摘要文本，不会自动删除历史消息。

### 会话摘要面板（手动）

- 「生成/更新摘要」：用当前对话生成一份摘要（会消耗额外 Token）。
- 「清空摘要」：删除摘要（不会影响历史消息）。
- 「结构化摘要」：用于侧信道/检索的分段摘要；它**不会自动**与正文摘要同步，需要你手工维护。

## 4) 角色更新（会话摘要 → 角色更新）

角色更新有两条路径：

1) **手动生成草案**：点击「生成更新草案」，可选择范围（最近 10/20/40/80 轮）。  
2) **合并输出 updates**：在输出偏好里把“更新草案”设为 `auto/on`。JSONL 会在同一轮输出末尾附带 updates；Markdown 仅 `on` 会改为额外调用补生成。

常见要点：

- 需要先开启写入（历战记录/当前状态至少一个）。
- 草案会先落在会话里（影子状态），你可以：
  - 在确认模式下点「确认写入」
  - 在自动模式下让系统自动写入
  - 或点「清空草案」直接丢弃
- 自动写入会生成快照，可「撤销上次自动写入」恢复到写入前状态。

## 5) 本地数据管理（全局设置 / 会话清理）

### 立绘缓存策略（全局设置）

立绘/插画会缓存到浏览器本地（IndexedDB）。你可以设置：

- 单会话缓存上限
- 全局缓存上限
- 空间占用上限（MB）

并随时执行：

- 清理超限（LRU）
- 清理过期
- 清空全部

### 会话清理

茶会会话与消息保存在本地。你可以设置：

- 保留天数
- 最多保留会话数

并预览/执行清理。清理前建议先导出归档。

## 6) 进阶：编辑导出会话 JSON（慎用）

茶会导出的会话 JSON 里包含一些高级字段（通常不需要改）：

- `temperature`
- `contextWindowTokens` / `responseReserveTokens`
- `maxContextMessages`
- `summaryTriggerRatio`（0.5~0.95）
- `summaryMaxTokens` / `summaryMinGapMessages`

这些字段主要用于“Token 预算提示”与自动摘要阈值。一般建议**保持默认**，只有在你明确知道模型上下文窗口、且希望更激进/更保守地摘要时再调整。
