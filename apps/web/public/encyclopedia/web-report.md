# Web 战报：让 AI 直接交一份可以点的战报

> 作者：MahoShojo Generator 管理组  
> 更新时间：2026-09-30  
> 适用版本：v0.10.0+

普通战报是一篇 Markdown 文章。**Web 战报**换了一种交付方式：AI 直接生成一份完整的 HTML 页面，可以有自定义排版、动画、图表、地图、小游戏，以及真的能点的交互。

它是实验性功能。Markdown 始终是默认且完整的路径——切到 Web 只是换一种呈现方式，不影响结算、计分、角色更新和历史存档。

---

## 1. 怎么打开

1) 进入 `/arena`（或旧入口 `/battle`）
2) 在「选择生成方式」旁边，把战报格式从 `Markdown` 切到 **`Web（实验性）`**
3) 像平常一样配好角色、模式、素材，然后生成

生成完成后，结果区会出现「显示方式」：**普通显示** / **Web 显示**。

- **普通显示**：战报卡片，正文、标题、表格、公式都在，适合阅读和保存图片
- **Web 显示**：在浏览器隔离框架里展示 AI 生成的网页，保留自定义排版和交互
- **沉浸显示**：整屏阅读，操作栏不再遮挡正文；退出后回到原来的位置

> 首次使用 Web 显示时会弹一次确认——这是必要的，页面里跑的确实是 AI 生成的 HTML。

---

## 2. 自由 Web 和 Web 包的区别

切到 Web 格式后，有两种做法：

| | 自由 Web（不选包） | Web 包 |
| --- | --- | --- |
| AI 生成什么 | 一份完整 HTML 页面 | **包指定的那一个数据文件** |
| 引擎和素材 | AI 现写 | 留在包里，不被替换 |
| 稳定性 | 每次重新发挥 | 结构由包和 schema 约束，稳定得多 |
| 适合 | 一次性尝鲜、简单互动 | 你已经有（或想做）一套自己的玩法 |

现在有一个**内置预设**「竞技场新闻」：包提供样式、素材和互动组件，AI 负责创作完整的新闻站，可以阅读报道、发表评论、体验模拟广告。

在「Web 包」区块 →「选择 Web 包」里可以看到全部内置预设，也能导入自己的本地 ZIP。玩法与创作细节见：`/encyclopedia/web-package-authoring`

## 3. 权限：受限模式与可选的同源授权

Web 包默认在**受限模式**下运行：包内的脚本、样式、模块、JSON 和素材都能正常工作，但它**拿不到**读取主站 DOM 和浏览器存储的同源权限。

绝大多数包在受限模式下就能正常工作。**拒绝同源授权不影响生成、历史查看和下载。**

如果你确实需要本站的同源能力，并且信任实际代码，可以在结果区点「授权本站同源权限…」：

- 必须先读过风险说明（至少三秒）才能确认
- 「仅允许本次结果」和「始终信任此包版本（仅本浏览器）」是分开的，后者默认不选
- 包的摘要、生成摘要、策略版本、风险类别、网络目的地或不确定性发生变化时，需要**重新确认**
- 随时可以「撤销信任并回到受限模式」

⚠️ **同源模式接近本站自身脚本权限。** 它可能访问本站存储和当前可读的凭据、操作你的账号功能、消耗额度、发送数据。撤销不会收回已经外传的信息或已经执行的操作。**不要把它当成更强的安全沙箱。**

## 4. 下载：三种文件不是一回事

| 按钮 | 下载的是什么 | 能不能离线重放 |
| --- | --- | --- |
| **下载生成目标** | AI 这一轮**原始产出**的那个文件 | 内容原样，但不是可运行的完整体验 |
| **下载 Web 包 ZIP** | **不可变的包本体**（引擎 + 素材），不含本场故事 | 可以重新导入后重放历史 |
| **下载 HTML** | 把包和本场数据合并后的单文件结果 | 直接双击能开，但**不再受站内沙箱保护** |

补充两点：

- 用隔离 URL 空间加载的包**不提供单文件 HTML 导出**，只有能成功物化的情况才会给「下载 HTML」
- 直接在浏览器打开下载下来的 HTML 时，外部资源可能仍需要联网；页面内的交互进度不会保存

## 5. 回看历史战报

结果区会按包的**精确版本**从你本机的缓存恢复。你会看到的是下面四种结果：

- **精确恢复**：本机还有这个版本，直接原样重放
- **版本不一致**：需要你显式选择用哪个兼容版本；历史记录里的原始包身份**不会被改写**
- **找不到包**：退化为纯文本结果。如果包曾经在你的本地库里，可以在结果区「重新导入本地 Web 包」
- **无法重放**：包在，但这一局对不上——可能是包声明的数据结构与这份故事数据不符、可用包的目标契约与历史战报不兼容，或历史生成内容的完整性校验没过。这时会说明是哪一种，并保留纯文本结果，不会强行渲染一个错的

> 「无法重放」不是可以靠反复点授权解决的那类问题：它发生在数据与包结构不匹配的地方，和运行权限无关。

> 删掉本地库里的包会导致引用它的历史战报无法原样重放。删除确认框里会提前说明这一点。

## 6. 当前兼容边界

本站采用**单文档物化**，支持经典脚本、ESM、动态 `import()`、相对 CSS / 媒体路径与包内 `fetch`。

以下形态**不保证工作**：

- 多 HTML 页面之间的跳转（没有页面导航）
- Worker / Service Worker
- 嵌套 iframe
- import map 的 scope 语义
- `eval`
- 任意动态 `innerHTML` / CSSOM 里再引用相对资源

写包时优先用**单文档 hash 路由 + 相对路径 + 浏览器就绪的构建产物**。遇到不支持的形态会给出诊断或渲染失败提示——**不要靠反复授予同源权限来「修」它**，那解决不了资源形态问题。

## 7. 生成失败了怎么办

Web 战报的失败会**说明是哪种失败**，因为两种的下一步动作完全不同：

| 提示 | 含义 | 该做什么 |
| --- | --- | --- |
| 格式不对 | 模型没按包的形态输出（输出了战报纯文本或包着包装的 JSON） | 多见于包作者的生成指引不足。换一个包，或改用普通战报格式 |
| 结构不对 | 输出是合法 JSON，但不符合包声明的结构 | 多见于 schema 约束不足。换一个包，或联系包作者补充 schema |

其他情况：

- 多人房间里的 Web 包失败**不会**被并入「稍后重试」——重试不会改变结果，会直接提示改用普通战报格式或换一个包
- 收到的内容会按纯文本保留，不会因为校验失败就整份丢失
- 如果失败发生在结束判定前，保留下来的 Markdown 正文和用量仍然可以查看

---

## 8. 多人房间里的 Web 战报

多人模式**只支持内置 Web 包预设**。本地 ZIP 包不可进入房间配置，也不提供本地库管理入口——成员的修改经过服务器安全投影与校验，本地文件和密钥不会进入房间。

单人模式下才可以导入本地 ZIP。
