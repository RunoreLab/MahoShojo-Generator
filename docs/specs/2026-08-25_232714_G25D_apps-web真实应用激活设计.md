# G25D `apps/web` 真实应用激活设计

状态：accepted
日期：2026-08-25
适用 Goal：G25D
source baseline：`45fee887`

## 1. Objective

行为等价地把 legacy root Next/OpenNext 应用迁入真实 `apps/web`，并在 Web、Hono API、D1 Gateway 都拥有独立 manifest 后，把仓库根收口为 workspace 编排、统一门禁和跨 runtime 数据工具层。

本设计只改变文件 ownership、工作目录与命令入口，不改变 Legacy/Better Auth 语义、API wire、Arena v1 authority/resume/replay 语义、D1 schema、生产数据、secret 或发布流量。`45fee887` 及此前 G25R abort/reconnect 修复必须原样随 Web source 搬迁。

## 2. 当前事实与范围重估

启动核对结果：

- 当前分支为 `refactor/platform-rearchitecture`，启动时 worktree clean；
- 不存在 `apps/web/package.json`，根 `package.json` 仍直接持有 Next/OpenNext runtime lifecycle 与 Web runtime dependencies；
- Web source/static/config/test 仍主要位于根 `app/`、`components/`、`lib/`、`public/`、`tests/` 等目录；
- `apps/api` 与 `apps/d1-gateway` 已是真实 workspace app；
- 当前 Hono inventory 为 `15 shared / 13 exited / 0 legacy`；
- G25R 永久日志之后又有 `477f6bbe`、`cc9112a4`、`45fee887` 三笔 abort/reconnect 修复，G25D 必须用 fresh regression 覆盖，不能仅引用旧日志。

按当前规模将实现拆为两个可独立 revert 的 checkpoint：

1. G25D-1：激活 `apps/web`，搬迁 source/static/config/test/script，保持 root compatibility command；
2. G25D-2：收口 root dependencies、workspace gates、CI 与文档。

预计 5–7 小时；如果完整 app ownership 无法在单次 Goal 内闭合，宁可把 root 最后的纯编排清理留为短 checkpoint，也不得留下半个可部署 Web app。本次用户要求完整 G25D，默认继续到 stopping condition。

**实施校正（2026-08-26）：** RED contract 形成独立提交 `39825c1f`。实际搬迁时确认，若把 source relocation
与 root manifest/CI cwd 收口拆成两个代码提交，任一中间态都会留下双 owner 或缺少可执行 lifecycle 的半应用，
反而不满足本设计的原子性。因此实现将上述 G25D-1/2 合并为单一可整体 revert 的代码 checkpoint

## 3. 适用强制约束

- `MONO-001`：root 最终只承担编排与统一工具；
- `MONO-002`：`apps/web` 自有 manifest、build、test、lint、env、deploy 与 readiness contract；
- `MONO-003..005`：不引入 app-to-app、package-to-app 或 deep internal import；
- `MONO-006`、`COMPAT-001/002`：结构搬迁必须用回归证明行为等价；
- `MONO-009`：删除 legacy root wrapper/source ownership，但保留 contract-tested Next/OpenNext DR adapter；
- 不改变客户端不可信、服务器权威、secret 隔离、D1/Redis ownership、Legacy/Better Auth compatibility、Arena v1 wire、非幂等 POST 不盲目重放等 accepted 保护性终点；
- 不激活自动 failover，不混入 local-library、Admin 或 UI 重构。

## 4. Ownership 决策

| Owner | 迁移后持有内容 | 说明 |
| --- | --- | --- |
| `apps/web` | `app/`、`components/`、`lib/`、`public/`、`styles/`、`types/`、middleware、Next/OpenNext/Wrangler/PostCSS/ESLint/TypeScript/Vitest 配置、Web tests、Web operational scripts、`env.example` | 完整 Next/OpenNext deployment unit；`@/*` 只指向 `apps/web/*` |
| repository root | workspace manifest、root orchestration manifest、boundary/naming gates、repo ownership/CI tests、`config/hono-api-routes.json`、`drizzle/`、`drizzle.config.ts` | route inventory 和 migration history 是跨 runtime contract/data tooling，不属于单一 app |
| `packages/*` | 既有 shared core/contract/runtime adapters | 不因目录搬迁改变 exports 或 authority |

`drizzle.config.ts` 继续在根执行，但 schema source 改为 `apps/web/lib/db/schema/**`；D1 Gateway 继续使用根 `drizzle/`。Web route manifest consumer 显式读取根 `config/hono-api-routes.json`，该依赖不是 app-to-app import。

## 5. 备选方案与结论

### 5.1 选定：完整物理搬迁 + root compatibility proxies

优点：单一 owner、可由 workspace gate 发现、OpenNext/Wrangler 从 app cwd 运行、root 不再持有 runtime dependency。根历史命令用 `pnpm --filter @mahoshojo/web` 代理，降低开发/CI 入口变化。

### 5.2 不选：root symlink 或双份 source

这会形成两个 owner、让测试和 deploy cwd 隐式分叉，也无法满足 `MONO-001/002` 与独立 revert 要求。

### 5.3 不选：把 route inventory 和 migration history 全部移入 Web

Hono API 与 D1 Gateway 都消费这些跨 runtime 事实；移入 Web 会制造 app-to-app ownership 或让 Web 成为数据 authority。它们应留在根的 contract/data tooling 层。

## 6. Behavior-equivalence contract

迁移前后必须保持：

- App Router route/component/static asset 集合只发生路径前缀变化，不改文件内容；
- `@/*` 从 root 变为 `apps/web/*` 后仍解析到同一 Web module；
- Next redirects、security headers、OpenNext compatibility、Wrangler bindings/routes/migrations directory 等价；
- Cloudflare build/deploy 从 `apps/web` cwd 执行；生产与 preview environment 名称及 bindings 不变；
- Legacy auth、Better Auth bridge/subrequest、D1 schema、Arena generation/resume/fault-injection contract 回归通过；
- Next DR adapter seam 与 Hono route inventory 保留，自动 failover 仍未启用；
- root compatibility commands 只代理到 workspace app，不重新声明 runtime ownership。

环境变量 canonical example 迁入 `apps/web/env.example`。CI 与 deploy 仍通过显式环境注入；本地显式 shell environment 不变。Next config 对 legacy root `.env*` 提供只读 fallback，便于未迁移的本地环境平滑过渡；`apps/web/.env*` 与显式环境优先，任何 secret 均不写入仓库。

## 7. Testing 与 no-new-regression

先增加会失败的 ownership contract，再实施搬迁。验证分层：

1. ownership/manifest/config/workflow contract；
2. Web targeted auth、Arena resume/adapter/fault-injection、route manifest；
3. `apps/web` test/lint/build/OpenNext Cloudflare build；
4. root repo tests、workspace boundary、naming no-new-regression、workspace verify、`ci:verify`；
5. independent architecture、security/authority、compatibility/replay/data、test-adequacy review；
6. 修复所有 Critical/Important，fresh re-run relevant/full gates。

已有 strict naming debt 按 no-new-regression 处理：迁入 `apps/web` 后不能因为 legacy root 目录消失而让 strict gate 虚假转绿；checker 必须继续扫描相同 Web source baseline。workspace-only 报告可随 ownership 路径改变，但不得新增 blocking finding。

## 8. Rollback 与影响

- `git revert fb8dd77e` 可整体恢复 root Web 与原 CI cwd；`39825c1f` 是先行 RED/权威契约，回滚整个 Goal 时再逆序 revert；
- 不执行 production deploy/cutover、remote DB migration/write/restore、Redis flush、secret/Access/credential 变更、release/tag 或 history rewrite；
- schema/wire/persistent data 均不改变，`drizzle/` migration contents 不修改；
- 本地/CI build artifact 可删除重建，不参与 rollback authority。
