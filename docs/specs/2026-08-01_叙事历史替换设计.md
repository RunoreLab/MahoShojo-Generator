# 角色管理页叙事历史替换设计

## 背景

角色管理页的数据卡列表已经为角色卡和情景卡提供“替换”入口，但叙事历史卡被 `DataCardsModal` 默认过滤掉了替换回调。叙事历史自身已有专用编辑器和替换提交逻辑，因此本次只补齐入口与路由，不新增另一套 JSON 编辑能力。

## 目标

- 在角色管理页的叙事历史数据卡上显示与其他卡片位置一致的“替换”按钮。
- 点击该按钮后打开现有叙事历史编辑弹窗，并绑定当前目标数据卡。
- 在弹窗中编辑标题或历史条目后，通过现有替换 API 完成敏感词检查、审核状态处理和列表刷新。
- 保持角色卡、情景卡、问卷卡现有替换行为不变。

## 设计

### 入口与数据流

1. 角色管理页向 `DataCardsModal` 开启 `allowHistoryReplace`。
2. `DataCardsModal` 对 `history` 卡提供现有 `DataCard` 的“替换”按钮。
3. 角色管理页的替换回调识别 `history` 类型，复用叙事历史卡加载逻辑，设置编辑草稿和目标卡信息，并关闭数据卡列表。
4. `NarrativeHistoryCardEditorModal` 编辑并归一化 payload 后调用现有 `handleReplaceHistoryCard`。
5. 替换成功后刷新数据卡和徽章列表；失败时在弹窗中保留编辑内容并显示错误。

### 边界与安全

- 叙事历史不进入基于 `characterData` 的通用替换分支，避免角色数据替换历史卡。
- 保留现有叙事历史 payload 的 `templateId`、版本、时间字段和条目排序规则。
- 保留现有敏感词检查、`dataCardApi.replaceCard`、审核提示和错误处理。
- 不改变数据卡类型、数据库 schema 或 API 契约。

## 测试

- 增加回归测试，确认角色管理页启用叙事历史替换入口。
- 增加回归测试，确认 history 卡的替换动作进入叙事历史编辑器，而不是通用角色数据替换流程。
- 运行相关 Vitest 测试，并执行完整 `pnpm test`、`pnpm lint` 和 `pnpm build`。

## 非目标

- 不把叙事历史编辑器改造成通用 JSON 编辑器。
- 不重构角色卡和情景卡的现有替换流程。
- 不改变“保存为新卡”或其他页面中的叙事历史替换入口。
