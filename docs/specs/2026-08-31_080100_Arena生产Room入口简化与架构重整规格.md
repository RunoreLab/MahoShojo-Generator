# Arena 生产 Room 入口简化与架构重整规格

状态：`accepted / implementation-pending`
日期：2026-08-31
规格标识：`SPEC-arena-room-primary-ingress-simplification-v1`
依据 ADR：`ADR-arena-room-reuse-hono-primary-origin-v1`
适用分支：`feature/v0.2.0_Battle_Growth_MahoShojo` 及从其切出的重整分支
基线提交：`3a972bd51909a1ae00990ef91e041ddad9ea0147`

## 1. 规范语言与目标

本文中的“必须 / MUST”“不得 / MUST NOT”“应 / SHOULD”“可以 / MAY”具有规范性，其解释遵循 RFC 2119 / RFC 8174。

目标是在**不改变 Arena 多人功能语义和 authority**的前提下，移除“为了 Room 再造一个 production service hostname”
形成的重复配置与门禁，使 v1 ingress 只依赖已有 Hono primary。

本文是后续架构重整的实施规格，不授权 production mutation。完成代码重整、测试和只读验证后，仍须按 production
activation 的 writer/request/Web 三层门禁与人工 go/no-go 执行。

## 2. 冻结目标态

```text
production Web: https://mahoshojo.colanns.me
        │
        │ HTTPS / WSS
        ▼
existing Hosted Hono primary
(current: https://homura.colanns.me)
        │
        ├─ /api/arena/rooms/v1/...
        └─ /api/arena/rooms/v1/ws
             Sec-WebSocket-Protocol: mahoshojo.arena-room.v1
        │
        ▼
RoomActor / RedisRoomStore / existing Arena generation authority
```

v1 **MUST NOT** 因 Room 入口建立新的 service hostname、proxy layer 或 deployment unit。

## 3. Source-of-truth 规格

### ARI-001 共享 Hono primary origin

production Room service origin **MUST** 使用现有 Hosted primary origin source of truth。

实现应优先复用 `config/hosted-dr-capabilities.json` 已有的 primary origin / generated client projection；若重整时该配置
已经被更新为新的共享 manifest，则使用其等价字段。**MUST NOT** 创建另一个 Arena-specific production endpoint registry。

当前观察值 `https://homura.colanns.me` 可用于 migration fixture，但测试不应把它升级成永远不可变的业务协议常量。

### ARI-002 `config/arena-room-origins.json` 收敛

该文件当前混合了 service origin 与 browser caller origin。重整时必须二选一：

1. **推荐：** 删除 Room-specific `logicalOrigin` / `provisioning`，仅在确有独立价值时保留 caller-origin policy；service
   origin 由共享 Hosted primary config 读取；或
2. 删除整个文件，把 caller-origin policy 迁入已有 server-side CORS/origin 配置的单一权威来源。

无论选择哪种，production service origin **MUST NOT** 同时存在两份可独立修改的机器事实。

### ARI-003 环境变量去重

后续重整 **SHOULD** 删除仅为重复 service origin 而存在的：

```text
ARENA_ROOM_LOGICAL_ORIGIN
NEXT_PUBLIC_ARENA_ROOM_ORIGIN
```

若 release-gate 需要验证“部署目标就是预期 Hono primary”，应读取共享 Hosted primary 配置，或使用一个跨 Hosted API 的
通用 deployment-origin contract，而不是保留 Room 专属 hostname 变量。

迁移期暂留旧变量时：

- MUST 由共享 primary origin 生成/注入；
- MUST exact-equal；
- MUST NOT 允许 operator 手工提供第二个不同值；
- MUST 在同一重整计划中列出删除点。

### ARI-004 caller Origin 继续独立校验

`ARENA_ROOM_ALLOWED_ORIGINS` 或其后继配置 MAY 保留，因为它表达浏览器 caller allowlist，而非 service origin。

必须继续：

- production Web caller exact allowlist；
- preview caller exact allowlist；
- WSS handshake Origin validation；
- installed client 不以 Origin 作为唯一认证依据。

不得因为复用 Hono primary 而改成 `*` 或放宽 credentialed CORS。

## 4. Client / server ingress 规格

### ARI-005 客户端 endpoint 解析

Web 端 Room HTTP 与 WSS endpoint MUST 从同一共享 Hono primary origin 派生。

建议形成一个很小的纯 helper：

```text
primary origin + versioned path -> Room HTTP/WSS URL
```

要求：

- HTTP 与 WSS 不维护两套 hostname；
- `https:` 对应 `wss:`；production 不允许 downgrade 到 `ws:`；
- path 保持 `/api/arena/rooms/v1` 与 `/api/arena/rooms/v1/ws`；
- subprotocol 保持 `mahoshojo.arena-room.v1`；
- 不能因 endpoint 解析失败静默回退到同源 Web Worker 或 Cloudflare DR。

### ARI-006 服务端不以 public alias 作为 authority

Hono Room runtime MUST 继续依赖 ticket/auth/membership/epoch/revision/replay fence 判断 authority。

`Host` / forwarded host MAY 用于部署安全校验，但不得把一个特定 public alias 当成 Room ownership 或用户授权依据。
若部署层允许多个受控别名，它们必须在通用 proxy/host policy 中显式管理，而不是业务状态机中分叉。

### ARI-007 preview 不与 production hostname 设计混淆

Preview 可以继续使用独立 preview Hono origin，因为它代表**不同环境**。这不构成 production Room 必须拥有独立业务域名的依据。

production/preview 的 caller allowlist、feature flag 和 writer activation 仍必须隔离。

## 5. Deployment / workflow 重整

### ARI-008 删除独立 DNS/Caddy/TLS provision 任务

production activation **MUST NOT** 再以以下工作作为 Arena v1 前置：

- 新建 `api.mahoshojo.colanns.me` Room DNS；
- 新建对应 Caddy site；
- 为该别名单独签发/验证 TLS；
- 把 `not-provisioned -> provisioned` 作为 Room enable gate。

已有 Hono primary DNS/TLS/Caddy 健康属于平台通用 readiness，继续验证但不重复 provision。

### ARI-009 workflow/backend probe

Hono/Cloudflare production backend probe 应直接针对共享 Hono primary origin，至少验证：

- `/api/health/ready`；
- Room HTTP 未认证请求按 contract 返回 401 + stable error；
- WSS 使用合法 RFC 6455 handshake + `mahoshojo.arena-room.v1`、无 ticket 时按 contract 拒绝；
- production Web Origin 得到 exact ACAO；
- request/writer disabled 时不得出现意外 2xx/101。

probe **MUST NOT** 依赖一个额外 hostname 才能证明相同 Hono binary 正常。

### ARI-010 保留 writer/request/Web 三层门禁

入口简化不得合并以下三个独立控制：

1. immutable release tuple 的 `writerActivation`；
2. Hono runtime request enable flag；
3. Web build/public exposure flag。

它们解决的是发布与回滚安全，不是 hostname 复杂度，继续保留。

## 6. 代码清理范围

实施 Goal 应至少盘点并处理当前涉及独立 Room logical origin 的文件：


该清单是**盘点起点，不是要求机械修改每个文件**。如果某文件只使用 caller-origin policy 或仍有独立安全价值，应保留；
如果代码搜索发现其他 duplicate service-origin consumer，也必须纳入同一重整审查。

禁止为了清理变量顺手重写 RoomActor、Redis schema、generation authority 或 Hosted DR adapter。

## 7. 迁移顺序

建议使用一个原子化 `/goal` 或小型连续提交完成：

1. **冻结测试目标**：新增/调整测试，证明 production Room endpoint 来自共享 Hono primary，旧独立 hostname 不再是 gate；
2. **收敛 config**：移除/派生 duplicate service-origin source of truth；
3. **收敛 client**：HTTP/WSS 都从共享 primary origin 派生；
4. **收敛 server/deploy**：移除 Room-only logical-origin env 与 provision assertion；
5. **收敛 workflows**：backend probe 直接打 Hono primary；
6. **更新 docs/runbook**：只保留 existing primary readiness + writer/request/Web rollout；
7. **全仓搜索**：确认 `api.mahoshojo.colanns.me` 不再作为 Arena v1 required endpoint；
8. **保持 production disabled**，完成 CI/只读公网验证后再进入单独的 activation window。

若步骤 2–5 不能在同一兼容窗口完成，过渡态必须 fail closed；不得让 Web 与 Hono 分别相信两个不同 endpoint。

## 8. 验收门禁

架构重整完成必须同时满足：

- [ ] production Room service origin 只有一个权威来源，并与 Hosted Hono primary 相同；
- [ ] 不需要新 DNS/Caddy/TLS 资源即可通过 build/release gate；
- [ ] `api.mahoshojo.colanns.me` 不再是 Arena v1 production activation blocker；
- [ ] browser caller Origin exact allowlist 仍通过 HTTP/WSS negative/positive tests；
- [ ] Room HTTP/WSS paths 与 subprotocol 未改变；
- [ ] writer/request/Web 三层门禁仍 fail closed；
- [ ] Room realtime 仍不进入 Cloudflare DR；
- [ ] Redis authority/checkpoint/directory/generation tests 无回归；
- [ ] workflow backend probe 直接验证共享 Hono primary；
- [ ] `pnpm run ci:verify`（或届时仓库等价全量 gate）通过；
- [ ] `git diff --check` 通过；
- [ ] 未执行 production mutation。

## 9. 回滚

本重整在 production Room 仍 disabled 时实施，因此首选回滚是普通代码回退：

- 恢复上一份已知可构建的 Room origin seam；
- 保持 writer/request/Web 全部 disabled；
- 不为“让旧代码继续工作”临时 provision 新 DNS；
- 不 flush Redis、不改 D1、不迁移 Room authority 数据。

如果 production 已经在后续窗口按新入口启用，回滚仍优先执行 Web exposure off -> request off -> writer disabled，
再回退代码；不得通过临时改 hostname 绕过 release gate。

## 10. 不属于本次重整

以下全部 deferred：

- multi-instance Room ownership；
- Durable Object / `apps/arena-room`；
- Room realtime Cloudflare DR；
- managed load balancer / paid control plane；
- Redis schema/TTL redesign；
- generation storage redesign；
- Hosted stable-origin seam 的全局删除。
