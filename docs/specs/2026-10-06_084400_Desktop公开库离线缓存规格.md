## DESK-CACHE-001 缓存范围与可信来源

缓存是本机保存的公开资料派生快照，**MUST NOT** 与账号私有缓存、正式本地库或服务器权威混为一体。对外只承诺已经捕获且可读取的部分，不承诺全库、实时公开性或跨设备同步。

正缓存只接受受控公开接口中校验通过、确定为公开可读的安全投影。首版捕获实际返回的摘要与按需完整卡，不扫描其它页、不预取全部正文、不追踪内容内图片/附件/链接。用户尚未使用线上能力时不得为缓存启动项目请求。

native 缓存获取优先采用明确不附带会话的公开读取；不能把“我的/收藏”数据、账号关系字段、私有批量元数据，或任意带凭据响应按 `isPublic` 自声明纳入公共缓存。若复用现有 Optional-auth 通路，应先固定公开投影不依赖身份并通过测试；不向 renderer 开放任意 auth/header 开关。

HTTP response caching 与本产品快照分层。不得将 no-store/private、非公开内容或未知策略响应写入公共快照。所需的最小存储许可/业务不可用分类由 native 在受控路由上判断并传安全枚举，不传原始 Cookie/headers。当前 IPC 未声明某字段时不可假定能直接读取；新增窄契约随 K1 同批验证。后续若服务器撤回缓存许可，不继续提供对应缓存内容。

验收：匿名公开卡可捕获；私有/收藏/身份附加字段不混入；当前 Web 行为未被该 Desktop 策略修改；renderer/native 无额外秘密传递。

## DESK-CACHE-002 持久化、身份与完整度

使用 native 固定持久数据子目录中的 `public-read-cache.sqlite`，不置于系统临时/可自动清理目录。与 `library.sqlite` 逻辑和物理隔离；复用已有 SQLite 依赖，不新增服务。缓存 schema 有版本和幂等迁移；未知未来 schema 保留原库并禁用该缓存功能，不阻止本地库启动。

记录身份至少按受控项目服务范围 + 公开卡 ID 区分，不以名字、URL 外观或账户用户名认领。单卡至少能表达：摘要快照、正文是否可用、各自版本/更新时间线索、最近成功获取时间、最近尝试时间、当前公开可用性已知/未知/已撤回，以及用于本地并发控制的 revision。字段名随现有 contracts 实现，不复制整张 D1 表。

摘要与正文必须分开管理：只有 summary 不能构造可用角色正文；新 summary 不得把旧 body 包装成同版正文。正文成功取得并校验后再原子替换；已知新版摘要但未取得正文时，保留上一完整快照并标注版本差异。更新失败保留旧完整数据，不把 `lastAttempt` 当 `lastSuccess`。

优先使用服务器实际提供的版本/ETag；现有接口没有则不编造。`updated_at`、请求完成时间不是全局单调 revision 的证明；本地请求次序只能防旧响应覆盖，不提供服务器最新性担保。304 只有在真实 validator 请求成立且有匹配正文时才更新验证时间。

D2 portable archive/完整备份不包含此缓存；正式本地库恢复不得删除或回滚缓存。缓存坏了显示“缓存不可读”，不伪装空库、不自动删库重建；显式清理/重建保留用户确认。K1 必须补相应隔离测试。

## DESK-CACHE-003 正缓存保留与容量

**禁止仅按年龄、未使用时长、soft TTL 或 LRU 删除正缓存。** freshness 只影响是否重验证；用户断网一年也可以查看仍在本机、未被确认撤回的完整快照。

首版默认预算为 **256 MiB 逻辑序列化载荷**，是可调整的初始产品值而非性能测量结论。包括摘要、正文及持久元数据，写前以 UTF-8 字节增量检查。单卡/单次 IPC 继续遵守现有更小上限；不因缓存预算较大放宽单条输入边界。

达到预算时拒绝新增或导致超预算的增长写入，保留当前缓存并提示“新读取尚未缓存”。在线响应仍可正常展示/使用；可以在预算内以有效新版本替换旧版。减少预算若小于现存占用，仅暂停增长，不能静默裁剪到新值。缓存持久化失败不推翻已成功的在线读取或 AI 结果。

逻辑预算不等于数据库文件/WAL/页碎片/临时事务或进程 RSS 硬上限。native 写入有界、事务提交/失败可恢复，并展示实际占用/磁盘失败；磁盘不足时暂停增长。不能靠无限重试继续占满磁盘，也不能自动删老卡腾空间。

手动清理可以按条目或全部执行；前置展示影响范围和完整正文数量，提示长期保留可先存本地库。清理不会触及正式本地卡、Provider、账户凭据或未保存编辑结果。纯负缓存/不存在记录可以短期失效并限量回收；不得据此回收旧正卡。

## DESK-CACHE-004 查询与离线使用

复用 CardLibraryModal 的既有公开库页签/筛选/详情区段，不另建第二套离线库模态框。界面区别“线上公开库”“离线缓存/正在重连”“主动查看已缓存资料”；有明确回到线上/刷新入口。

离线搜索/筛选/排序/分页作用域是本机已捕获集合。复用公开 summary 查询语义：ID/名称/描述、作者、类型/角色类型、标签及已有数值筛选；排序稳定收口到既有 metric → updated_at → id。缺少必要字段时不猜零或 true：禁用该筛选并说明，或将未知记录排除并说明覆盖限制。原生/推荐标志是抓取时的筛选元数据，不是当前资格证明。

离线 total 是匹配缓存数；可另显示其中正文齐全数。不得展示旧服务器 total 为当前完整范围，不能把“缓存里没有”写为“线上没有”。保留输入参数但在线/离线分页 cursor/offset 分开，切换数据源不拼出重复或缺页混合列表。

摘要行可浏览，但无正文时明确“尚未缓存正文，联网后可获取”，使用按钮不可执行。完整快照可用于普通本地阅读/单人/Direct；正文不需先存正式本地库。正文内外部图片缺失不影响文本查看，默认不自动下载；可执行内容仍受 D4。

缓存模式不得暗中请求标签、作者徽章、批量段位、收藏、点赞、使用量统计等附属接口。仅显示已有安全元数据或“未知”；不把失败当空成功，不排队离线赞/收藏/统计写入。

## DESK-CACHE-005 在线查询、重连与及时收敛

“新鲜”和“当前显示来源”是独立维度。用户进入公开库或显式刷新时，可以立即读快照供查看，但必须发起一次去重的当前线上查询，不能因为缓存存在永久不查线上。成功后更新当前线上视图及对应缓存；失败后保留快照、明确失败原因和重试入口。

在线界面仍活动时，连接恢复信号/窗口回到前台可触发一次合并的重验证；同一查询/单卡 single-flight，遵守既有有界 timeout/retry/backoff 和 429 退避。关闭相关页面后不维持无限探测；再次进入/手动重试仍能恢复。`navigator.onLine` 仅提示，不把它当真实服务健康或使用缓存的永久锁。

线上成功结果只呈现本次服务器查询的集合；不把缓存中本次未返回的旧卡无标识追加到线上页。旧卡可在“已缓存资料”视图继续查看。联网后打开/使用旧完整卡时按需重验证该卡，不要求后台扫描所有缓存才允许使用其它功能。

在“主动查看已缓存资料”时允许维持这个用户选择，但显示它不是线上库，并提供刷新；不能在自动故障降级后隐式永久锁住该视图。对正在输入的筛选、已选卡或生成快照，刷新不擅自替换；以请求作用域决定 UI 更新和选择保留。

## DESK-CACHE-006 更新、撤回与错误分流

| 已核实结果 | 缓存动作 | 用户界面 |
| --- | --- | --- |
| 当前查询成功 | 合并成功返回的安全摘要；更新该查询视图 | 显示当前线上结果；保留不属于该页的历史缓存 |
| 单卡正文成功且合法 | 原子更新该卡完整快照 | 下次选择使用新快照，在途任务不改 |
| 单卡明确业务不可用/撤回 | 移出公开可见/可选集合，清除该公开缓存正文，保留必要失效信息 | 不再提供旧卡作为公开库替代品；已存正式本地副本不受影响 |
| 空搜索页/卡未出现在某页 | 不推断单卡删除，不清其它缓存 | 当前线上页为空；缓存范围独立 |
| 网络/超时/429/5xx | 保留正缓存；可有界重试 | 可查看旧资料，标明未确认最新状态 |
| 无明确单卡撤回语义的 401/403、通用 HTML 404、WAF/协议/schema 不明 | 不据此宣称单卡撤回或删除；停止受影响的在线动作 | 解释登录/访问/兼容错误；已知公开快照可按只读降级策略展示 |
| 用户取消/切 tab/切账号 | 终止 UI 认领；按请求 epoch 决定是否仍可缓存安全公共读取 | 不让旧页面/账号结果覆盖当前列表 |

“业务不可用”必须来自匹配该卡 ID 的预期公开接口和可识别业务响应，不是任意 404。当前单卡接口用 JSON 404 表示不存在；如不足以与路由/版本错误区分，K1 增加最小错误投影并验证，不把未知含义变成删除依据。隐私化/审核撤回也可以表现为公开不可用，不需要向匿名用户泄露内部原因。

当前分页接口不是一致全库快照，没有删除流；即使顺序读过多页，也不能做“本轮没出现 → 全局删除”。首版只逐卡按需确认。后续真有完整快照 token 或 tombstone 协议时另按实际契约评估，不预建同步引擎。

已经确认不可用的卡在本次运行中立即不可选，不能因失效写盘失败再次走 stale fallback。持久化失效失败须报告，不声称撤回状态已落盘；后续在线读取重新核实。该故障不扩大为整个应用/正式本地库不可用。

业务撤回对公开缓存生效，不追踪删除正式本地副本。客户端离线无法获知新撤回，界面不声称离线资料当前仍公开/合规/有权参与权威玩法。

## DESK-CACHE-007 请求竞态、清理与冻结输入

同一记录的更新有有界 single-flight/写入次序。有效网络回复到持久化前还需核对 cache epoch/该记录 revision：清理、禁用捕获、确认撤回后，先前已发出的响应不能重新填回旧数据。仅在 React 中检查 `signal.aborted` 不足以保证 native/后台写入不会发生。

成功的新请求可以重新确认已恢复公开的卡，但只能来自新 scope 的真实结果；过期负缓存不自动复活曾撤回的正文。部分写入/磁盘错误保持原完整快照，不留下新摘要配旧正文而无版本提示的状态。

使用缓存卡时生成一个明确来源的冻结输入；追溯 cloud ID 可保留，但不能把它当作本次已验证的 `sourceDataCardId`。UI/selection contract 必须能区分当前线上引用、公开缓存快照和正式本地卡，不能靠可编辑 `_storageLocation` 文本或同名 ID 获得资格。

Direct/普通单人可使用缓存；Strict、多人可执行引用和权威写入必须由现有服务器流程重新物化/验权。断网时不可从缓存伪造完整线上引用；不自动上传缓存结果。刷新、取消、重连不会自动触发生成、更换 Provider 或二次计费。含旧签名的正文只保留证据，未验签不升级为官方有效。

问卷缓存同样是本地输入快照：经现有 selection 规则按上传/本地来源处理，不能仅凭旧 dataCardId/nativeAllowed 标志进入 database 来源的官方签名资格链。要使用当前线上问卷引用，须重新在线物化，再由服务器按既有许可规则决定。保留旧签名字节不等于获得新的签名资格。

## DESK-CACHE-008 设置与人工配置

K1 与 S2 同批实现以下真实消费者字段。它们是目标示例，**当前版本尚不能读取这份文件**：

```json
{
  "version": 1,
  "publicLibraryCache": {
    "captureEnabled": true,
    "maxBytes": 268435456
  }
}
```

`captureEnabled` 默认 true，但只有用户实际使用公开库时才捕获；false 仅暂停正缓存新增/替换，不删除已有内容、不关闭线上查询或必要撤回失效处理。保留的快照仍可显式阅读/清理。`maxBytes` 是正整数、首版接受 1 MiB 至 8 GiB 的逻辑预算；这些范围是保守产品限制，可在测量后通过显式规格修订调整，不承诺该范围任意规模都具有相同检索速度。

缓存策略文件损坏、版本未知或预算无法校验时暂停新增/增长捕获，保留既有缓存的只读访问和正常线上查询并显示诊断；不得静默恢复 captureEnabled=true 或放大预算。缺文件与坏文件须区分：只有缺文件才应用首次默认。

配置和设置 UI 必须同一 owner，不能在 localStorage 再存一份开关/预算。首版可先接手工配置、路径/重载与使用量说明，后续 UI 同源接线。不要提供 TTL 删除、自动全库下载、绕过公私权限或签名门禁的高级选项。

缓存明细、限额/磁盘失败与清理入口在设置的“数据与存储”下，与正式本地库分开；Web 只显示自己真实拥有的站点缓存能力，不渲染 Desktop 文件路径/配额控件。

## DESK-CACHE-009 实施与测试边界

共享层只抽实际复用的公开 DTO/归一化、查询规则、来源/完整度状态及库视图。native 负责路径、数据库、出站与写入机制。可以扩展现有 CardLibraryHost 的窄能力，但不能构建任意 HTTP/SQL/file proxy，不能把缓存实现塞进本地库或所有网络请求的万能中间件。

Web 继续回用共同视图/语义；其当前单卡 hard TTL/IndexedDB 策略和网站离线启动不在本任务默认变更范围。若抽取确实改变 Web，须点名并给出兼容/回归；不以“Web 断网一定不能打开”为假设设计所有宿主。

| 用例 | 预期 |
| --- | --- |
| 缓存完整卡，重启并断网，时间推进很久 | 可查找/筛选/阅读/使用；不因年龄删除 |
| 仅缓存摘要后断网 | 可搜到摘要，正文/使用明确不可用 |
| 新摘要、正文刷新失败 | 旧完整快照仍在，版本差异/状态诚实 |
| 在线读取成功但缓存写失败/达到预算 | 线上仍可用，旧缓存不丢，明确新内容未缓存 |
| 故障降级后网络恢复 | 活动公开面重新查询并回到线上结果，不永久停在缓存 |
| 线上空页或不同筛选少了一张卡 | 不删除其它缓存；线上 total 与缓存 total 不混 |
| 单卡业务 404 对比 503/HTML404/401 | 只在确认业务不可用时移除对应公共快照 |
| 先请求，后清理/撤回，再迟到成功 | 不重新填回清理/撤回前旧数据 |
| 账号 A/B 切换及退出 | 私有关系/资料不串；公共缓存不误删；本地库不变 |
| 缓存选卡进入 Strict/多人 | 不能直接作为已验证线上卡；服务器资格照常重验 |
| 缓存刷新发生于生成中 | 冻结输入/执行者不改，没有第二次 AI 调用 |
| 正式库备份/恢复、缓存损坏/未来版本 | 正式库和缓存互不破坏；失败可诊断而非空成功 |
| 离线列表打开、搜索、详情 | renderer/native 无附属元数据/统计/媒体隐式联网 |
| 减预算/禁捕获/手动清理/外改 config | 不隐式淘汰；配置单一 owner；清理范围明确 |

先用现有单测、SQLite/IPC 集成与宿主夹具验证。真实断网/重启/大缓存响应性与磁盘异常纳入集中实机 runbook，未执行保持 PENDING。只读缓存失败不能成为无关功能/整个应用的 fail-closed 门禁。
