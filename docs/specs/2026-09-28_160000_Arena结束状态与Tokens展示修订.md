## 范围与既有约束

## Tokens 展示

卡片沿用“输入｜推理｜输出”。输出展示非推理 Tokens：优先使用 SDK 的 `outputTokenDetails.textTokens` / 原生 Google `candidatesTokenCount`；缺失时，在已知包含推理的 completion 与 reasoning 都有效且前者不小于后者时相减。明确标记不含推理的渠道字段不再扣减。不明或矛盾数据展示 `-`，不把未知推理当成零。

`completionTokens` 和现有数据库列仍保存原始总输出口径，避免影响统计。新增的 `textTokens` 和规范化明细写入 `extra_json.usageDetails`，用于刷新、历史卡片和多人结果。总 Tokens 缺失时，仅在输入和总输出均已知时求和，不能再额外加推理。

截图样本的 11,568 总输出、8,273 推理，在该口径下展示输出 3,295；Tokens 与页面字符不是一一对应关系，模型正文还可能包含随后被剥离的元数据。

## 结束状态

Arena 原始流的 SDK finish reason 只有 `stop` 可正常完成；`length` 标记 `AI_OUTPUT_TRUNCATED`，`content-filter` 标记 `AI_OUTPUT_FILTERED`，未知、异常或其他非正常原因标记 `AI_STREAM_INCOMPLETE`。正文之后的 SDK error 事件同样传播为失败。已验证的结构化非流式执行路径不要求流式 finish reason。

浏览器遵循服务端 `done.status`，有标题不能把失败变成成功；没有二级标题也不能把正常完成变成失败。失败结果不执行完成后的角色写入、叙事历史追加、排位结算或成功冷却。错误不触发自动重生成。

连接结束但没有终态时，仍可能存在后台 producer，保留既有连接异常节流与恢复流程；它不代表生成成功。

## 部分正文与诊断

Markdown 在输出上限、未知结束或上游连接错误时，可保留已有正文到原有 R2 输出对象，逻辑状态保持 failed，并通过相同 owner 校验的恢复入口读取。刷新时恢复 Tokens 及稳定错误文案；归档失败仍按既有持久化降级处理。用户取消、内容策略取消、内容过滤、Web 文档/Web 包和结构化输出不使用此部分正文归档路径。

记录有限诊断到 `extra_json.completion`：规范化结束原因、SDK finish 事件是否出现、流错误、配置输出上限、SDK 文本字符数、首末文本相对耗时、思考模式与应用状态。不保存任意上游 payload、密钥、提示词或错误原文。相对耗时从 SDK 流建立后开始，SDK finish 事件不等于原始 HTTP/SSE 结束标记。

## 验收与限制

定向测试覆盖 Tokens 拆分、未知值、原生 Google 与 SDK 明细、晚到 error、非 stop 结束、缓冲尾部保留、失败归档与 owner 恢复、取消/策略/Web 排除以及前端终态判定。类型检查和 workspace 依赖边界继续适用。

旧记录没有保存的结束原因无法追溯补齐；上游如果错误地返回 `stop`，仍不能仅靠字符数可靠判断叙事完整性。未新增自动续写、重试、统一提高输出上限或强制关闭思考。上线后应结合新诊断按渠道分析截断原因，再调整相关模型配置。
