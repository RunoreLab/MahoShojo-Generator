# G25H-1 Arena 伴随 AI 路由归位设计

状态：active  
日期：2026-08-26  
适用 Goal：`G25H-1 Arena companion AI routes re-entry`

## 1. 依据与当前事实

本设计服从平台重整 accepted ADR、目标架构、实施规格、Goal 自治规格，以及
`2026-08-25_111500_Hosted长生成断网可恢复流实施规格` 和同名插入计划。它不修改
客户端不可信、服务器权威、secret 隔离、Legacy/Better Auth 兼容、Arena v1 wire、
非幂等请求不盲目重放等终点。

截至 `refactor/platform-rearchitecture` 的 `bae15fb0`：

- route inventory 为 `15 shared / 13 exited / 0 legacy`；
- `arena/generate`、`generate-battle-story`、`arena/session/generate-next` 的 handler
  分别为 852、1,102、524 行，共 2,478 行；
- `generate-battle-story` 是两条非流式实现中较新的行为超集，额外承载 PVP context、
  失败记录和同步 generation id；
- `arena/session/generate-next` 会从 Cloudflare/Next fetch Hono
  `arena/generate-stream`，解析 SSE、累积 Markdown/meta，再重编码 SSE；
- G25R 已提供 stable `generationRequestId`、single-producer reservation、server-owned
  lifecycle、Redis replay/snapshot、D1/R2 terminal fallback 和 single finalization，但服务只暴露
  HTTP `Response`，没有 typed subscription；
- Next/OpenNext DR composition 继续使用 unavailable active replay store：它可以读取 durable
  terminal，但 Redis reservation 不可证明时必须在 Provider 前 fail closed。G25E 才负责长期 DR
  capability manifest/cutover，本 Goal 不引入 process-local active fallback。

## 2. Objective 与非目标

本 Goal 精确归位三条 route：

- `arena/generate`；
- `generate-battle-story`；
- `arena/session/generate-next`。

归位后的常态路径为 Hono adapter → shared companion service → G25R typed generation core；
Next/OpenNext 保留同一 shared service 的 DR adapter。`me/battle-reports/[generationId]/regenerate`
继续属于 Next，因为它不启动新 Provider generation。

本 Goal 不新增 schema，不改变 Arena v1 multiplayer wire，不把 Redis 提升为业务终态权威，不实现
G25E 的自动跨 runtime failover，也不迁移 Details/Sublimation 或 Tea Party/Tavern。

## 3. 方案比较与选择

### 方案 A：Hono 内部继续构造 HTTP 请求并解析 SSE

改动最小，但公开 self-hop 只会变成进程内字节 self-hop；session 仍依赖 SSE parser/re-encoder，
不满足 typed subscription stopping condition。否决。

### 方案 B：把 1,102 行 structured handler 原样移入 shared runtime

外部 JSON 最容易保持，但会长期维护与 G25R 平行的 prompt、Provider、安全、签名、D1/R2、rating
和 adjudication pipeline；stable identity 与 server-owned lifecycle 仍需再造。否决。

### 方案 C：G25R typed subscription + route projector（采用）

将 G25R replay reader 抽成 `ArenaGenerationSubscription`，HTTP SSE 只作为 subscription 的一种
adapter。两条非流式 route 阻塞收集 typed events 并投影为兼容 JSON；session 在 typed event 层增加
`session_meta`/`chapter_digest`，不解析或重编码上游 SSE 字节。三条 route 因而共享 actor、
generation identity、Provider、authority、安全、replay、terminal/finalization 与故障语义。

这会把非流式 route 的内部 Provider 执行统一为 G25R Markdown generation，但保持公开 JSON 字段
`report`、`updatedCombatants`、`adjudicationResults`、`impacts`、`generationId`。这是有意的内部实现
收口，不是 wire 变更；回归测试固定两条 adapter 的状态码、响应字段、PVP winner/internal guidance、
角色更新与 replay single-producer 行为。

## 4. 边界与接口

### 4.1 Typed generation subscription

`@mahoshojo/hosted-api/arena-generation/service` 新增：

```ts
type ArenaGenerationSubscription = Readonly<{
  generationId: string;
  generationRequestId: string;
  headers: Readonly<Record<string, string>>;
  events: ReadableStream<GenerationStreamEvent>;
}>;

interface ArenaGenerationService {
  createSubscription(request: Request): Promise<ArenaGenerationSubscription | Response>;
  create(request: Request): Promise<Response>;
  // existing lookup/resume/status/cancel methods remain unchanged
}
```

`create()` 只负责把 typed events 编码为既有 SSE。Redis live replay、window-lost snapshot、stream
missing、D1/R2 terminal fallback 和 cursor 单调性都在 subscription 层完成，因此 typed consumer 与
HTTP consumer 观察同一事件序列。

### 4.2 Companion service

shared companion service 暴露三个窄方法：

```ts
interface ArenaCompanionService {
  generate(request: Request, route: 'arena/generate' | 'generate-battle-story'): Promise<Response>;
  generateNext(request: Request): Promise<Response>;
}
```

Hono 和 Next adapter 只选择方法，不包含 Provider、prompt、SSE parser、D1/R2 或角色更新实现。

### 4.3 Stable identity

- Web 非流式 client 在首次 POST 前生成 `generationRequestId`；
- PVP 使用 `(roomId, matchId, roundId, attempt)` 导出的稳定 request id，明确的纠错 attempt 是新的
  operation，不是对 unknown mid-flight 的透明重放；
- session 沿用客户端首次 intent 前生成的 `generationRequestId`；
- 兼容旧调用者时允许服务端生成 request id，但响应头明确返回；只有调用者预先提供的 id 才具备
  response-before-headers 故障后的安全 lookup/retry 能力；
- 相同 actor + request id + payload 复用同一 producer；payload 不同返回 409；unknown running 不启动
  第二 Provider。

## 5. Authority、安全与兼容

- actor 仍由 G25R resolver 从 Legacy auth、Better Auth、activity token 或 anonymous actor token
  解析，客户端声明的 user id 不成为权威；
- native/signature、scenario/material authority 继续由 Node executor 重新验证；
- `internalGuidance` 默认删除。session service 使用服务器签名能力添加 guidance signature；PVP
  subrequest 同样签名。公网仅提交 `internalGuidance` 不生效；
- custom Provider key 只进入 execution payload，不进入 semantic hash、replay event、telemetry、D1
  extra 或客户端响应；
- session rate limit lease 在 subscription terminal/error/cancel 时 exactly-once release；subscriber
  disconnect 只结束该订阅，不 cancel producer；
- typed projector 保留 generation SSE id；`session_meta` 不伪造上游游标，`chapter_digest` 在成功
  terminal 前生成；snapshot replay 会用 snapshot Markdown 恢复 digest 累积；
- safety preflight 的 4xx/redirect payload 原样返回，Provider/terminal failure 返回包含稳定
  `generationId` 的错误，不自动重跑。

## 6. 数据、副作用与 telemetry

- 远端持久副作用只由 G25R finalizer 执行，D1 generation claim、R2 output、combatant audit rows、
  rating/history finalization 仍以 generation id 幂等；
- 非流式 `updatedCombatants` 是本地卡片响应投影，不写服务器 card authority；投影以 generation id
  写入本地 history metadata，重复应用可识别；native card 只由服务器签名；
- generation server context 记录受信 pathname/delivery mode，D1 endpoint 与 route telemetry 可区分
  `arena/generate-stream`、两条非流式 companion 和 session；不接受 payload 自报 placement；
- Hono middleware 与 Arena observer 继续提供 placement/provider/replay/finalization 指标；Next DR
  adapter 走同一 response marker，便于对比 Cloudflare/Hono execution。

## 7. Manifest、回滚与影响

完成后 manifest 必须精确为 `18 shared / 10 exited / 0 legacy`。只移动上述三条 route；
`regenerate` 仍在 exited。

实现按 typed seam、session domain、companion core、dual adapters/callers、manifest/docs 分为独立提交。
整体回滚按逆序普通 `git revert`；不需要 schema/data restore、Redis flush、secret rotation 或 release
rollback。若只回滚公开 route，必须同时回滚 manifest、Hono adapters 与 Web client request identity，
不能留下 Hono route 指向不存在的 service。

## 8. 重新估算与 stopping condition

按当前代码重新估算为 **8–10 小时**：typed replay seam 2–2.5h，session domain/service 2h，
non-stream projector/角色更新 2–2.5h，dual adapters/callers/manifest 1–1.5h，完整验证与独立审查
1–1.5h。虽然高于先前 6–8h，但 typed seam 与三条 route 的 identity/finalization 是同一原子边界；
拆出 1b 会留下用户明确要求移除的 session 中间层，因此本轮保持一个 Goal，不降低 gate。

只有同时满足以下条件才停止：

1. 三条 route 都是 shared service + Hono/Next adapter；
2. session source 和 runtime 均不存在公开 generation HTTP self-hop 或 SSE parser；
3. contract、authority、side-effect、replay、manifest、boundary、server、workspace、Web/OpenNext build
   验证通过且 no-new-regression；
4. telemetry 能区分 route/placement；
5. `regenerate` 明确继续 Next；
6. independent architecture/security/compatibility-data/replay/test review 无 Critical/Important open。
