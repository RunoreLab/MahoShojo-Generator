# /challenge 战斗节点角色卡与战报卡复用设计

## 背景

当前 `/challenge` 的战斗、精英、Boss 节点只把 `enemySnapshot.displayName` 和 `promptSummary` 直接拼成文本说明。这样会丢失角色卡模板信息，也无法复用项目中已经成熟的角色卡导图能力。

类似地，挑战节点的 AI 流式故事与结算结果目前以纯文本区域展示，没有复用竞技场已经稳定使用的流式战报卡，因此也无法直接导出图片或 Markdown。

本次设计目标是让 `/challenge` 在战斗节点的“看对手”和“看战报”两个核心动作上，与现有角色卡体系和竞技场战报体系对齐。

## 目标

1. 战斗、精英、Boss 节点不再直接显示敌方纯文本摘要，而是优先按敌方原始数据卡模板展示角色卡。
2. 角色卡继续复用现有组件与其现有导图能力，不新增平行的卡片样式系统。
3. 挑战节点中的 AI 流式故事、结算结果统一复用竞技场流式战报卡，并保留导出图片与 Markdown 的能力。
4. 对于无法补齐完整原卡的敌人来源，稳定降级为“通用角色卡快照”，而不是退回现有纯文本敌人说明。
5. 敌方卡展示请求不能阻塞挑战主流程；即使卡片仍在加载，用户也必须可以继续选择动作并提交结算。

## 非目标

1. 不修改挑战地图、休整节点、商店节点、事件节点的主要交互结构。
2. 不把完整敌方原卡写回 `runState`、`encounterSnapshot` 或本地挑战存档。
3. 不为挑战模式单独设计新的角色卡视觉语言。
4. 不新增新的图片导出或 Markdown 导出基础设施。

## 现有可复用能力

### 角色卡

项目已经有完整的角色卡组件与图片导出能力：

- `MagicalGirlCard`
- `CanshouCard`
- `GeneralCharacterCard`

这些组件已经支持截图导出和移动端图片预览，不应重新实现。

### 战报卡

项目已经有成熟的 `StreamingBattleReportCard`，具备以下能力：

1. 渲染流式 Markdown。
2. 导出战报图片。
3. 导出 Markdown。
4. 展示 AI reasoning、telemetry 等扩展信息。

挑战模式应直接接入该卡片，而不是保留独立的纯文本战报区。

## 用户体验设计

## 战斗节点布局

当节点类型为 `battle`、`elite`、`boss` 时，页面结构调整为：

1. 顶部显示“敌方角色卡”区域。
2. 中部保留现有“推荐动作”和“自由意图”输入区。
3. 下方显示统一的“战报卡”区域，流式生成中与结算完成后都使用同一张卡。

敌方角色卡默认直接展开，不采用默认折叠或仅显示紧凑摘要的形式。

## 敌方角色卡展示规则

### 目标行为

1. 如果能拿到敌方原卡，按原卡模板展示。
2. 如果拿不到原卡，展示一张由 `enemySnapshot` 派生出的通用角色卡快照。
3. 不再使用“对手：名字 + promptSummary”的平铺文本作为主要展示方式。

### 敌方来源解析顺序

敌方快照来源包括：

- `preset`
- `public-card`
- `season-entity`

展示解析顺序如下：

1. `preset`
   - 通过 `getBundledPresetData(sourceId)` 读取预设原卡。
2. `public-card`
   - 通过现有公开数据卡接口补查原卡。
3. `season-entity`
   - 优先尝试按 `sourceId` 补查公开数据卡。
   - 若查不到原卡，回退为通用角色卡快照。

### 原卡模板分发

拿到原卡后，使用现有模板推断逻辑判断卡片类型：

1. `magical-girl`：使用 `MagicalGirlCard`
2. `canshou`：使用 `CanshouCard`
3. `general`：使用 `GeneralCharacterCard`

如果模板不可识别，同样回退为通用角色卡快照。

### 通用角色卡快照回退规则

当无法补查完整原卡，或模板无法映射到现有角色卡组件时，构造一张仅用于展示的通用角色卡快照：

1. `name` 使用 `enemySnapshot.displayName`
2. `content` 由以下信息拼成 Markdown：
   - 挑战对手快照说明
   - `promptSummary`
   - `strengthTier`
   - `tags`
   - `combatProfile` 的安全摘要
3. 文案中明确声明“该卡为挑战快照，不代表完整原始数据卡”

这样即使不能展示原卡，也仍然保持“卡片化展示”和“可导出图片”的体验。

## 战报卡设计

### 统一卡片

挑战模式中的以下内容统一复用 `StreamingBattleReportCard`：

1. AI 流式输出中的实时故事文本。
2. 流式完成后的正式结算战报。
3. 流式失败后本地系统 fallback 生成的结算结果。

不再保留一套独立的挑战模式纯文本战报区。

### 结果一致性

无论是流式成功还是 fallback 成功，最终都继续停留在同一张战报卡上，只改变其内容和流式状态：

1. 流式中：`isStreaming = true`
2. 流式完成：`isStreaming = false`
3. fallback 结果：仍用战报卡展示，并附带已有 fallback 提示

### 导出能力

战报卡直接继承现有能力：

1. 保存为图片
2. 导出 Markdown

挑战页面只需提供与竞技场一致的图片预览承接，不新增导出实现。

## 组件边界与状态流

## 页面级职责

`ChallengePage` 负责：

1. 承载挑战页面主布局。
2. 承载与竞技场一致的图片预览弹窗状态。
3. 把图片预览回调透传给敌方角色卡和战报卡。

## 控制器职责

`useChallengeController` 继续负责挑战流程状态，并新增两类展示状态：

1. 敌方展示卡状态
   - `idle`
   - `loading`
   - `resolved`
   - `fallback`
   - `error`
2. 战报卡状态
   - `markdown`
   - `reasoning`
   - `telemetry`
   - `finalSource`

控制器负责拿到这些展示数据，但不负责模板分发渲染。

## 节点展示职责

`NodeResolutionPanel` 继续作为节点页的布局容器，但不直接承担以下逻辑：

1. 不直接补查敌方原卡。
2. 不直接根据模板拼装具体卡片。
3. 不直接处理图片预览状态。

节点页内部建议拆为两个展示区：

1. `ChallengeEnemyCardSection`
   - 接收敌方展示卡状态
   - 负责显示加载态、原卡、回退卡、失败提示
2. `ChallengeStoryCardSection`
   - 接收 `markdown`、`reasoning`、`telemetry`、`isResolving`
   - 统一渲染 `StreamingBattleReportCard`

## 状态流

1. 用户进入战斗节点。
2. 控制器设置 `currentEncounter` 后，异步开始解析敌方展示卡。
3. 敌方卡区域先显示加载态。
4. 原卡解析成功则显示对应角色卡；失败则显示通用角色卡快照。
5. 用户选择推荐动作和自由意图后提交结算。
6. 流式过程中，`markdown` 持续更新到战报卡。
7. 流式返回的 `reasoning` 与 `telemetry` 一并透传给战报卡。
8. 结算完成后继续显示同一张战报卡，而不是切回纯文本结果区。

## 错误处理

1. 敌方原卡补查失败只影响展示层，不阻断节点流程。
2. 敌方卡加载不阻塞推荐动作选择、自由意图输入和提交结算。
3. 战报流式失败但系统 fallback 成功时，继续使用战报卡展示 fallback 结果。
4. fallback 提示沿用当前已有语义，不额外创建第二套提示体系。
5. 图片导出与 Markdown 导出异常继续沿用现有卡片内部处理。

## 测试设计

## 纯函数测试

为新的敌方展示解析层补测试，覆盖：

1. `preset` 成功映射为原卡展示。
2. `public-card` 成功映射为原卡展示。
3. `season-entity` 补查成功时映射为原卡展示。
4. `season-entity` 补查失败时回退为通用角色卡快照。
5. 原卡模板不可识别时回退为通用角色卡快照。

## 组件渲染测试

为挑战节点展示层补测试，覆盖：

1. 战斗节点展示敌方角色卡区域，而不是旧的纯文本敌人说明。
2. 流式中渲染战报卡。
3. 结果态继续渲染战报卡。
4. 回退通用角色卡也能正常渲染。

## 控制器回归测试

补充挑战控制器相关测试，覆盖：

1. 进入节点后触发敌方展示卡解析，但不阻塞结算主流程。
2. 流式解析得到的 `reasoning`、`telemetry` 会进入挑战页战报展示状态。
3. fallback 结算结果仍会落到战报卡展示链路。

## 验收标准

1. `/challenge` 的战斗、精英、Boss 节点默认直接展示敌方角色卡。
2. 敌方为可补查原卡时，角色卡样式与原模板一致。
3. 敌方无法补查原卡时，稳定回退为通用角色卡快照，且仍可保存为图片。
4. 挑战中的 AI 实时故事与结算结果统一显示为流式战报卡。
5. 战报卡可保存为图片，并可导出 Markdown。
6. 敌方卡加载失败不会影响玩家继续完成节点结算。
7. 现有挑战流程、地图推进、本地存档恢复逻辑不因本次展示改造而失效。
