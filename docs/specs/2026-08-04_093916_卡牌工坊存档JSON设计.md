# 卡牌工坊存档 JSON 设计

## 背景

卡牌工坊当前的 JSON 导入/导出只存在于已生成卡牌之后，且导出内容中的插图通常只是一个 URL。这样无法在导入一个已有卡面 JSON 时恢复卡牌，也无法保证远程插图链接失效后仍能重现原卡面。

本次改动将其重构为独立的、可版本化的“卡牌工坊存档 JSON”协议，目标是让用户可以导出一个完整的卡面工作结果，并在之后通过导入直接恢复卡面。

## 目标与非目标

### 目标

1. “导入卡面 JSON”入口在卡牌尚未生成时也始终可见。
2. 导入后直接恢复卡面，不重新调用 AI。
3. 导出并恢复以下内容：
   - 卡面 `faceData`；
   - 最终主题色；
   - 插图 Base64 Data URL；
   - 插图来源；
   - 插图比例；
   - 插图缩放、水平位置和垂直位置。
4. 导出图片时优先将远程图片下载并转为 Base64，使存档可以离线恢复。
5. 使用 schema 校验导入内容，校验失败时保留当前编辑状态并显示错误。
6. 兼容读取当前已经导出的元数据 JSON，以及直接包含卡面字段的 JSON。

### 非目标

- 不把卡牌存档写入 D1 或 R2。
- 不重新执行 AI 生成流程。
- 不改变卡牌卡面渲染协议和图片裁剪数学模型。
- 不为 JSON 增加 ZIP、压缩或多文件资源管理能力。

## 存档协议

新版存档使用明确的类型标识和版本号：

```json
{
  "documentType": "maho-shojo-game-card-forge",
  "documentVersion": 1,
  "faceData": {
    "cardName": "蔷薇荆棘",
    "cardType": "character",
    "rarity": "epic",
    "cost": 5,
    "element": "dark",
    "attack": 7,
    "defense": 4,
    "hp": 8,
    "effects": [],
    "traits": [],
    "flavorText": "",
    "powerLevel": "S",
    "description": "",
    "themeColor": "#8b5cf6"
  },
  "illustration": {
    "dataUrl": "data:image/png;base64,...",
    "source": "uploaded",
    "aspectRatio": "4:3",
    "transform": {
      "scale": 1.2,
      "x": 0.1,
      "y": -0.2
    }
  },
  "createdAt": "2026-08-04T09:39:16.000Z"
}
```

字段约定：

- `documentType` 固定为 `maho-shojo-game-card-forge`。
- `documentVersion` 当前为 `1`，未来协议变化通过版本升级处理。
- `faceData` 使用现有 `GameCardFaceDataSchema`，保证导入卡面能被现有卡面组件消费。
- `illustration` 可以为 `null`，表示卡面没有插图。
- `illustration.dataUrl` 只保存图片 Data URL，不在新版协议中保存不可离线依赖的远程 URL。
- `illustration.source` 使用现有图片来源枚举：`uploaded`、`data-card`、`generated`。
- `illustration.aspectRatio` 和 `illustration.transform` 使用现有图片裁剪 schema。
- 导出使用当前最终主题色写入 `faceData.themeColor`，导入后清除单独的主题色覆盖状态，避免两个语义等价字段长期并存。

## 导入与导出流程

### 导出

1. 用户在任意状态下都能看到卡面存档区域。
2. 没有 `faceData` 时，导出按钮保持禁用；导入按钮保持可用。
3. 有卡面时，导出处理器读取当前最终卡面、图片和裁剪状态。
4. 图片已经是 Data URL 时直接复用。
5. 图片是 Blob URL 或远程 URL 时，通过浏览器 `fetch` 读取 Blob 并转换为 Data URL。
6. 图片转换失败时不生成下载文件，显示可理解的行内错误。
7. 使用新版存档 schema 序列化为格式化 JSON，并以 `卡牌_<卡名>.json` 下载。

### 导入

1. 文件选择入口始终渲染在卡面存档区域。
2. 读取文本并解析 JSON。
3. 优先识别新版 `documentType`，使用 `GameCardForgeDocumentSchema` 校验。
4. 对现有元数据 JSON，使用兼容 mapper 转换为新版内部文档；旧 `imageUrl` 仅在仍可访问时作为运行时图片来源，不会被重新导出为新版远程 URL。
5. 对直接包含 `cardName`、`rarity` 等字段的卡面 JSON，包装为无插图的内部文档。
6. 校验通过后一次性更新 `faceData`、`imageUrl`、`imageSource`、`imageAspectRatio`、`imageTransform` 和主题色状态。
7. 校验失败或文件读取失败时，不更新任何卡面状态，只显示错误。
8. 导入同一个文件时，重置 file input 的 value，保证再次选择同一文件仍会触发处理器。

## 模块边界

- `lib/schemas/game-card.ts`
  - 增加工坊存档的协议常量和 Zod schema。
  - 复用现有卡面、图片比例和裁剪变换 schema。

- `lib/card-forge/document.ts`
  - 提供创建、校验、兼容转换和序列化工坊存档的纯函数。
  - 不依赖 React，不负责读取浏览器文件或触发下载。

- `lib/card-forge/image-data.ts`
  - 提供 Data URL 判断和浏览器图片 URL/Blob 到 Data URL 的转换。
  - 远程图片读取失败时抛出带用户可读信息的错误。

- `components/card-forge/CardForgePage.tsx`
  - 管理当前编辑状态。
  - 始终渲染卡面存档区域。
  - 调用纯函数组装/解析文档，处理文件选择、下载、加载状态和错误展示。

## 错误与安全边界

- 只把通过 schema 校验的字段写入 React 状态。
- `dataUrl` 必须是图片媒体类型的 Data URL；不执行其内容，也不把 JSON 中的任意字段透传到 DOM。
- 图片转换失败时明确提示“图片无法嵌入存档”，不静默导出不完整文件。
- JSON 解析失败、协议版本不支持、卡面字段缺失分别显示可理解的错误。
- 新版导出不保存 ModelScope 令牌、AI provider 配置或其他凭据。
- Base64 会显著增大文件体积，UI 文案提示存档包含内嵌图片。

## 测试与验收

自动化测试覆盖：

1. 新版存档能通过 schema 校验并完成序列化/反序列化 round-trip。
2. 插图 Base64、图片来源、比例和裁剪变换在 round-trip 后保持一致。
3. 无插图卡面可以正常导出和导入。
4. 直接卡面 JSON 和当前元数据 JSON 可以兼容导入。
5. 非法协议、非法卡面字段和非图片 Data URL 会被拒绝，且不产生部分状态。
6. 远程图片转 Data URL 成功和失败路径均有覆盖。
7. 卡牌未生成时，页面仍渲染导入入口，导出入口不可用。

手动验收覆盖：

- 上传 PNG/JPG/WebP 后导出，再导入，卡面和图片一致。
- AI 生成图片后导出，再断网导入，图片仍能显示。
- 调整四种比例、拖拽、缩放和精细位置后导出，再导入，裁剪构图一致。
- 在初始空白页面直接导入已有卡面 JSON，卡面正常出现。
- 导入损坏 JSON 后当前卡面不被清空。
