# 竞技场快捷视图设置与隐藏上下文边界设计

## 背景

用户反馈 `/battle`（怀旧简介版竞技场）与 `/arena`（完整版竞技场）之间存在设置持久化冲突：

- 进入 `/battle` 后，完整版中的长度、历战读写等设置会被改回默认值。
- 返回 `/arena` 后，用户需要重新逐项调整。

代码现状表明，两个页面共用同一个 `zustand persist` store，持久化 key 为 `arena-storage`。同时，`/battle` 在挂载时会执行 `applyBattleLiteDefaults()`，主动把部分共享状态写回默认值，而不是仅在本页展示时使用回退值。

## 目标

本设计要解决两个问题：

1. 保证 `/battle` 作为 `/arena` 的快捷视图，不再覆写完整版设置。
2. 明确“隐藏但会影响生成结果”的高级上下文，在快捷视图中的继承与展示边界，避免出现静默生效的黑盒行为。

## 产品定位结论

`/battle` 的定位是 `/arena` 的“快捷视图”，而不是独立产品或独立工作台。

因此应遵循以下原则：

- 两个页面共享同一套设置语义。
- `/battle` 不应创建自己的另一套默认配置并反向污染 `/arena`。
- `/battle` 与 `/arena` 默认应对同一份当前工作区产生一致结果。
- 如果 `/battle` 隐藏了某些会影响生成的高级输入，则必须向用户显式展示其存在，而不是静默继承。

## 状态边界划分

### 一、设置型状态

这类状态属于“用户偏好”或“生成参数设置”，应持续共享，并以 `/arena` 作为唯一真实来源。

包括但不限于：

- `storyLength`
- `selectedLanguage`
- `generationMode`
- `arenaFreeRankingEnabled`
- `settings.readArenaHistory`
- `settings.readArenaHistoryLimit`
- `settings.writeArenaHistory`
- `settings.readCurrentState`
- `settings.writeCurrentState`
- `settings.readNarrativeHistory`
- `settings.readNarrativeHistoryLimit`
- `settings.writeNarrativeHistory`
- `settings.streamTransport`
- `settings.userGuidance`
- `settings.battleReportCardWidthMode`
- `settings.battleReportCardWidthPx`

设计要求：

- `/battle` 不再在页面挂载时把这些值重置为默认值。
- `/battle` 对未展示的设置不做覆盖写回。
- `/battle` 对已展示的设置可继续直接编辑共享 store。

### 二、内容型上下文

这类状态不是“偏好设置”，而是“当前工作区正在生成所使用的内容上下文”。

包括但不限于：

- 主情景 `scenario`
- 辅助情景 `auxScenarios`
- 问卷选择 `selectedQuestionnaires`
- 判定事件链 `adjudicationEvents`
- 参战角色 `combatants`
- 分队信息 `teams`

设计要求：

- `/battle` 与 `/arena` 默认共享同一份当前工作区。
- 进入 `/battle` 时不自动清空这类状态。
- `/battle` 默认生成结果应与 `/arena` 在相同工作区下保持一致。

## 隐藏高级上下文的处理原则

`/battle` 虽然不展示完整的高级编辑面板，但这些高级上下文依然会进入生成请求，因此不能当作“不存在”。

结论如下：

1. 不静默清空。
   进入 `/battle` 时，不自动清除辅助情景、问卷、判定事件等上下文。

2. 不静默生效。
   `/battle` 必须增加一个只读摘要区域，明确告知当前继承了哪些高级上下文。

3. 保持一致性优先。
   默认生成行为以“与 `/arena` 结果一致”为最高优先级。

4. 如未来需要“纯简洁生成”模式，应新增显式开关，在生成请求阶段过滤上下文，而不是在进入页面时修改共享 store。

## 推荐交互方案

在 `/battle` 增加一个轻量只读提示区块，例如：

- 当前继承完整版高级上下文：辅助情景 2 个、问卷 1 个、判定事件 4 条
- 历战读取：开启（3 条）
- 当前状态写回：开启
- 叙事历史：关闭
- 前往完整版竞技场编辑

该区块目标：

- 让用户知道当前结果不是只由本页可见控件决定。
- 保留快捷视图的轻量感，不在 `/battle` 复制全部高级 UI。
- 为排查“为什么这次结果不一样”提供直接线索。

## 不推荐方案

### 方案 A：进入 `/battle` 时自动恢复简洁默认值

问题：

- 直接污染完整版设置。
- 违背“快捷视图”定位。
- 用户回到 `/arena` 后需要重新配置。

### 方案 B：`/battle` 独立持久化，未配置时回退 `/arena`

问题：

- 本质上变成两个产品。
- 用户难以理解究竟哪一套设置才是当前生效的真实值。
- 与快捷视图定位不符。

### 方案 C：进入 `/battle` 时自动清空隐藏高级上下文

问题：

- 会破坏用户在 `/arena` 的当前工作区。
- 清空动作不易感知，风险高。
- 让页面切换变成带副作用操作。

## 建议的实现方向

### 第一阶段：修复设置覆写问题

- 删除或重构 `applyBattleLiteDefaults()`。
- `/battle` 挂载时不再写入共享默认值。
- 对未展示设置仅读取，不重置。

### 第二阶段：统一快捷视图工作区语义

- 停止在进入 `/battle` 时清空 `auxScenarios`、`selectedQuestionnaires` 等内容型上下文。
- 保持 `/battle` 与 `/arena` 使用同一份当前工作区。

### 第三阶段：补充高级上下文可见性

- 在 `/battle` 增加“继承的高级上下文”只读摘要。
- 摘要中展示数量与关键状态，并提供跳转 `/arena` 的编辑入口。

### 第四阶段：后续可选增强

- 为 `adjudicationEvents` 增加来源元数据，如 `combatant`、`mainScenario`、`auxScenario`、`manual`。
- 如果未来需要“仅使用当前页可见内容生成”，通过显式开关在请求构建阶段做过滤。

## 数据流与行为要求

生成请求构建阶段应遵循：

- 所有共享设置从统一 store 读取。
- 所有当前工作区上下文默认继续参与请求。
- `/battle` 的只读摘要与最终请求保持一致，不允许摘要与实际生效内容脱节。

页面切换阶段应遵循：

- `/arena -> /battle` 不能带来隐藏副作用。
- `/battle -> /arena` 不能导致用户发现设置被被动改写。

## 错误处理

- 若本地持久化中缺失部分字段，继续沿用 store merge 逻辑补默认值。
- 若只读摘要无法解析某类上下文，应至少显示“存在高级上下文，建议前往完整版检查”，不能静默忽略。
- 若后续引入“纯简洁生成”开关，必须在 UI 中明确说明哪些上下文将被忽略。

## 验收标准

1. 用户在 `/arena` 修改长度、历战读写、叙事历史、战报宽度等设置后，进入 `/battle` 不会导致这些设置被改回默认值。
2. 用户从 `/battle` 返回 `/arena` 后，设置值保持不变。
3. `/battle` 默认生成结果与 `/arena` 在同一工作区下保持一致。
4. 当存在辅助情景、问卷或判定事件时，`/battle` 能明确显示其存在。
5. 页面切换本身不再产生隐式清空或重置副作用。

## 测试建议

- 为 store 行为补单元测试，覆盖“进入 `/battle` 不覆写共享设置”。
- 为页面行为补测试，覆盖 `/arena -> /battle -> /arena` 的设置保持。
- 为请求构建补测试，覆盖 `/battle` 在存在辅助情景、问卷、判定事件时的继承行为。
- 为只读摘要补渲染测试，覆盖有无高级上下文两种情况。

## 决策摘要

最终决策为：

- `/battle` 继续作为 `/arena` 的快捷视图。
- 共享完整版设置。
- 共享当前工作区。
- 不在进入 `/battle` 时清空或重置隐藏上下文。
- 对隐藏但会影响结果的高级上下文，提供只读可见性，而不是静默生效。
