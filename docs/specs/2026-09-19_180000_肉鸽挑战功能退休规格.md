# 肉鸽挑战功能退休规格

状态：accepted
日期：2026-09-19
适用范围：`/challenge` 肉鸽挑战产品、专属 API、内测入口与专属实现。

## 决策与依据

维护者确认肉鸽挑战是已放弃的半成品，授权从当前产品中移除。退休依据是产品停止投入和明确的维护负担，
不是以没有 D1 记录推断无人使用；其进度原本存放在浏览器 IndexedDB，服务器数据库不足以证明实际玩家数。

退休前专属实现与测试共 74 个追踪文件、14,891 行，包含页面、两组 API、地图、节点裁定、存档、世界定义和 25 个测试文件。
其中公共卡可渲染性判断已被排行榜缓存复用，需要保留并移到共享缓存目录。没有发现挑战专属公共图片资产。

本规格取代以下文件中要求继续提供挑战产品的口径，其设计过程保留为历史材料：

## 退休后的行为

- 移除 `/challenge` 页面及内测配置、导航登记。旧页面 URL 不再是有效产品入口，交由现行未知路由策略处理。
- 移除 `/api/challenge/enemy-candidates` 与 `/api/challenge/adjudicate-stream`。旧客户端不能再通过这些端点选敌或启动 AI 裁定。
- 移除专属页面组件、领域与服务器实现、公开卡批量读取 repository、专属测试，以及仅供挑战的限流 action 标识。
- 保留 Arena、排行榜、PVP、魔法茶会、AI 连续会话和共享公开卡缓存。共享角色可渲染性判断移入 `apps/web/lib/public-card-cache/`，其行为不变。

## 数据和兼容边界

本次不执行远程数据库操作、D1 migration、生产部署或用户浏览器清理。共享 IndexedDB 名称、版本和原有 store 布局不变，
挑战的旧 store 定义仍保留，避免同一版本下新旧数据库结构分歧，也不自动删除已有用户本地存档。
退休后没有产品入口读写这些挑战存档；本次不新建存档导出产品。

公开卡缓存仍能识别历史 `challenge-sidecar` 来源，排行榜详情继续要求完整 `public-data-card-api` 来源，
防止旧的简化侧载卡被误认为完整详情。移除挑战 sidecar 写入入口，现行写入统一由公开卡读取链路负责。

这次删除预期减少维护和构建范围，并停止上线后对已移除端点的正常业务调用；不承诺固定 AI 费用或 D1 存储节省。

## 验证要求

确认现行代码没有导入已删除挑战模块；保留的共享公共卡缓存、排行榜详情、连续会话存储与限流测试通过；
完成受影响 Web 静态检查，以及涉及共享 package 的相应检查。历史文档和明确保留的 IndexedDB/cache 兼容标识可继续包含 `challenge`。

代码退休不表示生产已经切换。发布沿用现有部署流程；需要恢复产品时采用代码回滚，保留的本地 store 不需要本次提供数据回滚。
