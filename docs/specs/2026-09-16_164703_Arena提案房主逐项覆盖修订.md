# Arena 提案房主逐项覆盖修订

> 2026-09-21 澄清：在线数据卡版本规则已由[产品一致性修订 §1.1 的 latest overlay](./2026-08-31_150000_Arena多人产品一致性与既有Arena复用修订.md#11-2026-09-20-online-datacard-latest-语义-overlay)取代。在线卡以 `id + kind` 为身份，单纯 `versionToken` 漂移不再属于引用冲突；下文不可覆盖的版本漂移规则仅继续适用于 preset。删除、无权限、审核失效、类型不兼容和非法正文仍不得通过 override 绕过。

状态：`accepted / implemented`

## 1. 决策与取代关系

成员 Proposal 表达目标意图；`expectedBase` 保留为审阅上下文和默认安全合并条件，不再禁止房主明确选择提案值。
本修订覆盖 GMR-08 的同目标冲突一律拒绝口径，细化 Arena 多人 v1 §7.2「由房主决定是否接受」。
其余认证授权、引用验证、资源上限、原子提交、viewer isolation、unknown/no-blind-replay 约束不变。
成员旧 baseline 草稿仍可提交；不强制 rebase，不自动丢弃 dirty draft。

## 2. 接受与覆盖

普通接受保持 CURRENT=BASE 可应用、CURRENT=PROPOSED 为 no-op 的三方语义。
对其余可覆盖冲突，房主 MUST 明确逐项选择「采用提案值」，才能把 CURRENT=C 改成 PROPOSED=B。
此操作只作用于所选 typed changes，不得将成员整份旧工作副本覆盖到 Room。
首期允许 setter、renameTeam、assignTeam 与 remove 的基准冲突；目标及赋值队伍必须存在。
新增对象发生 key 碰撞、完整列表重排冲突、引用版本漂移不可覆盖；权限、schema、依赖闭包和 atomic group 永不绕过。
移除已不存在对象和已满足目标继续作为 no-op；无效引用不得隐式升级到 latest。
所有选中项在同一次 RoomActor transition 中全成或全不成，失败保留 pending Proposal 和当前配置。

## 3. Resolve 请求兼容

在现有请求增加可选 `overrideChangeIds: string[]`，MUST 唯一、有界且是显式 `selectedChangeIds` 的子集。
非空 override MUST 携带房主审阅时的 `expectedRevision`；reject 不得携带 override 字段。
旧请求不带 override 保持既有行为；新客户端仅在非空时发送此字段，旧 strict 服务端拒绝而非静默丢弃。
API preflight 与最终 actor transition MUST 都核对 override 的 exact revision，阻止审阅 C 后未见 D 就覆盖 D。
普通接受继续不因无关 revision 前进失败；不得把 override fence 扩大到所有 Proposal。

## 4. 审阅界面

可覆盖冲突显示基准、当前值、提案目标和「保留当前值／采用提案值」，不是不可恢复的红色错误。
关键文本须可完整展开阅读，不得仅用截断摘要确认覆盖；不可覆盖项明确说明原因。
revision/epoch/Proposal 内容变化后，旧覆盖决定 MUST 立即失效；提交使用确认时的 revision。
有未裁决冲突或无效选项时禁用接受；仍可取消相关项、保留当前值或拒绝整份提案。
成员 stale 提示改为草稿仍可提交，冲突由房主审阅；房间实例变化仍要求重新同步。
接受后的 Room authority 继续经现有 controller 和房主 workspace reconciliation 收敛，不另建覆盖策略存储。

## 5. 影响清单与非目标

Canonical DTO：`packages/contracts/src/room-http.ts`；内部 command 复用同一 resolve 约束。
领域执行：`multiplayer-core` 的 staged preview/apply 与 state machine；不改 Proposal 持久格式。
API：resolve preflight、引用校验及 actor command；Web client/controller 透传 canonical DTO，unknown 不自动重试。
UI：房主提案审阅、成员 stale 文案；测试覆盖 schema、core、actor、API、client/controller 与交互。
HTTP 路径、Room snapshot/event、Redis checkpoint schema 不变；不新增 D1 migration、依赖、CRDT、全局锁或审计服务。
不修改已冻结的运行中 generation；accepted change 仍通过现有 provenance 进入后续生成。
