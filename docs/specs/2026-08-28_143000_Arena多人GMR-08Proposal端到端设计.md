# Arena 多人 GMR-08 Proposal 端到端设计

日期：2026-08-28

状态：`accepted / implemented`

实现基线：`a3538a950faab9f608fd64fa4769d3abe0a00a2a`

适用 Goal：`GMR-08 Proposal E2E`

## 1. Objective

在 GMR-05/GMR-07 已完成的 Hono + Redis Room runtime 与既有 `/arena` UI 上，接通 member 本地 working copy、typed
diff、Proposal submit/withdraw、host per-change review/partial resolve、RoomActor conditional checkpoint 与 WebSocket
实时更新。成功响应不得早于 Redis checkpoint；任一 unknown mutation 不得自动重放。

本设计不推翻既有 accepted ADR/spec。客户端不可信、服务器权威、secret 隔离、Legacy/Better Auth、Arena v1
authority/wire、D1/Redis 数据所有权与非幂等 no-blind-replay 继续有效。

## 3. Public HTTP contract

在既有 base path 下新增：

```text
POST /api/arena/rooms/v1/:roomId/proposals
POST /api/arena/rooms/v1/:roomId/proposals/:proposalId/resolve
POST /api/arena/rooms/v1/:roomId/proposals/:proposalId/withdraw
```

submit body 仅允许：

```ts
type ArenaRoomProposalSubmitRequest = {
  proposalId: string;          // client intent identity，不是 authority
  expectedRoomEpoch: string;
  baseRevision: number;
  changes: ArenaProposalChange[];
};
```

resolve body 仅允许：

```ts
type ArenaRoomProposalResolveRequest = {
  expectedRoomEpoch: string;
  expectedRevision: number;    // 绑定 ref preflight 所观察的 Room config
  resolution: 'accept-selected' | 'reject';
  selectedChangeIds?: string[];
};
```

withdraw 只携带 `expectedRoomEpoch`。三类请求均使用 strict schema、现有 control body bytes 上限、受信 auth actor、
exact Origin/cookie mutation guard、account+room+operation Redis 限流和 `no-store`。

服务端 MUST 注入 `roomId`、`authorUserId`、`proposalVersion`、`status=submitted`、`createdAt`；客户端不得提交
author/status/time/account/role/capability/authority state。`proposalId` 是稳定 intent key：同 room/epoch/author、同
baseRevision/changes 可对账为 idempotent；同 ID 不同 body、terminal replay 或跨 authority 复用返回 conflict。服务端时间不
参与客户端幂等比较。

mutation response 只返回：protocol/room/epoch/controlSeq/revision/proposalId/status/result。不得返回 account ID、完整
authority state、deadline、terminal ledger、Redis receipt、完整卡片、credential 或内部 conflict payload。

## 4. DataCardRef authority

新增 API-owned `ArenaDataCardRefVerifier`，只读取 D1 metadata：`id/user_id/type/is_public/review_status/updated_at/
deleted_at`。它不得返回或记录 `data` 正文。

校验规则：

- ref 必须是 canonical `data-card:<id>`；preset digest 与 host-local stub 不查询 D1；
- card 必须存在且未删除；`character` 只接受 character card，`scenario` 只接受 scenario card，`material` 可以引用
  现有允许作为 Arena material 的 online card type；
- `versionToken` 必须与 canonical `updated_at` 精确相同；不得 fallback 到 latest；
- card 必须 public + approved，或为当前 Room host 所有且 host 仍可读取；member 私卡不会因加入 Room 获得临时共享；
- D1 缺失、超时、畸形元数据或未知权限一律 fail closed；错误响应只给稳定 code，不泄漏卡是否私有或内容。

submit 前校验 Proposal 引入的新 online refs；resolve `accept-selected` 前先用同一 snapshot 纯应用 selected changes，再
校验 resulting shared config 的全部 canonical online refs。内部 resolve command 新增 `expectedRevision` 并在 state-machine
apply 边界精确检查，使 D1 preflight 不能应用到不同 Room revision。D1 与 Redis 无跨库事务；因此 generation reservation
仍 MUST 在 GMR-09 再验证 frozen config，权限/版本变化不能靠一次 Proposal 检查永久放行。

## 5. Viewer-specific projection

Redis checkpoint 继续保存 host review 所需的完整 typed Proposal，但对外 snapshot/event 按 viewer 投影：

- host：可见全部 pending Proposal；
- author member：只可见自己的完整 pending Proposal/status；
- 其他 member：`snapshot.proposals` 过滤为空或只保留其本人 Proposal，不看到其他作者 changes/guidance/expectedBase；
- host-local 完整 payload、private card data、Provider config 与 credential 在所有 viewer 均不可见。

HTTP create/join/session 使用 projected snapshot。WebSocket initial/replay/live fan-out 对允许 viewer 发送原 Proposal event；
对不允许 viewer 使用过滤后的 `room.snapshot` 作为 sequence-preserving control event，保持现有 protocol v1 schema 与
`controlSeq` 连续，不增加包含 Proposal ID 的旁路摘要。viewer projection 只发生在 API adapter，内部 RoomActor checkpoint/
replay 仍保持单一权威事实。

实施和独立审查后冻结以下细化：

- replay ring 只在每个 terminal Proposal entry 内保存最小 `proposalAuthorUserId` 投影上下文；该字段不进入
  public wire、snapshot 或 Redis checkpoint；
- mixed-visibility replay 必须逐 event 投影：隐藏 Proposal 转换为同 `controlSeq` 的过滤 snapshot，不得因
  批次中一个隐藏事件丢弃作者自己的 terminal event；
- checkpoint save 抛异常代表提交结果未知：当前 Actor 必须立即 quarantine，不再服务 stale snapshot/session，也不
  自动重放 mutation；下次权威读从 Redis checkpoint 恢复为新 epoch；
- Room mutation Origin 使用 literal exact allowlist；Hosted CORS 的 wildcard entry 不得授权 Room mutation；
- URL-addressable `proposalId` 是 opaque key，但精确的 `.` 和 `..` 不可接受，避免 path identity 漂移。

## 6. Web local working copy 与 review

member 从当前 projected snapshot 显式建立 detached `{baselineEpoch, baselineRevision, baselineConfig, workingConfig}`。
working copy 只包含 `ArenaRoomSharedConfig` 白名单字段，编辑时不联网。由于 safe snapshot 无法恢复完整 online/local card
payload，GMR-08 使用受限 Shared Config editor；不得把 stub 伪装成完整 BattleStore combatant，也不得让 member UI 触发
host-only generation/write。

preview 使用 `diffArenaSharedConfig(baselineConfig, workingConfig)`，逐项显示安全摘要、`expectedBase`、dependency/
atomic group，并以 `validateProposalChanges` 校验用户选择。host inbox 来自 projected pending Proposals，逐项选择后仍由
server 再做 schema/capability/precondition/ref validation；client conflict 仅是提示，不是 authority。

`room.config.updated` 到达时：未建立/未修改 draft 可显式重新同步；dirty working copy 不被自动覆盖，而标记 stale，并允许
用户预览旧 baseline Proposal。Proposal submit/resolve/withdraw 网络、5xx、畸形 2xx 均进入 operation unknown；controller
只等待 control event/reconnect snapshot 或用户显式对账，不自动 retry。

unknown fence 必须绑定 `{operation, proposalId}`：无关 Proposal event 只更新 projected session/cursor，不解除冻结。
submit 只能由同 ID submitted/updated/terminal 事件解锁；resolve/withdraw 只能由同 ID terminal 事件解锁。
当 reconnect cursor 已在当前序号时，显式对账先 `GET session` 取得当前 viewer-projected 权威 snapshot，再使用 fresh
ticket 重连；不得因 WSS 无新 event 而永久锁定，也不重放原 mutation。

## 7. Stopping condition

GMR-08 只有同时满足以下条件才能 `DONE`：

- member snapshot → detached working copy → typed diff/preview → submit/withdraw 闭环；
- host per-change accept-selected/reject 与 dependency/atomic selection 闭环；
- stale same-target、changed/deleted/permission-changed/wrong-kind ref、old epoch/revision、Redis conflict/failure 均 fail closed；
- checkpoint-before-success、control event sequence/replay/snapshot 与 Proposal viewer isolation 有可执行证据；
- arbitrary JSON、敏感字段、host-local/private payload negative fixtures 通过；
- feature off、unauthenticated 与 single-player 行为无回归；
- targeted/full package/workspace validation 通过，独立 architecture/security/test review 的 Critical/Important 清零，Minor
  修复或有明确非阻塞理由；
- 没有 production deploy/migration/write、Redis flush、secret/Access/credential、release/tag/push/history rewrite。

## 8. 回滚

contract/core projection、API verifier/service/routes、Web client/controller 与 UI/editor 分为独立 atomic commits，按逆序
revert。默认 feature flag 继续关闭，可作为即时暴露面止血，但不替代代码回滚。GMR-08 不新增 production schema migration，
不需要数据恢复。
