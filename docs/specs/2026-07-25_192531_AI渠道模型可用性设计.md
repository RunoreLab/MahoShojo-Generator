# AI 渠道 / 模型可用性设计

设计时间：2026-07-25 19:25:31（Asia/Shanghai）  
状态：`approved-for-planning`  
参考实践：CLIProxyAPI / 聚合网关常见的「近 1 小时成功率」展示，帮助用户在选择前避开实质不可用的渠道与模型。

## 1. 背景与目标

### 1.1 问题

用户在 `AiProviderSelector` 中选择渠道与模型时，无法得知近期是否可用。当前只能反复发起生成并等待失败，体验差，也浪费限流额度与上游配额。

### 1.2 目标

1. 基于**真实用户流量**聚合渠道/模型可用性（近 1 小时成功率为主）。
2. 在 **AI 能力供应商选择器**上以轻量百分比展示，便于快捷选择。
3. 控制 **D1 rows read**：选择器读路径以快照 + edge cache 为主，避免对明细或大窗口现场 `GROUP BY`。
4. 近 1 小时无足够样本时，明确「暂无近期数据」，并可附 **24 小时**参考，不伪装成实时状态。
5. **系统配置渠道**特殊口径：余额不足、Key 不可用等也计入失败，便于判断官方配置是否实质不可用。
6. **自定义（BYOK）渠道**不把个人 Key/余额问题算进共享可用性。

### 1.3 非目标（一期）

1. 主动健康探测 / 付费测活。
2. 管理后台大盘、错误明细面板、延迟分位、成本估算。
3. 按可用性自动排序或改写用户已选配置。
4. 用户级或 API Key 级私有成功率。
5. 展示调用次数（UI 以百分比为主；空间不足时仅百分比或灰态占位）。
6. 强制一期上 cron（允许惰性重建；cron 为可选补强）。

## 2. 决策摘要

| 项 | 决策 |
|---|---|
| 数据来源 | 真实流量聚合 |
| 架构 | 分桶写入 + 快照读取（方案 B） |
| 覆盖维度 | catalog 全部预置 + 自定义 `modelId` 单独统计 |
| 采集范围 | 所有 `generateWithAI` / 流式生成的**上游 attempt** |
| 系统渠道失败 | 含余额不足、Key 无效等账号/配额类错误 |
| 自定义渠道失败 | 仅上游/模型侧故障；个人 Key/余额 → `excluded` |
| 无 1h 数据 | 「暂无近期数据」+ 可选 24h 参考 |
| UI | 轻量百分比；不展示次数 |
| 系统记分键 | 用户选择的 catalog `modelId`（含 `default`），不暴露内部 upstream 名 |
| 读成本 | 快照 1 行级 + edge cache ~45s |

## 3. 总体架构

```text
AI 生成 attempt 结束
  → classifyOutcome(system | custom, error)
  → recordAiChannelOutcome  (upsert 5min bucket)
  → (不阻塞主流程)

选择器 / 公共客户端
  → GET /api/ai/channel-availability
  → edge cache (≈45s)
  → 读 snapshot 1 行；若过期则惰性重建后写回
  → 返回 entries（百分比 + status，无 sampleCount）
  → AiProviderSelector 徽章展示
```

### 3.1 写路径

- 统一入口：`lib/ai.ts` 的 `generateWithAI` 以及各流式路径在**每次上游 attempt** 结束时记分。
- 同一用户请求若轮询多个 provider，则**每个 attempt 各记一笔**。
- 记分失败只打日志，**不得**影响生成结果或延迟主路径（try/catch；允许 fire-and-forget）。

### 3.2 读路径

- 公共 API **只读快照**，不扫桶表给终端用户。
- 快照过期或缺失时惰性重建；用短 TTL 单飞避免惊群。
- 重建失败：若存在较新的陈旧快照（例如 &lt; 15 分钟）可降级返回并视为可接受陈旧；否则返回 catalog 全 `unknown`。

## 4. 数据模型

### 4.1 `ai_channel_availability_buckets`

分桶原始计数，供重建快照与排障。

| 字段 | 说明 |
|---|---|
| `bucket_start` | 5 分钟对齐的 UTC/ISO 起点（与 PK 组成部分） |
| `provider_id` | 如 `system`、`kourichat`、catalog id |
| `model_id` | catalog 或用户自定义 modelId（有长度上限，与现有自定义 model 限制对齐） |
| `success_count` | 成功次数 |
| `failure_count` | 计入可用性的失败次数 |
| `excluded_count` | 不计入成功率的次数 |
| `last_error_class` | 可选，最近一次计入失败的粗分类 |
| `updated_at` | 最后更新时间 |

- **主键**：`(bucket_start, provider_id, model_id)`
- **保留**：约 48 小时；维护脚本或惰性删除更旧桶
- **索引**：`bucket_start`（范围扫描重建快照）

### 4.2 `ai_channel_availability_snapshot`

| 字段 | 说明 |
|---|---|
| `id` | 固定 `'default'`（一期单快照） |
| `payload_json` | 见 §6 响应结构的可序列化形态 |
| `updated_at` | 重建完成时间 |
| `source_bucket_max` | 可选，重建时用到的最大桶起点，便于调试 |

快照 TTL：**60–120 秒**（与 edge cache 解耦；edge cache 可略短，如 45s）。

### 4.3 维度约定

- **系统**：`provider_id = 'system'`，`model_id` = 用户在选择器中选中的 system 模型值（含 `default`、具体模型 id 等）。
- **自定义渠道**：catalog `providerId` + **实际请求**的 `modelId`（含 `__custom_model_id__` 解析后的真实 id）。
- **不**把系统内部轮询到的 upstream 提供商名作为一期公共维度（避免与选择器选项对不上）。
- 系统在内部 fallback 到其他 upstream 时：仍记在**用户选择的 catalog model** 上（成功/失败反映「选该 system 选项时的实际体验」）。

### 4.4 基数治理

1. 公共响应必须包含 catalog **全部预置** `(providerId, modelId)`（无样本 → `unknown`）。
2. 额外包含近 24h 桶中出现过、且不在 catalog 的自定义 model。
3. 自定义额外条目按内部样本数降序，**硬顶 200**（常量可配）。
4. `model_id` 写入前做与现有 `MAX_CUSTOM_AI_MODEL_ID_LENGTH` 一致的截断/拒绝，防止异常超长键。

## 5. 记分口径

### 5.1 Outcome

| Outcome | 计入分母 | 含义 |
|---|---|---|
| `success` | 是 | 上游返回可用结果，完成本次 attempt 的成功主路径 |
| `failure` | 是 | 反映渠道/配置实质不可用（见下） |
| `excluded` | 否 | 不反映共享渠道可用性 |

\[
\mathrm{successRate} = \frac{\mathrm{success}}{\mathrm{success}+\mathrm{failure}}
\]

- `sampleCount = success + failure`（**仅服务端**用于最小样本与截断排序；**公共 API 与 UI 不展示次数**）。
- 仅有 `excluded`、分母为 0 → 视为无样本。

### 5.2 系统渠道（`providerId === 'system'`）

下列记 **`failure`**（便于发现官方 Key/额度问题）：

- 余额不足、quota exceeded、billing 类错误
- API Key 无效、过期、吊销、权限不足（401/403 等认证类）
- 上游账号级不可用
- 超时、网络错误、5xx、模型不存在/不支持
- 上游容量型 429（以及无法与「个人额度」区分时的 429，系统侧默认计 failure）

下列记 **`excluded`**：

- 本站限流 / Turnstile / 冷却
- 用户取消、客户端中断（能区分时）
- 未真正发往上游的本地校验失败
- 上游已成功返回后的本地 JSON/schema 解析或修复失败（偏遵从性；记 `excluded` 并可选 `error_class`）

### 5.3 自定义渠道（BYOK）

记 **`failure`**：

- 超时、网络、5xx
- 模型不存在 / 不支持
- 上游服务/模型容量型 429（非明确的个人 Key 配额时）

记 **`excluded`**：

- 用户 Key 无效、权限不足
- **该用户 Key** 余额不足 / 个人额度用尽（明确 billing/quota 归属个人时）
- 本站限流、用户取消、未发上游的本地错误
- 上游成功后的本地解析/修复失败

### 5.4 错误分类实现要点

- 在现有 `lib/ai/utils/error-extraction` 或等价层集中映射 `error → { outcome, errorClass }`，并传入 `isSystemChannel` 开关。
- 分类单测覆盖：系统 vs 自定义 ×（billing / 401 / 429 / timeout / cancel / parse）。
- 无法可靠区分时：系统渠道偏向 `failure`；自定义渠道对「像个人凭证」的错误偏向 `excluded`。

### 5.5 最小样本

- 常量 `MIN_SAMPLE_COUNT = 3`（可配置）。
- 近 1h `sampleCount < 3` → 不把 1h 作为 primary 数值窗口。
- 近 24h 同样用该门槛作为 reference。
- 两窗口都不足 → `status: unknown`，`successRate: null`。

## 6. 公共 API

### 6.1 `GET /api/ai/channel-availability`

- Runtime：Edge
- 鉴权：无（仅聚合指标，无 PII、无 Key）
- 缓存：`withEdgeCache`，TTL 约 **45 秒**；`Cache-Control` 与之对齐的 public 短缓存

#### 响应（概念）

```ts
type AvailabilityStatus = 'healthy' | 'degraded' | 'poor' | 'unknown';

type AvailabilityWindowRate = {
  window: '1h' | '24h' | 'none';
  successRate: number | null; // 0–1；unknown 时为 null
  status: AvailabilityStatus;
};

type ChannelAvailabilityEntry = {
  providerId: string;
  modelId: string;
  primary: AvailabilityWindowRate;
  /** 仅当 primary 非近 1h 有效数值时，若 24h 足够样本则附带 */
  reference?: {
    window: '24h';
    successRate: number;
    status: Exclude<AvailabilityStatus, 'unknown'>;
  };
};

type ChannelAvailabilityResponse = {
  success: true;
  generatedAt: string;
  windows: {
    '1h': { durationSeconds: 3600 };
    '24h': { durationSeconds: 86400 };
  };
  minSampleCount: number;
  entries: ChannelAvailabilityEntry[];
  /** 可选：快照是否陈旧降级 */
  stale?: boolean;
};
```

**注意：** 公共 JSON **不包含** `sampleCount` / `excludedCount`（减小包体，符合 UI 不展示次数）。

#### 状态阈值

| status | successRate |
|---|---|
| `healthy` | ≥ 0.90 |
| `degraded` | ≥ 0.70 且 &lt; 0.90 |
| `poor` | &lt; 0.70 |
| `unknown` | 无足够样本 |

### 6.2 快照重建算法（服务端）

1. 读取 `bucket_start >= now - 24h` 的桶行。
2. 按 `(provider_id, model_id)` 汇总全 24h；再按 `bucket_start >= now - 1h` 得到 1h。
3. 对每个 pair 计算 rate / status；应用最小样本规则。
4. 组装 entries：catalog 全量 ∪（24h 有样本的自定义，顶 200）。
5. 写入 snapshot 单行。

惰性重建与读 API 同进程时可加内存单飞；多 isolate 下允许少量重复重建（可接受）。

### 6.3 内部写接口

```ts
recordAiChannelOutcome(input: {
  providerId: string;
  modelId: string;
  outcome: 'success' | 'failure' | 'excluded';
  errorClass?: string;
}): Promise<void>
```

- 仅服务端调用。
- 对齐 5 分钟 `bucket_start` 后 UPSERT 计数。

## 7. 选择器 UI

组件：`components/AiProviderSelector.tsx`（可抽小组件如 `ChannelAvailabilityBadge`）。

### 7.1 展示

- 渠道下拉与模型下拉的选项行均可显示可用性。
- **默认只显示百分比**（如 `96%`）；**不显示次数**。
- 空间极有限时：仅百分比，或 `unknown` 时用灰色 `—`。
- 文案优先级：
  1. 近 1h 足够样本 → `96%`（颜色随 status）
  2. 近 1h 不足、24h 足够 → 优先 `暂无近期 · 24h 91%`；更窄布局可缩为 `24h 91%`
  3. 都不足 → `暂无数据` 或 `—`

### 7.2 颜色

与现有 battle-lite / 选择器语义色协调：

- healthy：绿系 subtle
- degraded：琥珀
- poor：红/玫
- unknown：灰

### 7.3 行为

- hydration 后请求一次 availability；失败**静默**，不阻塞选择与本地存储恢复。
- 不按可用性重排 catalog 顺序。
- 不自动修改用户已选 provider/model。
- 百分比格式：整数百分比（四舍五入）；`null` 不显示 `0%` 以免误解。

## 8. 无数据与冷启动

| 场景 | 表现 |
|---|---|
| 新部署无调用 | 全部 unknown / 暂无数据 |
| 冷门自定义 model | 同上直至计入样本 ≥ 3 |
| 大量 excluded、无 success/failure | 同无样本 |
| 快照重建失败且有 &lt;15min 旧快照 | 返回旧数据，`stale: true`（UI 可忽略该字段一期） |
| 无任何快照 | 全 unknown，选择器仍可用 |
| edge 缓存 | 最多额外约 45s 延迟 |

## 9. 接入点清单（一期）

凡最终走到 `generateWithAI` 或独立流式上游调用的路径，均需在 attempt 结束记分，包括但不限于：

- `lib/ai.ts`（核心；优先保证）
- 竞技场 `generate` / `generate-stream` 及 session 续写等流式路径（避免与 core 双计：能委托 core 则只在 core 记）
- 问卷/角色详情、残兽、情景、升华、free、tavern、creator、challenge 判定等

**去重原则：** 若流式只是包装 `generateWithAI`，只在一处记分；若流式自行 fetch 上游，必须在该路径显式记分。

## 10. D1 与性能预算

| 操作 | 预期 |
|---|---|
| 每次上游 attempt 写 | 1 次桶 UPSERT |
| 选择器读（edge 命中） | 0 D1 |
| 选择器读（edge 未命中、快照有效） | **1 行**快照 |
| 快照重建 | 近 24h 桶范围扫描；被 TTL + 单飞限制频率 |
| 桶清理 | 删除 48h 前数据（脚本或随重建附带限额删除） |

禁止：在公共读路径对 `battle_report_generations` 或未分桶明细做现场聚合。

## 11. 测试与验收

1. **分类单测**：系统/自定义 × 错误类型 → outcome 矩阵。
2. **聚合单测**：桶汇总、最小样本、1h→24h 回退、阈值边界（0.90 / 0.70）。
3. **API 测**：快照命中、惰性重建、空数据、自定义硬顶、响应无 sampleCount。
4. **选择器测**：百分比文案、24h 参考、unknown、请求失败不崩溃。
5. **手工**：system 与某一 BYOK 各触发成功/失败，在快照 TTL 量级内徽章更新。

## 12. 实现分期建议

### 12.1 一期（本设计范围）

1. Drizzle schema + 迁移：buckets、snapshot。
2. `recordAiChannelOutcome` + 错误分类。
3. 接入 `generateWithAI` 与必要流式路径。
4. 快照重建 + `GET /api/ai/channel-availability`。
5. `AiProviderSelector` 百分比徽章。
6. 单测与基础文档。

### 12.2 二期（可选）

1. Cron 定期重建与桶清理。
2. 管理后台只读大盘 / `error_class` 分布。
3. 主动探测补冷门模型。
4. Analytics Engine 等外部指标后端（若 D1 写压力上升）。

## 13. 风险与缓解

| 风险 | 缓解 |
|---|---|
| 自定义 modelId 基数膨胀 | 长度限制、48h 桶 TTL、响应硬顶 200 |
| 错误分类误伤 | 集中映射 + 单测；系统/自定义分策 |
| 记分拖慢生成 | 非阻塞、失败吞掉 |
| 快照惊群 | 内存单飞 + edge cache + 快照 TTL |
| 与内部 upstream 名不一致 | 一期固定 catalog 选择键 |
| 用户把 24h 参考当实时 | 文案带 `24h` /「暂无近期」前缀 |
