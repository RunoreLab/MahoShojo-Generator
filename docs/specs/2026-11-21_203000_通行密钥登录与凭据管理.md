# 通行密钥登录与凭据管理

状态：已接受，首版由现有 Web 认证服务承载

生产 RP ID：`mahoshojo.colanns.me`

## 账号与凭据

- 登录弹窗提供「使用通行密钥登录」。浏览器从可发现凭据里选择账号，服务端要求设备用户验证，并签发 Better Auth 会话。业务账号从 `ba_user.id → user_auth_links` 解析。桌面授权页复用此入口，通过既有 `desktop-auth-v1` 协议返回桌面端。
- 在「设置 → 账号 → 账号安全设置」查看名称、创建时间和最近使用时间，添加、改名或删除凭据。首版每账号在同一 RP 最多 10 把。同一个同步凭据在多台设备上使用时仍对应一条服务端记录。
- 添加和删除都要求重新确认。添加第一把和删除最后一把必须验证账号当前密码。已有多把时可选择已绑定的通行密钥或密码，已有一把时也可用它确认添加。只持有旧密钥的账号先按现有迁移流程设置密码。密码登录和邮箱找回继续可用。
- 删除撤销该凭据未来的登录能力。已建立的会话按正常过期和撤销规则处理，设备中的副本可通过系统密码管理器删除。

## 信任与数据边界

生产端对 `https://mahoshojo.colanns.me` 做精确来源校验。浏览器侧使用 WebAuthn 原生 JSON API，服务端用 SimpleWebAuthn 验签。用户句柄由稳定的 Better Auth 账号 ID 派生，同一账号的多把凭据共享此句柄。列表只返回管理所需的 ID 和展示字段。

登录挑战绑定当前浏览器的签名 cookie。注册与重新确认挑战绑定权威会话、用途和需要操作的目标，期限为五分钟。D1 原子消费挑战，并在写入时检查会话、账号、凭据归属、数量上限及删除最后一把的密码规则。Worker 限流先于挑战写入；挑战表有过期索引并在发放时限量清理。

AI 战报 iframe 和 Web 包运行页禁止直接调用 WebAuthn。[可信同源模式](../decisions/2026-09-28_205100_WebPackage受限模式与可信同源授权决策.md)按主站脚本的信任边界处理。

## 启用与回滚

`PASSKEY_ORIGIN` 为服务端启用配置，须与 `BETTER_AUTH_URL` 的 origin 一致。生产值为 `https://mahoshojo.colanns.me`，由 [Web 生产配置](../../apps/web/wrangler.jsonc) 提供。独立环境验收后，生产发布先应用 [D1 增量迁移](../../drizzle/0022_auth_passkeys.sql)，再在主站启用配置。生产部署带 `--keep-vars`，需要关闭时应显式将 `PASSKEY_ORIGIN` 置空后发布，也可回退到已验证的禁用版本。凭据表可供重新启用后继续使用。

当前仓库的生产和公开预览配置共用 D1。浏览器验收使用已构建的 Next 应用与 Miniflare 独立数据库。实际 Windows Hello、硬件安全密钥和跨设备扫码可在隔离环境中补做实机覆盖。

在 PowerShell 从仓库根目录运行以下命令可复现浏览器验收。浏览器使用独立配置和虚拟验证器，Rust 测试使用内存凭据存储。当前 Windows 环境可在 Playwright Chromium 缺失时使用已安装的 Edge。

```powershell
$env:NEXT_PUBLIC_HOSTED_API_ENVIRONMENT = 'local'
$env:BETTER_AUTH_URL = 'http://localhost:13480'
pnpm --filter @mahoshojo/web run build:next
node apps/web/tests/browser/passkey-auth.mjs
```
