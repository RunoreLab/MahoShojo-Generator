## 1. 审查裁决

平台重整不是用户行为等价的纯平台重构。相对默认分支，审查确认：

- AI Provider 的可诊断错误先在 Hosted Runtime 被压成固定分类，再在 Hosted API 被压成“服务器内部错误”；
  这是应阻断并轨的行为回归；
- 默认分支的产品意图——让用户看到 API Key、余额、权限、模型、限流、上游可用性和公开 request ID 等可操作原因——
  继续有效；默认分支把原始 Error、response body、URL、request body 和 cause 挂在异常对象上的具体做法不构成安全契约，
  不得原样恢复；
- 前端本来就会优先展示具体 `message`，不是上述回归的根因；
- Arena `plain-stream` 已由 accepted 可恢复生成规格正式废弃，旧 preference 单调迁移为 fetch-SSE；这不是静默移除，
  本轮不恢复第二套绕过 generation ID、cursor 与 replay 的 transport；
- subscriber/网络断开只终止本次读取，不等于 cancel；用户取消必须取得 server cancel 的明确确认，确认失败时不得向用户声称
  “已停止”；
- 断网→重连→cursor replay→完成的自动化验收范围是主 `arena/generate-stream` generation；
  `arena/session/generate-next` 当前仍是直接 POST companion operation，不在本规格中伪报为 resumable。若产品要求连续章节也具备
  同一恢复保证，必须作为独立行为变更接入稳定 request identity/lookup/resume；
- 生产 stable control plane、same-origin fallback placement 或生产演练没有闭合前，现有 release/activation gate 继续
  fail closed，不得为行为验收放宽。

## 2. AI 公共错误契约

### 2.1 唯一受信公共投影

只有 Hosted Runtime 明确构造并由 Hosted API marker/type guard 识别的 `SafePublicAiErrorProjection` 可以进入客户端。
未知异常即使具有 `message`、`status` 或 `responseBody` 字段，也必须使用 generic wire。

公共投影字段为：

```ts
type SafePublicAiErrorProjection = {
  code:
    | 'AI_UPSTREAM_REQUEST_FAILED'
    | 'AI_UPSTREAM_TIMEOUT'
    | 'AI_REQUEST_ABORTED'
    | 'AI_PROVIDER_REDIRECT_BLOCKED';
  message: string;
  upstreamStatus?: number;
  upstreamRequestId?: string;
};
```

公共字段使用 `upstreamRequestId`，不使用泛化的 `requestId`，以免与本项目入口层 request ID 混淆。该值只允许来自
受控 Provider 公共字段，命中任何已知 secret 时必须丢弃。

### 2.2 JSON 与 SSE

JSON 继续兼容既有 `error` / `message`：

```json
{
  "error": "生成失败",
  "code": "AI_UPSTREAM_REQUEST_FAILED",
  "message": "AI_APICallError: 余额不足（HTTP 402）",
  "upstreamStatus": 402,
  "upstreamRequestId": "provider-public-id"
}
```

SSE `event: error` 使用相同 `code`、`upstreamStatus` 与 `upstreamRequestId`，并同时把安全人类可读说明放入
`error` / `message`，以兼容现有 stream consumer。外层 HTTP status 本轮不随 Provider status 重映射。

无法安全识别的内部异常继续返回既有 generic wire；普通 `Error.message`、stack、HTML、服务器绝对路径、SQL/Drizzle
参数、Cookie、Authorization、API Key、URL credential/query、prompt、附件和 request body 不得进入响应。

### 2.3 提取与持久化边界

提取器只信任已知 AI SDK/Provider error 类别，只从受控 message/data/JSON responseBody/status/request-ID 字段取候选值，
再执行值级 secret 与请求内容重叠检查、credential/URL/stack/HTML 检查、控制字符清理和长度上限。Host/API 日志、D1、R2
与低基数 telemetry 只记录稳定 code/status，不记录 Provider message。

Arena live SSE 与有 TTL 的 Redis replay 可以携带安全公共说明；Redis TTL 结束后从 D1/R2 durable terminal 恢复时，
允许退化为稳定 code + generic 文案。若未来要求长期显示历史 Provider message，必须另行定义有界、可删除、可审计的
`failureSummary`，不得直接持久化 Error 或 response body。

## 3. 基础设施故障的最终用户文案

机器可读 source of truth 为 `config/user-visible-contracts.json#infrastructureMessages`，前端只对登记的基础设施 code
优先使用稳定文案；`AI_UPSTREAM_*` 不在该映射中，不能覆盖 Provider 的安全诊断。

| 故障 | 公共事实 | 用户最终语义 |
| --- | --- | --- |
| required Redis down / 限速不可用 | `RATE_LIMIT_UNAVAILABLE` | 限速服务暂时不可用，可稍后重试 |
| Arena reservation/state/ownership 不可确认 | `GENERATION_*_UNAVAILABLE` | 状态未知；稍后重试且不要重复提交同一场生成 |
| Arena durable D1/R2/finalization capability 不可用 | `ARENA_GENERATION_CAPABILITY_UNAVAILABLE` | 战报生成暂不可用，不伪造已接受或已完成 |
| terminal 已知但正文暂不可读 | `GENERATION_TERMINAL_CONTENT_UNAVAILABLE` | 已结束但正文暂不可读取，稍后查看 |
| Next DR binding/secret/placement 不可用 | `HOSTED_DR_CAPABILITY_UNAVAILABLE` | 备用生成服务暂不可用，不回退到不受信 authority |
| Hono primary down 且 safe/read 成功选到 DR | 成功 wire | 不显示故障；stable logical origin 不变 |
| primary down 但 operation 不可安全切换 | fail-closed code | 不透明重放 POST，不把网络断开解释为 cancel |
| 未预期内部异常 | `HOSTED_GENERATION_FAILED` / `INTERNAL_SERVER_ERROR` | 固定 generic 文案，不显示内部异常 |

当 production control plane 为 `not-provisioned` 时，正确行为是构建/激活阶段阻断发布，而不是让真实用户先收到一个
运行时错误页。真实切流、RTO/RPO 和生产文案只能在获得生产授权并完成演练后补充证据。

## 4. User-visible contract audit 门禁

`pnpm run check:user-visible-contracts` 已纳入 `workspace:verify`，因此也是 `ci:verify` 的结构性 merge gate。门禁以
`config/user-visible-contracts.json` 为机器事实；当前 `auditCoverage.status` 必须保持 `partial`，直到下述未覆盖维度由真实
runtime differential 闭合。现有自动检查：

1. 默认分支 route inventory 精确分解为当前 18 条 shared 与 6 条 exited，当前新增的 5 条控制面 capability 必须单独登记；
2. 18 条 default-vs-refactor shared API 的默认 `POST` capability 与统一 405 status/body 进入逐 route 测试；成功、参数错误、
   safe-upstream/unknown-internal、JSON/SSE、Hono/Next adapter 目前是 family-level evidence，并非 18 条逐路由完整差分；
3. 405 body 保持默认分支 `{ "error": "Method not allowed" }`；RFC-compatible `Allow` header 是允许的加法，
   Arena resumable generation 新增 `DELETE` 是已登记的行为变化；
4. 6 条 exited API 的 Next handler/route 内容 hash 固定到本轮审计记录的默认分支等价内容，并执行 405、五条生成路由的
   malformed-request 与 `regenerate` 未认证 runtime contract；该记录 hash 保护当前迁移内容不再静默漂移，但脚本本身不读取
   baseline Git object，也不等价于六条路由的成功、鉴权及上游错误全覆盖；
5. `plain-stream` 的正式 retirement 与 accepted authority 必须存在；
6. production control plane 必须继续是 `not-provisioned/deferred`，直到外部证据按既有 runbook 更新；
7. 基础设施最终文案的配置/可执行映射双向一致、Arena service/client 断网/replay/取消确认、Provider 可诊断错误与 secret
   canary 都有实际断言；`requiredEvidenceTests` 的文件存在性检查只是防遗漏索引，测试是否执行仍由 workspace test gate 保证。

因此当前只可作如下裁决：Provider 错误透传 blocker、基础设施文案映射、Arena 主要 service/client seam 与路由结构门禁为
`PASS`；完整 `ACCEPT-018` 为 `PARTIAL`。至少还需补齐 18 条 shared route 的 default-vs-refactor `POST` 成功/错误 runtime
differential、6 条 exited route 的鉴权/成功/上游错误 runtime differential，以及真实浏览器网络切换旅程，才能把整体改为
`PASS`。不得用“evidence 文件存在”替代这些断言。

内容 hash 是 exited route 未被静默修改的保护，不替代外部 Provider 或生产环境的端到端验收。需要真实网络、生产控制面、
生产 D1/Redis/R2 或真实 Provider 账户的场景继续明确 `DEFERRED`，不得由 fixture 冒充。

当前自动化证据在 service/client seam 证明主 Arena generation 的单 POST、重连、cursor replay、完成、Provider/终态副作用
不重复与恢复文案状态；真实 Wi-Fi/移动网络切换、浏览器后台挂起和生产入口切换仍是环境验收，不包含在 `PASS` 中。

## 5. ACCEPT-014 证据更正

`ACCEPT-014` 要求 Redis 全量丢失后，账号、线上卡、rating、settlement、audit 等全部权威事实均不丢失或被缓存改写。
当前真实 loopback Redis empty drill 只证明 Arena terminal 的 D1/R2 authority 路径，因此只能作为 Arena 子域证据，不能把
完整 `ACCEPT-014` 标为 `PASS`。

`config/hosted-dr-drills.json` 已移除两个 Redis case 对完整 `ACCEPT-014` 的声明。补齐跨业务 authority fixture，或经正式
规格修订收窄该 acceptance 条款之前，其状态必须保持 `PARTIAL`；这项更正不授权 production Redis flush。

## 6. 非目标与变更规则

本规格不恢复 `plain-stream`，不迁移到 RFC 9457，不修改 Provider HTTP status 映射，不把 exited route 强行迁回 Hono，
不放宽 DR replay/authority/release guard，也不恢复原始数据库或请求日志。

后续 runtime、placement、schema、transport 或数据层迁移只要改变成功 wire、校验、错误信息、限流、timeout/abort、stream
terminal、恢复、鉴权、持久化失败、DR unavailable 或用户设置，就必须更新机器契约、差分 fixture 与本规格（或其后继规格），
不能仅以“内部重构”为由豁免。
