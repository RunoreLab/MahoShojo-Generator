# Arena 战报正文分层与有限保留实施规格

状态：`accepted`

日期：2026-08-31

规格标识：`SPEC-arena-report-storage-retention-v2`

来源：用户提供的《Arena 战报正文分层与有限保留实施规格 v2》。本文将其规范性结论收录进仓库；若历史材料与本文冲突，以本文为准。

## 目标与边界

Arena 成功战报采用以下分层：

```text
Redis generation replay（短期断线恢复）
                 ↓
D1 authoritative metadata（终态、所有权、审计、R2 pointer）
                 ↓
R2 Standard（有限期完整正文）
```

本轮只治理战报正文，不缩短 generation/Room 恢复窗口，不清理 terminal authority、rating audit 或历史 D1 metadata。

## 强制决策

### D1

- 新 authoritative finalization 的 `battle_report_generations.output_preview` 必须为 `NULL`。
- `large_objects`、终态 identity、所有权、usage、winner/headline、reconciliation 和 rating audit 元数据继续保留。
- 历史 `output_preview` 继续作为 legacy fallback；本轮不得批量清空或启动大规模历史迁移。
- R2 pointer 只表示对象曾存在或预期存在，不是当前 existence proof。

### Redis

- 不新增独立战报正文 key、Web Redis client、Web→Hono Redis-body bridge 或 Redis→R2 read-through cache。
- generation active/terminal TTL 继续为 3600/2700 秒；`snapshotMaxBytes` 默认继续为 2 MiB。
- completed full terminal snapshot 超预算时，必须构造 markdown-only snapshot：保留 status、markdown、lastEventId、updatedAt、terminalResultRef，清空 reasoning，置 telemetry 为 `null`。
- markdown-only 仍超预算时才清除 terminal snapshot；failed/cancelled/producer_lost 的既有 bounded 行为不变。
- Redis unavailable 不得改变 D1/R2 authoritative finalization。

### R2

- 成功正文继续同步写入 R2；没有 durable outbox 前不得改为响应后的异步归档。
- `v1/battle-report-generations/` 下所有旧 dated key 与新 flat key 都必须受有限期 Lifecycle 管理。
- 使用 Standard；不转 Infrequent Access、不建立永久/saved prefix、不做访问续期、不用 Hono cron 高频 LIST+DELETE。
- Lifecycle prefix 必须精确为 `v1/battle-report-generations/`，不得影响其他 object family。
- production retention 必须由真实 account/bucket/prefix 数据决定，并为账户其他 R2 使用、增长和 Lifecycle 删除延迟保留余量。

### 过期与故障语义

- R2 GET 404/not-found 是正常 retention 结果，不得映射为 502/503 temporary storage failure。
- Web detail 对已过期正文返回 `hasStoredOutput=false`、`readError=null`、`canRegenerate=false`；regenerate 返回 409 业务结果。
- Hono 必须保留 completed/final-authoritative 事实，同时表达正文 unavailable/result unavailable；resume 不得对正常过期返回可重试 503。
- 403、5xx、network、timeout 和无效配置仍是临时或配置故障，不得静默当成过期。
- 实现必须使用 typed result/error，不得解析错误消息字符串判断 404。

## 成本与容量原则

Cloudflare 供应商额度不是项目永久合同。每次变更 retention 前必须重新核对官方 R2 Pricing。

截至 2026-08-31，R2 Standard 免费额度为 10 GB-month、每月 1M Class A、10M Class B，egress free；默认账户级安全余量为：

```text
H = max(1 GB-month, 10% × F_free)
F_plan = F_free - H
B_report = F_plan - O_other
```

当前 `F_plan=9 GB-month`。`O_other` 包括其他 bucket、本 bucket 其他 prefix 和可合理预见的增长。

保守日写入定义为 `D=max(avg_7d, avg_30d, p90_daily)`；样本不足时必须使用更高的可观测值校准。候选窗口用真实 `lastModified + Size` 回放，并额外容纳至少一天删除延迟。

## 上线顺序

1. 只读盘点 Pricing、账户/bucket/prefix、现有 Lifecycle、D1 pointer 和 Redis/Hono 容量。
2. 上线 D1 停写、Web/Hono 404 分流和 temporary failure 回归测试。
3. 上线 Redis markdown-only compact fallback。
4. 在非生产环境演练 prefix 与删除后语义。
5. 用管理权限读取账户级 `O_other` 和 Lifecycle，冻结 retention，写入规则并 read-back。
6. 观察 R2 storage/404/5xx、D1 新 preview、Redis memory/eviction 与 personal regenerate 409/502。

production Lifecycle 不得早于步骤 2 至 4。对象一旦删除不可恢复，撤销规则只能阻止未来删除。

## 验收

- 新 completed generation 的 D1 `output_preview` 为 `NULL`，历史 preview 仍可读。
- R2 200、404、403、5xx/network 具有互斥语义和回归测试。
- Web 404 detail/regenerate 不返回 502；Hono expired 不返回可重试 503。
- completed terminal snapshot 覆盖 full、markdown-only、cleared 三态，且 TTL/budget/resultRef/lastEventId 不变。
- 未新增 Redis 正文 key、Web Redis dependency、跨 runtime body bridge 或 IA transition。
- Lifecycle 精确匹配 battle-report prefix，retention 有真实数据记录、账户余量和 read-back 证据。

## 延期事项

永久保存、用户删除、saved/featured/shared 分级、访问续期、IA、异步 archive/outbox、stale `large_objects` 后台清理、历史 preview 批量迁移及 personal-page Redis cache 均为 evidence-triggered 后续工作。
