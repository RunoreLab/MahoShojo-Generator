# 公开数据卡众查一期协议附录

更新时间：2026-04-08 22:45:00

本文是 `公开数据卡众查机制总体规划与分期设计` 在 `Phase 1A / 1B` 落地阶段的实现口径补充，用于锁定首批实现中最容易分叉的协议细节。

## 1. 众查结果写回举报案件处理链路

### 1.1 写回映射

`crowd_review_rounds.result_code` 与 `report_cases` 的自动写回关系如下：

- `violation`
  - `report_cases.status = 'resolved'`
  - `report_cases.resolution_code = 'confirmed_violation'`
  - `report_cases.closed_at = now`
- `no_violation`
  - `report_cases.status = 'dismissed'`
  - `report_cases.resolution_code = 'no_violation'`
  - `report_cases.closed_at = now`
- `tie`
  - `report_cases.status = 'under_review'`
  - `report_cases.resolution_code = null`
  - `report_cases.closed_at = null`
- `escalated`
  - `report_cases.status = 'under_review'`
  - `report_cases.resolution_code = null`
  - `report_cases.closed_at = null`

### 1.2 范围限制

- 本批次不引入持久化的“等待管理员确认后再写回”运行时分支。
- 后续若需要区分“自动落地”与“管理员确认后落地”，必须在后续规格与后台计划中显式扩展数据结构与状态机，不能在本批次服务层中隐式保留未落库分支。

## 2. 最小 API 契约

### 2.1 `GET /api/crowd-review/summary`

#### 匿名访问

- 返回 `200`
- 响应体：

```json
{
  "eligible": false,
  "inspectorStatus": "anonymous",
  "statusReason": "登录后可查看调查院状态",
  "hasCurrentAssignment": false,
  "hasCrowdReviewPending": false,
  "entryUrl": "/investigation"
}
```

#### 已登录访问

- 返回 `200`
- 响应字段：
  - `eligible: boolean`
  - `inspectorStatus: 'anonymous' | 'ineligible' | 'active' | 'suspended' | 'revoked'`
  - `statusReason: string | null`
  - `hasCurrentAssignment: boolean`
  - `hasCrowdReviewPending: boolean`
  - `entryUrl: '/investigation'`

### 2.2 `POST /api/crowd-review/current/assign`

- 仅允许已登录且具备巡查使资格的用户访问
- 请求体可为空对象 `{}``
- 成功返回 `200`
- 响应字段：
  - `createdNewAssignment: boolean`
  - `currentCase: CrowdReviewCurrentCaseDto`

### 2.3 `GET /api/crowd-review/current`

- 仅允许已登录且具备巡查使资格的用户访问
- 无当前派单时返回 `404`
- 成功返回 `200`
- 响应字段：
  - `assignmentId: string`
  - `assignmentStatus: 'assigned' | 'voted' | 'abstained' | 'expired' | 'revoked'`
  - `assignedAt: string`
  - `expiresAt: string`
  - `caseId: string`
  - `reportCaseId: string`
  - `targetEntityType: 'data_card'`
  - `targetEntityId: string`
  - `targetSnapshot`
  - `reportSummary`
  - `ruleHints: string[]`
  - `availableDecisions: ('violation' | 'no_violation' | 'abstain')[]`
  - `postVoteSummary: CrowdReviewPostVoteSummaryDto | null`

### 2.4 `POST /api/crowd-review/current/submit`

- 仅允许已登录且具备巡查使资格的用户访问
- 请求体：

```json
{
  "assignmentId": "string",
  "decision": "violation | no_violation | abstain",
  "note": "string | null"
}
```

- 成功返回 `200`
- 响应字段：
  - `assignmentId: string`
  - `assignmentStatus: 'voted' | 'abstained' | 'expired' | 'revoked'`
  - `decision: 'violation' | 'no_violation' | 'abstain'`
  - `postVoteSummary: CrowdReviewPostVoteSummaryDto`
  - `idempotentReplay: boolean`

### 2.5 `GET /api/crowd-review/history`

- 仅允许已登录且具备巡查使资格的用户访问
- 成功返回 `200`
- 响应字段：
  - `items: CrowdReviewHistoryItemDto[]`
  - `fetchedAt: string`

### 2.6 `GET /api/messages/summary` 众查扩展字段

- 保留现有字段：
  - `unreadTotal`
  - `siteUnread`
  - `directUnread`
  - `latest`
  - `fetchedAt`
  - `isAuthenticated`
- 新增字段：
  - `hasCrowdReviewPending: boolean`
  - `crowdReviewPrompt: { title: string; body: string; actionUrl: '/investigation' } | null`

### 2.7 认证规则

- 匿名访问者：
  - 仅允许访问 `GET /api/crowd-review/summary`
- 已登录但无巡查使资格的访问者：
  - 可访问 `GET /api/crowd-review/summary`
  - 不可访问 `current/assign/current/submit/history`
- 已登录且具备巡查使资格的访问者：
  - 可访问全部一期巡查使接口

### 2.8 错误码约定

- `400`
  - 请求体格式错误
  - `decision` 非法
  - 缺少 `assignmentId`
- `401`
  - 未登录
- `403`
  - 已登录但不是可参与众查的巡查使
- `404`
  - 当前无派单
  - 派单记录不存在或不属于当前用户
- `409`
  - 派单状态已变化，当前请求与最新状态冲突
- `422`
  - 案件当前不可处理或提交内容违反业务约束
- `503`
  - D1 或服务层不可用

## 3. 并发与一致性约束

- 同一巡查使在任一时刻最多只能有 `1` 条活跃派单。
- 同一举报案件在任一时刻最多只能有 `1` 个活跃众查轮次。
- 同一轮次下，禁止给同一巡查使重复派单。
- 派单一旦进入最终状态，重复提交必须返回幂等结果，不得重复计票。
- 活跃轮次状态固定为：
  - `pending_dispatch`
  - `active`
  - `waiting_more_votes`
- 活跃派单状态固定为：
  - `assigned`
- 时限推进采用惰性更新：
  - `GET /api/crowd-review/summary`
  - `POST /api/crowd-review/current/assign`
  - `GET /api/crowd-review/current`
  - `POST /api/crowd-review/current/submit`
  - 以上入口在读取或写入活跃数据前，必须先调用同一套“推进已过期派单/轮次状态”的服务层 helper。

## 4. 本批次范围

### 4.1 固定运行时常量

- 巡查使徽章固定使用 badge ID：`crowd_review_inspector`
- `entryUrl` 固定为：`/investigation`

### 4.2 首批可进入众查的案件判定

在本批次中，可进入众查并被派发的案件必须同时满足：

- `report_cases.target_entity_type = 'data_card'`
- `report_cases.status IN ('open', 'under_review')`
- 目标公开数据卡当前仍存在且可公开访问
- 案件当前不存在活跃众查轮次

以下规则在当前批次只做“保守不实现”，并明确留待后续后台/申诉计划扩展：

- `仅管理员处理` 标记
- `已进入申诉复核` 标记
- 更细粒度的材料充分性审核
- 更复杂的派单优先级、冷却与信誉权重

### 4.3 明确排除项

- 用户申诉 UI 与 `POST /api/report-appeals`
- `feat/admin` 后台 UI
- 巡查使质量控制自动处罚
- 公开案件池、抢单、排行榜
