# 双端视觉基线与工程契约规格

状态：`active`（已接受目标；各条落地状态以代码与测试为准）
日期：2026-10-19
规格标识：`SPEC-visual-baseline-v1`
约束：[双端视觉治理体系决策](../decisions/2026-10-19_215000_双端视觉治理体系决策.md)（`ADR-visual-governance-v1`）；[Desktop 产品一致性与本地优先规格](./2026-10-02_184000_Desktop产品一致性与本地优先规格.md) 的 DESK-PROD-009。

规范词遵循 RFC 2119 / RFC 8174。下列 `VIS-***-*` 为新增要求，不重编号旧规格。

## 0. 边界与当前状态

**适用范围**：`apps/web`、`apps/desktop`、`packages/ui-web`。`apps/admin` 为独立管理端样式体系，不在本规格范围（登记：ADR §2.5）。

**当前事实**（截至 2026-10-19）：

- 颜色与字体 token 单点定义于 `packages/ui-web/src/styles.css` 的 `:root` / `@media (prefers-color-scheme: dark) :root:not([data-color-mode])` / `:root[data-color-mode='dark']` 三段结构；`data-motion` 承载减少动效偏好。
- `var(--x, 兜底)` 兜底写法、`var(--battle-lite-*, var(--app-*))` 可选主题覆盖链、`.blue-theme` 作用域 token 改写（`product-shell.css`）均为已登记的既有模式。
- 共享组件 CSS 中仍存在硬编码 hex/rgba 字面量（顶栏、blue-theme 蓝色系、危险操作红色系、`details-questionnaire-*` 暗色覆盖等）。
- 无间距/圆角/字号/阴影/z-index 刻度 token；无双端共享的组件原语层；无契约门禁；无样板间；无自动对比度检查。

**目标**：在不推翻现有三段主题架构的前提下，把视觉基线从「一份 CSS 文件」升级为「成文规范 + 机器契约 + 可审查样板间 + 本地巡检证据」。

## VIS-TOK-001 Token 所有权与分层

`--app-*` 与 `--creator-*` 自定义属性的 `:root` 级定义 **MUST** 唯一位于 `packages/ui-web/src/styles.css`。宿主样式表 **MUST NOT** 在 `:root` 或全局选择器上重定义这些 token。

已登记的作用域改写例外：`product-shell.css` 中 `.blue-theme` 容器内的 `--app-result-card-bg`（含其暗色变体）。新增作用域改写 **MUST** 同时满足：改写发生在具名主题作用域选择器内（非 `:root`）、在本规格的例外登记表中记录、`VIS-GATE-001` 的机器清单同步更新。

2026-11-13 已批准的阅读倍率例外：按[显示与阅读设置规格](./2026-11-13_151100_显示与阅读设置首期规格.md)，仅 `styles.css` 内的 `:root[data-reading-size='110'/'125'/'150'/'175'/'200']` 各独立选择器可以重定义 `--app-reading-scale`，分别取 1.1/1.25/1.5/1.75/2。默认值 1 仍在同一文件的 `:root`；这份例外用于阅读字号的严格倍率，不允许宿主写 token 或扩展到其他全局 token。机器守卫同步登记，不改变亮暗三段主题语义。

三段主题解析结构（`:root` 默认 / 系统偏好转暗且无显式选择 / 显式 `data-color-mode`）**MUST NOT** 改写为 Tailwind `@theme` 单点输出；`data-color-mode` 写入时机必须保持首屏前（共源 init 脚本）。`--battle-lite-*` 等可选覆盖命名空间按「作用域覆盖」登记，不构成第二套主题。

验收：`tests/design-tokens.test.ts` 的所有权检查通过；新增 token 不出现在例外之外的文件。

## VIS-TOK-002 Token 消费与兜底

新增/修改的样式 **SHOULD** 优先消费语义 token（`var(--app-*)`、Tailwind 任意值 `bg-(--app-*)`）。**MUST NOT** 引入引用未声明自定义属性的 `var()`：除已登记的可选覆盖命名空间外，每个 `var(--x)` 的第一参数必须在被扫描样式表中有定义。

新增代码 **MUST NOT** 对 `--app-*`/`--creator-*` 使用 `var(--x, 兜底值)` 形式掩盖未定义 token——token 不存在应该修复 token 定义，而不是写兜底。存量兜底写法随接触逐步清理，不强制一次性改写。

验收：`tests/design-tokens.test.ts` 的 `var()` 解析检查通过。

## VIS-TOK-003 刻度补全

按批次在 `styles.css` 增补主题无关刻度 token，命名沿用 `--app-` 前缀。首批已落地：`--app-space-1..10`（4px 网格）、`--app-radius-sm..pill`、`--app-text-xs..2xl`、`--app-shadow-sm..lg`、`--app-z-overlay/modal/toast`，取值从现有共享/宿主 CSS 用量归纳。后续新增样式 **SHOULD** 消费刻度而非散落字面量；两端各自持有的重复字面量 **MUST** 逐步收敛为共享常量/token 或登记为人工镜像并接受契约校验——结果卡渐变已收敛为 `@mahoshojo/ui-web/character-card` 的 `MAGICAL_GIRL_CARD_GRADIENT`（颜色值由 `@mahoshojo/domain/main-color` 维护），boot screen 字体/色板仍属登记中的人工镜像。

每条新增刻度 **MUST** 在同一工作单元加入 `tests/design-tokens.test.ts` 的对应守卫（如间距网格校验）。

## VIS-CSS-001 样式所有权与加载顺序

样式分层 **MUST** 保持：宿主 reset/层声明 → token 与共享底座（`ui-web/styles.css`）→ 共享组件闭包（`ui-web/**`）→ 页面/宿主局部样式。共享给两端消费的样式 **MUST** 位于 `ui-web` 并随组件闭包维护，**MUST NOT** 在两端各留一份再靠人工同步（DESK-PROD-009）。

宿主 globals.css 只允许宿主页框级规则与明确的宿主私有残留；发现两端重复的页面级规则应上移。

## VIS-CSS-002 写法政策

新代码与显著改动 **MUST** 使用以下两种机制之一：Tailwind utility class（消费语义 token），或 ui-web 共享 CSS 类。下列机制标记为 legacy-only，存量保留、新增禁止，随接触迁移或登记豁免：styled-jsx、CSS Modules、inline `style={{}}`（动态值除外，如运行时计算的坐标/进度）。

`!important` **MUST NOT** 用于常规层叠竞争；仅允许带注释说明的结构性用途（如 `[hidden]` 行为契约）。新增硬编码颜色字面量（hex/rgb/rgba/oklch 等）**MUST NOT** 出现在共享组件 CSS 中；组件局部装饰常量 **MUST** 在文件头注释登记为局部常量，或提升为 token。

验收：`tests/design-tokens.test.ts` 的字面量基线检查（逐文件计数不增长）。

## VIS-GATE-001 结构契约门禁

`tests/design-tokens.test.ts` 经根 `test:repo` 进入 `ci:verify:checks` CI 门禁，扫描 `packages/ui-web/src`、`apps/web`（`styles/`、`app/`、`components/`）、`apps/desktop/src` 下全部 CSS：

1. `var()` 可解析：每个 `var(--x)` 第一参数必须解析到被扫描样式表中的声明，或属于登记的可选覆盖命名空间/运行时属性清单；
2. token 所有权：`--app-*`/`--creator-*` 的 `:root` 级声明只在 `styles.css`；作用域改写只在 VIS-TOK-001 登记表内；
3. 字面量基线：逐文件硬编码颜色字面量、`var(--app-x, 兜底)` 写法与离网格间距（margin/padding/gap/inset 等非 4px 整数倍 px 值）计数 **MUST NOT** 超过 baseline 登记表（只降不增）。

豁免/基线清单与测试同文件维护，每条注明原因；消除存量后同步下调。

## VIS-GATE-002 对比度门禁

`tests/design-contrast.test.ts` 经根 `test:repo` 进入 `ci:verify:checks` CI 门禁。解析 `styles.css` token → 递归解 `var()` 链 → 按 WCAG 2.x 相对亮度公式（不取整）计算登记配对的对比度：普通文本 **≥4.5**，控件边界/焦点指示等非文本 **≥3**。带透明度的前景/背景先与登记背景合成再计算；渐变背景按各档位色计算并取最小比率。

配对登记表（语义前景/语义背景 × 亮/暗两套主题上下文）随测试维护，至少覆盖：正文 on `page-bg`、正文 on `surface`、弱化文本 on `surface`、弱化文本 on `page-bg`（页脚）、placeholder/辅助文本 on `input-bg`、强调色文本 on `surface`、输入边界 on `input-bg`、焦点环 on `surface`。

已知不达标项登记为 `known-violation` 条目（含原因与跟踪说明）：现状即失败但单独修复，门禁仍通过；一旦某条 known-violation 实测转为达标，**MUST** 将其状态提升为 required（测试须报告该提升）。测试 **MUST** 含反向哨兵：构造的必败配对必须被判定失败，防止矩阵形同虚设。

## VIS-SHOW-001 共源样板间

`packages/ui-web` 提供单源 `ShowroomView`（`@mahoshojo/ui-web/showroom`），分区以 `src/showroom/sections.ts` 的 `SHOWROOM_SECTIONS` 登记表为唯一事实源，当前覆盖：色板与语义 token、字体阶梯、主题无关刻度、控件/表单、弹层、卡片与结果面、页脚。两端 dev 入口消费同一组件：Web `/dev/showroom`（生产构建 404）、Desktop `/#/showroom`（仅 `import.meta.env.DEV` 时经 `main.tsx` 旁路挂载，不进产品路由树）；不进产品导航、不进 `DELIVERED_ROUTES`。

新增或显著变更共享组件/共享样式时，**MUST** 在同一工作单元加入或更新对应样板分区；分区 **MUST** 渲染生产组件/样式，禁止为展示另写「好看版」示例。样板分区覆盖清单即 `SHOWROOM_SECTIONS` 登记表，`tests/visual-showroom.test.ts` 断言必备分区覆盖、视图由登记表驱动、两端共源消费且不进生产面。

样板间证明「组件状态」，不冒充页面级验收；页面级双端对照仍按现有 runbook 流程。

## VIS-REVIEW-001 本地视觉巡检与证据

显式本地命令 `pnpm review:visual`（`scripts/review-visual.mjs`）已落地：经 `createRequire` 复用 `apps/web` 的 Playwright 依赖，默认自管拉起/回收 `next dev`（独立端口，`--no-server` 可复用外部实例），对 `/dev/showroom` 与 `/`（`--routes` 可覆盖）跑条件矩阵——亮/暗 × 1280/375 视口 × forced-colors × 200% 根字号；页面内断言含横向溢出、抽样元素 `getComputedStyle` 对比度（合成最近非透明祖先背景，按字号区分 4.5/3 阈值）、首个可聚焦元素焦点可见性。恒写 `.tmp/visual-review/report.json`（OS/Node/viewport/deviceScaleFactor/主题/SHA/条件范围/未验项/发现明细），`--screenshots` 显式采图到同目录。对比度低于阈值的抽样记为 `warn`（对照 `tests/design-contrast.test.ts` 已知缺口表核实），导航失败/横向溢出/异常记为 `fail` 并以非零退出码结束。

本命令 **MUST NOT** 进入 `workspace:checks`、CI 或提交硬门禁；不设像素阈值、不批量更新黄金图。浏览器模拟的 DPR/forced-colors **MUST NOT** 表述为原生显示缩放或高对比主题验收。

## VIS-A11Y-001 可访问性目标

以 WCAG 2.2 AA 为目标（非认证）：文本对比、键盘可达、`focus-visible` 可见且不遮挡、不以颜色作为唯一反馈、不在 hover 才暴露关键功能、`prefers-reduced-motion`（经 `data-motion` + 原生 media query 双保险）生效。新共享控件 **SHOULD** 处理 forced-colors（恢复系统色/原生外观优先，避免根级 `forced-color-adjust: none`），未处理项登记缺口。

机器侧：`apps/web` 经 `eslint-config-next` 已内置 jsx-a11y 推荐规则；`packages/ui-web` 与 `apps/desktop` 已在各自 flat config 挂载 `eslint-plugin-jsx-a11y` 推荐规则集——存量命中（主要为 `control-has-associated-label`、`label-has-associated-control` 等交互标签模式）整体先行 `warn`，只降不增、随接触收口后再逐级收紧，不一次性清零。

## VIS-GOV-001 变更权限分级

- **A 级**（可自主）：token 内样式修复、同源抽取、契约门禁维护、样板分区更新——完成后附验证；
- **B 级**（先说明再实施）：新增共享控件/原语、主要布局重做、新刻度 token——先说明问题、候选与复用路径；
- **C 级**（未批准不实施）：产品语义变化（保存/丢弃、费用、隐私、AI 写入）、主题整体换血、视觉语言重定义。

## Storybook 再评估触发条件

出现以下任一情况时可重开 Storybook 评估（独立专项，不走 storybook-nextjs，以独立构建器直指 ui-web 源文件）：样板间无法表达的隔离交互状态显著增多、需要 addon 工具链（如交互回放、可访问性面板）、或外部贡献者需要脱离应用壳的组件开发环境。

## 不做清单

- 不做像素 diff/黄金图体系，视觉类检查不进 CI；
- 不统一 `apps/admin` 样式体系；
- 不改写三段主题解析为 `@theme`；
- 不要求存量兜底写法、legacy 写法机制、硬编码字面量的一次性清零——只降不增、随接触清理；
- 不把样板间/巡检结果表述为真实 Windows 显示缩放、原生 IME、读屏或高对比主题验收。
