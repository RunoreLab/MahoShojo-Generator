## 1. 本轮冻结结论

Web Package 正式中文名称统一为 **Web 包**。英文与代码层使用 **Web Package / `web-package` / `WebPackage*`**。

Web 包不是新的 Arena 战报格式，也不是需要用户额外开启的一种模式。Arena 顶层格式继续保持：

```text
reportFormat = markdown | web
```

在 `reportFormat = web` 时：

```text
未选择 Web 包
→ 沿用现有自由 Web 路径
→ AI 生成完整 HTML document

选择了 Web 包
→ 采用 Package-backed Web 路径
→ AI 只生成该包声明的唯一 generation target
→ Base Package + Single-file Overlay
```

因此 UI MUST NOT 再增加“启用 Web 包”“是否使用 Web 包”等额外开关。

Web 包来源分为：

```text
builtin  预设 Web 包
local    用户本地 ZIP Web 包
online   未来线上 Web 包库
```

V1 当前应完成 `builtin + local`。`online` 只冻结扩展边界与数据方向，不作为当前 PR 的交付退出条件。

## 3. 核心架构模型

Web 包是一棵已经准备完成、可以在浏览器环境运行的不可变文件树。

```text
Immutable Base Web Package
        +
One AI-generated Overlay File
        ↓
Derived Web Experience
```

Web 包 MAY 包含：

- HTML；
- JavaScript；
- CSS；
- browser-ready Runtime；
- 第三方依赖；
- 图片、SVG、音频、视频、字体；
- JSON / Markdown / text；
- JSON Schema；
- creator instructions；
- semantic asset catalog；
- 其它静态浏览器资源。

AI 不得原地修改 Base Package。一次 generation 只产生一个完整 target file，并以 overlay 方式遮蔽同路径 base file。

V1 仍只支持：

```text
generation.mode = replace
```

不支持多文件生成、任意 diff、JSON Patch、AST patch、package stacking、package dependency graph、npm install、bundler、Node、WebContainer 或 Host Bridge。

## 4. 标准 Web Package Manifest V1

推荐冻结以下 logical contract：

```json
{
  "format": "mahoshojo-web-package",
  "formatVersion": 1,

  "id": "creator.example",
  "name": "Example Web Package",
  "version": "1.0.0",

  "entry": "index.html",

  "generation": {
    "target": "data/report.json",
    "mode": "replace",
    "mediaType": "application/json",
    "instructions": "ai/instructions.md",
    "schema": "schemas/report.schema.json",
    "assetCatalog": "ai/assets.json"
  },

  "capabilities": ["scripts", "audio"],

  "files": [
    {
      "path": "index.html",
      "mediaType": "text/html",
      "digest": "sha256:...",
      "size": 8192
    }
  ]
}
```

其中：

- `format` MUST 为 `mahoshojo-web-package`；
- `formatVersion` MUST 为 `1`；
- `entry` MUST 存在且为浏览器入口；
- `generation.target` MUST 唯一；
- `generation.mode` V1 MUST 为 `replace`；
- `generation.target` 不得为 `web-package.json`；
- `instructions`、`schema`、`assetCatalog`、`example`、`capabilities` MAY 缺失；
- 缺少 `capabilities` 等价于空数组；
- `files` 用于文件完整性、媒体类型、canonical identity 与导入验证；
- `files` 在 canonical manifest 中 MUST 存在，但在**创作与导入的 authoring surface** 上 MAY 省略，由导入方按归档内容派生；声明存在时始终权威。详见 [Web 包 ZIP 信封归一化与缺省导入决策](../decisions/2026-09-29_114500_WebPackageZIP信封归一化与缺省导入决策.md)。

V1 target 仍限定为文本型 artifact。初始允许：

```text
text/html
text/plain
text/markdown
text/css
text/javascript
application/javascript
application/json
image/svg+xml
```

二进制媒体应属于 Base Package，不作为 AI generation target。

## 5. Path 与完整性规则

所有包内路径 MUST：

- 为相对路径；
- 使用 `/`；
- 不以 `/` 开头；
- 不包含 `.` 或 `..` path segment；
- 不包含反斜杠；
- 不包含 NUL；
- normalization 后唯一。

实现 MAY 为跨平台可移植性拒绝明显危险的 Windows reserved filename，但不得通过过窄的 ASCII-only path schema 无必要地禁止正常 Web 文件名。

ZIP entry MUST NOT 解压到宿主真实文件系统。

Manifest 声明了 `digest` / `size` 的文件 MUST 对实际 bytes 验证。

文件 digest 统一使用：

```text
sha256:<lowercase hex>
```

Package-level digest MUST 基于 canonical manifest + file identity，而不是 ZIP archive bytes。不同 compression level、ZIP metadata 或文件排列顺序不应让逻辑上相同的包得到不同 package identity。

canonical serialization MUST 通过 contract tests 冻结。

## 6. 预设 Web 包是一等标准包

### 6.1 不允许“伪预设包”

所有预设 Web 包 MUST 遵循与本地导入完全相同的 Web Package manifest、文件完整性、generation target、overlay 与 rendering contract。

预设 Web 包不得依赖仅存在于宿主 TypeScript 中的私有运行逻辑才能工作。

### 6.2 可下载与可重新导入

每个预设 Web 包 MUST 提供 ZIP 下载。

用户下载预设 ZIP 后，再通过“本地 Web 包导入”加载，MUST：

- 通过同一 generic importer；
- 得到相同逻辑 package revision / digest；
- 使用相同 Prompt Projection；
- 使用相同 target validation；
- 产生等价渲染行为。

ZIP archive bytes 本身无需相同，但 canonical package identity MUST 相同。

### 6.3 当前预设与静态目录

2026-09-28 修订：本分支从未生产部署。Visual Novel Lite、星屑社区、命运岔路三个实验预设及其专属兼容代码、固定 revision 注册与测试已删除，不保留隐藏预设或历史解析承诺。当前注册表仅包含 `mahoshojo.arena-news@1.0.0` 的固定 revision。

每个预设以 `packages/web-package/presets/<directory>/` 的静态文件为唯一内容源，语义 manifest 不手工枚举文件；构建自动补齐标准 manifest 的 files / size / digest。竞技场使用与 ZIP 导出共同读取经过标准 validator 校验的同一份生成字节。竞技场新闻只提供可选素材、脚本与组件参考，AI 完整生成 `index.html`。

删除实验包不改变通用包机制：`id + version + digest`、生成快照、exact replay、用户明确选择的 compatibility replay 与 ZIP 一致性仍然保留。未注册的内置 ID / version / digest 必须明确解析失败，不得静默映射到当前包。JSON 目标和 schema 的通用测试使用最小本地测试夹具，不能为测试继续注册已删除的产品预设。

### 6.4 Builtin Registry

预设 registry 只负责“发现与选择”，不得成为包内部运行逻辑的第二份来源。

可包含：

```ts
type BuiltinWebPackagePreset = {
  packageRef: WebPackageRef;
  title: string;
  description: string;
  downloadUrl: string;
};
```

包实际是什么，由 canonical ZIP / package artifact 定义。

## 7. JSON Schema 必须通用化

通用 JSON 目标校验以包内 JSON Schema 为准，不依赖某个预设的宿主私有 schema。

当：

```text
generation.mediaType = application/json
```

Host / validator MUST：

1. 剥离 Arena control trailer；
2. `JSON.parse`；
3. 若包声明 `generation.schema`，读取包内 schema；
4. 使用通用 JSON Schema Draft 2020-12 validator；
5. validation 成功后才形成 overlay。

预设包与本地导入包必须走同一 validator。

2026-09-28 收口：schema 的支持性、关键字类型及引用合法性在导入验证和生成前的 Prompt Projection 预检阶段检查，不能等 Provider 已生成后才发现 schema 本身不可用。Web 包 V1 的 schema 子集拒绝 `pattern` / `patternProperties`，避免客户端提供的正则在服务端产生回溯型资源消耗；不为此引入独立正则运行时。预检同时限制 schema 结构复杂度，拒绝不推进数据层级的 `$ref` 循环；通过 `properties` / `items` 描述递归数据仍可用。普通字符串、枚举及结构约束仍受支持，输出仍须经过完整 target validation。

不允许 generic Web Package core import 某个预设包专属 Zod schema 作为真实 authority。

## 8. Web 包来源与统一 Resolver

实现应把“Web 包来自哪里”和“Web 包如何运行”解耦。

逻辑上：

```text
Builtin Source
Local ZIP Source
Future Online Source
       ↓
ResolvedWebPackage
       ↓
Prompt Projection / Overlay / Render
```

推荐 source abstraction：

```ts
type WebPackageSourceKind = 'builtin' | 'local' | 'online';
```

当前不要求提前实现 `online` 代码，只要求今天的接口不要把未来线上包堵死。

所谓“为线上库预留”是：

> 当前 contract / source / resolver seam 能在以后增加 online adapter，而无需重写 package identity、overlay、history 和 renderer。

不得为了未来预留而提前增加空 D1 migration、空 R2 API、空审核 UI 或半成品在线库。

## 9. 本地 ZIP 导入

本地 Web 包是当前下一阶段核心能力。

完整路径：

```text
Local ZIP
   ↓
Generic ZIP Importer
   ↓
Manifest + File Validation
   ↓
ResolvedWebPackage
   ↓
Browser-local staging
   ↓
Prompt Projection
   ↓
Arena Generation
   ↓
Single Target Overlay
   ↓
Package Resource Resolver
   ↓
Sandboxed Web Experience
```

使用成熟 ZIP library，不手写 ZIP parser。

本地导入不设置产品级固定：

```text
MAX_ARCHIVE_BYTES
MAX_UNCOMPRESSED_BYTES
MAX_FILE_COUNT
MAX_SINGLE_FILE_BYTES
```

但实现必须捕获：

- corrupt archive；
- unsupported compression；
- browser memory failure；
- quota failure；
- parser failure；
- manifest / digest / path validation failure。

可捕获的资源失败必须作为普通本地加载失败呈现。2026-09-28 按 YAGNI 明确本轮边界：ZIP 仅在客户端解压，不上传到服务器解压；不新增展开体积、压缩比、文件数或执行时间硬限制，也不承诺浏览器主线程在极端本地包下始终响应。巨大 ZIP 的同步解压仍可能卡顿或耗尽标签页内存；已缓存包在刷新时会再次恢复，因此刷新不保证解除卡顿，必要时需清除本站的 Web 包 IndexedDB 缓存。异步解压与缓存恢复优化留待真实需求；未来线上库使用平台资源时须另行遵循 §22.3。

现有 PR contract 中类似 `files.max(1024)` 的固定产品上限不应作为本地 Web 包协议不变量保留。

## 10. IndexedDB 与本地缓存

本地包导入后，当前运行所需 staging MAY / SHOULD 使用 IndexedDB 或其它适合的浏览器本地存储。

至少区分语义：

```text
current-session staging
optional persistent cache
```

用户此前明确的“可选缓存”原则继续有效，但主生成流程不要求一定出现一个显式 checkbox。

UI MAY 采用：

- 导入后提供“保留在本机”；
- 本地 Web 包管理区提供缓存/移除；
- 若实现成本更低，也可在不承诺 durability 的前提下自动 best-effort cache。

无论采用何种 UI，都不得宣称 IndexedDB 是永久保存。浏览器 eviction、清站点数据和 quota refusal 都可能使缓存消失。

## 11. Package Resource Resolver

通用 Web Package renderer 必须支持真实包内相对路径，而不是依赖某个预设的字符串替换。

应支持至少：

```text
<script src="./runtime/app.js">
import "./module.js"
<link rel="stylesheet" href="./styles/app.css">
CSS url(...)
<img src="./assets/foo.webp">
<audio src="./assets/bgm.ogg">
nested relative paths
```

### 11.1 当前实现（2026-09-28）

`renderWebPackageInstance(instance)` 是所有来源唯一的通用展示入口。输入是验证后的 Base + Overlay，不接受 builtin/local 身份分支。竞技场新闻、其下载后重新导入的 ZIP、独立用户 ZIP 使用相同的 HTML/CSS/JS 解析、资源解析与执行权限逻辑；新闻专用 `builtin-adapter.ts` / `arena-news-adapter.ts` 已删除。

本轮选择 **browser-local materialization**，不再尝试 opaque iframe + Service Worker 的不可达组合，也不需要新域名、服务器资源上传或临时 URL 文件托管：

```text
Verified Package + exact/显式兼容 Overlay
  → HTML/CSS/JavaScript parser（主页面只解析，不执行作者代码）
  → 相对资源闭包 + 不可变原始文件表
  → 浏览器消息交付固定 /__web-package__/runner
  → 子窗口创建 Blob/import map + 本地 fetch/XHR 映射
  → Restricted 或显式授权的 Trusted Same-Origin
```

`https://web-package.invalid/<digest>/...` 仅为逻辑 URL 基准，不是新部署的域名或可联网资源主机。静态资源及常见属性赋值在本地映射；ESM 的 Blob 在子窗口创建，避免把主窗口 Blob origin 误当作 opaque iframe 的资源权限。包内读取始终按 `overlay[targetPath]` 优先、其余 Base file 的规则，生成目标可以是 Base 中原来不存在的路径。

`resource-space.ts` 的 transport-neutral snapshot/response seam 保留，用于未来真正的隔离资源服务器；当前不得把它描述为已部署的 HTTP 文件空间。

### 11.2 支持范围与明确失败

当前支持单 HTML 入口、经典脚本（保留 async/defer）、ESM 静态/循环/动态导入、`import.meta.url/resolve`、import map imports/前缀别名、嵌套 CSS URL/@import、图片/srcset/SVG/字体/音视频引用、常见动态媒体和脚本属性赋值、包内 fetch GET/HEAD 及异步 XHR GET、单文档 hash 导航。包内 fetch 返回原始文件 bytes 与 MIME；不存在返回 404，写方法返回 405；URL query 不改变底层文件内容。

物化仅改变展示副本，不改变 Base manifest/digest、Overlay bytes/digest、Prompt Projection 或历史 provenance。原文件的 SRI 不再适用于经重写的 CSS/JS，展示副本据此处理，原始完整性仍由包文件 digest 校验。

这不是完整浏览器文件服务器。当前不支持多 HTML 文档导航、import map scopes/null 映射、Worker/Service Worker、嵌套 iframe/object、eval/new Function，以及任意动态 innerHTML/CSSOM 中的相对资源重写。可检测的不支持形态给出诊断；无法解析或缺少的入口依赖明确失败并保留目标/原包下载，不为此自动提高权限。复杂作者运行时应输出单文档 browser-ready 构建，使用相对路径、已支持的属性/API；不能宣称任意已有 HTML ZIP 无需适配即可运行。

上述限制针对**渲染能力**，与归档信封宽容度正交：导入层如何定位包根目录、是否要求声明 `files`，不改变包被渲染时能做什么；「不能宣称任意已有 HTML ZIP 无需适配即可运行」也不禁止导入层接受现实世界的打包方式。信封归一化与缺省导入见 [Web 包 ZIP 信封归一化与缺省导入决策](../decisions/2026-09-29_114500_WebPackageZIP信封归一化与缺省导入决策.md)。

未来其它 transport 可扩大上述兼容范围，但不得改写包身份、强制全局同源或恢复预设白名单。

### 11.3 固定运行页与权限分层

服务器只返回固定运行页和响应头。随机 nonce、准确父/子窗口引用、消息来源共同校验一次性的浏览器内 HTML 交付；不提供通用 Host RPC/API 代理。直接打开运行页不执行用户包。运行页设置 no-store、SAMEORIGIN、no-referrer、nosniff 和独立 CSP/Permissions Policy，主站和普通 Web CSP 不变。

两种执行等级共用资源物化实现。运行页不使用会把可信模式强制降回 opaque 的 CSP sandbox 响应头，iframe 的 sandbox 属性由经过独立授权的宿主组件设置。Restricted 默认无 same-origin；可信授权/撤销重建 iframe，因而未保存交互进度会重置，普通沉浸模式切换仍保留同一 iframe。Trusted 模式的站点级剩余风险遵循 §12，不能把固定运行页握手当成可信代码的宿主隔离。

### 11.4 浏览器验证而非仅函数模拟

相同夹具通过标准 ZIP 往返；在 Chromium/Firefox 验证模块、CSS、媒体、JSON/HTML target、404/405、opaque DOM/存储拒绝、可信模式及错误 nonce/兄弟窗口消息。测试支持实际本机 Next 生产运行页，并核对其 CSP 覆盖没有污染主站。WebKit 应使用同一矩阵；系统依赖缺失时必须标注未验证，不得由 Chromium 结果推定通过。

## 12. Sandbox、能力预检与 Trusted Same-Origin

Web 包默认继续按不可信 Web 内容处理。

### 12.1 Restricted Mode 是默认执行等级

默认至少保持：

```html
sandbox="allow-scripts"
referrerpolicy="no-referrer"
```

Package presence 不得自动增加：

```text
allow-same-origin
allow-forms
allow-popups
allow-top-navigation
Host Bridge
filesystem
clipboard
```

拒绝 `allow-same-origin` MUST NOT 删除包、取消选择、阻止 generation、使合法 Overlay 失效、破坏历史 provenance 或阻止 target / ZIP 下载。凡是能在 Restricted Mode 中运行的 Web 包，仍应继续运行；仅依赖宿主同源能力的特定功能 MAY 降级。

### 12.2 Trusted Same-Origin 是独立高权限授权

用户可对自己制作、审查过或完全信任来源的 exact Package revision 显式授予：

```html
sandbox="allow-scripts allow-same-origin"
```

在当前站点域名下，这一模式 MUST 按“用户主动授权第一方脚本 / XSS 等级代码执行”建模，而不是继续把 iframe sandbox 当作宿主安全边界。

它理论上可能访问或影响：

- parent / top DOM；
- localStorage / sessionStorage / IndexedDB；
- 当前 origin 下 JavaScript-readable 认证数据；
- 同源 API；
- 页面状态与 UI；
- 当前用户经站内 API 有权执行的操作。

CSP、Permissions Policy、静态扫描与 UI 风险说明都只是 defense-in-depth，不得宣称重新建立强隔离。

### 12.3 Base + Overlay 双阶段安全预检

Host SHOULD 在浏览器本地提供风险扫描；本地 ZIP 的 Base Package bytes 不得为了预检上传服务器：

```text
Base Package Scan
        +
Generated Target Scan
        ↓
Effective Risk Profile
```

至少识别并展示：

- scripts / executable content；
- external network；
- host-page access；
- site storage；
- dynamic execution；
- workers / background execution；
- Service Worker；
- navigation / popup / download；
- sensitive browser APIs。

Manifest `capabilities` 是作者声明；scanner findings 是宿主观察。二者可以并列显示“作者声明 / 静态扫描检测到 / 未声明但检测到”。

预检不得输出“安全”“已认证安全”“无风险”等结论。混淆、动态执行、WASM、运行时拼接与 Runtime 对数据的解释都可能绕过静态分析。

### 12.4 Generated target 必须标注能力不确定性

AI 生成目标可能改变 Effective Risk Profile。

- HTML / JavaScript / CSS / SVG 等 target MUST 标明生成内容可能改变实际能力；
- JSON / text / Markdown 等 target 也不得标为“能力固定”，因为 Runtime 可能把字段解释成 URL、HTML、脚本片段或其它行为数据；
- authoritative final 后必须重新扫描 generated target；
- Trusted Same-Origin 的最终授权判断应使用本次 Effective Risk Profile，而不是只看 Base Package。

### 12.5 Consent 比普通 Web 更严格

Trusted Same-Origin MUST 使用独立 consent version / storage key / UI，不得复用普通 Web 的“允许执行 `sandbox=allow-scripts`”授权。

首次授权或风险扩大重新授权时：

- 当前 Effective Risk Profile 必须可见，3 秒计时从风险档案已渲染且可阅读后开始；
- 必须明确说明可能读取/修改本站存储、访问宿主页面、以当前登录状态调用本站功能并向网络发送可访问数据；
- confirm action 至少禁用 3 秒；切换 package / generated overlay / risk profile 后重新计时；
- “始终信任”默认不得勾选；
- 取消立即回到 Restricted Mode。

V1 的 Trusted Same-Origin 授权状态 SHOULD 仅保存在当前浏览器本地，不做账号级跨设备同步。

授权至少绑定：

```text
packageDigest
consentPolicyVersion
```

“仅本次允许” SHOULD 进一步绑定 `generatedDigest`。持久信任 MAY 跨 generation 复用，但每次 authoritative final 仍必须重新扫描；若出现此前未接受的高风险类别，MUST 重新授权。

### 12.6 额外安全边界

用户 Web Package V1 不提供自行注册 Service Worker 的产品能力；相关行为应标为高风险，并通过可行的 CSP / resource namespace policy 限制其持久控制范围。

Host SHOULD 通过 iframe allow / Permissions Policy 默认拒绝当前产品不需要的 camera、microphone、geolocation 等敏感浏览器能力。same-origin 本身不得自动授予这些能力。

Package document response SHOULD 继续附加适合当前 execution mode 的：

```text
Referrer-Policy: no-referrer
X-Content-Type-Options: nosniff
```

Restricted Mode 的 HTML SHOULD 保持 `Content-Security-Policy: sandbox allow-scripts` 或等价约束；Trusted Same-Origin 的响应策略必须与其显式授权一致，不能被 Restricted Mode 的 CSP 意外再次降为 opaque origin。

HTTPS external resources MAY 使用，但关键 Runtime 依赖 SHOULD 自包含于 Package。Package capability 声明不是权限授予。

服务端 authorization 不因 Trusted Same-Origin 放宽：authentication、object-level authorization、role / owner、quota / rate limit、mutation safety 与幂等边界继续独立执行。

当前实现已提供双阶段本地预检、独立三秒确认、本次/版本信任、风险扩大重新确认、撤销及缓存失败提示；本次许可绑定 generated digest，版本许可绑定包摘要及策略/扫描版本。新增网络目的地和不确定性也触发重新确认；扫描不完整不能持久信任。普通 Web consent 仍独立，拒绝同源权限继续走 §11 的受限物化路径。

## 13. Prompt Projection 与 generation wire contract

完整 Web Package bytes MUST NOT 因为生成需要而整体上传给 AI。

模型只接收 bounded Web Package Prompt Projection，例如：

```ts
type WebPackagePromptProjectionV1 = {
  package: {
    id: string;
    name: string;
    version: string;
    digest: string;
  };
  entry: string;
  target: {
    path: string;
    mediaType: string;
    mode: 'replace';
  };
  instructions?: string;
  schema?: unknown;
  assetCatalog?: unknown;
  example?: string;
};
```

`example` 是包作者**显式声明**的目标文件结构示例（manifest `generation.example`），按与 `instructions` 相同的方式做 byte-budget 约束后投影。宿主 MUST NOT 自动把 base target 文件当作示例注入：base target 常常是占位内容（内置竞技场新闻的 base `index.html` 只有一句「这里等待 AI 生成完整新闻网站」），把它当示例等于教模型复现占位页。示例内容属于 creator material，落在不可信层。

Prompt trust boundary 必须保持：

```text
Host contract
> creator metadata / instructions / schema / asset catalog / example
```

creator material 不得覆盖：

- Arena authority；
- winner / adjudication；
- safety；
- system instruction；
- target path / media type；
- control trailer；
- writeback authority。

Host block 只包含宿主固定规则；包名称、schema 注释及其它 creator-controlled 字段均属于不可信数据。统一结构化编码 creator material，转义可伪造分隔符的字符，并在其后重申宿主权威。此分层降低提示注入混淆，模型输出仍必须通过独立的协议、权限和内容校验。

### 13.1 Local Package

服务端无法读取用户本地 ZIP，因此 generation request 应允许客户端发送经过结构校验和 byte-budget 约束的 Prompt Projection，而不是只发送 `WebPackageRef` 再让服务器从内置 registry 查包。

### 13.2 Builtin / Future Online Package

Builtin / online source MAY 由服务端按 immutable digest 自行解析并重建 projection；也 MAY 统一使用同一 projection wire shape并做额外验证。

实现应避免形成两套不兼容 generation contract。

## 14. 内部 output contract

`reportFormat` 继续为 `web`，但内部 output contract SHOULD 区分：

```text
web-document
web-package-target
```

不要继续把 JSON / JS / CSS target 伪装成 `web-document`。

逻辑：

```text
reportFormat=web + no package
→ web-document

reportFormat=web + package selected
→ web-package-target
```

这样 ordinary Web 的 HTML 专属 normalization / replay 逻辑无需持续增加 Package 特判。

## 15. Provider Output 与 authoritative final

Package-backed generation 输出逻辑上仍为：

```text
Generated Target Payload
+
Arena Control Trailer
```

Host MUST：

```text
provider final
   ↓
extract MAHOSHOJO_ARENA_META
   ↓
strip control trailer
   ↓
remaining target payload
   ↓
media-specific validation
   ↓
create overlay
```

control trailer 不属于 Package 文件。

streaming 期间 MAY 展示 target partial text，但 MUST NOT：

- partial overlay；
- iframe live reload；
- partial JSON apply；
- incremental JS execute。

只有 authoritative final + meta + target validation 全部成功后才能 mount Package。

输出契约失败不自动调用第二次 Provider 生成完整 HTML。

## 16. Web 包选择 UI / UX

### 16.1 UI 目标，而非固定组件结构

规格不强制实现为“三个默认折叠 accordion”。

实现应优先参考现有角色、情景和素材导入的交互语言，并结合响应式 UI / UX 最佳实践选择最自然的结构。

允许：

- compact section + disclosure；
- 预设 grid + 本地 file input；
- picker modal；
- tabs；
- 桌面展开、移动端折叠；
- 其它与现有产品视觉一致的结构。

但 MUST 满足以下产品不变量：

1. Web 包设置不得抢占 Arena 主流程的视觉层级；
2. 默认状态应保持简洁；
3. 当前是否已选择 Web 包必须清楚可见；
4. 同一 generation 最多只能有一个 active Web Package；
5. 未选择任何包就是自由 Web，不需要“禁用 Web 包”的额外选项；
6. 选择预设或成功导入本地 ZIP 即自动成为当前 Web 包；
7. 用户必须能移除 / 更换当前 Web 包；
8. 预设包必须有独立下载按钮，不能因选择卡片而误触下载，反之亦然；
9. 本地导入必须能展示导入失败原因和当前已加载包摘要；
10. 多人模式不得展示不可共享的本地包为可发布共享配置；
11. 键盘、焦点、ARIA、触摸目标和小屏布局必须保持可用。

2026-09-28 交互收口：预设 Web 包复用角色/情景预设的 grid 与下载小按钮。每个预设的下载入口始终独立于当前选择；“移除”只取消 active package、回到自由 Web，不删除 session staging 或本机缓存。导入区域提前说明任意非 builtin revision 当前只能生成目标与安全文本回退。

### 16.2 组件复用

优先复用或轻量抽取现有：

```text
PresetGridPicker
ScenarioPresetGridPicker
ScenarioPickerPanel
ArenaMaterialSection
BattleDataModal
CollapsibleSection / DisclosureButton
```

已有 `PresetGridPicker` 与 `ScenarioPresetGridPicker` 本身存在明显重复，允许抽出小型 generic resource/preset grid 供三者共同使用。

不得为了 Web 包过早建立一个巨大的 `UniversalResourcePicker`，除非真实重复量已足以证明收益高于抽象成本。

未来线上 Web 包库可以复用 `BattleDataModal` 的“我的 / 公开 / 推荐 / 收藏 / 搜索 / 分页”产品模式，但不要求现在提前泛化全部数据卡 UI。

## 17. Multiplayer 边界

PR #57 已实现 Web Package ref 在 Room Shared Config、Proposal、conflict、host reconciliation、generation snapshot 和多人 history 中的传播。该 plumbing 可以保留，但必须按 source capability 收口。

### 17.1 Builtin

预设 Web 包：


前提是所有客户端和服务器都能按 immutable digest 取得同一 revision。

### 17.2 Local

本地 ZIP：

```text

```

这里的 single-player = supported 现包括标准 ZIP 导入、生成、session/可选缓存、exact/显式兼容重放，以及 §11 支持范围内的通用 Web Experience。历史详情会单独恢复 exact 本地缓存，不要求先访问包选择器。缺失包、内容验证错误与渲染能力不支持是不同状态。竞技场新闻仍由 AI 完整生成 `index.html`，包提供可选静态素材和模拟交互；现已与用户包共用 generic renderer。选择/下载/导入不会自动授予同源权限。

### 17.3 Future Online

未来线上 Web 包在能够按 immutable digest 供所有成员解析之后，MAY 接入 multiplayer。

是否共享 Package 不改变每个成员独立的 Web execution consent。

## 19. Exact Replay 与跨版本兼容重放

Package digest 继续定义“原战报生成时的精确 Base Package 身份”，但不再定义“唯一允许尝试执行的 Base Package”。

### 19.1 Exact replay

```text
loadedPackage.digest === requiredPackage.digest
→ exact replay
```

这是默认、无警告路径。

### 19.2 Compatibility replay

若 digest 不同，用户 MAY 显式选择“仍尝试使用此 Web 包”。

只有一个匹配目标契约的候选时，可直接确认该候选；有多个候选时，必须先明确选择具体 `version + digest` 再确认，不自动挑选所谓“最高版本”。`version` 是包的标签，不要求 SemVer；候选列表的稳定展示顺序不代表兼容性优先级。选定候选失效时重新选择，不静默替换成其它候选。

首版最低兼容门禁：

- candidate package 本身合法；
- package `id` 与历史依赖相同；
- target path 相同；
- target media type 相同；
- historical overlay `generatedDigest` 仍正确。

然后尝试：

```text
candidate Base Package
+
historical Overlay
→ best-effort render
```

允许：

```text
new package + old overlay
old package + new overlay
```

只要 target contract 没有实质破坏，就可能正常工作。

若 candidate schema 明确拒绝 historical overlay，应显示明确警告 / 失败，不要求 V1 再提供“忽略 schema 强制运行”的第三层 unsafe mode。

Compatibility replay MUST NOT 改写历史 provenance。历史记录始终保留原 required digest。

UI 应明确：

> 当前使用的是不同版本的 Web 包，效果可能与生成时不一致。

## 22. Future Online Web Package Library

本轮不实现，但正式冻结演进方向。

### 22.1 产品语义复用数据卡

未来 SHOULD 复用：

```text
private / public / banned
pending / approved / rejected
public approved browsing
reviewed updates
recommendation
favorites / usage / likes（若实际有价值）
300 KiB per slot 的配额产品规则
```

具体哪些社交字段值得给 Web 包保留，应按真实产品价值决定，不要求机械复制所有数据卡字段。

### 22.2 存储模型

不要把 ZIP / 多文件正文塞进现有 `data_cards.data TEXT`。

倾向：

```text
D1
→ web_packages metadata / owner / visibility / review
→ immutable revision metadata / R2 refs

R2
→ immutable Web Package ZIP payload
```

线上库可以复用数据卡 moderation / visibility / update workflow 的语义与部分基础设施，但 SHOULD 使用独立数据模型，而不是把 `web-package` 硬塞进当前 data card type enum。

### 22.3 线上资源 ceilings

线上 Package 不继承普通数据卡当前 1 MiB hard cap。

但一旦使用平台 R2 / bandwidth / review / CPU，就必须另行设置：

```text
archive size
uncompressed size
file count
single-file size
per-user quota
frequency / bandwidth protections
```

300 KiB slot 的 charged-size 口径留到线上库规格冻结。优先考虑能代表平台真实长期存储成本、又不易被压缩比规避的口径。

### 22.4 Online Library 不是 History Pinning CDN

未来即使有线上库，历史系统也不因为 report 引用某个 Web Package 就额外复制或永久 pin 一份。

若 exact revision 仍在 online source，可用于 exact replay；否则用户可加载本地 exact / compatible revision，或查看 target fallback。

## 27. 设计原则摘要

后续实现出现取舍时，优先遵循：

> **Web 包是一项 Web 战报资源，不是新的战报模式。**

> **没选包就是自由 Web；选了包就自动使用。**

> **预设包必须是真正、可下载、可重新导入的标准包。**

> **预设专属逻辑属于包，不属于 generic Web Package runtime。**

> **Package ≠ Prompt；只把 Prompt Projection 给 AI。**

> **Base immutable；AI 只产生一个完整 target overlay。**

> **UI 优先复用现有角色 / 情景 / 素材交互语言，但不把实现绑死在某一种折叠结构。**

> **已有高价值地基保留；只有产生真实冲突的超范围实现才收回。**

> **线上库做好接口预留，但在 builtin + local 真正跑通前不提前建设。**

> **digest 定义精确 provenance，不禁止用户明确尝试兼容 revision。**

> **Restricted Mode 是 baseline；Trusted Same-Origin 是独立的高权限 opt-in。**

> **Same-origin permission 不是 transport dependency；拒绝授权不应让本来可用的 Web 包失效。**

> **安全预检描述风险与不确定性，不提供“安全认证”。**
