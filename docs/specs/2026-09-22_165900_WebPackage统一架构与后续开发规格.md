## 1. 本轮冻结结论

Web Package 正式中文名称统一为 **Web 包**。英文与代码层使用 **Web Package / `web-package` / `WebPackage*`**。

Web 包不是新的 Arena 战报格式，也不是需要用户额外开启的一种模式。Arena 顶层格式继续保持：

```text
reportFormat = markdown | web
```

在 `reportFormat = web` 时：

```text
未选择 Web 包
→ 沿用现有自由 Web 路径
→ AI 生成完整 HTML document

选择了 Web 包
→ 采用 Package-backed Web 路径
→ AI 只生成该包声明的唯一 generation target
→ Base Package + Single-file Overlay
```

因此 UI MUST NOT 再增加“启用 Web 包”“是否使用 Web 包”等额外开关。

Web 包来源分为：

```text
builtin  预设 Web 包
local    用户本地 ZIP Web 包
online   未来线上 Web 包库
```

V1 当前应完成 `builtin + local`。`online` 只冻结扩展边界与数据方向，不作为当前 PR 的交付退出条件。

## 2. 命名规范

### 2.1 用户可见名称

中文 UI 使用：

```text
Web 包
预设 Web 包
导入本地 Web 包
在线 Web 包
```

帮助文档首次出现时可写：

```text
Web 包（Web Package）
```

不要求普通用户理解 `WebPak`、Overlay、Prompt Projection 等内部术语。

### 2.2 技术名称

代码与包名继续采用：

```text
WebPackage
WebPackageRef
WebPackageManifest
WebPackageOverlay
@mahoshojo/web-package
mahoshojo-web-package
```

不再把 `WebPak` 作为正式协议名称，以避免与 Webpack 混淆。

### 2.3 Manifest 文件名

标准 ZIP 根 manifest 冻结为：

```text
web-package.json
```

不再使用旧稿的：

```text
webpak.json
```

PR #57 当前使用的通用 `manifest.json` 也应迁移到更具辨识度的 `web-package.json`。

## 3. 核心架构模型

Web 包是一棵已经准备完成、可以在浏览器环境运行的不可变文件树。

```text
Immutable Base Web Package
        +
One AI-generated Overlay File
        ↓
Derived Web Experience
```

Web 包 MAY 包含：

- HTML；
- JavaScript；
- CSS；
- browser-ready Runtime；
- 第三方依赖；
- 图片、SVG、音频、视频、字体；
- JSON / Markdown / text；
- JSON Schema；
- creator instructions；
- semantic asset catalog；
- 其它静态浏览器资源。

AI 不得原地修改 Base Package。一次 generation 只产生一个完整 target file，并以 overlay 方式遮蔽同路径 base file。

V1 仍只支持：

```text
generation.mode = replace
```

不支持多文件生成、任意 diff、JSON Patch、AST patch、package stacking、package dependency graph、npm install、bundler、Node、WebContainer 或 Host Bridge。

---

## 4. 标准 Web Package Manifest V1

推荐冻结以下 logical contract：

```json
{
  "format": "mahoshojo-web-package",
  "formatVersion": 1,

  "id": "creator.example",
  "name": "Example Web Package",
  "version": "1.0.0",

  "entry": "index.html",

  "generation": {
    "target": "data/report.json",
    "mode": "replace",
    "mediaType": "application/json",
    "instructions": "ai/instructions.md",
    "schema": "schemas/report.schema.json",
    "assetCatalog": "ai/assets.json"
  },

  "capabilities": ["scripts", "audio"],

  "files": [
    {
      "path": "index.html",
      "mediaType": "text/html",
      "digest": "sha256:...",
      "size": 8192
    }
  ]
}
```

其中：

- `format` MUST 为 `mahoshojo-web-package`；
- `formatVersion` MUST 为 `1`；
- `entry` MUST 存在且为浏览器入口；
- `generation.target` MUST 唯一；
- `generation.mode` V1 MUST 为 `replace`；
- `generation.target` 不得为 `web-package.json`；
- `instructions`、`schema`、`assetCatalog`、`capabilities` MAY 缺失；
- 缺少 `capabilities` 等价于空数组；
- `files` 用于文件完整性、媒体类型、canonical identity 与导入验证。

V1 target 仍限定为文本型 artifact。初始允许：

```text
text/html
text/plain
text/markdown
text/css
text/javascript
application/javascript
application/json
image/svg+xml
```

二进制媒体应属于 Base Package，不作为 AI generation target。

## 5. Path 与完整性规则

所有包内路径 MUST：

- 为相对路径；
- 使用 `/`；
- 不以 `/` 开头；
- 不包含 `.` 或 `..` path segment；
- 不包含反斜杠；
- 不包含 NUL；
- normalization 后唯一。

实现 MAY 为跨平台可移植性拒绝明显危险的 Windows reserved filename，但不得通过过窄的 ASCII-only path schema 无必要地禁止正常 Web 文件名。

ZIP entry MUST NOT 解压到宿主真实文件系统。

Manifest 声明了 `digest` / `size` 的文件 MUST 对实际 bytes 验证。

文件 digest 统一使用：

```text
sha256:<lowercase hex>
```

Package-level digest MUST 基于 canonical manifest + file identity，而不是 ZIP archive bytes。不同 compression level、ZIP metadata 或文件排列顺序不应让逻辑上相同的包得到不同 package identity。

canonical serialization MUST 通过 contract tests 冻结。

## 6. 预设 Web 包是一等标准包

### 6.1 不允许“伪预设包”

所有预设 Web 包 MUST 遵循与本地导入完全相同的 Web Package manifest、文件完整性、generation target、overlay 与 rendering contract。

预设 Web 包不得依赖仅存在于宿主 TypeScript 中的私有运行逻辑才能工作。

### 6.2 可下载与可重新导入

每个预设 Web 包 MUST 提供 ZIP 下载。

用户下载预设 ZIP 后，再通过“本地 Web 包导入”加载，MUST：

- 通过同一 generic importer；
- 得到相同逻辑 package revision / digest；
- 使用相同 Prompt Projection；
- 使用相同 target validation；
- 产生等价渲染行为。

ZIP archive bytes 本身无需相同，但 canonical package identity MUST 相同。

### 6.3 Visual Novel Lite

PR #57 已实现的 Visual Novel Lite SHOULD 保留为第一个预设 Web 包，但必须从“宿主中特殊硬编码的一种 Web 体验”收敛成真正的标准包。

其专属内容应放入包内，例如：

```text
visual-novel-lite.zip
├── web-package.json
├── index.html
├── runtime/
│   └── app.js
├── styles/
│   └── app.css
├── assets/
│   └── backdrop.svg
├── data/
│   └── story.json
├── ai/
│   ├── instructions.md
│   └── assets.json
└── schemas/
    └── story.schema.json
```

通用 `@mahoshojo/web-package` 层不得知道 `STORY_LOADER`、`VisualNovelStorySchema`、固定 CSS path、固定 SVG path 等 Visual Novel Lite 私有实现细节。

### 6.4 Builtin Registry

预设 registry 只负责“发现与选择”，不得成为包内部运行逻辑的第二份来源。

可包含：

```ts
type BuiltinWebPackagePreset = {
  packageRef: WebPackageRef;
  title: string;
  description: string;
  downloadUrl: string;
};
```

包实际是什么，由 canonical ZIP / package artifact 定义。

## 7. JSON Schema 必须通用化

PR #57 当前 Visual Novel Lite 虽声明 JSON Schema，但真正校验仍依赖宿主 `VisualNovelStorySchema`。这只能作为 PoC，不得成为最终标准包路径。

当：

```text
generation.mediaType = application/json
```

Host / validator MUST：

1. 剥离 Arena control trailer；
2. `JSON.parse`；
3. 若包声明 `generation.schema`，读取包内 schema；
4. 使用通用 JSON Schema Draft 2020-12 validator；
5. validation 成功后才形成 overlay。

预设包与本地导入包必须走同一 validator。

不允许 generic Web Package core import 某个预设包专属 Zod schema 作为真实 authority。

## 8. Web 包来源与统一 Resolver

实现应把“Web 包来自哪里”和“Web 包如何运行”解耦。

逻辑上：

```text
Builtin Source
Local ZIP Source
Future Online Source
       ↓
ResolvedWebPackage
       ↓
Prompt Projection / Overlay / Render
```

推荐 source abstraction：

```ts
type WebPackageSourceKind = 'builtin' | 'local' | 'online';
```

当前不要求提前实现 `online` 代码，只要求今天的接口不要把未来线上包堵死。

所谓“为线上库预留”是：

> 当前 contract / source / resolver seam 能在以后增加 online adapter，而无需重写 package identity、overlay、history 和 renderer。

不得为了未来预留而提前增加空 D1 migration、空 R2 API、空审核 UI 或半成品在线库。

## 9. 本地 ZIP 导入

本地 Web 包是当前下一阶段核心能力。

完整路径：

```text
Local ZIP
   ↓
Generic ZIP Importer
   ↓
Manifest + File Validation
   ↓
ResolvedWebPackage
   ↓
Browser-local staging
   ↓
Prompt Projection
   ↓
Arena Generation
   ↓
Single Target Overlay
   ↓
Package Resource Resolver
   ↓
Sandboxed Web Experience
```

使用成熟 ZIP library，不手写 ZIP parser。

本地导入不设置产品级固定：

```text
MAX_ARCHIVE_BYTES
MAX_UNCOMPRESSED_BYTES
MAX_FILE_COUNT
MAX_SINGLE_FILE_BYTES
```

但实现必须捕获：

- corrupt archive；
- unsupported compression；
- browser memory failure；
- quota failure；
- parser failure；
- manifest / digest / path validation failure。

资源失败必须作为普通本地加载失败呈现，不得拖垮主站。

现有 PR contract 中类似 `files.max(1024)` 的固定产品上限不应作为本地 Web 包协议不变量保留。

## 10. IndexedDB 与本地缓存

本地包导入后，当前运行所需 staging MAY / SHOULD 使用 IndexedDB 或其它适合的浏览器本地存储。

至少区分语义：

```text
current-session staging
optional persistent cache
```

用户此前明确的“可选缓存”原则继续有效，但主生成流程不要求一定出现一个显式 checkbox。

UI MAY 采用：

- 导入后提供“保留在本机”；
- 本地 Web 包管理区提供缓存/移除；
- 若实现成本更低，也可在不承诺 durability 的前提下自动 best-effort cache。

无论采用何种 UI，都不得宣称 IndexedDB 是永久保存。浏览器 eviction、清站点数据和 quota refusal 都可能使缓存消失。

## 11. Package Resource Resolver

通用 Web Package renderer 必须支持真实包内相对路径，而不是依赖某个预设的字符串替换。

应支持至少：

```text
<script src="./runtime/app.js">
import "./module.js"
<link rel="stylesheet" href="./styles/app.css">
CSS url(...)
<img src="./assets/foo.webp">
<audio src="./assets/bgm.ogg">
nested relative paths
```

当前实现状态（过渡收口，2026-09-24）：

- Builtin Visual Novel Lite 通过 first-party `srcdoc` 过渡适配器渲染；
- 非 builtin revision 在该适配器下 fail-closed，回落安全文本，不提供 URL mount；
- 生产 Arena 渲染已停用 Service Worker URL mount。

目标状态仍为：

```text
Service Worker / 独立 sandbox origin / materialization 之一
+
IndexedDB-backed package store
+
窄 URL namespace
```

例如：

```text
/__web-package__/instance/<opaque-id>/<path>
```

resolution：

```text
overlay[targetPath]
→ 命中则返回 overlay

否则
→ 返回 immutable Base Package file
```

其它路径不得逃逸出该 instance。

迁移差距：sandboxed iframe（`sandbox="allow-scripts"`，无 `allow-same-origin`）的导航与子资源经 Chromium 实证全部绕过 Service Worker；CSP 响应头 `sandbox` 变体的导航经 SW、`navigator.serviceWorker` 抛 `SecurityError`、子资源仍绕过。因此 SW + opaque 组合当前不可达 generic resource-space contract。独立 sandbox origin 或 materialization 方案另开专项 PR，需真实浏览器门禁。

规格仍要求 generic resource-space contract，不把 UI 或 renderer 绑定到仅适用于 Visual Novel Lite 的 materialization；Visual Novel Lite `srcdoc` 自包含 materializer 在此期间只作为过渡 fixture / adapter，不得继续命名或抽象成通用 `renderWebPackage()` 的唯一实现。

## 12. Sandbox 与网络权限

Web 包继续是不可信 Web 内容。

至少保持：

```html
sandbox="allow-scripts"
referrerpolicy="no-referrer"
```

不得因为 Package presence 自动增加：

```text
allow-same-origin
allow-forms
allow-popups
allow-top-navigation
Host Bridge
filesystem
clipboard
```

Package document response SHOULD 附加：

```text
Content-Security-Policy: sandbox allow-scripts
Referrer-Policy: no-referrer
X-Content-Type-Options: nosniff
```

HTTPS external resources MAY 使用，但关键 Runtime 依赖 SHOULD 自包含于 Package。Package capability 声明不是权限授予。

当前状态与迁移差距：过渡期仅 builtin 经 `srcdoc` 过渡适配器渲染（保持上述 sandbox 属性）；非 builtin revision 在过渡适配器下 fail-closed 到安全文本。URL mount 路径已停用，待独立 sandbox origin 或 materialization 专项 PR 恢复。见 §11。

## 13. Prompt Projection 与 generation wire contract

完整 Web Package bytes MUST NOT 因为生成需要而整体上传给 AI。

模型只接收 bounded Web Package Prompt Projection，例如：

```ts
type WebPackagePromptProjectionV1 = {
  package: {
    id: string;
    name: string;
    version: string;
    digest: string;
  };
  entry: string;
  target: {
    path: string;
    mediaType: string;
    mode: 'replace';
  };
  instructions?: string;
  schema?: unknown;
  assetCatalog?: unknown;
};
```

Prompt trust boundary 必须保持：

```text
Host contract
> creator instructions / schema / asset catalog
```

creator material 不得覆盖：

- Arena authority；
- winner / adjudication；
- safety；
- system instruction；
- target path / media type；
- control trailer；
- writeback authority。

### 13.1 Local Package

服务端无法读取用户本地 ZIP，因此 generation request 应允许客户端发送经过结构校验和 byte-budget 约束的 Prompt Projection，而不是只发送 `WebPackageRef` 再让服务器从内置 registry 查包。

### 13.2 Builtin / Future Online Package

Builtin / online source MAY 由服务端按 immutable digest 自行解析并重建 projection；也 MAY 统一使用同一 projection wire shape并做额外验证。

实现应避免形成两套不兼容 generation contract。

---

## 14. 内部 output contract

`reportFormat` 继续为 `web`，但内部 output contract SHOULD 区分：

```text
web-document
web-package-target
```

不要继续把 JSON / JS / CSS target 伪装成 `web-document`。

逻辑：

```text
reportFormat=web + no package
→ web-document

reportFormat=web + package selected
→ web-package-target
```

这样 ordinary Web 的 HTML 专属 normalization / replay 逻辑无需持续增加 Package 特判。

---

## 15. Provider Output 与 authoritative final

Package-backed generation 输出逻辑上仍为：

```text
Generated Target Payload
+
Arena Control Trailer
```

Host MUST：

```text
provider final
   ↓
extract MAHOSHOJO_ARENA_META
   ↓
strip control trailer
   ↓
remaining target payload
   ↓
media-specific validation
   ↓
create overlay
```

control trailer 不属于 Package 文件。

streaming 期间 MAY 展示 target partial text，但 MUST NOT：

- partial overlay；
- iframe live reload；
- partial JSON apply；
- incremental JS execute。

只有 authoritative final + meta + target validation 全部成功后才能 mount Package。

输出契约失败不自动调用第二次 Provider 生成完整 HTML。

## 16. Web 包选择 UI / UX

### 16.1 UI 目标，而非固定组件结构

规格不强制实现为“三个默认折叠 accordion”。

实现应优先参考现有角色、情景和素材导入的交互语言，并结合响应式 UI / UX 最佳实践选择最自然的结构。

允许：

- compact section + disclosure；
- 预设 grid + 本地 file input；
- picker modal；
- tabs；
- 桌面展开、移动端折叠；
- 其它与现有产品视觉一致的结构。

但 MUST 满足以下产品不变量：

1. Web 包设置不得抢占 Arena 主流程的视觉层级；
2. 默认状态应保持简洁；
3. 当前是否已选择 Web 包必须清楚可见；
4. 同一 generation 最多只能有一个 active Web Package；
5. 未选择任何包就是自由 Web，不需要“禁用 Web 包”的额外选项；
6. 选择预设或成功导入本地 ZIP 即自动成为当前 Web 包；
7. 用户必须能移除 / 更换当前 Web 包；
8. 预设包必须有独立下载按钮，不能因选择卡片而误触下载，反之亦然；
9. 本地导入必须能展示导入失败原因和当前已加载包摘要；
10. 多人模式不得展示不可共享的本地包为可发布共享配置；
11. 键盘、焦点、ARIA、触摸目标和小屏布局必须保持可用。

### 16.2 组件复用

优先复用或轻量抽取现有：

```text
PresetGridPicker
ScenarioPresetGridPicker
ScenarioPickerPanel
ArenaMaterialSection
BattleDataModal
CollapsibleSection / DisclosureButton
```

已有 `PresetGridPicker` 与 `ScenarioPresetGridPicker` 本身存在明显重复，允许抽出小型 generic resource/preset grid 供三者共同使用。

不得为了 Web 包过早建立一个巨大的 `UniversalResourcePicker`，除非真实重复量已足以证明收益高于抽象成本。

未来线上 Web 包库可以复用 `BattleDataModal` 的“我的 / 公开 / 推荐 / 收藏 / 搜索 / 分页”产品模式，但不要求现在提前泛化全部数据卡 UI。

## 17. Multiplayer 边界

PR #57 已实现 Web Package ref 在 Room Shared Config、Proposal、conflict、host reconciliation、generation snapshot 和多人 history 中的传播。该 plumbing 可以保留，但必须按 source capability 收口。

### 17.1 Builtin

预设 Web 包：

```text
single-player = supported
multiplayer   = supported
```

前提是所有客户端和服务器都能按 immutable digest 取得同一 revision。

### 17.2 Local

本地 ZIP：

```text
single-player = supported
multiplayer   = unsupported in V1
```

本地包不得进入 Room Shared Config / Proposal，也不得自动上传或分发给成员。

### 17.3 Future Online

未来线上 Web 包在能够按 immutable digest 供所有成员解析之后，MAY 接入 multiplayer。

是否共享 Package 不改变每个成员独立的 Web execution consent。

## 18. History Dependency

Package-backed result SHOULD 保存紧凑依赖信息：

```ts
type WebPackageReportDependencyV1 = {
  packageId: string;
  packageName?: string;
  packageVersion?: string;
  packageDigest: string;

  targetPath: string;
  targetMediaType: string;
  generatedDigest: string;
};
```

Generated target 继续沿用现有 report output retention / storage。

对于 local package：

- 服务器不保存 Base Package bytes；
- 不自动上传 ZIP；
- 不把 Runtime / assets 写入历史正文。

对于 builtin / future online package：

- history 仍保存 immutable digest；
- 服务端或客户端可以按 source 解析 exact revision。

## 19. Exact Replay 与跨版本兼容重放

Package digest 继续定义“原战报生成时的精确 Base Package 身份”，但不再定义“唯一允许尝试执行的 Base Package”。

### 19.1 Exact replay

```text
loadedPackage.digest === requiredPackage.digest
→ exact replay
```

这是默认、无警告路径。

### 19.2 Compatibility replay

若 digest 不同，用户 MAY 显式选择“仍尝试使用此 Web 包”。

首版最低兼容门禁：

- candidate package 本身合法；
- package `id` 与历史依赖相同；
- target path 相同；
- target media type 相同；
- historical overlay `generatedDigest` 仍正确。

然后尝试：

```text
candidate Base Package
+
historical Overlay
→ best-effort render
```

允许：

```text
new package + old overlay
old package + new overlay
```

只要 target contract 没有实质破坏，就可能正常工作。

若 candidate schema 明确拒绝 historical overlay，应显示明确警告 / 失败，不要求 V1 再提供“忽略 schema 强制运行”的第三层 unsafe mode。

Compatibility replay MUST NOT 改写历史 provenance。历史记录始终保留原 required digest。

UI 应明确：

> 当前使用的是不同版本的 Web 包，效果可能与生成时不一致。

## 20. Missing-package fallback

缺少 Base Package 时，用户仍应能读取 generated target。

建议：

```text
application/json → pretty-print
text/html        → source / safe ordinary text
JS/CSS/SVG/text  → code/plain text
```

不得为了 fallback 再调用模型生成 Markdown。

## 22. Future Online Web Package Library

本轮不实现，但正式冻结演进方向。

### 22.1 产品语义复用数据卡

未来 SHOULD 复用：

```text
private / public / banned
pending / approved / rejected
public approved browsing
reviewed updates
recommendation
favorites / usage / likes（若实际有价值）
300 KiB per slot 的配额产品规则
```

具体哪些社交字段值得给 Web 包保留，应按真实产品价值决定，不要求机械复制所有数据卡字段。

### 22.2 存储模型

不要把 ZIP / 多文件正文塞进现有 `data_cards.data TEXT`。

倾向：

```text
D1
→ web_packages metadata / owner / visibility / review
→ immutable revision metadata / R2 refs

R2
→ immutable Web Package ZIP payload
```

线上库可以复用数据卡 moderation / visibility / update workflow 的语义与部分基础设施，但 SHOULD 使用独立数据模型，而不是把 `web-package` 硬塞进当前 data card type enum。

### 22.3 线上资源 ceilings

线上 Package 不继承普通数据卡当前 1 MiB hard cap。

但一旦使用平台 R2 / bandwidth / review / CPU，就必须另行设置：

```text
archive size
uncompressed size
file count
single-file size
per-user quota
frequency / bandwidth protections
```

300 KiB slot 的 charged-size 口径留到线上库规格冻结。优先考虑能代表平台真实长期存储成本、又不易被压缩比规避的口径。

### 22.4 Online Library 不是 History Pinning CDN

未来即使有线上库，历史系统也不因为 report 引用某个 Web Package 就额外复制或永久 pin 一份。

若 exact revision 仍在 online source，可用于 exact replay；否则用户可加载本地 exact / compatible revision，或查看 target fallback。

## 27. 设计原则摘要

后续实现出现取舍时，优先遵循：

> **Web 包是一项 Web 战报资源，不是新的战报模式。**

> **没选包就是自由 Web；选了包就自动使用。**

> **预设包必须是真正、可下载、可重新导入的标准包。**

> **预设专属逻辑属于包，不属于 generic Web Package runtime。**

> **Package ≠ Prompt；只把 Prompt Projection 给 AI。**

> **Base immutable；AI 只产生一个完整 target overlay。**

> **UI 优先复用现有角色 / 情景 / 素材交互语言，但不把实现绑死在某一种折叠结构。**

> **已有高价值地基保留；只有产生真实冲突的超范围实现才收回。**

> **线上库做好接口预留，但在 builtin + local 真正跑通前不提前建设。**

> **digest 定义精确 provenance，不禁止用户明确尝试兼容 revision。**
