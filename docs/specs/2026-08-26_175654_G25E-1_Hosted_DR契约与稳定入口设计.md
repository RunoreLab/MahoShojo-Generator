# G25E-1 Hosted DR 契约与稳定入口设计

状态：`accepted`

日期：2026-08-26

设计标识：`DESIGN-G25E1-hosted-dr-contract-stable-endpoint-v1`

依据：`ADR-hosted-runtime-resilience-cloudflare-dr`、`SPEC-platform-restructure-v1`、
`SPEC-platform-restructure-goal-execution-v1`、`PLAN-platform-restructure-goals-v1`

## 1. 当前事实与迁移差距

G25H-2 终点的机器事实为 `22 shared-service / 6 exited / 0 legacy-next`。22 条 shared route
均有 Hono adapter 与 Next/OpenNext adapter，并复用 `@mahoshojo/hosted-api` / `@mahoshojo/hosted-runtime`
业务核心；客户端也已经把 `https://api.mahoshojo.colanns.me` 作为 Hosted 目标，不再编码物理
`homura.colanns.me`。

这仍未满足 G25E-1：

- `config/hono-api-routes.json` 只记录 placement inventory，不记录 method、replay class、secret、
  DatabaseProvider、contract test 或 DR activation 状态；
- 稳定域名、物理 primary/DR origin、健康探针与 unknown request 选择语义没有同一机器可读 contract；
- Hono D1 Gateway / management API client 与 Cloudflare 原生 D1 binding 没有共同的 consistency scope；
- Web runtime 虽优先读取 D1 binding，但 shared Hosted composition 没有显式要求 D1 Sessions/bookmark，
  且生产 DR binding 缺失时仍存在 HTTP fallback 路径；
- 客户端 hardcode 只能证明逻辑域名存在，不能机械证明物理 origin、active-passive 和 no-replay 约束；
- 缺少一个 Hono/Next 共用 contract 且能由控制面探测的 safe/read capability。

本 Goal 不把这些差距误写成“生产 DR 已启用”。Cloudflare Load Balancing、DNS、Worker router 或其他
实际流量产品的购买、配置、切流与 fault drill 均不在 G25E-1 授权内。

## 2. Objective 与范围

Objective：建立长期 Hosted DR 的可维护 contract 面，使每项 capability 的 replay/secret/data/contract
状态、两个 D1 provider 的一致性语义和稳定逻辑入口选择规则可由代码与 CI 机械验证；客户端只依赖稳定域名，
但仓库不伪报外部控制面已启用。

实际范围拆为三个可回滚 checkpoint：

1. versioned DR capability/control-plane manifest + validator；
2. Hono primary 与 Cloudflare D1 binding/Sessions DatabaseProvider + shared safe/read probe；
3. 客户端稳定入口 source of truth、Next DR capability guard 与 CI/文档收口。

明确不包含：

- production deploy、DNS/LB/Access/secret 修改或入口切流；
- G25E-2 的 Hono/Redis/Gateway/D1/mid-flight/version-skew 完整故障矩阵；
- generation active-active、unknown mid-flight transparent replay；
- 第二套 SQL authority、D1 schema migration、Redis authority 提升；
- Tea Party/Tavern re-entry、Arena Room realtime 或其他后置产品功能。

## 3. 方案比较与裁决

### 3.1 采用：外部 active-passive 控制面契约 + 可执行选择 seam

稳定域名、primary/DR origin、origin probe、active-passive 和 replay policy 进入机器可读 contract；
runtime-neutral selector 只决定“新请求可以选择哪里”，对已经 dispatch 或 outcome unknown 的非幂等请求
返回 fail closed。客户端只读取稳定 origin，不读取物理 origin，也不实现 fallback。

实际 Cloudflare 产品保持 `not-provisioned`，由后续授权与 G25E-2 drill 激活。这样既形成稳定 seam，
又不虚构尚未发生的 DNS/LB 状态。

### 3.2 不采用：新建通用 Cloudflare Worker reverse proxy

该方案能完全在仓库内实现请求级 router，但会让全部 SSE/长流再次经过 Worker，恢复此前的 CPU/成本故障域；
若 Worker 对失败 POST 自动换 origin，还会制造第二 Provider。缺少资源基线和生产控制面授权时，不应在 G25E-1
引入该部署单元。

### 3.3 不采用：浏览器 Hono 失败后改请求同源 Next

客户端无法证明请求是否到达 Hono/Provider，且 Installed Client 重新发布会成为切流前置条件。这违反
`DR-002`、`DR-008` 和客户端不可信边界。

## 4. 机器可读 DR contract

新增 `config/hosted-dr-capabilities.json`，它与 `config/hono-api-routes.json` 职责不同：

- route inventory 继续决定 Hono 挂载与 exited capability；
- DR manifest 决定长期双 runtime capability 的 method/replay/secret/provider/contract/activation 语义。

顶层至少包含：

```ts
type HostedDrManifestV1 = {
  schemaVersion: 1;
  contractVersion: string;
  controlPlane: {
    stableOrigin: string;
    primaryOrigin: string;
    drOrigin: string;
    mode: 'active-passive';
    provisioning: 'not-provisioned' | 'preview' | 'production';
    primaryProbePath: string;
    drProbePath: string;
  };
  databaseProviders: Array<{
    id: 'hono-d1-primary' | 'cloudflare-d1-binding';
    transport: 'd1-gateway-or-management-api' | 'd1-binding-sessions';
    authority: 'd1';
    supportsBookmarks: boolean;
  }>;
  capabilities: HostedDrCapabilityV1[];
};
```

每条 route/capability 记录：

```ts
type HostedDrOperationV1 = {
  method: 'GET' | 'HEAD' | 'POST' | 'DELETE';
  requestClass: 'safe-read' | 'durably-idempotent-command' | 'non-idempotent-operation';
  drMode: 'safe-read' | 'new-request-only' | 'fail-closed';
  replayPolicy: 'safe-read-only' | 'operation-id-required' | 'never-after-dispatch';
};

type HostedDrCapabilityV1 = {
  id: string;
  route: string;
  operations: HostedDrOperationV1[];
  requiredSecrets: Array<{ name: string; minLength?: number }>;
  requiredBindings: string[];
  primaryDatabaseProvider: 'hono-d1-primary';
  drDatabaseProvider: 'cloudflare-d1-binding';
  consistency: 'replica-ok' | 'primary';
  contractTests: string[];
  contractStatus: 'verified' | 'fail-closed-verified' | 'pending';
  drillStatus: 'pending-g25e-2' | 'verified';
};
```

validator MUST：

- 要求 DR capability 与 shared route inventory 双向覆盖，exited/legacy route 不得混入；
- 拒绝重复 capability、route、method 和非法动态 segment；
- 拒绝把 non-idempotent operation 配成 safe replay；
- 拒绝把 production provisioning 写成已启用而没有显式生产证据文件；
- 检查 Hono adapter、Next Route Handler 与 contract test path 均存在；
- 检查 stable/primary/DR origin 为互不混淆的 HTTPS origin，客户端配置只消费 stable origin；
- 只允许 secret 名称和最小长度进入仓库，不允许 secret 值；
- 保持 `legacyRouteIds=[]`。

根 `check:hosted-dr` 进入 `workspace:verify`，使 manifest drift 在 CI fail closed。

## 5. DatabaseProvider 与一致性 scope

`@mahoshojo/hosted-runtime` 新增窄 `DatabaseProvider`：

```ts
type DatabaseConsistency = 'replica-ok' | 'primary';

type DatabaseSession = {
  client: NodeDataD1Client;
  consistency: DatabaseConsistency;
  initialBookmark: string | null;
  getBookmark(): string | null;
};

type DatabaseProvider = {
  id: 'hono-d1-primary' | 'cloudflare-d1-binding';
  openSession(input: {
    consistency: DatabaseConsistency;
    bookmark?: string | null;
  }): DatabaseSession | null;
};
```

### 5.1 Hono provider

Hono provider 复用当前 D1 Gateway / management API client。该 transport 始终走 primary 语义，
因此对 `replica-ok` 提供更强保证；传入 bookmark 时保持其 scope lineage，但不伪造新的 D1 bookmark。
provider 不改变 HTTP retry contract：只有显式 `safe-read` 可以 transport retry，写操作继续 `retry: none`。

### 5.2 Cloudflare provider

Cloudflare DR provider 只接受当前 OpenNext runtime 的原生 `DB` binding，并要求 `withSession()`：

- `replica-ok` 且无 bookmark -> `first-unconstrained`；
- `primary` 且无 bookmark -> `first-primary`；
- 有 bookmark -> 以 bookmark 建立后续 session，维持 sequential consistency；
- `getBookmark()` 只返回 binding session 实际产生的 bookmark；
- production DR 缺 binding、缺 `withSession` 或 session 初始化失败 -> capability unavailable，MUST NOT
  回退 D1 Gateway/Cloudflare management API。

本地开发可以显式使用旧 HTTP adapter，但它不能被标记为 `cloudflare-d1-binding`，也不能成为 DR PASS 证据。

### 5.3 Shared safe/read capability

新增 `GET|HEAD /api/hosted/dr-readiness`：

- application contract 位于 `@mahoshojo/hosted-api`；
- Hono 与 Next adapter 注入各自 DatabaseProvider；
- 只执行固定 `SELECT 1 AS ok`，使用 `replica-ok` scope；
- 成功响应包含固定 contract version、`hono-primary | next-dr` placement、provider ID 与一致性等级；
- 不返回 bookmark 原值、环境变量、URL、SQL、secret 或任意用户数据；
- provider/binding/session/query 缺失或失败时返回固定 `503 HOSTED_DR_CAPABILITY_UNAVAILABLE`；
- response `Cache-Control: no-store`，可作为 DR origin synthetic probe；
- route 本身不需要 Redis、AI Provider、签名或认证 secret。

它是 `ACCEPT-012` / `ACCEPT-015` 在 G25E-2 进行 fault injection 的最小代表 safe/read capability，
不被描述为全部业务 readiness。

## 6. Stable endpoint 与选择语义

Web `honoApiConfig.origin` 从 DR manifest 的 `controlPlane.stableOrigin` 读取。客户端 bundle 只获得稳定域名，
不获得 primary/DR secret，也不执行 health routing。

共享 selector 固定：

| 请求状态 | safe/read | durably-idempotent command | non-idempotent/generation |
| --- | --- | --- | --- |
| 尚未 dispatch，primary healthy | Hono | Hono | Hono |
| 尚未 dispatch，primary unavailable | 可选 Next DR | 仅 authority proof 已启用时 | 可选择 Next DR 新 operation |
| 已 dispatch 或 outcome unknown | 可安全重新读取 | 只按稳定 operation ID 查询/恢复 | MUST fail closed，不透明第二次 POST |
| failback | 只影响后续新请求 | 只影响后续新请求 | 只影响后续新请求 |

selector 不调用网络、不重试请求，只输出 `hono-primary | next-dr | fail-closed` 决策，供未来 LB/Worker/DNS
adapter 与 fault harness 共同使用。实际外部控制面必须关闭 non-idempotent request-level zero-downtime retry；
本 Goal 只形成 contract，不声称供应商产品已配置。

## 7. Next DR secret/provider guard

所有 DR manifest 中的 Next Route Handler 在 production execution 前经过同一 guard：

1. 解析 route + method 对应 operation；
2. `drMode=fail-closed` 直接返回固定 503，不调用 shared service/Provider；
3. 校验 capability 所需 secret 名称、最小长度与 binding；
4. 要求 `cloudflare-d1-binding` provider 能建立声明的一致性 session；
5. 缺项返回固定 `HOSTED_DR_CAPABILITY_UNAVAILABLE`，只记录 capability ID 与缺失类别，不记录值；
6. 通过后才调用原 shared service，guard 不实现重试或 fallback。

Arena active generation create/cancel 在 Next 没有共享 Redis identity 时继续 `fail-closed`；terminal lookup/status/
stream 可以作为 safe read 从 D1/R2 恢复。常规生成只有在请求尚未 dispatch 且控制面已经选择 DR 时才可执行；
未知 Hono POST 不得由 guard 再发一次。

## 8. 测试与验收

按 TDD 至少覆盖：

1. manifest drift、route/adapter/test path、secret name 与 replay-class 负面矩阵；
2. selector 对 safe/read、idempotent、non-idempotent 的 before-dispatch/unknown/failback 矩阵；
3. Hono provider 的 primary-strength 与 safe-read retry 不扩张；
4. Cloudflare provider 的 `first-unconstrained`、`first-primary`、bookmark propagation 与 binding 缺失 fail closed；
5. shared readiness Hono/Next response parity、HEAD、provider/SQL failure、无 bookmark/secret 泄漏；
6. production Next guard 的 secret/binding/drMode 负面用例，确认 blocked handler 调用数为 0；
7. Web 客户端只使用 stable origin，manifest 切换物理 origin 不要求 client config 改动；
8. existing 22 route contract、Arena no-replay、Legacy/Better Auth、signature/data tests 无回归；
9. package/app tests、typecheck/lint、route generation、boundary、Next/OpenNext/Hono build 与 `ci:verify`。

G25E-2 才执行完整 Hono unavailable、Redis empty、Gateway unavailable、mid-flight disconnect、D1 unavailable、
version skew 与 cutback fault matrix。G25E-1 不用 mock-only probe 宣称这些场景已经 PASS。

## 9. 回滚与外部影响

三个 checkpoint 均可普通 `git revert` 逆序回滚。无 schema/data migration、Redis flush、DB restore、
secret rotation、release 或客户端数据迁移。若回滚 manifest，必须同时回滚 guard/generated route/readiness
adapter，不能留下 route inventory 与 DR contract 不一致。

未启用 production control plane 时，回滚不要求 DNS/LB 操作。未来 G25E-2/production activation 若建立外部
配置，必须先把稳定入口回切到已验证 primary，再回滚代码；该操作不属于本 Goal。

## 10. Stopping condition 映射

- DR manifest 记录 replay/secret/provider/contract：本设计第 4 节；
- representative safe/read 同核：第 5.3 节；
- Cloudflare 独立 D1 binding/provider：第 5.2、5.3 节；
- 两 provider consistency/bookmark：第 5 节；
- non-idempotent no replay：第 6、7 节；
- stable endpoint/control-plane seam：第 4、6 节；
- secret missing fail closed/minimal copy：第 4、7 节；
- 不伪造未启用 LB：第 1、3、6、9 节。
