# Arena 多人 GMR-09 权威生成发布设计

日期：2026-08-28

状态：`accepted / implementing`

实现基线：`9d212014dc43ec2f8a39f18bfbea41187d03cbc8`

适用 Goal：`GMR-09 authoritative generation publisher`

## 1. Objective

在既有 Hono + Redis Room authority 与 G25R durable Arena generation 上接通 host-only start、冻结 generation snapshot、
single producer、进程内安全投影、成员 story gap 恢复与权威终态读取。Room reservation 必须先于 provider execution 持久化；
浏览器、socket reconnect 和进程恢复不得盲目重发 provider POST。

本设计不推翻既有 accepted ADR/spec。客户端不可信、服务器权威、secret 隔离、Legacy/Better Auth、Arena v1 wire、
Redis/D1/R2 数据所有权和 non-idempotent no-blind-replay 继续有效。

## 2. 基线事实与方案选择

当前 Room core 已有 opaque `generation-reserver` / `generation-publisher` capability、exact epoch/request/generation/attempt
fence、64 条 immutable ledger 和 generation started/completed/failed control event；RoomActor 已保证 transition → Redis CAS →
install → replay/fan-out。G25R generation 已有 stable actor/request generation ID、Redis reservation/lease/single producer、
75ms/1024-byte markdown batching、typed subscription、D1/R2 terminal recovery 和 no-POST resume。

当前缺口是生产态 coordinator/publisher、story transient fan-out、Room-member-safe generation projection 和 Web generation
cursor。现有 owner HTTP resume 不能给成员复用：multiplayer generation 使用 `pvp-room:<roomId>` actor，成员身份不是 owner，
且 PVP actor signature 绑定 POST body。

评估方案：

1. **采用：Room coordinator + app-internal owned generation port + transient publisher。** Room 先 checkpoint reservation，再由
   同进程直接调用既有 generation service；重启后按 trusted actor scope 读/reconcile/resume，不建立第二套 execution。
2. generation service before-start hook。它会倒置 accepted 的 Room-reservation-before-generation 顺序，并把 Room Redis
   authority 耦合进通用 generation service，否决。
3. host browser 转发 AI stream。违反 ROOMRT-016，否决。

## 3. Start contract 与冻结边界

新增：

```text
POST /api/arena/rooms/v1/:roomId/generations
GET  /api/arena/rooms/v1/:roomId/generations/:generationId
```

start body 使用 strict outer schema：

```ts
type ArenaRoomGenerationStartRequest = {
  expectedRoomEpoch: string;
  expectedRevision: number;
  generationRequestId: string;
  sharedConfig: ArenaRoomSharedConfig;
  generation: Record<string, unknown>;
};
```

outer body 沿用 generation 12 MiB 上限；`generation` 是按既有 Arena generation contract 临时提交的完整 host payload。
它只存在于当前 Request/调用栈并直接交给 authoritative generation service，不写 Room checkpoint、directory、日志、WSS、
member response 或 client durable operation record。Provider credential 仍只在 HTTPS request 与 generation executor 内使用。

服务端顺序固定为：

1. 认证 account，解析严格 outer contract，验证 active host、exact room/epoch/revision；
2. 若提交的 safe `sharedConfig` 与 Room 当前 config 不同，以同一 host authority 执行 `publish-config`，等待 Redis CAS；
3. 对最终 frozen config 的全部 canonical online DataCardRef 再做 permission/kind/version 校验；
4. 从当前 authority state 冻结 revision、sharedConfig、active participant IDs、`collaborativeInfluence` 和 canonical
   `sha256:` digest；服务端构造 `ArenaMultiplayerGenerationSnapshot`；
5. 以 `pvp-room:<roomId>` + stable request ID 派生 deterministic `generationId`，attempt v1 固定为 `1`；以 opaque capability
   执行 `reserve-generation` 并等待 Redis checkpoint；
6. 仅在 reservation `applied` 后发起 generation；历史 `idempotent` start 必须先 read/reconcile generation state。只有权威
   `not-found` 且当前请求仍携带同一完整 payload 时才可用同一 request ID 调 create；unavailable/unknown 不得调用第二次；
7. generation payload 由服务端注入 PVP context 与 frozen multiplayer snapshot，再做 body-bound PVP signature。snapshot 进入
   generation semantic payload hash，使同 request ID 不能与不同 frozen snapshot 复用；客户端自带的同名 authority 字段会被覆盖。

`generationRequestId` 是 client intent identity，不是 authority。客户端在一次 unknown operation 内必须保留它；一旦 Room
snapshot 已显示 active generation，refresh/reconnect 只做 GET/session/resume，不得自动 POST。

## 4. App-internal generation port

`configureHonoArenaGenerationRuntime` 返回窄化 server-only capability，并由 `main.ts` 显式注入 Room coordinator；route
registry 继续只服务既有 HTTP adapters。窄化端口提供：

- `startFromHostRequest`：重建保留 auth/activity/signal 的 signed PVP Request，直接调用 concrete typed subscription；
- `readOwnedProjection`：固定 trusted `pvp-room:<roomId>` scope，复用 generation 的 Redis lease reconciliation 与 D1/R2
  terminal fallback，返回 allowlist projection；
- `resumeOwnedSubscription`：复用既有 typed replay/snapshot/terminal 逻辑，不暴露为任意 actorKey 的 public HTTP API。

projection 只允许 generation/request ID、status、完整 authoritative markdown、next Room chunk sequence、resultRef presence/
generationRecordId 和稳定 public error code。reasoning、telemetry、ranking raw payload、provider diagnostic、actor token、PVP
signature、D1 extra JSON、R2 credential/key details和 updated combatant private payload不得进入 Room member response。

## 5. RoomGenerationPublisher

publisher 在 reservation 后捕获 immutable `{roomId, roomEpoch, generationRequestId, generationId, attempt, expiresAt}`；
capability 只能由 trusted coordinator 根据 Room state 签发，不得从 incoming batch 自签。

- `started` 与 terminal 必须通过 RoomActor `mirror-generation`，继续满足 checkpoint-before-control-fanout；旧 epoch/attempt/
  expiry/current-generation mismatch fail closed。
- generation typed stream 中已按 time+bytes 合批的 `markdown` 才转换为 `story.delta`；reasoning/telemetry/snapshot 不广播。
- Room `chunkSeq` 每个 `{roomEpoch,generationId}` 从 `0` 开始且连续递增。typed resume 的 bootstrap snapshot 只作为 HTTP
  authoritative baseline，不转换为 delta；重启/新 epoch 后可重新从 0 fan-out，客户端必须先以 GET baseline 重锚。
- story publish 与 terminal command进入同一 per-room bounded serialized queue；story event再次过 `RoomEventSchema` 和 frame
  byte limit，验证 current open/epoch/running generation。story 是 transient fan-out，不写 checkpoint、controlSeq 或 control replay。
- 单 subscriber 背压继续由现有 per-connection 256 KiB queue 隔离；slow consumer 1013 close，不得阻塞 provider/Room。
- terminal 前 flush 已接收的最后 markdown batch；completed 记录现有 generation `resultRef`/record identity，failed 只投影稳定
  error code。starting 不直接 completed/failed，必要时先幂等 mirror running。

publisher/map 只保证单进程活跃 attach。进程恢复后 coordinator 必须先 `readOwnedProjection`：running/finalizing 才建立一个
typed resume consumer；completed/failed/cancelled/producer_lost 从 generation durable state mirror；not-found 保持 Room
`starting`/unknown，不凭空生成；unavailable 返回 recovery 状态。

## 6. Gap、refresh 与 Web projection

Room Web controller 增加与 control cursor 独立的 generation view：mirror、phase、authoritative baseline、preview markdown、
`{generationId,chunkSeq}` cursor、gap 和 final-authoritative 标记。

- 首帧只能接受 `chunkSeq=0`；之后 exact next append，duplicate/stale ignore，future seq 进入 `resyncing` 并冻结追加。
- reconnect ticket 同时携带 control/story cursor。当前 Room 不持久化 story replay，server 返回 `replay-unavailable` 后客户端
  对 generation GET 做 single-flight authoritative resync；替换全文/baseline 后才接受新 epoch/current generation 的 delta。
- terminal control 到达后必须再 GET 权威 projection；completed final 只能来自 Redis snapshot 或 D1/R2 terminal fallback，partial
  preview 不能冒充最终报告。R2 内容不可用时显式 recovery/unavailable。
- controller 的异步恢复受 room epoch + generation ID + attempt/dispose fence；旧响应不得覆盖新 Room incarnation。
- host/member 共用一个 lifted Room controller。member 与 non-host 不显示/启用 start；host active/unknown 时锁定重复 start。
  单人模式及 feature-off 继续走现有 `useBattleEngine` durable flow。

## 7. Stopping condition

GMR-09 只有同时满足以下条件才能 `DONE`：

- host pending config publish → ref verify → frozen snapshot/digest → Redis reservation → existing generation single producer；
- duplicate start/response-loss 只有一个 provider execution，unknown/reconnect/refresh 不盲目 POST；
- host tab/socket 关闭后 server publisher 继续；batched safe story 可达所有 active peers且不泄漏 reasoning/secret；
- old epoch/attempt/expiry/current-generation story或terminal均拒绝，story与terminal严格串行；
- contiguous/duplicate/gap/slow-consumer、new epoch/process recovery均有可执行证据；
- member GET 只在 active Room membership/current generation 下返回 allowlist projection；final terminal/R2/D1 语义复用 G25R；
- contracts/core/API/Web targeted/full tests、typecheck/lint/build、真实 Redis、workspace gates通过；独立 architecture、security/
  authority、compatibility/replay/data 与 test-adequacy review 的 Critical/Important 清零；
- 没有 production deploy/migration/write、Redis flush、secret/Access/credential、release/tag/push/history rewrite。

## 8. 回滚

contract、hosted generation internal port、Room coordinator/publisher、HTTP/WSS、Web controller/UI 和文档分别形成 atomic
commit，可按逆序 revert。默认 multiplayer feature flag 继续作为暴露面止血但不替代代码回滚。GMR-09 不新增 production
schema migration，不修改 Redis durable generation/Room checkpoint wire，不需要数据恢复。
