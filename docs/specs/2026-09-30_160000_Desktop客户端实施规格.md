# Desktop 客户端实施规格

状态：`active`
日期：2026-09-30
规格标识：`SPEC-desktop-client-v1`
约束决策：[Desktop Tauri V1 运行时与本地安全边界决策](../decisions/2026-09-30_160000_DesktopTauriV1运行时与本地安全边界决策.md)
被约束的既有决策：[客户端运行时与发行决策](../decisions/2026-08-22_022400_客户端运行时与发行决策.md)、[本地库与数据所有权决策](../decisions/2026-08-22_022300_本地库与数据所有权决策.md)

本规格只定义 `apps/desktop` 应用边界的可测试要求。规范性词汇遵循 RFC 2119 / RFC 8174。
Hosted、签名、排位与多人语义继续由各自 accepted 规格约束，本规格不重述。

2026-10-02 补充：[产品共源 ADR](../decisions/2026-10-02_184000_Desktop产品架构与Web共源决策.md) 与[产品一致性规格](./2026-10-02_184000_Desktop产品一致性与本地优先规格.md) 定义整体页面、能力与旅程；本规格继续定义 runtime 机制。`DESK-003` 的联网数据口径按下文精确修订，其余未说明的门禁不变。

## 1. 应用边界

### DESK-001 应用所有权

`apps/desktop` **MUST** 成为独立 workspace app，持有自己的 manifest、README、lint/test/build
生命周期与 `src-tauri` 运行时。占位 README 或空壳 manifest **MUST NOT** 被当作应用边界已激活的证据。

### DESK-002 依赖方向

- `apps/desktop` **MUST NOT** import `apps/*` 的内部源码；
- Desktop 的平台适配 **SHOULD** 通过 `@mahoshojo/*` 的显式 `exports` 消费共享能力；
- 未来若新增 Tauri 平台包，**MUST** 被纳入 workspace 边界检查的客户端包名单，使其受
  `MONO-005-CLIENT-SECRET` 约束。

### DESK-003 本地 UI 产物

主 UI **MUST** 由本地构建产物提供，`frontendDist` **MUST** 指向 Vite 的 `dist`。主 UI 的脚本、样式、字体与内置产品资源 **MUST** 随产物提供，**MUST NOT** 在运行时加载远端主 UI 或用远端代码替换本地产品壳。

本地启动与本地旅程 **MUST NOT** 依赖项目服务器的数据读取。用户主动使用线上库、账号、排行榜、Hosted 或多人等在线能力时，**MAY** 经独立、受控且完成认证/权限验收的在线适配器读取业务数据；故本条不再一律禁止“应用数据”。在线数据不授予脚本执行或 native 权限，也不允许 Direct Profile 访问项目域名。

该修订不直接放宽 `DESK-020` 的 CSP；任何需要新增来源或 native command 的实现仍须逐项接线并通过相应安全门禁。产品可用性与零项目请求验收见 `DESK-PROD-004` / `DESK-PROD-011`。

### DESK-004 不内嵌服务器运行时

Desktop **MUST NOT** 内嵌或启动 Hono、Node 或其他服务器运行时，也 **MUST NOT** 复用 Hosted
transport 作为本地能力实现。可复用的是 `domain` / `contracts` / `ai-core` / `local-library` /
`web-package`，以及按真实消费者提取的 `ui-web` 页面与控件；后者不携带 Next/Tauri 或服务器实现。

## 2. capability 与信任面

### DESK-010 capability 粒度

每个 capability 文件 **MUST** 只使用 `webviews`，**MUST NOT** 使用 `windows` 或通配 label。

### DESK-011 主 UI 授权面

主 UI webview label **MUST** 为 `main-ui`，并且：

- **MUST NOT** 匹配任何 `shell` / `fs` / `sql` / `http` 通用权限；
- **MUST NOT** 匹配任何允许任意 URL 或任意路径的参数化 scope；
- V1 **MUST NOT** 引入 Tauri 插件，除非该插件的每个 command 都被单独论证并写入本规格。

renderer 的业务与 native 应用能力 **MUST** 仅由本应用自有 command 提供。Tauri core 权限
**MAY** 仅为可信主 UI 的框架级生命周期需要逐项授予（当前为 event listen/unlisten 与
window destroy），**MUST** 采用显式最小集合并由结构门禁钉死，**MUST NOT** 使用
`core:default` 或任何成组 core 权限集合。

2026-10-26 D5.2 的唯一插件例外为官方 `tauri-plugin-updater`，用于签名版本更新。
插件 `check`、`download`、`install`、`download_and_install` 四个 command **MUST NOT** 向任何 renderer 授权：
分别涉及可覆盖检查选项、资源下载、安装与组合执行；这些参数与资源必须留在 Native 内部，
由 DESK-084 的窄自有 command 调用 Rust API。无需安装 renderer 的 `@tauri-apps/plugin-updater`。

### DESK-012 自有 command 收窄

一旦出现第二个 webview，`apps/desktop/src-tauri/build.rs` **MUST** 通过
`tauri_build::AppManifest::commands` 把全部自有 command 纳入应用 ACL——该声明的作用是
让每条 command 生成 `allow-` / `deny-` 权限并进入 ACL 判定，避免默认"所有 command 对
所有 webview 可用"。真正把权限授予 `main-ui` 的是 capability 对 `allow-*` 的逐项引用；
不匹配任何 capability 的 webview **MUST** 保持对全部自有 command 的拒绝。

### DESK-013 不可信渲染面

Web Package 渲染面 **MUST** 是独立 webview，且 **MUST NOT** 匹配任何 capability。主 UI
**MUST NOT** 以 iframe 承载 Web Package 或任何用户提供的可执行内容。

### DESK-014 浏览器权限默认拒绝

不可信 webview **MUST** 默认拒绝浏览器级权限请求（camera、microphone、geolocation 等）。

### DESK-015 受限作品窗口控制

可信 `main-ui` 可经自有 `control_web_package_instance` command 管理已打开的作品实例。
请求只包含 Native 已分配的 `instanceId` 与封闭动作：`status`、`focus`、`reload`、`close`、
`set-fullscreen`（后者附明确布尔值）。Native **MUST** 从 registry 的 Serving 实例取得窗口，
**MUST NOT** 接受调用方提供的 label、URL、脚本或权限；Collecting / Opening 不能被控制。
窗口 API 调用前释放 registry 锁，避免关闭回调重入死锁。关闭释放实例，重载沿用原冻结资源与政策；
该能力不读写本地库、不改变网络政策，也不赋予作品 capability。

状态回执区分 `open`（含实际 fullscreen 布尔值）与 `closed`。已销毁实例查询 / 重复关闭返回
`closed`；对已销毁实例的聚焦、重载或全屏请求失败，不自动创建新实例。重新运行需重新确认。
主界面退出不冒称撤销已经派发的打开；无法确定打开结果时提示用户检查独立窗口，不自动重发。
Native 作品菜单可提供同范围操作与全屏退出快捷键，其目标由原生窗口自身绑定，不能由作品页面指定。

Windows 可先加载 Native 自己创建的隐藏空文档，再安装 WebView2 的页面关闭与全屏退出处理器，
最后加载冻结的作品入口。空文档许可 **MUST** 限于首次精确 `about:blank`，且在任何作品加载前
永久撤销；安装失败或超时销毁窗口。该启动步骤不承载用户内容，不增加 capability，也不放行作品的
`about:` 导航。页面关闭事件须销毁所属顶层窗口，不能只关闭内部 WebView 而留下空窗及资源记录。

### DESK-020 CSP

`app.security.csp` **MUST** 显式配置，**MUST** 只允许自身与必要的 `ipc:` / `asset:` 来源。
**MUST NOT** 允许 `*` 通配脚本来源。开发模式所需的 Vite HMR 连接 **MUST NOT** 通过放宽生产 CSP 实现。

## 3. Direct AI

### DESK-030 Profile 与 endpoint 权威

- 出站 endpoint **MUST** 来自 `DirectProviderProfileV1`；
- 请求 DTO **MUST NOT** 携带 baseUrl、header 字面量或 secret 明文；
- **MUST NOT** 提供请求级 endpoint 覆盖参数。

### DESK-030a OpenAI Responses 独立文本适配

- `openai-responses` **MUST** 与既有 `openai-compatible` Chat Completions 分离；首片仅开放自定义 Profile，不迁移既有预设或本机发现协议。Anthropic 与 Google 后继分别见 DESK-030b/030c。
- 请求 **MUST** 在 Profile API 根路径追加 `/responses`，保留 `/v1` 等前缀，复用既有凭据快照、Bearer、出站和取消策略。输入按原序映射 `role` / `content`，保留所选模型；输出上限映射 `max_output_tokens`，JSON 模式映射 `text.format.type = json_object`，不宣称 JSON Schema 保证。
- 请求 **MUST** 显式 `stream: true`、`store: false`；**MUST NOT** 发送 `previous_response_id`、`conversation`、`background`、`tools` 或 Chat `stream_options`，不自动换模型、协议、删参数重试。
- typed events **MUST** 按 output item/content 身份与顺序消费文本和推理；added/done/final 快照只验证，不能重复追加。工具、图片或拒绝等不可消费输出即使混有文本也 **MUST** 明确失败；不把 `encrypted_content` 当正文或伪造重放。
- 同一 reasoning item 的 summary/content 两路 **MUST** 分别校验身份、索引与最终快照；以首个非空 delta 所属视图作为该 item 的唯一推理展示路，另一视图不得重复追加，空 delta 不抢占展示路。两路接受的文本均计入既有正文预算，不借隐藏路无限积累。仅最终快照出现的非空内容不得伪造为已收到的流式文本。
- 仅 `response.completed` 且 response status 为 `completed`、有可消费非空白正文才成功；`failed` / `error`（含 HTTP 200）失败，`incomplete` 的 `max_output_tokens` / `content_filter` 分别映射 `output-too-large` / `content-filtered`，其他原因映射 `invalid-response`。已接收正文保留。
- Responses **MUST NOT** 以 Chat `[DONE]` 充当终态；EOF 缺合法终态为截断。取消优先、单一终态、UTF-8/SSE framing、聚合、预算与 registry 沿 DESK-032；usage 缺失保持未知，不伪造零。
- 验收 **MUST** 分列官方形状合成 fixture、真实 loopback HTTP/SSE 与真实供应商/Windows；自动化通过不冒称后两项已验收。

### DESK-030b Anthropic Messages 独立文本适配

- 自定义 Profile 的 `anthropic` **MUST** 追加 `/messages` 到已保存 API 根路径，保留 DESK-030/031 的 endpoint、凭据与 transport 权威。`apiKeyRef` 映射 `x-api-key`；固定 `anthropic-version: 2026-10-21`，协议 header 冲突或重复 API key 来源明确拒绝，不静默覆盖。
- 请求 **MUST** 提取首部连续 system 为顶层文本块，其他消息保持 user/assistant 顺序；首末必须为 user。中途 system、developer/tool 与 assistant prefill 不在本片支持范围，明确失败，不改写历史指令。`max_tokens` 为正整数，未指定时为 4096，可由请求覆盖；不猜模型上限。
- 此固定 API 版本不接受采样参数。Native 首次构造 **MUST NOT** 发送 temperature/top_p/top_k；UI 明示温度与 thinking/effort 设置不生效并保留旧偏好，不按模型名猜测，也不失败后删参重试。JSON 继续使用文本指令与既有本地解析/schema 校验，不承诺供应商结构化输出，不发送其他协议的格式字段。
- typed reducer **MUST** 独立校验 message/content block 的类型、顺序与关闭状态。初始 text/thinking 与对应 delta 分别进入正文/推理；signature 与 redacted thinking 仅有界校验和消耗，不展示、解密、记录或持久化。未知顶层事件可在预算内忽略，未知 content/delta、工具、多模态或 fallback block 明确失败。当前 SSE 依 `data.type` 分派，不宣称校验 `event:` 与 data 一致性。
- 成功 **MUST** 有合法 `message_stop`、已关闭 block、已知正常 stop reason 与非空白正文；`end_turn`/`stop_sequence` 成功，`max_tokens`/`model_context_window_exceeded` 为 `output-too-large`，`refusal` 为 `content-filtered`，tool/pause/未知 reason 为 `invalid-response`。`[DONE]` 不算终态；流内 error 与 EOF 截断失败，保留已收正文，不提交半截卡片或自动续写。
- usage **MUST** 按累计字段更新，缺失保持未知；`input_tokens` 保留供应商不含缓存读写的原值，缓存读取单独映射，不伪造 total 或跨供应商精确费用。正文与 signature/redacted 各有独立 4 MiB 累计预算，普通元数据/未知事件为 16 KiB；原始全流含 SSE framing 的上限为 24 MiB + 16 KiB，单帧允许有界的完整 opaque 值及 JSON framing，不保留无界历史；取消/单终态沿 DESK-032。
- 预设默认、本机发现与 Hosted 不变；Google 独立文本适配见 DESK-030c。仅声明自定义 Profile Messages 文本及本地 JSON 消费；真实供应商/网关与 Windows/Tauri/keyring 必须独立验收，合成 fixture、loopback 与 DOM 测试不能替代。

外部协议依据：[版本史](https://platform.claude.com/docs/en/api/versioning)、[Messages](https://platform.claude.com/docs/en/api/messages/create)、[流式事件](https://platform.claude.com/docs/en/build-with-claude/streaming)、[thinking 密文](https://platform.claude.com/docs/en/build-with-claude/thinking#thinking-encryption)。本片固定版本，不自动回退旧版。

### DESK-030c Google Gemini GenerateContent 独立文本适配

- `google` **MUST** 仅开放自定义 Profile 的 GenerateContent 文本协议，不混用 Interactions、Vertex AI、工具或多模态。既有 Google 预设的 OpenAI-compatible 路径、Hosted 与本机发现保持不变，不因供应商或模型同名继承可信预设能力。
- 请求 **MUST** 从已保存 API 根路径追加 `/models/{model}:streamGenerateContent?alt=sse`，保留版本和代理前缀；模型使用请求覆盖或 Profile 默认，允许一个 `models/` 前缀，其余为安全编码的单个资源组件。配置中的查询、片段、末尾 `/models`、完整生成方法地址与模型路径注入明确拒绝。`apiKeyRef` 仅映射 `x-goog-api-key`，不放 URL；协议 header 冲突与重复 key 来源拒绝，无 key 代理仍允许；transport、secret snapshot 与错误净化沿 DESK-030/031。
- 首部连续 system **MUST** 映射 `systemInstruction.parts`，其余 user/assistant 按原序映射 `contents` 的 user/model；至少有一个非 system 内容，中途 system 拒绝。不额外限制首末角色或交替顺序。只发送本片支持的 `generationConfig` 字段：正整数 `maxOutputTokens` 原值覆盖，未指定省略；有限 0–2 的 `temperature` 原值发送，不夹断或失败后删参重试。UI 明示模型可能不支持/忽略温度，输出预算可能同时包含思考与答案。
- 本片 **MUST NOT** 发送 `thinkingConfig`、`includeThoughts`、tools、cache、续接字段或任意 provider options。UI 明示暂不发送 Thinking 开关/强度并保留偏好，不能保证关闭模型思考或返回摘要。共享 TS 请求虽有可选 thinking，当前 Native 窄 DTO 不接收该字段。显式 JSON 请求仅映射 `responseMimeType: application/json`；既有生成家族继续文本指令与本地 JSON/schema 校验，不宣称业务 schema 保证。
- SSE **MUST** 复用有界 framing，仅投影 candidate 0 的有序 parts：`thought: true` 的 text 进推理，其余 text 进正文；省略 index 时首个候选按 0 处理，其他候选不混入答案。缺候选、空 usage、usage-only、可忽略 role 与普通 metadata 不自行构成失败或成功。已出现的投影字段须类型有效；工具/多模态内容即使夹文本也失败。`thoughtSignature` 仅有界消耗，不展示、持久化或伪造多轮重放。
- 成功 **MUST** 同时有选定候选 `STOP`、非空白正文、正常 HTTP EOF 且未取消；finish 后继续消费有界尾部 usage，相同 reason 可幂等，冲突 reason 或新正文失败。`MAX_TOKENS`/`CONTINUATION` 为 `output-too-large`，已知安全 reason 为 `content-filtered`，未知/工具 reason、流内 error、截断 EOF 或只有推理均失败；`[DONE]` 不作为完成证据。不自动续写、重发或换协议，失败保留已收正文，不提交半截卡片。
- usage **MUST** 按字段快照覆盖，缺失保留未知或前值，显式 0 保留；prompt/candidates/thoughts/cached/total 分别映射 input/output/reasoning/cachedInput/total，不重复相加或反算 total。usage 是整次请求的上游计量，不宣称选中答案的独占费用。已知计数须为共享合同可准确表示的非负整数。
- 原始 wire、单帧、正文/推理和 opaque 均 **MUST** 有界；普通丢弃 metadata 由帧和 wire 预算覆盖，不累积历史或误套小额持久 metadata 限制。普通结果继续遵守共享信封上限，Arena 专用额度不外溢。取消优先、exactly-once result、Channel/registry 清理和默认无硬超时沿 DESK-032。官方形状合成 fixture、真实 loopback/Native→TS 消费与真实供应商、Windows/Tauri/keyring **MUST** 分列验收。

协议依据：[GenerateContent 流式文本](https://ai.google.dev/gemini-api/docs/generate-content/text-generation#streaming-responses)、[请求与响应类型](https://ai.google.dev/api/generate-content)、[Thinking](https://ai.google.dev/gemini-api/docs/generate-content/thinking)、[结构化输出](https://ai.google.dev/gemini-api/docs/generate-content/structured-output)。本片限定适配能力，不等同所有模型均支持每个参数。[Interactions 总览](https://ai.google.dev/gemini-api/docs/interactions-overview)推荐新项目使用 Interactions，同时明确 GenerateContent 仍完全受支持，未公布其退役日期；不把 Legacy 标识解释为已退役。

### DESK-031 transport policy

- HTTP(S) 公网 endpoint 默认允许；明文 HTTP 的非 loopback 地址 **MUST** 需要用户显式确认，
  并由 Profile 的 `transport.allowPublicHttp` 记录；
- redirect **MUST** 默认禁用；若启用 **MUST** 同源且 **MUST NOT** 跨 origin 携带凭据，
  次数 **MUST NOT** 超过 Profile 的 `transport.maxRedirects`（上限 3）；
- **MUST NOT** 提供跳过证书校验的开关；
- 项目自有域名 **MUST** 在 Direct 出站路径上被拒绝，并返回可诊断错误，而不是静默放行。

### DESK-032 流式与取消

- 流式 **MUST** 使用 `Channel<AiStreamEvent>`；
- `AiStreamEvent` **MUST** 遵守既有 `@mahoshojo/ai-core` 语义：单一终态、有序、delta 与事件数有界；
- 每个请求 **MUST** 有稳定 `requestId`，并提供取消入口；
- 取消 **MUST** 中止上游 HTTP body、释放任务、移除注册项，并投递 exactly-once 终态；
- **SHOULD** 在 Rust 侧聚合微小 delta，降低 IPC 压力；
- 2026-10-04 维护者修订：不占用项目线上服务器资源且用户可手动终止的 Desktop Direct 操作，默认 **MUST NOT** 设置应用层连接、空闲或总时长硬超时；**MUST NOT** 沿用 Web 的 300 秒上限。用户手动终止或确认离开/关闭页面后 **MUST** 取消上游并保留已接收正文；拒绝离开不得取消任务。系统网络错误与 Provider 自身限制仍可能结束请求。

## 5. 本地库

### DESK-050 职责分层

业务语义留在 TypeScript，存储机制在 Rust，具体边界遵循 ADR 第 7 条。TypeScript 侧
**MUST** 在调用 IPC 前完成 schema 校验与防御性复制。

### DESK-051 存储不变量

- SQLite **MUST** 启用 WAL，且 **MUST** 记录 schema 版本与 migration journal；
- blob 写入顺序 **MUST** 为：写同目录临时文件 → flush/校验 checksum → 同卷原子 rename → 写 SQLite metadata；
- 崩溃后 **MUST** 可能存在无引用 blob，**MUST NOT** 出现"记录存在但文件缺失"；
- 已存在且 digest/长度校验通过的 blob **MUST** 视为成功，而不是错误；
- 备份 **MUST** 通过 SQLite backup API 或 `VACUUM INTO` 生成一致快照，**MUST NOT** 直接复制运行中的数据库文件；
- 删除继续遵循既有 soft delete；真正 purge **MUST** 做可达性 GC。

### DESK-054 blob 消费范围

2026-10-22 图片后继：下述“唯一生产消费者/不预建图片入口”是 V1 原范围。
[双端本地图片资产首片合同](./2026-10-22_230500_双端本地图片资产首片合同.md)以真实 `/local-library`
独立图片库扩展第二消费者；其独立引用表、预算、备份与生产 schema 12 按该合同执行。
DESK-055/056/057 不变，不因此允许任意附件或图片 URL 下载。

V1 的内容寻址 blob **MUST** 以 **Web Package 原始 ZIP 字节**为唯一生产消费者。图片、附件等
其它消费者 **MUST** 等到出现真实需求时再扩展，**MUST NOT** 在 V1 预建 image metadata、缩略图管线、
引用角色或图片导入入口。

原因是可验证的：当前四种数据卡 schema **均无图片字段**（唯一的图片字段 `questionnaire.logoUrl` 是远程
URL 字符串），立绘字节存在与本地库隔离的另一个 IndexedDB，卡牌工坊的 base64 插图只产出下载文件。
按 [本地库与数据所有权决策](../decisions/2026-08-22_022300_本地库与数据所有权决策.md) 预留的
"大型图片"暂无对应物。

### DESK-055 blob 引用关系

- 每个 blob 消费者 **MUST** 使用**真实外键**指向 `blob` 表，**MUST NOT** 使用
  `owner_kind` + `owner_id` 形态的多态引用：数据库无法校验多态 owner 指向的记录真实存在；
- 出现第二个 blob 消费者时 **MUST** 新增该消费者的引用表，而不是把已有表泛化；
- GC **MUST** 统一查询所有引用表，删除不在任何引用表中的 blob；
- **soft delete MUST NOT** 改变 blob 可达性。删除只写 tombstone 并保留字节；**purge** 才移除引用，
  GC 才允许回收字节。这一规则同时适用于 Web 的 IndexedDB adapter。

### DESK-056 blob 损坏处理

- 写入时若目标路径已存在但重算摘要与该路径不符，视为确定的存储损坏。持有摘要匹配的正确字节时
  **MUST** 自愈覆盖，并**MUST** 返回可诊断的"已修复损坏"状态，**MUST NOT** 静默成功；
- 读取时发现损坏且**没有**已知正确内容时 **MUST** fail closed：**MUST NOT** 删除、**MUST NOT** 猜测、
  **MUST NOT** 返回空内容冒充有效数据。

### DESK-057 blob 物理布局

blob 的物理布局（是否按摘要前缀分片、单层还是多层）**MUST** 是存储 adapter 的实现细节。
`@mahoshojo/local-library` 的 portable archive、SQLite schema 与对外契约 **MUST NOT** 依赖该布局，
因此调整布局 **MUST NOT** 需要数据迁移或改变用户可见语义。

### DESK-063 记录身份摘要与 blob 地址的关系

Web 包记录里的 `contentDigest`（= `ref.digest`）是 **manifest** 的摘要，构成领域身份：包 id 由它
派生。归档 blob 的摘要则是**归档字节自身**的摘要，只充当存储地址与完整性校验。

两者 **MUST NOT** 被要求相等，存储层 **MUST NOT** 因此拒绝一次合法保存。ZIP 除 manifest 外还含
文件，因此二者作为**格式事实**必然不同；但这条事实 **MUST NOT** 被提升成一条被强制的不变量
（schema 或存储层加 `must differ`）：那会把"恰好相等"这个在当前格式下不可能发生的巧合写成拒绝
理由，而它的失败症状是"导入全部失败"，与真正的根因完全无关。规范要冻结的是"两者不得互相替代"，
不是"两者被断言不等"。

归档字节是否真的属于这条记录，**MUST** 由 TypeScript 侧在解包后核对（`unpackWebPackageZip` 会重算
`ref.digest` 并与记录比对）。native **MUST NOT** 为此重建 ZIP 与 manifest 的规范化逻辑（`DESK-050`）。

记录自称的归档长度（`archiveByteLength`）**MUST** 与实际字节数一致；native **MUST** 从 document 取该
字段与实际字节数比对并在不一致时拒绝。长度是"这个包多大"的唯一答复，而详情页、进度与配额估算都
建立在它上面。

### DESK-064 二进制传输信封

IPC 承载二进制 **MUST** 使用显式的、可校验的信封字段，**MUST NOT** 接受 renderer 提供的任意目标
路径。信封 **MUST** 同时携带编码后的载荷与其字节长度，两端 **MUST** 在解码后核对长度：静默接受截断
载荷会产出"看起来完整"的短归档，把失败点推到解包器里，离真正原因很远。

空字节序列在传输层 **MUST** 可表示。"空归档不是合法 ZIP"属于 ZIP 校验的职责，传输信封
**MUST NOT** 顺带断言——否则编码一个空 `Uint8Array` 会产出连自身 schema 都拒绝的载荷。

> 当前实现用 base64 承载该信封。Tauri 2 的原生 raw IPC 要求整个请求体是 raw 形式，无法与结构化参数
> 并存，因此这里是一个显式字段而非自定义通道。代价约 33% 体积，收益是解包路径只有一条。待搬运整个
> archive 的阶段（D2.3）再评估切 raw IPC。

### DESK-065 本地库维护的并发模型

一次 Web 包保存至少跨三个资源：blob 文件系统、blob metadata，然后才是包记录与引用行的事务。
GC、审计与备份**MUST** 在同一时间只与这些操作互斥，否则会观察到中间态。

- **V1 MUST 强制单实例**：同一数据目录 **MUST NOT** 被两个 Desktop 进程同时打开。第二个实例
  **MUST** 拒绝启动并给出可诊断的提示，**MUST NOT** 静默降级为只读或另开一份库。
  进程内互斥（各 store 自己的 `Mutex<Connection>`）**MUST NOT** 被当作满足这一约束的证据。
- GC 的判定 **MUST** 只依据引用表，**MUST NOT** 把 `last_referenced_at` 当作正确性条件。
  一个刚被引用、尚未落 `last_referenced_at` 的 blob 在 GC 眼里就是孤儿。
- 维护操作（GC、审计、备份）**MUST** 在一个受控窗口内独占数据目录：窗口内禁止 save、import、
  delete、restore 与 purge。窗口 **MUST** 由单一入口获取，**MUST NOT** 依赖各 store 自己的锁。
- 窗口内到达的写入 **MUST 被拒绝**，**MUST NOT** 排队。排队同样满足"不观察到中间态"，但会把
  UI 挂起在一个无法解释的等待上；拒绝让 UI 可以立刻告知"本地库正在维护，请稍后重试"。
- GC **MUST** 采用"标记—再确认"而不是"扫描即删"：候选集确定后、真正删除前 **MUST** 重新确认
  引用表未变，避免把 in-flight 写入的 blob 当成孤儿。
- 读取路径 **MUST NOT** 因维护窗口而被阻塞：GC 只回收无引用 blob，而读取只触达被引用的 blob，
  因此维护期间读到的仍是一致状态。要求读也受限只会让用户在备份时无法翻看本地库。

单实例是这条约束的第一部分，也是让 GC、restore 与备份的正确性不依赖跨进程锁协议的原因。
支持多实例属于 `DESK-061` 意义上的版本化演进，**MUST NOT** 靠"顺手加个文件锁"实现。

#### DESK-065 的落地形态

D2.2a 落地，三层并发控制各管一件事，**不可互相替代**：

| 层级 | 机制 | 覆盖 |
| --- | --- | --- |
| 跨进程 | 数据目录 advisory lock（`fs4`） | 同一数据目录只允许一个 Desktop 进程 |
| 跨操作 | `MaintenanceGate`（写者计数 + 单维护者） | 维护独占；窗口内写入被拒 |
| 进程内 | `Mutex<Connection>`（**一条**连接，四个 store 共用） | 单次数据库往返的原子性 |

由此产生两条派生要求：

- 所有本地库 store **MUST** 是同一个 managed state（`LocalLibrary`）的字段，**MUST NOT** 各自注册为
  独立的 Tauri `State`。四个独立 `State` 意味着四条连接，而四条连接之间没有互斥——于是
  `save_web_package` 的"写 blob"与"写包事务"之间存在一个无人持有的观察窗口，GC 落在那里就会
  删掉 in-flight 的字节。**这不是"未来 GC 引入后的风险"，它在 D2.1 落地时就已成立。**
- 写入许可 **MUST** 在 command 层获取，使"一次 IPC 调用 = 一次许可"。若只在某个 store 方法内部
  取许可，`save_web_package` 的第二步（包事务）就落在窗口之外。

### DESK-068 单实例的机制选择

V1 用**数据目录** advisory lock，**MUST NOT** 使用 `tauri-plugin-single-instance`。

- 该插件按 app id 判定，而 V1 的要求是"同一数据目录不被两个进程同时打开"。dev 构建与另一个
  构建可以有不同 app id 却指向同一个 `app_data_dir`——那正是要防的场景，按 app id 加锁挡不住。
- 它是 Tauri 插件，而 `DESK-011` 默认禁止 V1 引入插件。

实现要求：

- 锁 **MUST** 是 OS 持有的 advisory lock（随进程死亡自动释放）。**MUST NOT** 用"锁文件存在即已
  占用"的检查：进程崩溃后它会永久拒绝启动，而用户没有任何自救手段。
- 锁文件 **MUST** 在锁释放后仍然存在。若它随锁一起消失，第二个进程会新建一把锁，两个进程各拿
  一把，单实例约束静默失效。
- 锁 **MUST** 在打开数据库**之前**获取。反过来两个进程可能都已建立连接，然后第二个才失败——
  而它已经跑完迁移阶梯，可能留下一个"迁移了一半"的库。
- 锁句柄 **MUST** 被 manage 出 `setup`。它是 `setup` 的局部变量，不 manage 就会在 `setup` 返回时
  `drop`，锁随之释放。

### DESK-067 维护操作的执行形态

- 维护类 command（审计、GC、备份、恢复）**MUST** 是 `async fn` 且把阻塞工作放进
  `spawn_blocking`。Tauri 的同步 command 在调用线程执行，长操作会冻结整个 WebView。
- 维护类 command **MUST** 在开始前取维护许可，并在整个执行期间持有它。

### DESK-066 完整性审计的分类

审计结果 **MUST** 至少区分下列各桶，**MUST NOT** 只给出"有问题/没问题"：

- 引用存在但**文件缺失**；
- 引用存在但**摘要或长度与 metadata 不符**；
- 有 **metadata 但无任何引用**（可回收候选）；
- 有**文件但无 metadata**（孤儿，允许存在，崩溃窗口产物）；
- **包记录存在但没有引用行**；
- **SQLite 外键违规**。

第五桶（`record-without-reference`）单列的原因：外键方向是"引用行 → 包记录"，因此数据库**不**
约束"每个包记录都必须有引用行"。而缺引用行的包对用户表现为"打不开"（`readArchive` 返回
`null`），与真正的存储损坏无法区分——现有五桶都装不下它。

外键检查 **MUST** 直接运行 `PRAGMA foreign_key_check`；`PRAGMA integrity_check` **MUST NOT** 被
当作外键检查的替代——后者不检查外键。审计 **MUST NOT** 修复问题，**MUST** 只报告；修复只发生在
下一次写入的自愈路径上（`DESK-056`）。

`PRAGMA quick_check`（O(N)）与 `PRAGMA integrity_check`（O(N log N)，且额外验证索引与 UNIQUE）
回答的是另一个问题——"SQLite 文件本身是否损坏"，而不是"本地库的不变量是否成立"。V1 **MUST NOT**
把页级损坏检查纳入审计结果：它是独立问题，纳入会让桶的含义从"我们的不变量"滑向"引擎的健壮性"。
待本地库规模证明它有必要时再作为独立条目引入。

### DESK-072 GC 的删除顺序

GC 回收一个 blob 时 **MUST** 先删 SQLite metadata 行，再删文件。

反过来（先删文件）崩溃后会留下"metadata 在、文件不在"——正是 `DESK-051` 明令禁止的悬空记录。
先删行后删文件，崩溃最多留下孤儿文件，而孤儿文件是**允许存在**的。这与写入路径的不对称性是
镜像的：写入是"文件先、metadata 后"，删除是"metadata 先、文件后"，两者都让"引用不到字节"
成为不可能的状态。

### DESK-071 Desktop 导出与导入的路径与字节来源

> **导出部分的落地形态已由 `DESK-071b` 取代**：不再是"经一次 `export_local_archive` 交给 native"，
> 而是"渲染层组装完整产物 + native 分块落盘"。`DESK-071b` 同时规定了**导出全程不取维护窗口**
> 的理由、一致性边界的表述、命令形状与目标路径的命名保留策略。路径与能力面的要求（renderer
> 不得获得任意路径、V1 不引入 dialog/fs 插件）在本条仍然有效。

Desktop 的 renderer **MUST NOT** 获得任意目标路径，也 **MUST NOT** 直接写文件。落地形态：

- **导出**：渲染层组装完整归档字节，经 Tauri raw IPC 交给 native；native **自行** 选择目标路径
  （`<data_root>/exports/`）并写盘，回显绝对路径。V1 因此**不引入**
  `tauri-plugin-dialog` 或 `tauri-plugin-fs`（`DESK-011`）。
  代价是用户需要自己找到文件；收益是零新增能力面。
- **导入**：渲染层经 `<input type="file">` 读入字节——WebView 标准能力，不需要任何权限——
  再调用既有的 `save_local_card` / `save_web_package` 逐条写入。**导入 MUST NOT** 新增 native
  command：解析 manifest 与判定冲突都是纯 TypeScript 语义（`ADR-desktop-tauri-v1` 第 7 条）。

Web 侧两条路径都零新增能力：导出走 `downloadBlob`，导入走 `<input type="file">`。

`DESK-070` 定义的三个字节上限 **MUST** 分别命名与断言，**MUST NOT** 让其中一个充当另外两个。

### DESK-070 归档级字节上限

portable archive 有**独立的**归档级字节上限，**MUST NOT** 复用 `MAX_BLOB_BYTES`。

`MAX_BLOB_BYTES`（64 MiB）是**单个** blob 的上限。一个包含几十个 Web 包的归档轻松超过它，
而每个包都远小于 64 MiB——把两者混为一谈会让上限形同虚设。

归档上限 **MUST** 由实测推导：在合成归档上记录渲染层与 native 的峰值内存，取一个两侧都留有余量的
值。**MUST NOT** 沿用"整包 base64 过 JSON"而不给出实测数字。超过上限时 **MUST** 以可诊断错误
失败，**MUST NOT** 静默截断。

归档字节顺序 **MUST** 由打包器归一化，**MUST NOT** 依赖调用方预先排好数组。理由是排序只作用于
ZIP 条目顺序并不充分——`manifest.json` 自身把数组顺序写进了字节；调用方漏排一次，归档摘要就变了，
而症状（摘要漂移）与根因（谁忘了排序）完全无关。归一化 **MUST** 发生在唯一写字节的位置，
使这条不变量无法被忘记。

#### 归档的确定性边界

确定性 **MUST** 陈述为：**在给定 `exportedAt` 的前提下**，同一份库两次导出产出逐字节相同的归档。
`exportedAt` 是清单必填字段，因此它必然进入字节；**MUST NOT** 声称归档字节忽略它。

两种用途 **MUST** 分开：

- 判断"这份库的内容变了没有" **MUST** 比较各记录的 `contentDigest` / `archiveDigest`，
  **MUST NOT** 比较整个归档的字节摘要；
- 判断"打包逻辑变了没有" **MUST** 在夹具固定 `exportedAt` 的前提下比较归档字节。

两者混淆的症状是"同一份库两次导出摘要不同"，而根因是调用方问错了问题——它无法通过改打包器修复。

#### 条目时间与时区

所有产出 ZIP 的打包器（Web 包、本地库归档）**MUST** 从同一个共享常量取固定条目时间，
**MUST NOT** 各自内联一份字面量。纪元不同 ⇒ 归档字节不同 ⇒ 摘要不同 ⇒ 跨设备迁移后身份漂移。

该常量 **MUST** 由**本地时间**分量构造（`new Date(1980, 0, 1, 0, 0, 0)`），**MUST NOT** 写成 UTC
字面量（`new Date('1980-01-01T00:00:00.000Z')`）。ZIP 的 DOS 日期字段无时区，而打包库用**本地时间
getter** 编码并校验 1980–2099 区间，因此 UTC 字面量在 UTC 以西的时区是本地 1979-12-31，
年份越界后打包**直接抛错**。

这不是"未来某个功能可能有 bug"：Web 包导出是已在生产的路径，UTC 字面量意味着 UTC 以西的用户
无法导出 Web 包。跨时区回归门禁见 `tests/zip-epoch-timezone.test.ts`，它 **MUST** 起真实子进程
切换 `TZ` 运行两个生产打包器并比对产物摘要，**MUST NOT** 只断言常量的形状——后者在 UTC 机器上
恒真，抓不到这个缺陷。

上限检查 **MUST** 做两次：读之前按清单声明长度求和并拒绝（使不诚实来源也**不会**先分配到超限），
读之后核对累计（使谎报长度的来源无法悄悄突破上限）。只做前者则上限形同虚设，只做后者则上限
退化成事后观测。

当前**输入**上限为 `MAX_LOCAL_LIBRARY_ARCHIVE_INPUT_BYTES = 256 MiB`，由
`scripts/measure-archive-memory.mjs` 实测推导（node v24 / fflate 0.8.3，每档独立进程）：

```text
 8 MiB × 60 → 输入 480 MiB，归档 480 MiB，峰值 1055 MiB RSS  (2.20×)
16 MiB × 30 → 输入 480 MiB，归档 480 MiB，峰值 1025 MiB RSS  (2.13×)
64 MiB ×  8 → 输入 512 MiB，归档 512 MiB，峰值 1109 MiB RSS  (2.17×)
```

2.1–2.2× 是 `zipSync` 的固有代价：它要求**全体条目同时在内存**（1×），再产出完整输出归档（1×）。

因此本上限是**架构上限而非产品上限**：改为 fflate 的流式 `Zip`（逐块读入、逐块落盘）可把峰值降到
O(块大小)，上限即可由产品需要决定。**MUST** 在真机 WebView 里复核渲染层绝对值后才可依赖该数字；
Node 的测量只证明分配形态可比，不证明 Desktop 上的绝对占用。改动该常量 **MUST** 重跑实测脚本
并把新数字写入提交说明。

#### 三个不同的字节上限

"归档级字节上限"此前是一个名字覆盖三件不同的事，而它们的上限来源与失败后果都不同：

| 常量 | 度量什么 | 现状 |
| --- | --- | --- |
| `MAX_LOCAL_LIBRARY_ARCHIVE_INPUT_BYTES` | **打包输入**总量：manifest 字节 + 全部未压缩载荷声明长度之和，再核对读取后的累计 | 256 MiB（实测推导） |
| `MAX_LOCAL_LIBRARY_ARCHIVE_OUTPUT_BYTES` | `zipSync` 产出的**最终归档文件**长度 | 256 MiB（打包器与 native 两侧各自断言） |
| `MAX_LOCAL_LIBRARY_IPC_CHUNK_BYTES` | 单次 raw IPC 请求体 | 4 MiB（仅 Desktop；吞吐侧待真机实测） |

`MUST NOT` 让输入预算充当输出上限。ZIP 有 local header、central directory 与 EOCD 开销，
输入预算不等于输出文件大小；条目数多时这部分开销可观。输出上限 **MUST** 在 `zipSync` 之后
单独断言，与输入上限同值起步，超出时以可诊断错误失败。

输出上限 **MUST** 在**共享打包器**里断言，**MUST NOT** 只由 native 落盘时兜底。native 那条核对
是必要的（它独立于渲染层，且保护磁盘），但它发生在**打包的内存与 CPU 代价已经付完之后**；而
Web 侧的导出**不经过 Rust**，因此"输入预算与输出上限是两个概念"这条不变量必须在共享层落地。

在此之前，超过**输入**上限的库 **MUST** 以 `archive-too-large` 失败，**MUST NOT** 被静默截断或分卷。

#### 字节传输

超过单 blob 量级的字节 **MUST** 走 Tauri raw IPC（`tauri::ipc::Response`），**MUST NOT** 走 base64
过 JSON。已核对 tauri 2.12：结构化请求 + raw 响应可以共存（限制只在"命令参数不能来自 raw 请求体"），
因此读取方向不需要自定义封包；`InvokeBody::Raw` 取代整个请求体，故写入方向无法携带结构化参数。

写入方向的元数据 **MUST** 走 IPC header，**MUST NOT** 自造"长度前缀头 + 数据"的私有封包协议。
已核对 tauri 2.12 的 `InvokeOptions.headers` 与 `tauri::ipc::Request::headers()`：raw 请求体之外
仍可携带 header，而 `fflate` 式的自造封包要自行处理分片、校验与版本，是一处会长期腐化的东西。

单次请求体 **MUST** 以块传输，块大小 **MUST** 由实测确定（见下）。

读取方向 **MUST** 在字节量级超过单 blob 时就切 raw 响应，**MUST NOT** 以"这条路径结构化更省事"
为由长期留在 base64。写入方向仍保持结构化 + `{b64, len}` 载体，因为把一次 Web 包保存改成 raw
请求体会连带丢掉它的结构化参数与长度核对，而收益与成本不成比例——两条方向按各自的量级分别决定，
**MUST NOT** 把"是否切 raw"当成一次性全局决定。

### DESK-071b 导出的形状：内容寻址使一致性成为构造性质

Desktop 的 renderer **MUST NOT** 获得任意目标路径，也 **MUST NOT** 直接写文件。落地形态：

- **导出**：渲染层组装完整归档字节，经 Tauri raw IPC 交给 native；native **自行** 选择目标路径
  （`<data_root>/exports/`）并写盘，回显绝对路径。V1 因此**不引入**
  `tauri-plugin-dialog` 或 `tauri-plugin-fs`（`DESK-011`）。
  代价是用户需要自己找到文件；收益是零新增能力面。
- **导入**：渲染层经 `<input type="file">` 读入字节——WebView 标准能力，不需要任何权限——
  再调用既有的 `save_local_card` / `save_web_package` 逐条写入。**导入 MUST NOT** 新增 native
  command：解析 manifest 与判定冲突都是纯 TypeScript 语义（`ADR-desktop-tauri-v1` 第 7 条）。

Web 侧两条路径都零新增能力：导出走 `downloadBlob`，导入走 `<input type="file">`。

#### 导出 MUST NOT 持有维护窗口

导出**全程不取** `MaintenancePermit`。这条是本仓库里少见的"更弱的并发约束换来更可用"的选择，
理由必须写清，否则后人会把它当漏洞补回去：

1. **导出的产物自洽性由内容寻址保证，而不是由锁保证。** Web 包的 id 由 manifest 摘要派生；
   blob 按字节摘要存储且**只写不改**（`BlobStore::write` 摘要不符即拒）；`BlobStore::read` 在
   返回前**重算并校验摘要**（`blob.rs`）。因此渲染层读到的任何一块字节都已被验证为"就是清单
   即将声明的那个摘要"，清单与载荷**不可能**错配——这与并发无关。
2. **并发变更只会让导出失败，不会让它产出错误结果。** 可能的失败有三种，且都是显式错误：
   列举之后该包被 purge（行查找失败，`blob-not-found`）；行查找与文件读之间字节被 GC 删掉
   （同样 `blob-not-found`）；一条已被第一页读到的记录随后被更新、其 `updatedAt` 落到当前游标
   **之后**，于是再次出现在后续页——清单的路径唯一性检查把这条变成显式失败。keyset 分页按
   `(updated_at_sort, id)` 排序，而 `nextLocalTimestamp` 保证时间戳单调，因此**新**行只会被排到
   游标之后（只漏不重）。清单的唯一性检查因此不会被破坏。
3. **持窗口并不能让"取消"变得可用。** `zipSync` 在 renderer 主线程**同步**执行，那段时间
   event loop 被占满，用户**根本点不到**取消按钮。此处曾以"为了让取消可用所以不能持窗口"作为
   理由，那条论证不成立，已删除。结论仍然是不持窗口，但真正的理由是上面第 1、2 条：窗口在这里
   没有要解决的问题。

因此"导出期间库被冻结"这条**MUST NOT** 出现。它与 `DESK-058`（备份 MUST 持窗口）并不矛盾：
备份的产物要在**之后**被用来整体替换当前库，它必须是单一时刻的精确快照；导出是给人搬去另一台
设备的人工产物，"自洽列举，失败就重试"完全够用。D2.4 的 native 备份 **MUST** 持窗口，
理由是上一句。两者 **MUST NOT** 互相引用为前提。

#### 一致性边界的表述

导出的一致性 **MUST** 陈述为"**成功导出 = 自洽列举**"：一次成功产出的归档，其内部的记录、digest
与 blob **必然自洽**。并发修改**可能**被纳入、**可能**被遗漏、**也可能**让本次导出显式失败；
但它 **MUST NOT** 产出一个 record / blob 错配的归档。

导出 **MUST NOT** 被描述成"点击那一刻的库"或"列举时刻的快照"。当前算法做不到：它先分页列举，
再逐个读取 Web 包 ZIP，中间任何一次并发写入都可能改变结果范围。UI **MUST NOT** 承诺一个算法
不提供的性质。

#### 命令形状

导出 **MUST** 由两条命令构成，**MUST NOT** 是 `begin` / `append` / `finish` 三段状态机：

```text
begin_local_archive_export(declaredTotalByteLength)          → { exportId, absolutePath }
append_local_archive_export_chunk(raw bytes, x-export-id)     → { writtenByteLength, complete }
```

- **没有独立的 `finish`**：native 在累计字节等于 `declaredTotalByteLength` 时**自行**核对落盘
  长度、`fsync`、原子 rename 并清空会话。三段状态机里最容易泄漏的就是"begin 之后 renderer 崩溃，
  永远没人 finish"——去掉 `finish` 让"完成"成为字节计数的一个函数，而不是一个需要别人来调的动作。
- **exportId MUST 由 native 分配**（单调计数器）。它不是鉴权，而是 epoch guard：renderer 刷新后
  重新 `begin` 会拿到新 id 并让 native 回收旧会话，而旧会话的迟到 append 带着旧 id 因此被拒。
  若让 renderer 自己生成 id，native 无法区分"新的导出"与"迟到的旧块"——后者会写进新会话的文件。
- **`begin` MUST 回收任何已存在的会话**。这让"renderer 刷新导致会话泄漏"自愈：下一次导出总是从
  一个干净的 temp 开始。
- 累计字节 **MUST** 超过 `declaredTotalByteLength` 即失败**并删除 temp**——溢出是终态失败，
  留着会话与 temp 只会让一个已失败的导出继续占着磁盘。声明长度与实际落盘长度
  不一致 **MUST** 失败——一次静默截断会产出一个"能打开但少东西"的归档，而它比一次显式失败
  危险得多：用户会以为迁移完成了。

#### 落盘与崩溃

- temp 文件与最终导出 **MUST** 位于同一文件系统，否则原子 rename 不可用；
- 未完成的 temp **MUST NOT** 被当作有效导出；应用启动时 **MUST** 清理它们。

#### raw IPC 的静默回退

Tauri 的 raw IPC 走自定义协议；失败时它会**静默回退**到 `postMessage`（tauri 2.12
`ipc-protocol.js` 的 `customProtocolIpcFailed`）。那条路径会把 payload 序列化成字符串，对
数百 MiB 的归档是灾难性的，且不产生任何错误。

因此 D2.3b2 的退出门禁 **MUST** 包含"未发生回退"的断言，且块大小 **MUST** 由实测确定而非拍脑袋。
CSP 需允许 `ipc:`（当前 `tauri.conf.json` 已含 `connect-src 'self' ipc: http://ipc.localhost`）。

#### 导出目标路径的命名与保留

- 目录 `<data_root>/exports/`。D2.4 的 native 备份 **MUST** 落在 `<data_root>/backups/`，
  **MUST NOT** 与导出混在同一目录——两种语义不同的产物混在一处时，用户与排障都无从下手。
- 文件名 `local-library-<YYYYMMDDTHHMMSSZ>.zip`，时间取 UTC。
- 撞名时 **MUST** 追加 `-2`、`-3`…… 直到不撞为止。
- **MUST NOT** 覆盖既有文件。覆盖会毁掉用户唯一一份备份，而症状是"导出成功"。
- 发布步骤 **MUST** 使用**目标已存在即失败**的 no-clobber 原语，**MUST NOT** 用
  `exists()` 预检查再 `rename()`。两者之间存在窗口：目标在预检查之后、发布之前被别的进程或用户
  创建，随后一次普通 `rename` 就会**覆盖**它——而 Rust 的 `fs::rename` 文档明写"目标存在时替换
  目标"。这条窗口因此不是理论问题，`MUST NOT` 靠第二次预检查来消除。
- `begin` 回显的 `absolutePath` **MUST** 是真正的最终路径。若发布时极罕见地发现它已被占用，
  **MUST** 整体失败并让用户重试，**MUST NOT** 在最后悄悄换一个 `-2`——那会让 `begin` 回显的
  路径变成"仅供参考"，契约复杂度随之上升。
- V1 **MUST NOT** 自动清理。自动淘汰是未经请求的数据删除，其失败模式（删掉用户唯一一份备份）
  比代价（用户自己清目录）严重得多。UI **MUST** 回显绝对路径**与所在目录**，让用户能自己清理。
  若将来实测到磁盘压力成为真问题，再以独立阶段引入；那条规则 **MUST** 先规定"哪些文件可删"
  （只删 native 自己按上述规则命名、且超过 N 天的），**MUST NOT** 按"最旧"一刀切。
- 文件名 **MUST NOT** 包含任何用户数据或记录标题。

### DESK-074 归档输入的安全模型

导入面对的是**不可信字节**。V1 不把归档任意释放到文件系统（因此典型的 ZIP Slip 风险不成立），
但 zip bomb、巨量条目、重复路径与声明长度造假**依然存在**。

依据 OWASP ASVS 5.0 V5.2.3（L2/L3 必需）：压缩文件 **MUST** 在解压**前**检查最大未压缩尺寸与
最大文件数。按"先 `unzipSync` 全量解压、再校验 manifest"的形态实现**恰好违反**这条。

#### manifest 优先是格式属性，不是优化

V2 的归档布局 **MUST** 规定 `manifest.json` 是第一个 entry，读取器 **MUST** 在一个独立的、
远小于归档总预算的 manifest 上限内先读它。这不只是"读起来方便"：只有先拿到清单，才能在解压
其余条目**之前**算出期望路径集、条目数与声明总字节，从而在任何分配发生前拒绝超限输入。

manifest 缺失、不是第一个 entry、或超过 manifest 上限 **MUST** 整体拒绝该归档。

#### 逐条解压的判定

清单通过后，每个 entry **MUST** 依次满足：

```text
路径在 allowlist 内（cards/、web-packages/、archives/ 三个命名空间）
路径在整个归档内唯一（跨命名空间的重复路径同样拒绝）
实际解压长度 == 清单声明长度
实际字节的摘要 == 清单声明的摘要
累计实际输出字节 <= 归档总预算
任一条不满足即整体失败，且 MUST 在第一次 mutation 之前
```

累计字节 **MUST** 按**实际输出**计数，**MUST NOT** 采信中央目录里的 `originalSize`——那是
攻击者可控的声明值。fflate 的流式 `Unzip` 只在中央目录提供该值时给出它，因此它只能是优化的
提前退出条件，不能是判定依据。

#### 冲突策略

V1 **MUST** 收敛为 **existing wins / skip + report**：本地已存在的记录一律保留，跳过并在报告里
逐条列出。

**MUST NOT** 做"时间新的赢"。理由不是跨设备时钟不可靠（那是次要的），而是本地库已经用
`nextLocalTimestamp` 让时间戳单调、tombstone 与 non-monotonic timestamp 不变量让"强行恢复旧状态"
需要额外定义。在一个已有六个审计桶的模型里引入第七种时间语义，代价远大于收益。

**MUST NOT** 做 force overwrite。当前 store 的 tombstone 语义下"覆盖"意味着什么（复活？
保留 tombstone？）没有唯一定义，而猜错的后果是静默丢失用户刚刚做的删除。

preflight **MUST** 在第一次 mutation 之前全部完成。apply **MUST** 按确定顺序逐项执行，**MUST**
返回精确的 succeeded / skipped / failed 摘要。整体回滚 **MUST NOT** 作为要求——为此引入一个跨
SQLite 与 blob 文件系统的全局事务会破坏 `ADR-desktop-tauri-v1` 第 7 条的职责分层。

#### 零网络

导入全程 **MUST** 零网络请求。这条 **MUST** 由可执行断言证明（导入路径上任何 `fetch` / `XHR`
抛错），**MUST NOT** 只靠代码审查声称（`DESK-052`）。

### DESK-073 恢复采用重启时交换

从 native backup 恢复 **MUST** 采用"写 restore intent → 退出 → 下次启动时交换"，**MUST NOT**
在运行中热替换。Tauri `manage()` 持有的 owned connection 无法在运行中换掉；热替换还会引入渲染层
陈旧记录与在途 AI owner 的额外状态机，V1 没有收益。

**重启本身不提供原子性。** 当前一代本地库至少由 `library.sqlite` 与 `blobs/` 两个文件系统资源
组成，单次 rename 无法同时替换两者；若在两次移动之间崩溃，未经协议的实现会得到"新 DB + 旧 blobs"
或反向的混合代际状态。因此 D2.4b **MUST** 使用可幂等重放的 restore intent / journal，而不是把
"下次启动时交换"等同于"失败即天然回滚"。

#### 恢复准备与代际边界

- 当前进程在写 restore intent 前 **MUST** 完整验证所选 backup，并先成功完成一次 D2.4a
  pre-restore backup；任一步失败都 **MUST NOT** 安排恢复。
- intent **MUST** 只引用 native 分配并能重新验证的 `backupId` / `restoreId`，**MUST NOT** 接受
  renderer 提供的任意文件系统路径。marker 写入 **MUST** 采用 temp + flush/sync + 同卷 no-clobber/
  rename 的耐崩溃形态。
- 下次启动 **MUST** 先取得 `InstanceGuard`，再处理 restore intent，且整个恢复解析与交换
  **MUST** 发生在打开 `library.sqlite`、执行 migration 或注册 `LocalLibrary` managed state **之前**。
- 新一代内容 **MUST** 先完整 staging 到同一数据卷并按 backup manifest 重新验证；未验证完成的 staging
  **MUST NOT** 占用正式路径。
- SQLite 主库与同 basename 的既有 `-wal` / `-shm` **MUST** 被视为一个旧代际单元：安装新主库前，
  旧 sidecar 必须一并隔离，**MUST NOT** 让新 `library.sqlite` 与旧 WAL/SHM 同时出现在正式路径。
  `library.lock`、`exports/` 与 `backups/` 不属于被恢复的数据代际，**MUST NOT** 随库交换。
- 旧 `library.sqlite` 代际与旧 `blobs/` **MUST** 保留到新一代完成最终验证和 commit marker；
  在 commit 之前 **MUST NOT** 删除用户原有数据。

#### journal 的幂等收敛

实现可以选择具体 phase 名称，但至少要表达"staged / old quarantined / new installed / verified /
committed"这些事实。phase marker **MUST NOT** 被当作唯一事实来源：进程可能在文件系统动作成功后、
marker 更新前崩溃，因此每次启动都 **MUST** 结合 marker、正式路径、staging 与旧代际的实际存在状态
重新判定下一步；重复执行同一步 **MUST** 安全。

存在未完成 intent 时，应用 **MUST NOT** 打开本地库给产品 UI 使用。恢复器必须收敛到以下两种结果之一：

1. 新 DB + 新 blobs 均验证通过，写 committed，再允许正常启动；
2. 明确回滚到完整旧代际，并清除/标记该次 intent 失败。

若 I/O 或权限错误使两者都无法安全完成，应用 **MUST** fail closed，保留 staging 与旧代际并给出可诊断
错误；**MUST NOT** 为了"至少能启动"而打开混合代际、空库或临时内存库。

D2.4b 的自动化门禁 **MUST** 对至少以下断点做故障注入并重新启动恢复：staging 完成后、隔离旧 DB 后、
隔离旧 blobs 后、安装新 DB 后、安装新 blobs 后、最终 verify/commit 前后。每个断点最终都必须得到
完整旧代际或完整新代际，**MUST NOT** 出现可打开的混合状态。旧代际的物理清理属于 committed 后的
可重试 housekeeping；清理失败可报警并下次重试，但不得把已经验证的新库重新判失败。

### DESK-058 备份一致性

SQLite 快照与 blob 文件系统 **MUST NOT** 被当作一个原子事务处理。备份 **MUST** 在一个受控窗口内
禁止 delete、purge 与 GC，再依次完成快照、blob 复制、逐个 digest 校验、最后写入备份 manifest。

manifest 的存在只是完成标记，**MUST NOT** 被当作完整性证明；完整性 **MUST** 由 manifest 中的
digest 与长度校验判定。备份 **MUST NOT** 只靠标记文件判断可用。

### D2.4 native backup 落盘与 IPC 补充（2026-10-03）

native backup 是 `backups/local-library-<UTC YYYYMMDDTHHMMSSZ>[-N]/` 下的目录；撞名从 `-2`
递增。创建目录采用排他创建，只有最后以 temp + sync + no-clobber 发布 `manifest.json` 后才算完成。
目录内仅有 `library.sqlite`、内容寻址 `blobs/` 与 manifest；未完成目录不自动删除，也不能作为恢复源。

SQLite 的一致快照与中断损坏边界见 [VACUUM INTO 官方说明](https://sqlite.org/lang_vacuum.html#vacuum_with_an_into_clause)
（2026-10-03 核验）；manifest 发布前仍显式同步数据库与复制文件。

新写入的 manifest V2 包含 `formatVersion: 2`、`schemaVersion`、`backupId`、`createdAt`、数据库的固定 `path` / `digest` /
`byteLength` 和 blob 的 `digest` / `byteLength` 清单。读取端只从合法 ID 与摘要派生路径，并重新验证
SQLite 完整性、schema 版本、引用关系、清单与 metadata 的一致性，以及每个文件的摘要与长度；
未知版本与损坏内容拒绝恢复。备份包含数据库管理的全部 blob（含软删记录及尚未 GC 的 metadata），
不包含无 metadata 的孤儿文件、OS 凭据、导出目录及尚未迁入本地库的其他业务存档。

备份格式版本与 SQLite schema 版本 **MUST** 独立版本化。V2 备份 **MUST** 写入 `schemaVersion`，
且与快照的 `PRAGMA user_version` 一致。当前 migration 链明确支持的旧 schema 备份 **MUST** 可以恢复：
先按对应版本验证结构、完整性与引用关系，完成代际交换后再由正常启动的 migration 升级；
**MUST NOT** 为验证备份而修改源快照。高于当前版本、无支持迁移路径或声明与实库不符时 **MUST** 拒绝恢复。
读取端保留早期没有 `schemaVersion` 的 V1 manifest 兼容，只能从已校验快照读取版本，不能默认成当前版本。
旧客户端会拒绝未知的 V2 格式；该前向拒绝不影响新客户端读取已有 V1 备份。

`blobs/` 的实际文件集合 **MUST** 与 manifest 及数据库管理的 blob 集合完全相等；枚举 **MUST** 有条目上限，
额外文件、子目录、链接、非法名称或摘要/长度不符均拒绝。恢复复制 **MUST** 由已验证清单驱动，
不能把目录内未声明的文件带入 live store。旧 schema 的真实结构与恢复后 migration、未来版本拒绝、
缺省版本兼容和额外 blob 拒绝均属于 D2.4 / D5.2 回归门禁。

renderer 仅能创建、列举与按 `backupId` 选择本机备份，不能指定文件路径。响应回显 native 产生的路径
与所在目录用于人工管理；无自动淘汰策略。该契约为新增能力，不改变 portable archive 的格式或导入语义。

恢复请求 `prepare_local_restore({ request: { backupId } })` 只接收合法本机 ID。响应的 `restoreId` 与
`preRestoreBackupId` 由 native 分配；准备成功后 native 持有维护许可直到退出，renderer 刷新不能释放它。
`exit_after_local_restore` 只在 native 已持有待恢复许可时退出，不提供通用重启/执行/路径能力。

V1 journal 使用固定 `restore.intent` 和 `restoreId` 对应的 `.restore-staging/`、`.restore-old/`、
`.restore-journal/`。逐项隔离记录后写 `old-quarantined`，再安装新库；以 staging/正式路径实际状态与
摘要共同判定 rename 成功但 marker 未写的情况。committed 后不再次应用旧快照，避免覆盖之后的新写入。
旧代际与诊断目录保留供人工处理；无自动淘汰。现阶段选择安全向前重放，无法完成时 fail closed，
不进行自动回滚或空库降级。自动测试证明进程中断后的重放，不宣称已验证实机断电持久性。

### DESK-052 导入导出


导入导出 **MUST** 是业务级 IPC。导入 **MUST** 先展示摘要、版本、条目数与冲突策略。
导出包 **MUST NOT** 包含 API Key、secret header、会话、设备密钥或服务器凭据。导入
**MUST NOT** 自动创建 Provider 或发起网络请求。

`archive.test.ts` 的"无 Provider 秘密字段"断言对 V2 同样成立，且其成立方式 **MUST** 保持为
manifest schema 的 `.strict()`——未知字段即解析失败，而不是靠导出时过滤。

导入 **MUST** 全程零网络请求。这条 **MUST** 由可执行断言证明（导入路径上任何 fetch/XHR 都
抛错），**MUST NOT** 只靠代码审查声称。

不可信归档的解压边界、预算维度与冲突策略见 `DESK-074`。

### DESK-059b portable archive manifest 的 Web 包条目

V2 的 Web 包条目 **MUST** 是独立 schema，**MUST NOT** 复用 V1 的 asset 条目。

V1 的 asset 条目有两条 `superRefine`：`checksum === contentDigest`，且 path 必须由
`contentDigest` 推导。这两条对 Web 包**全部不成立**（`DESK-063`：manifest 摘要 ≠ ZIP 字节摘要）。
复用会让每一条真实 Web 包都被自己的 `superRefine` 拒绝，而症状表现为"所有包都导入失败"。

因此 Web 包条目 **MUST** 显式分开命名的摘要字段（与卡片条目不同，Web 包条目有**三个**摘要）：

- `contentDigest`：manifest 摘要，构成领域身份，等于记录的 `contentDigest`；
- `archiveDigest`：ZIP 字节的摘要，充当存储地址与完整性校验（`archivePath` **MUST** 由它推导）；
- `checksum`：`path` 处那条 JSON 记录自身的字节摘要。

`contentDigest` 与 `archiveDigest` 两者 **MUST NOT** 被要求相等，也 **MUST NOT** 被断言不等——前者
会破坏整个身份模型，后者会把一个合法的巧合变成拒绝理由（`DESK-063`）。`checksum` 与前两者是
三个独立概念，**MUST NOT** 被合并成一个泛化的 `digest`。

`archivePath` **MUST** 由 `archiveDigest` 推导，且其构造函数 **MUST NOT** 接受 stem 作为参数。
这条让"路径指向的字节"无法与"清单声称的摘要"脱节；只接受 digest 的签名让"用 stem 命名归档
字节"在类型上不可表达。

### DESK-059c portable archive 的容器与布局

`formatVersion` **MUST** 从 `2` 起步，**MUST NOT** 从 `1` 递增。V1 只有 schema 与它自己的测试，
**零 producer、零 consumer**，野外不存在任何 V1 归档；让第一个真实格式占用 `1` 会使将来的读取器
以为自己需要处理一个它从未见过的历史版本。保留 V1 reader 亦无收益：为一个永远没人产出的格式
维护代码是负债，而 [Desktop Tauri V1 运行时与本地安全边界决策](../decisions/2026-09-30_160000_DesktopTauriV1运行时与本地安全边界决策.md)
第 8 条约束的是摘要算法下沉，不是这个。

V1 的 `assets` 命名空间 **MUST NOT** 保留。它设想卡片内嵌图片，而 `DESK-054` 已确认当前四种
数据卡 schema 均无图片字段（唯一的图片字段 `questionnaire.logoUrl` 是远程 URL 字符串）。为不存在的
消费者保留命名空间，会让后来者以为它有人在用。

归档内布局 **MUST** 为：

```text
manifest.json                     清单
cards/<stem>.json                 一条 LocalCardRecordV1 的序列化
web-packages/<stem>.json          一条 LocalWebPackageRecordV1 的序列化
archives/<64 位小写 hex>.zip      Web 包的原始 ZIP 字节
```

卡片 schema 版本与 Web 包 schema 版本 **MUST** 分开记录，**MUST NOT** 合成一个数字。两者独立
演进，合成后在其中一方升级时会让读取器无法知道自己能读懂哪一种。

路径唯一性 **MUST** 覆盖**整个归档**而非各命名空间内部：卡片 `cards/a.json` 与包
`web-packages/a.json` 的 stem 相同是允许的，但两个包写同一个 `archivePath` **MUST** 失败——解包
时后者会静默覆盖前者。

归档内记录路径 **MUST** 是小写安全 stem（`[a-z0-9][a-z0-9._-]{0,127}`），**MUST NOT** 以 `.` 结尾，
且 **MUST NOT** 命中 Windows 保留设备名（`con` / `prn` / `aux` / `nul` / `com1`–`com9` /
`lpt1`–`lpt9`，含其后接 `.` 的形式）。归档可能被解到 Windows 上：这些名字在 Windows 上指向意料
之外的位置或根本无法创建，而症状会表现为"用户刚导出的归档打不开"。

stem 派生 **MUST** 与路径 schema 共用同一张保留名表，且**必须**产出 schema 本身接受的路径。
修法 **MUST** 是**前缀**而非后缀：保留名判据是 `^con(?:\.|$)`，只看开头，`con.txt` 追加 `-` 仍是
设备名。派生规则 **MUST** 保持确定性（同一 id 恒得同一 stem），**MUST NOT** 追加哈希或计数器——
那会让路径随库增长而变化，而稳定性是"同一份库在固定 `exportedAt` 下两次导出产出相同归档"的前提。
撞名 **MUST** 由清单的唯一性检查兜住，导出侧据此换名。

归档内记录的解析 **MUST** 是"严格 UTF-8 解码 → JSON 解析 → 记录 schema 校验"三步，**MUST NOT**
使用 `TextDecoder` 的替换模式或跳过 JSON 解析。替换模式会用 U+FFFD 静默替换非法序列，于是**通过
校验的记录与用户导出的字节不再对应**，而 `checksum` 的全部价值就在这个对应关系上。

解析失败与校验失败 **MUST** 表现为同一类错误（同为 `ZodError`）。调用方逐条 try、失败记进报告，
但任何单独捕获 `ZodError` 做分类统计的代码都依赖这一点；`SyntaxError` 会让那类代码漏掉一半输入。

解析函数 **MUST NOT** 返回"原文 + 校验结果"两份东西，**MUST** 只返回校验后的记录副本。

摘要校验 **MUST NOT** 放在契约层。契约层是同步的、在 Node 与浏览器测试中被覆盖，而摘要计算是
异步的 `crypto.subtle`。导入侧 **MUST** 在拿到字节后**先**校验摘要再做别的任何事。

### DESK-059 Portable archive 与 native backup 的分工

两者 **MUST** 作为不同能力实现，**MUST NOT** 互相替代：

| 能力 | 跨 Web/Desktop | 目标 |
| --- | --- | --- |
| Portable export / import | 是 | 数据迁移、跨浏览器、Web 与 Desktop 之间搬运本地库 |
| Full backup / restore | 契约共享、实现各自 | 灾难恢复、完整设备状态 |

portable archive 的 manifest 契约 **MUST** 由 `@mahoshojo/local-library` 单点持有，Web 的 IndexedDB
adapter 与 Desktop 的 SQLite/blob adapter **MUST** 都能产出与消费它。native backup **MUST** 使用各自
运行时的存储原生手段，**MUST NOT** 要求另一运行时能够读取。

portable archive **MUST NOT** 需要服务器参与。Web 侧承载它的页面 **MUST** 是设备级页面而非账号级
页面：本地库不要求登录，把它挂在个人页会让产品语义变成"本地数据属于账号"。

### DESK-053 导入导出的 IPC 形态

IPC **MUST** 接受字节流或由 Rust 打开的受控句柄，**MUST NOT** 接受 renderer 提供的任意目标路径。

跨 IPC 传递二进制 **SHOULD** 走 Tauri 2 的原生 raw IPC（前端 `invoke(cmd, Uint8Array)`，native 侧
读 `InvokeBody::Raw`；回程用 `tauri::ipc::Response`），以避免 JSON 序列化开销。D2 **MUST NOT** 为此
引入自定义协议；大规模流式或随机访问的资产传输延后到 D3/D4 再评估。

## 5b. 项目服务云通路（D5.0c）

以下条款在 `DESK-ONLINE-005` / `DESK-ONLINE-012` / `DESK-ONLINE-013` 的框架内收窄
Desktop 访问项目自有服务的全部信任面。未列出的在线能力（云卡库、消息、上传等）不在本
节范围，仍受 `DESK-PROD-*` 阶段门禁约束。

### DESK-090 项目服务通路的唯一性

- Desktop 访问项目自有服务的**唯一**通路是 native 侧受控项目边界（既有 `cloud` 与
  `DESK-095` 的独立 Arena transport）：固定 origin、显式
  路由/操作白名单、由 Rust 构造请求。
- renderer **MUST NOT** 获得指向项目服务的通用 fetch/XHR/WebSocket/EventSource 能力，
  也不得通过 IPC 参数注入任意 URL、路径或请求头。
- Direct AI transport 对项目域名的拒绝（`DESK-031`）维持不变；项目服务地址 **MUST NOT**
  经由 Provider Profile 的 `baseUrl`/endpoint 字段走私进入 Direct 通路。
- `open` crate（系统浏览器唤起）是 V1 唯一新增的外部进程能力；它只能由 native 侧以
  受控参数调用，renderer **MUST NOT** 传入任意 URL。

### DESK-091 原生授权协议 `desktop-auth-v1`

- 登录 **MUST** 走系统浏览器 + RFC 8252 loopback 回跳 + PKCE S256 + state 的窄协议；
  **MUST NOT** 在 Tauri WebView 内加载远端登录/授权页。
- grant **MUST** 一次性、短时效（≤120s）、原子消费；服务端 **MUST** 只通过
  Better Auth 官方 API（`internalAdapter` + `setSessionCookie`）建立会话，**MUST NOT**
  直写 session 表或自行构造会话 cookie。
- `code` / `code_verifier` / 会话 cookie **MUST NOT** 出现在 renderer 可观测的
  IPC 返回值、日志、诊断包中；服务端 DB 只存 `sha256(code)` 派生键。
- 回跳地址 **MUST** 严格匹配 loopback IP literal（`127.0.0.1` / `[::1]`）+ 固定
  `/callback` 路径；`localhost` 主机名、自定义 scheme、非 loopback 地址一律拒绝。
- `state` 不匹配、超时、重复消费、verifier 不匹配 **MUST** 立即失败并可诊断；
  listener 在一次回跳或流程结束后 **MUST** 关闭。

### DESK-092 账号凭据命名空间

- 账号会话凭据 **MUST** 存放于操作系统凭据存储的独立命名空间
  （`account-session:*`），与 AI Provider secret（`provider-key:*`）完全隔离；
  同一 keyring service 下两类引用 **MUST NOT** 互相解析。
- 账号凭据适用 `DESK-041` 同款收敛：renderer **MUST NOT** 获得读取凭据明文的 IPC。
- 账号凭据 **MUST NOT** 写入 SQLite、本地库、导出包、日志、崩溃报告、Room 快照，
  也不得作为 Direct AI 的 Provider 凭据复用。
- 注销 **MUST** 本地幂等：本地凭据删除不依赖服务端响应成败；`unreachable` 状态
  **MUST NOT** 触发本地凭据删除。

### DESK-093 云请求边界

- 项目请求 **MUST** 满足：固定 origin、HTTPS（loopback 开发源除外）、不跟随
  重定向；普通账号通路只注入账号会话 cookie，Arena 的有限身份/创建凭据例外只按
  `DESK-095`。开发构建 **MAY** 在编译期经
  `MAHOSHOJO_CLOUD_ORIGIN` 覆盖 origin（仅 loopback HTTP 或 HTTPS 联调地址，
  构建时固化）；release 构建 **MUST** 恒用生产 origin，运行时环境变量
  **MUST NOT** 生效。
- 非生成类操作（状态查询、注销、探测等）的请求体/查询 **MUST NOT** 携带
  AI Provider Key 或任何 Provider 凭据字段。
- hosted 生成的凭据注入 **MUST** 只发生在 native 侧：renderer **MUST NOT**
  传明文 key、自选 `secretRef` 字符串、endpoint/请求头，或在业务 body 中预置
  `customProvider`；native 对携带这些字段的请求一律 fail-closed，不依赖
  renderer 侧 schema 已校验。
- 服务器 BYOK 需要 native 持有、native 校验的 Provider 绑定（如
  `profileId → {serverProviderId, serverModelId, apiKeyRef}`）作为前提；在该
  绑定落地前，hosted 生成 **MUST** 只开放系统默认通道，renderer **MUST NOT**
  通过 `providerId`/`modelId`/`secretRef` 三元组自选服务端凭据。绑定落地后
  renderer 也只能选择绑定标识（`profileId`/`bindingId`），不得任意组合凭据
  字段。
- **修订（2026-10-09，D5.1-AIP-r1）**：系统默认通道自身 **MAY** 携带受检
  非秘密偏好 `systemConfig`——`providerId` 固定 `'system'`、`modelId` 限
  共享系统目录、`generationOverrides` 限既有覆盖参数语义；native 将其注入
  为服务器 `customProvider:{providerId:'system',...}`，对未知字段与凭据类
  字段（apiKey/secretRef/endpoint/header 等）仍 fail-closed。这是「使用
  系统默认配置」通道与 Web 同语义的模型/参数选择，不构成上款所禁止的
  服务端凭据自选；Desktop Server BYOK 继续 deferred。

### DESK-094 版本与探测边界

- `desktop-auth-v1` 协议版本 **MUST** 严格匹配；hosted 侧契约版本沿用

首版仅支持 Windows x64，通过设置页手动检查，不要求启动自动检查或静默安装。
更新来源由 Native 固定为项目 HTTPS stable 清单，公钥随应用打包；官方 updater 负责下载验签及 NSIS 安装。
客户端 **MUST** 验证签名绑定的版本并拒绝降级，不允许 renderer 覆盖更新 URL、公钥、路径或比较器。

只新增三个主 UI 自有 command：

| command | 输入 | 返回 / 语义 |
| --- | --- | --- |
| `check_desktop_update` | 无 | `{currentVersion, available: null 或 {version, notes}}`，Native 缓存候选 |
| `install_desktop_update` | 检查所得 `version`、进度 Channel | 只消费匹配的 Native 候选；用户确认后下载、验签、安装 |
| `cancel_desktop_update` | 无 | 是否请求取消当前下载；安装开始后不可取消 |

Channel 事件为 `{phase: downloading 或 installing, downloadedBytes, totalBytes: number 或 null}`。
可诊断失败采用 `{code,message}`，区分 busy、cancelled、not-checked、check-failed、download-failed、install-failed、unsupported。
这是新增的本机契约，不改变服务器 API 或本地持久化格式，不新增共享平台抽象。

UI 在安装前提示保存作品，复用既有离开守卫的在途状态，下载期间阻止离页或关闭。
Native 安装前检查生成任务并取得本地库维护许可；有在途写入、备份或恢复时返回 busy，不强行结束。
更新网络失败或取消保留现有安装与本地数据，提供重试；没有更新清单或 GitHub 不可达不能阻止本地功能。

2026-10-27 官网 stable 清单入口的失败诊断为向后兼容的可选 HTTP header：既有 307 / 204 / 503 状态与空失败响应体保持不变。
503 可附带 `X-Desktop-Release-Failure`，值仅允许 `network`、`timeout`、`upstream-http-error`、`rate-limited`、`invalid-json`、`invalid-cache`；
`X-Desktop-Release-Upstream-Status` 仅允许 100–599 的整数，`Retry-After`（如有）仅允许 1–3600 秒的整数。
这些字段仅用于排障，不携带上游 body、错误 message、凭据、任意 URL 或授权结论；旧 Native 客户端忽略额外 header，仍按原状态拒绝安装并提示重试。
官网页面只消费 published/preparing/unavailable 状态，不展示内部诊断。失败结果不得进入正式发布状态缓存；缓存写入失败不改变已验证结果或放宽资产校验。

2026-10-27 生产排障确认部分 Cloudflare 出口的 GitHub 匿名 API 配额耗尽。公开发行元数据查询集中到既有 Hono Node 服务的固定 `GET|HEAD /api/desktop/releases/stable`：
该基础设施只读端点不属于生成类 shared route registry，沿用 `/api/*` 的既有限流，不接受用户指定 repository、tag、版本或代理 URL，不读取/转发用户 cookies、Authorization 或发布凭据。
上游仍为固定仓库、固定目标版本的公开 GitHub Release；仅精确 tag、非 draft、非 prerelease 且四项必需资产均已上传、大小有效、下载 URL 精确匹配时返回 200 与最小 published JSON 投影。
未发布或资产未齐返回 204 空体；网络、限流和解析失败返回 503 空体及上列受限诊断 header，均 `no-store`。Node 仅将验证后的 published 投影在单进程内缓存 300 秒，并合并并发查询。
失败及 preparing 不进入成功缓存；为避免串行请求耗尽固定出口的匿名配额，单进程另设 120 秒的上游查询冷却，限流提供更长合法 `Retry-After` 时可延长至最多 3600 秒。冷却期间仅返回上次的 preparing/受限 unavailable，仍为 `no-store`；到期重新查询，不延长过期 published，也不把失败转成授权下载。
Web 只向固定 Hono HTTPS 地址查询，不向其发送用户凭据，仍重验固定版本和下载 URL 后才决定下载及更新响应；Web 成功缓存同为最多 300 秒，两层缓存累计陈旧窗口最多约 600 秒，过期后重新验证，不以失败延长旧条目。
此调整不新增生产数据库写入、运行时 GitHub token、Native 网络权限或安装授权；Hono 不可达时沿用可重试 unavailable，不能降级到未验证资产。

安装包构建 **MUST** 仅由维护者手动触发，不能因每次 push 自动打包；GitHub Release 手动发布已验收的同一份文件。
不要求额外 enable 开关或多层审批链。发布私钥与普通 CI 隔离，官方更新签名及不覆盖旧资产的要求仍有效。

## 魔法茶会预设与会话组织（T-TEA-1）

### 预设与显式会话组织

- 双端 MUST 消费共源受控预设选择器和纯投影，提供普通及三预设新建。已有会话 MUST 先展示风格、世界书、选项、主情景替换和清空辅助情景，再明确确认；重复选中已有预设为取消。保留原始未涉及设置、角色、消息、摘要与输入，不把 Desktop 请求安全投影写回原件。启用预设同步选项输出计划，关闭状态转必要时输出，已有每轮输出保持。
- Desktop MUST 使用现有两条 Tea IPC/owner/CAS 与 receipt，新增窄 set-pin 和 delete-selected，不开放通用 patch/批量任意动作。置顶传 desired boolean、目标 id/instance/revision 与 operationId；Native 生成时间，新 order 大于全库有效 order；取消移除两个 pin 字段，updatedAt 不变。
- 任意已列出行均可置顶，不切换当前会话、不隐式保存当前草稿。当前行要求加载正文身份/修订与目录一致；成功只确认新 revision/pin。失败/取消组织操作 MUST 保留当前正文、消息与全部草稿；未知提交只查询原 receipt，未确认前不重发。
- 仅正 safe integer pin/order 参与目录组织，非法旧扩展按未置顶/零 order 读但保留归档 JSON。全库排序为 pinned-first、order DESC、pin timestamp DESC、updatedAt DESC、id DESC，游标含全排序键和 catalogRevision。持久 preview 和 SQLite DDL 不变；只返回小投影。每页最多 50 及响应预算不是查询总成本上限，SQLite 仍扫描/解析文档并排序；合成生产查询计划与时延单列，不承诺任意库规模常量时间。
- 清理只针对当前已加载最多 50 行的明确勾选；置顶和当前会话保护。翻页/刷新/搜索范围变化清除选择与确认，确认列出实际标题/ID/数量及永久删除影响。冻结 targets 后，在同事务先检查全部 CAS/Busy/保护条件，再执行删除；任一失败全批不写。复用 receipt 防未知提交/ABA重删。取消确认零写，不增加自动 retention、全库年龄清理或后台删除。
- 本片不开放置顶拖拽重排、媒体、分支合并或输出更新草案。

### 无 DDL 不等于可降级

保持生产 schema 12、既有 migration journal/DDL/preview，不抢占仅测试 history 候选号。新版本可读旧库与旧备份；新组织动作首次提交后会持久保存新 receipt discriminant。旧 reader 的封闭校验不识别它，因此不支持原地降级：正式启动在迁移/回收前 fail closed，旧版本通常报 UpgradeBackup(Corrupt)/upgrade-backup-failed，旧备份验证报 backup-corrupt，而不是明确 unsupported；这不表示新版本判定库已损坏。回退使用组织前备份或先由新版本导出。不能删 receipt 绕开该边界。

正式安全依赖同 data_root InstanceGuard 排他持有至退出；不能声称已打开、绕锁的旧连接每写必检新语义。旧备份创建可能留下失败暂存目录/快照，不宣称零文件写；原 live 数据和源备份保留。使用新/旧源码 binary 的合成库重开/恢复对照和既有锁测试核实，实际未运行项须单列。若后续需要统一 future-version 墙，再实施受控版本step与升级前备份，不借此偷建索引或扩表。

## 魔法茶会编辑消息分支（T-TEA-2a）

本片只实现编辑已有 user 消息后建立独立会话、手动继续剧情、重开及文本归档；不实现合并。

- 使用现有 Tea write 的窄 `fork`：operationId、源 sessionId/instance/expectedRevision、anchorMessageId、editedContent、targetSessionId。Native 在单事务内检查源 CAS、无活动生成及 user 锚点，按 SQLite ordinal 复制完整前缀，不使用 UI 当前页。排除原锚点与后尾，赋新消息 ID 并重映射前缀内 sourceMessageId/revisionOf，追加编辑消息（revisionOf 指向原锚点）。子会话新 instance、revision 1，正文、消息、目录和 receipt 同时提交；源会话和消息保持不变。
- 子会话沿用 Web 的角色、情景、设置及 draft/lastChoices/updateSnapshot/protocolShadow/pin 继承语义；仅清除 autoSummaryState、关闭自动摘要，采用当前玩家身份。摘要使用共享纯规则：水位与稀疏 coverage 独立映射；锚点替换水位、coverage 涉及未保留或未知消息时整体失效；无 coverage 的旧摘要保持既有兼容语义。不能把摘要覆盖端点当全历史水位。
- 分支复制复用导入总消息数量与写入 JSON 总量预算，包含新 user 消息；预检失败不写部分子会话。这是本片准入上限，不保证所有已合法保存的大历史都可分支。
- 编辑草稿独立于发送框。取消、空编辑零写；未保存的会话/角色/连接编辑不得被切换丢弃。确认分支不自动调用模型；成功后打开子会话，继续剧情须用户明确触发。失败保留编辑输入；未知提交只查原 receipt，相同 operationId 幂等，不新建第二条分支。
- forkedFrom 沿用来源 sessionId/messageId/createdAt，仅用于来源展示和归档，不作为安全合并授权；合并后继必须冻结父/子 instance 和双 CAS、导入身份、覆盖确认及事务边界。
- DDL/schema 不变不表示可降级。新 fork receipt 后，旧 reader/旧备份恢复应在写入前拒绝；回退用分支前备份或新版本导出，不删除 receipt 绕过。须以真实前版/新版 reader 对照验证，Windows 平台体验单列验收。


## 魔法茶会文本分支合并（T-TEA-2b）

本片为已有文本分支增加显式审阅并合并到直接父会话，不调用模型，不合并配置、媒体或更新草案，不增加 schema、权限或通用 lineage 系统。

- `merge-preview` 在同一只读事务读取两端当前 sessionId/instance/revision、父 user 锚点和子唯一 user 编辑消息。子 `revisionOf` MUST 精确等于父锚点 ID；任一锚点已 superseded、缺失或多义均拒绝，不按时间戳、UI 页或祖先链猜测。关系完整的同包导入只作为待审阅候选；unresolved 来源不可合并。
- 确认只提交 operationId、双 target、anchorMessageId 和 editedMessageId，不接受客户端替换正文。Native 在既有维护锁、连接锁及单事务内先查原 receipt，再检查双 CAS/Busy，并从实际源文档重新核验 `forkedFrom.sessionId/messageId` 与请求父/锚点相同。任一变化须重新审阅，不刷新原包 CAS 自动重发。
- 父锚点起的完整 ordinal 尾部保留 ID/正文，新增既有 superseded 标记；已经失效的历史保留原归因。子编辑锚点起完整尾部另分配 ID，追加至父最大 ordinal 之后，保留源顺序与 createdAt。已 superseded 子消息不得复活；源正文、消息、instance/revision 全部不变。已知 sourceMessageId/revisionOf 优先映射复制尾内 ID，其次保留父现存 ID，否则移除；未知扩展不递归重写。
- 先 SQL COUNT/SUM 有界准入，再计量实际变更：父文档、重写旧消息及新消息合计遵守既有单记录、10000 消息和 64 MiB 写入预算，包含标记增量。超限零写。父 revision/catalog 各加一，旧尾标记、新尾、文档及 receipt 同事务提交；写入和提交失败不能留下部分结果。
- 父角色/情景/设置/draft/pin/来源及无关扩展保真，不复制子摘要或整份 session。父摘要按共享 branch-summary 的无 clonedMessageIds 模式处理：水位落替换尾部，或 coverage 选中/裁切 ID 不在保留前缀（含未知 ID）时整体清除；旧无 coverage 语义保持。清 lastChoices/autoSummaryState，保留 autoSummaryEnabled，不触发模型。共源 ChatMessage MUST 禁用 superseded choices 与其回调，Web fallback 同样排除旧剧情。
- owner 在每次异步返回核对 incarnation；取消、切换和卸载使迟到预览失效。页面先保护未保存的连接/角色/导入输入，确认列两端标题、锚点及替换/复制数量，并说明旧历史与源分支保留。取消零写；unknown 只能查询原 receipt，not-found 才可原包重试。saved 后加载父，刷新失败明确为已保存，不复活后来删除的父。
- merge receipt 是永久旧 writer 屏障，MUST 不因 UI 确认、父/子删除或未来清理而移除；以后若清理，须先提供等效永久屏障并另行评审。回执可引用已删除的会话，不要求重建它。SQL schema 与归档版本不变，不意味着可以降级。
