# 故事模型输入去冗余与原卡隔离

状态：已接受，分批实施。日期：2026-09-11。
适用：Arena 普通/流式战报、多人共用的 Hosted runtime，以及连续战报与升华的相关投影。
上位约束：[平台复杂度预算](../decisions/2026-09-01_193200_平台复杂度预算与故障降级决策.md)。

## 数据边界

完整数据卡继续用于验签、原生性判断、编辑、同步、导出、战后更新和备份。
`packages/domain/src/story-prompt-data.ts` 是模型输入专用的纯函数投影，不得写回原卡。
`stripBattleSelectionTransportMeta` 继续只负责选卡传输字段，不扩张为正文裁剪器。

## 已实施的基础投影

- 角色、结构化主/辅助情景、素材剥离 templateId、签名、已知卡片 metadata、创作输入、预设标记、传输统计与已知往返备份。
- adjudicationEvents 只交给已有判定器；正文只接收判定结果，不从嵌套配置自行判定。随机算法、种子、重试和结果返回不变。
- 普通战报核心 JSON 不再携带 arena_history/current_state；独立块遵守读取开关、历史筛选和条数上限。
- userAnswers 独立格式化且只出现一次，兜底角色也遵守严格排位的关闭开关。
- buildState 以“角色参数”输出；保留规则标识、版本、输入与派生数值，剥离 rules[].validationSummary。
- _battle_story 留在原卡供章节规划解析，不作为情景正文传入模型。
- 仅处理已知 schema 路径；不递归按 metadata/author/下划线等通用名称删除用户自定义嵌套设定，不改写 Markdown 字符串。
- 不把 0、false 或未知扩展当作空值丢弃；不因文本相似就合并不同角色/事件。

## 验收与非目标

`packages/domain/tests/story-prompt-data.test.ts` 保护不变性、规则参数和自定义字段；
`packages/hosted-runtime/tests/arena-prompt-projection.test.ts` 保护单次注入、历史上限与严格排位；Prompt 业务回归由 `packages/hosted-runtime/tests/arena-prompt-builder.test.ts` 与 `arena-generation-prompt.test.ts` 直接验证 canonical runtime，覆盖问卷开关、角色参数、素材、长度和输出契约；不再保留已退出生产的 Web builder 副本及逐字 parity。
不变更 wire/schema、原卡存储、权限或安全审核政策；裁剪不是提示注入防护的替代品。

## 连续战报组合

Hosted session 在内部调用中声明 `baseContext: 'arena-provided'`，不从请求字段读取该选项。
基础 Arena 已提供当前完整角色、情景、素材、问卷 Lore 和玩家引导；会话附加上下文不再重复这些块。
会话附加块保留章节规划、会话摘要和近期章节窗口。分支、重写、读取开关、种子与原卡持久化不变。
独立上下文编排仍可生成完整输入；有 workingCombatants 时以当前完整快照替代种子中的角色副本，而非同时序列化两份。
种子情景/素材使用共享投影，问卷只携带启用的 Lore，source 不再携带 Provider/模型或运行标识。
最近章节只剥离已知机器元数据注释，并在正文预算截断前完成；普通正文、Markdown 和故事注释保留。
验收覆盖纯领域投影及 `arena-companion-session.test.ts` 的实际组合请求，确保基础内容没有随去重而丢失。

## 升华输入

结构化升华继续先从完整原卡生成历史、当前状态和问卷专用块，再使用共享投影编排核心设定。
目标模板只省略与原始设定同名且 JSON 序列化值完全相同的参考字段；不同字段保留，不做模糊语义去重。
差异参考不改变完整输出 schema、保留字段规则或服务端 finalize；原卡和模板初始对象均不被修改。
流式升华复用共享投影，同时保留原有历史处理方式，以及模型仍需要的当前状态、问卷和目标模板提示。
验收：`packages/hosted-runtime/tests/sublimation-prompt-projection.test.ts` 与原有升华 runtime 测试。

## 明确保留的内容

安全检查仍走原有策略，不直接复用写作投影以缩小审核范围；审核成本不计入本次已实现的节省。
角色正文、人物分析、能力设定与问卷不做自动摘要；未知自定义字段、不同角色的同名事件不按相似性合并。
创建/修复任务中确实需要的模板和输入条件不因字段名称相似而移除；只删除故事模型不需要的那一份。
