- Preview 资源机器事实由 `config/preview-environment.json` 管理：当前 `status=not-provisioned`、
  `activation=fail-closed`；D1 binding/Gateway authority 明确与 production 共用，R2 与非 D1 运行时权威输入按后果要求专用，Redis 首期允许与 production 共用网络，

  runtime 不暴露 `FLUSHALL`/`FLUSHDB`/任意 `sendCommand`；
- 公共 `NEXT_PUBLIC_*`、Turnstile site key、GA ID、非敏感 feature flag，以及明确接受 quota/billing 耦合的 AI provider

- 现有 Arena 可恢复 generation fault test 已证明单次 Provider、稳定 request identity、Redis replay/terminal、D1/R2
  finalization 和 subscriber disconnect 语义，但尚未把 Hosted DR 的完整故障矩阵、版本门禁和总退出审计统一成

因此本 Goal 重估为约 `5–7 小时`，范围是“共享控制契约 + 隔离故障矩阵 + Phase 2.5 审计收口”，不扩展到

## 2. Objective 与非目标

Objective：在不降低客户端不可信、服务器权威、secret 隔离、D1/DO/R2 数据所有权、Legacy/Better Auth、Arena v1
wire 和 no-replay 不变量的前提下，建立可重复的 G25E-2 Hosted DR fault matrix，证明可执行的 ACCEPT-012–017
安全语义，并完成 Phase 2.5 总退出审计。

非目标：

- 不执行 production deploy/cutover、remote production DB migration/write/restore、production Redis flush；
- 不修改 secret、Access、credential、release/tag 或 Git 历史；
- 不把 Redis 提升为 authority，不为不确定结果自动重放非幂等 operation；
- 不因为演练方便而把所有 capability 强行改成 DR eligible；未列入或未覆盖的 capability 继续明确降级/待演练；
- 不宣称生产 RTO/RPO 或真实外部控制面已经通过，除非有独立生产授权和可审计证据。

## 3. 方案裁决

### 3.1 采用：共享 seam 上的混合 fault harness

故障演练由三层组成：

1. runtime-neutral Hosted DR selector/version gate，作为不带 I/O 的决策真相；
2. Hono/Next/Redis/D1 现有真实 adapter、provider、runtime 和 Arena service 的隔离 fault injection，验证固定
   error wire、authority、replay 和 telemetry；
3. 机器可读矩阵登记 case、ACCEPT 条款、覆盖 scope、证据测试、恢复步骤和生产授权状态，validator 拒绝漏项、
   伪造 production PASS 与不安全 replay policy。

这种混合方式保留真实业务 seam 和已有本地 Redis/D1 built-runtime 证据，同时使每次 CI 可重复运行，不把外部
Cloudflare 控制面或不稳定网络状态作为必要依赖。

### 3.1.1 资源隔离按后果分类

本 Goal 不把“每个环境每个变量都必须独立”作为机械规则。隔离判定按失败后果分层：

- 只影响展示、分析或运营配额的输入可以共享，但必须在 preview 配置中显式登记其运营耦合；
- 能读写 production D1/R2、提交 D1 Gateway authority、签名业务事实或完成 Arena terminal/finalization 的输入必须隔离；
- Redis 只承载 cache、rate-limit、lease、presence、Pub/Sub、active replay 等可丢失/可重建状态。首期共享网络与
  `preview` prefix 解决 key collision，不提供 ACL 意义上的权限边界；未来可按风险升级为 Redis ACL、独立 container 或
  完全独立 Redis，不改变 D1/DO/R2 authority 规则。

`config/preview-environment.json`、preview workflow checker 和 runtime prefix port 是该裁决的机器可读执行面。
它们不得被解释为 production Redis 的授权隔离或 Redis flush 的安全许可。

### 3.1.2 Stable origin 必须按已验证控制面激活

客户端安全投影同时包含 stable/preview logical origin 与非秘密 activation state，但继续不得包含 physical
primary/DR origin。production Hosted routing 必须遵守：

- stable control plane activation 与 production same-origin fallback readiness 是两个独立状态；
- `controlPlane.provisioning=not-provisioned` 且 `productionFallback.artifactReadiness!=verified` 时，production target
  构建必须 fail closed；既不能把请求发送到 manifest 中尚未纳管的 stable hostname，也不能自动把所有请求放置到
  same-origin Next/OpenNext；
- 只有独立机器事实将 `productionFallback.artifactReadiness` 标记为 `verified`，且 validator 证明所有会被客户端放置到
  same-origin 的 operation 均可执行、双 adapter/contract/build/secret/binding gate 完整时，production target 才可选择
  same-origin fallback；实际 production placement 仍需单独记录，不能由 artifact evidence 伪造；
- 只有 `controlPlane.provisioning=production` 且 `check:hosted-dr` 验证合法 production evidence 后，生产客户端才启用
  stable origin；后续切换 physical primary/DR 不需要重新发布客户端；
- preview activation 继续由 `config/preview-environment.json` 与 preview workflow 独立门禁，不能借 production stable
  状态激活；local/test 只有显式 loopback origin 才能绕过外部控制面用于 fault injection。

Production、preview 与 local/test 必须使用可信、显式、互斥的 compile-time deployment target。不能用
`NODE_ENV=production` 或“配置了哪个 origin”推断 deployment target，因为 OpenNext preview build 同样使用 production
优化模式。production 永远不得接受 preview origin/evidence；preview 永远不得接受 stable origin 或 production
activation evidence；未声明 deployment target 的普通本地/CI build 按 local、Hosted client routing disabled 处理。

`not-provisioned` 下的同源路径若未来被独立验证并启用，属于迁移期 execution-placement fallback，不代表 stable
control-plane failover 已上线或通过。若该路径在 production release 中承载真实流量，exit/release audit 必须另行记录
production placement/readiness 证据，不得仅以隔离 selector 或 artifact PASS 代替。

### 3.1.3 D1 Gateway 信任边界

`D1_GATEWAY_URL` 是服务器部署配置，不来自不可信请求。生产 preflight 必须继续拒绝非 HTTPS、带 username/password、
非根路径、query 或 fragment 的 URL，并要求 HMAC 或 Bearer transport credential；loopback HTTP 只允许显式
`HOSTED_DR_LOCAL_FAULT_INJECTION=true` 的 local/test drill。

不再要求 `D1_GATEWAY_ALLOWED_ORIGINS`。当 URL 与 allowlist 由同一个 runtime env owner 提供时，重复登记既不能抵抗
env owner 被错误授权或攻破，也不能替代 credential、最小权限和 preview authority 隔离。若未来需要独立 origin
policy，必须由不同 trust owner 的 immutable deploy policy 或平台 egress policy 提供，不能重新增加同源自证变量。

### 3.2 不采用：只用静态 manifest/mock 断言

静态断言不能证明 provider/session、Redis 空态、D1/Gateway 失败或 subscriber 中断后的实际行为，无法满足
ACCEPT-012–017 的故障证据要求。

### 3.3 不采用：本地演练直接替代生产演练

local/preview fault injection 只能证明代码与隔离语义。生产控制面、真实域名、真实凭据和生产数据的演练继续标为
`DEFERRED`，并在退出日志中列出授权前置条件与 runbook。

## 4. Fault matrix 与判定

机器可读事实落在 `config/hosted-dr-drills.json`。每个 local case 必须关联实际测试，并使用固定的
`verified`/`deferred` 状态；生产专属 case 不得写成 `verified`。

| Case | 故障注入 | 最小真实证据 | 保护性判定 |
| --- | --- | --- | --- |
| `G25E2-HONO-UNAVAILABLE` | Hono primary 不可达 | 隔离 selector 选择 DR readiness，client projection 不变，双入口 wire parity；真实 stable control plane 与 fallback placement 分别需要 production evidence | safe/read seam 可切换；未验证任一 production placement 时 production target 构建 fail closed |
| `G25E2-REDIS-UNAVAILABLE` | Redis 连接/命令不可用 | Redis runtime status、限流/重放命令 fail closed，D1/DO/R2 authority 不变 | 允许降级；不得缓存升权 |
| `G25E2-REDIS-EMPTY` | 清空隔离 Redis namespace | authority fixture 仍从 D1/DO/R2 恢复，ephemeral replay/presence/telemetry 重建或明确降级 | Redis 不是 authority |
| `G25E2-GATEWAY-UNAVAILABLE` | Hono D1 Gateway 失败 | Hono readiness 503；Cloudflare binding provider 仍能执行 safe read | 不共享 Gateway 故障域 |
| `G25E2-MIDFLIGHT-DISCONNECT` | accepted generation 流中途断开 | 稳定 request/generation identity、单 Provider、状态查询/恢复或明确失败 | 不创建第二 generation |
| `G25E2-D1-UNAVAILABLE` | D1/session/query 失败 | authoritative write/read fail closed；Redis/local state 不被提升 | 不伪造成功 |
| `G25E2-DR-SECRET-MISSING` | DR required secret 缺失 | production Next guard 在 handler 前固定 503，日志不泄露 secret | fail closed |
| `G25E2-VERSION-SKEW` | Hono/DR 允许的短暂版本偏差 | expand/rollout 可读写兼容；destructive cleanup 在不兼容时阻断 | 先 expand/rollout，后 cleanup |
| `G25E2-CUTBACK` | primary 恢复后的切回 | 只影响新 safe/read 或未 dispatch 请求；旧 dispatched/unknown operation 不重发 | active-passive、new-request-only |

`G25E2-MIDFLIGHT-DISCONNECT` 复用并扩展现有 Arena resumable generation fixture；其余 cases 直接调用当前
Hono/Next/provider/runtime seam。证据必须观察实际响应、调用次数、authority 状态或固定错误码，而不是只检查
实现源码字符串。

## 5. Version skew 与 cutback contract

在 `@mahoshojo/hosted-api/hosted-dr` 增加纯函数 version gate：

- `expand` 允许同一 contract family 内受限的 backward-compatible version skew；
- `rollout` 要求 shared core、Hono adapter、DR adapter 和 client contract 都能读写当前/旧字段；
- `contract`/destructive cleanup 只有在 primary、DR、client 对齐且旧字段不再被读取后才能放行；
- 不同 family、过大的版本差、未完成 expand 或未知版本一律 fail closed。

cutback 不新增第二个请求执行器。它只把后续 `not-dispatched` 请求重新指向 Hono；已 `dispatched` 或 outcome
`unknown` 的 non-idempotent operation 仍返回 `fail-closed`，safe/read 才能按明确状态恢复查询。

终态副作用使用稳定 effect identity：`arena-terminal:<generationId>:<effect>`，其中 effect 为
`combatants`、`story-impacts` 或 `ratings`。D1/R2/ratings bridge 在 transport timeout 或 post-claim retry 时
必须使用同一 key（或由该 key 确定性派生的写入 identity）；该 key 不是允许跨 runtime 重放未知 non-idempotent 请求的理由，
而是终态已被权威 claim 后用于抑制重复副作用的幂等契约。
