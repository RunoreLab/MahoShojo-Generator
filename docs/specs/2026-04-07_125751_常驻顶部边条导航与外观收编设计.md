# 常驻顶部边条导航与外观收编设计

- 日期：2026-04-07
- 状态：已完成讨论确认，待实现计划
- 目标：在核心页面提供常驻顶部边条，收编原外观浮球，并为未来消息提醒与用户入口扩展预留稳定位置。

## 1. 背景

当前项目的全站入口主要集中在首页功能目录，各业务页也有少量局部“返回首页 / 跳转竞技场”等链接。全局层面唯一常驻的交互组件是 `_app.tsx` 中挂载的外观浮球 `ColorModeSwitcher`。

随着 `/battle`、`/arena`、`/creator`、`/pvp`、`/me` 等页面逐渐形成跨页面使用链路，用户需要更稳定的全站导航入口。同时，外观浮球虽然解决了全局主题切换问题，但会占据页面浮层空间，容易遮挡内容或操作区。

本次设计采用顶部边条替代浮球式外观入口，并为未来消息提醒、用户菜单等能力建立位置约束。

## 2. 范围

v1 实际覆盖页面：

- `/`
- `/battle`
- `/arena`
- `/creator`
- `/character-manager`
- `/me`
- `/pvp`

v1 明确排除页面：

- `/ranking`
- `/encyclopedia`
- `/encyclopedia/[slug]`
- `/details`
- `/canshou`
- 其他未列入覆盖白名单的长尾或沉浸式单任务页面

说明：`/ranking` 与 `/encyclopedia*` 仍可作为顶栏导航中的跳转目标，但它们自身不在 v1 顶栏覆盖范围内。这样可以先避开这些页面已有页内 header、侧栏 sticky 与表格 sticky 的偏移兼容成本。

## 3. 非目标

- 不做全站搜索。
- 不做真实消息系统。
- 不展示未读数或假消息数据。
- 不重写各页面已有局部 header。
- 不在 v1 覆盖所有长尾页面。
- 不把 `/ranking` 与 `/encyclopedia*` 的 sticky 偏移问题纳入一期实现。

## 4. 信息架构

顶部边条采用“Logo 回首页 + 主导航组 + 右侧功能区”结构。

Logo 区：

- 显示站点标识和简短站名。
- 点击跳转 `/`。
- 首页不额外显示“首页”文字导航，避免重复。

主导航组：

| 分组 | 入口 |
| --- | --- |
| 创作 | 创作工作台 `/creator`、魔法少女生成 `/name`、自由生成 `/free`、情景生成 `/scenario` |
| 竞技 | 简洁竞技场 `/battle`、完整竞技场 `/arena`、PVP `/pvp`、排行榜 `/ranking` |
| 角色 | 角色管理 `/character-manager`、个人页 `/me`、角色成长 `/sublimation` |
| 百科 | 百科目录 `/encyclopedia` |

高亮规则：

- 当前路由属于某一组时，高亮该组。
- `/battle`、`/arena`、`/pvp`、`/ranking` 归入“竞技”。
- `/creator`、`/name`、`/free`、`/scenario` 归入“创作”。
- `/character-manager`、`/me`、`/sublimation` 归入“角色”。
- `/encyclopedia` 与 `/encyclopedia/[slug]` 归入“百科”。
- 首页只通过 Logo 区表达当前位置，不额外制造双高亮。

## 5. 桌面端交互

桌面端顶栏为常驻 sticky top bar，高度约 `56px`。

布局顺序：

- 左侧：Logo / 站名。
- 中部：主导航组。
- 右侧：外观菜单、消息占位、用户入口。

导航组交互：

- 鼠标 hover 或键盘 focus 时打开轻量下拉菜单。
- 下拉项点击后直接跳转。
- 当前组高亮，当前具体入口可在下拉中使用更强的文本或背景状态。

视觉约束：

- 使用半透明玻璃质感或与现有 `--app-surface` 变量一致的表面样式。
- 避免大面积紫色默认风格，优先贴合项目现有粉色、蓝色与白色渐变基调。
- z-index 高于普通页面内容，但不应覆盖弹窗模态层。

## 6. 移动端交互

窄屏顶栏只保留必要入口：

- Logo / 站名。
- 外观图标。
- 消息占位图标。
- 菜单按钮。

移动端菜单：

- 点击菜单按钮打开抽屉或全屏下拉面板。
- 抽屉内按“创作 / 竞技 / 角色 / 百科”分组展示完整导航入口。
- 用户入口放在抽屉底部或顶部固定区。
- 抽屉支持点击遮罩关闭与 Escape 关闭。
- 抽屉打开时应避免页面横向溢出。

## 7. 外观设置收编

原外观浮球全部停用，不再作为全局悬浮控件渲染。

新的外观入口：

- 顶栏覆盖页通过 `TopBarThemeMenu` 提供外观切换。
- 复用 `lib/color-mode.ts` 中的 `useColorModePreference`、`COLOR_MODE_OPTIONS`、存储键和文档属性应用逻辑。
- 不再保留浮球拖拽、最小化、位置记忆等交互。

兼容说明：

- 未覆盖顶栏的排除页面 v1 不提供新的外观切换 UI。
- 已保存的外观偏好仍通过现有 color-mode 逻辑生效。
- 如果排除页后续也需要外观入口，应优先接入顶栏或增加页内非悬浮入口，而不是恢复浮球。

## 8. 消息占位

v1 只提供消息位置，不提供实际消息能力。

约束：

- 不请求消息接口。
- 不显示未读角标。
- 不展示假消息列表。
- 可显示 disabled 状态或“敬请期待”提示。

后续真实消息系统接入时，应复用该位置，并补充消息数据源、未读计数、跳转目标和通知权限规则。

## 9. 用户入口

用户入口复用 `lib/useAuth.ts`。

未登录状态：

- 显示 `登录 / 注册`。
- 点击跳转 `/character-manager`，沿用当前登录入口所在页面。

已登录状态：

- 显示用户名或头像首字母。
- 下拉项包含 `个人页`、`角色管理`、`退出登录`。
- 退出登录调用现有 `logout` 能力，不新增认证协议。

可选展示：

- 如果后续需要显示头像，应优先复用 `/me` 现有头像数据接口；v1 不强制新增头像请求。

## 10. 组件与文件边界

建议新增文件：

| --- | --- |

| `components/navigation/GlobalTopBar.tsx` | 顶栏骨架、桌面布局、移动布局切换 |
| `components/navigation/TopBarThemeMenu.tsx` | 外观菜单，复用 color-mode 逻辑 |
| `components/navigation/TopBarUserMenu.tsx` | 登录态与未登录态用户入口 |
| `components/navigation/TopBarMobileDrawer.tsx` | 移动端抽屉 |
| `components/navigation/TopBarMessagePlaceholder.tsx` | 消息占位入口 |

建议修改文件：

| 文件 | 改动 |
| --- | --- |
| `pages/_app.tsx` | 按路由白名单挂载 `GlobalTopBar`，移除原全局 `ColorModeSwitcher` 浮球挂载 |
| `components/shared/ColorModeSwitcher.tsx` | v1 可保留文件但不再从全局渲染；若没有其他引用，后续可删除 |
| `styles/globals.css` | 如有必要，增加顶栏变量或全局样式辅助类 |

## 11. 页面兼容策略

- 顶栏通过 `_app.tsx` 统一插入，避免每个页面重复实现。
- 覆盖页内容应自然排在顶栏之后，优先使用 sticky in-flow 顶栏，减少内容被遮挡的风险。
- 对已有“返回首页”等局部入口的页面，v1 允许短期共存。
- 如果某个覆盖页出现明显冗余或拥挤，再单独收敛该页面局部 header。

## 12. 测试与验收标准

单元测试：

- 导航配置能正确返回覆盖白名单结果。
- 路由能正确归类到“创作 / 竞技 / 角色 / 百科”。
- 排除页 `/ranking`、`/encyclopedia`、`/details`、`/canshou` 不显示顶栏。

组件测试：

- 桌面端渲染 Logo、主导航组、外观入口、消息占位、用户入口。
- 未登录时显示登录入口并指向 `/character-manager`。
- 已登录时显示用户入口，并提供个人页、角色管理与退出登录。
- 移动端菜单按钮可打开和关闭抽屉。
- 移动端抽屉展示完整导航分组。

回归检查：

- `bun test`
- `bun run lint`
- `bun run build`
- 对 `/`、`/battle`、`/arena`、`/creator`、`/character-manager`、`/me`、`/pvp` 做桌面与窄屏人工检查。

## 14. 风险与后续

风险：

- 覆盖页已有局部导航可能短期重复。
- 用户在排除页无法直接切换外观，但已保存偏好仍会生效。
- 顶栏引入 `useAuth` 后可能增加一次认证状态检查，需要观察是否影响首屏体感。

后续：

- 二期可评估 `/ranking` 与 `/encyclopedia*` 的顶栏接入，并同步处理 sticky 偏移。
- 若后续要做全站搜索，应先定义搜索域与索引来源。
- 消息系统接入前应先明确消息类型、未读计数来源和用户设置入口。
