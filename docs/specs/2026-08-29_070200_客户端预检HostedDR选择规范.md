# 客户端预检 Hosted DR 选择规范

状态：`accepted`

日期：2026-08-29

规格标识：`SPEC-hosted-dr-client-preflight-v1`

依据：`ADR-hosted-dr-low-cost-client-preflight`

本文中的 `MUST`、`MUST NOT`、`SHOULD`、`SHOULD NOT`、`MAY` 按 RFC 2119 / RFC 8174 的规范性含义解释。

## 1. 目标

本规范定义 Web/Installed Client 在一个新 Hosted 请求首次 dispatch 之前，如何依据 Hono primary readiness、Next/OpenNext DR readiness 和 capability manifest 选择唯一 runtime，同时保证：

- 不依赖付费 Load Balancing 或新的托管 control plane；
- 不在 POST 已经可能执行后跨 runtime 重放；
- 不把 `fail-closed` capability 误当作可切换；
- 不在客户端暴露 secret 或提升客户端信任；
- production build 从旧 control-plane gate 安全迁移到 client-preflight gate。

首期实现范围是 `apps/web`。Desktop/Mobile 未来复用同一纯选择 contract 时，可以使用不同 transport adapter，但不得改变本文的 dispatch、eligibility 和 no-replay 语义。

## 2. 术语

- **generation intent**：一次用户明确发起的新生成意图。浏览器渲染重试、React 重跑或网络恢复不是新的 intent。
- **preflight probe**：在业务 POST 之前发送的有界 readiness GET。
- **selection**：根据 probe 与 manifest 为新请求选择 `hono-primary`、`next-dr` 或 `unavailable`。
- **dispatch boundary**：客户端已经开始或无法证明尚未把业务请求交给选定 runtime 的边界。
- **route pin**：selection 完成后，在该 operation 生命周期内固定首次业务请求的 placement。
- **ambiguous outcome**：请求可能已被服务器/Provider 执行，但客户端没有可靠终态。
- **eligible operation**：manifest 对当前 route + method 明确允许 `safe-read` 或 `new-request-only` DR 的 operation。
- **managed control plane**：Cloudflare Load Balancing、Worker router、DNS selector 或其他独立于客户端的托管/外部流量选择层。

## 3. 机器输入与 source of truth

### 3.1 服务端 manifest

`config/hosted-dr-capabilities.json` 继续保存完整控制面、DatabaseProvider、capability、secret/binding 名称和 contract 状态。它是 route/method/request class/DR/replay policy 的唯一机器事实源。

实施时应以向后兼容方式增加或明确以下非秘密 routing 信息；字段名可在编码前按现有 schema 风格微调，但语义不得改变：

```ts
type HostedDrRoutingV1 = {
  defaultMode: 'client-preflight' | 'managed-control-plane';
  managedControlPlane: 'optional-disabled' | 'preview' | 'production';
  primaryOrigin: string;
  drOrigin: string;
  primaryProbePath: '/api/health/ready';
  drProbePath: '/api/hosted/dr-readiness';
  preflightTimeoutMs: number;
};
```

默认 production 值必须表达：

```text
defaultMode = client-preflight
managedControlPlane = optional-disabled
```

### 3.2 客户端投影

生成器 MUST 从服务端 manifest 产生最小 client projection。客户端不得直接 import 带 secret/binding 细节的完整 manifest。

client projection 至少包含：

- routing mode；
- public primary origin；
- Web DR placement（同源相对路径或 public DR origin）；
- primary/DR probe path；
- preflight timeout；
- contract version；
- 每个可路由 route pattern + method 的 `drMode`/request class 最小投影。

client projection MUST NOT 包含：

- secret 名称之外的任何 secret 值；
- Authorization、Cookie、Access service token；
- D1/R2/Redis credential；
- 私网 IP、内部管理地址或仅运维可见 endpoint；
- Provider 配置、prompt 或用户数据。

### 3.3 当前 endpoint contract

Primary probe：

```http
GET {primaryOrigin}/api/health/ready
```

成功条件：

- transport 在超时内完成；
- HTTP status 为 2xx；
- JSON object 的 `ok` 精确为 `true`；
- `service` 精确为 `mahoshojo-hono`；
- `placement` 精确为 `hono-primary`；
- `contractVersion` 与 client projection 兼容。

计划冻结基线中的 `/api/health/ready` 尚未返回 `placement` / Hosted DR `contractVersion`；当前实现已以向后兼容的附加字段补齐。其他 status、非 JSON、body 缺失、字段不匹配、CORS failure、DNS failure、TLS failure、abort 或 timeout 均视为 primary non-ready。客户端不得根据 dependency 文案猜测“部分可用”，也不得记录或持久化 readiness body 中的 dependency 细节。

DR probe：

```http
GET {drPlacement}/api/hosted/dr-readiness
X-MahoShojo-Hosted-DR-Capability: {canonicalCapabilityId}
X-MahoShojo-Hosted-DR-Method: {operationMethod}
```

DR probe MUST 从 generated operation 的 canonical route/method 产生固定低基数 capability headers，不得发送包含真实资源 ID、query 或用户输入的实际路径。服务端 MUST 用同一 manifest capability guard 校验目标 operation 的 `drMode`、required secret/binding、database provider 与 consistency，再执行固定 safe-read；通用无 header readiness 可为旧监控保持兼容，但客户端不得把缺少目标回显的响应当作该 operation ready。

成功条件同样要求 HTTP 2xx、JSON object 的 `ok` 精确为 `true`、`placement` 精确为 `next-dr`、`capabilityId` / `operationMethod` 与请求目标精确一致，且 `contractVersion` 与 client projection 兼容。实施者应复用现有 shared readiness contract，不创建只在客户端里理解的第二种响应。Primary/DR probe request MUST 使用 `GET`、`cache: 'no-store'`、`credentials: 'omit'`，不得附带业务 Authorization、Cookie、prompt/body、真实资源 ID 或用户标识；两端 response MUST 设置 `Cache-Control: no-store`。

## 4. 选择算法

### 4.1 规范算法

对每个新的 generation intent：

```ts
const operation = manifest.lookup(path, method);

const primary = await probePrimaryOnce({ timeoutMs });
if (primary.ready) return pin('hono-primary');

// 未登记 route/method 只能继续走健康的 primary，不能自动进入 DR。
if (!operation) return unavailable('operation-not-declared');

if (!isEligibleForPreDispatchDr(operation)) {
  return unavailable('dr-not-eligible');
}

const dr = await probeDrOnce({
  timeoutMs,
  capabilityId: operation.canonicalCapabilityId,
  operationMethod: operation.method,
});
if (dr.ready) return pin('next-dr');

return unavailable('no-ready-placement');
```

`isEligibleForPreDispatchDr` MUST 只在下列情况返回 true：

- request class 为 `safe-read`，且 replay policy 为 `safe-read-only`；或
- `drMode` 精确为 `new-request-only`，且 replay policy 为 `never-after-dispatch`，contract status 已验证。

`drMode=fail-closed`、unknown、pending、route/method mismatch 必须返回 false。

### 4.2 状态表

| Primary probe | Operation policy | DR probe | 结果 |
| --- | --- | --- | --- |
| ready | 任意 route/method（未登记者仅允许 primary） | 不执行 | pin `hono-primary` |
| non-ready | `new-request-only` / eligible safe-read | ready | pin `next-dr` |
| non-ready | `new-request-only` / eligible safe-read | non-ready | `unavailable:no-ready-placement` |
| non-ready | `fail-closed` | 不执行 | `unavailable:dr-not-eligible` |
| non-ready | 未登记 route/method | 不执行 | `unavailable:operation-not-declared` |
| non-ready | contract pending/unknown | 不执行 | `unavailable:dr-not-eligible` |
| probe internal error | 任意 | 按上述规则 | 不得绕过 policy |

### 4.3 Probe 次数与缓存

v1：

- 每个新的 generation intent MUST 发起一次 primary probe；
- primary ready 时 MUST NOT 再探测 DR；
- primary non-ready 且 operation eligible 时 MUST 最多发起一次 DR probe；
- probe MUST 使用独立 `AbortController`，超时后终止自身 transport；
- probe MUST 使用 `cache: 'no-store'` 与 `credentials: 'omit'`，不得被 browser HTTP cache、service worker 默认缓存策略或 credential 状态改变；
- probe MUST NOT 与业务 POST 共享 AbortSignal；
- probe MUST NOT 自动重试；
- v1 MUST NOT 使用跨 intent 的正向健康缓存。

后续若 telemetry 证明 readiness RTT 成为实质问题，可以另行引入不超过数秒的 bounded cache，但必须保留 generation intent freshness、负缓存上限和故障演练；不得仅在实现中偷偷加长 TTL。

### 4.4 超时

初始默认 `preflightTimeoutMs` 为 1500ms，由单一配置生成。实现允许在 500–3000ms 范围内按部署环境调整；超出范围必须修改规范或提供明确审查理由。

业务 generation timeout、SSE idle timeout 与 preflight timeout 是不同概念。不得用 300 秒业务超时作为 readiness timeout。

## 5. Dispatch、route pin 与重试

### 5.1 Dispatch boundary

在调用业务 `fetch` 前，selector MUST 返回不可变 decision：

```ts
type HostedPlacementDecision =
  | { placement: 'hono-primary' | 'next-dr'; reason: string; contractVersion: string }
  | { placement: 'unavailable'; reason: string; contractVersion: string };
```

业务 adapter MUST 先完成 selection，再创建/发送业务 fetch。不得用两个并行 POST 的 `Promise.any`、hedged request 或“谁先返回用谁”。

一旦业务 fetch 被调用，即认为 dispatch boundary 已跨越。即使异常同步抛出，也只能在 transport adapter 能以机器证据证明未提交任何字节时另行讨论；v1 一律按 ambiguous outcome 处理，不自动改发另一 runtime。

### 5.2 Route pin

- selection 必须在一次 intent 内保持不变；
- request body、request ID、generation ID、headers 和 auth 只能为该 intent 构造一份语义实例；
- streaming response 必须继续读取选定 placement，不得中途换 origin；
- 页面 rerender、hook retry、service worker retry 不得重新触发第二次首次 POST；
- 对有稳定 operation ID 的 status/stream lookup，safe-read route 可以按其独立 manifest policy选择 placement，但不得重新创建 generation；
- cancel/settlement/authority command 继续遵循自身 route/method policy，不能继承“初始 generation 可 DR”推断。

### 5.3 Ambiguous outcome

业务 POST 后出现 timeout、abort、断线、页面关闭、流读取错误或未知 5xx 时：

- MUST NOT 自动改发另一个 runtime；
- SHOULD 向上层返回结构化 `AMBIGUOUS_OPERATION_OUTCOME`；
- 有稳定 request/generation ID 时 SHOULD 提供 status/reconnect/resume；
- 无恢复 contract 时 SHOULD 明确告知用户“请求可能已开始，避免立即重复提交”；
- telemetry MUST 区分 preflight failure 与 post-dispatch ambiguity。

只有 future manifest 明确标记 durably idempotent、权威去重已验证且 operation ID 不变的 command，才可在独立 spec 下重试。

## 6. 请求、鉴权与安全

- Primary cross-origin 业务请求继续使用现有 auth/activity header adapter；不得把同源 Cookie 自动发送到 Hono；
- DR 同源请求继续遵循原 Next auth/actor resolution；
- 两侧必须保持相同 public request/response contract 和安全错误投影；
- Hono CORS MUST 精确允许生产 Web origin 和必要 headers/methods，不得使用 wildcard credential 组合；
- readiness endpoint MUST NOT 依赖它正在检查的 Redis/D1 业务 limiter 才能返回结果；SHOULD 使用项目已经具备或无需新增付费产品的 edge/DDoS、连接数、并发或速率保护，并且不得因此绕过全局连接保护；
- 服务端 MUST NOT 信任客户端声明的 placement、health 或 `isDr=true`；每个 runtime自行验证 capability、secret、binding、auth 和 authority；
- public origin 暴露不等于允许 direct-origin 绕过管理后台 Access。Admin 与 Hosted API 的安全边界继续分开。

## 7. 错误模型

selector 至少产生以下稳定、低敏感错误原因：

```text
PRIMARY_PROBE_TIMEOUT
PRIMARY_NOT_READY
PRIMARY_PROBE_PROTOCOL_ERROR
OPERATION_NOT_DECLARED
DR_NOT_ELIGIBLE
DR_PROBE_TIMEOUT
DR_NOT_READY
DR_PROBE_PROTOCOL_ERROR
NO_READY_PLACEMENT
AMBIGUOUS_OPERATION_OUTCOME
```

用户文案可以本地化，但不得把 `DR_NOT_ELIGIBLE` 描述成“系统肯定丢失数据”，也不得把 `AMBIGUOUS_OPERATION_OUTCOME` 描述成“请求未发送”。

未知异常对用户保持通用安全文案，诊断只记录错误类别和 request correlation，不记录 secret/prompt/body。

## 8. Telemetry

客户端 SHOULD 记录：

- contract version；
- route family（低基数，不含动态 ID）；
- primary probe outcome/duration；
- DR probe outcome/duration（若执行）；
- selected placement；
- selection reason；
- post-dispatch terminal class；
- ambiguous outcome count。

MUST NOT 记录：prompt、生成正文、完整 URL query、Authorization、Cookie、API key、Provider credential、Data Card private content 或用户可识别自由文本。

Hono/Next runtime telemetry 可以继续记录受信 placement；客户端选择值只作为 observation，不提升为服务器权威事实。

## 9. Production build 与 CI 门禁

### 9.1 必须替换的旧门禁

`controlPlane.provisioning=not-provisioned` 在 `client-preflight` 模式下是合法状态，MUST NOT 单独导致 production build 失败。

但实现 PR MUST 同时引入新的 fail-closed gate，至少验证：

1. `defaultMode=client-preflight` 显式存在；
2. primary/DR origin 是无凭据、无 query/fragment 的允许 HTTPS origin；
3. probe path 与现有 route 精确匹配；
4. client projection 与 manifest 无 drift；
5. 所有 projected route/method 在 manifest 中存在；
6. `fail-closed`/pending operation 不被投影为 eligible；
7. Next DR adapter/guard/contract test 对 eligible route 存在；
8. Hono readiness 的 `service`/`placement`/`contractVersion`/`Cache-Control` 与 CORS contract test 通过；
9. client bundle 不含 secret/internal endpoint；
10. selector/no-duplicate-dispatch tests 通过。

旧 production gate 与新 gate MUST 在同一原子提交或可构建 checkpoint 中替换，避免出现“先放开、后补安全”的窗口。

### 9.2 测试矩阵

至少覆盖：

- primary 200 + `ok:true` + `placement:hono-primary` + compatible `contractVersion`；
- primary/DR response 缺少或伪造 placement/version、被缓存、携带 credential；
- primary 503；
- primary timeout/abort/DNS/CORS/protocol error；
- primary ready 后不请求 DR；
- eligible route primary down + DR ready；
- eligible route primary down + DR down；
- `fail-closed` route primary down 时零 DR POST；
- 未登记 route/method 在 primary ready 时只走 primary，在 primary non-ready 时不探测/不发送 DR；
- 动态 route pattern mismatch；
- probe 只执行一次、POST 只执行一次；
- POST timeout/stream disconnect 后零 cross-runtime replay；
- React rerender/重复 callback 不创建第二 intent；
- auth/activity headers 在 primary/DR 的既有语义；
- public client projection 无 physical secret/internal value；
- production/preview/local/test config；
- optional managed-control-plane mode 未激活时不影响默认 build。

### 9.3 集成验证

实现完成后至少运行：

- Hosted DR manifest/schema/contract gate；
- Web selector/client targeted tests；
- Hono health/CORS targeted tests；
- Next DR readiness/capability guard tests；
- user-visible contract gate；
- workspace boundary/naming gate；
- Web production build 与 OpenNext build；
- 全量 `ci:verify`；
- 在隔离环境执行一次 Hono unavailable → eligible Next DR 新请求切换；
- 执行一次 POST 后断链，证明没有第二 Provider/第二 POST。

不得把源码字符串匹配或 mock-only test 描述为真实 production failover。

## 10. 首期范围与非目标

首期 MUST：

- Web 常规 `new-request-only` generation family；
- primary/DR readiness；
- selector、route pin、错误模型、telemetry；
- production build gate 替换；
- 可选 LB 代码降级为 inert；
- 文档、测试和回滚。

首期 MUST NOT：

- 把 Arena generation/companion `fail-closed` route 改为 eligible，除非独立规格证明；
- 实现 POST 后 transparent failover；
- 实现 active-active、随机负载分摊或 hedged generation；
- 新建 Worker reverse proxy；
- 购买/配置 Cloudflare LB；
- 修改 DNS、Access、production secret、D1/R2/Redis 数据；
- 以本规范关闭管理后台 Access 或其他无关 blocker。

## 11. 验收条件

本规格实现完成必须同时满足：

- 新 generation intent 在 primary ready 时只有一份 Hono POST；
- primary non-ready 时，eligible operation 只有一份 Next DR POST；
- `fail-closed` operation 在 primary non-ready 时没有 DR POST；
- 任意 POST 后网络异常均不会跨 runtime 自动重放；
- `controlPlane.provisioning=not-provisioned` 不再单独阻断 `client-preflight` production build；
- 新 production gate 对错误 origin、drift、secret、missing adapter 和 policy widening fail closed；
- Hono/Next public wire、auth、authority 和用户错误投影无回归；
- 默认路径未相对于 ADR 定义的默认分支成本基线新增付费产品或生产资源；
- 完整验证与独立审查没有开放的 Critical/Important finding。
