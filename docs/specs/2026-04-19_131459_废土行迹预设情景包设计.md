# 废土行迹预设情景包设计

日期：2026-04-19 13:14:59  
状态：已完成设计讨论，待人工评审  
范围：为现有预设情景库新增一组《废土行迹》世界观向预设情景包，首轮包含 3 张彼此独立、偏叙事开局型的通用情景卡。

---

## 1. 本轮目标

本轮设计聚焦以下结果：

1. 在现有预设情景体系中新增 3 张可直接使用的《废土行迹》世界观向预设情景。
2. 三张情景彼此独立，可分别作为旅途中的不同开局舞台使用，而不是必须串联成固定主线。
3. 预设情景整体采用克制现实向的废土旅途基调，强调信息差、判断、试探、立场摩擦、处置与后果。
4. 首轮优先服务“废土行迹旅人角色”，同时允许普通角色被投放进废土局面中展开故事。
5. 保持现有预设情景接入方式与 UI 不变，不新增废土专属路由、分类或专门交互。

本轮不是要一次性做出《废土行迹》的完整情景矩阵，也不是要把预设情景系统重构成专门面向废土世界的结构化任务引擎。

---

## 2. 非目标

本轮明确不做以下内容：

1. 不新增“废土行迹”专属页面、专属筛选标签或专属入口分组。
2. 不新增第 4 张“世界总览母卡”或“势力说明卡”。
3. 不把三张卡设计为连续主线中的固定三章节。
4. 不为首轮情景引入 `_battle_story` 连续章节规划。
5. 不把三张卡直接做成重机制、强流程、强判定的结构化 `scenario` 卡。
6. 不在首轮发明会改变世界格局的超大城市、终极势力或万能超科技中枢。
7. 不把角色默认写成高规格新人类、顶级技术持有者或世界级大组织核心成员。

---

## 3. 已确认的产品方向

### 3.1 情景包形态

- 采用 `3 张基础情景包`，而不是只做 1 张主打卡。
- 三张卡之间为 `彼此独立` 关系，可单独使用。
- 风格为 `叙事开局型`，重点提供舞台、摩擦和推进钩子，而不是完整流程规则。

### 3.2 角色适配范围

- 优先服务《废土行迹》世界观内的旅人角色。
- 同时允许普通角色被作为外来者、临时同行者、委托人或误入者接入，但不以“异世界误入废土”为主轴。

### 3.3 世界锚点强度

- 采用 `中锚点` 方案。
- 默认放在 `硅晶之路 / 铁火地带 / 废土通路网络` 的共同语境中。
- 允许出现：
  - 世界调查协会
  - 学城与知识节点
  - 商路网络
  - 地方聚居地与地方势力
  - 救世军背景旅人或外围武装
- 但不把任一张卡写死为单一地点或单一势力的专属舞台。

### 3.4 整体气质

- 采用 `克制现实向`。
- 重点是：
  - 信息差
  - 风险判断
  - 立场摩擦
  - 合作与不合作的边界
  - 代价与后果
- 冲突未必以全面战斗收束，调查也不等于“下副本拿奖励”。

---

## 4. 方案比较与选择

### 4.1 方案 A：全部做成通用情景卡

- 做法：
  - 三张卡全部采用 `general-scenario` 形式，以 Markdown 正文承载世界锚点、开场局面、推进钩子和可能走向。
- 优点：
  - 最符合“叙事开局型”的目标。
  - 角色接入门槛低。
  - 写作自由度高。
  - 与现有通用情景链路兼容最稳定。
- 缺点：
  - 首轮不会直接提供很强的结构化规则消费能力。

### 4.2 方案 B：全部做成结构化情景卡

- 做法：
  - 三张卡全部采用 `scenario` 结构，写入 `scene / roles / events / development` 等字段。
- 优点：
  - 更利于后续规则化消费。
  - 结构统一。
- 缺点：
  - 容易把情景写成任务模板或流程卡。
  - 与本轮“旅途舞台优先”的目标不完全一致。

### 4.3 方案 C：推荐方案

- 首轮三张卡全部使用 `general-scenario`。
- 但三张卡的正文骨架保持统一，并按未来可升级为 `scenario` 卡的方式组织内容。

选择理由：

1. 改动面最小，能直接接入现有预设情景体系。
2. 更适合废土旅途中“偶遇、调查、冲突”这类需要保留叙事弹性的舞台。
3. 后续若某张卡反馈特别好，可以单独升级成结构化规则卡，而不影响首轮落地。

## 5. 情景包分工

### 5.1 废土行迹·偶遇：同路人未必同行

- 定位：
  - 旅途遭遇型开局卡。
- 主要作用：
  - 让角色因为同一路段、同一中继点、同一事故或同一条情报而发生接触。
- 核心问题：
  - 这些人为什么会撞上彼此。
  - 他们是否值得信任。
  - 他们要不要临时同行。
- 典型摩擦来源：
  - 学城背景角色更重规程与验证。
  - 调查协会合作调查员更重记录、核查和通报。
  - 商路旅人更重时效、补给和收益。
  - 救世军背景旅人对超科技遗产、技术相关人员和“污染风险”更敏感。
- 不写死的边界：
  - 不默认初见必战。
  - 不把某个势力直接写成脸谱化反派。

### 5.2 废土行迹·调查探索：路标失效之后

- 定位：
  - 调查与路线复核型开局卡。
- 主要作用：
  - 让角色面对一段突然失效、变质或产生异常的通路、节点或记录。
- 核心问题：
  - 异常到底是什么。
  - 是否值得继续深入。
  - 查明后该如何处理成果。
- 典型切口：
  - 旧路突然失效。
  - 补给点或哨点失联。
  - 旧档案与新传闻互相冲突。
  - 有人带回不完整记录或可疑样本。
- 真正戏剧点：
  - 情报该公开、付费出售、限制流通还是暂时封存。

### 5.3 废土行迹·战斗冲突：封路与突围

- 定位：
  - 局势升级后的武装冲突型开局卡。
- 主要作用：
  - 让角色因封锁、误判、拦截、争夺目标物或护送失败而被逼到必须动手。
- 核心问题：
  - 为什么非打不可。
  - 打完后谁还能带走什么。
  - 是否需要断后、撤退、放弃目标或承担追责。
- 适合承载的局面：
  - 狭窄通路上的封锁。
  - 护送途中被拦截。
  - 围绕样本、记录、许可或幸存者归属发生争夺。
  - 救世军外围武装或地方武装将角色误判为高风险对象。
- 边界：
  - 战斗本身不是终点。
  - 打完后的代价、去留与后果同等重要。

## 6. 统一内容骨架

三张卡正文统一使用以下 Markdown 骨架，以保证首轮风格稳定：

### 6.1 这是一张什么样的情景卡

- 用 2 至 4 句说明该卡的用途与基调。
- 明确这是废土旅途中的开局舞台，不是百科设定介绍，也不是纯战斗模板。

### 6.2 世界观锚点

- 仅放与行动判断直接相关的锚点。
- 重点包括：
  - 通路
  - 聚居地接口
  - 危险区边缘
  - 信息差
  - 调查与记录的价值
  - 势力之间的现实摩擦

### 6.3 开场局面

- 写清楚角色当前为什么会在这里。
- 写清楚眼前出了什么事。
- 写清楚这个局面为什么不能被轻易忽视或绕开。

### 6.4 角色为何会在这里

该部分沿用《废土行迹》已有的“旅途接口”思路，至少包含：

- `进入理由`
  - 旅人为什么必须来到此处。
- `离开理由`
  - 旅人为什么不能长期停留。
- `可能带走的东西`
  - 旅人离开时可能带走的，不只是实物，还包括情报、债务、关系裂痕、样本、幸存者、许可、记录等。

### 6.5 潜在冲突与摩擦

- 不把冲突简化成“善恶对立”。
- 重点写：
  - 不同背景角色的判断差异
  - 对风险与技术的不同态度
  - 资源压力
  - 时效压力
  - 责任与信誉压力

### 6.6 推进钩子

- 每张卡提供 4 至 6 个常见推进方向。
- 不强制单一路线。
- 让 AI 可以根据在场角色自行挑选推进方式。

### 6.7 可能走向

- 不写成简单的成功 / 失败二分。
- 采用“结果、代价与变化重新流回世界”的结局谱系思路。
- 典型走向可包括：
  - 情报被带回节点
  - 路线被暂时确认
  - 错误情报被扩散
  - 样本被带走
  - 队伍临时结盟后再分流
  - 冲突结束但问题未解决

### 6.8 使用提示

- 明确提醒 AI：
  - 少堆设定术语。
  - 少把角色默认成高规格存在。
  - 少直接升级成总力战。
  - 多写试探、协商、记录、止损、撤退与后果。

## 7. 三张卡的专属侧重

### 7.1 废土行迹·偶遇：同路人未必同行

#### 推荐开场

- 在中继点等待放行。
- 在危险区边缘共同避险。
- 因事故而被迫拼队。
- 围绕一条真假难辨的路线情报碰头。

#### 推荐推进钩子

- 是否共享情报。
- 是否互换补给。
- 是否暂时结伴通过危险段。
- 是否为陌生人提供担保。
- 是否将某人排除在行动之外。

#### 推荐结局方向

- 关系变化优先于事件完成。
- 重点是“是否同行、如何分流、带着什么认识离开”。

### 7.2 废土行迹·调查探索：路标失效之后

#### 推荐开场

- 原本可走的路线突然失效。
- 补给点或哨点失联。
- 旧记录与地方传闻出现冲突。
- 有人带回一份可疑但不完整的调查记录。

#### 推荐推进钩子

- 先遣试探。
- 复核旧标记。
- 判断谁有资格继续深入。
- 是否上报。
- 是否公开异常。
- 是否封存成果。

#### 推荐结局方向

- 重点落在“调查成果如何流转”。
- 情报的公开尺度与接触资格本身就是戏剧点。

### 7.3 废土行迹·战斗冲突：封路与突围

#### 推荐开场

- 路口封锁。
- 护送途中被拦截。
- 围绕样本、记录、许可或幸存者发生争夺。
- 角色被武装势力误判为高风险目标。

#### 推荐推进钩子

- 谈判破裂。
- 拖延争取时间。
- 断后掩护。
- 突围撤离。
- 放弃部分目标保全队伍。
- 战后通报与追责。

#### 推荐结局方向

- 重点落在“代价如何分配”与“局势如何变化”。
- 不把战斗写成唯一高潮。

## 8. 实现边界

### 8.1 数据模板

- 三张卡全部使用 `GeneralScenarioSchema`。
- 每张 JSON 至少包含：
  - `templateId: "通用情景"`
  - `title`
  - `content`

### 8.2 文件与注册位置

- 在 `public/scenario-presets/` 新增 3 个 JSON 文件。
- 在 `lib/scenario-presets.ts` 中新增 3 条预设元数据。
- 三条元数据的 `template` 全部为 `general-scenario`。

### 8.3 建议文件名与标题

- `S13_wastetrace_encounter.json`
  - `废土行迹·偶遇：同路人未必同行`
- `S14_wastetrace_route_failure.json`
  - `废土行迹·调查探索：路标失效之后`
- `S15_wastetrace_blockade_breakout.json`
  - `废土行迹·战斗冲突：封路与突围`

### 8.4 建议描述

- `废土行迹·偶遇：同路人未必同行`
  - `【旅途遭遇】通路与中继点上的临时相遇，强调试探、立场摩擦与是否同行。`
- `废土行迹·调查探索：路标失效之后`
  - `【调查探索】围绕失效路线、失联节点与异常记录展开复核，强调判断、记录与处置。`
- `废土行迹·战斗冲突：封路与突围`
  - `【冲突】因封锁、误判或争夺目标而升级的废土武装冲突，强调代价、撤离与后果。`

## 9. 文案强约束

### 9.1 世界补完边界

- 允许补完：
  - 小型聚居点
  - 临时中继点
  - 失效路段
  - 边缘驻点
  - 临时合作网络
- 禁止补完：
  - 改写世界格局的超大核心城市
  - 万能技术中枢
  - 一次性解释世界终极真相的核心设施

### 9.2 角色默认规格

- 若用户没有明确指定，不默认角色为：
  - 高规格新人类
  - 顶级意识技术使用者
  - 世界级势力核心层
  - 单人能决定地区格局的关键人物

### 9.3 气质约束

- 不自动把偶遇升级成死斗。
- 不把调查写成“刷副本”。
- 不把战斗写成纯爽文推进。
- 冲突要服务于现实问题：
  - 能不能过路
  - 要不要救人
  - 要不要带走样本
  - 要不要上报
  - 要不要承担后果

## 10. 测试与验证边界

首轮只验证接入正确，不测试文案优劣。

建议覆盖以下最小验证项：

1. `lib/scenario-presets.ts` 已注册三条新预设。
2. 三个文件名均可通过 `normalizeScenarioPresetFilename`。
3. 三条预设的 `template` 均为 `general-scenario`。
4. 三个 JSON 都至少满足 `templateId/title/content` 的基本形态。

本轮不强制新增页面交互测试，除非实现过程中需要锁定分页或展示行为。

---

## 11. 与现有世界观条目的挂接

本设计主要引用以下已确认的《废土行迹》世界观边界：

- 世界整体采用 `聚居地 + 通路 + 危险区` 结构。
- 旅途不只是战斗，还包括判断、调查、探路、记录、通报与带回结果。
- 旅途遭遇更适合写成要求队伍做出处置判断的遭遇谱系。
- 旅途结局更适合写成结果、代价与变化再分流的结局谱系。
- 探路与路线复核的核心，在于把不确定空间转化为有条件可执行的通行方案。
- 聚居地和节点更适合通过 `进入理由 / 离开理由 / 带走的东西` 与旅途相连接。

---

## 12. 最终结论

本轮采用以下落地方式：

1. 新增 3 张彼此独立的《废土行迹》预设情景。
2. 三张卡全部采用 `general-scenario` 形式。
3. 三张卡统一使用“旅途舞台骨架”，但分别对应：
  - 偶遇
  - 调查探索
  - 战斗冲突
4. 标题统一使用 `废土行迹·` 前缀，保证识别度。
5. 首轮只做预设内容接入，不扩 UI，不上专属分类，不顺手改造成重流程情景系统。

该方案改动面小、世界观识别度够高、风格统一，并为后续继续扩写《废土行迹》世界观向预设情景留下足够空间。
