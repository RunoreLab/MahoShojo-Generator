# /creator 创作页工作台布局设计

## 文档信息

- 日期：2026-04-02 15:37:28
- 状态：已确认，可进入 implementation plan
- 适用范围：`/creator`
- 参考页面：`/magic-tea-party`、`/arena`

## 背景

当前 `/creator` 页面仍继承早期问卷生成页的窄屏导向骨架，主内容放置在全局 `.container` 与 `.card` 约束下，页面宽度长期停留在约 `500px`。这一结构在手机端可用，但在桌面宽屏场景下存在明显问题：

1. 模板、规则、问卷设置、答题、结果被串在一条长纵向流程里，切换成本高。
2. 新增的规则与摘要面板只是插入旧页面，没有形成持续可见的工作区。
3. 右侧主任务与全局设置混在一起，答题阶段容易被配置项打断。
4. 宽屏空间利用率低，结果阅读、规则编辑、答案回顾都显得拥挤。

用户希望为宽屏用户提供更舒适、更高效的创作体验，同时保持窄屏与手机端的可用性，并参考魔法茶会与竞技场的布局经验。

## 目标

1. 将 `/creator` 从窄屏单列页面升级为桌面端工作台布局。
2. 让右侧主区专注当前任务，减少配置噪音。
3. 将持续可调、持续可看的上下文信息固定到左侧控制台。
4. 保持手机端单列体验，不让窄屏操作变复杂。
5. 在不改动创作业务链路的前提下完成第一阶段 UI 重组。

## 非目标

1. 不改 API 契约。
2. 不重写问卷、生成、保存、立绘链路。
3. 不在本轮抽离 `/creator` 页面全部状态到新 hook。
4. 不在本轮做大规模视觉重绘或全站样式翻新。
5. 不处理与 `/creator` 工作台无关的历史样式债。

## 现状结论

### 布局约束

`/creator` 目前受全局样式中的 `.container` 与 `.card` 宽度限制，导致宽屏下仍保持窄列阅读体验。页面主体在视觉和信息结构上都仍是旧版问卷页的延长线。

### 页面结构

当前 `/creator` 实际上把三类内容串在一页中：

1. 开始阶段：介绍、注意事项、模板与规则配置、开始按钮。
2. 答题阶段：题目导航、问卷设置、当前题目、语言、生成方式、AI 提供商、批量填充、答案概览、备份导出。
3. 结果阶段：流式 Markdown 结果或结构化结果卡、保存动作、立绘生成。

这些内容在业务上并非同一优先级，但在现有结构中被同等对待，造成主任务焦点模糊。

### 参考页启发

- `magic-tea-party` 的价值不在于“有侧栏”，而在于把持续要看、持续要调的内容固定到一侧，把主任务放到主画布中。
- `arena` 的价值在于页面已经摆脱全局窄容器约束，具备真正面向宽屏的工作区。

因此，`/creator` 应参考魔法茶会的工作台结构与竞技场的宽壳层，而不是简单放大旧问卷卡片。

## 方案总览

本次设计采用“魔法茶会式创作工作台”方案：

1. 桌面端使用左右双栏。
2. 左侧为 sticky 创作控制台，负责全局配置、进度、导航与回顾。
3. 右侧为主工作区，只显示当前阶段的核心任务。
4. 手机端回退为单列，左栏内容变为顶部折叠区。

核心原则是：`右侧保留主任务，左侧承接上下文。`

## 信息架构

### 左侧控制台

左栏采用四组结构，自上而下排列：

#### 1. 创作概况

用途：提供用户进入页面后第一眼就能理解的总体状态。

包含内容：

- 当前阶段
- 当前题目进度
- 当前模板
- 主规则状态
- 原生性提示
- 必要的轻量警告信息

该区块应紧凑、摘要化，不承载重编辑逻辑。

#### 2. 创作配置

用途：承载开始前最重要的内容，同时允许答题中回看或微调。

包含内容：

- 输出模板
- 自由补充说明
- 规则预设选择
- 主规则详情编辑
- 规则运行时摘要

开始阶段默认展开；进入答题阶段后可默认折叠，但必须保留可访问性。

#### 3. 问卷与作答

用途：承载答题阶段的导航与回顾能力。

包含内容：

- 题目导航
- 问卷设置
- 已选问卷与 Lore 状态
- 答案概览

该区块将吸收当前主区中所有“辅助答题但不属于当前题目主体”的信息。

#### 4. 高级生成

用途：放置低频但重要的生成控制项。

包含内容：

- 生成语言
- 生成方式
- AI 提供商设置
- Token 估算
- 批量填充
- 问卷答案导出备份

默认折叠，避免在答题阶段喧宾夺主。

### 右侧主工作区

右侧主区继承当前 `/creator` 的核心主流程，但做减法，只保留主任务。

#### 1. 开始阶段

保留：

- 标题
- 简要介绍
- 关键注意事项
- 开始按钮
- 少量与当前模板强相关的即时提示

移出右侧：

- 模板选择
- 规则编辑
- 自由补充
- 高级生成设置

#### 2. 答题阶段

右侧以当前题目为唯一主角，继续复用现有问卷面板。

保留：

- 当前题目
- 轻量进度信息
- 上一题 / 下一题控制
- 与当前题目直接相关的提示

移出右侧：

- 完整题目导航
- 问卷设置
- 答案概览
- 批量填充
- 语言设置
- 生成方式
- AI 提供商

#### 3. 结果阶段

右侧继续承接现有结果组件与后续操作。

保留：

- 流式 Markdown 结果
- 结构化角色卡 / 情景卡
- 保存到本地
- 保存到云端
- 复制动作
- 立绘生成

要求：

- 不再受旧 `.card` 最大宽度限制。
- 结果排版以宽工作区为前提重新编排，允许更舒展的结果阅读和操作区。

## 响应式策略

### 断点与容器策略

第一阶段使用明确断点表，避免实现时出现多种解释：

1. `< lg`：单列布局。
2. `lg` 到 `< xl`：双栏布局，使用窄侧栏。
3. `xl` 到 `< 2xl`：双栏布局，使用标准侧栏。
4. `>= 2xl`：双栏布局，整体继续居中，但允许更宽的最大容器。

页面外层使用独立工作台壳层，采用 `max-width` 而不是固定宽度：

- `lg` 到 `< xl`：`max-width` 约 `1200px`
- `xl` 到 `< 2xl`：`max-width` 约 `1360px`
- `>= 2xl`：`max-width` 约 `1440px`

这意味着 `1360px` 到 `1440px` 是容器上限区间，而不是进入双栏的最小条件。

### 宽屏桌面

- `xl` 及以上使用标准工作台布局。
- 左栏宽度建议 `360px` 到 `400px`。
- 右侧主区自适应填充剩余空间。

### 中等屏幕

- `lg` 到 `< xl` 仍保留双栏。
- 左栏收窄到约 `320px` 到 `340px`。
- 通过折叠分组控制高度，避免右侧主区被过度压缩。

### 窄屏与手机

- `< lg` 回退为单列。
- 左侧四组内容变为顶部折叠区。
- 右侧主流程保持当前单列思路，不保留左右并排。
- 答题阶段优先展示当前题目，避免手机端被配置区打断。

### 滚动与 sticky 规则

第一阶段采用全页滚动模型：

1. `body` 为唯一纵向滚动容器。
2. 不为左右栏引入独立滚动区，避免双滚动。
3. 左栏 sticky 仅在 `lg` 及以上生效。
4. sticky 的 `top` 偏移统一按页面壳层上边距处理，目标值约为 `24px`。
5. 当左栏内容高度超过视口时，依赖分组折叠缩减高度；第一阶段不引入左栏内部滚动。
6. 手机端禁用 sticky，顶部折叠区随页面自然滚动。

### 移动端折叠默认值

移动端顶部折叠区默认行为如下：

1. 开始阶段：`创作概况`、`创作配置` 默认展开；`问卷与作答`、`高级生成` 默认折叠。
2. 答题阶段：`创作概况`、`问卷与作答` 默认展开；`创作配置`、`高级生成` 默认折叠。
3. 结果阶段：`创作概况` 默认展开；其余分组默认折叠，但必须可访问。

最低交互要求：

1. 每个分组必须通过按钮展开/折叠，并支持键盘访问。
2. 折叠区展开后不得遮挡主任务内容。
3. 用户手动展开的分组在当前阶段内不应被强制自动关闭。

## 组件策略

本轮采用“页面壳重组 + 组件搬家”的方式，不重写核心业务逻辑。

### 新增组件

建议新增以下布局组件：

1. `CreatorWorkbenchLayout`
   - 负责桌面双栏与移动单列切换。
   - 仅处理布局，不持有业务状态。

2. `CreatorSidebar`
   - 承接左栏四组内容。
   - 组合现有配置、问卷与高级生成面板。

3. `CreatorMainStage`
   - 承接右侧三阶段主流程。
   - 按阶段渲染开始、答题、结果。

4. `CreatorOverviewCard`
   - 负责展示创作概况摘要。
   - 用于统一显示阶段、进度、模板、规则、原生性提示。

5. `CreatorQuestionnaireSidebarPanel`
   - 收拢题目导航、问卷设置、答案概览等答题辅助能力。

### 优先复用的现有组件

以下组件应优先直接复用，避免重复实现：

- `TemplateSelector`
- `FreeformBriefPanel`
- `BuildRulePicker`
- `BuildRulePanel`
- `BuildSummaryPanel`
- `QuestionnaireQuestionPanel`
- 现有流式结果渲染链路
- 现有结构化结果渲染链路
- 现有保存、复制、立绘生成相关组件

### 需要从页面中搬出的内联区块

当前 `pages/creator.tsx` 中以下内联区块应迁入左栏：

- 问卷设置
- 语言设置
- 生成方式
- AI 提供商
- 批量填充
- 答案概览
- 问卷答案导出备份

## 状态与数据流

第一阶段保持现有状态来源不变：

1. 继续由 `pages/creator.tsx` 持有当前主要 state、effect、提交逻辑和 handler。
2. 新布局组件通过 props 接收数据与回调，不新增独立业务状态源。
3. 问卷答案、生成模式、流式结果、保存动作、问卷库选择、立绘逻辑维持现有链路。
4. 本轮只允许新增少量派生摘要数据，用于左栏概况展示。

这样可以把本次工作限定为 UI 重组，而不是高风险业务重构。

## 样式策略

1. `/creator` 需要脱离当前全局 `.container` 与 `.card` 的窄宽度限制。
2. 该脱离应只作用于 `/creator`，不能误伤旧页面。
3. 优先为 `/creator` 增加独立页面壳类名或工作台类名，再在其作用域内定义宽屏布局。
4. sticky 行为仅在工作台壳层内定义，避免影响旧页面。
5. 当前已有的卡片视觉可以在第一阶段尽量保留，避免同时引入新视觉系统。

## 第一阶段实施范围

第一阶段仅做以下内容：

1. 新增工作台布局壳。
2. 完成左栏四组落位。
3. 右栏保留现有三阶段主流程。
4. 将辅助答题与高级生成信息迁入左栏。
5. 解除 `/creator` 的窄容器限制。
6. 补充布局相关测试。

第一阶段不做：

1. API 调整。
2. creator 业务状态结构调整。
3. 问卷组件重写。
4. 全新视觉语言重构。
5. 与 `/creator` 无直接关系的通用样式清理。

## 风险与控制

### 风险 1：页面拆分时回归现有生成逻辑

控制方式：

- 保持 `pages/creator.tsx` 为主要状态持有者。
- 只搬运 JSX 和展示逻辑。

### 风险 2：桌面端改善了，但手机端体验退化

控制方式：

- 明确移动端使用单列回退，不强行保留双栏心智。
- 让左栏内容在手机端折叠显示，题目优先。

### 风险 3：右栏再次被塞满辅助信息

控制方式：

- 坚持“右侧只放主任务”的设计原则。
- 问卷设置、答案概览、生成控制项统一收敛到左栏。

## 验收标准

第一阶段完成后，必须满足以下条件：

1. 桌面端 `/creator` 不再停留在窄列，能够稳定显示左侧控制台与右侧主区。
2. 手机端保持单列使用方式，开始、答题、结果流程不比当前更复杂。
3. 答题阶段右侧主区默认只突出当前题目，不再被答案概览和大段设置打断。
4. 左栏可完成模板、规则、题目导航、答案回顾、生成设置等现有关键操作。
5. 流式结果、结构化结果、保存到云端、下载/复制、立绘生成保持可用。
6. 现有 creator 相关测试不回归，并新增关键布局测试。
7. 改动重点是“重排与收口”，不是大规模重写业务逻辑。

## 第一阶段测试要求

第一阶段至少补足以下关键用例：

1. 桌面布局用例：在工作台模式下渲染左右双栏壳层，且左栏与右栏同时存在。
2. 移动布局用例：在单列模式下渲染顶部折叠区，且主区仍可显示当前题目或结果。
3. 答题阶段隔离用例：答题主区继续渲染当前题目面板，同时被迁移到左栏的设置块不再出现在主区。
4. 结果阶段回归用例：流式结果或结构化结果在新布局中仍可渲染后续操作区。

测试实现约束：

1. 若测试环境便于模拟 viewport，则直接按断点模拟桌面与移动状态。
2. 若测试环境不便修改 viewport，则应为布局壳提供可注入的布局模式或断点判定入口，避免测试依赖浏览器真实尺寸。

1. 采用“魔法茶会式创作工作台”布局。
2. 右侧主区继承当前主流程，但只保留主任务。
3. 左侧控制台承接配置、导航、概况和高级生成。
4. 第一阶段只做布局重组与响应式改造，不做业务重构。
