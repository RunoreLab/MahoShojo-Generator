# Desktop 多人原生会话最小闭环

状态：工作规格，范围与 HTTP/WS 传输容量已确认；Native 缓冲、消费回执与生命周期仍须实施验收。归属既有 D5.1c，不代表完整多人生成交付。

依据：[线上本地整合规格 DESK-ONLINE-006/012/013](./2026-10-04_202000_Desktop线上本地整合与AI配置共源规格.md)、[Room 共享 Hono 入口规格 ARI-001/004/005](./2026-08-31_080100_Arena生产Room入口简化与架构重整规格.md)。本片只扩展 Desktop 的受控 Room 通路，不修改 Web 默认协议、房间权限或生成规则。

## 1. 可交付范围

首片包含 `discover/create/join/session/ticket/leave/close` 七项已有操作，路由以 `packages/contracts/src/room-http.ts` 为准：collection 的 GET/POST，以及 `/:roomId/{join,session,ticket,leave,close}`。ticket 仅供 Native 内部消费。Desktop 必须同批完成创建或加入、权威成员与在线状态、断线重连、成员退出及房主关闭的真实页面闭环；不能只交 HTTP 快照页面。

- 创建仅在用户明确操作后发送既有 sharedConfig 投影；加入不上传当前本地草稿。沿用现有空草稿/可共享配置语义及 visibility，不新增公开发现权限。
- 页面明确当前阶段；不展示不能执行的配置发布、提案、踢人或生成按钮。这些操作既不注册 Native capability，也不回退 Web 请求。已有房间的配置与生成状态只能作权威状态展示；本片不宣称正文恢复或生成控制已实现。
- 房主退出导致关闭、成员退出只撤销自身 membership，遵守既有服务端裁决。失联/本机断订阅不表示已退出房间或已停止服务器生成。
- 多人期间有效执行位置锁为 server，普通 AI 配置不落盘修改；退出恢复普通偏好。不上传 Provider 配置、Key 或本地生成结果。

## 2. 同路径 opt-in 与身份

服务目标由现有 `config/hosted-routing.json` primary 构建期固化；WSS 只从该 HTTPS origin 派生，无 DR fallback。Rust 固定注入当前环境已批准的 Web caller Origin，该值与 Hono 服务 origin 分开；renderer 不得提供两者。保留浏览器 exact Origin/CSRF 策略，不添加通配或无 Origin 豁免。Origin 仅为 CSRF 兼容，实际权限仍来自受保护 cookie 的真实 resolver。

新增 `packages/contracts/src/desktop-room-session.ts` 定义以下窄协商，不扩为通用网络代理：

- 每次 HTTP 都由 Native 注入 `X-Mahoshojo-Desktop-Room-Protocol: desktop-room-session-v1` 与 `X-Mahoshojo-Room-Expected-User-Id: v1:<正安全整数>`。
- 每个 POST 都使用闭合外封套 `{ desktopRoom: { version: 'desktop-room-session-v1', expectedUserId }, request: 原操作DTO }`。仅 create 的 desktopRoom 还必带 `createMode: 'new' | 'resume-only'`，其他操作拒绝此字段。header/body 版本与 owner 必须完全相等；缺失、未知版本、未知字段均拒绝，不能降回 legacy 分支。
- 新服务在所有 Room service 与 operation rate-limit 前核实际 resolver.userId 等于 expectedUserId。全局 ingress limiter 仍可能计数。房间 `self.userId` 是 opaque 成员 ID，不是账号 numeric owner。
- 仅协商请求使用闭合响应 `{ desktopRoom: { version, viewerUserId }, result: 原操作回执 }`；错误采用闭合 error 分支，包含白名单 code、有界 message 与 outcome；只有 resolver 与 expected owner 匹配后 viewerUserId 才为 numeric，否则为 null，不返回实际错配账号或业务数据。GET 的 outcome 为 not-applicable；POST 在任何 Room service 前的明确拒绝为 not-applied，进入服务后保守为 unknown，均不表示认证或限流没有副作用。Native 对缺失/错误版本、错误 viewer、非法原 DTO 一律拒收，不展示正文或继续 ticket 流程。
- 未协商 Web 请求与响应保持原样。Native 不接收任意 URL、header、method、cookie、ticket、secretRef 或自报角色权限。

### 旧部署与滚动节点

首片各 POST schema 均为顶层 `.strict()`，旧节点必拒绝上述外封套；新节点核对协商后才剥封套并复用这些原 schema：

| 首片写入 | 原严格 schema | 原业务调用前的解析位置 |
| --- | --- | --- |
| create | ArenaRoomCreateRequestSchema | 创建 receipt 读取、额外创建预算、memberships.create 之前；包括 new/resume-only 两种 wire |
| join | ArenaRoomJoinRequestSchema | memberships.join 之前 |
| ticket | ArenaRoomTicketRequestSchema | websocketAuthority.issue 之前 |
| leave / close | ArenaRoomEpochMutationRequestSchema | memberships.leave / close 之前 |

因此旧节点可以拒绝业务写入、ticket 签发和生成，不承诺零限流计数。验收必须将每条新 wire 送入冻结旧 handler，断言这些业务调用为零；不能仅凭 header 或一次能力 GET。GET 旧节点可能正常读取，Native 拒收无协商回执即可；`session` 会进入 actor recovery，甚至可能收敛已到截止时间的房间关闭，不能描述为绝对无存储维护的纯读。新节点 owner 检查必须早于该 recovery。

## 3. Native socket 与双重作用域

新增独立 `arena_room` Native consumer，复用现有账号受保护槽、固定请求构造与 main-ui ACL，不扩大 `arena_hosted_*` 授权。窄 IPC 为 `arena_room_attach/request/subscribe/detach`：attach 只在本机建立作用域，request 区分上述六种固定 HTTP 操作与闭合的本地 pull/ack 分支（后者绝不发 HTTP/WS），subscribe 内部取得 ticket，detach 只关闭匹配本机作用域。需采用已维护的 Rust WSS 客户端并复用正式 TLS 验证，不手写握手，不开启压缩、代理继承、重定向或明文降级。

- attach 返回随机非秘密 handle，绑定 Native 账号快照和真实 Document 代次，不返回凭据派生 fingerprint。后续操作强制引用该 handle，失效后不得在旧 callback 中自动 attach 续签。前端在 attach 前后核当前面板、账号验证与凭据意图代次；迟到 handle 只 detach 丢弃。同一 Document 按显式 attach 的发起代次保留最新意图，不能按异步完成顺序让旧 attach 取代新 attach；旧 detach 只能命中原 handle。
- 真实宿主以私有 ResourceTable marker 的 `Arc` 身份匹配，不能用可复用 label 代替；marker 缺失也不能重置未消费账。主 frame 的 document-start nonce 不可改写，固定 Native eval 同时核 nonce 与随机 challenge；Started 立即撤销并标 loading，Finished 后才允许稳定 attach。物理 eval 单槽在超时后仍占用，只有真实 callback 或匹配实例销毁才能释放。每个 Document 按显式 attachIntent 单调推进，旧排队调用不能取代新意图。导航开始到各平台 commit 回调之间的实际时序仍须实机验收。
- 账号作用域：在现有账号写入锁内一起冻结 raw session 与 credential epoch；所有 await、成功、错误、401 条件清理都检查原作用域。同账号重新登录也撤销旧作用域。当前原凭据的过期或腐坏清理即使遇删除 IO 失败也先撤销旧 Room 连接；Room 受检条件清理保留实际存储错误，不假报已删除。旧 cached-first 腐坏记录恢复只表示无可用缓存，不作为物理凭据删除成功的回执。
- 房间作用域：roomId、服务器 roomEpoch、Native 连接代次及 main-ui Document 代次共同绑定；旧 ticket、HTTP、socket callback 或 detach 不能影响新连接。服务器 recovery 换 epoch 后，先丢弃旧副本并安装匹配 owner 的新 session，再明确重连；不以重连重放业务 mutation。
- 登出、凭据替换/清除、切房、Document reload/destroy、主动 detach 必须立即撤销 ticket flight、重连 timer 与闲置 socket。仅在下一帧检查身份不足以关闭持续 Pong 的旧在线连接；应在账号 epoch 更新处增加窄内部撤销信号。
- ticket 只短暂存在 Native 内存。复用原固定 WSS path 和既有一次性 ticket query handshake，URL、票据及错误原文不得进入日志、IPC、持久化或导出。Native 必须校验 ticket 响应固定 path，不能跟随任意返回地址。
- 必须成功选择 `mahoshojo.arena-room.presence.v1`；缺少 presence 能力时明确不可用，不回退为假在线。复用原 Ping/Pong、membership/role/roomEpoch 校验及一次性消费。
- HTTP session 与 socket.open 都不能单独证明在线。只有当前连接、room/epoch 匹配的服务器 snapshot 与 presence 才建立在线展示；presence 的成员必须来自 active membership。断线立即清空 presence。
- 只采用 Native 有界缓冲、小 Channel 通知、本地 pull/ack 这一条传输路径。通知不带正文；pull 的闭合批次带 handle、subscriptionId、batchId 与递增 sequence，同 scope 最多一笔未 ack，不能重复派发同一批。TS 完整验证并接纳到有界状态后才 ack，不把回调到达当消费或像素已绘制。ack 只单调推进已发范围，重复幂等，未来序号/错误 scope 拒绝。
- 已交给 Tauri 但未 ack 的通知/批次按完整序列化字节纳入跨订阅总额度；invoke 大响应也可能进入框架队列，不能假定 pull 绕开它。退休/detach 清 Native 自有正文，但不退还框架在途额度；超额暂停并关闭 socket，UI 明示重新打开真实窗口/重启应用的恢复方式。timeout、reload、换账号不能自动清账。退休 ack 仅释放同 Document 精确旧批次自身额度，不续签、不发网络、不推进新订阅；无法证明跨 Document 消费时保留至真实 Webview 销毁。
- 所有业务 HTTP（含 discover、session 与 ticket）按真实实例共享一个物理在途槽，退休任务实际结束前不释放；socket 后台任务同样等待真正退出。业务 POST 不自动重放。HTTP 派发前预留固定终结投递容量，成功/失败必须关联原 requestId、operation 与 outcome；成功回包尚未可靠交付或确认时仍保留原意图，不能因本地缓冲失败偷偷新建。 业务 HTTP 与存续订阅分别在原总预算内预留至多 1 KiB 的终结通知容量，订阅预留不占住在线 leave/close 的 HTTP 槽。当前受检认证失效或原 HTTP/订阅读取凭据失败时，原子选取一个闭合 `revoked` 终结；内部 ticket 失效只标记原 subscribe（requestId 为 null），不暴露 ticket。只释放尚未投递的预留，桥仅终结原作用域；该通知独立计入交付债，其精确 ack 不释放任何旧未消费批次。通知失败不等于原 mutation 未发生。
- 无任意 WS send；仅允许 Native 自己发送既有固定 resync 请求。失序、慢消费者或溢出走明确 resync/断连，不悄悄丢帧后继续显示最新状态。每个新连接（含重连）都会清空本机 socket 快照证明，因此重新取 ticket 时不带旧 control cursor，要求服务器先发送完整 snapshot，再用当前连接中包含 active self 的 presence 确认在线；未来增量恢复需另行提供可验证的连接基线，不能复用 HTTP session 或旧连接的在线证明；本片不收集或伪装完整 story 正文。权威关闭与自身 membership 撤销作为明确终态交付，不当作暂时断网重连。

生产 WSS 采用固定 TCP、平台验证 TLS 后的 handshake-only 客户端，SNI 与证书验证不放宽，仅声明 HTTP/1.1，不接受扩展或重定向。显式使用 NoKeyLog，禁用 early data 与 secret extraction。Desktop 普通 runtime/test 依赖图的 `log` 在 debug/release 均编译为最高 info，因此开发时也不能用 trace/debug 打开第三方握手和帧正文日志；这不覆盖独立构建工具日志。平台验证器仍可能记录 OS、CA 或证书警告/错误，不得误称证书零日志。传输错误、Close reason、URL、Request/Response 原件始终只在私有边界内处理，对外仅给固定码。

## 4. 未知结果与本地边界

所有 mutation 禁止网络自动重试。POST 一旦可能已派发，响应丢失、超预算或缺失/非法 version、viewer、DTO 都归结果未知；拒收展示不等于业务未发生。只有明确受检认证失败且原 raw+epoch 仍当前时才可沿既有条件清理凭据，普通协议/业务错误不能删凭据。create 冻结 creationRequestId、原正文和账号作用域；结果未知时禁止新 ID 的隐式再次创建。现服务没有 creationRequestId 的 GET 查询接口，只能由用户显式确认后，以原 ID/原正文重发既有幂等 create 来核对；UI 不得将其称为只读查询。确认前再次核原 owner/credential epoch；`resume-only` 由服务端强制 `memberships.create({ requireExistingCreationReceipt: true, ... })`，不能把 `hasCreationReceipt=false` 当首次创建。复用原 service 对账号、creationRequestId、正文 digest 和活跃原房间的检查；receipt 过期/丢失、原房间已关闭或原意图失效时只返回明确 conflict/unresolved，不能新建或偷偷换 ID。`new` 保持原创建逻辑，未协商 Web 行为不变；本机计时不能证明 receipt 存在。join、leave、close 先用 session 核对；未知、拒绝与已结束分别呈现，不因重连或恢复自动重发 mutation。

本片不新增本地 room membership 数据库。Native 进程内保留待核对意图供 Document 重建后显式恢复；意图仍绑定原 raw、credential epoch 与撤销 token，不能凭 numeric owner 或新 attach 续签。同账号重登也废止旧意图；临时凭据读取 IO 失败只保留私有待核对，不当作已换账号或已完成。账号切换不得向新身份暴露旧意图；跨进程恢复尚未实现时必须如实提示，不能从草稿自动重建房间。离开页面与显式退出/关闭是不同操作，页面关闭前须处理在途或未知意图。

## 5. 容量与验收门

以下为 Desktop 的传输拒收门：原业务 POST 的完整 UTF-8 JSON 上限为 64 KiB，固定外封套另留 1 KiB，完整 request 的实际 raw body 上限 65 KiB；Native 封套中的 request 在任何 schema 投影前按 compact JSON 的 UTF-8 字节限制为 64 KiB，legacy Web 仍按原 raw body 计量；HTTP 响应完整序列化上限 256 KiB；完整 WSS message（含碎帧聚合）仍为 64 KiB。原 ticket 不超过 4,096 字节、寿命不超过 60 秒。限制按实际 UTF-8 wire bytes 判定，不按字符串长度，也不能截断后接受。

这些容量不保证容纳所有原 schema 合法数据。比如原 ISO 时间戳允许长小数精度，合法目录也可能超过响应上限；Desktop 对过大的 GET 明确显示暂不可用，对可能已派发的 POST 保留结果未知与原意图。服务端不能通过裁剪配置、材料、成员或时间字段伪造可用回执，也不为 Desktop 放宽或收紧 Web 原格式。Room 状态机保证 snapshot 能放入控制帧，不代表含重复 self 的完整 HTTP session 也只有 64 KiB。

Native 慢消费相关容量仍是实施验收门：含作用域元数据的单批 IPC 上限候选 256 KiB、小通知 1 KiB、Native 自有缓冲 256 KiB、跨退休订阅框架未 ack 总额度 1 MiB。须以完整序列化批次、重复 pull、慢消费者、多次退休与真实 Webview 销毁验证；不能从 HTTP/WS 样本推断队列回收已经成立。

Native Rust 字符串的可表示边界限定为 Unicode 标量文本，IPC 的字符串值和对象键都拒绝孤立 UTF-16 高/低代理项，合法配对不受影响；先验证再计 UTF-8 字节，不替换、规范化或截断。原 JSON/Web schema 不因此改变，合法但不可表示的上游 GET 明确拒收，已派发 POST 保持结果未知。

跨退休额度只约束本片受控业务路径的 Native 缓存、通知和大结果。固定小回执与错误小于 1 KiB；携 start pending/fence 的 attach 与 start-tracking-ended 回执单独最多 8 KiB（见第 14 节），由 bridge 串行等待每次 invoke 完成，不增加 ack-of-ack；等待消费者不持 invoke 队列锁，退出先同步废止旧回调再发 detach。此保证不覆盖任意直接 invoke 洪泛或框架自动错误回执的全局内存。已完整验证且确认同 Document 的退休批次可丢弃后精确 ack，只释放自身债务；跨 Document 或无法确认消费的批次仍不清账。

TS/Rust 应消费同一黄金样本，覆盖 32 成员、50 项目录、完整权威 snapshot、Unicode/JSON 转义、重复 self、新封套和恰好超界一字节；拒绝不安全整数、非对象输入、未知字段与过深结构。预算调整须先更新该窄合同，不放松 Web 原预算。

验收分层：

1. 冻结旧 handler 与新 handler：逐 POST 的拒绝/双标记一致性/owner 顺序；原 Web 全回归；resume-only 的缺失/过期/关闭/异体正文/跨账号 receipt 均零新建；GET recovery 先验 owner；重定向与错误无秘密泄露。
2. 真实 Native 模块和合成 HTTP+WSS：presence 子协议、Ping/Pong、ticket 过期/重放、帧边界、主动注销闲置连接、同账号重登、切房、reload、迟到结果、cursor gap、唯一终结、unknown 零自动重放。
3. 真实 Desktop 页面与同一服务器权威 fixture：host/member 互相看见 presence、断线重连、member leave/host close、权限与错误路径；Web 宿主实际回用同一展示/纯状态规则。禁止 renderer 网络和 secret 通路，三处 command/ACL 登记相符。
4. 原完整 CI；Windows/Tauri、OS 凭据、真实部署 WSS 和生产配置分别待验，不用合成测试替代。新 producer 需要用户另行部署，本源码施工不执行生产部署。

## 6. 原子实施顺序

- 合同与 producer：新增窄 opt-in schema/fixture，原 HTTP handler 受检适配与旧 client/server 兼容测试；不复制 Room 业务服务。
- Native consumer：固定 HTTP、WSS、主动身份/Document 撤销及有界 Channel，与同一 fixture 端到端联测；不提前开放尚无 consumer 的其余路由。
- Desktop 实际入口：同批接通上面的 host/member 会话闭环，抽取的最小展示/纯状态接缝必须 Web 当下回用；不整体迁移 Web controller 或 BattleStore，不建立只有未来消费者的平台。

前两步可以分原子提交审查，但仅在第三步闭合后宣称本片产品可用。D5.1c 后续配置/提案/生成仍复用原权威协议，另按实际消费者扩展，不能据此开放 Web 的任意 customProvider JSON。

## 7. 后继：受检房主配置发布

本节扩展前述首片的操作白名单，仅增加固定 `config` HTTP 操作和本地 `end-config-tracking` 分支；不开放提案、踢人、生成或任意网络入口。传输底座与实际发布 UI 分原子片实施，只有 UI 明确接通后才能宣称用户可发布。

- `config` 复用既有 `ArenaRoomPublishConfigRequestSchema` 和完整 `ArenaRoomSessionResponse`。沿原 opt-in owner 封套、预算、错误分相与服务端 host/CAS/引用治理；Native 另核当前权威的房主、roomEpoch、revision、controlSeq。旧 producer 必须拒绝新封套，不尝试 legacy 回退。非 discover HTTP 仍先退休 socket，完整权威回执安装后才明确重订阅。
- 只有匹配原 request/owner/room/self 的严格 POST 成功回执能确认原请求已处理。回执 revision 为原值或原值加一，配置须满足原目标语义；增版必须推进 controlSeq。同 epoch 的完整权威安装不得倒退 revision/controlSeq，同 revision 的配置须精确相同。固定摘要递归排序对象键、保留数组顺序和全部观测版本；目标语义比较则沿共享规则仅忽略 online data-card 的 versionToken，不能混用两种相等。
- unknown 不重发 POST。GET/WSS 只说明当前权威状态：即使目标相同，也不证明原请求成功；原 revision 未变也不证明未写入。GET 成功、不存在或无访问资格均不能自动结束配置跟踪。
- 进程内待核对槽仅保留原作用域、CAS 坐标及原权威固定摘要，不保存目标正文，不扩 attach/通知预算。reload 后不可从当前草稿或新 GET 重建原目标；只允许核对当前状态。GET 同时受当前权威与原 CAS 下界约束，可观察更高 revision，不套原 POST 的加一上界。有配置跟踪时不跨 roomEpoch 认领新 incarnation；无此跟踪的普通 recovery 保持前述换 epoch 行为。
- 明确结束使用原 intentId，先撤销本机作用域及回调权，再移除匹配跟踪；迟到结果不能安装权威、清新意图或推进后续操作。结束不撤回已派发服务器写入，普通关闭/卸载也不表示取消。新写入仍须重新取得权威、比较并明确操作，由服务器 CAS 裁决；不能自动重试。账号/凭据换代不得显示或接管旧意图。

## 8. 后继：受检提案写入 producer

## 9. 后继：Native 提案操作与观察

在既有 `arena_room_request` 内增加固定 submit/withdraw/resolve action 和本地 `end-proposal-tracking`，不增加网络 command 族或 Desktop 写入按钮。

- Native 仅从完整受检 snapshot 与连续控制事件维护当前作用域的 pending 提案索引，最多 256 条，完整提案数组的序列化总额最多 256 KiB，沿原合法 snapshot 上界，不裁剪。原子替换；游标缺口、同 ID 内容冲突或超界使提案写权失效，须重新读取完整权威。摘要回执不更新完整副本游标，也不能单独恢复写权。
- 单一待核对槽冻结共享观察器的完整 target（原 request、proposal identity、有序 changes、selection 与 linked），序列化上限 192 KiB；不额外复制正文到通用 frozen request。它与最多 256 KiB 的索引分账，合计新增常驻业务 JSON 上限 448 KiB；此数不是进程 RSS，解析对象、在途 HTTP 与原投递账本仍各受原预算约束。没有持久化意图或 terminal 历史账本。
- submit 要求当前 active member，允许旧 baseline，拒绝未来 baseline；withdraw 要求当前 member 为索引中的作者；resolve 要求当前 host 与 pending 身份。普通接受不增加全局 revision CAS，逐项 expectedBase、依赖闭包和 atomic group 仍由原业务服务裁决；只有非空 override 使用精确 reviewed revision。
- 原 POST 成功须匹配操作、目标 ID、roomEpoch 与原 owner。resolve 的完整 snapshot 原子安装并沿既有完整副本单调性检查；submit/withdraw 摘要不安装 snapshot。未知结果只读观察，不自动重发；TS 与 Rust 使用同一业务观察金样。可信关联 terminal 结束等待，partial 只报告范围未知；pending、缺失、冲突或关联不足保留防重发。
- 观察结果走原有界投递队列，只有精确 ACK 才释放已确认目标的待核对槽。原 Document/handle 退出后不得由新 scope 认领旧目标；reload 后仅保留防重发与显式结束能力。结束先撤销旧回调再释放匹配 intentId，不取消服务器写入；新操作须 fresh 权威与明确发起。失权、换账号及凭据换代沿原 Native 围栏处理。

选择校验与逐项预览复用 multiplayer-core 的依赖闭包、atomic group 和 staged expectedBase 分析。覆盖同意绑定当前宿主身份、room、epoch、revision 与完整提案身份及 changes；审阅或选择变化不能复活旧同意。普通接受不增加全局 CAS，非空 override 仍要求精确 reviewed revision。宿主派发前复核原 owner、房间与提案身份，预览不能授予权限。

## 11. 后继：当前战报读取与断线恢复

仅开放当前 active generation 的 `generationRead`：固定 GET `/api/arena/rooms/v1/:roomId/generations/:generationId`，禁止 query/history、启动与取消。服务端沿既有 membership/current-generation 校验和 replay 恢复，Desktop owner 检查在业务读取前。读取可恢复已有生产者订阅，不创建新模型任务。普通错误与其余操作仍用原预算；仅此操作的成功原件上限采用现有 companion 的 76,711,888 字节，超限明确拒收，不裁剪或收紧 Web DTO。

Native 共用原物理 HTTP 槽，读取不取消 socket，也不更新在线、配置或控制游标。HTTP 完成后释放物理槽；普通操作可以中止本机 reader，不能被剩余正文 ACK 长期占住。账号 raw/epoch、真实 Document、room/epoch、active self、generation/attempt 与不可变生成坐标在读取及交付时复核；已观察的同代终态不得被旧 active 结果覆盖。无效 snapshot/control 会先废止 reader 权限，完整权威恢复前不沿旧 membership 继续读。

- 原始 UTF-8 封套只长期保留一份；借用校验完整 DTO（包括任意合法时间精度与大 adjudication），只物化有界身份字段。摘要覆盖原始字节，自由文本中的合法孤立代理项 JSON 转义不被改写。此预算不是进程 RSS 上限。
- 小 `generation-descriptor` 关联 requestId、room/epoch、generation/attempt、byteLength、SHA-256；其精确 ACK 后才物化首个原文片段。每片原始 UTF-8 最多 16 KiB，前片精确 ACK 后才产生下一片。沿原 256 KiB 批次/Native 队列、1 MiB 跨退休框架债务记账；重复 pull 不重发，重复 ACK 不推进，退休不退款。禁止预切整份片段数组。
- 末片 ACK 的 `accepted` 仍只表示精确消债；仅首次末片 ACK 可附 `generationRead: { requestId, current }`。同一 Native 临界区复核读取身份与权限后才授予 `current: true`。失效已交末片只留下单个无正文回执，ACK 或 scope 退休即清理；`false` 不把仍有效 socket 当失败。存储错误保留原固定撤销路径。
- 未 pull 的 descriptor/片段失效时，仅以同 batch/sequence 的固定错误替换，重新计算全部容量和预留；已交正文债务不可退款。读取、消费停滞、总期限、scope 失效均明确结束唯一 reader；取消本机订阅不调用服务器生成取消。
- Renderer 不逐片刷新 React 或复制累计全文。终片触发异步 digest/DTO 验证，但不阻塞控制事件泵；完整验证、首次末片许可与最后本机 nonce/身份围栏同时成立才安装。socket 终态和拼接预览不等于最终权威战报。

首读、重连 snapshot、缺片和终态触发同一个单飞恢复，最多合并一次必要重读。协议、摘要与超限错误在同 generation/attempt 下停止自动重试，用户可明确重试；正常传输错误不重放任何 mutation。HTTP 超时与本机片段消费计时分离，本机使用进度空闲期与有界总期限。

Web 与 Desktop 当下回用 multiplayer-core 的 128 帧/256 KiB 故事缓冲和 ui-web 结果壳；宿主只装配报告能力。Desktop 保持既有安全媒体/外链、长正文折叠和源码展示，完成报告不授予 D4 HTML 执行。验收覆盖真实 Native 模块的合成 HTTP/WS 到 Renderer 原件轨迹、权限/终态竞态、精确债务、稳定错误和真实页面；Windows/Tauri、系统凭据性能及生产 TLS/部署仍须分别验证。

## 12. 后继：房主停止当前生成

本片只增加固定 `generationCancel` POST 与 `generation-cancel` IPC；不开放生成启动、历史、成员发起、Provider/Key 或自动重放。Web/Desktop 当下回用同一个受控停止确认组件，确认打开时捕获 room/epoch/self/generation/attempt，确认提交时复核原目标，不能将旧确认改指向新任务。

- Native 仅允许已观察的当前 active host 停止当前 starting/running 目标；在实际 HTTP 派发前再次核对账号、Document、房间权限与完整 generation 身份。已知未发送可报告 not-applied；进入业务或无法验证回执时保守为 unknown。取消保留有效 WSS、presence 与 control cursor。
- 请求沿用 `{expectedRoomEpoch}` 原严格 DTO。API 先通过 opt-in 解封/owner 校验，再标记 enterBusiness 并调用既有取消服务。协商回执在构造 Response 前投影为严格 `{protocolVersion,roomId,roomEpoch,generation,status}`，使用普通 256 KiB 上限；不包含正文、result 或 finalAuthoritative。Web 未协商回执不变。status 与 mirror.state 必须按原 generation view 映射闭合。
- 每个取消意图只发送一次 POST。该操作的 accepted.requestId 与保留 intentId 相同；public pending/unknown 另含 `generationTarget:{roomEpoch,generationId,attempt}`，仅取消操作允许此字段。Native 私有 basis 保留完整不可变 generation 身份。重新 attach 可恢复同一目标，不能重发取消。
- HTTP 200 的 reserved/running/finalizing 不证明停止。普通 Session 成功、404、权限消失、epoch 换代和目标替换也不证明原目标已结束。此时继续锁定原意图，显示等待核对或原目标已不可核对；断开/reload 不解除 Native 防重发。
- 只有匹配完整原身份的终态证据可收敛。HTTP、Session、WSS 的终态批次精确 ACK 可附 `generationCancel:{intentId,current}`；ACK 当时复核仍成立且 current=true 才解除意图。字段不是正文完整性证明，旧 ACK 不能清新意图。同 tuple 的完整身份冲突在 Native 转发前拒绝。
- 存在取消 pending 时，generationRead 仅允许原匹配目标。完整原件的最终精确 ACK 同时返回 generationRead 与适用的 generationCancel 确认；Renderer 待 digest/DTO、末片许可及本机身份全部通过后才应用。非终态 GET、部分片段、取消本机 reader、错误或重复 ACK 均不收敛。终态见证不被晚到 running/unknown 回包降级或复活。

“原生成已结束”不证明由该停止请求造成，也不等于战报已完成。本节不单独开放启动，启动后继见 §13；合成取消验收采用单独显式模式，原只读验收继续要求零取消/启动/模型派发。Windows/Tauri、系统凭据与生产 TLS 门禁保持独立。


## 13. 房主以系统默认开始生成

在既有 fixed primary Room 通路增加 `generationStart`：只有当前在线、完整快照中的 active host 可明确确认开始；不增加成员发起、历史读取、自动重发或任意 endpoint。Web/Desktop 共用受控确认按钮与待处理提案警告。未处理提案不会随开始自动接受。

- 在线且 active 的房主可编辑当前本机草稿的角色、主辅情景和素材，再显式比较并发布到房间；成员、离线、操作结果未知、配置/提案跟踪中或活动生成期间保持冻结。普通模型选择和单人生成继续锁定。异步导入或选择落地前复核原 Document、账号/credential epoch、room/epoch/self 与权威快照，不能将旧身份结果写入新草稿。
- 开始生成的确认冻结当前草稿，异步摘要后复核原 Document、账号/credential epoch、room/epoch/self、权威快照和草稿身份。只接受与房间已落定配置一致、完整 key/kind/contentVersion/digest 对应的本地正文，不从隐藏的 room-only 工作副本或新草稿补材料。不同则先明确比较/发布，再重新确认开始。
- 固定服务器系统默认：Desktop opt-in 禁止 `customProvider`、系统/预设覆盖、Key、URL；`isDowngrade` 和 `arenaFreeRankingEnabled` 只允许缺省或 false。普通 AI 偏好不落盘改变；固定目录 BYOK 按第 14 节独立扩展，系统路径保持不变。
- start 原始业务 DTO 上限为 12 MiB，完整 HTTP 封套额外预留 1 KiB，完整 Tauri 参数额外预留 3 KiB；按实际 UTF-8 和 JSON 转义计量，不只量正文。其余小请求预算不变。Renderer 在来源冻结前占用整个 Document 共享的大请求单槽，直到实际 invoke settle 才释放，卸载/换 Room owner 不能增加槽数。草稿冻结、规范化、schema 校验与序列化有瞬时副本，不能把单个常驻请求误称为全链路零复制。
- Desktop start 的完整本机冻结来源另有独立 12 MiB compact JSON UTF-8 / 100,000 节点预算，包含当前草稿中尚未发送的缓存。在 `structuredClone`、摘要和完整来源预览前，逐字符/节点有界计量，不创建整份 JSON/UTF-8 副本。超限明确提示并保留普通草稿，不截断、不收紧 Web；合法来源的 pretty 预览还受深度和节点上限约束。最终 start DTO 再独立守 100,000 节点，Native 重核；每个 SafeJsonValue 仍最多 10,000 节点。容器与每个标量均计一个节点，键不计节点但计字节；节点超限稳定报告材料过于复杂。Native 接收前的 Tauri 初始反序列化由框架执行，此门不构成全进程 RSS 硬界。
- Native 只保一个原 HTTP wire 与小 start basis；物理 HTTP permit 未结束时不得另起发送副本。每次发送重核原账号 raw/epoch、Document、房主和房间代次，禁止重建请求或补入当前草稿。小 `retry-generation-start` 仅携原 intentId；无自动重试。
- Hono 在进入 start service 前调用 `enterBusiness`，只有此前明确拒绝为 not-applied。Desktop 成功必须为 202，服务返回的完整 view 在序列化前投影成闭合小 receipt；Web 原完整响应保留。receipt 不安装 authority、presence 或控制游标，开始/读取不拆 WSS。
- 202 reserved 或匹配的 starting 镜像仅证明已占位，仍保原 pending/wire。当前 generation GET 的精确 not-found 可启用显式原 ID 重试；unavailable、空 Session、换代或不同任务不能证明未执行。同 ID 重试可能补执行，必须与只读核对分开确认。匹配原 request/完整 identity 的 running/terminal 权威批次经精确 ACK 后才结清；未知重试的业务前拒绝不得抹去原 unknown。
- 尚未确认启动且仍保原 pending 的匹配占位可按第 15 节明确放弃原重试并尝试一次停止；不能把它当作普通停止或保证未执行。用户也可明确停止本机跟踪：销毁 wire、旧 AccountAccess 与重试许可，把事实移到一个不含凭据/正文的小 tombstone，再返回大厅。Document/credential 不可逆退休同样转为小记录；不释放仍在途的 HTTP 或框架债务。原 owner+room 新 start 受防重围栏，账号/room epoch 变化不能绕过；新账号不收到旧账号元数据。
- start 准入预留唯一 tombstone 槽，满槽只禁止新 start，大厅/只读/创建加入/退出关闭仍可用。已在其它房间时，核对旧记录须先明确断开，不能悄悄丢成员草稿。只有原 request/完整 identity 的 running/terminal 或原房精确 closed 回执的当前权威 ACK 可清记录；旧 ACK 不清新意图，不退还他方预算。关闭房间不等于取消服务器模型。
- 本机记录不跨应用进程持久化；关闭应用不证明原请求未执行，也不是建议的防重恢复手段。优先只读核对或明确停止跟踪后处置原房间。

合成 start 使用独立 `self-check-start` / `launch-start`，复用真实 Room service/materializer/publisher，仅模型 port 为有界合成实现；原只读/取消模式仍各自要求零 start，所有模式均零实际 model dispatch。Windows/Tauri、系统凭据、生产 TLS 与真实模型验收保持独立。


## 14. 房主固定目录 BYOK

房间自有易失选择默认 system，明确选择目录供应商、模型与覆盖参数后，仍只由项目生成服务执行。复用 Web/Desktop 的供应商、模型、手填 ID 和高级参数控件，不写普通 AI overlay，不保存 Key 草稿，不开放 custom Profile 或任意 endpoint。手填模型沿既有 Hosted 规则与共源别名，不借 Direct 支持列表收紧。成员无 start。

- Renderer 的 `presetConfig` 仅位于 `generation-start` action 中、与原业务 `request` 同级；只含目录身份与参数。原 request 仍拒绝 `customProvider`、Key、secretRef、URL/header。API 专用 wire schema 只允许 Native 重建的 `{providerId, modelId, apiKey, generationOverrides?}`，仍经正常账号、房主、catalog/model 与业务资格检查，不接受客户端自称可信。
- 只使用已保存 Key。状态未知、缺失、读取失败、保存中或所选供应商有未保存 Key 草稿时阻止新确认；页面不调用普通生成前的隐式保存流程。确认同时绑定原来源、房间权威与 funding 身份/本页凭据意图版本；异步准备期间变化即不发送。未知请求只显示原冻结的非秘密选择，retry 仍只有原 intentId。
- Native 复用真实 `hosted_preset`/目录/SecretStore；先独立校验选项并派生固定 ref，核准原 host scope 后才读取 Key。读取的 raw UTF-8 先限 8 KiB，再 trim 判非空。系统路径、只读、取消等不读取 provider Key。Key 仅进入原私有 outbound wire 和不序列化的原值 guard，不进入 renderer、Room snapshot、语义摘要、回执、日志或导出。
- 注入后的完整业务 DTO 仍限 12 MiB/100,000 节点，Key 的 JSON 转义也计入，不使用封套余量。原来源/原 DTO/每自由值上限不变。Native 保唯一 wire Arc、一个原 Key guard及至多一个实际 HTTP body 副本；重核时短暂读取一个当前值。超大存储值在继续复制前拒绝，不能声称 OS 原读取或 Tauri 反序列化已受完整 RSS 硬界。
- 每次实际派发复核原账号 credential epoch/Document/room/host及原 Key。Key 被观察为不同、缺失、空或超限时撤销 wire/guard并保留原防重身份，换回旧值不恢复许可；临时 provider-store IO 只阻本次发送并保原件，账号存储失败沿原退休规则。停止跟踪/退休不退在途 HTTP 债。释放可达材料不等于物理内存零化；现 store 不提供写入世代，不能识别未观察到的 A→B→A 历史或保证 Key 写入与 HTTP 派发原子。
- 为完整保留未知请求的非秘密选择与合法长房间身份，携 generationStart pending（系统/BYOK）或 start fence 的 attach，以及 start-tracking-ended 回执使用独立 8 KiB 上限；其余小回执仍为 1 KiB，pull/通知/框架债不扩大。Native 先按完整序列化字节计量，TS 同限，超限不截断。
- 沿当前 v1 做窄 additive consumer 扩展。旧 API 会在业务进入前拒绝 BYOK，不自动回退系统或 Web；新 API 继续接受原 system 请求。合成验收使用真实 Room service/materializer/publisher/canonicalizer，仅底层 producer 和 SecretStore 为合成；Windows/Tauri/真实凭据及生产模型门继续独立。

## 15. 未启动占位转一次停止请求

状态：消费者已接通原意图交接、一次停止与只读/退出恢复。服务端[未启动取消与执行准入](./2026-08-28_190500_Arena多人GMR-09权威生成发布设计.md#41-未启动任务取消与执行准入)已实现且默认关闭，本节规定其 Desktop 消费者，不启用生产开关；Windows/Tauri 实机验收仍独立。

### 准入与不可逆交接

- 仅承接同一真实 Document、原账号 raw/credential epoch 下的 `generationStart` 待核对意图，且已获得与原 request 和完整不可变身份匹配的 `starting` 镜像。无镜像、旧 tombstone、新 Document 或已换账号时只读核对/结束本机跟踪，不猜 generationId，也不拼回原材料。已经运行并结清 start 的任务继续使用第 12 节。
- 确认冻结原 intentId、room/epoch/self 与 generation/attempt，复用双端停止确认控件，明确告知：会不可恢复地销毁原 start 材料及重试许可；只尝试一次服务器停止；服务不支持或回执未知时仍需核对，可以结束本机跟踪，不能恢复原 ID 的 start 重试。取消对话框只关闭确认，不产生业务动作。
- Native 必须取得原单一物理 HTTP permit；原 start 请求真正 settle 前不交接、不抢发 cancel。先验证完整小请求/回执预算，再在同一临界区复核原 intent、账号、Document、在线 active host、房间及完整镜像，销毁 wire、Key guard 与 retry 许可，建立取消模式及同一逻辑槽的防重记录。准入失败且尚未交接时保留原 start；交接后任何失败都不恢复原 wire 或重试许可。
- 新 IPC 只携原 intentId，不接受 renderer 提供的正文、Key、endpoint 或替代 generation；Native 从原受检 basis 建立精确目标。旧重试、旧 start 结果与交接竞争必须有单一线性化点，不能生成两个发送意图。请求不读取 Provider Key；原物理任务持有的 body 副本直到其真正 settle 才释放，不宣称内存零化。
- 交接时仅分配一次新的 cancel intentId，`accepted.requestId` 使用该 ID，私有链接原 start intentId、原服务器 `generationRequestId` 与完整目标；不新建 generation。仍只有一个 pending 和唯一关联 tombstone 槽。旧 start 意图不再授予业务结清或重试许可，旧批次仍可按原精确 ACK 消自身债；新 ID 不替代模式、owner、精确 batch/sequence 检查，终态 ACK 按新 cancel ID 与私有链接原子结清对应记录。

### 窄协议与旧服务兼容

- 复用原 `generationCancel` URL。仅此动作的严格 `desktopRoom` metadata 增加 `cancelMode: "starting-v1"`，原未标记 Web/普通 Desktop cancel 不变；旧 schema 必须在业务前拒绝新字段，不能仅依赖可能被忽略的 header，也不能回退 legacy POST。
- 新标记的 request 保留 `expectedRoomEpoch`，增加严格 `expectedGeneration`：沿现有不可变比较的八个字段 `generationRequestId`、`generationId`、`attempt`、`configRevision`、`snapshotDigest`、`collaborativeInfluence`、`participantUserIds`、可选 `hostAccountUserId`。保留字段缺省与数组顺序，不加入可变化的 state/时间或私有 gate/token/digest。该身份进入原业务正文预算，不借封套余量容纳。
- 严格封套、owner 与正文校验拒绝仍在业务前；服务端进入 membership recovery 或 generation read/reconcile 前即调用 `enterBusiness`，这些路径可能写恢复 checkpoint，不能称为零写探测。进入服务后先核当前认证 host、原 room/epoch、完整目标身份及目标 record 的 gate-v1，再执行取消 CAS。目标已成为匹配终态时只返回/核对该终态；非终态无 gate 明确不可用且保守 unknown，不能降级普通 cancel。随后沿现有 Room CAS、实时 Redis admission 与 D1 finalization 裁决，不能由客户端声明赋予权限。身份检查不是另一个可绕过原子准入的授权快照。
- `ARENA_ROOM_STARTING_CANCEL_ENABLED=false` 不能代替逐 intent 判断：v2 不获得该能力，已有 v3 关开关后仍保留取消和恢复。旧 writer 全量升级及兼容回滚条件沿服务端规格；本片不安排启用、迁移或维护窗口。
- 不新增 capability probe 或公开 authority 版本。当前 generation GET 在 core 尚未建立时可返回 not-found，不能拿它探测支持度。旧协议拒绝只说明本次取消未获接受，不证明原 start 没有执行；原 start 许可仍不复活。若以后要求“不支持时保留原重试机会”，须另立无副作用协商合同。

### 结果核对、退出与资源账本

- 一次 POST 后只沿现有 Session、当前 generation GET 与 WSS 核对，不自动重发 cancel/start。GET 可以收敛服务端已持久取消围栏，不能新建另一个取消意图。200 reserved/running/finalizing、404、空 Session、失权、目标替换与 epoch 变化均不证明已停止；业务前的严格拒绝也不能抹去原 start 的未知事实。
- 取消模式与普通 start 模式明确区分；不能只修改 operation 而原样保留可被 start witness 接纳的 basis。原 start ACK 永远不清取消模式；matching running 也不清其防重记录。HTTP、Session、WSS 和战报末片 ACK 共用完整原身份与模式检查，匹配终态的精确 ACK 在同一临界区结清 pending 及其关联记录，保留终态单调性。小取消回执不替代完整正文的 digest/DTO/末片许可与 Renderer 身份验证。
- 取消未知或服务不支持时提供明确“停止本机跟踪并返回大厅”。先废止旧回调，再丢取消 pending 的账号访问权；复用唯一 tombstone，只保无秘密的原 owner/room/request、完整 generation 身份和取消模式，不增加无限账本。Document、凭据或账号不可逆退休沿同一转换，不能沿普通 cancel 分支直接丢弃围栏。只读、创建加入、退出关闭、换房和非多人功能保持可用；唯一槽饱和只限制新 start，新账号不显示旧 owner 元数据。
- 取消模式记录只能由原目标 terminal 或原房精确 closed 的当前权威 ACK 结清；running 不能解除，closed 不冒称 cancelled。回到原账号仅可重新授权只读核对，不恢复旧发送权；旧 Document、旧账号或旧批次 ACK 不能结清后来的意图或退还他方额度。本片不从旧 tombstone 发起新的取消；同 owner/room/request 的普通停止入口同样受该围栏限制，不能换 epoch 绕过。
- 完整 generation 身份仅保 Native 私有 basis/tombstone，并在发送时计入 64 KiB 业务正文；公共投影沿原小 target/fence，只增加固定模式与关联 ID。沿第 5 节原 HTTP 响应、通知/pull/ACK 和框架债预算，HTTP 封套仍限 65 KiB；不扩大大请求或正文读取上限。现有专属 8 KiB 明确覆盖此派生取消 pending/fence 的 attach 与结束跟踪回执，进入不可逆交接前验证其完整投影可送达，不能退出时才发现超限；不截断。取消保持有效 WSS；退出不假释放在途 HTTP、invoke 或已交付通知/批次，真实 settle/精确 ACK 只释放自身资源。
- 文案分别表达“原任务已终态”“已结束本机跟踪”“原房间已关闭”，不能互相代替，也不承诺撤回已经开始的预检或费用归零。本机记录不跨应用进程持久化，不把重启应用当防重恢复手段。

### 最小完整交付与验收

先闭合严格封套/服务端 gate 重核，再接 Native 单意图交接、明确模式与统一 ACK，最后接原共享确认控件、Desktop 核对/退出旅程及现有合成 mock。可分内部原子片审查，但没有实际消费者与退出旅程前不宣称产品交付；不扩成员发起、历史、任意 endpoint 或通用 IPC。

最低反例覆盖：无/错镜像、旧账号/Document/epoch、失权；真实 HTTP 未 settle、retry/交接竞争及旧 start ACK 晚到；旧 API 严格拒绝、v2 无 gate、flag-off 已有 v3；取消回执丢失、D1 pending、running/terminal 抢先；未知后结束跟踪、Document/凭据退休、换房、账号隔离、满槽及 terminal/closed ACK；最大合法转义 ID 的 attach/退出与末片 ACK 同时结清两种记录且不退款。复用真实 service/materializer/publisher 与 Native 模块，底层 producer/SecretStore 合成，证明一次取消、交接后零 start 重发及零真实模型。原只读模式继续零 start/cancel，普通 running cancel/system/BYOK 回归独立保留。Windows/Tauri/TLS/视觉与生产启用仍另验，不阻塞本地实现与合成验证。
