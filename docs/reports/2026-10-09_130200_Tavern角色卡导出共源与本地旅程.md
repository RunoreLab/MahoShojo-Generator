## 本片完成面

在同一个 `/tavern` 工具页增加 Desktop 站内角色卡导出：本地角色 JSON / 卡库 → Web 既有字段规则映射 → 编辑 → 可选 PNG 底图、默认世界书与本地情景 → Tavern V3 JSON / PNG → 用共享入口重新读取。完整源 JSON 有独立另存出口。

Web 保留原 `TavernExportPanel`，实际改用共享字段控件、纯映射和组装；没有增加平行的第二个 Web 工具入口。Web 的在线来源验证、档案馆、随机选择、AI 补全和立绘仍由原宿主承担；Desktop 不因共享字段而获得这些能力。来源验证等会联网，Web 页面说明已更正，不能泛称只有 AI 才联网。

## 共源边界

- `domain/tavern-card/export.ts` 从原 Web 实现抽取字段默认值、角色映射、creator、tags、情景组合、世界书与扩展组装；时间与已核验来源资料均由宿主显式传入。纯核不读取身份、网络、文件或系统时钟
- `ui-web/tavern/export-fields.tsx` 抽取原 Web name/description/personality/scenario、对话、作者、高级字段与 PNG chunk 选项的实际 JSX。Web 与 Desktop 都使用这些控件，而非两套相似表单
- `TavernLocalExportPanel` 接受 `CardRepository`、文件导出和默认底图端口；同一来源选择器支持保留原件或普通角色两种过滤，沿用分页、墓碑检查、不可读记录提示
- JSON/PNG 文件预检共用 `readTavernSourceJson` / `readTavernBasePng`；默认 Logo 的 DOM 栅格化从 Web 抽到 `renderTavernDefaultBase(loadLogoSvg)`。具体宿主只加载固定打包的 `/logo.svg`，不接受用户指定远程地址。Web 服务端也消费 Tavern 纯编解码出口，因此 Logo helper 通过独立 `tavern-default-base` 显式出口导入，避免服务端依赖整个 React 控件 barrel。原 viewBox 匹配中的双重转义同时修正并有回归
- Desktop 使用既有 IPC 卡库、WebView2 下载、窗口离开保护与页脚导航端口。没有新 IPC、数据库迁移、网络权限、秘密或付费模型调用

## 数据损耗、原件与信任

1. 新 Tavern 卡是字段投影，不承诺保留所有站内字段、未知扩展或媒体。未映射源数据不自动变成 Tavern 标准字段；完整源另存保留整个已解析对象，包括未知字段及签名声明，但不是文件空白/排版的字节复制
2. `ms_export.sourceDataJson` 是可关闭的诊断快照，既有上限为 24,000 字符。截断时显式提示且标记 `sourceDataTruncated`，不能用于完整恢复。主 description 不因快照上限而裁剪
3. 既有情景提取上限为 24,000 字符，世界书每条目 6,000 字符；上游片段和世界书截断警告会展示。没有情景提取截断时，世界书预算不改变独立 scenario 正文。它们都是可见的格式映射限制，不称完整迁移
4. V3 同时包含 data 与旧版兼容顶层字段，正文可能重复。最终序列化产物重新执行 SafeJson 与 4 MiB UTF-8 门禁，超限明确拒绝，不静默截正文。此时完整源 JSON 仍可另存；它不受投影体积或 24k 快照预算影响
5. Desktop 只注入 `{ source: 'local' }`，`signature`、`_isNative`、排名及源 ID 不提升为已验证 metadata。输出 `isNative` 为 null；原始声明只作为源数据保留。Web 已有核验由原 host 完成，不随纯核迁移
6. PNG 默认覆盖已有 ccv3/chara，保留底图其他块；关闭覆盖可能留下冲突候选，沿用 UI 的明确提醒。至少需一个角色 chunk；两项全关会阻止“PNG 角色卡”导出。PNG 有 32 MiB 写出上限，写出后对保留的其他压缩文本加新角色块复核累计解压文本预算；不能只因底图本身合格便宣称最终产物可读。超限报错，不静默删无关块；不声称完整图像解码或 CRC 验证
7. 下载反馈只是发起下载，真实目标目录与保存成功由系统界面确认。下载失败不清空输入，可重试

## 同步补齐的真实边界

- 自定义底图中保留的压缩 Comment 与新角色块叠加可能超过读入预算；共同 writer 在最终输出复用既有预算校验，运行时小压缩 fixture 覆盖双块拒绝、单块可读与原底图不变

- 最大合法 Base64 的分组正则曾在约 5.59 MB 编码串上栈溢出；已先以独立修复改成线性校验，保留非法 Unicode/padding/尾部拒绝。测试在运行时构造完整 4 MiB JSON 和双块 PNG，不提交大 fixture
- `talkativeness=0` 原来被 `Number(value) || 0.5` 错改成 0.5；共享组装保留合法 0/1，非有限数回落默认值
- Web 文件/随机来源、云 metadata、AI、立绘和底图均有来源/请求代次；旧请求不能覆盖新来源或编辑，旧 finally 不关闭新请求状态。对正在显示的 B 开始生成，会取消尚未应用的 A 来源读取
- Desktop 文件/库读取遵守共同选择意图，字段编辑和导出使早期未应用来源失效；底图和情景为独立意图，互不取消。情景读取期间单飞且有提示；卸载后不触发迟到下载
- 双端 tab 从“切换即卸载丢草稿”改为“首次访问才挂载，之后 hidden 保留本页草稿”。这是明确的共性 UX 修复，不是无行为变化的移动；不新增持久存储。每实例独立 ARIA ID、左右方向键和 Home/End、hidden 面板不进入键盘焦点顺序。Web AI/导出和 Desktop I/O 在途禁切，避免隐藏进行中的任务

## 验证与剩余项

自动证据覆盖：纯映射对拍、0/1/非有限数、未知字段/签名声明、快照关闭与截断、世界书限制、最终临界 JSON → PNG → 共享读取、完整源另存、源/AI/底图延迟 Promise、下载失败重试、tab 懒挂载与草稿保留、实际宿主固定资源和下载字节。

已通过单 worker targeted：domain 58 例、共享 UI 26 例、Desktop host 5 例与导航 12 例；Web Tavern 核心/组件 44 例，另一次生命周期/真实生成 39 例（与前组有 21 例重叠，不重复累计）。domain / ui-web / Desktop build-types / Web build-types、workspace boundary、内容源校验通过；Desktop Vite 生产构建、Web Next webpack 生产构建与 Hosted DR client bundle safety 检查通过。Desktop 全测试树 typecheck 仍有本片外既有测试类型错误，宿主新增测试的独立 typecheck 通过，生产 build-types 通过。本片不以 Linux jsdom/构建替代 Windows Tauri/WebView2 文件选择、真实下载目录、重启读回、键盘与高 DPI 视觉验收。前片运行环境 Chromium socket 权限限制仍在；本轮没有再消耗资源重复尝试，也没有伪造浏览器或 Windows 通过证据。

尚未迁移到 Desktop：Tavern AI 深度转换/补全、云保存与云来源验证、立绘、其他导入目标模板与占位符替换设置，以及茶会会话仓储。它们继续归原 D5.1 计划逐片验收；本报告不扩大为全站 Tavern 迁移完成。
