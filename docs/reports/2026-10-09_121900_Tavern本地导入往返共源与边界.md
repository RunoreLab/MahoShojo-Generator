日期：2026-10-09

## 本片范围

完整本地旅程是：PNG / Tavern JSON → 候选选择与预览 → 通用角色规则映射 → 本地库另存 → 读取保留的酒馆原件 → JSON / PNG 导出。

这不是全部 Tavern 功能迁移。普通站内卡生成新的 Tavern V3 卡（现有 Web `TavernExportPanel`）、其他目标模板、占位符替换设置、AI 深度转换、云保存、立绘与茶会会话迁移尚未接入 Desktop。本片 Desktop 保留原始占位符，不执行 Tavern 脚本或系统指令。Windows 集中验收独立跟踪，不阻塞下一已冻结开发片。

## 共源与宿主

| 区段 | 实现与实际消费者 | 宿主边界 |
| --- | --- | --- |
| 纯编解码、候选、规范化、V3、推荐、情景与世界书 | `domain/tavern-card`；Web 原 `lib/tavern-card` 出口直接回用 | `File` wrapper 与 Web Logo 的 fetch/canvas 栅格化留宿主，不搬 cloud/AI |
| 标题、品牌、文件输入、候选选择、卡片预览 | 从 Web 真实组件和原 `TavernImportPanel` 抽出 `ui-web/tavern`；原 Web 导入路径与 Desktop 同时使用 | 既有 CSS 与 `content/sync-manifest.json` 品牌资产同步到双端 |
| 原件导出、本地来源、通用卡本地保存 | 两端原有导入路径共用区段、来源代次和受控保存反馈 | Web IndexedDB / Desktop `IpcLocalCardRepository`；不请求云端 |
| 原始 JSON → 通用正文 | `buildGeneralMarkdown` 为 Web 原映射；Desktop `convertTavernToGeneralCard` 构造未签名投影 | Web 原模板、AI、占位符、keepRaw 选项保留，不改变已有选项含义 |
| 文件导出 | 共享组件只投递 bytes/name/MIME | Web Blob 下载；Desktop 既有 WebView2 下载能力与 60 秒 URL 生命周期，无新 native 文件/网络权限 |
| 本地记录 | `local-library/imported-unsigned-card`，既有 `CardRepository.putIfAbsent` | existing-wins、保留墓碑，成功写入或确认已有活动记录后才报成功 |

Desktop 注册真实 `/tavern` 路由与导航能力。页脚注入 hash 路由、受控外链和品牌来源，保存期间沿用窗口关闭/离开保护。

Web 没有另加第二个 Tavern 工具入口：在现有导入区增加 JSON / 本地原件读取及原件导出；本地另存消费现有“规则映射 → 通用角色”的实际结果。Web 原 AI、其他模板、云保存、导出 tab 与设置仍在原路径，原生成结果定位回归已覆盖。

## 保真、损耗与信任

- 原始 Tavern JSON 与规范化显示分开。导出所选候选保留未知字段、扩展、世界书和嵌套签名字段；非法 JSON、危险键、过深结构或超限输入明确拒绝，不静默删字段
- JSON 往返是数据语义保真，不保留原始空白、转义拼写和键布局等文件字节形式
- PNG 导出保留原图片数据与非替换文本块，**重写 ccv3/chara 两个块为所选候选**，不能称 PNG 原始字节无损；冲突候选不会在重写后继续并存。JSON 不携带底图，没有 PNG 底图时用既有占位图
- 通用正文只映射描述、性格、场景、开场白、对话样例与标签。世界书、脚本、system prompt 等在 `_tavern.raw` 保存，不假装转成通用卡功能
- Desktop 通用卡始终保留原件；Web 本地保存遵循用户的 keepRaw 选择，关闭时清楚提示缺失未映射字段。修改通用卡正文不会自动合并回原件
- 只有确认为通用角色投影时才展开 `_tavern.raw`；真正 Tavern 卡的同名扩展完整保留，不被误当包装层
- 通用投影与新本地记录均为 `unsigned / imported`。原件内签名只是原始数据，不验证、不继承到新正文、不提升为官方来源
- 下载只报告“已发起下载，请在系统下载界面确认保存”，不把浏览器 dispatch 当成真实落盘确认

## 不可信输入与生命周期

- JSON / 通用卡往返上限 4 MiB：复用既有 1 MiB 数据卡单位的 4 倍，与现有 Desktop 单记录规模一致，但不把云配额施加到本地；实际记录序列化后的宿主限制仍可能更小，失败保留原件
- PNG 文件上限 32 MiB，为元数据之外的图片留出空间。文件读取前按类型检查 size，纯核再次检查实际 bytes
- PNG 文本聚合预算是 `2 × ceil(4 MiB / 3) × 4 + 1024`，按 ccv3/chara 双份 Base64 与少量块封装推导；不另加任意固定文本块数上限，避免合法 JSON 导出后自身无法读取
- zTXt/iTXt 使用每 1 KiB 压缩输入递进的 Unzlib，回调检查解压预算，超限即抛出、停止后续 push；累计文本预算也独立检查。PNG 写出总字节不得超过可读文件上限
- 严格拒绝非法 Base64 字符/填充，Base64 JSON 与独立 JSON 文件的 UTF-8 解码失败不替换为 U+FFFD；PNG 文本中非 UTF-8 数据保留在底图，但不作为 JSON 候选。损坏候选可跳过并选有效候选，不静默“修好原件”
- 文件与库读取共用一个来源意图代次；较早的库 A 晚于新文件 B 返回不会覆盖 B。开始 Web 转换会使尚未完成的旧来源读取失效
- 本地列表只在用户点击时读取，按页查找含原件的记录；收到 unreadable 信息时展示可读子集并提示坏记录，不伪装成空库、不修复或删除源数据
- 本地写入与导出单飞；切换候选后旧结果反馈不认领新候选。写入失败、墓碑、损坏文件、取消文件选择可恢复；转换/导入不会隐式上传

- 既有 Web Tavern 编解码、世界书、推荐、AI attachment、云 payload 回归及新共源身份/未知字段保真测试
- 新 domain 本地 JSON/PNG/通用投影往返、双块大 JSON、坏 Base64/UTF-8、压缩膨胀、截断/超限/危险键、同名扩展用例
- 新 local-library 保存/去重/墓碑/写入失败与嵌套签名不提权用例
- 新共享 UI 重选同文件、候选禁用、原件下载、保存单飞/旧反馈、前置 file.size、库来源代次/坏记录提示用例
- Desktop 下载 URL 生命周期、保存读回与导航能力测试；Web 现有卡片生成/停止/流式结果定位测试

本片 domain / local-library / ui-web / Desktop typecheck、Web build-types、Desktop Vite 生产构建、Web Next webpack 生产构建与 Hosted DR client bundle 检查通过；workspace boundary 与内容源校验通过。集成更新基线后仍需对最终树重跑相关门禁。

本环境尝试启动临时 Chromium 做完整页面截图，被运行环境的 socket 权限限制阻止；一次受支持的提权重试仍未能启动，因此不提供伪造截图或宣称真实浏览器旅程通过。真实 Windows 文件选择/下载目录/重启后 SQLite 读回、系统取消、键盘/高 DPI 与视觉仍 PENDING；jsdom/headless/构建不替代这些证据。

回滚可撤下 Desktop `/tavern` 装配与新 Web 区段，不删除本地记录；`_tavern.raw` 为既有附加字段，旧通用卡消费者可保留它。没有数据库迁移、发布凭据或生产部署。
