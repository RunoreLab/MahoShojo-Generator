## 角色库分页

`CardLibraryModal` 原先以 `allowedTypes` 数组引用作为依赖。桌面端加入角色后父组件重新渲染，内容相同的新数组导致查询回调变化，进而重置页码。

现按有效类型集合内容生成稳定依赖，重复项、类型排列和无效项不触发无意义的重查。真实类型、搜索、排序、来源切换仍重置查询。公开、我的、收藏、本地四种来源均覆盖连续选择两张卡仍保留当前页的回归。

同时补齐本地库超过 12 条时缺失的分页控件，以及删除最后一页唯一条目后退回有效末页。该修复由双端共用，无宿主侧特殊规避。

## 叙事历史操作

桌面 `/battle` 与 `/arena` 现在都提供“查看 / 编辑活动叙事历史”，由同一个宿主控制器装配 Web 已在使用的 `NarrativeHistoryEditor`。导入、导出、追加/覆盖确认、编辑、排序、重排和另存本地库继续共用生产编辑器。

“引用本地叙事历史”弹窗增加“导入 JSON 并保存到本机”：

1. 在网页叙事历史编辑器点击“导出 JSON”。
2. 在桌面历史选择弹窗选择该文件。
3. 仓储确认保存后刷新列表，勾选需要的条目即可引用；关闭重开仍可读取。

此入口仅接受正式 `narrative-history` V1 文件，明确区分完整会话备份与未完成草稿。完整 payload（包括扩展字段、原条目 ID）保存为独立未签名导入卡；引用读取使用临时复合 ID，原件不变。digest 与 `putIfAbsent` 保证同内容幂等、已有记录优先；回收站记录需用户显式恢复，不自动复活。

导入不覆盖当前活动历史，也不自动上传云端。沿用现有 Arena 文件输入和 Native 单卡 4 MiB 容量边界，超限明确报错且不截断。需要编辑或兼容其他导入形状时，使用活动历史编辑器；编辑结果另存仍需显式操作。

文件读取/保存期间阻止重复提交、关闭与生成，纳入宿主原有离开保护。作用域变化会阻止旧读取写入，已开始写入的晚到结果不更新新作用域。AI 目标变化保留编辑器内尚未提交的文本，不误当作应清空编辑稿的身份变化。两页活动历史混合手写、导入、生成内容，完整历史卡不继承最后一次生成的单一执行来源。

## Direct 结束原因

现有 Native HTTP 客户端未设置应用层生成硬超时；本机交付确认计时在 Native 完成后才开始。用户报告的泛化文案来自 `finishReason !== 'stop'`，不能据此判定应用主动超时，更不能推断用户那次请求的具体上游原因。

现区分：

| 原因 | 用户反馈 |
| --- | --- |
| `length` | 达到输出 Token 上限，提示检查参数或缩小范围 |
| `content-filter` | 供应商内容过滤中止 |
| `tool-calls` | 当前战报流程无法执行模型返回的工具调用 |
| `other` | 未提供可确认的正常结束原因 |
| 缺少合法终态 | 连接结束但无法验证完整性，提示检查网络/接口 |

保留原文、不完整输出失败语义及原有恢复边界，不自动重试付费请求。复制错误摘要只增加白名单结束原因、终态状态、正文长度，不含 API Key、自由文本异常、模型输入、账号或正文。旧诊断与旧草稿仍可读取。
