# 问卷编辑器共源与本地另存边界

日期：2026-10-09  
范围：D5.1-T 的问卷定义本地工具纵切；不包含工坊、茶会、AI 或在线治理迁移。

依据：[唯一 Desktop 计划](../plans/2026-09-30_160100_Desktop客户端阶段实施计划.md)、[DESK-PARITY-006](../specs/2026-10-06_084200_双端产品对齐与设置共源规格.md)、[共源切片指南](../runbooks/2026-10-06_084500_双端共源切片模板与验收指南.md)。

## 共源与宿主边界

- `@mahoshojo/domain/questionnaire-editor` 承载原 Web 可编辑题目与 JSON 的双向映射；运行时问卷定义/流程继续使用既有 `questionnaire-definition`，不把运行时归一化输出冒充原件。
- `@mahoshojo/ui-web/questionnaire-editor` 承载原 Web 问卷信息、题目/选项/灵感、条件显示/跳题、引用、排序/插入/折叠区及有界文件读取。Web 实际使用该映射和共享区，不保留另一套题目编辑实现。
- Desktop `/questionnaire-editor` 接本地 JSON 文件/粘贴、按 `questionnaire` 类型分页的既有本地卡库、编辑、另存与下载；本地源由选取时重新读取，墓碑/类型变化/不可读不伪装成功。
- Desktop 保存调用既有 `saveCardDraft`，`original: null`、`cardType: questionnaire`、`insert-if-absent`；原卡不覆盖、不隐式复活墓碑，新记录的 authoritative provenance 为 `unsigned/imported`。相同内容活动记录报告已存在，不伪称新写。
- Web 认证、云库、旧卡修复、回收站、替换和敏感词检查继续由原 Web 宿主处理。没有新增 native command、数据库迁移、Provider、网络来源或签名能力。

## 保真、规范化与不可信声明

原 Web 导入重建已知字段，会丢弃顶层/题目/选项扩展；简单条件还会丢失跨问卷限定，数组值经 `|` 编解码可能改变含竖线值。此片修复为：

1. 合法的未知顶层、题目、选项扩展保留；`origin`/`provenance` 等未知 payload 字段只是惰性来源数据，不被提升为记录信任信息
2. 跨问卷/字符串引用、复合条件、数组规则/数组条件值及不能无损表示的条件保留在题目高级 JSON；简易控件的空值或未勾选不表示已删除高级规则，界面明确说明
3. 用户显式启用简易规则/填写简易引用时接管对应高级字段，之后取消不会复活旧高级规则
4. 编辑结果始终 `nativeAllowed: false`，不继承顶层 `signature/isPreset/_native/_isNative/isNative`；原始来源下载保留这些未经本编辑器验证的声明
5. 既有编辑规范化仍会裁剪部分文本/选项空白、补默认题号/值、展开默认必答设置、清除不可信 Logo。界面明确区别编辑输出与独立原始来源下载，不承诺字节级编辑往返

文件采用 fatal UTF-8 解码；损坏字节拒绝而不是静默替换。UTF-8 BOM 在保存的源文本中保留，解析副本仅去掉一个 leading BOM。粘贴/文件输入先限 1 MiB；解析时和编辑产物使用既有 SafeJson 深度/节点/危险键门禁；实际 pretty JSON 下载也受 1 MiB 限制。库载入以紧凑 JSON 传给输入解析，不因预先格式化空白膨胀而拒绝合法已存记录。过预算或高级 JSON 错误时保存/编辑导出禁用，输入、旧编辑和可下载原始来源保留。

## 生命周期与 Web 行为变化

Desktop 当前页编辑/粘贴不建立新持久草稿；原始来源下载也属于当前页状态，本地另存仅保存编辑结果，源文件/原库卡仍不修改。沿用现有离开/窗口关闭守卫；导入/载入新来源前确认放弃未保存编辑；读写单飞、忙碌时禁编辑；卸载后的读取不回填。保存失败保留草稿，继续编辑会清除上一版本的成功/错误反馈。下载只表示发起下载，不能证明用户在系统对话框中保存，因此不清除未保存状态。

Web 保留原成熟布局与云操作，并实际获得扩展/规则保真、安全输入、原件下载和 import intent 栅栏：晚到文件/剪贴板/旧云来源不能覆盖较新的输入或编辑；错误云导入不关闭模态并谎报成功。问卷 logo 常量移到纯共享模块，资产继续沿用已有同步链。

- domain：31 文件 / 237 项；ui-web：64 / 600；Desktop：87 / 1170；Web：441 / 2851，全通过
- 其余 workspace 测试、全 workspace lint/build，以及 root 34 文件 / 264 项与 root lint 全通过；本次先构建再跑 root suite，无 dist 缺失跳过
- Web 生产 tsc、Next webpack、Hosted DR 客户端 bundle 检查和 Desktop 生产 tsc/Vite 均通过；D1/Admin 的构建部署命令为 `--dry-run`，没有实际部署
- 21 份已发布预设问卷均通过新映射导入及有界编辑输出检查
- 保留三条既有 Web 内部导航 lint warning、Vite 大 chunk warning 与测试宿主未实现浏览器 API 的提示；未调低门禁

验证环境使用 Node 22.23.3 与对应编译的隔离 SQLite 测试依赖。此执行环境的代理注入会触发 `UNDICI-EHPA` 实验警告，命令仅定点关闭该警告，不改仓库测试；Wrangler 配置/缓存使用自有可写 XDG 目录，不登录、不新增 token。初次默认 HOME 配置目录失败后，先独立验证 D1 `--dry-run` 通过，再重跑完整脚本。

整套验证还暴露一个既有测试稳定性问题：Web 包导入测试固定等待八次宏任务后就断言已落库，负载下可能读到写入中状态。该修复独立提交，仅改测试为等待可观察导入终态并保留全部原数据/行为断言；新增可控延迟写入回归验证不会提前完成。它不是问卷迁移造成的业务缺陷，没有改产品存储逻辑。

Windows WebView2 的真实文件对话框、中文/BOM文件、本地 SQLite 重启读回、窗口关闭/焦点与布局仍待集中实机验收；jsdom/IPC mock 不替代这些项目。Windows 待验独立于后续既定源码开发，不构成生产部署或发行授权。回滚时可撤 Desktop delivered route 与入口，保留已另存问卷及原来源数据。
