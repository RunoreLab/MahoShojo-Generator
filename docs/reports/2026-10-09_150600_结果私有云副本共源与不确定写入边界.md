- 只有 2xx + `success:true` + 非空字符串 id 确认创建成功，旧本地库 uploader 同样收紧。400/401/403/413/429 为明确拒绝；网络、超时、无法识别 2xx、5xx 为不确定，保留输入并禁止自动重发。
- 不确定结果使用既有 CardLibraryModal 同页 browseOnly“我的云端卡”页签检查（禁选择、下载、点赞、收藏、分享及编辑动作），不离开原结果；用户检查并再次确认后才允许另一次显式创建。服务器没有幂等 key，不能承诺去重。服务器可能 insert 后在 metrics/自动审查步骤出错返回 500。
- Web 保留宿主鉴权、敏感词检查和 `/arrested` 导航，既有公开参数、替换与删除能力不扩大。新建 controller 增加来源/准备/容量代次、ref single-flight、表单冻结与不确定反馈。

## 已知未闭合：Web 跨标签 cookie 优先

Web 的现有鉴权没有可冻结的服务端 session epoch。当前只承诺本页可见账号/存储凭据检查及迟到 UI 结果隔离，不能承诺跨标签账号的服务端写入 fence。

具体复现条件：本页 `authStorage` / `user` 仍为账号 A；另一个标签页把有效 BetterAuth session cookie 切为 B；新建 POST 使用 `credentials:'same-origin'`，同时附实时 B cookie 和冻结的 A Bearer。现有 `lib/auth/server.ts` 优先识别有效 cookie，因此可能在 B 账号新建。本轮没有修改通用鉴权优先级、没有静默改为 `credentials:'omit'`，也没有新增需部署的服务端协议。

后继最小闭合入口是独立审定“服务端校验预期账号”或已有 Bearer-only 安全通路。此问题明确保留为既存缺口，不因本片独审无新增阻断而消失；Desktop 的 Native 冻结 cookie 与账号 fence 不具有该浏览器 cookie 竞态。
