# 日常模式提示词优化与真实验收

状态：实现、自动验证与免费模型新旧对照验收已完成；未执行生产部署、数据库迁移或远程写操作。

依据：[叙事提示词与设定忠实性规格](../specs/2026-11-13_181100_叙事提示词与设定忠实性规格.md)（2026-11-18 修订日常模式细则）与 [竞技场百科](../../content/encyclopedia/arena.md)。

## 问题背景与根因

用户反馈官方“日常模式”在素材较少或未填写引导时容易莫名滑向战斗，需要借助第三方长情景卡才能稳定获得日常体验。对照仓库 `d6856d05` 源码核查，根因位于五处上下文与约束叠加：

1. **System 任务缺失与上下文权重倒挂**：`packages/ai-core/src/arena-generation/mode-rules.ts` 中经典、羁绊与派生战斗模式均有显式 `【当前创作任务】`，但 `SYSTEM_PROMPTS.daily` 此前直接将仅有两句的 `NARRATIVE_MODE_STYLES.daily` 拼在长篇 `NARRATIVE_FIDELITY_RULES`（密集讨论能力效果、消耗、免疫与对抗胜负）之后；且 `prompt.ts` 对所有模式共用“请按能力效果与明确例外认真演绎”导语，面对高密度武器/魔装/战斗经历角色卡时容易触发战斗惯性。
2. **缺少超自然降维、去标签与生活口语隔离**：未说明在日常互动中如何将魔法武装转化为生活习惯与小便利，未确立具体问答细节（`userAnswers`）在日常刻画中的优先级，也未约束专业或理性角色在点餐、闲聊时避免学术掉书袋、概率百分比量化与直接输出性格标签词。
3. **低输入下缺少生活小事切口与留白许可**：未提供用户零引导时的低烈度生活切口与单章留白许可，模型为凑出戏剧张力而转向遇袭、切磋或竞技场对决。
4. **`isPureBattle` 历史过滤误伤**：`packages/ai-core/src/arena-generation/prompt.ts` 原先计算 `isPureBattle = !userGuidance && !scenario && !(auxScenarios && auxScenarios.length > 0)`，未排除 `daily` 与 `scenario` 模式，导致日常模式无引导开启 `readArenaHistory` 时反而把带引导/情景标记的过往日常记录过滤殆尽，仅余纯战斗记录。
5. **格式与 Schema 的战斗措辞暗示**：分队文案固定出现“团队对抗”“各自为战”；非流式 `buildArenaStructuredReportSchema` 固定将 `headline` 与 `article.body` 描述为“新闻标题，可以使用震惊体”“战斗简报”；流式 Markdown 的 `## 胜利者` 与 `MAHOSHOJO_ARENA_META` 缺乏“日常模式默认无胜负、切勿为填此栏安排战斗”的明确提示。

同时结合社区情景卡反馈与本项目边界，本次优化明确两点原则：
- **聚焦日常重心而非抹平世界背景**：日常模式重点不是写战斗推演，但也不把世界观强制抹成无危机的乌托邦；允许保留战前逛街游玩、巡逻间隙、赛后休整等背景脉络，只在缺乏交战指向时不无故开打。
- **拒绝社区越狱词条**：不引入原情景卡中的跳过伦理审查、修改年龄界定、开启 NSFW 或“描写粗暴”等违规与风格冲突条文，严格维持 `NARRATIVE_CONTENT_POLICY`。

## 免费模型真实验收样本与方法

全部验收样本仅使用仓库公开内置预设角色卡（`M01_centaurea.json` 翠雀、`M02_white_rose.json` 白玫、`M06_sparrow.json` 麻雀、`M13_greatness_in_complexity.json` 千日红、`M16_xuemo.json` 雪沫）与合成日常上下文，不涉及生产数据库查询、账户或用户数据。API Key 仅通过忽略路径 `.tmp/api-keys/` 由脚本读取，原始提示词快照与完整模型输出保留在忽略目录 `.tmp/daily-prompt-eval-20261118/`，均不纳入仓库。

设计 8 组高压对照用例（`storyLength='standard'`、`temperature=0.7`、`max_tokens=8192`）：

1. `preset-centaurea-whiterose-zero`（流式）：翠雀 + 白玫，零引导，开启 `readArenaHistory=true` 并混入 1 条战斗胜负与 1 条带 `user_guidance` 的日常“糕点店偶遇”；验证不滑向战斗、不误删日常历史及白玫不知翠雀身份的视角边界。
2. `preset-thousandred-xuemo-zero`（流式）：千日红 + 雪沫，零引导；验证高维概念角色不凭空开战、不掉书袋、不输出百分比与物理术语点评生活。
3. `preset-prebattle-merch-hangout`（流式）：翠雀 + 白玫，携带“明晚将赴强敌硬仗”的 `current_state` 与引导“明天就要和强敌交手了，今天下午两个人去商业街逛逛周边店、游玩放松一下”；验证保留战前背景与情绪的同时把叙事重心稳在游玩逛街上。
4. `preset-rivals-centaurea-sparrow-zero`（流式）：对立角色翠雀 + 麻雀，零引导；验证不直接动手打成战报，同时保持各自立场的微妙分寸而非突兀洗白和解。
5. `preset-solo-centaurea-zero`（流式）：单人翠雀，零引导；验证单人日常切面不刷出残兽袭击，且不拆分林昀与翠雀双重身份。
6. `multi-turn-daily-continuity`（流式）：翠雀 + 白玫，携带“超市门口屋檐避雨”的 `narrativeHistory` 与物品 `current_state`，零引导；验证时间线和物品衔接及单章余韵留白。
7. `structured-daily-zero`（非流式 `structured-report`）：千日红 + 雪沫，零引导；验证 JSON 结构化路径不出现“震惊体战斗新闻”。
8. `regression-classic-battle`（流式，`mode='classic'`）：翠雀 vs 麻雀；验证经典战斗模式正常展开能力对抗而非被日常规则误伤。

### 已确认改善

1. **显著抑制无故开战与刷出袭击**：Agnes 首轮基线 14 次日常生成（含 12 次流式与 2 次结构化）中，有 8 次直接写成了残兽袭击击杀、街头/工厂对战或竞技场规则交锋（如 `preset-centaurea-whiterose-zero` 3.0-flash《高架桥下的残兽拦截战》、`preset-rivals-centaurea-sparrow-zero` 两模型《丝线之弈》《银线对羽翼》、`preset-solo-centaurea-zero` 两模型分别凭空刷出魔弹残兽与“铁砧”残兽、`preset-thousandred-xuemo-zero` 2.5-flash《星穹与浮云的对决》与结构化基线两例；另含 1 次训练场练枪与 1 次休战口吻交锋），OpenRouter `ernie` 基线在对立组同样写成了街头交战《丝线止于此夜》；相比之下，候选版跨各轮合计 30 次日常生成调用（首轮 Agnes 14 次 + 精修复测 10 次 + `ernie` 2 次 + 终版抽验 4 次）均未凭空刷出残兽袭击或展开战报式对抗，全部以具体生活小事切入并收束。
2. **修复日常历史丢弃并强化前情连续性**：基线因 `isPureBattle` 过滤丢掉了带有 `user_guidance` 的“糕点店偶遇”，候选版成功保留该线索，模型自然围绕“草莓蛋糕打折日 / 买糕点与奶茶约定”续写，并在 `multi-turn-daily-continuity` 准确承接超市屋檐雨幕、青菜鸡蛋与焦糖布丁状态。
3. **战前游玩等带背景脉络的日常不误伤**：在 `preset-prebattle-merch-hangout` 中，两代 Agnes 模型与 `baidu/ernie-5.5-flash-preview:free` 均保留了“明晚出战”的紧迫感与心理背景，同时稳妥展开商业街买手办、发圈、缎带、钥匙扣与喝热饮的互动，未提前滑入交战。
4. **结构化日常与经典战斗回归正常**：候选版 `structured-daily-zero` 两模型均从“竞技场大鹅/法则对决（`winner=千日红/平局`）”转向“商业街点单与百香果茶日常（`winner=千日红、雪沫`）”；`regression-classic-battle` 在新旧两版中均正常展开丝线、替身、飞爪与奇境战斗对抗，未出现经典战斗退化。
5. **精修收敛三重细节**：`e3a3ed91` 后，`preset-solo-centaurea-zero` 不再出现“林昀看着翠雀同框”的双重身份分裂，`## 胜利者` 与 `impacts.characterName` 精确使用 `翠雀`；`agnes-2.5-flash` 在千日红病例中的“热力学/物理定律”学术用语消失；白玫也未再直接叫破翠雀的父亲身份。

### 仍存在的客观边界与未通过项

1. **流式 Markdown 偶发省略正文 `## 胜利者` 二级标题**：即使在 `e3a3ed91` 和 `9ce3e0a8` 强化顺序要求后，`agnes-3.0-flash` 在 `preset-centaurea-whiterose-zero` 的复测与终版抽验中仍出现 2 次跳过正文里的 `## 胜利者` / `## 最终结果` 直接输出 `<!-- MAHOSHOJO_ARENA_META ... -->` 的情况。虽因末尾 `MAHOSHOJO_ARENA_META` 均完整闭合且 `report.winner` 正确，线上主要解析链仍可取回标题与参与角色，但纯依赖 Markdown 正文二级标题的回退路径在该局部输出上会读不到标题。
2. **结构化文本 JSON 仍依赖宿主容错修复**：`structured-daily-zero` 候选组中，3.0-flash 携带了 ` ```json ` 代码围栏（去围栏后可严格通过 Zod 校验），2.5-flash 在 `analysis` 字段内部嵌套了未转义直双引号导致裸 `JSON.parse` 失败（实际生产运行时会经过 `repairNormalizeValidate` 修复，但不能认为小模型在文本 JSON 模式下无需修复即可 100% 严格通过）。
3. **部分小模型的对话与场景偶发偏差**：在 `agnes-3.0-flash` 终版抽验的 `preset-centaurea-whiterose-zero` 中，翠雀对白玫提及林昀时出现了冷硬反斥，虽不等于叫破身份，但人物情绪分寸仍有小样本波动；`e3a3ed91` 复测的 `preset-rivals-centaurea-sparrow-zero`（2.5-flash）让麻雀仅作为后台观察者出现在结尾和 `impacts` 中而非正面同行。因此本报告不对未测试的长情景、Web HTML/Package 合约或其它闭源商业模型宣称普遍无误。
