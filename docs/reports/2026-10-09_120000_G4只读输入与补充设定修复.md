# G4 只读输入与补充设定修复

状态：源码修复与自动回归；本轮 Windows/Tauri 尚未验收，不阻塞后续既定源码施工。没有生产部署、真实 Key 或付费 API 调用。

## 已确认问题与修复

1. 结构化 `createSublimationGenerationCore` 把输出 schema 的保留字段集合复用于提示输入删除。保留姓名/魔装/问卷等字段时，模型反而失去用于生成其他字段及事件的事实依据；`writeCurrentState=false` 也会错误遮蔽仍允许读取的状态。现在只读输入按 `readArenaHistory`/`readCurrentState` 裁剪，输出 omission 与写入策略保持原契约。通用模板由原卡派生的正文继续先按读取权限重建；原数据与未知扩展不被改写。此确定性错误属于结构化构造器，不声称流式原本有同一删除错误。
2. 双输出原提示的无条件“全面重塑和升级”与明确保留能力限制可能冲突。共同短规则现要求正文、其他字段、事件和过去事实保持一致，成长可表现为技巧/合作/代价管理，同时保留用户明确许可且未勾选保留的创作变化。没有增加事后关键词拦截、重试模型或硬编码某角色。本项改善提示约束，不保证模型遵守，不把单次失败归因为唯一原因。
3. Desktop 会恢复并发送旧 `loreText`，但来源 UI 仅显示 typed selections，补充设定会隐藏地进入生成。共源 Lore 面板增加宿主可选的受控补充设定输入；Desktop 连接既有字段，折叠标题标记非空补充、Token 与非原生提示包含其内容。可查看/编辑/清空，清空不删除独立已选来源；草稿格式、Hosted wire 与来源身份不变。Web 没有该宿主字段，既有面板保持兼容。

## 生命周期与边界复核

- 共享卡库已在关闭/页签/账号变化时中止正文读取，回调前检查 signal；未将宿主缺少重复围栏夸大为已确认跨账号缺陷
- 既有 session 继续持有取消/迟到结果、重复派发、uncertain 防自动重发、恢复签名降级、墓碑与保存失败语义

- 本地/上传 Lore 不升级为服务器身份；Hosted 原生资格仍由服务端来源重读与签名流程裁决。未改 Native endpoint、凭据、数据库或迁移
