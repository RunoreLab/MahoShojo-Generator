## 范围与基线

维护者在 V1/V2 实测复测完成后明确授权继续 V3。基线为 `feat/desktop` 的 `ddcca3b16edc991bc734e20d085cedf24ce843e8`；此前字体、Surface 与操作层级的实机记录仍只覆盖原报告范围，不能直接作为本轮产品行为变更的验收。

本轮遵循产品共源 ADR 与 DESK-PARITY-003 公告契约，属于双端共同的体验升级，不是“无行为变化”的搬迁。不修改 AI 协议、签名判断、凭据、持久化数据或保存目标；不新增依赖、不调用模型、不部署。宽屏信息架构继续留到单独评估。

## 三个实现主题

### 情景结果优先阅读

- 结构化情景使用共源 `ScenarioResultContent`，默认呈现简介、类型、场景、角色、事件、氛围和发展方向。按当前字段的真实类型只读展示，不经过领域 schema 清洗或重写。
- 原始对象完整序列化到原生 `details` 的“完整 JSON（技术视图）”；已知内容优先阅读，JSON 默认折叠。未识别或畸形数据无可读字段时明确提示并默认展开 JSON，不制造空白结果或丢弃扩展字段。
- 完整 JSON 不截断，取消原 JSON 面板的固定高度内滚动；复制、下载、云端 / 本地库保存与容量提示继续接原对象。
- Web 通用情景编辑器仍保留原可编辑 Markdown 内容，辅助 JSON 改为相同折叠控件。Desktop 通用卡原 Markdown 预览不变。Free 的自定义 schema 不冒充为情景结构，不强加通用摘要。
- 折叠属于临时视图状态，没有新增持久设置；手动展开后同组件的数据更新保留展开并显示新 JSON。恢复、重新生成和首次结果自动定位仍由既有宿主控制。

### 公告不遮挡页面末尾

- 固定公告栏按实际 border-box 高度在文档末尾保留自有占位，包括安全区；不再覆盖 `body` 的原有 padding。Desktop 公告在 Outlet 前挂载，因此占位通过 portal 放到 body 尾部，避免把空白挤到页面顶部。
- 尺寸观察、窗口变化与字体加载重新测量；关闭、无公告与卸载移除占位和监听。置顶 / 日期排序、新公告与已读记忆、数据读取和外链策略不变。
- 公告正文与关闭为独立原生按钮；焦点可见、聚焦暂停滚动，沿用减少动效偏好。详情弹窗复用既有共享可访问性 hook，负责初始焦点、Tab、Escape 栈和返回触发按钮，不另造模态框系统。

### 限定生成按钮间距

五个生成页的两端主生成按钮显式消费 `generationSubmitClassName`，保留原渐变、字号和交互，仅将额外 `margin-bottom:20px` 交回宿主布局控制。组合选择器只作用于这些消费者；旧全局大按钮仍保留原规则，不借此重排全站。

## Windows 本地 Agent 复测任务

1. 在现有仓库核对 `feat/desktop` 最新发布 SHA、工作树及本轮报告，保留无关修改；两端固定同一源码版本。继续使用上一轮非秘密受控数据和隔离方案，不读取真实 Key、不调用模型。
2. Scenario 使用同一张结构化卡：亮 / 暗、相同 CSS 视口下确认默认易读内容、单层结果 Surface、JSON 默认折叠；Tab 到 summary 后 Enter / Space 展开，确认完整扩展字段与中文代码字体仍正确。复制与下载应与原对象完整 JSON 一致，容量指示仍基于完整数据。
3. 在 Web 通用卡编辑中展开 JSON，再修改正文，确认 JSON 即时更新且不意外合拢。未知 / 畸形结构应可读到明确提示与完整原 JSON；流式正文、旧草稿恢复、重新生成和自动定位不重复跳动。
4. 公告显示时分别在宽屏、约 375 CSS 像素窄屏、200% 文本 / 页面缩放下滚到页面末尾，确认最后一个可聚焦操作不会被公告挡住。测试打开、关闭、新公告、刷新记忆、窗口 resize；占位随实际高度变化，关闭无残留空白。
5. 用键盘打开公告：焦点进入弹窗，Tab 留在弹窗，Escape 只关公告并返回触发按钮，不能打开 Desktop 底层快捷菜单；减少动效开启时不滚动。打开公告内容外链时，确认 / 错误框应位于公告上方；取消返回链接，未经确认不调用系统浏览器。检查公告长标题和安全区。
6. 抽查 Free / Details / Canshou / Creator 主生成按钮上下间距及错误 / 取消区，确认主操作尺寸、disabled 与点击行为未变。
7. 回传版本、视口 / DPR / 缩放、通过与未测项目、截图与必要 console 信息。截图 / 大日志留仓库外；不把模拟服务成功写成真实供应商验收，也不将视口不同的截图称为像素一致。
