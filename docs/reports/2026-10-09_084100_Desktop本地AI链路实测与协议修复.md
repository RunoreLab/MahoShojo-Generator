# Desktop 本地 AI 链路实测与协议修复

日期：2026-10-09。范围：`feat/desktop` 的 Direct 本地 OpenAI-compatible 通路；基线 `6c5792f2`。本报告记录有证据的修复与验证，不代表 Windows GUI / 真 Tauri IPC / OS 凭据系统的再次验收。

## 结论与边界

真实 CPU 本地模型已经通过 `/scenario`、`/details`、`/canshou`、`/free`、`/creator` 五个生产生成入口的代表性闭环。每页一次请求，无自动重试、无真实 Key、无付费模型调用。这里的 Direct 仍是**以 SSE 运输结构化结果**；底层增量回调不是“客户端已支持 Markdown 流式生成”这一产品能力的验收。

发现并修复了结束原因契约、同源重定向、SSE 结束/尾帧、大块增量与推理用量映射问题；另按真实模型输出复核并消除 Free 共源提示中的宿主字段/模型 Schema 矛盾。模型产生可用卡片不等于每条创作约束都被遵守，具体质量限制见下文。

## 1. 实际执行路径

生产 `execute*Generation` → 共源 prompt/schema → Desktop 通用 executor → `direct-ai-bridge` → 测试注入的 invoke/Channel 边界 → JSONL 子进程 → 仓库实际 Rust `stream_direct_ai` → 实际 Profile 校验、隔离 SQLite、reqwest、SSE → llama.cpp CPU 模型 → Rust `AiStreamEvent` 序列化 → 生产 TS schema/reducer → 生产结构化 parser 与卡片投影。

Rust headless harness 使用原仓源文件，不重写 HTTP、Profile、解析器或事件核。仅 Tauri `Channel` 类型使用编译 facade；该 facade 的 `send` 一旦被调用就 panic，避免把它误作真实 IPC。实际事件通过仓库既有 `EventSink` 出口传递。凭据替身只允许无凭据路径，若解析/写入 secret 即失败；不使用 OS vault。

- 本次实测不等于手工 curl 返回 200，也不等于仅把固定 mock JSON 喂给页面
- 未运行真实 WebView2 页面、Tauri command macro、Windows 安装包、真实 OS SecretStore
- 测试中止用的子进程 SIGTERM 是 harness 清理，不计为产品取消验收；产品取消由真实本地 socket 的 Rust 回归验证上游断开
- 当前执行环境各 shell 调用的网络命名空间隔离；模型服务与 TS/native 子进程放在同一受控 supervisor，避免跨调用 localhost 的拒连被误判为产品故障

## 3. 修复

### 3.1 结束原因跨语言拼写

Rust `camelCase` 会输出 `contentFilter/toolCalls`，但 TS 权威契约要求 `content-filter/tool-calls`。修正为 kebab-case；共享 fixture 覆盖全部五种枚举，Rust/TS 同读，防止仅测试 `stop` 而漏掉其他终态。

### 3.2 启用 redirect 时必须同源

默认 `maxRedirects=0` 原本不跟随，保持不变。原 opt-in `Policy::limited` 只限次数，不能保护任意 `secretHeaderRefs` 或 POST prompt 跨源。修复在跟随前比较完整 URL origin，并继续原次数门禁，落实 DESK-031。

真实两端口测试先 RED 后 GREEN：307/308 跳到另一端口时，第二站零请求；同源相对跳转用 GET 对照保留假凭据，0/1/2 次门禁分别验证；未把该 GET 对照声称为同源 POST body 验收。未使用真实 secret，未扩大网络权限。

### 3.3 SSE DONE 与尾帧

原实现收到 `[DONE]` 后仍等 HTTP EOF，本地服务保留连接会使已经完成的请求一直等待。现在应用协议终态即结束并 drop 上游 body，保留 DONE 前 usage；缺少 DONE 的 EOF 仍是失败，不把半截正文当成功。

正常帧与 EOF 尾帧统一折叠，尾部 reasoning、usage、错误不再被忽略。无正文的完成信号不会生成不符合 TS 的 `completed` DTO：按真实原因输出已有错误码；有正文时保留 finishReason，页面继续按既有规则判定非正常结束。取消与 exactly-once 终态保持。

### 3.4 大块增量与 UTF-16

单个合法 SSE content 为 65,537 个 ASCII 字符，或 emoji 跨临界时，原 Native 会一次投递超过 TS 65,536 UTF-16 单元上限的 delta，被 renderer 拒绝。修复仅无损分片，不截断正文、不提高门禁；按 UTF-8 字符边界切片并累计 UTF-16 宽度，正文/推理两路一致。共享 fixture 对拍上限。

### 3.5 推理 token usage

补读标准 `completion_tokens_details.reasoning_tokens`，其有值（包括 0）时优先；缺失/null 才回退旧顶层 `reasoning_tokens`。不从事件数或字符串长度虚构推理 token 数。

### 3.6 共源生成提示与模型 Schema

Free/Creator 的模型生成字段与宿主附加元数据应明确分工。原字段说明把模型 Schema 不接受的 `templateId`、`current_state` 或 metadata 列为生成字段，造成“禁止额外字段”与字段说明冲突。仅修正已知模板的字段说明，宿主模板标识/元数据处理与 Schema 不变，禁止模型伪造签名的要求保留；未知模板不回退成 general。

## 6. 剩余边界

- Thinking 配置的 Direct 下发仍未实现，原 executor 已注明；本轮不宣称该控件会改变本地模型思考行为
- Native 累计输出预算仍主要依赖 TS 消费端限制；`execute()` 完整收集模式不等于实时资源保护。本轮只修合法单帧分片，不新增重复预算框架或擅自降低输出上限
- `[DONE]` 后续 chunk 不再消费；若同一 chunk 中 DONE 后紧跟非法 UTF-8，既有整 chunk 解码仍可提前失败。不声称任意尾噪声分块均兼容
- 尚未认证所有模型、所有 Free/Creator 模板、长上下文或所有语言；Windows GUI/IPC/真实 OS vault 是独立验收边界
- 权重、runtime、完整日志与模型输出均保存在仓库外；Git 只保留小型回归和报告
