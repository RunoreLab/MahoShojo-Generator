## 4. 公开库：现有缓存为什么不足

[types.ts](../../apps/web/lib/public-card-cache/types.ts) 当前定义 1 小时 fresh、24 小时 hard TTL、256 张正缓存；[storage.ts](../../apps/web/lib/public-card-cache/storage.ts) 按 expiresAt 清理并按访问次序限量淘汰，借用 AI session IndexedDB。[shared-loader](../../apps/web/lib/public-card-cache/shared-loader.ts) 在 soft stale 时返回旧单卡并刷新，但 hard expired 后删除；没有对整个已缓存集合的离线分页搜索接口。

此外，两端当前 [CardLibrary Web adapter](../../apps/web/lib/card-library-host.tsx) / [Desktop adapter](../../apps/desktop/src/platform/card-library-host.tsx) 的公开列表是摘要分页、正文按需读取；它们并不因为项目已有单卡缓存 helper 就自动拥有离线公共库。

[公开 API handler](../../apps/web/app/api/public-data-cards/handler.ts) 固定公开查询，summary 分支仅 public+approved；成功响应当前 `Cache-Control: public, max-age=15`，单卡不可用返回 404，数据库不可用返回 503、其他查询失败 500。**成功的某页缺少卡片、空搜索页、500/503 都不能证明卡已被删除。** native 目前只投影有限响应信息；后续若缓存策略依赖 response directive/业务撤回原因，须增加窄字段契约并同步测试，而非假定 renderer 已能读所有头。

适合 Desktop 的目标是“持久公开资料快照 + 在线重验证”，不是把现有 hard TTL 改成无限后就完成。必须同时解决摘要/正文完整度、局部缓存统计、失联降级、恢复在线、撤回边界、账号隔离、容量和并发写入。

缓存失效与删除应分开：旧资料仍可在离线状态使用；查询的新结果控制当前线上列表，不能把无限追加的缓存全集冒充最新线上库。也不宜自动镜像整库：既无完整稳定快照/增量撤回协议，也会增加服务端读取与带宽成本。

## 5. 个人页与设置：共享信息架构，不合并数据所有权

当前 [MePage](../../apps/web/components/me/MePage.tsx) 混合战报、资料、账号安全与 Legacy 迁移；[Desktop settings](../../apps/desktop/src/app/settings-page.tsx) 是账号、AI 连接、Web 包诊断和运行时面板。可统一产品分组，但两端存储与权限不同。

[useMeProfile](../../apps/web/components/me/useMeProfile.ts) 已有资料/头像 GET、PUT、DELETE，以及现有尺寸和格式约束；重构应复用这些事实。资料中的 `signature` 是个性签名文字，**不是数据卡密码学签名**。迁设置不能意外改变后者的延期决定。

建议 `/me` 保留个人展示/历史，`/settings` 作为共同设置中心；个人资料编辑从两处进入同一共享面。设备偏好不要求登录，也不因资料编辑而自动同步。旧 `/me?tab=settings` 与账号恢复 query 必须兼容；安全 token 不进入通用分享链接、日志或缓存。

高级 JSON 配置应是未来 UI 的同一写入面，不是第二份 AI 选择/Profile。当前 AI overlay 为 localStorage，Profile 为 native SQLite，Key 为 OS SecretStore；字段逐项迁移前不得双写。

以下于 2026-10-06 查阅，只支持设计原则，不证明仓库已实现相应功能。

| 来源 | 可借鉴之处 | 不照搬的部分 |
| --- | --- | --- |
| [RFC 9111](https://www.rfc-editor.org/rfc/rfc9111.html) §4.2、§5.2、§6 | 区分新鲜度、重验证、传输缓存与应用保存资料；不能把离线快照伪装为当前网络成功 | 不以新命名绕过 no-store/private/撤回要求，不新造通用 HTTP cache |
| [TanStack Query Important Defaults](https://tanstack.com/query/latest/docs/framework/react/guides/important-defaults) | staleTime 与 gcTime 是不同问题；新鲜度不等于保留期 | 不为持久缓存额外引入 Query；也不让 Query 默认 GC 决定永久资料去留 |
| [Tauri path](https://v2.tauri.app/reference/javascript/api/namespacepath/) | 使用运行时解析的 app config/data 路径 | 不把当前工作目录当配置目录，不授予 renderer 任意路径访问 |
| [Tauri capabilities](https://v2.tauri.app/security/capabilities/) | 按 webview/command 限制能力 | 不扩大 D4 ACL，不把产品可用性当权限 |
| [Tauri Opener](https://v2.tauri.app/plugin/opener/) | 系统浏览器及受控 URL 打开 | 当前已有 native `open` 用于授权；先复用窄能力，不必另加泛化 shell 插件 |
| [WAI-ARIA Modal Dialog](https://www.w3.org/WAI/ARIA/apg/patterns/dialog-modal/) | Escape、焦点限制与关闭后返回 | 不能只加 aria-modal 就宣称无障碍完成；共源修改同时覆盖两端 |

## 7. 决策建议与成本控制

接受先对齐、再迁近似功能的方向；保留 D5.1a–d 历史身份，在唯一计划插入可读的 P/G/S/K/T 切片，不重编号发行 D5.2。小型纠错与展示改进可以同一业务切片完成，但与纯搬迁分开提交；更大设置重构走明确设计与兼容切片。

公开缓存首版建议独立、持久、限额但不按年龄自动淘汰；只缓存实际浏览的摘要和成功读取的正文。独立缓存数据库有明确失败/备份边界，可避免把可重建公开资料塞进现有 `library.sqlite` 完整备份。达到预算先暂停新增缓存并提示，不删老卡为新卡腾位置。需要长期由用户保证保留的内容，显式存为本地库副本。

不新增全站 SDK、自动同步、全量镜像、后台抓取守护进程、服务定位器、插件注册表或证明型 CI。源代码、普通行为测试、少量真实浏览器/原生验收已能覆盖本轮主要风险。
