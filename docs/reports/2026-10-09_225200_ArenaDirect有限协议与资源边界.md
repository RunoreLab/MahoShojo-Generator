## 固定资源合同与测量点

canonical 来源为原 `packages/hosted-api/src/arena-generation/resource-budget.ts` 与 Hosted runtime 的 `consumeOutputBudget`。
共享常量移至 `contracts/arena-capabilities.ts`，Hosted 继续回用原值。

1. 原业务输入：12 MiB（12,582,912）UTF-8 字节，测量对象为冻结的业务 JSON 文本。`arenaInputJson` 保存 A1 投影的真实业务快照，TS 和 Native 重验四模式最少人数 2/2/1/1、最多 32、参考集合总数 256、判定事件 100，不静默截断
2. `arenaInputJson` 只是资源证据，不证明格式化 messages 与 source 语义等价，不授予业务、角色资格、签名、endpoint 或 secret 权限。既有 Direct 允许客户端提供 prompt；formatted messages 沿原链没有总字节上限。因此本片不宣称整个 IPC 或格式化 prompt 都受 12 MiB 限制，也不在 Rust 复制整套 Prompt
3. 输出内容：正文与 reasoning 的 UTF-8 字节累计合计 4 MiB（4,194,304）。正文内的 meta 也计入，terminal 中重复的完整正文不再双计；拒绝越界 delta，保留此前已接受内容
4. JSON/SSE 转义是运输开销，不能误算为正文。Arena-only wire 上限为 6 × 4 MiB + 16 KiB（25,182,208），覆盖 JSON 最坏转义；terminal 去掉 output 后的 metadata 另限 16 KiB，按严格 schema 校验。Native SSE line/frame 使用同一固定 wire 上限
5. TS collector 与 terminal schema 根据固定 `requestKind: 'arena'` 选择策略；Native 重验 kind、源输入与身份后选择相同固定策略，不接收 renderer 数值预算。Arena 结果不允许 structured 字段绕过正文预算
6. Arena 结构化解析的字符安全上界为 4 MiB，在完整原文已经通过 UTF-8 内容预算后使用；原 parser 的深度/节点等安全门禁保留。旧六族仍用原 1,000,000 字节 serialized result、1,000,000 字符 collector 和 250,000 字符 structured parser，旧 Native 行为和拒绝时点不变

## 生命周期与结果所有权

输入、ProviderTarget、模型、参数、记者/判定数据和 local scopeKey 在首次 await 前冻结。
取消立即停止接收，并沿原注册表向上游取消；提前取消不 POST，晚取消由真实 loopback socket 断连验证。
身份/序号不符、重复终态、晚包、缺终态、连接失败和非 stop finishReason 都不会生成历史候选。
正文只在公共 collector 接受后保留；terminal 不能用另一份文本替换已经接受的正文。

reasoning 和 metadata 与显示 Markdown 分开，usage 来自原生事件/终态，不信任正文 telemetry 声称的 token 数。Direct 只解析 source 顺序最后的 update meta，坏的新块不回退旧闭合块，也不产生历史候选。新 split 额外隔离已知裸 marker 的截断 JSON 尾部，坏 update 不产生候选，坏 telemetry 不进入正文/历史；Web 兼容入口保持旧行为。
只有显式 completed 且本地报告校验成功，才按原 writeNarrativeHistory 意图返回附原 scopeKey 的历史候选。候选的 generationId 使用归一化 requestId，现有纯历史 consumer 重复接收时仍只追加一次。
本片无历史 writer；后续宿主必须核对该原 scopeKey 后才可写入，不能在账号切换后写进新 scope。
不输出官方 signature、server updatedCombatants，也不修改角色卡或 DB。
