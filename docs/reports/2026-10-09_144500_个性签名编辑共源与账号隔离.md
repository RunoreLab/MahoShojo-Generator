# 个性签名编辑共源与账号隔离

日期：2026-10-09
状态：D5.1d-2 首个个性签名子切片实现、独审与完整自动门禁通过；Windows/Tauri 实机待验

## 范围与事实

遵循 accepted DESK-SET-002 / DESK-SET-003 和唯一 Desktop 计划。本片的「签名」是账号展示文字，不是数据卡官方签名、resign 或生成资格。

- 共享 `ui-web/settings` 的 `ProfileSignatureField` 与 `useProfileSignatureEditor`，Web `ProfileSettingsPanel` 实际回用；原头像控件与账号安全流程保留
- Desktop `/settings` 账号组与 `/me` 使用同一个资料签名面板、同一个会话 store，以及既有顶栏缓存扩展出的同账号资料缓存；没有新增持久化配置、账号草稿数据库或写入队列
- 服务器 `/api/me/profile` 是唯一权威。草稿只是当前页面内存，按账号/会话世代隔离；退出/切号清除对应展示缓存，不改变本地库或设备偏好
- 120 UTF-16 单位与 CRLF→LF 沿用现有 Web 合同。共享编辑时避免截出半个 emoji；窄 native DTO 拒绝不完整 Unicode，而不是接受无法由 Rust String 表达的文本

D5.1d-2 的头像修改、敏感账号系统浏览器流程、结果云保存及剩余资料功能未交付。本片不迁移 Arena 或茶会会话，也不改认证凭据存储、模型执行或生产服务。

## 先复现的 Web 缺陷

原实现把初始空草稿与异步非空资料比较成 dirty，随后 hydration effect 因 dirty 拒绝填入；另一个 effect 把 `isSavingSignature: true→false` 一律标记「已保存」，即使请求失败。修改前两项真实组件回归均失败，修改后通过。

新编辑器以「尚未载入」与已知空签名区分状态，未载入不能提交空白覆盖；初载正确填入。dirty 时服务器刷新保留当前草稿并提示双方不同，只有显式放弃才采用线上值。保存结果必须来自成功响应或匹配草稿的显式读回；保存中继续编辑的较新文本不被旧确认覆盖。

错误/中断统一提示未能确认保存、保留草稿，明确服务端仍可能已保存。用户可调用既有读取端口核对，再决定是否重试；读取不发送 PUT，也不覆盖不同的本地草稿。不进行后台上传或自动重放。

## 写入与生命周期边界

| 层 | 实际边界 |
| --- | --- |
| Web | 原固定 PUT；校验 success 与返回资料；捕获发起账号与既有 auth store 的身份对象，同账号重新登录也失效；卸载/切号后不回写。取消旧 GET，防止迟到读取覆盖确认写入 |
| Desktop renderer | 只提交 `{expectedUserId, signature}`；保存前验证账号、会话 verified 与无授权流程，响应再次核对 userId/credentialEpoch；未验证缓存可显示并保留草稿，不授权写入 |
| Native | 固定 PUT `/api/me/profile`，凭据只由 trusted host 注入；预期账号必须匹配本机当前凭据；不接受 renderer URL、Cookie、HTTP method、avatar 或未知字段 |
| Native response | 有界读取，success=true 且必填有效 signature，携发起时账号 ID；不使用请求文本伪造成功。401 仅报错，不清除可能已换成 B 的凭据 |
| Retry / redirect | 新 PUT 客户端显式禁止 reqwest 协议重试和重定向；Web mutation retry=false；每次再次写入都来自用户点击 |
| 缓存 | 个性签名和头像同一按 userId 缓存；确认写入推进读取世代，旧 GET 不可倒退新值。登出/新登录沿既有失效面清理；同账号新会话旧响应也无效 |
| 离开 | Desktop 路由/关闭沿既有 guard；保存中不允许「放弃草稿」确认绕过，闲置 dirty 可确认。Web普通链接沿共用 guard 的可选 busy 判定，其他消费者语义不变；浏览器刷新/关闭仍是平台 beforeunload 提示，不宣称可撤销已发 PUT |

写入不具有服务端 revision/CAS 契约；刷新时检测到线上变更会保留草稿并提示覆盖，不能宣称跨设备强一致或永久离线草稿。
