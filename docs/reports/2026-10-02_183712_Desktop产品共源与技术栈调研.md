范围：产品整体设计、Web 复用边界、临近仓库经验、正式版技术栈与已有文档的衔接；不修改运行时代码或依赖。

## 1. 需求与已有约束

维护者确认：Desktop 与 Web 是同一产品，页面、UI/UX 和功能默认保持一致；非必要不重写，能本地完成的流程不绕项目服务器。不冲突的本地库、Direct AI、安全、发行规格继续有效。

本次补充意见：Desktop 首期不建设数据卡原生性签名机制，也不设计页面上的手动申请签名动作。未来若增加签名，可在服务端能够验证的可信流程中自动请求，设置默认关闭；这不意味着相信客户端自述或把任意本地结果送去盖章。新增技术按实际需要选择，参考临近仓库与近期正式版本，而非照搬全套工具链。

既有 [Monorepo ADR](../decisions/2026-08-22_022200_Monorepo与应用边界决策.md) 已预留 `ui-web`，并禁止 app-to-app 源码依赖；[本地优先 ADR](../decisions/2026-08-22_022100_本地优先与服务器权威边界决策.md) 已区分设备自由与服务器权威。因此本轮是补齐产品层，不是重启技术路线。

## 3. 临近仓库：借鉴机制，不复制产品

只读核对临近仓库，读取时工作区干净。核对的是该版本的实现，不宣称它是所有仓库或市场上的最新方案。

可借鉴的部分：

- React DOM 客户端与平台能力分离；路由、滚动恢复、离开确认有集中入口，不散落到每个页面。
- TanStack Router 的实现把路由切换阻止与刷新/关闭窗口区分；它的 `enableBeforeUnload: false` 是该产品的决定，不是可以照抄的通用安全默认值。
- workspace catalog 与锁文件集中管理依赖；真实浏览器导航回归比只 mock router 更有用。

### 路由风险必须一起借鉴

临近仓库仍有 `@tanstack/history@1.162.4` 补丁：处理无有效 history delta 或 delta 为零时的回退边界。该补丁存在本身不证明所有导航问题已经解决，也不意味着应该直接移植补丁。

本次通过 GitHub 元数据核验，[TanStack/router PR #8264](https://github.com/TanStack/router/pull/8264) 已于 **2026-09-06** 合并，merge commit 为 `9035abc41163d83409ef582f7743a3c7be57dd93`。它处理 back/forward/go 的 blocker 与 unload 警告一致性，并在说明中保留越界 traversal 的已知限制。**合并不等于所选 npm 包已经包含全部修复**；本次没有建立发布包与该 commit 的完整对应关系，临近补丁也不能据此判定可删除。

建议把 TanStack Router 作为 Desktop 的优先验证候选；先用少量 code-based routes 与 hash history 验证，不预装文件路由生成器或迁移到 TanStack Start。验收覆盖返回、前进、同页 query 变化、中文路径、百科锚点、取消离开，以及真正的窗口关闭。具体依赖在 D2.5 接线时重新核验并锁定。

## 5. 官方资料支持的边界

资料于 2026-10-02 核验；以下是外部依据，具体产品取舍仍由仓库 ADR/spec 决定。

- [Tauri：Vite 前端配置](https://v2.tauri.app/start/frontend/vite/)支持构建本地 `dist`，不需要把在线站点作为主 UI。示例的 JS build target 不等于本产品已经验证的最低操作系统版本。
- [Tauri：Next.js 配置](https://v2.tauri.app/start/frontend/nextjs/)要求静态客户端产物，而非运行服务端能力；不能据此推断现有 Next/OpenNext 全站可直接打进安装包。
- [Tauri：Capabilities](https://v2.tauri.app/security/capabilities/)明确多个 capability 权限会合并，也说明应用自注册 command 默认可被各 window/webview 使用，须通过 `AppManifest::commands` 收窄。仅创建一个没有 capability 文件的新窗口不构成完整隔离证明。
- [TanStack Router：History Types](https://tanstack.com/router/latest/docs/guide/history-types)提供 browser/hash/memory history；[Navigation Blocking](https://tanstack.com/router/latest/docs/guide/navigation-blocking)提供阻止与继续导航的机制，仍需产品定义本地任务与关闭行为。
- [Rsbuild：Quick Start](https://rsbuild.rs/guide/start/quick-start)可作为备选构建方案的官方入口，但本次没有发现足以支付迁移成本的实际需求。
- [Node.js：Release policy](https://nodejs.org/en/about/previous-releases)用于区分 Current 与 LTS，选型时需重新检查实际支持状态。

## 6. 对整体设计的修订建议

**先补上位产品架构，再迁页面。** 新架构应表达首页与主要旅程、共享源码归属、能力注入、本地/在线状态、数据所有权、可信/不可信渲染与发行边界；不是再列一套 native 功能清单。

**精确修订 `DESK-003`。** 当前“不得从项目域名加载脚本、样式或应用数据”把用户主动请求的线上库 DTO 也禁止了。建议禁止远端主 UI 代码与本地流程对项目服务的依赖，同时允许通过已授权在线适配器加载数据；不得因此放宽现有 CSP 或 Direct provider 的项目域名拒绝规则。

**避免阶段依赖成环。** D2.3d 需要可承载导入导出的产品页面，而 D2.5 若又要求 D2 全部结束才能建设页面，会循环阻塞。静态产品壳可在 D0 安全基础上与 D2 存储工作并行；真实生成与真实存储功能各自依赖对应门禁。D1 未验收不应阻止离线百科，但仍阻止宣称 Direct 生成已验收。

**将签名从首期移除，而不是新增签名 UI。** 本地内容通过 schema 只证明结构有效，官方 app 也可被修改。未来自动签名必须基于服务器能够独立确认的流程和精确输出；默认关闭，不阻断本地保存，不重发已执行的 AI 请求。现有签名字段仍需无损携带；离线无法验证 HMAC 时不能把“有签名”展示成“已验证”。

**共享源码不等于运行期热同步。** Web 对共享模块的修改通过正常 Desktop 构建/发行进入已安装客户端，不在本地壳中热载远端 JS。在线 API 需要考虑旧安装包，而不是要求两个运行时每次同时发布。

本报告没有安装、升级依赖，没有运行真实 Provider、真实 WebView 或发行验收，也没有修改临近仓库。后续以 accepted 决策及配套规格落实以上取舍，原有不冲突的规范继续有效。
