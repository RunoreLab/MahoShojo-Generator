## 实现

既有 Direct Native 已使用 SSE，但产品层固定追加 JSON schema 并解析结构化结果。本轮把执行位置与输出形态分开：不新增 Native 命令、Provider 框架或凭据存储，也不改变旧请求省略 generationMode 时的结构化行为。

五页客户端均可选择流式：

- Details / Canshou：与 Web 同源的问卷、设定和语言 Markdown prompt → 通用角色卡
- Scenario：同源情景 prompt、留空字段及标题回退 → 通用情景卡
- Free / Creator：仅 `general`、`general-scenario` 支持流式；其余结构化模板必须非流式，不隐式回退

`generationMode` 随派发意图冻结，预设/自定义目标和执行位置仍独立。页面通过已有 session、direct-ai bridge、Native SSE 和 collector 接收增量；在终态前使用共享 MarkdownBlock 阅读正文，原始文本仍可展开。预览不开放模型提供的导航链接/外部媒体。非流式、取消和失败保留原正文展示语义；保存仅消费经过验证的最终卡，流式不产生官方签名。

推理与正文分别保留，正常终态回传 usage/finishReason。`length`、过滤、工具调用等非正常结束不发布成功卡；独审发现空壳 `{}` 等可被构造成卡，本轮将 Web 原判空函数抽为共源并在 Direct 构卡前拒绝，保留原文而不自动重试。没有增加流式输出截断；原有预算及大帧分片规则不变。

## Windows 本地 Agent 补验指令

在 GOZHONG-NB1 的现有仓库读取 AGENTS.md，核对 `feat/desktop` 实际提交和工作区；保留其他会话改动。使用隔离应用数据与测试连接，不操作正式凭据或用户卡库。启动真实 `pnpm run dev:desktop`，用本机 OpenAI-compatible 模拟服务或已配置本地模型完成以下测试；不使用付费模型。

1. 五页客户端 local/remote 选择流式，确认正文在请求结束前已逐段显示、原始文本可展开；推理不能混入正文。Free/Creator 分别检查两类通用卡及不兼容模板的明确拒绝。
2. 生成结束后预览通用卡，保存到测试本地卡库、下载、复制，核对正文完整与无官方签名；退出重启恢复结果不发起新请求。
3. 输出途中取消，确认上游停止且残稿可读取、不出现成功卡。模拟断流、token length、空壳输出，确认原文保留、不自动重试。
4. 连续点击生成、准备凭据期间切位置、在途更换凭据：不得产生额外请求或改变原请求目标。流式预览里的内外链接、相对链接、图片均不应触发导航或外部请求。
5. 回归客户端非流式、服务器系统与 BYOK 的已有模式；取消后重新生成、已有未保存结果确认、草稿恢复与自动定位正常。

报告实际 SHA、Windows/WebView2 版本、受控输入、工具退出码、HTTP 请求数与终态、截图/日志位置。Mock/DOM/headless 证据不替代真实 Tauri IPC、GUI 或 OS SecretStore。已有前轮实机验收不自动覆盖本轮新增流式模式。
