# Web 数据卡创建账号围栏

状态：源码独立审查与整合终版完整 CI 通过；不代表生产部署。

## 范围与兼容

- 新增固定 `POST /api/data-cards/create-owned`，必填 `expectedUserId` 为正安全整数；缺失、null、字符串、小数或越界返回 400。
- 服务端只鉴权一次，冻结得到的用户；所属账号不符返回 409 与稳定 `ACCOUNT_MISMATCH`，在敏感词、容量和写入之前结束。既有 cookie 优先规则不变。
- 旧 `POST /api/data-cards` 与新端点复用唯一创建 helper，显式传入已鉴权用户，不重新进入旧 handler。旧接口兼容且不具有账号围栏。
- 成功仅为 201，包含 `success: true`、非空且长度不超过 200 的 `id`、`accountFenceVersion: 1` 和 `ownerUserId`。guarded Web 调用必须验证冻结账号及版本。
- 新客户端遇旧服务端 404/405 明确不可用，绝不回退旧 POST，并用 `redirect: error` 阻止 307/308 将 POST 转发到旧路径。400/401/403/413/429 和确定的账号不符为已拒绝；未知 409、异常 2xx、5xx、网络错误保留不确定结果与草稿，零自动重试。
- 保留公开/私有表单及既有业务检查；Desktop Native 现有账号围栏接口不变。不加入替换、购买槽位、自动保存、数据库迁移或幂等协议。

## 接线边界

当前数据卡 CRUD 由 Next 承载。Hono 只加载独立共享 application service；不能回导 Web handler。最小修复不迁移整个创建业务到 Hono，Hono 未注册新路径时保持 404。此范围已经核对确认，不以跨 app 导入规避架构边界。

## 验收

测试 cookie B / Bearer A 拒绝且无业务副作用、只鉴权一次及冻结用户、严格成功确认、混合部署/回滚不回退、旧调用兼容、共用业务规则及草稿保护。仅测试合成数据，禁止真实账号写入。独立审查和实际完整 CI 完成前不发布。


## 部署与回滚事实

新接口属于 Next/OpenNext 数据卡业务部署，不是 Hono 生成服务的新能力。旧源码 `e8b692a6f` 的 API 树只有 `data-cards/route.ts` 和 `data-cards/repair-questionnaire-type/route.ts`；唯一 API catch-all 是 `auth/[...all]`，不匹配本路径。仓库 Next 配置无 rewrites/相关 redirect，Hono 实际 app 对两种 data-cards POST 均返回 404。没有调用旧创建 handler 的映射。生产反代配置本轮未审查，也未部署。

新客户端+旧服务端会拒绝安全保存且保留草稿；新服务端+旧客户端保持原接口兼容，但不能声称旧客户端已有服务端账号围栏。回滚服务端后，新客户端不降级写入。若将来代理错误地内部改写本路径，属于部署路由不变量被破坏，客户端确认只能防假成功，无法撤销已经发生的错误写入；不要把客户端 ack 说成写前授权。
