## 问题与修复

原 Web 停止流程把本地结束绑定到服务器取消确认和整个读流退出。取消回执虽有默认五秒预算，初始握手、重连或读流清理挂起仍可能让 `isGenerating` 长期保持。随后手动中断又从结束时开始完整冷却，进一步延长不能新开的时间。

共享客户端现在把本地停流和有界取消确认分开：Web 显式启用即时结束；初始请求、读取、重连与清理均可退出。只有有效回执才投影 `cancelled`，202 只表示受理；网络失败、拒绝和超时保持 `cancel_unconfirmed`。普通断订阅仍不取消 producer。迟到响应不会恢复旧流，旧取消回执不能覆盖新恢复指针。

Web 点击停止立即释放生成/接收状态并保留已显示正文；异步准备和终态后的本地处理也可停止。取消确认独立显示，确认期间不允许新生成；失败后显示后台运行与重复费用风险，用户显式确认后才创建新意图。刷新后从最新或相同输入的持久化取消记录恢复门禁，风险确认匹配旧 request ID；新 request ID 或修改表单不能绕过最新未确认取消。现有 body hash、active 恢复协议和 HTTP/SSE wire contract 未修改。

手动停止只计算实际 create `beforeDispatch` 起点的剩余客户端冷却。例如官方通道已等待 20 秒则剩余约 100 秒，已等待超过 120 秒则不额外冷却；自定义通道同理按原 3 秒时长计算。未发请求的准备阶段不新增冷却。正常完成、其他失败分支及服务器限流策略保持原状。

补充保护覆盖新任务接管前中断旧 controller、旧 finally 不清新任务、换号不以新身份取消旧请求、取消期间换号不永久遗留 `cancelling`、新身份经风险确认后只创建新 request ID。Desktop Hosted 仍采用默认的“有界确认后形成 outcome”，多人 Room authority 未改。
