## 1. 实际范围与共享消费者

- `library.sqlite` v5 增加专用 session、chapter、checkpoint 表；首章和续写的会话元数据、章节、检查点及精确回执在同一事务提交。
- `LocalLibrary` 实际拥有 `StoryStore`，复用其 `SharedConnection` 与维护门。没有平台条件编译假 owner，也没有把连续故事塞进通用 blob 或 D4 协议。
- `domain/arena-story-commit` 的 Web 原消费者继续使用同一完成章组装、内容摘要和 JSON 遍历。新增逐字节计数/分块从同一冻结载荷产生；角色更新使用现有 post-battle 逻辑的写时复制计划，不复制剧情算法。
- 实际 Web 故事导出改用 `domain/arena-story-export` 的共享投影与 Markdown writer；旧 Web 原实现捕获的 14 组金样逐字一致。Desktop 的完整遍历生成器消费同一 writer。
- Desktop `arena-story-storage.ts` 是可注入端口的内部接线层，已经通过真实 Native 原件读回验证；尚没有 `invoke` 绑定、主界面入口或 Native 完整导出文件 sink，不能称为已交付页面旅程。

## 2. 保存、身份与资源合同

机器可读合同是 `contracts/desktop-arena-story`，Native 实现在 `arena_story.rs` / `arena_story_read.rs`，TypeScript 发送和接收实现为 `apps/desktop/src/platform/arena-story-storage.ts`。

### 2.1 完成章与计数

宿主先用 `buildCompletedBattleStoryRecords` 取得原共享完成记录，再调用 `prepareStoryStorageCommit`。首章传 `expectedRevision=0`、`expectedLastChapterId=null` 和 boundary 0/1 两个检查点；续写传捕获的 revision/head、一个新增检查点，以及本次输入的 `lastInputCheckpointId`。operation ID 固定为新 chapter ID。

投影移除 session 内重复的 seed/working/last-input 快照，改为独立 seed 原件与 checkpoint 引用。未知 JSON、角色扩展、原有历战、章节全文保留；source 只保明确的非凭据来源字段。192 字节目录标题是明确标记截短的预览，完整标题仍在原件。

预算先对最终待存图做精确 UTF-8 计数，再 schema 验证和发送；超限时不复制放大的整个图，也不开始 Native 上传。JSON token 遍历、原 domain canonical digest 和分块共源；新 `arena-story-wire-v1` operation 身份则是固定小 manifest 的 SHA，绑定全部决定写入的 ID/CAS/op 字段及每个 part 的实际 SHA/字节数，二者语义不混用。

### 2.2 Native 暂存与事务

- 候选单提交预算 128 MiB；raw frame 上限 4 MiB。不是一次 128 MiB JSON IPC。
- 每个 library 实例最多两个 stage，所有 stage 的声明字节总和最多 128 MiB，寿命 15 分钟；Native 分配临时路径，调用者仅能提供固定 part kind 与连续 offset。
- 首章 part 顺序为 session/seed/chapter/checkpoint0/checkpoint1，续写为 session/chapter/checkpoint1。长度、顺序、SHA、JSON 身份和关系均复核；部分文件写失败只废弃该 token。
- 上传不持 `WritePermit`。end 验证完成后取得同库维护门与连接锁，一事务写入；同 operation 精确回执优先于 CAS 判断，不重复应用角色效果。端到端写阶段的耗时包含上传、校验与事务，并未单独测量持锁时长。
- 暂存不是备份，也不保证跨崩溃恢复未保存结果。恢复/重开产生新实例身份，旧 token/descriptor 无法跨库续写或读取。

### 2.3 保存证据

`savePreparedStoryCommit` 返回精确 receipt；失败抛 `StorySaveError`，携 `not-written` 或 `unknown`。Native 明确未提交的维护/验证/回滚失败可以原包本地重试；COMMIT 不确定和传输异常保持未知。未知结果先 `queryStoryCommitReceipt`，回执必须全身份匹配；回执缺失不能降低为安全重写或重发模型。

宿主须保留同一 pending 包和单调保存证据。读取失败不能把已确认保存改成未保存；页面退出丢失内存结果的提示、另存新身份确认、零模型重发与 pending 防覆盖仍由后继真实页面负责验证。

## 3. 分页、按需读与完整导出接线

- `listStorySessions`、`listStoryChapters` 返回摘要。默认 25 行，Native 最多 50 行，每页最多 128 KiB；会话按 updatedAt/id、章节按 index/id 做 keyset 分页。
- `readSelectedStoryChapter` 仅取选章。descriptor 绑定 library 实例、session、record ID、revision、固定 record kind、原件字节数与 SHA；不接受表名、列名、SQL、任意 rowid 或磁盘路径。
- Native 每帧重新在同连接锁下验证身份并打开固定列的 read-only incremental blob；append/restore 后旧 descriptor 明确失效，不串记录。TS 按帧验 raw SHA，完成后 hydrate 一个原件；Zod 只验证原对象，不用其重构副本替换原件，因此 JSON 自有 `__proto__` 等未知扩展保真且不赋值污染原型。
- `readStoryContinueState` 返回 `{ session, seed, checkpoint, recentWindow }`。最近最多十二章依次读取后立即转为原共享 prompt 窗口，旧章 digest、末两章各 6000 字符正文，不保留十二份完整 chapter。seed/checkpoint 完整保留，后继 prompt 仍须沿实际 12 MiB 输入门检查，不能把窗口数量当作整个 prompt 字节保证。
- `readAllCommittedStoryChapters` 遍历所有分页，核总数、连续序号、head 和 revision；不依赖界面可见页。`streamCommittedStoryMarkdown` 按章消费共享 writer 并输出有界 UTF-8 块。
- 接线方必须先写未发布的 Native 导出文件，只有生成器完成全部枚举/身份校验后才能发布成功；中途错误或取消不能把半份文件称为完整导出。pending 未保存章节不混入已提交全故事出口。

## 4. v5 迁移、备份与回滚

`store.rs` 的单次迁移事务创建三张专用 STRICT 表、索引与延迟关系约束；故障注入证明 DDL、版本日志和原有数据一起回滚。没有通过 `ALTER` 给旧 schema 虚构新列。

备份仍是原 library SQLite 与既有 blob 的同库备份机制。v5 校验新表/列、关系、元数据边界、JSON 与索引一致性、逐原件实际 SHA，以及完整 receipt 的 version/op/session/chapter/index/revision/count/checkpoint 顺序；只改 JSON/hash 而破坏预览、计划或 receipt 的备份会被拒绝。

真实历史 schema 1–5 × 旧/版本化 manifest 共十组恢复后迁移通过，源备份文件逐字不变。首个 v5 备份包含已提交故事，排除未提交 stage；旧备份恢复后自然为空故事库。

应用回滚不能让旧二进制直接打开 v5，也没有自动 down-migration。沿原 restore：预备代在 `.restore-staging/<restoreId>`，替换前原 SQLite/WAL/SHM 与 blobs 整代保存在 `.restore-old/<restoreId>`，日志位于 `.restore-journal/<restoreId>`。应使用升级前验证过的备份/保留代恢复旧 schema；不能混配新 main 与旧 WAL。恢复中断、损坏新代保留旧代、启动恢复等既有测试与新表测试在同批运行。

## 5. 同原件容量链与内存限制

实测在冻结干净源码上顺序运行十个 case。真实 TypeScript Direct producer 接收合成 Native 事件，使用现有输入快照、报告/digest、角色效果和完成章组装；它不调用真实模型。发送分块写入当前 Rust/SQLite，独立进程重开后再导出 raw 原件，由实际 TypeScript 接收/选章/续写代码读取。成功案例逐 part 的字节数、SHA、完整 Markdown 与角色数一致。Rust 是真实 1.99 工具链的 debug headless 模块；没有 Tauri/WebView IPC 或 Windows GUI。

下表 RSS 单位 KiB，来自独立子进程的 Linux `getrusage` 最大值，不是各阶段相加，也不是 WebView 上限：

| case | 提交字节 | 最大原件字节 | producer RSS | Native 写 RSS | Native 重开 RSS | TS 接收 RSS |
|---|---:|---:|---:|---:|---:|---:|
| 当前预设 2 角色 | 200,595 | 62,334 | 79,548 | 8,576 | 8,576 | 64,620 |
| 当前预设 8 角色 | 669,345 | 220,838 | 80,200 | 8,576 | 8,576 | 65,388 |
| 当前预设 32 角色 | 1,113,961 | 386,578 | 86,016 | 8,576 | 8,576 | 65,340 |
| 完整输入恰好 12 MiB，主要为角色 content | 37,789,105 | 12,608,300 | 323,964 | 59,460 | 55,404 | 206,260 |
| 输出恰好 4 MiB，NUL 正文 | 25,171,276 | 25,167,740 | 169,764 | 112,536 | 63,540 | 199,248 |

最后一行是独立传输防御 fixture，不冒充真实 producer 极值。该 case Native 写阶段约 15.11 秒、重开约 6.33 秒；NUL 标题真实放大例写阶段约 10.50 秒。常规 32 预设体量与极端例差别很大，不用轻量样例为全部输入担保。

其余三个拒绝 case：

1. 12 MiB 合法 guidance 输入经原角色历战逻辑重复放大，精确计数在超过保存预算后停止，返回 generated-not-saved，零 Native 上传；observedBytes 为首次证明超限的计数，不是整包总量估算。
2. Direct 原始输出 4 MiB + 1 被现输出门拒绝，不创建完整故事提交；已接收的部分正文不冒充完成章。
3. 合成提交 128 MiB + 1 在精确预检拒绝，零 Native 上传。Native 独立声明门另有单元反例。

因此 128 MiB 只暂作为后续受控 UI 接线的独立保存预算候选，不保证每个合法 Direct 生成都能保存。4 MiB raw frame、128 KiB 目录页并非内存保证：TS 仍须 hydrate 单个完整 record，解码块、连接后的文本与解析对象会同时占内存；极端单章接收实测约 649 MiB RSS。后继页面必须保全文、允许失败后导出、不给自动重生成，Windows/WebView 资源表现继续待验。没有降低角色上限、增加总章数上限或截断原文。

## 7. 后继候选：真实 IPC 绑定与完整故事出口

TypeScript/binder/共享 writer 提交 `49db102d28a7b09b79038683f67ac6358baff876`，Native/权限候选 `1f5fa7611f467b926578f2243f2ae38aa5979f74` / tree `b89c1a1b60f17219f88cea8d996a67248444bda2`。两页真实消费者在独立集成树接线；这里登记私有候选协议供最终验收，不单独发布无消费者能力。

### 7.1 窄原生绑定

`arena-story-native.ts` 提供实际默认 Tauri `invoke` 的 `createIpcStoryNativePort`、`createIpcStoryMarkdownExportPort`。存储十条、出口四条 command 与 `generate_handler!`、AppManifest、精确 `main-ui` webview capability 三方一致，不给包窗口、通配窗口或任意文件/SQL 权限。结构化请求仅小 metadata；raw 上传固定 `x-story-token` / `x-story-part` / `x-story-offset`，读取返回 `tauri::ipc::Response` 二进制，TS 拒绝 JSON 数组/base64 替代。

磁盘与连接等待沿既有异步 command 调度。提交 stage 的 token-scoped 单次计时器在 15 分钟后清理；出口是单 flight，15 分钟**空闲**到期，成功 append 续期，旧 token timer 不动新出口。没有后台 job 框架或活跃大故事的 15 分钟总时长硬限。

### 7.2 两遍完整计数与派生磁盘界

`exportCommittedStoryMarkdown(port, sink, head, {signal,onProgress})` 第一遍在固定 revision/head 下遍历全目录和实际共享 writer，只精确计 UTF-8 字节。共享 writer 现在输出文本/数值缩进段，旧 Web 字符串 API 从同一段构造，金样保持；巨大缩进可 O(1) 计数，无巨大 `string.repeat`，超安全整数在分配前明确诊断。

begin 传 session/revision/head/count/expectedByteLength。Native 复核实际记录和派生上界，再用现有 fs4 读取该 exports 目录的实际可用空间；不足返回明确 `story-export-no-space`，不创建 temp。没有新增固定 256 MiB 或总章数限制，也不把 safeInteger 误当资源可承载证明。

派生界为 `B + 64 × (章数 + 判定数组项数) + 4096 + 4 × Σ floor(max(finite depth,0))`，其中 B 是实际 session/chapter 原件 UTF-8 总长，所有运算在安全整数边界饱和。证明与对拍：

- 每个用户字符串只输出一次，trim 不增长；解码后的 UTF-8 不长于其 JSON 原件。summary、分支标签/来源、title、mode/language 同样各一份，没有重复乘子。
- 每个有效判定项的全部固定标记、换行和详情括号最多 35 字节；双缩进共 `4 × floor(depth)` 空格。无效项仍计入 Native 的每项 64 字节 allowance，只会放宽上界。
- 每章分隔符与判定标题最多 36 字节；会话全部静态标记含未命名 fallback 共 157 字节，加安全整数进度/分支数值文本后仍远低于 4096。
- Native 只读取固定 JSON 路径的数组项和数值 depth，不渲染第二套 Markdown。测试覆盖 depth 20、极大 safe/unsafe、Unicode、控制符、孤立代理、无效项/类型与上界精确值/+1。独立审查另以 1,000 组输入重算实际 writer 段长度，均不超过公式；PB 级合法数值缩进只形成 11 段而非实体字符。

第二遍使用同 head 和每条原件 descriptor/hash，边输出边由 TS、Native 各自计算 SHA；end 比较最终 SHA、声明长度、实际文件长度及当前 head/count/revision。文件先 sync，再在短维护写许可与同连接锁下做最终 scope 核对和 no-clobber 发布到 Native 生成的 `exports/story-markdown-*.md`。失败/取消只清私有 partial，不改源故事。原件各阶段读取与计数仍需 hydrate 单 record，未承诺小内存显示任意大章。

此完整出口依赖当前库的受控 writer/CAS 与原件 hash，不宣称防御同用户外部进程主动替换临时路径/inode；与既有 archive 原语相同，renderer 自身没有这种路径写入能力。磁盘空间预检也不是预留，之后磁盘竞争仍可明确写失败。

### 7.3 实际原件链与剩余门禁

当前冻结源码的真实存储/出口/原有 archive/维护/备份/恢复模块共 154 项、Clippy 全目标零警告、root command/ACL 结构 36 项与 workspace boundary 通过。桥/JSON/真实 binder 共 42 项；writer/旧 Web 金样/判定 33 项，目标类型与触达 lint 通过。

实际默认 TS binder 的 command/headers/raw 字节经证据专用长度前缀 pipe 进入真实 Rust owner：写入 53 章、独立进程重开、旧 descriptor 拒绝、3 页完整导出 9,085 字节。最终 `.md` 原件 SHA-256 为 `ec30201f27795732ed85b2aa100773c051398fddb7a1d93d2cbc6e425b02bcfb`，与共享 writer 逐字一致。902 个实际 raw 写帧；lost end 通过原回执确认而不重存，出口中途取消无残留 partial；第 54 章 PB 级缩进先到 Native 磁盘拒绝，未上传出口正文。该小数据链退出 0，用时约 0.95 秒，进程采样峰值 151,612 KiB；不能借它解释极端记录 RSS。

pipe 验证的是实际跨语言格式与原件，不是 Tauri IPC：本环境缺 Linux Tauri 所需 GTK/WebKit 系统库，未安装新工具或伪装整壳编译通过。主窗口/真实权限执行、Windows/WebView 与最终整旅程完整 CI 仍须分别验收。

特别区分 producer：§5 的约 100.7 MB 例使用较早基础组装配方。后继真实页面 owner 保留 `report.article.body` 和完整 fallback summary，同样 2 角色 / 4 MiB NUL 长标题会形成六个各约 25 MB 字段，超过 128 MiB 保存候选。页面 owner 探针实测峰值 419,948 KiB、约 2.704 秒，1 次合成派发、0 次保存，保留完整 4 MiB 原文可导出。不能用旧 100.7 MB 成功例宣称最终页面的该输入可保存；后继页面证据与完整集成验收由同一纵切合并记录。
