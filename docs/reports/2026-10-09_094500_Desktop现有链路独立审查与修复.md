## 已复现问题与修复

所有下列问题均先在基线或对应候选代码上得到失败回归，不以静态猜测代替复现。

| 优先级 | 问题与影响 | 最小修复 |
| --- | --- | --- |
| P1 | Direct SSE 错误消息及反序列化错误可包含上游回显的凭据，随错误事件进入 renderer | 不可信诊断统一投影为固定安全文案，保留稳定错误类别；不改变正文/推理 |
| P1 | 角色保存等待期间的新字段/标题编辑被保存前快照覆盖；初始目标卡慢读期间仍可换来源 | 保存只推进已提交基线、保留后续编辑；读取/保存期间保护来源切换，迟到回调不切换工作区 |
| P2 | 合法正文伴随纯空白推理时，Native 成功输出被 TypeScript 非空约束拒绝 | 按 ECMAScript 空白语义省略空推理；有效首尾空白及完整正文不裁剪 |
| P2 | Hosted 收到响应头后，慢 JSON 正文或 SSE 错误正文不响应取消 | 所有对应正文读取继续监听原取消令牌；唯一终态与请求注销不变 |

| P2 | 粘贴内容自动保存失败或清空草稿后，内存内容可能失去离开保护 | 持久化失败不能被清档动作伪装为已保存；保留显式清档与内存创作语义 |

| P2 | 公告与卡库模态层非顺序关闭时，滚动提前解锁或永久残留 hidden，下层还可能抢焦点 | 两处消费者共享轻量引用计数锁，最后一层归还原样式；下层退出不夺走上层焦点 |
| P3 | 结果更新时，有无可读字段的变化会覆盖手动 JSON 开合状态 | 单组件临时记住用户开合，未手动操作仍使用原 fallback；完整原始 JSON 不变 |

测试、构建与 RED/GREEN 原始输出放在仓库外 `desktop-review-*.log` 与 `native-protocol-audit-evidence/`，不提交模型、凭据、重复大产物。本报告不把 Mock、DOM、headless Native harness 当作真实 Windows GUI、Tauri IPC 或 OS SecretStore。

本轮没有调用模型、真实 Key 或付费服务，没有生产部署、主分支合并或远端历史重写。Native 测试使用回环受控 HTTP/SSE 与假凭据；协议修复不需要重复五页真实模型推理。

## 下一项既定计划

唯一 [Desktop 阶段计划](../plans/2026-09-30_160100_Desktop客户端阶段实施计划.md) 的 D5.1-G4 与 [DESK-PARITY-006](../specs/2026-10-06_084200_双端产品对齐与设置共源规格.md) 指定：Sublimation 迁移先隔离 NarrativeHistory 读取、选择与参考合成，不引入整个 Arena store。

可独立推进的首片为：纯顺序/参考格式/合并函数进入 domain 显式出口；历史选择 UI 改为受控数据端口并由 Web 同批回用；保留既有存储 key、迁移与 hydration，区分读取失败和真正空历史。该首片不增加 Desktop 路由，也不宣称 G4 已交付。

完整 G4 仍需原生 Hosted 两端点、纯生成核及本地/云端历史来源适配；后续再按真实依赖实现选卡、引用、生成、另存。既有 Windows 行为验收仍保持 PENDING，发行、签名、部署的授权与门禁不随本次代码审查改变。
