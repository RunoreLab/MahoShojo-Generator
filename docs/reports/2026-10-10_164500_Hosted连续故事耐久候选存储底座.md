# Hosted 连续故事耐久候选存储底座

状态：本地源码候选；同源 Native/TS 验证、独审与正式树完整 CI 已通过，待统一发布。2026-10-10 UTC。

## 范围与复用

本片只提供 `desktop-arena-story` 的严格 pending contract、Desktop raw IPC bridge 与 SQLite 存储 seam，尚未接 Hosted 网络 transport、两页 owner/UI 或 slot secret 生命周期。因此本片不宣称已实现模型重连、角色恢复、完成作品导出按钮，或完整 Hosted 连续故事旅程；这些后继必须消费这里的原 product/actor/request 身份和恢复证据。

- 同一 `library.sqlite` schema 5→6；新增 pending/part 两表，按 battle/arena 原 product 各一 active 槽
- 复用 `StoryStore`、`SharedConnection`、`MaintenanceGate`、既有 Direct stage 的同一锁与总预算
- `zeroblob(actual_length)` + incremental BLOB；只按受检声明的实际长度分配，不预分配每槽128MiB
- `validate_documents`、`check_cas`、`write_documents` 是原章节验证/CAS/receipt writer 的共同实现，Direct 文件 stage 和已封存 pending BLOB 各自提供原件读取，没有第二份 save stage
- 整库备份沿原 `VACUUM INTO`、校验、摘要与 restore journal；portable ZIP 不纳入 pending，不新增磁盘文件族

## 可观察合同与预算

严格 metadata 只允许固定 ID、actor 类型/expectedUserId、时间、CAS 基线、写选项、证据标签、摘要与有限 kind/length manifest。没有任意 metadata map；原始 input 中 `customProvider`、认证 Key/bootstrap/token/headers 等网络 carrier 字段不能写库。用户卡与创作文本本身可含私密内容，本片不是秘密识别或内容清洗器。

四种闭合 JSON carrier（input、header、meta、roleResponse）在有界进程内缓冲收齐并通过 Native shape 校验后才写入 SQLite；input 排除网络 funding carrier，header 仅受检的 Markdown HeaderMeta，meta 仅原 `meta/meta_error` 事件 JSON，roleResponse 仅原 reconciliation success。传输响应头不落盘。其他正文/commit part 按 ≤4MiB raw frame 增量写入。未完成的 JSON buffer 可能已有内存 append 回执，而 durable offset 仍是0；未知回执必须查实际进度/相同块，或中止该本地 upload 后原样重传，不能据此调用模型/role。释放 buffer 不代表 secure-zero。闭合 carrier 所有层级拒绝解码后重复 JSON 键（包括 `seed` 与 `\u0073eed` 等转义同名键），避免 last-wins 解析把早先未验证 carrier 字节藏进 BLOB；opaque 用户业务对象不递归清洗，重复键与孤立代理项原字节仍保留。

- active payload：每 product ≤128MiB，两槽 ≤256MiB
- pending upload 与旧 Direct stage：总共最多2个、声明 payload合计 ≤128MiB
- 逻辑在途 payload上限384MiB，控制 metadata每条 ≤64KiB，最多2 active +2 upload，即 ≤256KiB
- input ≤12MiB；markdown+reasoning合计 ≤4MiB；meta ≤24MiB+64KiB；header ≤64KiB；roleResponse ≤16MiB；仍至多32角色
- 原 Direct commit 总128MiB上限保持。本片 pending 为“冻结 commit + 必须保留的原件 ≤128MiB”，并不承接每个本来能单独保存的128MiB commit

本片在封存完成包和实际保存前验证必要内容覆盖，不凭“有 chapter”推断可以释放原件。原件在 pending 生命周期仍保守保留，因此上述合计上限不变；超限会保留旧 active 全部原件。原件读取 seam 可供后继完整导出，但本片没有新导出UI。

JSON opaque 数据保留孤立 UTF-16 代理项的 JSON escape。raw UTF-8 reasoning 本身无法编码孤立 UTF-16；比较采用与现 TextEncoder 相同的替换语义，不声称可从 U+FFFD 反推原孤立项。正常有效 Unicode/换行字符串精确一致。原请求 envelope、SSE id/event 壳及重复角色响应壳仅供恢复；必要内容已证明覆盖后随成功 pending 删除，无永久 raw archive。

尚未接 Hosted telemetry：后继应把已有 `DesktopArenaHostedTelemetrySchema` 的 aiModel/usage/narrativeHistoryReadCount 窄投影到既有 cardSnapshot.aiModel/aiUsage/narrativeHistoryReadCount，不添加任意 metadata 袋。展示 adapter 应从 reportJson 组回旧视图要求的 debug.meta，当前尚未接两页显示。以上是存储底座范围，不是完整 Hosted 恢复。

磁盘页、WAL、备份、最终故事库和进程 RSS不受384MiB逻辑预算限制。allocation/commit/backup按已知字节做 available-space 提前检查；不引入未测的固定余量，SQLite full/I/O仍须保守处理。没有把增量落盘说成零拷贝或4MiB RSS上限。

## 原子性与恢复

- begin幂等匹配原 manifest；seal把旧active删除、新revision发布和T→P额度转移放在同一连接锁和事务内。失败保旧，已发布token可精确查询，不发布半个候选
- 原actor/request/输入摘要/写选项/IDs/时间/CAS基线不随页面或账号改变。已封存原件不能改摘要；已采纳角色不换结果；冻结commit不得重新组装
- save前必须先调用 prepare-save，耐久写入本次 attempt，并返回仅本进程可单次消费的attempt ID；最终事务原样写章节/checkpoints/receipt与删除该exact pending。重启留下的attempt视为unknown，仅查原精确receipt，缺失/读取失败/身份或digest不匹配不授予重传或再提交权限
- 当前进程内、已明确回滚的单次保存失败，只有其自身attempt可耐久清除；已有unknown不被后来错误抹掉。成功但回执失联时pending可以已删除，原operation/session的exact receipt仍可查询
- precommit失败显式调用并检查 rollback，只有成功证据才能清同一次attempt；rollback失败仍为unknown。共享 `lock_connection` 拒绝继承非autocommit连接，防止残留事务中的未提交receipt成为假成功或其他store继续混写；不自动重建/重开数据库。既有store-failure或story-commit-unknown代码携带安全重启诊断，重启后仍只查精确receipt。
- restore在既有journal committed之后、清intent之前，幂等写pending-fenced：恢复库中的active标记 restored。旧备份中缺少后来receipt不证明从未提交，禁止自动save；恢复的模型意图也不能作为再次create许可。允许保留/读取原件，显式恢复另存动作留后继
- 正常启动只清未发布upload；active不会因坏数据、超限或无法验证而被静默删掉

本片不包含任何 model/role POST，因而测试不会把“无网络代码”冒充真实重试次数或Hosted端到端验证。后继transport/owner必须另外证明模型创建未知只原request lookup/resume、已采纳role不重复POST、普通create不能覆盖pending占用的原product秘密槽。
