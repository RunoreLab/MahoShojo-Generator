# 桌面端情景卡加载兼容性修复

## 定位

本次没有取得用户报错原卡；以下结论来自当前源码对比及合成旧卡回归，不能据此断言所有用户报告都属于同一原因。

Arena 网页端原 `apps/web/components/arena/utils/schemas.ts` 使用消费 schema：非空 title、宽容的 elements 与 passthrough。桌面端 `apps/desktop/src/features/arena/input.ts` 却使用 `domain/data-card-schemas` 的完整编辑 schema。

由此产生两种差异：

- 网页接受的旧字段形状（如 `elements.events` 数组、`elements.scene` 字符串）在桌面被拒绝；结构化卡顶层扩展也可能触发拒绝。
- 即使完整编辑 schema 校验成功，其解析输出会裁剪嵌套扩展和 metadata 中的作者等字段，影响原文完整性与已有签名内容。

魔法茶会也存在同类差异：网页按共享模板识别规则消费原卡，桌面额外使用编辑 schema 校验情景已知字段，拒绝旧字段形状或扩展版本的 `_battle_story`。

可复现样例：

```json
{"title":"旧卡","elements":{"events":["事件一"],"scene":"旧场景"}}
```

## 修复范围

- 将网页 Arena 的消费 schema 原样提取为 `@mahoshojo/domain/arena-scenario`，网页与桌面直接共用，覆盖桌面的文件、粘贴、预设、主/辅助情景卡库和排位准备入口。
- Arena 原文中的嵌套扩展及 metadata 不再经过编辑 schema 裁剪；保留网页既有通用情景 `name` 到 `title` 的兼容归一化。
- 茶会沿用共享 `inferDataCardTemplate` 识别情景并保留原卡，不再对情景施加编辑 schema；保留原有标题检查、通用情景别名与整批预检后才分配 ID 的行为。角色校验没有改变。
- 保留 Arena 12 MiB、茶会 4 MiB、安全 JSON 及茶会 Unicode 检查。导入成功不表示签名通过验证，扩展字段仅作为内容保留。

本次遵循 [Desktop 产品共源决策](../decisions/2026-10-02_184000_Desktop产品架构与Web共源决策.md) 中共享规则、保留已有签名且不伪造信任的要求。不改 wire contract、持久化格式、生成/编辑输出 schema 或服务器鉴权。

## 验证

实际通过：

- Desktop 5 个定向测试文件，共 59 项：Arena 消费兼容、主辅卡库选择、草稿恢复、生成正文投影、既有高级输入及茶会导入。
- Web 共源回归测试 3 项，确认共享 schema 实例、旧格式与字段保留及通用别名行为。
- Desktop、Web 的 `typecheck:build`；domain 的 `build`（类型检查）。
- 改动源码及测试的定向 ESLint；workspace boundaries；`git diff --check`。

未执行完整 CI、Native/Rust 测试、Windows 安装包界面验收或用户原卡实测。未修改 Native、环境变量、数据库或发布配置；无迁移及服务端部署要求。Desktop 用户需使用后续包含此修复的构建，当前已发行安装包不会因源码提交自动更新。
