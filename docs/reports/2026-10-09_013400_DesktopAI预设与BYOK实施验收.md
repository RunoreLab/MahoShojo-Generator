## 产品与存储

- `ProviderTarget` 严格区分 system、preset(providerId)、custom(profileId)，不按 URL/显示名猜测身份
- overlay v5 分别保留 `clientTarget` 和 `serverTarget`；v2/v3/v4 完整受检迁移，旧 `clientConnectionId` 仅作为兼容投影，不继续建立第二个持久 writer
- 预设模型/参数按 `presetsByProviderId` 隔离；旧 Profile、旧模型字典和凭据引用保持，不自动转为预设
- 新手填模型 ID 采用共源 trim/200 UTF-16 单位/控制字符约束；旧自定义连接合法 201–256 字符模型保留读取与执行，不能新建超限值或截断旧值
- Web 与 Desktop 共享手填模型控件、目录归一化及供应商表单；预设模型直接显示，只有显式新建/复制才创建自定义连接
- 预设 Key 只驻留易失草稿或 OS SecretStore；首次生成执行写入、存在性确认，再进行一次派发；设置提供状态、更换和清除，不读回明文
- Key 保存、查询与生成准备有单飞/迟到响应保护；取消准备只阻止尚未派发的生成，不承诺回滚已完成的 Key 写入
- Desktop 取消冗长执行通路说明，同时保留简洁准确的 Key 接收方披露

## 执行与安全

### 可信预设目录

Rust 消费由 ai-core 单一目录生成的受检清单，检查项进入 workspace 门禁。脚本使用已有 esbuild 在内存中打包真实目录依赖，避免 Node 原生 TS 与 bundler 路径解析不同而漏检。目录变更不靠人工维护第二套供应商表。

Direct 仅接受已核验 wire 与当前 native adapter；模型级禁止优先于供应商默认。DeepSeek 等既有别名转换也来自同一目录规则，只作用于预设，不改写自定义连接任意模型。

### 凭据用途隔离

安全审查发现旧 custom Profile 的自由 secret 引用可能指向账号会话；新增预设后也可能指向预设 Key。仅保存时过滤不足以保护历史/恢复数据，因此以下边界同时生效：

- custom 的预检、写入身份、读取执行及删除清理拒绝内部会话和预设保留命名空间，包括大小写变体与 secret header 引用
- 供应商凭据 IPC 不允许操作账号会话；预设凭据必须准确匹配当前目录身份；cloud 自身正常登录/读取/退出不受底层统一封禁
- 最后 `SecretStore.resolve` 前按 native 私有 `CredentialPurpose` 再验用途；trusted preset 重新核对目录目标、adapter、准确引用、零重定向及 header 限制，不能通过伪造 Profile ID 取得例外
- 不自动清理或改写可疑旧记录；正常旧自定义凭据继续可用；测试仅使用受控假数据，没有读取或传输真实账号凭据

攻击回归已确认旧入口接受、修复后三个解析/存储入口均拒绝；完整 native 测试进一步执行保存、请求、取消、重复注册和 Key 快照边界。

### 固定 Hosted BYOK

`presetConfig` 与 `systemConfig` 互斥，前者只声明目录 provider/model/生成参数。Native 在首次网络 await 前读取凭据并冻结请求快照，沿固定 origin/route 发送 Web 同形载荷；renderer 不能提交任意 Endpoint、secretRef、明文 Key 或 customProvider。

保留并复用上游严格参数规范化、8 KiB 覆盖预算、缺省/null 区分与最终注入后 body 大小复核。固定 origin 不自动跨站重定向；服务端仍独立按项目目录解析。错误字段名、失败 body/diagnostics 使用安全投影，不回显凭据。请求 ID 在兼容探测前登记，避免探测期间的重复点击派发。

签名继续由实际业务许可和服务端响应决定，不根据“BYOK”或执行位置自行增加或删除官方签名。
