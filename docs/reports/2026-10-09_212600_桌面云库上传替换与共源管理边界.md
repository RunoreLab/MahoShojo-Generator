## 现状、共源与宿主地图

- Web `SaveToCloudButton` 和角色管理使用 `ui-web/cloud-save` 的真实 `SaveCardModal`、`DataCardsModal`、`EditCardForm`、`ReplaceCardModal`。Desktop 通过相同组件提供上传、已有卡列表和替换确认，不另写平行模态 UI。
- Desktop 六个完成结果入口复用 `DesktopCloudCardActions`，保留兼容组件名 `PrivateResultSave`。字段默认私有，用户可选择公开；保存和替换本身都不改动本地结果。角色管理通过宿主装配同一操作面，列表读取、完整正文读取和导出分别注入端口。
- 创建规则仍唯一归 `createDataCardForUser`；新安全替换与 legacy PUT 共同调用 `updateDataCardForUser`。用户类型、作者注入、1 MiB 单卡上限、槽位、敏感词、问卷 `nativeAllowed`、公开审核、豁免与管理员分支沿既有 Web 语义。
- Web 保留认证存储、cookie、导航和浏览器文件能力；Desktop 保留窄 IPC、冻结 Native cookie、原生关闭守卫和本地库。共享组件不导入 Next/Tauri 或秘密。
- 管理列表与真实 Web 详情接入同一模态焦点栈；补齐实际详情叠层 Tab 回归。摘要的指标响应遗漏某个 ID 时记为未知，避免无限重查。

## 最小写入合同

### 新建

`data-cards.create` Native 路由现在固定为 `POST /api/data-cards/create-owned`，不再落旧 POST。调用方必须冻结 `expectedUserId`；Native 核对实际会话并注入正文所属账号。新建默认 `isPublic: 0`，表单可选 `1`。在线协议支持既有四种类型，页面只提交自己真实支持的结果类型，不能凭此宣称所有工具页都已接通云写。

成功仅接受 201、`success: true`、有效 ID、`accountFenceVersion: 1` 和匹配的 `ownerUserId`。Web 既有 guarded 创建与 Desktop 同样不向旧接口降级。

### 选择和替换

1. 用户从“我的数据卡”明确选择同类型目标；来源正文在原操作作用域冻结
2. `GET /api/data-cards/replace-owned?id=…&expectedUserId=…` 单次鉴权后，只读当前账号的未删除卡。返回 ID、类型、名称、描述、可见性、审核状态、有无待审版本和 opaque `version`，不返回此用途不需要的卡片正文
3. 共源确认框明确保留目标 ID/名称/描述/公开状态，并提示现有待审版本及服务端最终审核决定
4. `PUT /api/data-cards/replace-owned` 只接受 `id`、`type`、`expectedVersion`、完整 `data`、`expectedUserId`。服务端重新验证实际账号、所有权和类型，客户端不能借此改目标类型、元信息或公开状态
5. 返回 200、所属账号/fence、`replacementVersion: 1`、匹配 ID 和明确 `pendingReview` 才算确认成功。待审核成功只说“已提交审核”，不说线上正文已生效

普通用户替换 approved 卡时，待审行的名称/描述采用主卡元信息，与原 Web 替换行为一致；不偷偷使用先前待审稿的元信息。豁免/管理员及非 approved 卡仍沿原直写分支。`-1` 封禁状态通过原始整数读取，不被 Drizzle boolean adapter 变成 `true`；正文替换不会解封。

## 原子性和明确限制

`version` 是服务端生成的 SHA-256 状态摘要，覆盖主卡正文、名称、描述、类型、owner、公开/审核状态、时间及待审行实际字段。它不是单调操作序号；同内容、同秒写入不保证变更版本，也不提供 exactly-once。

- 直写用一条 `UPDATE … WHERE`，把正文和目标名称/描述一并写入；条件同时检查主卡和观测到的待审版本
- 待审写用一条 `INSERT … SELECT … WHERE` 加显式 `ON CONFLICT(data_card_id) DO UPDATE`，完整快照条件在同一语句内覆盖插入和冲突更新分支。nullable 字段采用 null-safe `IS`；待审 absent 与 present 分开约束
- 变化发生在预检之后，SQL 仍返回零行并映射为 `409 TARGET_CHANGED`。账号不符返回 `409 ACCOUNT_MISMATCH`。这两种情况不会触发 metrics、严格排位重置或自动审核
- 只有成功 CAS 后才执行原后处理；后处理不是 CAS 事务的一部分。旧 metrics 的时间戳竞争、跨卡总配额并发及 legacy 无围栏写入不因本片被宣称全部解决
- 未增加数据库列、迁移、持久幂等表或分布式锁。实际 D1 Drizzle adapter 单语句的参数数目小于 100，SQL 文本小于 100 KB；1 MiB 产品正文上限和既有 2 MiB Native transport 上限保持不同职责

## 生命周期、错误与兼容

账号 ID/凭据世代、来源类型/正文和表单被同一作用域持有。同步 ref 锁防重复点击；换账号/来源、取消选目标或关闭读取窗口后，迟到结果不能显示在新作用域。保存中禁止通过关闭、Escape、遮罩或离开守卫退出写入；取消等待不代表撤销服务器写入。

400/401/403/413/429 及已确认的 owner/target conflict 保留输入。404/405 显示目标或安全入口不可用，不回退旧 POST/PUT。未知 409、5xx、网络/正文截断、异常 2xx 或不匹配 ack 都视为可能已经写入，零自动重放。新建须检查已有卡并显式确认再新建；替换须检查主卡及待审版本，再重新选择、获取新版本并确认。Native create/replace 同时禁用协议级 retry 和重定向；fenced 迟到 401 不删除新会话。

原私有副本组件与宿主页面重复注册原生关闭监听的问题在整合时修复：六生成页及角色管理均由页面唯一 `useLeaveGuard` 持有关闭/导航决策，云卡操作只通过同步 busy 回调贡献状态。真实路由测试按 Tauri 每回调独立默认 destroy 语义，覆盖旧结果再生成、云写、拒绝离开确认、空闲关闭和 StrictMode 迟到事件；不再以多个监听中任意一个 preventDefault 当作全部安全。

公开列表、标签、公开指标等仍按 Optional 路由匿名可读；账号围栏只加在“我的”、收藏、卡组和本次写入对应路径，不用旧账号快照阻断公开读取。

新路径属于 Next/OpenNext 数据卡业务部署，并非新增 Hono 生成服务能力。新客户端遇旧服务端安全保存不可用且保稿。旧客户端继续使用 legacy 入口，其账号和目标版本保证不会自动升级；生产部署和默认分支由维护者另行执行。
