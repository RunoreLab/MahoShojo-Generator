## 1. 确认的根因

维护者报告新增桌面内容的首页 Logo 缺失及样式与 Web 不一致。本轮没有收到截图，以下结论来自真实代码、资源生成输出、修前生产 CSS 和页面 DOM，不把它们写成实机视觉验收。

1. `/character-party` 与 `/card-forge` 已进入 Desktop 交付能力。共源首页目录分别引用 `party-white.svg` / `card-forge-white.svg`，但 `content/sync-manifest.json` 仍将两者列为 Web-only。实际 Desktop 内容生成没有输出这两个文件。
2. 两个共源战报卡实际渲染 `classic-mode.svg`、`daily-mode.svg`、`kizuna-mode.svg`、`scenario-mode.svg`。四文件仍只在 Web `public/`，未进入 Desktop 内容生成。
3. Desktop 在 Tailwind 前导入 Arena CSS，Arena 的 `@layer components` 提前建立了层次。修前生产 CSS 的首次层序为 `properties → components → theme → base → utilities`，Web 为 `properties → theme → base → components → utilities`。CSS 普通声明按层优先于选择器特异性：Desktop 较后的 base 通用 `padding: 0; border: 0 solid` 覆盖 components 的 `.input-field` `padding: 15px; border: 2px solid ...` 等声明。仅检查 class/token 存在会漏报这种错误。
4. 问卷编辑器 Desktop 标题和 Web 的 SVG 品牌标题分叉；卡牌工坊 Desktop 另写 `container !max-w-[1200px]`、旧标题及等宽两栏，Web 实际使用 `max-w-7xl`、独立标题间距与受限预览栏。

`/battle` 与 `/arena` 已实际消费 `BattleLitePageView` / `AdvancedArenaPageView`、`ThemeImage` 和共享报告卡。未发现需要另写一套页面或报告 Surface 的证据；本次保留它们，修复 CSS 与资源闭包。已有报告媒体、执行、保存及来源语义不变。

## 5. 同批整合的独立问题：数据卡模态背景滚动

维护者随后报告“我的数据卡”弹窗触屏滑动会带动角色管理背景页。此问题独立于上文 CSS 层序，修片 `59e8b240a` 经独审后以 `7765a66e3` 合入同一候选，未扩展数据卡权限或写入行为。

- 原共享生命周期只锁 body；Web 根元素本来有 `overflow-x: hidden`，不能依赖 body overflow 传播完成视口锁。现在在第一层打开时同时锁 html/body，最后一层关闭时按原声明顺序和 `!important` 还原滚动属性，不覆盖其他样式；嵌套 / 非顺序关闭保持引用计数。
- “我的数据卡”把可滚动容器从 fieldset 拆为能在 flex 中收缩的普通 div，fieldset 继续只负责 busy 禁用。容器增加可键盘聚焦的 region 与 overscroll containment，标题不收缩，面板使用动态视口高度上限；BaseModal / 公共卡库共用正文布局。
- 初始和返回焦点使用 `preventScroll`，不固定背景位置，也不全局截获触摸事件。
- 故障片新增用例在旧实现确定失败；独立定向 103 项通过，覆盖共享生命周期 / 嵌套、真实 Web adapter 与 Desktop 角色管理写入。合入后本树重跑两个直接相关共享文件 22 项通过。
- 生产 CSS 回归追加两种 overscroll utility、动态视口高度以及品牌主题显隐的真实输出检查；构建验证与完整 CI 同上排队。

真实触屏浏览器 / Windows 仍未执行。需打开“我的数据卡”并在列表中、列表上下边界、嵌套详情内滑动，确认背景不移动、正文可滚动；关闭详情与父弹窗后确认背景滚动和位置正常。取消、Escape、重复开关、busy 操作期间的禁用也须实机抽查。
