## 有界字段与真实 owner

- Desktop Creator：既有草稿中的 `imageSaveMode`、`jsonSaveMode`、`showDetails`、`allowMultipleQuestionnaires` 可修改/重置。`language` 与 `generationMode` 只读、不重置；模式与模板联动仍归页面。首写复用页面初值 `template: general`、`generationMode: stream`。
- Web Creator：沿用 Details 偏好 owner，不另设存储键；设置说明明确同时作用于两个工作台。
- Scenario 双端：只登记 `isAdvancedVisible`。Desktop 使用既有草稿；Web 使用既有 page-draft 的 `payload.isAdvancedVisible` 为唯一权威，旧 preferences 同名字段仅作为缺字段时的迁移源。canonical 写成功才删除 legacy 同字段，其余内容保留；重置显式写 false，避免旧 true 复活。
- Sublimation 双端：`isAdvancedVisible` 与既有五项历史/状态策略。Desktop 重置必填策略为既有 `true` × 4、`keep-sublimation-only`。Web 保留两个现有 owner：general preferences 只手术展开字段；history-state preferences 只手术五策略，不清除未知扩展、指导语、问卷或保留字段。

## 实现与保护合同

Desktop 的首写工厂与页面共源；设置适配器使用真实 owner parser 作 validator，不把规范化输出用于写回。修改前重新读取并校验，保留非登记字段与原始结果。坏、未来版本、超限或不满足 owner 约束的文档拒绝写入，原字节不变。Web 无 version 字段的既有对象不新增版本语义。

Web Scenario 的迁移与设置写入复用同一 owner；原文档内容/扩展不因字段迁移丢失。canonical 保存失败不删除 legacy、不反转已经读取的偏好；legacy 清理失败时 canonical 仍权威，后续重试可幂等收口。canonical 缺失时，首写工厂只沿原页面已经读取的 title/mode/language/fields 初值兼容建立空壳，避免丢失旧选择；不删除这些 legacy 字段。显式 false 跨默认空草稿整理、页面自动保存和重复进入仍然存在；坏草稿页原有“仅清内存、保留坏原文”行为不变。
