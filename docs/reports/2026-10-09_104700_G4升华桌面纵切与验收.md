# G4 升华桌面纵切与验收

状态：代码与自动验证完成；真实 Windows/Tauri、本轮模型质量验收待补。目标分支 `feat/desktop`。本报告延续 DESK-PARITY-006 和唯一 Desktop 阶段计划，不替代 accepted ADR/spec，也不宣称完整 Arena 或全部 Web 特性已迁移。

## 交付及共享边界

Desktop `/sublimation` 已接通选卡、历史参考、目标模板/保留字段/语言与引导、生成、预览及另存。本地上传/粘贴、共享本地库/公开库选择器均保留原始卡数据；原卡不会被生成结果覆盖。结果可保存到本地库、导出及复制。页面使用现有草稿、取消、离开保护和凭据准备机制。

- `packages/ai-core/src/sublimation-generation.ts` 承载纯结构化与 Markdown 生成核；Web Hosted 实际回用。模型路由、服务端 finalize/签名不移入客户端。
- `packages/ui-web/src/sublimation/` 承载工作台布局及领域字段控件，Web/Desktop 同时消费。历史选择器沿用前片受控组件；宿主提供历史来源。
- Desktop 历史 adapter 读取本地库 history 卡并分页合成参考，不依赖账号、不搬迁 Arena store。读取失败与空库区分；未知格式留在原库并提示，绝不自动修复或删除。
- 执行位置与输出形式正交：客户端/服务器分别支持结构化与流式。流式保留原当前状态，不声称模型生成了结构化状态更新；相关控件明确提示。
- Native 只开放两个固定 Hosted 升华路径；各自预检最终序列化请求的 4 MiB UTF-8 字节预算，包括凭据配置注入后的正文。其他路由限额不变。这不是草稿的字符上限；合法超大卡仍可能超预算，明确报错，不截断卡片或历史。
- 卡库选择的 `rawSourceData` 与旧 battle 装饰 payload 分离，原卡 `_author`、嵌套下划线扩展等不被 UI 元数据覆盖；旧选择器消费者协议不变。

## 本轮发现并修复的共性问题

1. 流式读取开关过去未传到纯提示构建；关闭状态读取仍会发送状态，开启历史读取却可能漏发。现按开关构建提示，默认兼容旧行为。
2. 结构化转换到通用卡时，状态/历史可能已被序列化进 `content`；只删顶层字段不足以关闭读取。现只重建受读权限限制的提示内容，输出保真骨架不裁剪。
3. 保留扩展时区分已知重写字段、用户扩展和卡级/metadata 权威字段。新直接生成不继承原可信签名；不把任意嵌套用户字段误作权限。目标字段冲突、不可安全更新的旧状态与不可保真的历史结构，在模型请求前明确报错。
4. 历史 keep 策略保留未知根字段/attributes；reset-all 保持明确重置语义。原始非对象 metadata 等也不被静默丢弃。
5. Hosted 返回卡验证不使用会剥字段或填默认值的解析结果覆盖原始结果，避免破坏签名载荷。实际可信判定仍遵循现有服务端规则。

这些是有意的行为修复，不将其包装成完全无行为变化的文件搬迁。服务端代码尚未生产部署，线上端点不能视为已经采用本轮修复。

## Windows 本地 Agent 验收指令

在 `feat/desktop` 拉取本报告所在提交或其后代，记录准确 SHA 与工作树状态；保留用户未提交改动。使用隔离 app identifier、appData/WebView2 数据目录及仅测试用途的凭据命名空间，测试结束只清理本次创建的资源。不得读取真实凭据或调用生产模型。

1. 启动真实 `pnpm dev:desktop`，本机模拟 Hosted 服务与 OpenAI-compatible 服务分别返回受控 JSON/SSE；使用 dummy Key。先验证来源/执行目标显示，禁止把 mock 成功当真实供应商成功。
2. 准备含顶层、metadata、嵌套扩展、旧式 history/current_state 的原卡。本地文件/粘贴、本地卡库、受控公开库各选一次，核原始 JSON 未被 `_author` 等展示元数据覆盖；来源错误和未知历史卡有明确提示。
3. 四组合（客户端/服务器 × 结构化/流式）依次完成：选择原卡与参考、生成、预览、复制、导出、另存本地库、重新读取。核原卡不变、扩展按策略保留、直接产物不继承旧可信签名；流式状态更新限制明确。
4. 验证刷新/重启恢复草稿；损坏草稿不删除原文；取消、离开页面、迟到响应、重复点击、准备 Key 时切换控件、读回失败都不产生重复请求或覆盖旧结果。真实 OS 凭据仅可用新建 dummy 测试项，不接触现有项。
5. 在 mock 端核历史/状态读取关闭后请求提示无对应受控标记，开启后存在；验证最终 UTF-8 超预算在网络派发前失败（包括 Unicode 与 Native 注入），不截断数据。
6. 亮/暗、常用缩放及窄宽窗口截取源区、流式预览、结果保存区和历史弹窗；核键盘焦点、返回入口、滚动与共源字体。结果文件保存到仓库外，回报请求计数、实际视口/引擎、日志终态、通过/失败及未测项。

不要求 Windows Agent 提交产品源码；如发现问题，保留最小复现证据再修复。正常源码提交授权不等于生产部署授权。
