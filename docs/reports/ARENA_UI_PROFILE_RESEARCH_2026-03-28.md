# 竞技场页“怀旧 / 简洁 / 进阶”改版调研报告

- 日期：2026-03-28
- 状态：调研中结论稿，可作为后续产品讨论与设计评审底稿
- 结论先行：
  - 我不建议把“怀旧版 / 简洁版 / 进阶版”直接做成三个并列、长期共存的一等模式。
  - 更推荐把“简洁 / 完整”做成功能分层，把“怀旧”降级为一个视觉与交互预设，或作为“简洁版”中的一键回退样式。
  - 如果必须保留三档，也应明确区分：
    - 怀旧版：强调旧版视觉、窄宽度、线性流程。
    - 简洁版：强调当前推荐主流程，隐藏高级能力。
    - 进阶版：保留现在的完整能力集。

## 1. 背景与范围

近期用户反馈的核心不是“某一个具体功能不好用”，而是竞技场页相较旧版失去了原本的轻量感，第一次打开时更像一个面向重度用户的控制台，而不是“选角色 -> 选模式 -> 开始生成”的单线流程页。

本次调研基于以下范围完成：

- 当前实现：`components/arena/ArenaPage.tsx`
- 当前扩展能力：`components/arena/components/*`
- 当前持久化与交互基础：`components/arena/stores/useBattleStore.ts`、`components/shared/CollapsibleSection.tsx`
- 旧版参考：`master` 分支下的 `pages/battle.tsx`
- 宽度参考：`components/arena/utils/battleReportCardWidth.ts`

本报告未做外部用户访谈，也未做线上埋点分析；结论基于仓库现状、历史实现与信息架构比较。

## 2. 现状梳理

### 2.1 当前页的主体结构

当前竞技场主区采用双栏布局，外层宽度可达 `1380px`，主操作区同时并列多个模块，见 `components/arena/ArenaPage.tsx:156-181`。

当前主流程里实际可见的区块包括：

1. 使用须知
2. 预设角色
3. 在线角色库 / 随机匹配
4. 本地导入
5. 已选角色 / 分队
6. 模式选择
7. 情景设置（条件显示）
8. 排位与快速设置
9. 读写设置（历战 / 当前状态 / 叙事历史）
10. 故事引导 / 裁判 / AI 模型
11. 生成方式
12. 开始生成
13. 社区

代码证据见 `components/arena/ArenaPage.tsx:183-340`。

### 2.2 当前“复杂感”主要来自哪里

主观复杂感并不完全来自功能数量，而更来自以下几点：

1. **主流程与高级流程平权出现。**
   - `排位与快速设置`
   - `读写设置（历战 / 当前状态 / 叙事历史）`
   - `故事引导 / 裁判 / AI 模型`
   这些都出现在和“模式选择”“开始生成”同一层级。

2. **默认展开项仍然较多。**
   - `预设角色`
   - `在线角色库 / 随机匹配`
   - `本地导入`
   - `已选角色 / 分队`
   - `模式选择`
   - `故事引导 / 裁判 / AI 模型`
   这会让初次访问者立刻看到较大的信息密度。

3. **“故事引导 / 裁判 / AI 模型”混合了核心项与重度项。**
   `StoryOptions` 本身包含：
   - 故事方向引导
   - 字数偏好
   - 生成语言
   - 问卷 Lore
   - 裁判 / 随机判定
   - 自定义 AI 能力提供商

   这里面至少有一半并不是新手第一次生成必须理解的内容。

4. **连续战报会话默认展开，并且容器很宽。**
   `BattleStorySessionPanel` 在主区下方单独占据一个宽达 `min(1180px, calc(100vw - 2rem))` 的面板，且 `defaultOpen` 为 `true`，见 `components/arena/components/BattleStorySessionPanel.tsx:250-267`。  
   这虽然不一定属于“主生成流程”，但会显著增强页面“功能平台化”的观感。

### 2.3 当前页已经有一定“渐进披露”，但还不够

当前已经存在折叠区机制，且折叠状态按 `localStorage` 单独持久化，见 `components/shared/CollapsibleSection.tsx:27-87`。  
这说明项目并不是完全没有“收起高级功能”的基础能力，只是当前的信息分层还不够克制。

## 3. 旧版为何会被认为更简洁

`master` 分支旧版 `pages/battle.tsx` 的主流程非常线性，核心顺序大致是：

1. 使用须知
2. 预设角色
3. 上传 / 粘贴设定文件
4. 已选角色
5. 模式选择
6. 等级选择
7. 故事方向引导
8. 开始生成

见 `master:pages/battle.tsx` 的 `586-740` 行附近内容。

旧版简洁感主要来自以下几个特征：

1. **单列线性流程。** 用户不需要在左右两栏之间来回扫视。
2. **心智模型单一。** 页面目标非常明确，就是“准备参战角色并开始生成”。
3. **功能边界更窄。** 没有在线角色库、情景主/辅结构、问卷 Lore、裁判设置、读写设置、生成方式切换、连续战报、战报插图等现代扩展项。
4. **视觉宽度更紧。** 旧版阅读与操作节奏更像一个“卡片式工具”，而不是一个控制面板。

## 4. 功能膨胀并非单次失控，而是持续叠加

从 `git log -- pages/battle.tsx pages/arena.tsx components/arena` 可见，复杂度是多轮功能叠加带来的：

- `b79b2318`：预设情景
- `41441c05`：战报可参考问卷卡设定
- `48430fe5`：流式传输策略开关
- `7301a4ed`：战报插图主链路
- `6dfd5dfc` / `bda1dc6f`：连续战报会话
- `e07cf981`：战报卡片宽度设置
- `041f805e` / `0fd99fcb`：竞技场大屏布局优化

这些能力本身大多合理，问题在于：

- 功能保留了；
- 主入口也保留了；
- 但缺少一轮新的“信息架构收束”。

所以用户现在抱怨的不是“某个高级功能不该存在”，而是“高级功能没有退到恰当层级”。

## 5. 对“三模式切换”方案的评估

## 5.1 这个方案的优点

你的方案有三个明显优点：

1. **直面用户反馈。** 它不是抽象优化，而是明确承认“用户对简洁感有需求”。
2. **不需要删除高级能力。** 这比直接砍功能安全得多。
3. **新用户默认简洁版是正确方向。** 这能优先解决第一次打开时的压迫感。

所以我认为：  
**“通过模式切换给不同用户不同密度的竞技场页”这个方向是成立的。**

## 5.2 这个方案的主要问题

问题不在“要不要分层”，而在“是否需要三个并列档位”。

### 问题一：怀旧版与简洁版重叠过多

你当前定义里，怀旧版与简洁版高度相似：

- 都保留：使用须知、在线角色库、本地导入、已选角色、模式选择、自定义 AI 提供商、生成方式、开始生成、社区
- 差异主要集中在：
  - 情景能力的呈现方式
  - 是否保留“故事方向引导”
  - 是否应用旧版视觉和宽度

这说明“怀旧”和“简洁”并不是两个完全独立的产品人格，更像是：

- 一个是**功能分层**
- 一个是**视觉/交互风格偏好**

把这两者混成并列模式，会导致概念不清。

### 问题二：模式含义不够直观

新用户不一定能理解：

- “怀旧版”和“简洁版”到底差在哪
- 为什么怀旧版反而没有故事方向引导，但简洁版有
- 为什么怀旧版保留自定义 AI 提供商和生成方式，却又称“怀旧”

如果模式语义不直观，用户会把它理解成“开发者额外加了一个设置页”，而不是“产品在主动帮我降噪”。

### 问题三：会放大维护和测试矩阵

如果三档模式都长期存在，后续每次往竞技场主流程加一项能力，都要回答：

- 哪些模式显示？
- 默认展开还是折叠？
- 文案是否不同？
- 使用须知是否要跟着变？
- 老用户切换后是否要迁移状态？

这会让后续维护成本持续上升。

### 问题四：把“复杂度”从页面转移到模式本身

如果最终是：

- 页顶多一个模式切换控件
- 切换后只是隐藏一批区块

那用户看到的很可能不是“更简单”，而是“这个页面现在又多了一个要理解的系统”。

所以，三模式方案要成立，必须确保模式本身非常自然、差异清晰、长期维护成本可控。

## 6. 我的建议：功能分层与怀旧风格分离

## 6.1 推荐方案

我更推荐下面这个结构：

### A. 一级分层：`简洁版 / 完整版`

这是**功能密度分层**，真正解决“复杂感”问题。

- `简洁版`
  - 面向新用户与轻度用户
  - 默认只显示主生成流程
  - 高级能力收起或移到二级入口

- `完整版`
  - 面向老用户与重度用户
  - 保留当前完整布局与高级能力

### B. 二级预设：`怀旧风格`

这是**视觉与交互预设**，不应与功能层级混为一谈。

怀旧风格可以包含：

- 500px 主操作区宽度或 500px 结果卡片宽度
- 更接近 `master /battle` 的单列节奏
- 更克制的说明文案与视觉装饰
- 更偏线性的操作顺序

也就是说：

- “简洁 / 完整”回答的是：**你要看多少功能**
- “怀旧”回答的是：**你希望页面像以前那样怎么呈现**

这样更符合用户直觉，也更利于后续维护。

## 6.2 如果你坚持三模式，我建议重定义

如果产品上坚持保留三档，我建议不要直接沿用现在这组含义，而是改成：

1. `怀旧版`
   - 单列
   - 窄宽度
   - 情景能力降为旧式表达
   - 不展示故事长度、语言、Lore、裁判、读写设置、排位快捷设置
   - 强调“像以前一样快速开打”

2. `简洁版`
   - 当前推荐主流程
   - 保留情景设置、故事方向引导、自定义 AI 提供商、生成方式
   - 隐藏 Lore、裁判、排位、读写设置、连续战报等高级能力

3. `进阶版`
   - 当前完整形态
   - 保留所有能力与当前大屏布局

也就是说，三档必须形成稳定梯度：

- 怀旧版：旧手感
- 简洁版：新手感，但更轻
- 进阶版：完整控制台

不能只是两个相近模式再加一个完整版。

## 7. 对你当前功能清单的具体看法

## 7.1 简洁版方向基本可行

你给出的简洁版列表整体方向是合理的，因为它保住了以下关键链路：

- 角色来源
- 已选角色与分队
- 模式选择
- 情景能力
- 故事方向引导
- AI 提供商
- 生成方式
- 开始生成

这基本覆盖了“普通用户真正关心的设置项”。

我唯一的保留点是：

### “预设角色”是否真的要从简洁版里消失？

当前 `ArenaPage` 里有一个独立的 `预设角色` 区块，且旧版 `master /battle` 也有预设角色入口。  
如果简洁版完全拿掉预设角色，可能会影响：

- 首次试用时的快速体验
- 没有本地文件的新用户上手

所以我建议不要直接删除，而是：

- 方案 A：并入“角色来源”区块，做成标签页
- 方案 B：作为次级入口收起，但仍可见

## 7.2 怀旧版方向也成立，但更像“旧流程预设”

你给出的怀旧版与简洁版最大的差异在于：

- 情景入口更接近旧式“选择情景 / 上传情景文件”
- 不保留“故事方向引导”
- 宽度和视觉参考旧版

这说明怀旧版真正承担的是“旧流程回归”，而不是单纯“比简洁版更简洁”。  
这进一步证明：怀旧版更像一个**预设皮肤 / 旧流程模板**，而不是必须与简洁版平级存在的长期功能模式。

## 8. 建议的信息架构重排

下面是我更推荐的主流程结构。

## 8.1 简洁版

建议主流程按下面顺序组织：

1. 使用须知
   - 补充版本切换说明

2. 添加角色
   - 在线角色库 / 随机匹配
   - 本地导入
   - 预设角色（建议并入，不再独立占一个面板）

3. 已选角色 / 分队

4. 模式选择

5. 情景设置
   - 仅在情景模式下显示

6. 故事方向引导

7. 自定义 AI 能力提供商

8. 生成方式

9. 开始生成

10. 社区

默认隐藏的高级项：

- 排位与快速设置
- 读写设置（历战 / 当前状态 / 叙事历史）
- 问卷 Lore
- 裁判事件
- 字数偏好
- 生成语言
- 连续战报会话

## 8.2 怀旧版

怀旧版建议做成：

- 单列
- 主操作容器 `500px ~ 560px`
- 视觉参考 `master /battle`
- 情景入口简化为：
  - 选择情景
  - 上传情景文件
- 不展示故事方向引导
- 不展示排位、读写设置、Lore、裁判、连续战报

这里要特别注意：  
如果“500px”指的是**整个主操作列宽度**，那么在线角色库、已选角色 / 分队、AI 提供商这些现代组件会明显变得更拥挤。  
因此需要尽早确认：

- 是只让结果卡片宽度恢复 `500px`
- 还是让主操作列也恢复到 `500px`
- 还是仅在桌面端应用窄宽度

当前代码里已经存在 `LEGACY_BATTLE_REPORT_CARD_WIDTH = 500`，见 `components/arena/utils/battleReportCardWidth.ts:7-13`。  
也就是说，“战报卡片宽度回到旧版”是现成的；“整个主表单回到旧版宽度”则需要额外设计。

## 8.3 进阶版

进阶版可以基本保持当前结构，但建议仍做两点收束：

1. `BattleStorySessionPanel` 默认改为折叠
2. `故事引导 / 裁判 / AI 模型` 继续拆分出“核心”与“高级”

否则进阶版会继续放大“控制台感”，也不利于老用户逐步理解功能边界。

## 9. 即使不做模式切换，也值得立即执行的低风险优化

如果你想先做一轮低风险试探，而不是直接上完整模式系统，我建议先做下面几项：

1. **把连续战报会话默认改为折叠。**
   - 当前它默认展开，且视觉占比太大。

2. **拆开“故事引导 / 裁判 / AI 模型”。**
   - 核心项保留：故事方向引导、自定义 AI 提供商
   - 高级项收起：裁判、Lore、字数、语言

3. **把“预设角色 / 在线角色库 / 本地导入”重组为一个“添加角色”大区块。**
   - 当前左栏四块同时展开，视觉噪音偏大。

4. **把“排位与快速设置”明确标成“仅排位玩家使用”。**
   - 现在虽然已标“高级”，但仍处在主流程层。

5. **在使用须知里直接写明：**
   - 新用户默认简洁模式
   - 老用户可切换完整版 / 怀旧风格

这五项即使未来不继续推进三模式，也大概率是增益。

## 10. 可行的实现与状态策略

## 10.1 技术上可行

当前竞技场配置已经通过 `zustand persist` 持久化，见 `components/arena/stores/useBattleStore.ts:57-118` 与该文件后半段的 `partialize`。  
这意味着新增一个 `uiProfile` 或 `viewMode` 字段在技术上没有障碍。

同时，各折叠区自身也在用 `storageKey` 记忆开合状态，见 `components/shared/CollapsibleSection.tsx:27-87`。

## 10.2 需要注意的问题

### 不要让“模式切换”直接覆盖用户已有折叠记忆

当前每个区块都独立记忆开合状态。  
如果模式切换时直接把这些状态重置，很可能出现：

- 用户切回完整版后发现自己原来的展开习惯丢了
- 老用户感知为“页面变得不听话”

更稳妥的做法是：

1. 用单独的 `uiProfile` 控制“哪些区块可见”
2. 在可见区块内部，继续保留原有折叠记忆
3. 仅在首次访问且无旧配置时，应用默认模式

## 10.3 新老用户分流建议

建议策略：

- 新用户：默认 `简洁版`
- 老用户：保留当前完整体验，或在首次进入时提示选择

这样可以避免你为了照顾新用户而伤害已经适应现状的老用户。

## 11. 建议的决策顺序

我建议不要立刻讨论“最终 UI 长什么样”，而先把下面三个决策钉住：

1. **先确认目标优先级**
   - 是优先降低首次打开压迫感
   - 还是优先给老用户一个“回到过去”的入口

2. **再确认模式结构**
   - 两层：简洁 / 完整 + 怀旧风格
   - 还是三层：怀旧 / 简洁 / 进阶

3. **最后确认怀旧的边界**
   - 只复刻视觉宽度
   - 还是连信息结构也回退

只有这三个问题明确了，后续实现和测试才不会反复返工。

## 12. 我当前的最终建议

基于现有代码与历史版本，我的建议是：

1. **优先目标应定为：降低首次打开压迫感。**
   - 这是最广义、最稳定、最容易验证的问题定义。

2. **模式设计优先采用：简洁版 / 完整版。**
   - 新用户默认简洁版。
   - 老用户保留完整版。

3. **怀旧不要先做成长期并列的第三模式。**
   - 先做成视觉/交互预设，验证用户是否真的在乎“旧风格”，还是本质上只是在抱怨“默认太复杂”。

4. **立即执行一轮低风险减负优化。**
   - 连续战报默认折叠
   - 拆分故事区块
   - 合并角色来源区块

如果这一轮做完，用户抱怨显著下降，那么说明真正的问题是“默认暴露太多”；  
如果抱怨依旧集中在“还是没有以前那种感觉”，那时再投入“怀旧预设 / 怀旧版”会更稳。

## 13. 待确认问题
