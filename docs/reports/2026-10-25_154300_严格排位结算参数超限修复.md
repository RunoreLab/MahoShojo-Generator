# 严格排位结算参数超限修复

状态：首轮修复已上线。下文保留首次提交时的排查与待授权方案；实际授权、发布、积压恢复和后继保护见
[排位生产发布与历史结算恢复](./2026-10-25_161500_排位生产发布与历史结算恢复.md)。

## 故障与证据

2026-10-25 用户报告排位不计分、页面长时间显示「结算中」。本轮只读检查 Hono 容器状态、
有界日志与 D1 聚合状态，未执行生产部署、生产数据写入或凭据变更，未读取 SSH 私钥正文。

排查时 D1 中当月严格排位有 146 条 `pending`；自 10 月 20 日起的 65 条严格排位 `pending`
均已保存计算结果，其中 59 条双方当前评分和场次仍同时匹配事件的 before-state。
同时自由排位仍有成功事件。这表明异常集中在严格排位评分写入，不能据此把所有历史积压
都判定为同一原因，亦不能仅凭 before-state 认定旧局现在仍有资格计分。

`applyArenaRatingsUpdateIfBothMatch` 把两名参战实体的身份条件重复绑定到每个更新字段。
严格排位还需更新六个赛季极值字段，来源与事件 guard 加入后，正常 UPDATE 达到 117 个绑定参数；
去掉 `last_delta` 的兼容重试仍有 110 个。Cloudflare D1 每条语句上限为 100 个绑定参数，
两个分支都无法执行，事件停在 `pending`，上层结算重试仍然失败。

本轮在生产 D1 执行的合成 **SELECT** 分别使用 117、110、93 个参数；前两者返回
`too many SQL variables ... SQLITE_ERROR`，93 个成功。该验证不修改业务表。
平台依据：[Cloudflare D1 Limits](https://developers.cloudflare.com/d1/platform/limits/)（2026-10-25 核验）。

## 修改与不变量

只调整 Web 的评分 repository，不改变 API、schema、持久化格式或 Hono 生成流程：

- UPDATE 的 WHERE 已限定 queue 与双方精确的 `(entity_type, entity_id)`，字段 CASE 因而只需判断 A，
  其余命中行取 B 的值。复用该表达式将正常严格排位语句降为 93 个参数。
- 保留双方 before-state CAS、完整事件 pending/computed 条件和双方来源全文、版本、权限 guard；
  保留同一条 SQL 同时更新双方的边界，不拆成两次评分写入。
- 保留完整分数、胜负场次、最近分差、赛季极值与段位晋升刷新，以及旧 schema 的无 `last_delta` fallback。
- 公共 `generation-ranking` GET 继续只读，不因页面轮询触发计分。

适用边界沿用 [平台主题](../topics/2026-08-22_022000_平台重整与本地优先架构.md)、
[G25R 终态整改规格](../specs/2026-08-25_205143_G25R可恢复Arena生成审查整改设计.md)
与 [Hono 排位实体来源绑定说明](../../apps/api/README.md#排位实体与参战正文绑定)。
本次不改变终态协议、幂等键、来源信任或既有评分与事件标记分步持久化的限制。

## 实际验证

先给既有真实 SQLite proxy 测试施加 D1 的 100 绑定参数上限，修复前观察到 8 项因超限失败，
兼容分支明确报出 110。修复后再扩充回归覆盖：

- 严格排位与 Free owner 来源校验、同时间戳改正文、版本/可见性/审核/删除/所有者变化；
- 混合 preset/data_card 使用相同字符串 ID 时仍按实体类型分流，其他实体和其他 queue 的行不变；
- 已应用/跳过事件、缺证据恢复、computed 冲突与来源校验竞态；
- 实际持久化的双方分差、场次和赛季极值，以及缺少 `last_delta` 时的兼容重试。

在 `apps/web` 运行：

```text
node node_modules/vitest/vitest.mjs run tests/arena-ratings-identity-cas.test.ts tests/arena-ratings-write-season-peak-tier.test.ts tests/arena-ratings-settle-retry-promotion.test.ts tests/arena-ratings-entity-binding.test.ts tests/arena-ratings.test.ts tests/arena-generation-finalization-internal-route.test.ts tests/generation-ranking-read.test.ts --reporter=dot
```

结果：7 个文件、101 项通过。Web `tsconfig.build.json` 的 TypeScript 无输出检查通过；修改的 repository
与测试文件 ESLint 通过。未运行完整 workspace CI、Next/OpenNext 构建或真实付费对局；源码验证不代表已上线。
