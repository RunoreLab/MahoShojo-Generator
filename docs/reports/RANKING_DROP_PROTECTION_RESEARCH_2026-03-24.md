# 排位掉分挫败感问题调研与方案建议（2026-03-24）

状态：讨论稿 / 产品决策备忘录  
调研时间：2026-03-24  
适用范围：当前项目的 strict / free 角色卡排位系统

> 说明：本报告按“产品策略决策备忘录 + 可落地规则草案”整理，重点回答一个问题：当用户觉得“自己辛苦把角色打上去，过段时间却被不知道谁打下来了”时，应该如何降低挫败感，同时不把排行榜做坏。

---

## 1. 问题不是单纯的公式问题，而是“成就归属”问题

结合当前仓库文档与现有实现，现状有三个关键前提：

1. 当前排位对象本质上是“**角色卡的公共强度/稳定性指标**”，不是“玩家账号的个人履历”。
2. strict 已经有一套偏“**反刷分**”的保护规则，例如每日上限、同对手冷却、同对手日上限、分差限制。
3. 但在用户感知里，排位仍然像“**我亲手打出来的成果**”，所以当分数被后来者打掉时，会被理解为“我的努力被抹掉了”。

这说明当前痛点至少包含四层：

- **成就不可保留**：用户投入后，没有一个“不会被后续波动抹掉”的成果层。
- **掉分来源不透明**：用户不知道是谁、何时、用什么对局把自己的卡打下来了。
- **公共榜单与个人成就混在一起**：一个指标同时承担“全服当前强度排序”和“创作者自我成就感”两种职责，天然冲突。
- **LLM 裁判天然有噪声**：当前系统本来就不追求电竞级公平，因此用户对单次失利、被动失利会更敏感。

结论先行：

- 这类问题**不能只靠改加减分公式解决**。
- 最有效的方向通常不是“让真实分永远不掉”，而是把“**当前公共分**”和“**用户已获得的成就**”拆开。

---

## 2. 与当前项目语境的关系

仓库现有设计已经明确：

- `docs/V0_6_0_RANKING_TECH_TAGS.md` 将排位定义为“角色卡强度/稳定性指标”的近似统计，而非用户排位。
- `docs/STRICT_RANKING_ANTI_ABUSE_2026-03-08.md` 当前重点放在“反刷分”，还没有专门处理“掉分挫败感”。
- `arena_rating_events` 已经具备“审计 / 追踪 / 反查某次分数变化”的基础能力，这意味着“透明化最近失分来源”并不需要推翻现有架构。
- 个人页与公共榜单当前已经刻意弱化了全量精确排名，尤其 live `publicRank` 只在 Top300 口径下保留；这意味着如果要加“历史最高名次”，不能默认依赖全量精确 rank。

因此，本项目最适合的方向不是“照搬传统玩家段位系统”，而是：

- 保持 live rating 作为公共竞争指标；
- 另加一层对创作者友好的“峰值 / 赛季成就 / 防挫败”展示；
- 再补一点轻量保护，避免“刚升段马上掉回去”。

## 3. 外部案例调研摘要

以下案例均于 2026-03-24 查阅官方资料，重点看它们如何处理“掉分焦虑”“升段成就感”“真实匹配准确性”的矛盾。

| 产品 | 官方做法 | 对本项目的启示 |
| --- | --- | --- |
| 《英雄联盟》Ranked | 定位赛输掉不扣 LP；跨 tier 降段有 demotion protection | “新上路 / 新进入分段”时可以先保护，减少初次挫败 |
| VALORANT | `Rank` 与 `Act Rank` 分离；`Act Rank` 由“最高 ranked win”决定；若输给作弊者可返还 RR | “当前段位”与“已证明的最高成就”分层展示，非常适合缓解“成果被抹掉”的感觉 |
| VALORANT | 若隐藏 MMR 高于当前 rank，赢时多给、输时少扣；反之相反 | “加分比掉分多”可以存在，但前提是它是**收敛机制**，不是永久福利 |
| VALORANT | 不做 rank decay，但高段位排行榜名次会因别人上分而变化 | “榜单位置变化”和“自身段位变化”可以拆开，用户更容易接受 |
| 炉石传说 Ranked | 设 rank floor；Star Bonus 基于上赛季表现；有 bonus 时仍按 MMR 匹配 | “段位地板 + 快速回到应在位置”是成熟做法，但需要隐藏匹配层支撑 |
| 炉石战场 Battlegrounds | external rating 有 floors / protection；internal rating 不受保护层影响；6500 以下还有小幅 progression bonus | 这是最值得参考的案例：**真实匹配 rating** 与**玩家看到的进度 rating**可以不是同一层 |

### 3.1 这些案例背后的共同原则

可以归纳出四条成熟产品普遍在做的事：

1. **保护“成就感”，不一定保护“真实分”**  
   例如最高段位、赛季最高成绩、Act Rank。

2. **保护往往发生在“边界”而不是全程**  
   例如定位赛、刚升段、低分段、赛季初回爬。

3. **加分比掉分多通常是“回归正确位置”的临时机制**  
   不是一个永久存在的福利公式。

4. **如果要同时保公平和保体验，往往需要双轨**  
   即“用于匹配/真实排序的内部值”和“用于展示/情绪体验的外部值”。

## 4. 对三个直觉方案的逐项分析

### 4.1 方案 A：限制角色掉分幅度

#### 优点

- 最直接缓解“我睡一觉起来掉了一大截”的体验。
- 对 LLM 裁判噪声更有容错。
- 容易理解，也容易做成配置项。

#### 风险

- 如果是**全局统一限掉分**，排行榜会越来越“粘”，强卡很难被真实打下去。
- 当前项目的排位是“公共角色卡强度指标”，不是玩家本人段位；如果 live 分过于抗跌，榜单的“当前强度”含义会变弱。
- 对热门卡尤其危险：热门卡被很多人挑战，本来就应该有更充分的样本让分数回归；如果过度限损，反而会把榜首钉死。

#### 适合怎么用

不建议直接做成“所有对局最多只掉 X 分”的全局规则。  
更推荐的变体有两种：

1. **段位保护带 / 滞回带（推荐）**  
   例如升到 `1200` 才进新段位，但要掉到 `1150` 才真正掉段。  
   这样保护的是“段位边界体验”，不是整个分数曲线。

2. **被动掉分上限（仅可做实验）**  
   只对“非持有者本人发起的对局”做每日掉分上限或额外缓冲。  
   这更精准命中当前抱怨，但复杂度和可解释性都更高。

#### 结论

可做，但应**只保护边界体验，不应全面保护 live rating**。

---

### 4.2 方案 B：达到新段位后就不会再掉段

#### 优点

- 对用户情绪帮助最大，尤其适合“终于上去了”的里程碑心态。
- UI 很好讲清楚，用户也最容易记住。

#### 风险

- 如果这是对 **live 段位/榜单** 生效，会快速积累“名不副实”的高段位卡。
- 由于本项目允许别人继续挑战你的卡，永久不掉段会让“公共榜单”越来越像“历史荣誉墙”，而不是“当前强度榜”。
- 当前项目已经明确不把排位当成用户 rank，而是卡的公共指标；在这种定义下，live 层永久地板会更违背系统原意。

#### 更合理的替代做法

把“不会失去”的对象，从 `currentTier` 改成：

- `seasonPeakTier`
- `seasonPeakRating`
- `seasonBestRankTop300`（仅当确实进入过 Top300 时才记录）

也就是：

- **当前分 / 当前段位**：可以继续波动
- **赛季最高段位 / 赛季最高分 / 历史徽章**：不会被后续波动抹掉

这类设计和 VALORANT 的 `Act Rank` 很像，能保住“我上去过”的成就感，但不污染 live 排行榜。

#### 结论

**不建议**把“永不掉段”直接施加到 live ladder。  
**强烈建议**把它改造成“赛季最高段位永久保留”的成就层。

---

### 4.3 方案 C：加分比掉分多

#### 优点

- 体感上更友好，尤其对“我明明应该更高”的玩家很有效。
- 恢复速度快，挫败后更容易继续玩。

#### 风险

- 如果没有隐藏 MMR / 内部 rating，这几乎等价于长期印钞，最终一定带来分数通胀。
- 玩家会很快看穿这套规则，导致“分数含金量”下降。
- 对项目当前“角色卡公共强度排序”的定位不利。

#### 什么情况下可以成立

只有当它被明确定义为**收敛机制**时才合理，例如：

- 新卡 / 定级期
- 赛季软重置后的回爬期
- 引入 hidden internal rating 后，只有当 internal > external 时才“赢多给、输少扣”

这和 VALORANT、炉石战场的做法一致：  
它们不是“永远奖励你”，而是在把你推回系统判断的合理位置。

#### 结论

**不建议**当前系统直接上永久性的“加分比掉分多”。  
如果以后要做，前提是先引入“双轨 rating”或至少“定级 / 回爬阶段”的限定条件。

## 5. 更适合本项目的推荐方案

### 5.1 总原则：保成就，不保假分；护展示，不护真实榜单

推荐按三层做，而不是赌一个单一公式：

1. **先补透明度**
2. **再补成就层**
3. **最后只在边界处做轻量保护**

---

### 5.2 第一优先级：把“是谁打下来的”讲清楚

这件事优先级非常高，因为当前用户抱怨里最刺眼的词就是“**不知道哪个人**”。

建议新增一个“最近排位变动 / 最近防守记录”视图，至少展示：

- 时间
- 对局模式（strict / free）
- 对手 / 触发来源
- 本局 `delta`
- 变动后分数
- 战报链接
- 是否为“持有者本人发起”还是“外部挑战”

为什么这一步很重要：

- 透明度本身就能显著降低“系统黑箱感”
- 用户会从“莫名其妙掉了”变成“这张卡昨晚被 A 和 B 连续挑战输了两局”
- 这一步对排行榜平衡几乎零副作用
- 现有 `arena_rating_events` 已经有审计链路，属于高收益低风险改动

这一步做完之后，即使暂时不改公式，体感也会明显改善。

---

### 5.3 第二优先级：新增“赛季最高成就层”

建议新增以下字段或等价派生能力：

- `seasonPeakRating`
- `seasonPeakTier`
- `seasonBestRankTop300`（可选，仅在进入过 Top300 时记录）
- `seasonPeakAt`

前端展示建议：

- 当前排位分：`currentRating`
- 当前段位：`currentTier`
- 赛季最高：`seasonPeakTier / seasonPeakRating`
- 若进过 Top300：展示“赛季最佳名次 #xx”

这样会直接改变用户心智：

- “我现在被打下来”不再等于“我之前没打上去过”
- Live 排名仍然真实
- 个人成就可以累积

这一步尤其适合本项目，因为当前系统本就更接近“公共卡强度榜”，不是纯玩家天梯。  
既然如此，就更应该单独给创作者一层可保留的成果视图。

> 注意：由于当前 live 精确 public rank 只保留 Top300 口径，`seasonBestRank` 不宜假设全量可得。最稳妥的是先做 `seasonPeakTier + seasonPeakRating`，`seasonBestRank` 仅在确实进入 Top300 时落库。

---

### 5.4 第三优先级：给“刚升段”加一个轻量保护带

推荐做法不是“永不掉段”，而是下面二选一：

#### 方案 1：段位滞回带（更推荐）

- 升段阈值：例如 `1200`
- 掉段阈值：例如 `1150`

优点：

- 实现简单
- 解释直观
- 不改 live rating
- 不会造成长期段位堆积

缺点：

- 只能缓解“边界来回横跳”，不能解决所有被动掉分

#### 方案 2：升段后 1~2 次保护（次推荐）

- 首次进入新段位后，给 1~2 个 demotion shield token
- 只有在“本应掉段”的结算时才消耗

优点：

- 对“刚上去就掉回去”的挫败更有效

缺点：

- 规则比滞回带稍难解释
- 要考虑“别人打你下来”是否也消耗 shield

我的建议：

- 第一版优先做 **滞回带**
- 如果用户仍然很在意“刚升段就回落”，再加 token 化的升段保护

---

### 5.5 不建议作为第一波上线的做法

以下做法都不是不能做，但不适合作为第一反应：

#### 1) 全局永久“加分比掉分多”

原因：

- 高通胀风险
- 破坏 live 榜单含金量
- 没有 hidden MMR 时很难讲清楚为什么

#### 2) live 层永久不掉段

原因：

- 会让公共榜单越来越像“历史陈列馆”
- 与当前“角色卡强度指标”定义冲突

#### 3) 先大改 Elo 公式

原因：

- 用户抱怨的核心不是“Elo 不够高级”
- 当前更缺的是成就层与可解释性

---

## 6. 如果要更进一步，可以考虑“双轨 rating”

如果未来真的想同时做到：

- 排行榜足够实时、公平
- 用户又几乎不再为掉分痛苦

那么最终形态大概率会走向“双轨”：

- **internalRating**：只用于真实排序 / 匹配 / 风控
- **displayRating**：用于段位展示 / 成就进度 / 情绪体验

这样就可以安全地做：

- display floor
- 回爬 bonus
- 阶段性加分 > 掉分
- 赛季展示优化

而不污染真实榜单。

但这个方向的代价也更高：

- 数据模型变复杂
- 调参与解释成本上升
- 需要更多回归测试与赛季迁移规则

所以不建议第一波就上。

---

## 7. 建议的落地顺序

### Phase 1：先做“低风险高收益”

目标：先把“黑箱感”和“成果被抹掉感”降下来。

建议：

1. 新增“最近排位变动 / 防守记录”面板
2. 新增“赛季最高段位 / 赛季最高分”
3. 在文案中明确区分：
   - 当前分：会随公共挑战实时波动
   - 赛季最高：不会因后续波动抹掉

### Phase 2：再做“边界保护”

目标：减少“刚升段就掉回去”的挫败。

建议：

1. 先上段位滞回带
2. 必要时再上升段 shield token

### Phase 3：若投诉仍高，再试更强保护

目标：专门处理“被动掉分”。

候选实验：

1. 非持有者发起对局的每日掉分上限
2. 非法 / 异常 / 回滚对局的自动返分
3. 双轨 rating

---

## 8. 建议重点监控的指标

在决定是否继续加保护前，建议先把下面这些数跑出来：

- 首次升到某段位后，`24h / 72h` 内掉回原段位的比例
- 角色卡掉分中，“外部挑战导致”的占比
- 用户在首次被动掉段后的 `D1 / D7 / D30` strict 活跃留存
- 高段位卡的榜单流动性（Top100 / Top300 周转率）
- 全服 rating 均值与各段位人数占比变化
- 用户投诉中，“不知道谁打的”与“掉太快”的占比

如果数据表明投诉核心主要来自“黑箱感”，那么优先级应继续放在透明度。  
如果主要来自“刚上去就掉回去”，再加强边界保护。  
如果主要来自“长期外部挑战吃掉成果”，再考虑 passive-loss cap 或双轨。

---

## 9. 最终建议（给决策用的一句话版本）

如果只能给一个明确建议，我的推荐是：

**不要先做“永久加分比掉分多”，也不要直接做“live 永不掉段”；先做“最近失分来源可见 + 赛季最高成就保留”，再给当前段位加一个轻量保护带。**

展开成产品语言就是：

- **当前分数继续真实波动**
- **用户的历史高光不再被抹掉**
- **刚升段时不会一碰就掉**
- **用户能看见是谁把自己打下来的**

这套组合比单改公式更稳，也更符合当前项目“角色卡公共强度榜”的定位。

---

## 10. 可执行结论摘要

### 强烈推荐

1. 新增最近排位变动/防守记录面板
2. 新增 `seasonPeakTier + seasonPeakRating`
3. 段位显示增加滞回带

### 可以后做

1. `seasonBestRankTop300`
2. 升段 shield token
3. 异常对局返分

### 暂不推荐

1. 全局永久“加分比掉分多”
2. live 层永久不掉段
3. 先动核心 Elo 公式
