## 前提与记录

1. 记录实际 Windows 版本、WebView2/Tauri 版本、构建 commit/tree 与安装包哈希；若与验收源码不同，先说明差异。不得把 Linux Rust loopback、DOM/合成 IPC 或完整本地 CI 填为 Windows 通过
2. 不改变产品固定目的地，不添加 renderer URL、调试代理、绕过 TLS 或重定向。新写 true 需要 Next 自身能力以及 C2 的 Hono 新 capability；无凭据 readiness 只证能力声明，不能证明跨 runtime D1 归属正确
3. 以下需要服务端生成/角色更新/登录的项目，在取得明确测试环境与账号/操作授权前只记“未执行”。本轮代码授权不等于这些操作授权；不部署、不新建令牌/Key，不以合成凭据冒充生产账号
4. 仅记录脱敏 requestId/generationId、协议版本、状态/错误码、字段变化与必要截图。不得记录/上传 cookie、匿名恢复 token、ProviderKey、完整个人角色卡或含秘密的网络抓包
5. 每项填写 `未执行 / 阻塞 / 通过 / 失败`、构建、时间、步骤、实际结果、证据与缺口；能力未就绪或账号未获授权不能填通过

回传先列实际通过项、失败/阻塞项和未执行项，再列构建身份与证据。只有上述有限范围逐项有真实结果时才能更新该范围结论；不据此宣布全部 Desktop 或 D4 完成。
