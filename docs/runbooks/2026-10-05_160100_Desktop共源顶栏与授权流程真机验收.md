# Desktop 共源顶栏与授权流程真机验收

日期：2026-10-05
状态：`pending-manual-acceptance`；本文件提供步骤，不构成真机通过证明。

对应[唯一阶段计划](../plans/2026-09-30_160100_Desktop客户端阶段实施计划.md)的 D5.0d / D5.0d-r1。约束为 `DESK-ONLINE-008/012/014`；覆盖共源 `ProductTopBar` 在 Web/Desktop 两宿主的行为一致性，以及进程级云会话授权 flow 的所有权边界。Web 侧观察用真实浏览器，Desktop 侧用真实 Tauri WebView，两者不可互相替代。

## 准备

记录 `git rev-parse HEAD`、Windows / WebView2 版本与构建方式。Desktop 从仓库根运行 `pnpm run dev:desktop`，或 `pnpm --filter @mahoshojo/desktop exec tauri build --debug --no-bundle` 的本地可执行产物；该命令不部署、不发行、不生成 release/tag。Web 由 `pnpm --filter @mahoshojo/web run dev` 提供，在真实浏览器打开。

Desktop 授权往返需要可登录的测试账号与可达的项目服务；沿用 D5.0c 在线门禁记录的环境（见[在线门禁验收](./2026-10-05_144424_Desktop在线门禁验收.md)）。不要把 Web 登录会话与 Desktop 原生授权混在同一份记录里：两者是不同通路的独立会话。

## 场景

| 项目 | 操作 | 通过条件 |
| --- | --- | --- |
| active group 同步（Desktop） | Desktop 首页 → 顶栏「角色」→「角色管理」；再进「百科」；随后前进 / 后退遍历 | 每次导航与 traversal 后顶栏高亮分组随 `data-active-group` 对应变化，不停在旧分组 |
| 内链 modifier click（Web） | Web 顶栏对 logo、导航项与账号菜单内链分别执行 Ctrl+Click / Cmd+Click（按平台）与中键 | 每种修饰键都打开新标签/新窗口，当前标签不跳转；普通左键仍由 Next Router 接管、无整页刷新 |
| 离开设置页不取消授权（Desktop） | 设置页打开云账号面板 → 顶栏账号区发起登录（系统浏览器打开授权页）→ 在授权完成前导航离开设置页 | 授权 flow 不被取消：顶栏保持「登录中…」；回浏览器完成授权后会话落到 active；回到设置页看到已登录或授权进行中 |
| 并发认证单 flow（Desktop） | 快速双击顶栏账号区；或顶栏与设置页登录入口同时触发 | 只产生一条 `cloud_login_begin`，不出现两条 loopback flow 或两个授权页 |
| 未验证不冒称已登出（Desktop） | 冷启动后直接进入设置页 | 会话状态先显示「尚未验证/正在读取」，不出现先闪「未登录」再跳变的情况 |
| 跨宿主一致性 | 同一窄窗宽度分别查看 Web 与 Desktop 顶栏；Tab 键遍历 | 导航分组、文案、主题菜单位置一致；键盘可达主要入口；未交付入口在 Desktop 不出现而非死链 |

## 回传格式

回传 commit、运行方式、系统/WebView2 版本与浏览器版本，各项「通过 / 失败 / 未测」。失败附操作顺序、错误文本、对应时间与脱敏截图/录屏。

已知不属本轮验收范围：桌面下拉在 hover/focus 展开后缺少 Escape dismiss，移动抽屉（`aria-modal="true"`）缺少 Tab focus containment 与关闭后 focus restore——两者是沿用自旧 Web 顶栏的既有债务，列入 D5.2 前 release hardening；可在本表记录观察但不作为 FAIL 条件。
