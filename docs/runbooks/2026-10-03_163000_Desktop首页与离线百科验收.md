- 共源内容寻址：`scripts/generate-encyclopedia-content.mjs --check` 校验源完整性；两端 dev/build 生成各自副本，
  `--check-output` 及临时目录测试核对与 `content/` 逐字节一致；
- 产物里没有远端样式/标记资源、授权面没有 `fs:` / `http:` / `shell` / `opener`：
  `tests/desktop-offline-content.test.ts`；Desktop CI 在构建后以 `DESKTOP_OFFLINE_CONTENT_REQUIRE_DIST=1` 强制运行，
  普通 root 测试在无产物时明确 skip；
- 目录筛选、关键词检索、分类计数、正文取回与失败、heading slug 承接、以及锚点的自动化部分：
  `packages/ui-web/tests/encyclopedia-views.test.tsx`；
- 路由往返、query、hash history 下的 fragment 形状：`apps/desktop/tests/desktop-router-history.test.tsx`。

**自动化跑在 jsdom，不是真实 WebView。** 下面的步骤覆盖 jsdom 无法证明的部分：真实字体渲染、真实
滚动、真实网络出口、真实高 DPI 与键盘输入法。

## 准备

记录 `git rev-parse HEAD`、Windows / WebView2 版本、分辨率与缩放百分比、输入法。

从仓库根运行 `pnpm run dev:desktop` 打开真实 Tauri 窗口。生产构建复核使用
`pnpm --filter @mahoshojo/desktop exec tauri build --debug --no-bundle`，然后运行其本地可执行产物。
该命令不部署、不发行、不生成 release/tag。

**断网准备**：关闭 Wi-Fi 或断开网线，并确认浏览器测试 profile 与本机账号均处于未登录状态。Desktop
本机没有账号概念，因此"未登录"对 Desktop 恒成立；要验的是"没有可用 Provider 配置 + 项目服务器
不可达"。

安装包体积基线：`pnpm --filter @mahoshojo/desktop run build` 后记录 `apps/desktop/dist` 总大小，以及
`dist/assets` 下 KaTeX 字体合计（D3.0b 实测 59 个文件、1.2MB，含 woff2/woff/ttf 三种格式）。
本阶段**不做**资源压缩，只记录 delta；是否收窄字体格式待有安装包基线后再决定。

## 零网络请求

这是本阶段最关键、也最难自动化的一项。

1. 打开 WebView2 DevTools，Network 面板勾选 **Preserve log**，清空记录。
2. 从应用启动开始，完整走一遍「首页 → 百科目录 → 搜索 → 条目 → 锚点 → 返回首页」。
3. 逐条检查请求：所有请求的 URL 必须是本地 origin（Windows 上是 `http://tauri.localhost`）、
   `ipc://` 或 `data:` / `blob:`。**不允许**任何 `https://` 到外部主机的请求。
4. 特别确认这几类不会漏看：CSS `url()` 指向的字体与背景图、`<img>` 与 `<video>`、KaTeX 字体文件、
   `EventSource` / `WebSocket`、以及 favicon。
5. **同时观察 native 出站**：用资源监视器或 `Get-NetTCPConnection` 确认应用进程（含 WebView2
   renderer 进程）在整段旅程中没有对外连接。renderer 的 Network 面板看不到 native 侧发起的行为，
   两层都要看。
6. 单独复验：断网状态下重走一遍上述旅程，必须完全正常。

任何一条无法观测就填「未验证」，不要以"没有报错"判 PASS。
