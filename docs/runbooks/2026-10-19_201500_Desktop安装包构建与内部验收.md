## 已确认的产品决策（2026-10-19，维护者）

- 首批安装包只做**内部跨设备测试**，稳定后再考虑 Beta / GitHub Pre-release。
- Windows Authenticode 代码签名 **Alpha 暂缓**：安装时出现 SmartScreen 提示属于
  预期行为，公开发行前再决定采购方案。
- identifier 保持 `me.colanns.mahoshojo.desktop` 不变——它同时决定应用数据目录
  （Windows 下 `%APPDATA%\me.colanns.mahoshojo.desktop`）与 Windows Credential
  Manager 的 service 命名空间（`secret.rs` 的 `SECRET_STORE_SERVICE`），首批安装
  包分发后不再变更。
- Desktop 使用**独立版本序列**，首个内部版本 `0.1.0-alpha.1`；Web 序列
  （当前 0.10.x）不受影响。
- Updater 不随本阶段启用：`createUpdaterArtifacts` 保持 `false`，本阶段
  「升级」= 手动安装新安装包，为后续 in-app 更新做准备。

## 版本契约

`apps/desktop/package.json` 的 `version` 是唯一权威来源；三个派生位置由
`scripts/sync-desktop-version.mjs` 同步：

- `apps/desktop/src-tauri/tauri.conf.json`（bundle/安装包版本）
- `apps/desktop/src-tauri/Cargo.toml`（crate 版本，也是运行时 `appVersion` 来源）
- `apps/desktop/src-tauri/Cargo.lock`（`mahoshojo-desktop` 自身包记录）

```bash
# 修改版本号：先改 apps/desktop/package.json，然后：
pnpm run sync:desktop-version

# 只校验不改写（CI/打包前置已接入）：
pnpm run check:desktop-version
```

`check:desktop-version` 已并入 `workspace:checks`（进 `ci:verify`），
`desktop-package.yml` 打包前也会校验，三处不一致时拒绝产出。

版本命名约定（内部阶段）：`0.1.0-alpha.N`（内部 Alpha）→ `0.1.0-beta.N`（限定
测试）→ `0.1.0`（首个正式版）。Git tag 采用 `desktop-v<version>` 前缀，
与 Web 的 tag 区分；当前阶段**不打 tag、不发 Release**。

## 构建

### 本地

```powershell
pnpm install --frozen-lockfile
pnpm build:desktop
```

产物：`apps/desktop/src-tauri/target/release/bundle/nsis/*.exe`
（文件名形如 `MahoShojo Generator_0.1.0-alpha.1_x64-setup.exe`）。

记录校验和，跨设备验收时按它核对文件未被改动：

```powershell
Get-FileHash 'apps/desktop/src-tauri/target/release/bundle/nsis/*.exe' -Algorithm SHA256
```

### CI（内部打包流水线）

`.github/workflows/desktop-package.yml`：**仅手动触发**（Actions 页面运行
workflow；Windows release 构建成本高，不随推送自动执行），在 windows-latest
上执行同一 `pnpm build:desktop`，产出 NSIS 安装包
与 `SHA256SUMS.txt` 并上传为 workflow artifact（保留 30 天）。该流水线**不含**
发布私钥、代码签名与 Release 步骤；正式发布是另一条受保护 workflow（尚未建立）。

## 安装包形态（当前）

- NSIS `.exe`，`installMode: currentUser`：按当前用户安装，不要求管理员权限。
- 安装器语言 `SimpChinese` / `English`：按系统语言自动选择，无语言选择弹窗。
- WebView2 缺失或版本不足时**在线下载引导**（`downloadBootstrapper`，静默）。
  注意区分「安装时联网引导」与「安装后离线运行」：本方案不是离线安装器，
  不能把当前安装包宣称为全离线安装（D5.2 明确口径）。
- 应用数据在 `%APPDATA%\me.colanns.mahoshojo.desktop`（SQLite 本地库、
  `config.json`、备份目录），凭据在 Windows 凭据管理器。
- 未签名：下载与安装会触发 SmartScreen「Windows 已保护你的电脑」，
  选「仍要运行」。验收记录里应如实记下各设备的拦截表现。

## 用户数据红线（验收必须覆盖）

- 正常升级（覆盖安装新版）**不得**删除或重置用户数据；卸载默认保留数据
  目录，彻底清除必须有显式选择。
- 应用身份、数据目录、凭据 service 名在版本间保持稳定。
- 新版遇到无法理解的旧数据时给出可诊断错误，不得静默重置。
- **回滚安装包 ≠ 回滚用户数据**：新版本升级过 SQLite schema 后，旧版本可能
  打不开库。执行升级测试前先跑整库备份（`/local-library` 导出），
  并单独验证「旧版数据 → 新版」单向迁移。
- 既有 Web 端本地数据不会自动出现在桌面版；跨宿主依赖既有导入导出机制。

## 内部验收清单

按**安装后的 Release 构建**验收，不以 `tauri dev` 代替。每次验收记录：
设备/OS build、WebView2 版本、安装包文件名与 SHA-256、测试人、结果与问题。

### A. 安装与启动

| 项 | 检查点 |
| --- | --- |
| A1 | 干净 Windows 11 x64（无开发工具、无历史数据目录）：双击安装 → 完成 → 从开始菜单/桌面快捷方式启动，无白屏、无缺资源 |
| A2 | 安装全程未要求管理员权限；安装后可由普通用户运行 |
| A3 | 无 WebView2 或版本较旧的环境：引导器在线下载并成功安装后启动 |
| A4 | 安装时断网（有 WebView2 的机器可离线装；无 WebView2 的机器应给出可理解失败而非静默退出） |
| A5 | 安装后断网启动：离线首页、百科、本地库可用；在线能力（Hosted AI、账号）明确提示而非崩溃 |
| A6 | 中文用户名与含空格/非 ASCII 路径：安装路径、数据目录、文件对话框正常 |
| A7 | SmartScreen 拦截表现如实记录（版本/文案/是否需「更多信息→仍要运行」） |

### B. 显示与交互

2026-10-26 窗口整改：保留默认 1180×800，最小客户区降为 800×450，并启用 Tauri `preventOverflow`。
Desktop 前端构建及 `cargo check --locked` 通过；800×450 Chromium 中首页、设置、问卷、本地库、样板间无横向溢出，
示例弹窗位于视口内。浏览器未接 Native bridge，不能替代下表真实 DPI / WebView2 与功能操作验收。
`preventOverflow` 只处理创建窗口时的工作区限制，不保证跨屏拖动或后续调整自动适配；详见
[Tauri WindowOptions](https://v2.tauri.app/reference/javascript/api/namespacewindow/#windowoptions)（2026-10-26 核验）。

| 项 | 检查点 |
| --- | --- |
| B1 | 125% / 150% DPI 缩放：字体回退、窗口尺寸、按钮与模态框不出屏 |
| B2 | 1366×768 @150% 缩放的极限工作区：记录真实工作区与客户区；启动不出工作区、800×450 逻辑客户区仍可滚动到关键按钮，弹窗确认/取消不被遮挡。配置已降低最小尺寸并启用启动 preventOverflow；不能仅凭配置或浏览器模拟判为通过 |
| B3 | IME 中文输入、键盘导航、Esc 层级在真实 WebView2 中行为正确 |

### C. 数据持久化与升级

| 项 | 检查点 |
| --- | --- |
| C1 | 建本地卡、写设置、保存 Provider Profile（含凭据）→ 关闭重开应用，数据保留 |
| C2 | 旧版本数据目录 → 覆盖安装新版 → 启动，卡库/设置/凭据完好；新版本能读旧 schema |
| C3 | 整库导出 → 恢复演练（沿用 D2.4 runbook），升级前备份可回读 |
| C4 | 卸载：默认保留数据目录；重装后数据仍在（记录卸载器是否提供「删除数据」显式选项） |
| C5 | 凭据：升级后 Provider Key 与账号会话仍在（Windows 凭据管理器记录不丢） |

### D. 功能旅程抽查（按当前已支持范围）

| 项 | 检查点 |
| --- | --- |
| D1 | 首页、百科（离线可读）、本地库列表/详情/回收站 |
| D2 | `/details` 问卷 → Direct AI 生成（自定义连接）→ 本地保存 |
| D3 | 设置页：AI 连接、config.json 打开/重载、版本号显示与构建一致 |
| D4 | 文件导入导出：local-library portable archive、角色卡 JSON/PNG |
| D5 | 账号登录回跳（浏览器拉起 → 回应用）、云库浏览/保存副本（在线时） |
| D6 | 诊断面板信息可用于回报：appVersion、os、arch、tauriVersion、WebView2 版本 |

### E. 异常场景

| 项 | 检查点 |
| --- | --- |
| E1 | 磁盘空间不足时的安装/运行表现 |
| E2 | 数据目录被占用/只读时的启动错误可读性（不静默重建空库） |
| E3 | 重复安装同版本、降级安装旧版本的表现（预期：旧版可能打不开新 schema，须可诊断） |
| E4 | 双开：第二个实例给出明确提示而非损坏共享数据目录 |

## 已知边界（本阶段不做）

- 无 updater：不验证 in-app 更新；签名更新、更新清单地址（拟
  `mahoshojo.colanns.me/desktop/updates/stable/latest.json`）属 D5.2-C。
- 无 OS 代码签名；SmartScreen 提示属预期。
- 不做 MSI、免安装 ZIP、离线 WebView2 安装器、ARM64、macOS/Linux——
  有具体需求或测试证据后再决策。
- 官网 `/download` 入口待正式 Release 后再上线。
- 公开发行前需核实安装包内素材分发权利（`ASSET_LICENSE.md`：数据卡、
  Logo 与美术资源不自动适用 Apache-2.0）与第三方依赖许可。
