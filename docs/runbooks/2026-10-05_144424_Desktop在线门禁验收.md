## 验收环境

Windows 桌面端实机，经 native `cloud` 边界访问生产部署 `https://mahoshojo.colanns.me`（固定 origin 与路由白名单，`DESK-090/093`）。使用维护者自有 Web 账号；账号名与凭据细节不写入本记录。

## 实机验收记录

| 项目 | 操作与预期 | 证据 |
| --- | --- | --- |
| 原生授权登录（`desktop-auth-v1`，DESK-091） | 设置页「登录账号」→ 系统浏览器 `/auth/desktop` 授权页（已登录 BA 会话进入直接授权态）→ loopback `127.0.0.1` 回跳 → grant 一次性兑换 → 面板进入已登录态 | 已验：面板显示已登录账号与会话有效期（签发 +7 天）；`code`/`verifier`/会话 cookie 均不出现在 UI 可观测面 |
| 会话凭据持久化（DESK-092） | 退出并重启应用后 `account-session:*` 凭据仍可读，状态保持已登录 | 已验：重启后会话保持 |
| 会话状态服务端确认 | `cloud_auth_status` 命中 `/api/auth/get-session`，已登录态来自服务端确认而非本地缓存假设 | 已验：账号摘要与有效期由服务端响应投影 |
| 连通性与契约兼容探测（DESK-094） | 「检查服务连通性」→ native 带会话 GET `/api/hosted/dr-readiness` → 期望 reachable 且契约兼容 | 已验：「项目服务在线（契约 `g25e1-v1`，兼容）」 |
| 退出登录（DESK-092） | 「退出登录」→ 本地凭据删除、服务端 `sign-out`；面板回到未登录态 | 已验：退出后回到未登录态 |

## 门禁口径调整与未覆盖项

- **生成联调口径调整（维护者决策，2026-10-05）**：阶段计划 D5.0c-r3 把「真实部署的 grant/exchange/生成联调」并列为在线门禁。本轮验收完成 grant/exchange 与契约探测后，维护者裁定 dr-readiness 连通性 + 契约版本兼容为在线通路验收的充分证据，`stream_hosted_ai` 对真实部署的 SSE 生成往返不再作为本门禁前置。该往返在「服务器执行」具备 UI 可达入口的切片落地时按既有门禁实测（当前 renderer 不存在 `streamHostedAi` 消费方，预计随 D5.1a 双执行接线开放）；本条是口径调整记录，不把未执行的生成往返记为已验。
- 自动化已覆盖、真机未逐项复测的行为：登录取消/错 state/兑换重放/过期、`native-grant`/`native-exchange` 限流桶、`/auth/desktop` 授权页三态与 `authSource` 透传、native grant/exchange 审计 await（覆盖情况见阶段计划 D5.0c-r1..r3 记录与对应测试）。
- 未实测：多账号轮换的账号隔离（当前仅单一账号）；服务器 BYOK 仍按 `DESK-093` 关闭，不占本门禁。

代码与自动化验证记录统一写入阶段计划。
