## 准备

使用测试 Windows 账户和浏览器测试 profile，避免将大体积合成包混入日常库。两端导入是 existing-wins 合并，不会清空原库，也不应通过删除真实数据来准备空库。所有包均应无秘密、无外链、无脚本执行需求。

记录 `git rev-parse HEAD`、Windows / WebView2 版本、内存、磁盘类型、构建方式。从仓库根运行 `pnpm run dev:desktop` 打开真实 Tauri 窗口；生产构建复核使用 `pnpm --filter @mahoshojo/desktop exec tauri build --debug --no-bundle`，然后运行其本地可执行产物。该命令不部署、不发行、不生成 release/tag。

Web 测试页由 `pnpm --filter @mahoshojo/web run dev` 提供，访问本地 `/local-library`。Web 自身 bootstrap 可能有项目请求；Desktop 本地旅程零网络需要独立观察，不能把 Web bootstrap 混在同一份网络记录中。

生成小夹具：`node scripts/create-desktop-archive-fixture.mjs 1`。性能档位依次用 `64`、`128`、`248`（MiB 载荷目标；以脚本输出的实际输入/ZIP 字节为准，最后一档为容器开销预留空间）。脚本只写合成文件，导入仍由用户显式完成。每档用独立测试库或 Windows 测试账户，避免三档累加超过预算；资源不足时暂停后续大档并保留未验收状态。

## 性能与 raw IPC

每档冷启动后导入该档夹具，再测导出。任务管理器详细信息页分开记录应用进程与其 WebView2 renderer 进程 PID、起始/峰值工作集；不要把整机内存或 JS heap 当成 RSS。记录导出总耗时、打包阶段停顿、最后一块返回耗时，以及拖动窗口/操作 UI 是否卡顿。必要时在 WebView DevTools Performance 录制主线程长任务。

DevTools Network 中保留 IPC 请求记录：检查 `append_local_archive_export_chunk` 的真实自定义协议请求、`application/octet-stream` 请求体和 `x-export-id`，完整块应为 4 MiB，末块可更小；响应的累计 `writtenByteLength` 必须与已发送字节匹配，只有最后一块 `complete` 为真。导出成功的文件长度必须等于 begin 声明长度。

“最终生成了文件”不足以证明 raw 通道没有回退。保留 DevTools Console 的协议失败警告；若宿主不显示 IPC Network 条目，在 Sources 的 Tauri 注入 IPC 脚本中定位 `customProtocolIpcFailed` / fallback 分支并设断点，确认整个导出没有进入回退分支。无法观测就填“未验证”，不要只以没有报错判 PASS。记录最后一次 append 的开始/返回时间；它包含最终 flush/sync/persist，不能把网络面板总耗时当成单独 fsync 时间。

## 进程与离线门禁

1. 用同一个本地可执行文件启动两个进程（同 Windows 账户、同 app identifier/data root）。第二个应明确拒绝打开本地库，第一个仍可使用；退出第一个后重新启动应成功。不可改 identifier 来“测试”同目录互斥，因为它会选另一数据目录。
2. 使用本地打包产物断网冷启动；进入首页/本地库，选择夹具、预检、导入、导出。记录 renderer 网络及 native 出站观测；项目网络请求应为零。dev 模式需要本地 Vite，不能把停止 dev server 导致打不开 UI 误判为产品离线失败。
3. 只在测试库模拟进程中断。未完成 `.partial` 不能作为正式成功 ZIP 出现；下次启动回收，或本进程下一次 begin 回收旧 session。正式 ZIP 不自动清理。不增加 abort IPC；未来若引入取消按钮，再单独设计窄 abort。
