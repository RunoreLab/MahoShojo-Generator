# 双端共源切片模板与验收指南

状态：`active`（开发操作指南，不是自动门禁或实施完成记录）
日期：2026-10-06
适用：将真实 Web 产品面抽共享并接入 Desktop，或修改已经共源的行为。
约束：[产品/设置 ADR](../decisions/2026-10-06_084100_双端产品对齐与设置共源决策.md)、[对应规格](../specs/2026-10-06_084200_双端产品对齐与设置共源规格.md)、[公开缓存规格](../specs/2026-10-06_084400_Desktop公开库离线缓存规格.md)、[复杂度预算](../decisions/2026-09-01_193200_平台复杂度预算与故障降级决策.md)。
施工顺序与验收状态只写[唯一 Desktop 计划](../plans/2026-09-30_160100_Desktop客户端阶段实施计划.md)。本模板按风险裁剪，不要求一个小图标变更填完整表。

## 1. 开工前：确定事实和授权

阅读 root/docs AGENTS、docs/README、相关 topic、accepted ADR/spec 及目标 slice。确认本次是调研、文档、代码还是部署授权；记录当前分支和具体已提交基线，查看未提交改动/其他会话。不要把他人的在途变更或旧测试结果当作本次交付。

从 Web route 追到页面、controller、CSS、资源、数据与副作用；从 Desktop 实际入口核对已有能力。不以“有同名组件”“编译通过”代替真实页面行为，也不把注释当实现。

## 2. 最小切片说明模板

将必要内容填入唯一计划的对应 slice，不新建另一套里程碑表：

| 项目 | 填写内容 |
| --- | --- |
| 目标/编号 | 本次解决的用户旅程，保留既有阶段 ID |
| 当前/目标 | Web 已有事实、Desktop 差距、合理差异、明确延期 |
| 规范依据 | 真正约束本次行为的 spec ID，不堆全部历史门禁 |
| 源/目标 | 实际组件/规则/CSS/资源路径、共享 feature subpath 与宿主装配点 |
| Web 影响 | 无行为改变，或逐项列出已授权的文案/布局/交互/协议变化 |
| 数据/副作用 | 数据 owner、读取时机、发往哪里、写入什么；secret/账号边界 |
| 生命周期 | 输入/配置冻结点、取消、离开、窗口关闭、错误和 unknown/no-replay |
| 验证/回滚 | 自动行为用例、必要构建/真实宿主项目、如何撤回入口但保留数据 |

**能力对照表**按具体区段填写，示例行只是调查方向，不表示完成：

| 区段 | Web 现状证据 | Desktop 目标/合理差异 | 本次状态与行为用例 |
| --- | --- | --- | --- |
| 标题/导航/主题/布局 | route + view + CSS | 同源主要信息、平台窗口边界 | 填写 |
| 输入/选择/导入 | controller + schema | 公共状态机；文件/云端由 adapter | 填写 |
| 生成/取消/错误 | request + response 契约 | 现有执行端口，不能自动重发 | 填写 |
| 结果/保存/导出 | 卡片外层、正文、动作 | 公共展示、真实宿主写入 | 填写 |
| 在线/离线/缓存 | 公私来源及缺失状态 | 失败不伪装空；快照不冒充当前云端 | 填写 |
| 键盘/焦点/响应式 | 可重复操作步骤 | 同行为；真实 WebView 待验项 | 填写 |

状态使用“已实现未验收 / 已验收（列实际证据） / 待实现 / 不适用（原因）”。不存在 UI 的底层函数不能算该旅程完成。

## 3. 四层拆分检查

| 层 | 应放内容 | 不应放内容 |
| --- | --- | --- |
| 现有 domain/contracts/ai-core 等 | 纯数据、规则、请求构造、解析/转换与现有端口 | React、Next/Tauri、服务端 secret、平行同义规则 |
| ui-web feature | 完整产品区段、受控交互/生命周期 hook、所需 CSS/资源 | 隐式项目 fetch、auth bootstrap、任意 native invoke、isDesktop 业务分叉 |
| apps/web adapter | Router/metadata、Web auth/HTTP/IndexedDB、浏览器文件能力 | 另一份共享产品 UI、Desktop 隐含约束 |
| apps/desktop adapter/native | Router、IPC、SQLite/secret、固定外链、原生关闭 | Rust 重写 TS 业务、任意 URL/header/路径代理、远端主 UI |

优先沿用已有端口，只为真实宿主边界增加窄方法。公共 DOM API 的交互 hook 不必全部做 port；同样不要把所有请求都包入万能 SDK。第二个真实消费者出现时再判断是否抽页面级 controller。

## 4. CSS、资源和布局不能漏

检查组件依赖的自定义 class、CSS layer、主题 wrapper、@source、暗色/减少动态效果、图标/字体/静态 JSON。将实际用到的资源迁入既有 content 权威源，产物副本继续忽略；不复制 Web public 或 globals 整包。

对 P1/P2 特别核对：AppShell 的 undefined/null/custom；TopBar favicon 与 Hero 标题区分；Home Grid 所需 Web 留存 CSS；blue-theme 作用域；结果卡外层和保存按钮。不要仅通过截图推断 Tailwind 未生成，先检查真实产物/计算样式。

现有项目链接更新到 RunoreLab 不等于改原作者/赞助或历史记录。小型改进单独提交，列出 Web 前后效果；不以 Desktop 风格覆盖 Web 已成熟的页面。

## 5. 有副作用的流程单独走查

每次生成在 dispatch 前冻结输入、选定 Provider 和操作身份。导航/重挂载/断线恢复不启动新 AI；unknown 不写成安全失败，取消订阅不等于取消服务器 producer。保存失败与生成失败分开。

数据来源、存储位置、账号作用域和授权依据分别表达。缓存/本地 ID 不冒充新鲜云端引用；问卷快照不能借旧 nativeAllowed 取得官方资格。在线页签取消/账号切换后迟到响应不能更新新 scope；缓存写入也要检查清理/撤回 epoch。

设置每个字段一个 owner，迁移前列旧键、目标键、兼容和失败保留；不因为有 config 文件就双写已有 store。预算/损坏/磁盘失败不能造成旧资源无提示丢失。

## 6. 验证怎么做才有效

优先扩展项目已有测试。D5.1a 已有 domain golden；新生成族复用实际输入/请求断言方法，不增加第二套 fixture 注册平台。至少一个用例到真实页面请求或 native IPC body，避免测试自行复制实现然后自证一致。

按实际风险选用：共享组件 DOM 行为；Web/desktop adapter 同夹具；相关包类型/构建及 RSC subpath；真实输出 CSS/资源；native 路由/ACL 与数据库隔离集成。缓存行为要覆盖“很旧仍保留、summary-only、重连、缺页非删除、撤回/清理后迟到成功、配额满不淘汰”。

视觉比较固定相同可控输入和视口，不要求两个模型生成相同正文；不盲目全量更新截图基线。无需为一处文字修改重跑全仓库或建立源代码正则门禁。

集中实机清单保留：真实 WebView 文件对话框、IME/焦点/Tab/Escape、关闭保护、缩放、高 DPI、原生网络出口、重启/断网、SQLite/磁盘异常及实际使用的 D4 不可信内容。记录“未执行/PENDING”是正确状态，不允许用 jsdom 通过代替。

## 7. 提交与收口

建议每个提交形成可理解闭环：纯规则/契约及其消费者 → 共享 UI/CSS/资源与 Web 回用 → Desktop adapter/接线 → 独立小改进；测试随对应行为提交，不集中留到最后。生成资产与语义修改按仓库规则分开。

提交前看 diff，仅暂存本次文件/块；同目录并行开发时不吞入他人的代码/文档，不 reset/stash 他人变更。提交、推送和部署是不同授权。文档任务只提交文档/skill，不顺手实施已发现代码问题。

收尾记录：实际提交、实际运行检查和未执行项；更新唯一计划的 slice 状态及 docs 导航；设计变化同步 ADR/spec，不能只在 plan 写一个更弱规则。审查表是帮助人推理的材料，不做报告 marker/hash 成功证明。
