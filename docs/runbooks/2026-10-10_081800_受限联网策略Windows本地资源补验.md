# 受限联网策略 Windows 本地资源有限补验

状态：**待真实 Windows 执行**。接续[规范来源 / Document / 页面关闭 S01–S03](./2026-10-10_074400_D4b规范来源与Document关闭有限补验.md)，本页只增加新 Native 政策下包内资源正对照，不重跑 W01–W13、不开放 Arena 产品执行。策略及授权边界见[共源合同](../plans/2026-10-10_075500_不可信Web内容受限策略与确认共源合同.md)。

## 1. 基线与范围

- 使用最终发布且已包含 `generated/web-execution-policies.json` 的独立测试树，记录 `git rev-parse HEAD HEAD^{tree}`、实际二进制 SHA-256、debug / release、Windows / WebView2 完整版本及测试时间。不要用旧 be802 二进制代测
- 沿[原始交接](./2026-10-10_030600_D4b隔离窗口Windows有限验收.md)的隔离 identifier / 凭据 service / 合成数据流程；不要读日常库、真实 Key / 登录资料，不操作系统网络安全设置
- 本页**不启动外联 / 私网扫描 / HTTPS 服务 / WebSocket 探测**。所有测试资源都来自已声明的合成包与 `maho-webpkg` handler；只验证 transport 与实际响应政策，不据此声称所有外部网络路径或私网限制已测
- 不修改 `use_https_scheme`、CSP、sandbox、capability、浏览器安全参数或证书信任来使测试通过。临时观测只沿 S01 记录无秘密的合成 handler URI，不新增 Native command

## 2. D4-S04：确认后本地资源与政策正对照

1. 本地 Agent 新建一个不含任何外部 URL 的小合成包，manifest 逐项声明：`index.html`、`next.html`、`app.js`、`style.css`、`d4-origin-probe.png`、`data.json`。两 HTML 与脚本不得依赖模型 / 凭据 / 未声明文件；PNG 用固定 1×1 合成图，JSON 只放 `{"marker":"d4-policy-local"}`
2. `index.html` 包含相对 `./style.css`、`./app.js` 和 `./d4-origin-probe.png`，静态节点 `id="d4-local-result"`。`app.js` 用 `addEventListener` 绑定真实按钮；点击后 `fetch('./data.json')` 检查 marker，并在节点显示固定结果。CSS 给该节点固定可见样式。再放真实链接到已声明的 `next.html`；次页使用相同相对资源。只捕获固定 `securitypolicyviolation` 的 violatedDirective / blockedURI 与资源结果，不收集页面外数据
3. 经 `/battle` 或 `/arena` 包导入区显式保存，核对 manifest / ZIP hash；在高级诊断选中该精确包。第一次取消确认，记录无新实例；再次打开并确认后，应只出现一个包窗。诊断按原样包运行，测试不注入 overlay
4. 记录 PNG `naturalWidth`、脚本 marker、CSS 计算样式、按钮触发的 JSON marker、次页结果。对每类保存浏览器 Network 状态及资源 URL；S01 的 PNG 单条 Native trace应为 `maho-webpkg://localhost/__web-package__/instance/<本实例>/d4-origin-probe.png`，浏览器侧 Windows 映射仍应为 `http://maho-webpkg.localhost/...`
5. 从该包窗 DevTools Network / CDP 的实际 HTML response headers 保存完整 `Content-Security-Policy`（不要用包内 fetch 去读取未暴露的该头）。两页都应是 `sandbox allow-scripts; ` 加同二进制生成清单的 `policies.web-package`；五项 worker / frame / object / manifest / form 仍各为 `'none'`，并含 UIR。包内普通 JS 能运行与 Native 有无权限是不同判断
6. 包内相对图片 / CSS / 脚本 / fetch 应成功；若出现升级到 HTTPS 或 CSP 拦截，记录原始 URL、最终 URL、directive / blocked reason 和是否到达 handler。**CSP、UIR、混合内容、CORS 与资源 404 分层记录**，不要只凭 `onerror` 猜原因。停止依赖失败资源的后续项并回报，不自行放宽规则

不需要测试任意远程脚本能否执行。自由 HTML profile 本片只有固定政策准备、尚无产品运行桥；不借本页开启自由 HTML 或 same-origin 模式。两 profile 的生成同源 / 差分与类型冻结由源码定向验证另记。
