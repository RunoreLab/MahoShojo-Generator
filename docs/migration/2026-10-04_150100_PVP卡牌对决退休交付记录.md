## 外部审查收口（2026-10-04）

对 `38afb58e`–`84001cfc` 四提交的外部审查发现两项与生产持久状态相关的兼容风险，核实与处理结果如下。

### 已退休 capability 的兼容处理

`resolveAdminPrincipal` 新增 `retiredCapabilities` 参数：存量 principal 的 `capabilities_json` 中已退休 capability 仍可解析，但从返回的有效权限中过滤，不授予任何 Admin resource/action。`apps/admin` 以 `RETIRED_ADMIN_CAPABILITIES = ['pvp.read','pvp.write']` 传入请求级解析与 control-tool 诊断；bootstrap/restore 仍只接受 `ADMIN_CAPABILITIES`，无法重新授予 PVP 权限。回归测试覆盖：仅传当前 allowlist 时带 `pvp.read` 的 principal 仍报 `ADMIN_PRINCIPAL_INVALID`、传入退休集合后解析成功且有效权限被过滤、授予路径拒绝 PVP capability、仓库无 `pvp.` Admin capability 与路由注册。

### 后续生产数据清理的两个硬约束

- 历史战报 ACL 依赖 `pvp_match_players`：只要仍承诺历史 PVP 参与者可打开旧战报，就不能 DROP 该表，除非先把参与关系迁移到中性的历史 ACL 表。
- Admin 清理安全条件仍查询 `pvp_rounds`（`packages/hosted-runtime/src/admin/jobs.ts` 的 `terminalLinkedGeneration` 与 `battle_report_generations` 保护条件）：DROP `pvp_rounds` 前必须先重写该保护条件，否则普通战报清理会报 `no such table`。
