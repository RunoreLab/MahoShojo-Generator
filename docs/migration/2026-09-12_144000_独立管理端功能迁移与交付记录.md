下表省略旧 `/api/admin/` 前缀；旧 HTTP 路径不再作为兼容入口，行为通过版本化资源读取、显式动作注册或私有作业迁移。

## 数据与部署影响

canonical schema 和纯 Drizzle factory 的机械提取未改变表结构。业务安全基础另有三个增量 migration：`0014_admin_foundation.sql` 建立 principal/operation/audit/job，`0015_admin_actor_attribution.sql` 增加独立管理员关联，`0016_admin_object_tombstones.sql` 防止分步 R2 删除的旧 key 被重新绑定。

Web 的 schema 兼容出口依赖上述新增列。因此在生产部署包含该 schema 的 Web 前，必须先确认 0014–0016 已按既有 migration 流程执行；不要把“只部署 Admin”误解为可跳过共享 D1 迁移。新表是增量保留结构，回滚不删表。原有业务用户外键不填入 Access principal。

新 Arena 内部读取采用独立密钥、固定 audience/action、最长 60 秒服务 JWT。接口只读取现有 Redis 记录，不创建 actor、续 TTL、恢复 checkpoint 或触发生成，不返回房间凭据。该功能需要 Hono 与 Admin 分别配置，默认未启用。

生产 Access、D1/R2/Queue 资源、秘密及部署的具体操作仍须单独确认。操作步骤和恢复验收见 [部署与恢复 runbook](../runbooks/2026-09-12_143000_独立管理端部署与恢复验收.md)。后台新写能力默认关闭，第一次上线按只读验收，后续逐域启用。
