## 当前决定

### 1. 免费资源与既有资源优先

成本基线以变更合入时 GitHub 默认分支已经依赖、且已明确承认的产品与资源为准。本决定形成时，默认分支为 `feature/v0.2.0_Battle_Growth_MahoShojo`，观察 HEAD 为 `07d8edf1544cf30867e81f929748a73ecd3cd362`。feature/refactor 分支中仅作为候选设计出现、尚未购买或授权的产品，不因“代码已经存在”而进入成本基线。

默认生产架构不得相对于该成本基线新增必须购买的产品、固定付费附加项或新的付费控制面依赖。Cloudflare Load Balancing 或等价托管流量产品不进入默认部署、默认 CI、默认 production build 或默认分支并轨门禁。

默认分支已经使用且已承认的服务器、Cloudflare 能力及其可用免费额度可以继续使用；但“已有”或“有免费额度”不等于无限预算。任何预期显著增加现有计量开支、资源规格或运营负担的变更仍需由人工审阅。

### 2. 保留双运行时，简化流量选择

- `apps/api` / Hono 继续是 Hosted HTTP 主执行面；
- `apps/web` / Next.js/OpenNext 继续为小型运行配置明确列出的 operation 提供长期 DR adapter；
- 两侧继续共享 service/domain/contracts，不恢复两套业务逻辑；
- D1/R2/Redis 等权威与非权威边界不因流量选择方式改变；
- 默认生产选择从“外部付费 control plane”改为“客户端在首次 dispatch 前预检并选择一次 runtime”。

### 3. 新生成意图的选择顺序

```text
用户发起一个新的 generation intent
          │
          ▼
GET Hono /api/health/ready（单次、短超时）
          │
          ├─ ready ───────────────→ 将该 operation 固定到 Hono，再发送唯一一次 POST
          │
          └─ unavailable/timeout
                    │
                    ▼
            检查 operation safety
                    │
          ┌─────────┴──────────┐
          │                    │
new-non-idempotent / safe-read  未登记 / durable command
          │                    │
          ▼                    ▼
验证 Next DR readiness       明确降级，不发送 DR POST
          │
          ├─ ready ───────────────→ 将该 operation 固定到 Next DR，再发送唯一一次 POST
          └─ unavailable ─────────→ 明确降级
```

预检失败发生在 generation POST 之前，因此允许为 `new-request-only` operation 选择 DR；一旦 POST 已经开始 dispatch，客户端看见 timeout、断线或 `connection reset` 时不得改向另一 runtime 重放。

### 4. 小型运行配置只保存路由所需事实

`config/hosted-routing.json` 只保存公开 origin、probe、timeout、contract version 与 Web DR 实际需要的 route/method
`OperationSafety`。`config/hono-api-routes.json` 是 Hono route/method inventory；secret、binding、DatabaseProvider 与 CORS
由服务端实际代码验证。未登记的 Arena generation/companion operation 不进入 Next DR；显式
`durably-idempotent` command 在没有自身去重条件时也不会被 client-preflight 自动重放。

### 5. Cloudflare LB 成果保留但不激活

双 adapter、readiness 与 contract compatibility 继续保留。大型 manifest、生成投影、drill registry、schema evidence、
production evidence 和对应 checker 已删除；只服务于托管 stable control plane 的历史方案保留在归档文档中。

- 默认不创建、购买、配置或调用付费产品；
- 默认构建和合并不因 `controlPlane.provisioning=not-provisioned` 失败；
- 不要求维护生产 secret、DNS/LB pool/monitor 或生产 evidence；
- 不允许可选路径静默改变当前客户端预检路径；
- 未来启用前必须另立 ADR、预算、授权、演练和回滚计划。

现有实现与恢复点见 [Cloudflare LB 与 stable control plane 实现归档恢复指南](../references/2026-08-29_070400_CloudflareLB与StableControlPlane实现归档恢复指南.md)。

## 当前生产与合并口径

- “Cloudflare LB / stable control plane 尚未纳管”不再单独构成默认分支并轨或常规 production build blocker；
- production build 仍执行正常 typecheck/build、bundle secret/internal-endpoint 扫描；运行时继续验证 origin、CORS、secret、binding 与 session；
- 管理后台 Access/direct-origin bypass、真实 secret、D1/R2/Redis、schema/version、用户可感知契约和其他独立 blocker 不因本决定自动关闭；
- 仓库已在 `34d79bec` 原子实现客户端 selector 与新 production gate；这不等于 production 已部署或已观察到真实切换；
- 本轮没有执行或授权 production deploy、DNS、LB、Access、secret、数据或服务器修改。

## 当前实现状态

- `config/hosted-routing.json` 直接提供 client-preflight 的公开 routing 与最小 operation safety，不再维护生成投影；
- Hono readiness 已补齐 `service`、`placement`、`contractVersion`、`no-store` 与 CORS contract；
- DR readiness 接收 canonical capability/method，复用同一 capability guard 校验目标 operation 的实际 secret、binding 与
  database session，并要求响应精确回显；通用 readiness 不会被客户端误当成 operation ready；
- Web 每个显式 generation intent 先探测、后固定唯一 placement；React intent latch 跨 rerender/重复 callback 保持同一
  intent 到 response body 终态；`fail-closed`/未登记 operation 不进入 DR，业务 dispatch 后写操作 transport/未知 5xx、
  stream/cancel 或 SSE EOF-before-done 不跨 runtime 重放，明确 SSE `done` / `error` 分别收敛成功/失败；readiness 复用共享
  contract version 兼容窗口；
- `pnpm verify:hosted-dr:client-preflight` 使用隔离 loopback HTTP transport 验证 primary ready、eligible DR、fail-closed 与
  POST disconnect 四场景，并输出 operation identity、placement、探测/POST 次数、latency 与 terminal class；
- Next/OpenNext production build 在生成静态产物后扫描 client bundle，拒绝缺失 routing token、服务端
  secret/binding 名称及任意 client JavaScript 的静态 `.internal` / `.local` / localhost/无点/IP endpoint；framework URL parser
  只允许精确 synthetic fixture，hostname 先移除尾随点并规范化 IPv6；scanner 读取完整 authority/path/query/fragment，
  识别大小写 scheme 与 protocol-relative string literal；credential、未知 URL metadata 与 internal endpoint fail closed 且错误
  不回显 candidate。既有公开出站链接仅按 `HTTPS 默认端口 + exact hostname/path/query keys/fragment` 窄规则放行；contract
  gate 同时比较 route ID、规范化 pattern 与 methods；
- Cloudflare LB/stable control plane 与旧 runbook 保留为 `reference-only`，没有进入默认
  workflow、production build 或付费成本基线；
- production deploy、真实生产 fault drill、客户端真实浏览器网络切换旅程和生产观测仍为 `DEFERRED`，不得用本地证据冒充。

## 开发入口

涉及 Hosted API origin、generation fetch、readiness、DR capability、production build gate、Cloudflare LB/DNS/Worker router 或跨 runtime retry 的 PR，必须：

- 在描述中引用 `ADR-hosted-dr-low-cost-client-preflight` 与 `SPEC-hosted-dr-client-preflight-v1`；
- 明确请求在 dispatch 前还是 dispatch 后；
- 明确 operation safety 与 dispatch state；
- 证明不会因 timeout/断线创建第二次 Provider 调用；
- 说明是否新增产品、固定费用、计量开支或生产资源；
- 若引入付费控制面，先形成新的 accepted ADR 与预算授权，不能在 feature flag、workflow 或环境变量中暗中激活。
