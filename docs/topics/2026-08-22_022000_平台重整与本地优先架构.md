## 当前执行窗口（2026-08-23）

当前分支已在 source commit `c5e789cd` 上通过 [Phase 2 退出审计](../logs/2026-08-23_195301_平台重整Phase2退出审计.md)：通用 contracts、最小 domain、`ai-core` / Direct、`local-library` 与跨运行时端口已经收口，且现有 Web 真实生产路径已消费共享 package。生产 Web/Hono/D1 Gateway 仍主要属于 legacy root/server 路径，`apps/*` 尚未形成真实应用集合；因此当前状态是“Phase 2 共享内核已通过门禁，Phase 2.5 真实应用边界激活尚未开始”，不能把 README-only 占位视为 MONO-002 完成，也不能把共享契约完成描述为 Web 本地库、Desktop 或 Arena Room runtime 已实现。

后续平台关键路径统一为：

```text
Phase 2 通用共享内核收口（已通过退出审计）
  -> Phase 2.5A apps/d1-gateway（当前下一步）
  -> Phase 2.5B-E Hono seam + apps/api + apps/web + Hosted DR
  -> Admin / Web local-first / Desktop 薄 PoC 并行
  -> Desktop MVP / Arena Room runtime 等后续阶段
```

执行约束：

- 在 Phase 2.5 退出前，Arena 多人业务轨只继续 contracts、纯逻辑、真实 Web consumer adapter、兼容/安全测试与阻断性修复；不继续展开 DO/WebSocket/D1/ticket/GenerationBridge/UI runtime。
- 在 Phase 2.5 退出前，Hono API 路由面默认不继续为“迁移覆盖率”扩张；优先拆除 Hono 对 legacy Next route module 的结构性耦合并形成真实 `apps/api`。
- Phase 2.5 同时建立 Hosted DR seam：Hono HK 是主执行面，Cloudflare Next/OpenNext 只保留显式 DR manifest 的长期 adapter；legacy import/wrapper 要删除，DR adapter 不删除。
- `feat/admin` 不整分支合并；Phase 2.5 后从 read-only 业务域开始迁入 `apps/admin`。
- Desktop 可以在 Phase 2.5 后尽早做最小 Tauri PoC 验证共享边界，但完整 MVP 等 Web local-library/Direct 数据语义稳定后再展开。

当领域实施计划与平台计划在同一分支上产生顺序冲突时，**平台阶段退出门禁决定“何时做”，领域规格继续决定“做成什么语义”**。这项优先级规则不允许借实施顺序修改已冻结的 Arena、认证、数据所有权或服务器权威语义。

## 当前稳定口径

### 1. 本地优先、按需联网

- Desktop/Mobile 在本地能够完成的编辑、卡库、历史、草稿、Direct AI 与本地模型调用，默认不得绕经项目服务器。
- APP 的本地功能不得要求用户先登录。
- 项目服务器只承担确实需要项目资源、全局共享状态或服务器权威的能力。

### 2. 服务器权威边界

- 官方 Hosted 生成、官方原生签名、严格排位、多人权威状态、线上卡库、账号、审核与治理继续由服务器控制。
- 客户端、客户端构建产物和客户端提交的数据均视为不可信输入。
- 本地 Direct 生成不能自行获得官方原生签名，也不能直接进入严格排位。

### 3. Monorepo

仓库迁移为 pnpm workspace。目标独立应用和部署单元为：

```text
apps/
  web/
  admin/
  api/
  d1-gateway/
  arena-room/
  desktop/
  mobile/
```

领域规则、协议、Direct AI、本地库、云端客户端与多人基础设施通过有明确依赖方向的共享包复用。

`apps/*` 只有在成为真实源码/manifest/构建/环境/部署所有者后才算完成应用边界迁移；占位 README 或空壳 manifest 只表示目标位置，不得作为阶段完成证据。

### 3.1 Hosted 运行时容灾

- `apps/api` / 香港 Hono 是 Hosted HTTP 默认主执行面；单台 VPS 不被视为业务事实源。
- `apps/web` / Cloudflare Next/OpenNext 对显式 DR capability/route manifest 提供长期灾备 adapter；两个 runtime 共享同一 service/domain/contracts，不维护两套业务逻辑。
- 客户端目标态只依赖稳定逻辑 API endpoint；切换 Hono/DR 不要求重新发布前端或 APP。
- D1/DO/R2 按领域继续持有权威事实；Redis 只保存可重建或允许丢失的 cache、rate-limit、lease、presence、Pub/Sub/telemetry 等状态。
- Hono 正常走 D1 Gateway；Cloudflare DR 尽量使用独立 D1 binding/Sessions，避免共享同一 Gateway 故障路径。
- safe/read 可以健康路由切换；generation/stream/settlement 等非幂等操作一旦可能开始执行，不得因为连接失败盲目跨 runtime 重放。
- D1 本身故障时不把 Redis 提升为数据库；线上权威能力明确降级，Local/Direct 路径继续可用。

### 4. 管理后台

- `feat/admin` 不再作为长期管理员专用分支。
- 后台迁入独立 `apps/admin`，Cloudflare Access 是入口访问控制；若 origin 为自托管/VPS，再使用 Tunnel 或等价的 origin-bypass 防护。若 Worker 本身就是 origin，可直接使用 Worker/hostname Access，不为满足形式要求强制增加 Tunnel。
- Access 之后仍执行 Origin/JWT（按实际部署形态）、应用层 RBAC 与审计；现有分支中的“管理员本地运行即可信”假设不得原样带入公网部署。

### 5. Direct AI

- 供应商登记簿是便捷预设，不是允许名单。
- Desktop/Mobile 允许用户显式创建自定义供应商、端点、模型和请求参数。
- APP 首期以本地 Direct 为主，可以不提供 Hosted 生成。
- Direct 请求不得携带项目 Cookie、Legacy Bearer、Better Auth session、活动令牌或服务器秘密。

### 6. 本地库与线上库并列

- Web 使用独立 IndexedDB 本地库；Installed APP 使用 SQLite 等适合其运行时的持久存储。
- 本地库不占用线上卡槽。
- 首期只支持显式“保存到本地、上传副本、下载副本、导入、导出、备份/恢复”，不做自动双向同步。
- 存储位置与原生性是两个正交维度。

### 7. 公开仓库与发行

- 服务器密钥、项目 AI Key、签名私钥、数据库凭据和发布私钥不得进入仓库或客户端包。
- Desktop 首选 Tauri 2，Electron 作为经 PoC 触发的后备方案。
- Desktop 通过 GitHub Releases 分发，并使用 Tauri Updater 签名校验更新。
- Android 可通过 GitHub Releases 分发签名 APK，但不得把 Desktop Updater 方案误用于移动端。
- iOS 发行作为独立工作流，不阻塞 Desktop/Android。

### 8. Legacy 兼容范围

Legacy 登录在本轮大重整中保持现状，不改变用户流程、不下线 authkey，也不混入本轮迁移。较早提出的 Legacy 收口与短期令牌设计保留在后续 backlog。

### 9. 旧 PVP

- 旧 PVP 去留与正在推进的 Arena 多人协作不是同一决策。
- 不凭代码规模或主观印象直接删除 PVP；先采集使用、完成率、复玩率、成本与维护负担。
- 若决定下线，先抽取可复用的房间、参与者、版本控制、事件与恢复能力，再移除 PVP 产品层。

### 10. Arena 多人协作

2026-08-21 的 Arena 多人协作 v1 规格与计划继续作为该业务域的权威文档；部署边界由 Arena Room ADR 补充冻结：

- **产品层不拆 Arena**：多人入口、配置和结果继续整合在现有 `/arena`。
- **运行时拆 Room**：`apps/arena-room` 独立承载 WebSocket、Durable Object、alarm 与最小房间状态。
- Room Shared Config 只保存安全白名单投影，不保存 Provider 凭据、完整本地私有卡或战报运行态。
- host-local 完整 payload 不进入 Room plane；权威生成确有需要时，只按既有 generation contract 临时直送 generation service。
- 成员同步后在本地编辑，Proposal 除 `baseRevision` 外还必须有 typed base precondition，服务端/DO 可在不保存无限 revision 历史的情况下判定 stale conflict。
- 生成由房主发起并冻结不可变 snapshot；一次用户意图使用稳定 `generationRequestId`，浏览器/网络重试不得重复生成。
- 房主浏览器不是 AI stream 的房间中继；generation service 通过受认证的 GenerationBridge 向 Room 批量发布。
- Hibernation reconnect 使用 durable control cursor；story delta 是可恢复失败的临时展示流，最终战报以权威 generation storage 为准。
- Monorepo 迁移可以调整文件路径，但不得静默改变上述语义。
- 实施顺序受平台计划 Phase 2.5 门禁约束：当前已完成的 contract/纯逻辑成果保留；Room runtime 在真实 Web/API 应用边界激活后恢复，避免平台重整分支继续被单一功能纵向开发占用。

## 已延后但有明确门禁的事项

1. **Mobile Runtime 最终选型**
   - 比较 Tauri Mobile 与 Capacitor；
   - 通过 Mobile PoC 门禁后形成单独 ADR。

2. **旧 PVP 去留**
   - 完成生产数据盘点后单独决策；
   - 不影响 Arena 多人协作 v1 继续推进。

3. **APP Hosted 生成**
   - Desktop/Mobile 首期不要求；
   - 只有在用户价值和项目资源预算明确后再设计。

4. **本地库自动同步**
   - 首期明确不做；
   - 等显式复制流程稳定后再评估双向同步和冲突模型。

5. **iOS 发行**
   - 独立评估签名、审核、地区与分发要求；
   - 不阻塞 Web、Desktop 和 Android。

6. **签名算法升级**
   - 当前服务器 HMAC 原生签名继续有效；
   - Key ID、轮换与非对称签名另立规格。

7. **多人 Direct 生成**
   - v1 继续由服务器执行唯一权威生成；
   - 未来若允许房主 Direct 生成后共享，只能作为非权威休闲模式，并需单独 ADR。

## 开发入口

涉及以下范围的 PR，必须在描述中列出对应规格编号并说明符合情况：

- Monorepo 目录或依赖边界；
- Direct AI、自定义 Endpoint 或 API Key；
- 本地库、导入导出或线上卡槽；
- Desktop/Mobile runtime；
- Admin 上线与权限；
- 原生签名、排位、多人与服务器预算；
- Hosted Hono/Cloudflare DR、Redis/D1 authority、failover/replay；
- Arena Room Worker / Durable Object；
- GitHub Release、自动更新或发布密钥。

如实现需要违反当前权威口径，应先新增或更新 ADR，不得只在代码、feature flag 或 PR 评论中临时改变边界。

实施排期必须同时检查平台 plan 与领域 plan：平台 plan 的阶段门禁优先决定跨应用/跨运行时工作的启动时点；领域 plan 不得仅因为自身“下一阶段”已排到 runtime，就跳过尚未闭合的 Monorepo 应用边界。
