计划标识：`PLAN-arena-reconciliation-recovery-v1`

审查基线：`a4beb4002170b6f212c930be5e882fbf72e6d803`

**目标：** 恢复 Arena 战报完成后的角色历战记录/当前状态写回，并让首次写回失败能够安全重试，同时保持 G25R 的 generation owner、服务器冻结 effect、base revision fencing 与原生签名边界。

**架构：** 浏览器 reconciliation 必须同时携带 create 使用的业务认证头和 anonymous actor token；Web 服务端直接以同一 actor resolver 解析身份，并在一次 D1 读取中联合验证 owner、completed/finalized terminal 与有界 reconciliation manifest。失败恢复只重入当前 `generationId + baseRevisionHash` 的服务器冻结 effect，不再启动第二个 Provider，也不再用客户端 meta 或模糊 history 匹配获得服务器签名。

**技术栈：** TypeScript、React 19、Next.js 15 Route Handler、Vitest、D1 data port、pnpm workspace。

## 1. 已确认根因与不变量

### 当前故障链

```text
createGenerationApiIntent
  -> Authorization / activity headers + anonymous actor token
  -> actor = user:<id>
  -> D1 generationOwnerHash = SHA256(user:<id>)

update-combatants-after-stream raw fetch
  -> 只有 anonymous actor token
  -> actor = anonymous:<id>
  -> Next replay store 固定 unavailable
  -> D1 owned terminal 对错误 owner 返回 not-found
  -> 503 GENERATION_STATE_UNAVAILABLE
```

`apps/web/components/arena/hooks/useBattleStorySession.ts` 的连续故事角色同步存在同一凭据遗漏。

### 必须保持

- reconciliation 继续忽略客户端 `report`、`impacts`、guidance 与 write flags；
- `generationId` 不是 credential，必须重新解析请求 actor；
- wrong-owner 与 row-missing 对用户保持不可枚举，但内部日志区分低基数 reason；
- `baseRevisionHash` 必须同时匹配本地卡正文与 terminal 冻结 hash；
- 原生卡签名无效只能降级，客户端 manual impacts 不得获得服务器原生签名；
- 重试不得启动新 Provider，不受 Provider cooldown 限制；
- Next/OpenNext 继续使用 unavailable active replay store，不建立第二套 generation lifecycle。
