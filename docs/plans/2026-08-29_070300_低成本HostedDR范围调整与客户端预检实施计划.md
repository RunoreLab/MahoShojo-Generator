## 1. Objective

在不相对于上述默认分支成本基线新增付费产品、不执行生产操作、不删除有价值 DR adapter 的前提下：

1. 把默认 Hosted DR routing 从 `managed-control-plane` 收敛为 `client-preflight`；
2. 让常规 `new-request-only` generation 在首次 dispatch 前根据 Hono readiness 选择 Hono 或 Next DR；
3. 保持 `fail-closed` capability、ambiguous outcome 和 no-replay 安全边界；
4. 用新的 production validation 原子替换仅因 stable control plane 未纳管而失败的旧 gate；
5. 将 Cloudflare LB/stable control plane 成果保留为不激活、可恢复的 optional path；
6. 完整测试、审查并更新主题/日志，不执行 DNS/LB/Access/secret/data/deploy。

## 2. 实施前事实与迁移差距（冻结基线）

以下内容冻结计划形成时的实现事实，用于解释迁移理由；当前结果以本计划顶部 checkpoint 和实施日志为准。

当前已经具备：

- `config/hosted-dr-capabilities.json`：active-passive、primary/DR origin、probe path、request class、`drMode`、replay policy；
- `apps/api/src/health.ts`：`GET /api/health/ready`，按配置检查 Redis/D1 并返回 200/503；当前 body 尚无 Hosted DR `placement` / `contractVersion`，response 也尚未显式设置 `Cache-Control: no-store`；
- `apps/web/app/api/hosted/dr-readiness/route.ts`：Next DR readiness + capability guard；
- `apps/web/config/hono-api.ts`：production activation/build gate；
- `apps/web/lib/hono-api-routing.ts` 与 `apps/web/lib/hono-api-client.ts`：静态 Hono URL 解析和统一 generation fetch；
- `scripts/check-hosted-dr-contract.mjs`、`check-hosted-dr-schema.mjs`、`generate-hosted-dr-client-config.mjs`、`hosted-dr-client-config.mjs`、`verify-hosted-dr.mjs`：manifest、投影和验证工具；
- 双 runtime adapter、DatabaseProvider、版本兼容、fault evidence 和 no-replay tests。

当前差距：

- production client projection 不暴露 client-preflight 所需的最小 public primary/DR routing metadata；
- primary readiness 尚未提供可由客户端验证的 Hosted placement/contract version 与显式 no-store contract；
- production gate 把 `controlPlane.provisioning=not-provisioned` 当作 placement 未就绪；
- generation fetch 在 build-time 选择 Hono/同源，没有 per-intent readiness selector；
- 没有独立 immutable placement decision、ambiguous outcome 和 no-cross-runtime-replay client contract；
- optional paid control-plane 与 current path 的规范地位尚未在代码/schema/workflow 中分开；
- 当前 `fail-closed` 与 `new-request-only` capability 不能只凭 route inventory 区分，必须以 DR manifest 为准。

## 4. 原子实施单元

### P0：Schema 与 generated projection

目标：先建立单一机器事实，再改客户端。

工作：

1. 为 Hosted DR manifest 增加显式 `defaultMode=client-preflight` 与 `managedControlPlane=optional-disabled` 语义；
2. 冻结 `preflightTimeoutMs`、primary/DR probe path 和 public placement；
3. 为 route + method 生成最小 eligibility projection；
4. 以向后兼容附加字段扩展 Hono readiness：`placement=hono-primary`、shared `contractVersion`、`Cache-Control: no-store`；DR readiness 保持同一 shared contract；
5. 更新 schema/validator：
   - `fail-closed` 不得投影为 eligible；
   - production `client-preflight` 允许 `provisioning=not-provisioned`；
   - managed mode 仍要求其独立 evidence；
   - public origin 必须安全、规范、无凭据/query/fragment；
6. 更新 generated file drift test、readiness contract test 和 client bundle secret scan。

退出门禁：schema/contract/generator targeted tests PASS；生成文件无 drift；没有客户端代码行为变化。

建议原子提交：`refactor(platform): 冻结低成本 Hosted DR 路由模式`。

### P1：纯 selector 与 probe adapter

目标：建立可穷举测试、无 UI/React 依赖的选择核心。

建议结构：

```text
apps/web/lib/hosted-dr/
  client-preflight-policy.ts   # pure lookup/state transition
  client-preflight-probe.ts    # fetch + AbortController adapter
  client-preflight-types.ts
```

工作：

1. 实现 route/method policy lookup；
2. 实现 primary 单次 GET probe，默认 1500ms，固定 `cache: 'no-store'`、`credentials: 'omit'`，验证 service/placement/contract version；
3. 仅在 primary non-ready + eligible 时实现 DR 单次 GET probe，并验证 placement/contract version；
4. 返回 immutable `HostedPlacementDecision`；
5. 结构化分类 timeout/non-ready/protocol/CORS/network；
6. 增加 fake timer/fetch tests，证明 probe 次数上界和 `fail-closed` zero-DR behavior。

退出门禁：规范状态表全覆盖；没有业务 POST；测试不存在真实网络依赖。

建议原子提交：`feat(web): 建立 Hosted DR 客户端预检选择器`。

### P2：Generation client 集成与 route pin

目标：每个新 generation intent 只 dispatch 一次。

工作：

1. 将 `generationApiFetch` 或其上层 port 改为先 selection、后唯一 fetch；
2. 为调用方提供 intent/operation scope，防止 React rerender、callback retry 或多个 helper 重复选择和 POST；
3. 保持 auth/activity headers、credentials 和 public wire；
4. primary selected 时使用 public Hono origin；DR selected 时使用同源 Next route；
5. POST 被调用后所有 transport exception 映射为 ambiguous outcome，不触发第二 selector/POST；
6. streaming EOF/cancel/read error 保持所选 placement；
7. 对稳定 request/generation identity 的恢复接口继续使用其各自 manifest policy，不重新生成。

应先选择 1–2 个代表性常规 generation route 纵切，再扩展所有 `new-request-only` family；不得同时纳入 Arena `fail-closed` route。

退出门禁：代表性 route 的 primary-ready、primary-down/DR-ready、双端 down、POST timeout、stream disconnect、rerender replay tests PASS；Provider/POST invocation count 精确为 0 或 1。

建议原子提交：`feat(web): 在生成 dispatch 前选择 Hono 或 Next DR`。

### P3：Production gate 原子替换

目标：关闭付费 control-plane blocker，但不降低生产配置安全。

工作：

1. 修改 `apps/web/config/hono-api.ts` 与相关 parser/test；
2. 在 `client-preflight` 模式下接受 `provisioning=not-provisioned`；
3. 同一提交增加新的 origin/probe/projection/eligibility/adapter/CORS/secret/no-replay gate；
4. 保留 `managed-control-plane` optional mode 的严格 activation evidence，但默认不执行；
5. 检查 `.github/workflows/cloudflare-deploy.yml`、preview workflow、package scripts 与 build env，移除仅为未购买 LB 设置的默认 blocker；
6. 不改变 production deploy branch、environment protection 或 secret 注入范围；
7. production build、OpenNext build、local/test/preview config 全部验证。

退出门禁：不存在一个 commit 状态是“旧 gate 已删、新 gate 未生效”；错误配置 mutation tests 全部 fail closed。

建议原子提交：`fix(platform): 以客户端预检门禁替代付费控制面前置`。

### P4：Telemetry、错误投影与真实隔离演练

目标：证明行为、成本和 no-replay，而不是只证明源码存在。

工作：

1. 增加低基数 selection telemetry；
2. 为 `DR_NOT_ELIGIBLE`、`NO_READY_PLACEMENT`、`AMBIGUOUS_OPERATION_OUTCOME` 接入安全用户文案；
3. 在隔离 Hono/Redis/D1/Next 环境执行：
   - Hono ready → one primary POST；
   - Hono unavailable → eligible one DR POST；
   - Hono unavailable → fail-closed zero DR POST；
   - primary probe ready 后 POST 断链 → zero DR replay；
4. 记录实际 preflight latency 与误切换情况，为未来 timeout/cache 调优留证据；
5. 不使用真实用户请求或 production Provider 费用做首次验证。

退出门禁：fault evidence 包含请求计数/operation identity/placement/terminal；无 prompt/body/secret；用户可感知 contract gate PASS。

建议原子提交：`test(platform): 固化客户端预检与不重复生成证据`。

### P5：可选控制面收口与最终审查

工作：

2. 逐项分类 KEEP / OPTIONAL / DELETE；
3. optional path 加清晰状态，不加载 production secret，不注册默认 workflow，不影响 build；

   - 成本/部署面；
   - non-idempotent/replay/authority；

## 6. 回滚

实现应保持以下回滚 checkpoint：

1. P0 schema/projection 可独立 revert，恢复旧生成配置；
2. P1 selector 未接业务时可直接 revert；
3. P2 client 集成 revert 后恢复静态 Hono/同源 routing；
4. P3 gate 必须与 P2/P0 作为一个兼容组回滚，不能只恢复旧 blocker而留下新 projection，或只删新 gate；
5. P4 telemetry/error 可在不改变路由语义时独立 revert；
6. optional control-plane 资产不在本轮删除时无需恢复生产资源。

发生以下任一情况必须回滚/停止：

- 观察到两次业务 POST 或两次 Provider start；
- `fail-closed` route 被发送到 DR；
- auth/actor/signature/authority 语义漂移；
- client bundle 出现 secret/internal endpoint；
- production build 在错误配置下通过；
- readiness 导致显著误切换且无法在有界 timeout 内修正；
- 实施需要新增付费产品或未经授权的生产操作。
