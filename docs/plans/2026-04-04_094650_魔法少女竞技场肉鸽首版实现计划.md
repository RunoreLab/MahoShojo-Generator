# 魔法少女竞技场肉鸽首版 Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** 在本地浏览器中落地“魔法少女竞技场”世界的路径式叙事肉鸽 MVP，先完成可恢复、可通关、可失败、可流式 AI 裁定的单人挑战闭环。

**Architecture:** 新增独立的 `/challenge` 页面与 `lib/challenge/*` 领域层，复用现有竞技场的角色参数、排行榜/赛季来源、流式 Markdown、隐藏 meta comment 与结构化修复链路。共享层只承载挑战编排状态，世界数值进入 `worldState`；客户端负责本地存档、地图与系统节点，服务端只负责远端敌人候选归一化与 AI 流式裁定。

**Tech Stack:** Next.js Pages Router、React 19、TypeScript strict、Zustand、IndexedDB、Cloudflare Edge Runtime、Vercel AI SDK 1.x、Bun test、Tailwind 4

### 关键实现约束

- `ResourcePresentationPresetV1` 实例不放数据库、不放 JSON 配置，首版直接由 `lib/challenge/worlds/arena/preset.ts` 导出，并由 `lib/challenge/world-registry.ts` 注册

- `challenge_nodes.encounterSnapshot` 必须冻结 `rewardOptions / eventOptions / shopOffers`
- `challenge_checkpoints.snapshot` 只信任 `snapshot.runState.mapState`，不再单列 `mapState`
- `battle / elite / boss` 与 AI 事件走流式 API；`rest / shop / choice-only event` 坚持纯本地系统结算
- 第一个可玩里程碑必须是“无 AI 也能从开始走到结束”的本地闭环
