# 不可信 Web 内容受限策略与确认共源合同

状态：**维护者已同意的有限后继合同；纯策略 / Web 消费 / 普通确认与 Native 固定政策已分片接线；自动验证和 Windows 门禁单列，产品执行仍关闭**。纳入[唯一 Desktop 计划](./2026-09-30_160100_Desktop客户端阶段实施计划.md) D4 / b2-B2，不另开平行执行计划。

2026-10-10 维护者同意按内容类型共用 Web 既有两套受限联网策略和确认交互，保留 Desktop 零 Native 权限，不迁入 Web 可选的高风险同源运行。HTTPS / WSS 不保证仅公网；本合同没有完整私网过滤、远程代理、实际外联探测、系统网络设置或生产部署授权。

## 1. 当前事实与目标

- Web 自由 HTML：`ArenaWebReport` 的 `srcDoc` iframe 使用 `sandbox="allow-scripts"`，继承主站 CSP；主站环境决定生产 / 开发及 Turnstile / Insights / GA 固定域集成
- Web 包：固定 runner 页投递物化内容，受限 iframe 无 `allow-same-origin`；runner 允许 HTTPS / WSS 及必要 data / blob 资源，禁 Worker / frame / form / object 等。Web 另有高风险 same-origin 信任流程，本合同不迁移或修改它
- Desktop 诊断：原 be802 / origin 修复片的 Native HTML 仅 `sandbox allow-scripts`，不保证禁止 HTTP / WS；[Windows 回传与来源修复](../runbooks/2026-10-10_074400_D4b规范来源与Document关闭有限补验.md)已将网络与零 Native capability 分开。普通确认本身不等于网络策略已切换；本合同第 4 节的后继才接入实际响应头，Windows 新策略仍待验
- Desktop 产品结果：`/battle`、`/arena` execution port 仍不可用，主 UI 不执行用户 HTML。共源政策和诊断面不能替代 D4 实机门禁

目标是**同一规则 owner、内容类型分开、宿主机制明确适配**，不承诺两端 CSP 字节完全相同，也不把两套政策合成更宽的一套。

## 2. 第一片：纯策略与真实 Web 消费

唯一规则 owner 位于 `packages/web-package/src`：`execution-policy.ts` 保纯主站 composer，`runner-policy.ts` 保固定 runner 字串，`desktop-execution-policy.ts` 单独适配 Native transport；分别经同名显式子路径导出。无 DOM、环境读取、账户、存储或网络请求，也不手写第二份 CSP。Web client 的 frame 仅导入宿主 `runner-client.ts` 的固定路径，响应 header / composer 和 Desktop adapter 不属于这个 client 入口。

- 将现 Web `buildContentSecurityPolicy` 的纯 composer 完整迁入；Web `browser-headers.ts` 实际调用共享实现，`next.config.ts` 保留原环境读取与开关选择
- 将现 runner 固定 directives 完整迁入；Web runner header 实际消费该常量，bootstrap、frame sandbox、nonce 握手与高风险额外信任均不变
- 自由 HTML 的 Desktop 规则基线固定生产、关闭可选主站集成标志，不借开发 HMR 的 `unsafe-eval`、HTTP 或 WS；其脚本来源不得偷换成包策略的任意 HTTPS
- Web 原生产 / 开发 × 三个集成开关共 16 组合及 runner 字节，冻结自 `6219048b11391e272d2cc4dd3db15d549560020b` 的未修改实现，存于 `packages/web-package/tests/fixtures/web-execution-policy-baseline.json`。金样含原文本与 SHA-256，回归逐字比较；Web 集成测试另验证真正消费共享 owner

第一片只准备 Desktop 生产政策常量；实际 Native 消费在第 4 节独立后继，不能拿第一片的 UI / owner 测试替代它。

## 3. 普通确认共源与宿主所有权

共享普通确认视图放在 `packages/ui-web/src/arena-report`，复用现 `BaseModal` 与风险文字/按钮。视图受控，不读写 localStorage，不签发同源信任，不决定执行目的地。

- Web 保留现 `useWebConsent` 的 session / localStorage / 多人 room 语义与“此浏览器不再提示”选项，真正回用共享视图
- Desktop 诊断只按原样运行已重验的本地包；展示实际 manifest 名称 / 版本，逐次确认，不显示或保存长期记住选项
- Desktop 取消、卸载、刷新或目标失效时不能派发 begin / append / open；重复确认不能重复执行。复用现 owner / epoch / flight 围栏，不能新增关闭或授权 command
- 确认 Native open 已派发后，离页不能冒称撤销窗口；仍沿既有晚回执忽略与用户正常关闭语义

## 4. 第二片：Native 固定消费，不开放产品运行

当前源码已按以下边界接线；本节不代表 Windows 验收通过：

1. `generate-desktop-web-execution-policies.mjs` 从唯一 owner 生成固定 `generated/web-execution-policies.json`，`workspace:checks` 包含 `--check` 漂移检查。Rust `include_str!` 消费同一清单，不手写第二套 CSP
2. `contentKind` 仅 `free-html` / `web-package`，由已验证来源的可信主 UI 选择，begin 时冻结。省略兼容旧包请求并解释为 `web-package`；显式 null、非法值和未知 CSP / URL / 网络字段均拒绝。append / open 不接受改类型；现包 bridge 显式固定发包类型，不读取 snapshot 的同名额外字段
3. Native 在每个 HTML 响应（含 Range 和包内次页）硬追加 `sandbox allow-scripts`，清单缺坏 fail closed，类型不能去掉 sandbox 或加入 `allow-same-origin`。保留原权限、独立窗口、incognito、导航、新窗、下载、规范 URI / label-instance 钉定与生命周期
4. transport 来源固定为 `maho-webpkg://localhost` 和 Windows 的 `http://maho-webpkg.localhost`，无端口 / userinfo / 通配 / `http:` 泛来源。仅 script / style / img / font / media / connect 六类添加这些来源；包原 worker / frame / object / manifest / form 五个 `'none'` 逐项不变，自由 HTML 保原较窄脚本 / 样式 / 字体及 frame / worker 语义
5. `base-uri` 独立适配固定本地来源，用于包显式 `<base>`；普通相对资源本来不依赖 base 标签。独立窗 `frame-ancestors` 固定 `'none'`；两策略保生产等效 UIR。除这三处宿主差异及上述六资源来源外，各 directive 与 Web 基线逐项相同
6. 诊断只按包原样运行并逐次确认；自由 HTML profile 只是预备，尚无正式自由文档数据准备 / 校验 / 运行 bridge。`/battle`、`/arena` 产品运行 port 继续关闭，不因可选枚举接通产品执行

### upgrade-insecure-requests 的证据边界

保留自由 HTML 原生产规则，不因为 Desktop 当前使用 `http://maho-webpkg.localhost` 就删除 UIR 或切换 `use_https_scheme`。Chromium 2026-10-10 核定 commit `793cfcc178df1afee0faac67649e9269af47e7a9` 的[升级函数](https://github.com/chromium/chromium/blob/793cfcc178df1afee0faac67649e9269af47e7a9/services/network/public/cpp/content_security_policy/content_security_policy.cc#L1579-L1594)先排除 potentially trustworthy URL；[官方已有测试](https://github.com/chromium/chromium/blob/793cfcc178df1afee0faac67649e9269af47e7a9/services/network/public/cpp/is_potentially_trustworthy_unittest.h#L213-L225)包含 `vhost.localhost` / 多级 `.localhost`。这是保留现映射的源码依据，**不是 WebView2 154 二进制实测**。

Web 包 runner 自身不含 UIR，但其生产父页的 insecure-request policy 可能按[继承规则](https://www.w3.org/TR/upgrade-insecure-requests/#inheriting)影响嵌套页面；不能仅据 runner header 缺少 UIR 就宣称 Web 包一定不升级 HTTP。Native 独立窗已在 shared adapter 明确补入生产父页等效 UIR，不能暗中放宽外部 HTTP，也不能把 CSP / 混合内容 / CORS 各层失败混为一谈。

## 5. 验证与停止条件

- 第一片：16 组金样及 runner 逐字保持、实际 Web 消费、共源确认视图、Desktop 取消/竞态/卸载/重复确认；受影响 package 与 app 定向测试、lint / 类型检查，最终整合完整 CI 另记
- Native 后继：固定 manifest 漂移、两 profile 差异、缺失/非法类型与兼容调用、HTML / Range 响应 policy、非规范 origin 与跨 instance 仍 404；不收任意字符串政策
- Windows 后继：规范 handler URI + 自身图片 / 相对脚本 / CSS / fetch 的真实加载与 CSP、UIR 结果；沿有限合成夹具和隔离命名空间，不拿纯测试或旧 be802 回传冒称新网络 policy 已验
- 若固定本地资源 transport 不成立或无法证明 sandbox / instance / Native 隔离，停依赖它的执行分支；不靠删 CSP、扩 capability、忽略安全错误或改系统网络配置通过
