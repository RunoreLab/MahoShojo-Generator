# Arena 高级单次配置与历史编辑实施合同

状态：范围已冻结并通过独立审查；源码实施与完整本地 CI 已完成，见[验收报告](../reports/2026-10-10_012025_DesktopArena高级单次配置与历史编辑验收.md)。本合同是唯一 Desktop 阶段计划 D5.1b **b2-A** 的有限工作切片，不关闭整个 b-2。基线为 b1-B2 已验证源码及其文档树；下列“冻结时事实”保留立项上下文，不改写既有验证或发布证据。

依据：[唯一阶段计划](./2026-09-30_160100_Desktop客户端阶段实施计划.md)、[产品共源规格](../specs/2026-10-06_084200_双端产品对齐与设置共源规格.md)、[本地优先与可执行内容规格](../specs/2026-10-02_184000_Desktop产品一致性与本地优先规格.md)、[b1-B2 实际交付](../reports/2026-10-10_001340_DesktopBattle薄宿主纵切与验收.md)。仅增加本地高级单次配置与活动历史编辑，不修改既有权限或预算决定。

## 冻结时事实与本片目标

Desktop `/battle` 已有普通四模式、结构化及 Markdown 流式 Direct、角色/分队、主情景、素材、故事设置、活动历史追加与显式本地另存。`/arena` 尚未登记。Web `components/arena/ArenaPage.tsx` 已有高级单次工作区，包含辅助情景、问卷 Lore、手动判定和叙事历史编辑；还混有排位、多人、Web 报告、连续故事及插图入口。

本片目标是让真实高级单次工作区共源，完成 Desktop 选择/编辑 → 冻结单次输入 → 现有 Direct → 结果 → 显式另存 → 重开旅程，之后才登记 `/arena`。页面明确标示当前支持的高级单次能力，不能称全部 Web Arena 已迁移。`/battle` 保持简洁独立产品；二者共享执行/session 实现，分别持有活动 session 与不同草稿 key，不自动导入、覆盖或互相清理草稿。

## 共源接缝与实际消费者

| 接缝 | 当前真实来源 | 迁移要求 |
| --- | --- | --- |
| 高级页面布局 | `apps/web/components/arena/editor/ArenaEditorWorkspaceLayout.tsx` 及 `ArenaPage.tsx` 的外框 | 抽受控双栏、折叠区块与页框；标题、说明、折叠持久化由宿主 ports 提供。Web 保持当前标题、storage key、默认展开和 keepMounted 行为；Desktop 不复制近似表单 |
| 角色/分队/主辅情景/素材/故事 | `packages/ui-web/src/arena/` | 直接消费已共享控件；辅助情景以现 `ArenaScenarioSection` capabilities 接线，不另写选择器。旧主情景、辅助情景和素材语义区分不变 |
| 手动判定 | Web `AdjudicatorSettingsPanel.tsx` 外壳、现有 `ui-web/character-manager` 的 `AdjudicatorEditor` | 外壳共源并保 Web 回用；只编辑现领域事件结构，不引入新算法。执行仍复用 `domain/arena-adjudication` |
| 问卷 Lore | Web `QuestionnaireLorePanel.tsx`、`utils/questionnaireRequest.ts` | 受控 UI 与纯请求投影共源，原 Web wrapper 保查询/云选择；Desktop 复用现有问卷 domain、content、卡库和文件端口，支持预设、本地/公开缓存及上传粘贴，不复制解析器 |
| 活动叙事历史编辑 | Web `NarrativeHistoryModal.tsx`、`useNarrativeHistoryStore.ts` | 将列表/新建/编辑/排序/重排/导入导出视图与少量尚未共享的纯 entry 行为分离；Web 保原 store、key、version、migration、hydration、quickCheck、云保存。Desktop 使用既有 Arena draft 和 CardRepository，不新增历史数据库 |

现 `domain/narrative-history-operations` 已实现顺序、排序、移动、重排、导入提取、合并、追加和生成去重；直接复用。尚在 Web Modal 的归一化、卡封装，以及 store 内 update 纯逻辑按现行为迁出，时间和缺失 ID 由宿主注入。不得在 Desktop 新建第二套 entry 格式。G4 `NarrativeHistoryPicker` 仍只读选择外部参考，不能承担活动历史编辑。

## 数据、存储和执行边界

1. 初始设置、完成资格、角色 unsigned 工作副本、默认关闭叙事历史自动追加、显式另存及 existing-wins/tombstone 语义沿 b1-B2。新增 UI 不改变“生成成功”和“保存到库成功”两个状态。
2. `/arena` 使用独立版本化草稿 owner/key；`/battle` 旧 key 和合法恢复内容不变。可通过现 session 依赖注入区分 key/capabilities，不复制 session 状态机，也不引入新的通用存储框架。草稿损坏、未来版本、超限及失败保原件/内存与显式恢复机制仍适用。
3. 活动历史以原始 entry ID 编辑。显示排序不改提示词顺序；用户显式重排才改变顺序。追加/覆盖导入复用原规则和重复 ID 处理；覆盖、删除、清空均明确确认。导入原文与可编辑规范投影分开保存/导出，说明原归一化损耗；未知字段不能被宣传为已无损进入规范卡。源库卡不自动覆盖，G4 聚合临时 ID 不回写。
4. 历史新增/编辑的局部草稿、粘贴、判定和 Lore 编辑统一参与当前页唯一 dirty/busy/close guard。关闭编辑器或切换选中 entry 时不得悄悄丢未提交正文；在途导入/保存不能用取消窗口冒充已取消写入。异步操作沿原 scope fence。
5. Web 的 quickCheck 和云保存是 Web host 行为；Desktop 本地编辑不得隐式调用项目过滤/云接口，不据此获得云端已审核标记。显式云能力仍走其原宿主合同，本片不新开。
6. `ai-core/arena-generation/input-snapshot` 已承载 auxiliary scenarios、questionnaires/selections 和 adjudication events；沿现业务投影和 B1 adapter 派发，不造 full/lite 双执行器。新增编辑输入应有严格草稿结构校验，合法未知扩展保持来源原文保真。
7. 事件执行包含手动、角色和当前主辅情景；素材、问卷 Lore 的嵌入事件不被提升为执行输入。Web `useBattleActions.ts` 的辅助情景选择/上传/粘贴均会继承事件；沿 `lib/arena/adjudication-events.ts` 和 store 现 sourceKey 身份规则，沿现实现，仅非空有效事件按 sourceKey 替换该来源事件而不累计；空事件和旧版格式仍按既有 early-return，不借抽取改写 Web 行为。source 身份沿 card ID > 文件名 > 标签，移除仍按全局同 key 过滤，不新建引用计数或实例身份。切换/移除/清空来源沿当前 store 操作移除关联事件，手动事件按原规则保留。需要共源此来源纯核并对拍，不能只在生成时盲目拼接后造成重复或覆盖用户编辑。任务冻结时一次本地掷骰，重绘、编辑、取消或晚包不重掷；本地结果不构成服务端权威。b1-B2 未开放辅助情景，不回改其冻结范围。
8. 保留 32 角色、256 总参考项、模式最少 2/2/1/1、原业务 12 MiB 和 decoded text+reasoning 4 MiB。辅助情景、素材、问卷和实际历史引用共同按现 contracts 计数。草稿 4 MiB 字符与本地卡完整封套 4 MiB 字节上限不变；保存超限显式失败，内存内容和完整原件可导出，不裁截生成数据。

## 独立后继，不在本片开放

- **Web 报告/包格式**：Web `ArenaWebReport.tsx` 包含执行脚本的 iframe、包重放/信任、外部资源与导出，不是一个文案开关。Desktop 已有 D4b `webpkg-instance-bridge.ts` 和隔离窗口机制；后继应复用它并单独验收生成输出/包引用/许可/导出链，禁止搬 Web 主界面 iframe。本片保留 `reportFormat=web` 的 Direct 拒绝与零入口，不重造格式/包系统，也不以静态检查关闭 D4 运行期门禁。
- **Hosted**：Next unavailable replay store 的 create 阻断仍存在；固定 Hono origin、actor/auth、恢复与取消授权或 Next active runtime 须独立冻结。不得借已有通用 Hosted command 绕开 Arena 实际创建协议，不回落 Direct。
- **连续故事**：现 `useBattleStorySession.ts` 依赖 battle-story session/chapter/checkpoint 仓储与 summary/reconciliation 端点；不是普通 history 卡编辑。其存储、分支/重写、恢复/no-replay 单独迁移。
- **插图**：`BattleIllustrationPanel` 依赖 TachieGenerator、图片资源与 media proxy；生成/上传/导出各自的媒体预算和权限另案。现结果卡 illustration port 不等于图像旅程已交付。
- Strict、自由排位计分、随机线上匹配、占位角色、多人及其权威写入不在本片；未实现动作隐藏，不添加可点击占位入口。

## 文件 ownership 与原子顺序

1. **共享 UI owner**：`packages/ui-web/src/arena/**`、新增 `narrative-history` 编辑视图与相应 UI tests；Web `ArenaEditorWorkspaceLayout.tsx`、`ArenaPage.tsx`、`AdjudicatorSettingsPanel.tsx`、`QuestionnaireLorePanel.tsx`、`NarrativeHistoryModal.tsx` 的 adapter 和 DOM tests；ui-web exports 由此 owner 统一维护。不得改 Desktop session 或 Web store 持久化配置。
2. **纯逻辑 owner**：`packages/domain/src/narrative-history-operations.ts` 或新增窄 subpath、其 tests/exports；问卷请求纯投影及 Web `questionnaireRequest.ts` wrapper；事件 source 身份/标记/移除纯核及 `lib/arena/adjudication-events.ts` wrapper、`useBattleStore.ts` 的对应纯调用；`useNarrativeHistoryStore.ts` 仅把纯行为换为共享调用，存储配置保持。修改 Modal 内纯 helper 删除由 UI owner 按接口完成，避免同文件并写。
3. **Desktop owner**：`apps/desktop/src/features/arena/**`、高级页面 adapter/路由/capability 与对应 Desktop tests；在共享候选审查通过后消费实际 exports。不得复制共享控件、修改 Native 预算或扩大 Hosted allowlist。
4. 合同/导航作为一个先行文档原子；共享布局/配置、历史纯核、历史视图及 Web 回用、Desktop 接线分别内聚提交。最终产品冻结后统一独审与完整 CI，文档依据实测结果收口，不在每次轻测后追加报告。

## 验收与回滚

- 双端真实控件测试覆盖辅助情景、Lore 选择/禁用/排序/移除、手动及角色/主辅情景继承判定（来源重复导入、切换和移除）、历史新建/编辑/排序/重排/多卡追加或覆盖导入。Web 原 store migration/hydration、原 quickCheck 和云保存 callback 不回归。
- Desktop 实际路由四模式×两输出：UI 输入到 B1 请求字段，结果/完成资格、活动历史、unsigned/history 显式另存、库重开。两页面草稿彼此隔离，切页/账号/目标/恢复不会隐式派发或搬移另一页状态。
- 精确覆盖 32/256/12 MiB/4 MiB 边界及含 Lore/历史的新组合；原文保真、未知字段、无效/未来草稿、磁盘失败、重复点击、迟到导入/生成/保存和取消/EOF/failed 均有回归。
- 未配置仍可编辑，守卫初始化失败不接收未保护输入；唯一 Native close guard 合并所有暂存与在途状态。纯本地编辑无隐式网络或附属图片请求。
- Windows/WebView2、真实 Tauri IPC/OS 凭据、真实模型质量、文件对话框/下载、视觉/缩放仍分项待验；不调用真实模型/Key、用户设备或生产服务作为本片自动验证。
- 回滚只撤回 `/arena` 宿主/路由与该页装配；不删用户数据、不改 `/battle` 旧草稿。共享 UI/纯核及 Web wrapper 按依赖整组回退，保原 Web 高级功能。
