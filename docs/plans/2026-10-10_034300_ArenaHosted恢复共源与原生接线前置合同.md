## 3. 当前 Hosted 来源与权威链

### 3.1 不是同一个 origin

`config/hosted-routing.json` 声明 primary 为 `https://homura.colanns.me`、stable 为 `https://api.mahoshojo.colanns.me`、DR 为 `https://mahoshojo.colanns.me`，preview 单列。Native `cloud.rs` 当前生产 origin 是最后一项，只开放六族固定生成路由；不能把三个名称当别名、换一个 URL 就称原权限未变。

正式 Hono `apps/api/src/main.ts` 调用 `arena-generation/runtime.ts`，真实注入 Redis replay store、D1/R2 terminal、签名、season authority 与 finalizer。Redis 未 ready、D1/签名/finalization 能力不满足时 fail closed。Next `apps/web/app/api/arena/generation-runtime.ts` 仍无条件使用 `createUnavailableGenerationReplayStore()`；共享代码存在不意味着 Next 可以创建 producer。

真实端口如下，C1 只能映射到受检 operation，renderer 不传任意 method/path/header/origin：

| 操作 | 现服务端端点 | 语义 |
| --- | --- | --- |
| 流式创建 | POST `/api/arena/generate-stream` | 首次固定 request ID、最多一次 create；返回 generation 头与有 ID 的 SSE |
| 非流式创建 | POST `/api/arena/generate` | companion 订阅同一 server-owned producer，收集后另构 report/updatedCombatants JSON；不是 Markdown 流冒充结构化 |
| 未知创建查找 | GET `/api/arena/generation-requests/{requestId}` | 同 actor 查稳定 ID；404/503 不是允许重发 create 的证据 |
| 状态/续流 | GET `/api/arena/generations/{id}`、`/{id}/stream` | owner 校验、cursor、保留窗口/terminal fallback；缺正文/到期如实显示 |
| 显式停止 | POST `/{id}/cancel`；未拿到 generation ID 时 DELETE `/api/arena/generate-stream` 携同 request ID | 固定 reason；202 是接受请求，finalizing 可返回409；未到达的 create 不能被一次404证明已撤销 |

`service.ts` 以 actor + request ID 派生 generation ID，语义 hash + Redis reservation 约束唯一 producer。随机 preparation seed、判定结果、Prompt、签名及 durable effects 属于服务器；Native 不能上传 Direct 本地 roll 冒充 Hosted 权威。未知初始结果只查找/续流，不能新 POST 或换模型、runtime、执行位置。

### 3.2 actor 与资金来源不是一回事

`hosted-runtime/arena-generation/actor.ts` 优先解析认证账号；有效 Bearer/activity token 对应 D1 用户与封禁检查，hybrid 模式支持 Better Auth cookie。显式无效 Bearer/activity 凭据拒绝，不能当匿名降级；cookie 验证不可用的现有回落也不能被 Desktop 解读为“仍是冻结账号”。C1 必须在实际服务端身份/会话失效时停止，不把 cached userId 当鉴权证明。

匿名来源在首个 POST 前固定 `bootstrap.<UUIDv4>`，服务器签发 90 天 actor token；后续 lookup/resume/cancel 要沿同 actor。它是恢复访问凭据，不放进可导出 Arena 草稿、日志或普通卡片。Web 原 localStorage/内存策略留在 Web wrapper；Desktop 如何由 Native 保存、绑定来源/账号世代并恢复尚待 C1 合同，不直接复制 Web key。

系统模型与预设 BYOK 继续由服务器目录解析。Native 已有受信 `presetConfig` → OS SecretStore 注入机制可供后继复用，用户自定义 Direct endpoint 不能改走 Hosted。Provider Key 只用于明确的创建请求，不出现在 GET lookup/resume、停止、hash、持久恢复指针或诊断。语义 payload 的去秘密投影不是可再次调用模型的凭据快照。

## 4. Native 当前不能承接的差距

1. `cloud.rs` / `contracts/desktop-cloud.ts` 只有六族 stream/JSON 路由，固定原 origin；当前 `g25e1-v1` 探测不证明 Hono Arena Redis/terminal/actor 能力可用。
2. `HostedSseEvent` 只透传事件名/data，解析器不保留 SSE ID；现 allowlist 无 Arena `snapshot`、`meta`、`meta_error` 等恢复语义。Arena 不应通过全局放宽旧解析器来吞并协议。
3. 当前 `cancel_hosted_ai` 仅取消本机 RequestRegistry/reader。Arena 断订阅不停止 server-owned producer，必须有独立的服务器停止结果，并区分接受、拒绝、未知和 terminal。
4. 当前通用流单帧512 KiB/缓冲1 MiB 与 Arena snapshot 不等价；Arena create12 MiB、文本+reasoning4 MiB、active replay snapshot 默认2 MiB、Redis active3600秒/terminal2700秒各自有含义。新窄协议须针对实际序列化扩张、快照与事件验证，不降业务上限、不把旧六族预算全局放大。
5. 生成时冻结目标/model/业务输入/actor/origin/request ID，账号或配置变化只影响下一意图。Native scope、renderer scope 和恢复记录须共同防止旧请求写新页面；退出账号不可用新凭据替旧 actor 补请求。
6. 跨进程恢复只保存无秘密指针，不重放创建。恢复能力失效、正文到期、finalization pending、生产者丢失均有明确状态；成功生成、服务端归档、已写本地库是三件事。

## 5. 完成结果、双输出和签名

非流式 `arena-companion/service.ts` 从同一 generation 收集结果，再构造 report、随机 presentation 字段及服务器更新角色；流式仍是 Markdown/Web 文本与独立元数据。不能把 stream 当非流式替身，也不能在 Native 本地重新投影后宣称获得服务器签名。

durable terminal fallback 主要给 snapshot + done/error，可携 telemetry/Web artifact，但不包含原 JSON 响应的全部 headerMeta 和 signed updatedCombatants。故“恢复正文/终态”不等于“恢复原完整 JSON”。C1 必须选择明确的缺失态或复用现权威读回/对账；不可再次调用 create 来取附加字段。

现 `update-combatants-after-stream` 仍是 Next 端 handler，不在 Hono 路由目录：它读取 owner/completed/finalized/frozen effects，局部稳定身份对应后才处理原生性。若 Desktop 后继需要此能力，应单列固定控制面操作及可信来源，不把它伪装成 Hono replay 自动具备。不在 C0 搬该 handler、增加修复AI或任意签名入口。

本地工作副本、完整历史卡与角色卡显式保存继续分开。新鲜服务器响应的签名证据可沿既有 `official-signed` provenance；可编辑草稿/导入恢复的签名字段只沿 `signature-unverified`，本地不验签。没有服务端更新时不能调用 Direct unsigned projector 后仍保留旧官方签名。没有合格 completed 或原 scope 已失效时，不应用历史/角色副作用。

## 6. C0 最小共源范围与 ownership

**C0 不修一个未经复现的取消 bug。** 当前 Web `resumable-generation-client.ts` 的 cancel 不传 routePin，`useBattleEngine` 将其交独立 generation intent；现 primary-only 分类直接返回 Hono，不 probe、也不改投 DR。现测试明确保护此行为。不能用非法 mock selector 制造“第二 probe 失败”RED；任何改变此政策均需另作有意行为修订。

| owner | 建议文件与可交付物 | 不纳入 |
| --- | --- | --- |

共享核只要求显式 transport、状态读写、hash/ID/时间/等待、actor头装配/回收等宿主端口；不得默认读取 window、document、localStorage/sessionStorage 或 import Web auth。可用 Web 标准 Response/ReadableStream 作中性载体；这些端口不要求共享核取得 Cookie/Key/actor token 明文。Web 头装配/actor token 回收仍在 Web adapter，Native 后继在私有 transport 内完成、只返回受检公开握手/事件；请求仍限定为操作枚举和受检ID/cursor，不能把共享 transport 接成通用fetch IPC。若最小抽取无法做到该接口可实现性，则缩减共享范围或退回审查，不新建平行执行器/通用网络框架。

旧 API 的状态文案、v1/v2/v3 恢复兼容、endpoint/body-scoped key、8次默认恢复预算、默认backoff、202“停止请求已受理”与 `cancel_unconfirmed`、EOF未终态、reader普通关闭不显式取消等按既有金样保持。caller 的账号冻结与 Native token方案不借此宣称已经解决。

## 7. C1 待确认的最小决策与后续顺序

需要维护者在正式 Native 接线前明确的第一项是：**是否将公开 official Hono primary 纳入 Desktop 专用受信项目目标，以及账号凭据与选定预设BYOK到该接收方的具体规则。** 不能从现有 Web 公开URL或现六族BYOK授权推导任意 origin 可收凭据。可选方案需比较复用既有 Native 账号会话与服务器现认证入口、或另定受限交换协议；现 activity token 默认90天，并非天然更窄的短期凭据，不擅自新增/持久化它。

其余是应先冻结的产品/工程范围：首纵切支持匿名/登录、系统/预设BYOK的具体矩阵；恢复仅当前进程还是跨重启及其无秘密指针/Native actor存储；非流式响应丢失后呈现缺失态还是接权威对账。建议复用既有目录/SecretStore与新鲜响应provenance，不另造第二套账号或签名系统。未支持组合显式不可用，不能降级为匿名、当前账号、Direct或其它Provider。

这些未定项不阻 C0。C1 获明确范围后才同步 accepted 安全规格、contracts/fixture、Native transport和前端session；默认/生产配置、真实凭据传输、用户设备任务及部署各自按授权执行，本合同本身不构成许可。

源码阶段使用合成actor与loopback服务验证create/lookup/resume/cancel和秘密不外泄，必要时复用既有本机Redis故障工具；真实Windows IPC/SecretStore、线上Hono配置/身份联调和真实模型成本验证仍单列，不因单测/本地CI关闭。D4内容运行和上述Hosted网络通路独立，C1即便可用也不开放Web内容执行。
