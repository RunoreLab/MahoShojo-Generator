# Phase 2.5B Hono Seam 结构退出审计 Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** 在保留 10 条已验证 shared capability、其余 14 条继续由 Next 同源执行的前提下，关闭 Hono legacy import 回退口、补齐 consumer/dispatcher/Web 退出 contract，并形成 Phase 2.5B 结构退出审计。

**Architecture:** `config/hono-api-routes.json` 同时记录 retained `sharedRouteIds`、空的兼容 tombstone `legacyRouteIds` 和只用于审计/回归的 `exitedRouteIds`。Hono generator 只允许 shared adapter，任何非空 legacy 清单都 fail closed；客户端只把 shared 清单路由到 Hono，Hono 对 exited 路由返回 404，而对应 Next route 文件及 POST surface 必须继续存在。G25B-3..5 的 shared-service 方案不再执行，因为当前 accepted 主计划与 G25C 启动裁决已选择 capability exit，Phase 2.5B 不以覆盖率为 KPI。

**Tech Stack:** TypeScript、Node ESM、Hono、Next Route Handler、Vitest、pnpm workspace、ESLint、esbuild。

**Source commit:** `3a2b3009`

**Implements:** `MONO-003`、`MONO-009`、`GOAL-040`、`GOAL-061`。

**Preserves:** `AI-006`、`AUTHORITY-001..006`、`DR-004..011`、`DR-013..014`、`COMPAT-001..002`、`ACCEPT-008`、Arena v1 authority/wire、签名和非幂等不盲目重放。

**Explicitly excludes:** `apps/api` 激活、root server relocation、AI/D1/Redis telemetry、Docker/CI/deploy ownership、Hosted DR 自动切流、Arena Room runtime、14 条 exited capability 的业务重构。

## 方案裁决

### 方案 A：继续执行旧 G25B-3..5，把 14 条全部迁入 shared service

拒绝。当前 accepted 主计划已记录 capability exit，且 Hono manifest 不以 API 覆盖率为目标；强行恢复这些高副作用 route 会扩大双 runtime 面和 replay 风险。

### 方案 B：保留现有 10/0 配置，只补退出日志

拒绝。当前 `tests/hono-api-client.test.ts` 已证明 consumer contract 未同步；generator 与 `RouteAdapter` 仍能生成 `legacy-next -> app/api` 回导，无法满足结构退出的机械门禁。

### 方案 C：显式 exited inventory + fail-closed generator + 三面 contract

采用。它保持 Next 行为和 10 条 retained shared service 不变，同时让新增 legacy route 必须重新完成运行时价值、shared seam、兼容、副作用/replay 证明，无法通过一次 manifest 编辑绕过。
