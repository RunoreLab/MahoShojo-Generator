## 3. 目录、身份和本地包

1. 可信**分发来源**是 `packages/web-package/preset-catalog.json` 和 `presets/`，由 `scripts/generate-web-package-presets.mjs` 生成索引/字节。`builtinWebPackageSource.resolve` 精确匹配 id/version/digest、离线加载且验证；“随应用分发”不是安全认证，也不提升权限。
2. 通用 `resolveWebPackage` 允许经验证的本地暂存同身份包优先，以支持下载再导入。不得因 UI 自报 builtin/source kind 跳过验证；精确 ref 只是内容身份，不是宿主目录路径。包无任意宿主目录读取 API。
3. 用户 ZIP 复用 `importWebPackageArchive` 的标准/兼容导入、摘要验证、未知资源 opaque bytes 和诊断。不能只支持内置新闻模板，也不能丢弃未知资源后声称原包保真。Archive 解压预算、路径/重复项/摘要拒绝规则不另写。
4. 选择、替换、移除选择与删除本地记录分开。库记录复用 digest 派生 ID 与 tombstone。现 Web 单包显式重新导入会按同 digest `put`，遇已删除记录先显式 `restore`；整库导入才用 `putIfAbsent` 的 existing-wins，不能混为一种语义。Desktop 对已删包提示并确认恢复导入后才走 `restore`，不由晚响应或普通 `put` 隐式复活；重试沿固定记录身份且不重复。删除包不删除战报正文，历史缺包明确显示；不新增 purge。
5. 复用“导入后保存到本地库”受控 UI，默认关闭。Web 的 `saveImportedWebPackages` 与原 key 保持；Desktop 当前没有这个偏好，首片用默认 false 的当前页导入选择，不新增长期记忆 key，也不读取 Web IndexedDB。只有用户明确勾选的导入才写库；会话暂存和持久保存分别反馈。存储失败保当前包与原件导出，不能显示已保存。
6. 输入 ZIP、重建标准 base ZIP、generated target、完整结果 JSON 是不同出口，明确文件含义。重建 ZIP 不是原始压缩字节保真；需要原件时读取已有 archive bytes。Base ZIP 不混入 overlay，不改原 package digest。HTML/JS 下载是显式文件导出，提示在外部打开不受应用隔离保护，不自动启动浏览器执行。
7. 选文件由 main UI 的受控 File 输入完成；ZIP 导出可在既有 `downloadTextFile` 的 main UI Blob 下载机制增加有限二进制适配。现整库 archive 导出具有专用验证，不能冒用其会话作为任意文件写盘器；不新增任意路径 IPC、包窗下载或 fs 权限。

### 独立预算不能混淆

- Arena 原始业务输入仍 12 MiB，模型 decoded content + reasoning 合计仍 4 MiB；32 角色 / 256 引用及四模式最小数量不变
- Prompt Projection 自有预算和总提示预算保持；仅投影进入模型，ZIP、原包全部资源不整体上传。`example` 仍显式声明、128 KiB，不能自动用 base target 补成范例
- 本地 package archive 存储上限是 **64 MiB ZIP 字节**；record 文档封套仍 4 MiB。当前写 archive 用结构化 base64 `{b64,len}`，读 archive 为 raw 响应，不误称两向都 raw
- ZIP 展开 256 MiB 与 D4b 单实例 256 MiB 有效载荷是两种独立预算；D4b 4096 文件、8 live / 512 MiB 总有效载荷、每次 raw append 4 MiB 沿原合同，不是 RSS 上限保证
- Arena draft 4 MiB 字符、CardRepository 完整文档 4 MiB 字节不变。生成或导入成功不等于存储成功，超限不裁截、不静默丢资源、不全局放宽；保内存与完整导出

## 4. AI 输入、输出资格与副作用

### 冻结输入和唯一调用

在第一次 await 前取得同步锁并冻结业务输入、output contract、generationMode、Direct target/model、ref 和对应经验证 base。异步解析/投影阶段亦受 scope/epoch 围栏；解析完成不能重新读取新选择后拼入旧任务。完整冻结投影随输入资源证据，包字节留在 host。账号/配置/选择变化、取消或离页均不能让晚响应发布到新 scope。

四模式 × stream/non-stream × 自由 Web/包目标采用同一个 Direct 适配器。Web 非流式是一次完成的原目标文本，不套结构化战报 JSON schema；Web 流式与非流式语义一致。必须消费 `assembleArenaGenerationPrompt` 返回的 package `systemPrompt` 与 task prompt，不合并丢掉 host > creator-material 分层；不把未信任包说明提升为服务端/判定权威。

### 完成、可重放、运行是不同状态

1. 完成仍要求同一请求的显式 completed / stop、终态正文一致及原 scope 有效；EOF、length、cancel、failed 均仅保部分原文，不追加历史/应用角色效果、不创建成功 overlay。
2. 复用现 stream-meta split/parse/repair，reasoning、usage、raw meta 不进入目标文件。包目标用现 strict-trailer 语义：有效 v1、非空 headline/winner、剥控制尾、目标 normalization/validation、冻结 ref/target 与 generatedDigest 一致后才形成 artifact。模型不许自行换目标/包身份。不发第二次 Provider 调用修补输出。
3. 自由 Web 的 prompt 要求 meta；当前 Hosted 实现与包目标不同，没有统一把“缺 meta”判为整场失败。抽取应保持这个现状：framing 仅提取完整 HTML document 和独立前后附言，不是 sanitizer；无完整文档保安全文本、运行不可用，不从 DOM/脚本猜 winner 或 impacts。任何拟加强的共同完成政策需独立说明，不能借迁移悄改 Web。
4. 包目标媒体类型复用既有纯核：JSON 保守剥包装后验证 schema，digest 对应归一化字节；HTML/JS/CSS 等现验证不构成无害性保证。解析/摘要/目标失败、缺包、渲染不支持、D4 gate 未过是不同状态，不能统称生成失败或自动换格式/换包。
5. 流式只展示 escaped source/text，不创建 partial overlay、不注入 HTML、不解析执行 Markdown 内资源、不执行增量 JS。完整结果在主 UI 仍是安全源码与共享 report chrome；进入独立窗是另一个显式动作。
6. 战后角色效果继续共享 unsigned 候选核，时间/generationId 固定、源库卡不变；只使用合法机器元数据，不能把 UI 的“Web 战报”标题或空 winner 补成游戏裁决。活动叙事历史沿原默认关闭/完成时追加/用户显式保存，不因 Web 格式新建自动库写入。

### 结果、叙事历史与恢复

复用 `WebPackageArtifact` 和现 `BattleReportRenderSnapshotV1` 的格式/ref/provenance 字段，放入严格验证的 Arena **结果草稿及完整导出**，保 raw transport text、剥离后 target、normalization 结果和元数据隔离。两产品原 draft owner/key 不合并；合法旧 Markdown 草稿兼容，坏/未来版保原件，不恢复旧请求 authority、自动调用或自动运行。

NarrativeHistory 卡现只承载原 entry 正文和扩展，并非战报运行仓库。它继续按现规则另存完整叙事内容；不得为可执行历史新造 DB 或假造第二套历史字段。恢复安全结果时使用保存的精确 artifact；单纯导入含 HTML 的历史条目不自动成为可运行结果。若未来要求从普通 history 卡重建完整可执行战报，需另定版本化映射，不能靠标题/DOM推断或偷塞并声称现已支持。

重放复用 `prepareWebPackageReplay`：先加载 exact revision；missing/mismatch/rejected 保安全文本、target/原包出口。多候选让用户选择具体版本与 digest，显式确认才兼容；只变 working instance，不改历史 artifact/provenance。再次验证 generatedDigest，不能自动 latest、自动下载未知包或默默跳过完整性。

## 6. 隔离、危险 URL、确认和最小源码缺口

现 D4b 创建独立 incognito `webpkg-*` 窗口，capability 只赋给 main UI；HTML 响应 `sandbox allow-scripts`，no-referrer/nosniff。顶层导航只允许本实例声明的 text/html；main/app/foreign-instance、about/data/javascript、SVG/XML 顶层导航、新窗、浏览器权限和包窗下载拒绝。资源按实际 webview label + native instance 钉定，失败统一 404。包路径不能升级为宿主绝对路径。

**以上不等于浏览器零网络。** 当前 CSP 没有 connect-src 等目的地限制；on_navigation 不覆盖 fetch、图片、脚本或 WebSocket。既定 WebPackage 规格允许 HTTPS 外部资源；Desktop 尚无完整包浏览器 scheme/local-network/DNS 策略。Provider HTTP 例外确认和项目 API 固定 origin 是不同通路，不能直接套用或用其“已确认”授权包网络。静态 scan 是风险提示，manifest 声明不是能力授予，也不证明无外联。

本合同仅识别以下可窄化源码接缝，不自行增加网络白名单、任意端点或权限：

- 格式选择允许生成并不表示允许执行。首片运行 port 不可用时不发 begin/open；提示与按钮状态不能被 remember-consent 或诊断开关越过。Web 原 consent 不迁作 Desktop 执行授权
- 未来开放执行时共享普通风险说明，明确 HTML/CSS/JS、外部资源/数据发送、卡顿、临时交互状态；Desktop 不提供 Trusted Same-Origin 授权。运行按每次明确确认的最小提案，不默认长期记忆、不新增“永久信任”偏好；不能默默认定 builtin 安全
- 主 UI 的说明/报告外链仍走既有 `openContent` 验证与确认。包内链接不授予 Host Bridge；既有新窗/外部顶层导航继续拒绝，不能把页面 link 自动转发到 `open_external_url`
- 桥可加现 owner signal/current predicate：begin 前、每次 await 后及下一个 append/open 前核 scope，过期不再派发下一步、不自动重试。未 open 的 collecting 由既定 300 秒 TTL 回收。open 一旦已派发只能忽略旧 UI 回执，不能承诺窗口创建已撤销，不为此新增第四条 abort IPC
- 包实例继续使用 `createWebPackageResourceSnapshot`。自由 HTML 仅将已 framing 完成文档作为单 text/html 内存资源；桥可接受它实际消费的最小 entry/files 结构，不能伪造 packageRef、注册 builtin 或把任意URL传给 Native。wire 仍由 Native 分配 instance/label/URL
- 导入/验证/安全文本/保存导出不会执行包脚本，不能隐式加载缩略图 URL 或触发 base/target 网络。已有 scanner 原样展示风险与不完整状态，失败不自称安全

## 7. 验收与开放门禁

### A. 源码可验证，不依赖实机

1. 真实 `/battle` 与 `/arena` 共源视图：四模式 × 两传输 × 自由文档/包目标；预设、本地库、ZIP 导入、选择/清除、缺配置编辑、Direct preset/custom、生成→安全结果→导出/保存→重开。Hosted 仍显式不可用，无 fallback
2. Web/Hosted 旧 consumer 真回用；free framing、meta 切块/截断/重复/最新块、JSON 包装/schema、HTML/JS/CSS target、未知资源及相对资源的旧新金样；不把局部函数通过等同运行时隔离
3. 未完成/取消/EOF/length/错 ref/坏 digest/非法 target/超限及迟到解析无成功 artifact 或战后副作用；只一次 Provider 调用；同 scope 冻结 reporter/判定随机，改配置/包选择不改当前任务
4. 完整源/规范 target/原包 ZIP 三者可区分；ZIP 原件与重建包按字节/manifest 摘要分别验证；64 MiB 库存档、4 MiB 输出与封套边界、磁盘失败/tombstone/重试不重复；大小拒绝保内存和出口
5. exact/reimport/缺包/候选冲突/显式兼容与历史 provenance；旧草稿恢复和坏草稿保护；HTML 历史条目不进入执行面
6. 主 UI 无 executable iframe/HTML 注入，无 Web renderer runtime 导入；D4 gate 关闭时 zero begin/append/open，完整生成/导出照常工作；外链绕过路径/隐式资源请求为零
7. 源码桥模拟验证分块offset/回执、过期不继续派发、open已发的未知结果、重复点击同步锁；保存/导入/临时编辑纳唯一 close guard。Native 协议 fixture、ACL/命令清单/主 CSP 结构门禁不回退
8. 冻结后独立审查及完整 `ci:verify`；重型验证统一排队。测试标明纯核、DOM、模拟 IPC、合成 loopback，不将其宣称为真实 Tauri/模型效果

### B. Windows / WebView2 对应 D4 实机门禁

- 实际 webpkg 窗无法调用所有 app/core commands，不能窃听/接收 main Channel 或借原生对象逃逸
- app/main/foreign-instance/非法路径统一拒绝，SVG/XML/data/about/javascript/URL 编码导航与新窗、权限、下载探针验证
- 普通资源、模块/图片/CSS、目标新增路径及 Range 206/416 连续读取；raw IPC 完整文件回执；重复 open 聚焦不死锁
- Destroyed 释放；无后续 IPC 时 300 秒 collecting 回收；8 live/512 MiB 上限和内存观察，不把有效载荷预算称为 RSS 硬限
- 明确观测子资源/fetch/WebSocket/HTTP/HTTPS、loopback/private-network 与凭据/存储可达性。测试只用合成内容和受控本地探针，不向真实用户端点或第三方发包；若要对外探针或用户设备须另有执行授权
- 主 UI 文件选择、ZIP/target 下载取消和错误、SQLite 重开、真实关闭守卫、窗口生命周期、深浅色与视觉验收

只有相应证据收口才改变产品运行能力；Windows 待验不阻塞 A 的实现，不把 A 通过宣传为 B 通过。

## 8. 仍需决定的事项与施工顺序

已冻结、无需重新询问用户：共享核/UI、精确内容身份、已有预算、本地库优先、零 Native capability、独立窗口、默认受限、不迁移 Trusted Same-Origin、不在主 UI 执行；首片安全文本与导出可先交付。运行 consent 按每次明确确认、不默认长期记忆的最小提案，不自动开放新网络或原生能力；任何系统安全配置变动须单独批准，本合同设计范围不包含该类执行授权。

真正影响后续执行开放的待定项：

1. **运行网络策略**：如期望进一步限制 HTTP、loopback/private-network、WebSocket 或远端脚本，需明确目的地/协议边界并评估真实 WebView2 可实现性；现规格没有足够事实替用户选择完整策略。先保留执行门禁，不能自行声称“已全封网络”或新造宽泛权限
2. **超出逐次确认的授权记忆**：Web 的普通浏览器 consent 与其 Trusted Same-Origin 授权分别有既定语义；Desktop 本片不复制旧 key 或自动信任。只有未来另要求永久/会话复用时才需要决定记忆范围、撤回与 owner，不因此阻塞当前默认不记忆的源码工作
3. **实机授权与证据**：用户提供 Windows 实机执行条件或回传证据后才能关闭对应 D4 门禁。这是运行能力开放所需证据，不是源码研究停止理由

建议顺序：审定本合同 → 纯核与受控 view 并行 → Desktop 包库/结果草稿/Direct 接线 → 源码负向旅程与独审 → 一次冻结完整 CI → 记录 b2-B1 交付及 D4 PENDING → 独立执行政策/Windows 探针 → b2-B2 开放。每次以实际可用能力登记，不将尚未完成的 Hosted/连续故事/Strict 顺带开放。

本次验证范围：仓库源码、accepted 文档与当前测试入口的只读核对；文档链接与 diff 校验。没有执行包、模型、真实 Native 窗口或新的完整 CI。
