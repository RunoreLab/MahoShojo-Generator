# 消息系统 Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** 落地首版站内消息系统，提供全站通知与定向通知的数据层、读取 API、顶部栏未读入口和独立 `/messages` 消息中心页面。

**Architecture:** 使用 `site_messages`、`user_messages`、`user_message_state` 三张 D1 表分离全站通知、定向通知和用户全站通知游标。服务层负责模板渲染、统一排序、分页 cursor 和已读状态映射；API 层只暴露摘要、列表、标记已读和全部已读能力；前端通过 TopBar 低频读取摘要，通过 `/messages` 展示响应式消息中心。

**Tech Stack:** Next.js Pages Router、React 19、Cloudflare Edge Runtime、Cloudflare D1、Drizzle ORM、Tailwind 4、Bun test、`react-dom/server` 静态渲染测试。

CREATE TABLE IF NOT EXISTS site_messages (
  id INTEGER PRIMARY KEY AUTOINCREMENT,
  message_type TEXT NOT NULL,
  template_key TEXT NOT NULL,
  payload_json TEXT NOT NULL DEFAULT '{}',
  title_text TEXT,
  body_text TEXT,
  action_url TEXT,
  priority TEXT NOT NULL DEFAULT 'normal',
  expires_at TEXT,
  created_by_user_id INTEGER,
  created_at TEXT NOT NULL DEFAULT CURRENT_TIMESTAMP,
  updated_at TEXT NOT NULL DEFAULT CURRENT_TIMESTAMP,
  FOREIGN KEY (created_by_user_id) REFERENCES users(id) ON DELETE SET NULL
);

CREATE INDEX IF NOT EXISTS idx_site_messages_active_id
  ON site_messages(id, expires_at);

CREATE INDEX IF NOT EXISTS idx_site_messages_created_at
  ON site_messages(created_at);

CREATE TABLE IF NOT EXISTS user_messages (
  id INTEGER PRIMARY KEY AUTOINCREMENT,
  recipient_user_id INTEGER NOT NULL,
  actor_user_id INTEGER,
  channel TEXT NOT NULL DEFAULT 'system',
  message_type TEXT NOT NULL,
  template_key TEXT NOT NULL,
  payload_json TEXT NOT NULL DEFAULT '{}',
  title_text TEXT,
  body_text TEXT,
  action_url TEXT,
  source_entity_type TEXT,
  source_entity_id TEXT,
  priority TEXT NOT NULL DEFAULT 'normal',
  read_at TEXT,
  archived_at TEXT,
  expires_at TEXT,
  created_at TEXT NOT NULL DEFAULT CURRENT_TIMESTAMP,
  updated_at TEXT NOT NULL DEFAULT CURRENT_TIMESTAMP,
  FOREIGN KEY (recipient_user_id) REFERENCES users(id) ON DELETE CASCADE,
  FOREIGN KEY (actor_user_id) REFERENCES users(id) ON DELETE SET NULL
);

CREATE INDEX IF NOT EXISTS idx_user_messages_recipient_inbox
  ON user_messages(recipient_user_id, archived_at, read_at, id DESC);

CREATE INDEX IF NOT EXISTS idx_user_messages_recipient_created_at
  ON user_messages(recipient_user_id, created_at DESC);

CREATE INDEX IF NOT EXISTS idx_user_messages_recipient_source
  ON user_messages(recipient_user_id, source_entity_type, source_entity_id);

CREATE INDEX IF NOT EXISTS idx_user_messages_expires_at
  ON user_messages(expires_at);

CREATE TABLE IF NOT EXISTS user_message_state (

  last_summary_read_at TEXT,
  created_at TEXT NOT NULL DEFAULT CURRENT_TIMESTAMP,

Use Drizzle query builders and indexed filters. Avoid offset.

Repository requirements:

- `listSiteMessages` must filter out expired rows using `expires_at IS NULL OR expires_at > now`.
- `listUserMessages` must normalize snake_case DB rows to canonical camelCase return shapes.
- `listUserMessages`, `countUnreadUserMessages`, and `markAllUnreadUserMessagesRead` must consistently use inbox口径：仅处理 `archived_at IS NULL` 且 `(expires_at IS NULL OR expires_at > now)` 的消息。
- `listMessages` service with `filter='unread'` must exclude read `user` messages and site messages whose `id <= last_read_site_message_id`; it must not merely return all rows with an `isRead` flag.
- `advanceSiteMessageCursor` must implement monotonic update semantics: if the requested ID is lower than the stored cursor, preserve the existing value and return it.
- Canonical cursor SQL boundary must be explicit per source. For source rank `R` and cursor `{ createdAt, scope, numericId }`, a row belongs to the next page only if:

```text
row.created_at < cursor.createdAt
OR (
  row.created_at = cursor.createdAt
  AND (
    R < cursorScopeRank
    OR (R = cursorScopeRank AND row.id < cursor.numericId)
  )
)
```
