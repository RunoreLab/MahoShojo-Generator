# 平台机制简化实施计划

状态：`active`
日期：2026-09-01
计划标识：`PLAN-platform-simplification-20260901`
基线：平台重整前参考 `e2cdb423418c02f189b730eb58235811cbbb8eeb`
当前审查参考：`c9aea49b23d392224133dbb32532f8628d9755f7`

配套决策：[`2026-09-01_193200_平台复杂度预算与故障降级决策.md`](../decisions/2026-09-01_193200_平台复杂度预算与故障降级决策.md)

## 1. 目标

本计划不是回滚 Hono、Monorepo、Redis、多人或可恢复生成。

目标是删除自平台重整后逐步长出的**证明型、重复型、非必要强一致性机制**，让平台恢复为：

```text
业务代码
+ 少量真实安全边界
+ 普通行为测试
+ 简单 CI
+ 简单可回滚发布
```

而不是：

```text
业务代码
+ 机器事实清单
+ evidence registry
+ source digest
+ gate schema
+ gate checker
+ checker test
+ release tuple proof
+ historical compatibility proof
```

## 2. 非目标

本轮不应：

- 把 Hono 搬回 Next；
- 把 `apps/web` / `apps/api` 重合并为根应用；
- 删除所有测试；
- 降低账号 / Admin / secret / 严格排位的真实安全边界；
- 允许重复 AI Provider dispatch；
- 删除多人 ticket / membership 授权；
- 删除 WebSocket payload / queue 上限；
- 为追求“代码少”而破坏现有用户功能。

## 3. P0：立即解除正在制造故障的机制

### P0-1 战后角色更新：移除完整 base revision 强一致性

目标文件族（以实际调用关系为准）：

- `packages/domain/src/arena-reconciliation.ts`
- `apps/web/app/api/arena/update-combatants-after-stream/handler.ts`
- `apps/web/lib/arena/reconciliation-retry.ts`
- `apps/web/components/arena/hooks/useStreamCombatantUpdater.ts`
- `apps/web/components/arena/hooks/useBattleStorySession.ts`
- `packages/hosted-runtime/src/arena-generation/d1-finalization.ts`
- 相关 tests

目标行为：

1. `generationId` 定位服务器已确认的 terminal report / impacts；
2. 客户端提交当前角色；
3. 使用稳定 roster identity 对应角色，而不是完整对象 SHA；
4. 对需要原生性的 effect 单独重新判定；
5. 单角色冲突局部失败；
6. 成功角色正常更新；
7. 返回 `{ updatedCombatants, warnings/errors }`；
8. 不再出现仅因 `baseRevisionHash` 不等而整场 `409`。

若 `baseRevisionHash` 不再有其他真实用途，完全删除其 API 字段和 domain helper。

验收：

- generation 后用户本地角色发生无害字段变化仍可更新；
- bundled preset authority 变化不再让普通战后成长失败；
- 非原生卡不能通过伪造 `isNative=true` 获得原生专属效果；
- 全部角色身份都无法匹配时才允许整体失败；
- 不引入第三套 / 第四套 legacy revision compatibility。

### P0-2 原生 authority：从 provenance proof 回到 causal verification

保留客户端不可信原则。

简化策略优先级：

1. 服务器已知内建 preset ID / server-owned reference；
2. 当前合法签名；
3. 否则非原生。

如果 canonical preset digest registry 只服务于“证明 bundled preset 原样未变”，且删除后不会造成权限提升，可删除 generated digest authority。

禁止：

- 为普通战报/成长要求证明 generation 起点与当前卡的完整 provenance 连续性；
- 因 native 无法确认而阻塞与 native 无关的低风险操作。

### P0-3 删除 `user-visible-contracts` 的源码冻结职责

优先删除：

- `exitedRoutes[].files[].sha256`
- baseline commit 固定
- `requiredEvidenceTests`
- `auditCoverage.automatedEvidence`
- 由固定文件 hash 驱动的 CI 失败
- “必须补 runtime differential evidence 才能修改 handler”的结构性要求

保留方式：

- 真正有价值的 API / UI 行为测试直接留在普通 tests；
- infrastructure error copy 可以留成普通代码常量或轻量配置，不需要一个覆盖全平台的 audit manifest；
- route inventory 如仍由运行时注册需要，可独立保留，不要和历史审计绑定。

目标删除 / 重写：

- `config/user-visible-contracts.json`
- `scripts/check-user-visible-contracts.mjs`
- 对 checker 结构本身进行断言的 tests

允许拆出一个极小的 `public-error-codes.ts/json`，但只有当前运行时真正消费的字段。

### P0-4 删除 GMR-11 source digest / reviewed source proof

删除 production activation 中的：

- `reviewedCommit`
- `reviewedSourceDigest`
- `--print-source-digest`
- 全仓 `git ls-tree` SHA-256
- reviewed/current evidence 内容等价验证
- Markdown front matter marker 作为 production gate

多人启用由：

- feature flag
- GitHub Environment / manual approval（如维护者希望）
- 正常 CI
- 最小线上 smoke

共同决定。

### P0-5 合并 GMR-10Q / GMR-11 / Room release 三层发布门禁

目标状态：

```text
CI tests/build
  -> optional preview
  -> multiplayer smoke
  -> deploy
```

而不是：

```text
product parity gate
  -> independent review evidence
  -> production activation gate
  -> release gate
  -> release gate schema
  -> deploy
```

迁移完成后可删除/归档：

- `config/arena-product-parity-gate.json`
- `config/arena-production-activation-gate.json`
- `config/arena-room-release-gate.json`
- 对应 checker / schema / prepare script / checker tests

若 feature flag 仍需要发布时明确控制，直接使用环境变量。

### P0-6 根 CI 收缩

目标 `ci:verify` 最终建议接近：

```text
typecheck / workspace build
lint
unit tests
少量 integration tests
```

可以保留极少高价值专门检查，例如：

- client package 不得 import secret/server-only module；
- deploy bundle 能构建；
- auth / authorization 基本回归；
- WebSocket message / backlog 上限；
- Provider duplicate-dispatch 防护。

应退出 merge gate：

- source digest
- evidence manifest schema
- migration inventory
- hardening evidence
- GMR project-state slice
- docs marker
- 纯 naming 规则（除非实际语言工具无法覆盖）
- verifier-of-verifier

## 4. P1：缩减平台证明与容灾体系

### P1-1 Hosted DR capability manifest 退场或大幅瘦身

当前 per-route 描述的：

- requestClass
- drMode
- replayPolicy
- required secrets
- binding
- contractStatus
- drillStatus
- contract test owner

不应全部由机器 manifest 长期维护。

替代方案：

```ts
type OperationSafety =
  | 'safe-read'
  | 'new-non-idempotent'
  | 'durably-idempotent';
```

核心执行状态记录：

```ts
providerDispatchState:
  | 'not-dispatched'
  | 'dispatched'
  | 'terminal'
```

由实际代码根据这两个维度决策 fallback/retry 即可。

如果 `hosted-dr-capabilities.json` 仍有 Web 构建配置用途，拆出仅包含当前 origin / feature config 的小文件，不继续承载审计状态。

### P1-2 generation success 与 archival durability 解耦

调整 terminal lifecycle：

- AI 输出完成并完成最低限度解析 -> generation success；
- Redis/D1/R2 依次作为恢复/归档增强；
- 持久化失败记录 `persistenceWarning` / `replayUnavailable`；
- 已经下发给用户的正文不因 R2/D1 故障消失。

对服务器还没向客户端交付任何 terminal 内容的情况，可以按产品需要决定是否等待一个短的最低持久化步骤；不得无限把全部存储层绑成原子事务。

### P1-3 hardening evidence 退场，保留真实 fault tests

删除：

- `config/arena-room-hardening-evidence.json`
- 精确 command / owner / assertion 文案 schema
- “十个场景必须恰好按固定顺序登记”的 gate

保留并按测试价值重新分类：

- slow consumer bounded queue；
- oversize/malformed frame；
- membership/ticket auth；
- Redis unavailable 不破坏已提交状态；
- process loss 不重复 Provider；
- reconnect 基本路径。

低价值/高维护的故障演练可转为手工 release checklist 或非阻断 nightly。

### P1-4 Admin migration inventory 归档

`config/admin-migration-inventory.json` 属于一次迁移工作的项目管理证据，不应永久成为仓库事实来源。

迁移完成后：

- 可将总结保留到 `docs/logs/`；
- 删除 440 KB 级机器 inventory；
- 删除 generator / inventory CI；
- Admin 当前行为由自身测试保护。

### P1-5 部署流程恢复为普通发布工程

Hono / Web 推荐流程：

```text
checkout
install
test/build
build artifact
(optional) artifact digest
deploy
health
smoke
```

保留：

- SSH known_hosts 固定；
- environment secrets；
- release directory / 上一版本 rollback；
- health ready；
- production concurrency；
- artifact digest（可选但合理）。

删除：

- 业务 GMR gate 随 artifact 一起打包；
- release gate schema；
- 为证明 release tuple 合法而存在的多层 installer contract；
- 与实际部署安全无直接关系的本地 fault drill。

## 5. P2：代码结构减负

### P2-1 拆解大型状态机

重点审查：

- `packages/hosted-runtime/src/arena-generation/d1-finalization.ts`
- generation lifecycle
- Room actor / recovery
- Hosted DR
- Arena companion repair/update

原则：

- 一个业务状态只保留一个 canonical representation；
- 不为历史 proof 继续增加 compatibility state；
- 不再通过“状态枚举 + evidence 状态 + release 状态”三套平行模型描述同一事实。

### P2-2 错误机制改为“详细但安全”

建立一个轻量 sanitizer，例如：

```ts
sanitizePublicError(error): {
  code,
  message,
  upstreamMessage?,
  retryable?,
  phase?,
  requestId?
}
```

清洗重点：

- API key
- Authorization/Bearer
- Cookie/session
- signed URL/query token
- connection string
- private key
- filesystem absolute path
- stack trace
- SQL/internal DB details
- 其他用户数据

Provider 文案如果清洗后安全，应直接保留，而不是二次吞掉。

### P2-3 自定义 workspace checker 逐个做价值证明

每个 checker 必须回答：

- TypeScript / ESLint / package exports 为什么不够？
- 它过去是否真实阻止过用户级事故？
- 它是否曾制造 false positive 或额外修复工作？

无法证明高价值者：

- 从 CI 移除；
- 先降为 report-only；
- 稳定一段时间后删除。

## 6. 多人模式发布

### 6.1 本轮不再等待证明型 GMR gate

多人可在 P0 门禁简化完成前后独立发布；不必等整个 P0/P1/P2 全部结束。

发布前只确认真实 blocker：

1. production Redis 正常；
2. Hono health ready；
3. Room HTTP endpoint 可以正确拒绝未认证请求；
4. WebSocket upgrade/ticket 语义正常；
5. 创建 Room；
6. 第二用户加入；
7. host 提交 / 接受 Proposal；
8. 发起一次真实或受控生成；
9. 成员收到结果；
10. 普通成员无法执行 host-only operation；
11. feature flag 可关闭；
12. 上一版可回滚。

### 6.2 当前仓库事实

在本计划撰写时：

- 默认分支为 `feature/v0.2.0_Battle_Growth_MahoShojo`；
- 当前参考 HEAD 为 `c9aea49b23d392224133dbb32532f8628d9755f7`；
- 该 HEAD 的最近 `Deploy Hono` workflow 已成功完成；
- 但当前仍有 Arena 战后角色更新 `baseRevisionHash` 409 回归，因此该问题应作为普通 Arena P0 bug 处理，而不是继续扩大 GMR 门禁。

“多人是否能发布”不应由角色战后更新这一单人/共享 Arena companion bug 自动否决；如果多人主流程本身不依赖该失败路径，可以先发布多人，并并行修复角色更新。

## 7. 每个阶段的退出标准

### P0 DONE

- 不再存在完整角色 baseRevision 作为战后更新许可；
- native/provenance 失败对低风险路径降级；
- `user-visible-contracts` 不再冻结业务源码 hash；
- production activation 不再计算 source digest；
- GMR proof 不再是多人 release blocker；
- 根 CI 不再运行明显的 proof-of-proof gate；
- 用户主流程测试通过。

### P1 DONE

- Hosted DR 核心重试/切换语义能用少数代码规则解释；
- AI 成功不再被附加归档失败推翻；
- hardening evidence machine registry 删除；
- Admin migration inventory 退出 CI；
- deploy workflow 明显缩短，且保留 rollback/health。

### P2 DONE

- 关键大型状态机职责清晰；
- 错误响应详细且安全；
- 自定义 checker 数量明显下降；
- 不存在为了历史 proof 而新增的 compatibility 分支；
- 新开发者可以在不先阅读多份 GMR/evidence 文档的情况下理解和修改主流程。

## 8. 实施方式建议

建议使用一系列可回滚的原子提交，而不是一次“大爆炸”删除：

1. `docs(platform): accept complexity budget`
2. `fix(arena): simplify post-generation combatant reconciliation`
3. `refactor(arena): reduce native authority to causal verification`
4. `chore(ci): remove source hash and user-visible proof gates`
5. `chore(multiplayer): replace GMR release proof with runtime smoke`
6. `refactor(hosted): simplify DR operation policy`
7. `refactor(generation): decouple result success from archival durability`
8. `chore(ci): retire hardening/admin migration evidence`
9. `refactor(deploy): simplify Hono/Web release workflow`
10. `refactor(errors): expose sanitized actionable diagnostics`

每一提交只需证明其行为目标，不应为“证明简化是安全的”再创建永久 gate。
