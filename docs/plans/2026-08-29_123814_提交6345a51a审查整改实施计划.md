### Task 1：关闭带 path 的 URL metadata 扫描绕过

- [x] **Step 1：增加失败 mutation**

在 `tests/hosted-dr-client-bundle.test.ts` 的 URL metadata 表中至少加入：

```ts
['path + query', 'https://example.com/path?token=bundle-secret', 'bundle-secret'],
['nested path + fragment', 'https://example.com/a/b#bundle-secret', 'bundle-secret'],
['path + port + encoded query', 'https://example.com:8443/a;b?token=bundle%2Dsecret', 'bundle%2Dsecret'],
['comma path + encoded fragment', 'https://example.com/a,b#bundle%2Dsecret', 'bundle%2Dsecret'],
```

同时把 routing fixture 表达为真实 JavaScript 字符串，避免用裸分号人为截断 URL candidate。

实际还补充了 IPv6、protocol-relative、公开 URL 正向与额外 query key 负向 mutation，确保 parser 既读取完整 candidate，
又不把产品现有公开出站链接误判为秘密。

- [x] **Step 2：运行 RED 测试**

Run: `pnpm exec vitest run --config vitest.config.ts tests/hosted-dr-client-bundle.test.ts`

Expected: 新增的 path + query/fragment cases 因 checker 返回 `0` 而失败，原有 case 继续通过。

- [x] **Step 3：最小修复 candidate 提取**

在 `apps/web/scripts/check-hosted-dr-client-bundle.mjs` 中先以大小写无关的 scheme locator 找到候选起点，再以 anchored
candidate pattern 读取完整 authority/path/query/fragment；同时识别完整 JavaScript string literal 中的 protocol-relative URL。
候选解析统一使用 WHATWG `URL`；精确更新 `http://localhost/` location fallback fixture。credential、未知 query/fragment、
非法 URL 与 internal endpoint 错误只报告类别和文件，不回显 candidate。

真实 production bundle 含有 referral、QQ 群邀请、Google Tag、Next 文档锚点等既有公开 URL metadata。实现只对
`HTTPS 默认端口 + exact hostname + exact pathname + exact query key set + exact fragment` 建立窄规则；值不进入 allowlist，
credential、HTTP、protocol-relative、非默认端口、额外/重复 query key 和未登记形态继续 fail closed。该边界比原计划的
blanket metadata rejection 更符合 accepted spec 的“不得泄漏 secret/internal endpoint”要求，同时保留既有产品链接。
