## 1. 结论与插入位置

当前远端状态为：

```text
G25C COMPLETE
-> G25D apps/web + root ownership（尚未开始）
-> G25E-1 Hosted DR contract
-> G25E-2 Hosted DR fault drills
```

生产反馈已证明 Arena 长生成存在真实的客户端网络中断问题；同时 G25D 被既有计划明确限定为 **behavior-equivalent relocation**，不适合夹带 generation lifecycle 重构。

因此本计划对 `PLAN-platform-restructure-goals-v1` 做如下增量队列修订：

```text
G25C COMPLETE
-> G25D apps/web + root ownership
-> G25R-1 resumable generation backend
-> G25R-2 resumable generation client + drills
-> G25E-1 Hosted DR contract
-> G25E-2 Hosted DR fault drills
-> Phase 2.5 exit audit
```

**G25D 的 objective / stopping condition / scope 保持不变。**

在主 Goal 计划尚未同步修改前，关于 G25D 与 G25E 之间的执行顺序，以本插入计划为准；其他不冲突条款继续由原计划控制。

## 2. 为什么不是现在立刻打断 G25D

### 2.1 G25D 需要保持可归因、可回滚

G25D 的核心价值是把 legacy root Next/OpenNext application 等价迁入 `apps/web`，并收紧 root ownership。若在 relocation 同时改变 Arena 的：

- runtime placement；
- cancellation semantics；
- Redis dependency；
- SSE resume protocol；
- client reconnect state machine；

发生回归时将很难区分“搬迁问题”与“可靠性行为变化”。

因此 G25D MUST 先独立完成和验收。

### 2.2 为什么必须早于 G25E

G25E-1/2 本来就要处理：

- generation/stream replay class；
- stable logical endpoint；
- mid-flight disconnect；
- 不产生第二次 Provider/generation。

若先做 G25E 再补 generation resume，DR contract 会建立在旧的“连接即 generation”模型上，随后还要重写一次。

因此 G25R SHOULD 位于 G25D 与 G25E 之间，作为 Hosted DR 的可靠性前置输入。

## 3. 为什么分成两个 Goal

完整改造横跨：

- Arena generation service seam；
- Hono route re-entry；
- Redis runtime / replay store；
- idempotency / producer ownership；
- SSE wire；
- Web client state machine；
- R2/D1 fallback；
- fault harness / telemetry。

把这些强行塞进一个约 5 小时 Goal 会失去 review 与 rollback 边界。

因此分为两个约 4–5 小时 checkpoint，并规定：**G25R-1 完成后不得单独 production cutover；G25R-2 验收通过后才允许公开切流。**

## 4. G25R-1：server-owned generation + Redis replay seam

**预计工作量：4–5 小时。**

### Objective

建立不依赖 subscriber connection 的 Arena generation producer，完成 stable request identity、single-producer reservation、Redis snapshot/replay、status/cancel backend contract，并为 `arena/generate-stream` 重新进入 Hono shared-service seam 建立可验证边界。

### Scope

1. 在共享 contract/service 层抽取 Arena generation producer 边界；
2. `req.signal` 不再直接作为 Provider abort signal；
3. 新建 generation-owned abort controller；
4. 定义 `generationRequestId` 与 payload hash；
5. 新建窄 `GenerationReplayStore` port；
6. `apps/api` Redis adapter 实现 reservation/state/lease/snapshot/XADD/XREAD/terminal；
7. delta batching；
8. status/resume/cancel Hono backend contract；
9. R2 output pipeline 改为 producer-owned；
10. 增加后端专项单元/集成测试；
11. 为 route re-entry 补 contract parity evidence，但本 Goal 不公开切流。

### Backend contract checklist

必须验证：

- auth user / activity actor parity；
- Arena request schema；
- safety / rate limit；
- provider/model resolution；
- signature/native card semantics；
- D1 battle report write；
- R2 large output；
- rating / history / current-state finalization；
- SSE existing event semantics；
- explicit cancel；
- single producer；
- Redis unavailable before reservation => Provider 未启动；
- producer lease expiry => 不自动重跑。

### Stopping condition

- `GenerationReplayStore` 为窄 port，shared code 不依赖 raw Redis client；
- 同一 `(actor, generationRequestId, payloadHash)` 只能得到同一 generation；
- conflicting payload fail closed；
- subscriber disconnect 不会触发 Provider abort；
- explicit cancel 会触发且幂等；
- replay event 具备单调 cursor；
- R2 upload 不再因 subscriber cancel 自动取消；
- Hono adapter 可以通过测试执行完整业务 core；
- public route 仍保持旧 production path 或 feature flag off；
- package/server/workspace/build + targeted tests 通过；
- 独立 review 无 Critical/Important open finding。

### Rollback

G25R-1 必须保持未切流状态。失败时删除/关闭新 adapter/replay feature，不影响 G25D 已完成的 `apps/web` relocation。

---

## 5. G25R-2：Web reconnect + route cutover + fault evidence

**预计工作量：4–5 小时。**

### Objective

让 Web 对同一个 generation 自动 reconnect/resume，补齐 snapshot/final fallback、明确 UX 与故障演练；全部验收通过后再把 `arena/generate-stream` 作为可靠性例外重新纳入 Hono shared-service manifest。

### Scope

1. Web 在首次请求前生成并保存 `generationRequestId`；
2. 保存 `generationId + lastEventId`；
3. fetch-SSE parser 支持 SSE `id:`；
4. reconnect/resume state machine；
5. bounded exponential backoff + jitter；
6. `online` / `visibilitychange` 的低频恢复触发；
7. `snapshot` replace semantics；
8. terminal D1/R2 fallback；
9. 显式“停止生成”调用 cancel endpoint；
10. disconnect/resume/producer-lost UX；
11. 多 subscriber/replay 去重；
12. telemetry 与 fault harness；
13. contract gate 全通过后修改 Hono route manifest 并切流；
14. 保留 Next/Cloudflare DR adapter，但不对 non-idempotent generation 做透明自动 replay。

### Route re-entry rule

只允许首个 vertical：

```text
arena/generate-stream
+ 该能力必要的 generation status/resume/cancel endpoints
```

MUST NOT 借此把其余 13 条 exited routes 批量重新纳入 Hono。

只有出现明确 runtime/cost/reliability/security/platform benefit 且有独立 parity 证据的 route 才能另案重评。

### Fault matrix

至少真实/半真实验证：

1. 生成中断网 5–30 秒再恢复；
2. Wi-Fi ↔ mobile 切网；
3. 页面刷新；
4. 首次 POST 服务端已接受但客户端未收到 response headers；
5. reader cancel 但未 explicit stop；
6. explicit stop；
7. 两个 tab 同时观察；
8. cursor replay；
9. cursor trim 后 snapshot bootstrap；
10. Redis replay 写失败；
11. 创建时 Redis reservation 不可用；
12. producer process kill；
13. Redis TTL 到期但 R2/D1 terminal 已存在；
14. 多次 resume 后 rating/history/finalize 无重复。

每个场景 MUST 记录：

- generationRequestId / generationId；
- Provider start count；
- subscriber disconnect count；
- resume attempts/success；
- replay/snapshot bytes；
- terminal state；
- D1/R2 finalization；
- rating/history side-effect count。

### Stopping condition

- 五类核心网络场景（断网、切网、刷新、初始握手丢失、多 tab）均不会启动第二 Provider；
- reconnect 后正文无明显 duplicate/gap；
- Redis cursor 丢失有 snapshot/final fallback；
- `producer_lost` 不自动重新生成；
- explicit cancel 可用；
- `arena/generate-stream` re-entry parity gate 通过；
- `config/hono-api-routes.json` 只做经证据支持的精确 capability 变更；
- full targeted + package/server/workspace/build 验证通过；
- 独立 review 无 Critical/Important open finding；
- production cutover 有独立 rollback 开关/步骤。

## 6. 与 G25E-1 / G25E-2 的交接

G25R-2 完成后，G25E 不再从“如何定义 generation mid-flight 身份”开始设计，而直接消费以下已验证 contract：

- stable `generationRequestId`；
- `generationId`；
- create/status/resume/cancel；
- `safe | durable-idempotent | generation-non-replayable` replay class；
- D1/R2 terminal evidence；
- Redis transient replay state；
- `producer_lost` 明确状态；
- second-provider prevention evidence。

G25E-1 仍负责 Hono ↔ Cloudflare DR 的长期 stable logical endpoint / control-plane / provider contract。

G25E-2 仍负责更高故障域：Hono unavailable、D1 Gateway unavailable、Redis unavailable、version skew、DR secret missing 等。G25R 只提前把 **客户端连接中断** 这一最常见 generation failure domain 做成可恢复能力。

## 7. 验证命令与证据要求

Agent 应根据当时 workspace 脚本精确选择命令；至少包括：

```text
pnpm test -- <targeted generation/replay tests>
pnpm test:server
pnpm lint
pnpm build
pnpm verify:server:runtime
```

如 G25D 后命令已迁到 workspace package，必须使用最新 package-owned 命令，不得机械沿用本计划示例。

还必须保存：

- route manifest diff；
- contract parity matrix；
- fault matrix 结果；
- Provider start count 证据；
- Redis key/TTL/memory 观测；
- reconnect telemetry 示例；
- independent review 结论；
- rollback 结果。

## 8. 不在本轮顺手做的工作

- 不迁移全部 Hosted generation routes；
- 不启用 Arena Multiplayer runtime；
- 不引入 DO/Queue/Workflow；
- 不把 SSE 改为 WebSocket；
- 不把 Redis 当长期战报库；
- 不做大规模 Arena UI/视觉重构；
- 不在 G25R 中重写 Hosted DR adapter；
- 不实现“进程死亡后从最后 token 继续同一个 Provider 请求”的虚假能力。

## 9. 需要后续根据数据调整、但不阻塞开工的参数

以下属于运行参数而非待拍板产品决策，Agent 可先采用保守默认并通过 telemetry 调整：

- replay TTL（建议 terminal 后 30–60 分钟量级起步）；
- XADD trim 上限；
- delta 50–100ms / 0.5–2 KiB batching 阈值；
- reconnect base/max delay 与 jitter；
- producer lease/heartbeat 周期；
- snapshot flush 周期。

任何参数调整都不得改变以下硬约束：**单 producer、断线不 cancel、显式 cancel、无不安全 replay、Redis 非业务 authority、D1/R2 terminal fallback。**

## 10. 本轮决策记录

本轮没有需要新增顶层 ADR 的未决产品问题。

已经收敛的关键实施决策：

1. 不打断 G25D；先完成纯 relocation；
2. G25R-1 / G25R-2 插在 G25D 与 G25E-1 之间；
3. v1 先解决 Arena battle report；
4. `arena/generate-stream` 可因明确可靠性收益重新进入 Hono，但必须重新过 capability parity gate；
5. generation producer 与 subscriber lifecycle 解耦；
6. stable generationRequestId 在首次请求前生成；
7. Redis Streams + snapshot 做短期 resume，R2/D1 做 terminal fallback；
8. fetch-SSE 保留现有 auth/activity headers，遵循 SSE `id` / `Last-Event-ID` 语义；
9. process loss 不自动重新生成；
10. 完整切流必须等后端和客户端两个 Goal 都验收通过。
