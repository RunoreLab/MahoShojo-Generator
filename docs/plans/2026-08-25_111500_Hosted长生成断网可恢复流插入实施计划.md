## 1. 结论与新的默认执行顺序

Phase 2.5B 当时将 14 条高风险 capability 退出 Hono 是正确的结构裁决：先删除 `legacy-next` 动态导入和伪双运行时，再要求未来 re-entry 必须证明 runtime 收益并建立 shared service / parity / replay contract。

现在新增了两类足以重新打开 placement 的证据：

1. **生产可靠性**：Arena 长生成已出现真实移动网络断开导致战报截断；当前 subscriber abort 会传导到 Provider generation；
2. **运行成本**：仓库已有历史生产分析显示 `/api/arena/generate-stream` 曾约占新 Worker CPU 的 52.5%，而 `apps/api` / Hono 已完成真实应用激活与 Redis/telemetry ownership。

因此本计划不再默认“先 G25D、再修流”，而把 Arena 最小可靠性/成本纵切提升为当前阻断优先级：

```text
G25C COMPLETE
  -> G25R-1 Arena execution seam + server-owned generation backend
  -> G25R-2 Web resume + arena/generate-stream Hono cutover
  -> G25D apps/web + root ownership（COMPLETE）
  -> G25H-1 Arena companion AI routes re-entry（COMPLETE）
  -> G25H-2 Details / Sublimation re-entry（COMPLETE）
  -> G25E-1 Hosted DR contract / stable endpoint（COMPLETE；control plane not-provisioned）
  -> G25E-2 Hosted DR drills + Phase 2.5 exit audit（当前入口）
```

`G25H-3 Tea Party / Tavern re-entry` 是 **telemetry-gated optional Goal**，默认不阻塞 Phase 2.5 退出；若在执行期证明其已成为显著 Cloudflare CPU/request hotspot，可提前插到 G25E 前。

### 1.1 为什么现在允许 G25R 位于 G25D 前

G25D 仍然必须保持纯 behavior-equivalent relocation；本计划并不把 reliability change 混进 G25D，而是把 G25R 做成 **独立且先完成的 Goal/commit boundary**。

本计划形成时 G25D 尚未开始；同时 Arena 已有生产故障和历史 CPU hotspot 证据。先把最重、最脆弱的 Arena stream 从当时的 legacy root 业务实现抽成 shared service，反而能让随后 G25D 搬迁的 Next route 更薄，降低 relocation 时携带的高风险业务体积。

如果执行时发现 G25D 已经开始、或已有未合并的大规模 relocation diff，则 MAY 先闭合 G25D 再恢复 G25R；不得把两个目标交叉执行成长期不可独立 revert 的混合 worktree。

### 1.2 为什么不是 14 条全部迁回

Cloudflare Workers 当前 Standard 主要按 request 与 CPU time 计费，HTTP wall-clock duration 本身不收费，等待外部网络响应不等于 CPU 消耗。因此“这是长 AI 请求”不是充分迁移理由。

本轮以 **真实 CPU/request、payload/安全扫描/序列化、流式处理、Redis/可靠性、跨 runtime 编排** 为 placement 依据，不以 Hono route 数量作为 KPI。

## 3. Goal 拆分原则

Arena re-entry + resumability 横跨：

- Arena generation service seam；
- Hono adapter / route manifest；
- Redis reservation / state / lease / Streams；
- provider-owned lifecycle / explicit cancel；
- SSE wire + replay cursor；
- Web reconnect state machine；
- D1/R2/rating/history finalization；
- production fault evidence。

为了保持约 5 小时 Goal、独立 review 和 rollback，本轮先拆为两个阻断 Goal；`arena/generate-stream` 完成公开切流后再恢复平台搬迁。

**G25R-1 完成后不得单独 public cutover；G25R-2 验收通过才允许 `arena/generate-stream` 从 exited 精确 re-enter shared manifest。**

Arena 其余三条 AI route 另放 G25H-1，避免为了“family 整齐”拖长故障修复。

## 4. G25R-1：Arena execution seam + server-owned generation backend

**预计工作量：4–5 小时。**

### Objective

把 `arena/generate-stream` 的高风险业务链从 legacy Next handler 抽成可由 Next/Hono adapter 共同调用的 shared execution boundary，并建立稳定 request identity、single-producer reservation、server-owned lifecycle、Redis snapshot/replay/status/cancel backend。

本 Goal **不公开切流**。

### Scope

1. 盘点当前 Arena stream 的 request schema、auth/activity、Provider、安全、签名、历史、排位、D1/R2、SSE 与 finalization 顺序；
2. 抽取最小 shared business service / runtime-neutral contract；
3. Hono/Next adapter 不再通过 app-to-app 或 handler import 复用；
4. `req.signal` 不再直接作为 Provider generation abort；
5. 新建 generation-owned `AbortController`；
6. 定义客户端预生成的 `generationRequestId` 与 payload/semantic hash；
7. 新建窄 `GenerationReplayStore` port；
8. `apps/api` Redis adapter 实现 reservation/state/lease/snapshot/XADD/XREAD/terminal；
9. markdown/reasoning delta batching；
10. status/resume/cancel backend contract；
11. R2 output pipeline 改为 producer-owned；
12. 后端专项单元/集成/contract tests；
13. Hono adapter 可完整执行 shared core，但 route manifest 仍不切 production。

### Backend contract checklist

必须验证：

- auth user / activity actor parity；
- Arena request schema；
- safety / rate limit；
- provider/model resolution；
- signature/native card semantics；
- D1 battle report write；
- R2 large output；
- rating / narrative/current-state/history finalization；
- SSE existing event semantics；
- explicit cancel；
- single producer；
- Redis unavailable before reservation => Provider 未启动；
- producer lease expiry => 不自动重跑；
- subscriber disconnect => Provider 与 R2 producer 继续。

### Stopping condition

- `GenerationReplayStore` 是窄 port，shared code 不依赖 raw node-redis；
- 同一 `(actor, generationRequestId, payloadHash)` 只能得到同一 generation；
- conflicting payload fail closed；
- subscriber disconnect 不触发 Provider abort；
- explicit cancel 可触发且幂等；
- replay event 有稳定单调 cursor；
- R2 upload 不因 subscriber cancel 自动取消；
- Hono 与 Next adapter 的核心业务 contract parity 可机械验证；
- public client/route 仍走旧路径或新 path 未启用；
- package/server/workspace/build + targeted tests 通过；
- 独立 review 无 Critical/Important open finding。

### Rollback

删除/关闭未切流的 Hono adapter、ReplayStore 和 feature seam 即可恢复原公开行为；不得要求回滚数据库 schema 或生产数据。

## 5. G25R-2：Web resume + `arena/generate-stream` Hono public cutover

**预计工作量：4–5 小时。**

### Objective

让 Web 能对**同一个** Arena generation 自动 reconnect/resume，补齐 snapshot/final fallback、显式 cancel、移动网络 UX 与 fault evidence；全部通过后再精确把 `arena/generate-stream` 纳入 Hono primary。

### Scope

1. Web 在首次 POST 前生成并持久保存 `generationRequestId`；
2. 保存 `generationId + lastEventId`；
3. fetch-SSE parser 支持 SSE `id:`；
4. reconnect/resume state machine；
5. bounded exponential backoff + jitter；
6. `online` / `visibilitychange` 低频恢复触发；
7. `snapshot` replace semantics；
8. terminal D1/R2 fallback；
9. “停止生成”调用 explicit cancel；
10. disconnect/resume/producer-lost UX；
11. 多 subscriber / replay 去重；
12. reconnect + placement telemetry；
13. fault harness；
14. parity/review/gate 全通过后修改 `config/hono-api-routes.json`，只让 `arena/generate-stream` 精确 re-enter；
15. Next adapter 作为 Cloudflare DR surface 保留，不做 mid-flight transparent replay。

### Route re-entry gate

必须同时满足：

- shared core；
- Next/Hono adapter parity；
- auth/authority/safety/signature/provider parity；
- D1/R2/rating/history side-effect parity；
- existing Arena SSE event compatibility；
- new resume/status/cancel contract；
- no app-to-app import；
- `legacyRouteIds=[]`；
- targeted + package/server/workspace/build；
- independent review；
- standalone rollback/cutback path。

### Fault matrix

至少验证：

1. 生成中断网 5–30 秒再恢复；
2. Wi-Fi ↔ mobile 切网；
3. 页面刷新；
4. 首次 POST 服务端已接受但客户端未收到 response headers；
5. reader cancel 但未 explicit stop；
6. explicit stop；
7. 两个 tab 同时观察；
8. cursor replay；
9. cursor trim 后 snapshot bootstrap；
10. Redis replay 写失败；
11. 创建时 Redis reservation 不可用；
12. producer process kill；
13. Redis TTL 到期但 R2/D1 terminal 已存在；
14. 多次 resume 后 rating/history/finalize 无重复。

每个场景至少记录：

- generationRequestId / generationId；
- Provider start count；
- subscriber disconnect count；
- resume attempts/success；
- replay/snapshot bytes；
- terminal state；
- D1/R2 finalization；
- rating/history side-effect count。

### Stopping condition

- 断网、切网、刷新、初始握手丢失、多 tab 均不会启动第二 Provider；
- reconnect 后正文无明显 duplicate/gap；
- Redis cursor 丢失有 snapshot/final fallback；
- `producer_lost` 不自动生成第二次；
- explicit cancel 可用；
- `arena/generate-stream` Hono re-entry parity gate 通过；
- route manifest 只做这一条及必要 status/resume/cancel control surface 的精确变更；
- full targeted + package/server/workspace/build 验证通过；
- 独立 review 无 Critical/Important open finding；
- public cutover 与 rollback/cutback 步骤已验证。

完成 G25R-2 后，**恢复 G25D**。

## 11. Telemetry 与 placement evidence

执行每个 Hono re-entry Goal 前后，至少保存 capability/runtime 可比指标：

- request count；
- Worker/Hono CPU 或 process CPU；
- AI TTFB / total duration；
- input/output bytes；
- provider starts / retries；
- stream disconnect/resume；
- D1/R2/Redis latency/error；
- safety/prompt/finalization stage timing（安全可观测时）；
- runtime selection / DR reason（可信入口具备后）。

## 13. 外部设计依据

最近核验：2026-08-25。

- Cloudflare Workers Pricing：<https://developers.cloudflare.com/workers/platform/pricing/>；Standard 以 requests + CPU time 为主要计费维度，duration 本身不收费；
- Cloudflare Workers Limits：<https://developers.cloudflare.com/workers/platform/limits/>；Paid request CPU 可配置到更高上限，但这不消除总 CPU 成本与 denial-of-wallet 风险；
- Cloudflare Load Balancing Standard steering：<https://developers.cloudflare.com/load-balancing/understand-basics/traffic-steering/steering-policies/standard-options/>；`Off - Failover` 支持典型 active-passive；
- Redis Streams / XREAD：<https://redis.io/docs/latest/develop/data-types/streams/>；按 last seen ID 做 bounded replay；
- WHATWG SSE：<https://html.spec.whatwg.org/dev/server-sent-events.html>；`id` / `Last-Event-ID`；
- Hono Streaming：<https://hono.dev/docs/helpers/streaming>。

外部平台能力只作为实现依据；实际业务 replay/authority 仍以仓库 accepted ADR/spec 为准。

## 16. 本轮决策记录

本次修订冻结：

1. Phase 2.5B capability exit 不被否定；禁止恢复 legacy dynamic import；
2. Hosted heavy AI execution 的目标形态是 **Hono primary + Cloudflare DR adapter**，但 route-by-route/family-by-family 证明收益；
3. Cloudflare wall-clock wait 不等于 CPU，因此不按“长流”机械迁移；
4. Arena `generate-stream` 有生产可靠性事故 + 历史 CPU hotspot，默认 **先于 G25D** 执行 G25R-1/2；
5. G25D 仍保持纯 relocation，不混入 generation 语义变更；
6. `arena/generate-stream` 是第一条公开 re-entry；后端与客户端均验收后才 cutover；
7. Arena companion 三条 route 在 G25D 后继续 Hono re-entry；`regenerate` 继续 Next；
8. Details/Sublimation 四条已作为 Phase 2.5 Hosted AI execution 精确 re-entry 并闭合；
9. Tea Party/Tavern 按 telemetry 触发，默认不阻塞 Phase 2.5；
10. generation producer 与 subscriber lifecycle 解耦，stable generationRequestId 在首次请求前生成；
11. Redis Streams + snapshot 做短期 resume，D1/R2 做 terminal authority/fallback；
12. Hosted generation 默认 active-passive；未知 mid-flight 不跨 runtime transparent replay；
13. G25E 在上述真实 execution/replay contract 上做长期 DR，而不是反过来定义 generation identity。
