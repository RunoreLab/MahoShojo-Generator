# Arena 多人 Redis-only Room Directory 清理实施计划

状态：`completed`
日期：2026-08-28
对应规范：`SPEC-arena-multiplayer-redis-only-directory-amendment-v1`
基线 source SHA：`0e53b8d1`

## 1. Objective

在不回退 GMR-07/GMR-08 行为的前提下，把 Arena 多人 v1 的 Room directory 从 D1 derived projection 收缩为 Redis-only derived index，并从生产迁移链、schema mirror、运行时 wiring、依赖和验证脚本中完全移除 `arena_multiplayer_rooms`。

Room checkpoint 继续是唯一 session authority。Directory record/index 只负责发现候选；所有 lookup/list/join 在返回或建立 membership 前仍以 current Redis checkpoint 的 open lifecycle、exact `roomEpoch` 和 host authority 最终校验。

## 2. 实现边界

### 2.1 Redis keyspace

- 保留既有环境 `ROOM_REDIS_*` namespace 语义；新增目录 key 必须由同一个 keyspace helper 生成。
- 每个可发现 Room 使用一个有界 directory record；public Room 额外进入一个有界分页的 sorted set。
- unlisted Room 不进入 public index；v1 没有产品级 host list 路由，因此不新增 per-host index。
- public index candidate 永远不是 authority；record absent、malformed、closed、wrong epoch 或 wrong host 时不得返回。

### 2.2 原子 lifecycle

- create：服务端验证 canonical directory record 后，把 Room checkpoint、directory record 与 public index member 放在同一次 Redis Lua/CAS 提交中。
- recovery/低频 authority checkpoint：若 directory record 已存在，在同一次 CAS 中更新 exact epoch 与活动时间；不得通过异步补偿重绑。
- close：在 terminal checkpoint 提交的同一次 CAS 中删除 directory record/public member。
- Redis 返回未知时沿用 RoomActor quarantine/recovery；不得在 checkpoint 成功后另做盲重放的目录写。
- lazy cleanup 使用 exact raw/CAS，不能删除并发 replacement record。

### 2.3 明确删除

- D1 adapter、registration store、两类 reconciler、tombstone/compensation wiring；
- `drizzle/0014_arena_multiplayer_rooms.sql` 与两个 schema mirror；
- D1/registration 专属测试、依赖与 Redis verifier case；
- `ROOMRT-018` / GMR-06 D1 当前态叙述，改为显式 superseded 历史。

保留 storage-neutral directory contract、public/unlisted HTTP/UI 语义、分页硬上限及 GMR-06 历史归档。

## 4. 验收矩阵

必须证明：

1. public create 的 checkpoint、record、index 同 commit 可见；
2. unlisted create 不出现在 public index，已知 roomId 仍可 join；
3. create reply-loss/recovery 不产生 registration 补偿或第二份目录事实；
4. recovery epoch 只由 current checkpoint CAS 更新，old epoch 不得覆盖；
5. close checkpoint 与 index removal 同 commit；
6. absent/malformed/closed/wrong-epoch/wrong-host candidate 不返回，lazy cleanup 不误删并发 replacement；
7. cursor/limit 有硬上限，单页 Redis work 有界；
8. Redis unavailable 时 create/close 等 authority transition fail closed；
9. Redis restart/AOF 后 checkpoint 与已提交 index 一致；
10. GMR-07 create/list/join/session/ticket/leave/close 和 GMR-08 Proposal 不回归；
11. 仓库不再存在 `arena_multiplayer_rooms`、D1 Room adapter 或 registration/reconciler runtime；
12. 未执行 production/preview migration/write/deploy/secret/release 操作。

## 5. Production 与回滚影响

- production/preview schema：未发布 `0014`；实施期间除 production D1 的两条只读 metadata query 外，不访问或修改
  远程 schema。preview 未配置独立 D1，记为 `NOT_APPLICABLE`。
- production Redis：不 flush、不迁移、不写；新 keyspace 只在 local/test verifier 使用。
- secret/release：无变更。
- 若未来审计发现共享环境已应用 `0014`，停止自动清理并另立带备份/回滚的人工 schema operation；本计划不授权远程 `DROP TABLE`。
