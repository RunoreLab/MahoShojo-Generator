# Challenge 入口角色卡选择与导入 Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** 让 `/challenge` 的 lobby 入口复用 `/arena` 现有的数据卡选择与导入体验，支持数据库选择、随机匹配、文件上传、粘贴文本、试玩示例和高级 JSON 编辑，同时保持 challenge 自有的单卡入场草稿状态，并为未来组队扩展预留数组形态。

**Architecture:** 复用 `DatabaseSelector`、`BattleDataModal` 和 `CollapsibleSection`，但不复用 arena 的战斗 store。新增 challenge 专用的共享导入 helper 与入场草稿状态转换 helper，把“选卡 / 随机匹配 / 文本解析 / 编辑区 dirty 判定 / prepareChallenge 取源优先级”收敛成可测试的纯函数；`useChallengeController` 负责持有草稿状态与入口动作；`ChallengePage` 负责数据库弹窗和登录态；`ChallengeLobby` 改造成分区式入口。

**Tech Stack:** Next.js Pages Router、React 19、TypeScript strict、Bun test、Tailwind 4、现有 `BattleDataModal`、现有 `DatabaseSelector`、现有 `CollapsibleSection`

## 关键约束

- `/challenge` 当前不接入 `useBattleStore`
- `ChallengePage` 持有 `BattleDataModal` 开关状态，`ChallengeLobby` 不直接管理 portal/modal
- `useChallengeController` 必须显式维护：
  - `entrantCards`
  - `sourceMode`
  - `rawEditorText`
  - `lastAppliedEditorText`
  - `isEditorDirty`
  - `inputError`
- 非编辑来源写入角色卡后，必须同步重置 `isEditorDirty=false`
- 高级 JSON 编辑只有在“应用编辑内容”成功，或“生成竞技场快照”触发自动应用成功后，才允许把 `sourceMode` 变为 `manual-json`
- 失败的自动应用只在高级编辑区显示错误，不升级为全局 challenge 错误
