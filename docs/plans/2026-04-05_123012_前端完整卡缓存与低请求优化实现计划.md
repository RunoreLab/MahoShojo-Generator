# 前端完整卡缓存与低请求优化 Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** 为 `/challenge` 与 `/ranking` 详情建立共享的完整公开卡两级缓存，在不改变服务端选敌真相源的前提下提升前端响应速度，并减少重复 `/api/public-data-cards?id=...` 请求与对应数据库读流量。

**Architecture:** 复用现有 `ai-continuous-dialogue:v1` IndexedDB，在其上新增 `public_card_cache` store，配合模块级 memory `Map` 组成 L1/L2 两级缓存。读取顺序固定为 `sidecar -> memory -> IndexedDB -> network`，写入来源限定为 challenge sidecar 与单卡详情成功结果；`/challenge` 与 `/ranking` 详情弹窗统一走共享 loader，而不是各自维护局部 fetch/cache 逻辑。

**Tech Stack:** Next.js Pages Router、React 19、TypeScript strict、Bun test、fake-indexeddb、现有 `ai-session` IndexedDB 基础设施、`/api/public-data-cards`

## 关键约束

- 完整卡共享缓存与 `lib/arena/rank-cache.ts` 必须保持隔离，禁止复用 `localStorage` rank cache 存完整卡 JSON
- `selectionSeed` 与服务端选敌仍是 challenge 真相源；本地缓存只服务展示与详情读取
- `resolvedSourceCardLite` 仍优先于任何本地缓存命中
- 正缓存 TTL 固定为：
  - `FRESH_TTL_MS = 60 * 60 * 1000`
  - `HARD_TTL_MS = 24 * 60 * 60 * 1000`
- 负缓存只允许缓存 `404`，TTL 固定为：
  - `NEGATIVE_TTL_MS = 3 * 60 * 1000`
- 500、超时、Abort、网络错误都不得写入负缓存
- IndexedDB 不可用时必须安全降级为 memory-only，不得阻塞主流程
- 本轮容量上限固定为：
  - 正缓存 `256`
  - 负缓存 `128`
