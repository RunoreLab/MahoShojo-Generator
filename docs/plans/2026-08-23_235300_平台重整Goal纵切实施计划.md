状态：`active`

## 1. 定位

本计划是 [平台重整分阶段实施计划](./2026-08-22_022700_平台重整分阶段实施计划.md) 的 `/goal` 执行层。

主计划继续决定 Phase 顺序、退出门禁和长期依赖；本计划只回答：

- 下一段工作如何组合成约 5 小时的 durable Goal；
- 每个 Goal 的 objective 与 stopping condition 是什么；
- 哪些工作属于同一上下文，应在一个长时 run 中闭环；
- 哪些工作预计明显超过约 5 小时，应另开 Goal。

执行治理、Agent 自治权限、文档变更权限、review 和最终验收统一遵循 [平台重整 `/goal` 自治执行与验收规格](../specs/2026-08-23_235200_平台重整Goal自治执行与验收规格.md)。

## 2. Goal 尺寸口径

默认目标：**每个 Goal 约 5 小时有效自治开发工作量**。

规划时采用以下口径：

- 约 `3.5–5.5h` 可视为正常单 Goal 区间；
- 明显低于该区间的同主题工作优先与前后 checkpoint 合并，不单独开 Goal；
- 预检后预计明显超过约 `5h`，优先按独立 stopping condition 拆分；
- 5 小时是 sizing heuristic，不是到点自动停止；接近完成时继续闭环；
- Agent 启动每个 Goal 时必须按最新代码重新估算，本文数字不是承诺或计时器。

当前估计参考：

- 已有 Phase 2 / 2.5A / 首条 Hono seam 的实际实施日志；
- 当前全仓测试、workspace/build 验证规模；
- 一条代表性 shared-service seam 已建立后，重复生成类 route 的边际成本下降；
- Arena/session/tea-party/regenerate 等状态型 route 的认证、幂等和副作用差异显著高于普通生成 route；
- app relocation 与 DR/fault drill 分别拥有独立构建/部署和故障语义，不宜强行塞进同一 Goal。

### G25B-1：常规 Hosted 生成族 shared-service 收口

**预计工作量：4–5 小时。**

**Objective**

把 Phase 2.5B 中结构相似、主要是单次/流式 Hosted 生成的 legacy Hono route 批量收口到稳定 shared service + Next/Hono adapter 模式，显著减少 legacy root/Next handler 动态导入面，同时不改变用户可见语义。

**优先候选族**

Agent 应按当前依赖图重新聚类，制定时优先考虑：

- Creator generate / stream；
- 残兽 generate / stream；
- Free generate / stream；
- Scenario generate / stream；
- Sublimation generate / stream；
- Magical Girl details generate / stream；
- Game Card generation；
- 与上述共享 composition/service port 的其他低状态 route。

这不是要求保留所有现有 Hono route。若某 route 不满足 Hono 运行时/成本/可靠性价值，Agent 可以依据主计划的 Hono 路由扩张门禁决定退出 Hono，并保持 Web 行为与回滚证据。

**Stopping condition**

- 本 Goal 选定的常规生成族不再通过 Hono 动态导入 legacy Next handler；
- retained Hono route 与 Next adapter 调用同一 shared business core；
- request/response、auth actor、内容安全、签名/活动记录等适用副作用保持 contract parity；
- route manifest、dispatcher 和 workspace boundary tests 能机械阻止退回 app/root 深层复用；
- 不新增“只是因为能迁”而进入 Hono 的 route；
- targeted + package + server + workspace 验证通过；
- 独立 review 无未关闭 Critical/Important finding；
- 日志记录迁移/退出的 capability、理由与剩余 legacy family。

**拆分触发**

若启动时发现这些 route 已明显共享同一 service composition，应继续合并推进；只有实际依赖差异使本组预估明显超过约 5 小时时，才把后半族移动到 G25B-2，不按固定 route 数硬拆。

**Objective**

把 Hono Node runtime 从 legacy `server/` 所有权迁入真实 `apps/api` workspace app，并把与该 runtime 强相关的剩余容量 telemetry 和构建/部署 ownership 一并收口。

**为什么合并 telemetry**

AI upstream、D1、Redis 和 runtime selection telemetry 都依赖 Hono runtime composition。与 `apps/api` 激活分开做会重复触碰 middleware/provider/deploy seam，因此作为同一 Goal 的 checkpoint 更节省上下文和验证成本。

**Stopping condition**

- `apps/api` 拥有真实 source/manifest/test/lint/build/env/health/deploy ownership；
- 根 manifest 不再替 `apps/api` 持有其 runtime 依赖；
- Docker/CI/deploy 以 `apps/api` 及其真实 workspace dependency closure 为边界，不继续要求未来 Admin/Desktop 等无关 app 进入 Hono image；
- Hono 不直接导入 `apps/web` 或 legacy root application internals；
- `RESOURCE-005` 中可由 Hono runtime 自身真实观测的 AI/D1/Redis 指标收口；入口层无法观测的信息继续显式 `not-observed`，不伪造；
- build artifact、health/readiness 和回滚语义与迁移前等价；
- production deploy 不在默认 Goal 授权内；
- full server/workspace/CI verification 与独立 review 通过。

目标是用一个最小真实客户端纵切验证 Tauri 2 是否满足核心 runtime-neutral 架构，而不是复制完整 Web：

```text
本地打包 UI
-> Direct Provider Profile
-> localhost/OpenAI-compatible stream + cancel
-> Secure Vault
-> SQLite CardRepository
-> restart persistence
-> import/export
```

必须验证 no generic shell/fs/fetch、IPC schema、Key 不离设备、server secret 不进 bundle。只有 accepted ADR 的 Tauri failure gate 被真实触发后，才启动 Electron fallback spike。

## 7. Goal 启动时的自主重排规则

上述 G25B-1...G5A-1 是**当前最佳估计，不是不可修改的任务清单**。

Agent 启动任一 Goal 时可以根据最新事实：

- 合并已经缩小到明显不足一个 Goal 的相邻工作；
- 把预计明显超过约 5 小时的独立 stopping condition 移入下一 Goal；
- 调整 route family/文件分组；
- 删除已被后续提交完成的计划项；
- 因新证据增加必要的 blocker-fix checkpoint。

但 Agent 不得：

- 跨越主 Phase 前置条件；
- 为了凑工时提前做后置产品功能；
- 将相互独立的高风险目标拼成开放 backlog；
- 通过降低 accepted spec/acceptance 来让 Goal 看起来更小。

重排后应在实施日志记录“原估计 -> 实际范围 -> 调整理由”。

## 8. 每个 Goal 的统一完成模板

每个 Goal 在开始时应把具体 stopping condition 转成验收表，并在结束时更新为：

```text
Objective: <one durable objective>
Estimated size: ~5h
Actual scope: <implemented checkpoints>

PASS:
- ...

NOT_APPLICABLE:
- ...

DEFERRED:
- ...

BLOCKED:
- ...

Review:
- Critical: 0 open
- Important: 0 open
- Minor: <fixed or documented>

Validation actually run:
- ...

Rollback:
- ...

Next goal estimate:
- ...
```

如存在阻塞 stopping condition 的 `FAIL` 或 `BLOCKED`，不得写成 Goal 完成。
