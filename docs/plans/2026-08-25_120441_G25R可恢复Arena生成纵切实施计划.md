# G25R 可恢复 Arena 生成纵切 Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use `superpowers:test-driven-development` task-by-task；本 Goal 明确禁止创建 worktree，最终必须经过独立 review。

状态：`completed`

依据：`SPEC-hosted-resumable-generation-stream-v1`、`PLAN-hosted-resumable-generation-insertion-v1`
启动基线：`00ece445`

**Goal:** 将 Arena stream 变成由服务器拥有、可幂等创建、断线后可恢复的单 producer generation，并在故障矩阵与双 adapter parity 通过后精确切入 Hono。

**Architecture:** `@mahoshojo/hosted-api` 持有 runtime-neutral lifecycle、replay/status/cancel application service 与 SSE contract；`apps/api` 持有 node-redis reservation/snapshot/Streams adapter 和进程内 producer registry；`@mahoshojo/hosted-runtime` 持有 Hono/Next 共用的 Arena server runtime composition。Next 与 Hono 只做 request/actor/runtime adapter，客户端通过稳定 `generationRequestId` 与 replay cursor 恢复同一 generation。

**Tech Stack:** TypeScript、Web Streams/SSE、Hono、Next Route Handler、Redis 7 Streams/Lua、Vitest、D1 Gateway、R2。

## 1. 启动事实与重新估算

- 当前 inventory 为 `10 shared-service / 14 exited / 0 legacy-next`；`arena/generate-stream` 仍 exited。
- 当前 Next handler 约 1,952 行，直接引用 legacy root 的 auth、AI、Arena prompt、安全、签名、D1/R2、rating 与 ranking 实现；不可被 Hono/package 深层导入。
- 当前 subscriber cancel 会同时 `reader.cancel()`、中止 R2，并把 generation 记为 `aborted`；Provider 使用 `req.signal`。
- Web fetch-SSE parser 不解析 `id:`，没有 resume/status/cancel 状态机；刷新/切网只得到中断错误。
- 当前相关测试以源码字符串断言为主；本 Goal 必须增加行为级、慢流与故障注入证据。
- 原 `4–5h + 4–5h` 估计未计入 legacy root 依赖抽取与真实故障 harness。按当前事实重新估算为约 `12–16h` 的单一阻断纵切，仍保持两个可独立 revert 的 commit boundary；不降低 stopping condition。
