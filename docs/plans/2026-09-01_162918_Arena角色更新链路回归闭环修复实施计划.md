# Arena 角色更新链路回归闭环修复实施计划

日期：2026-09-01
状态：`IN_PROGRESS / remediation-plan`
关联规格：`SPEC-arena-post-battle-dual-trust-v1`

## 目标

闭合战报生成后的四个已复现回归：canonical preset 的 base revision 漂移、AI 修复错误落在 Web runtime 并统一返回 HTTP 500、客户端持久状态导致的 SSR 首屏不一致风险，以及 Zod JIT 触发的 CSP `eval` 拒绝。修复不得削弱 authoritative reconciliation、CSP 或 Hosted DR fail-closed 门禁，也不得持久化或记录 BYOK 凭据。

## 1. Canonical preset 权威判定

- 从生成时使用的 server-owned preset registry 生成仅含 `id/kind/versionToken` 的 Hosted authority manifest。
- 在 `@mahoshojo/hosted-runtime` 建立统一 resolver：精确匹配 canonical filename、kind 与内容 digest 的内置 preset 视为 native；否则重新验签，绝不相信客户端 `isNative`。
- generation roster freeze、authoritative reconciliation 与 repair safety 复用同一 resolver。
- 先增加 exact preset、篡改 preset、签名 DataCard 以及 client/server base revision 一致性的失败测试。

验证：Hosted runtime targeted tests、Web update handler tests、registry generator drift check。

原子提交：`fix(arena): 统一 canonical preset 原生权威判定`

## 2. AI repair 归位与 Provider provenance

- 把 repair 注册为 Hosted/Hono shared route；Next route 只保留 DR capability guard 和 adapter，不再实例化 Web AI runtime。
- `generationId` 必填并在服务端校验 generation owner/finalized/provenance；system 通道固定使用该次生成实际落库的 provider/model，失效时 fail closed。
- BYOK 请求使用生成时保留在客户端内存中的 credential snapshot；服务端把 `providerId/modelId` 与 generation provenance 核对，API key 不进入 D1、响应、日志或持久化 store。快照丢失或不一致时明确拒绝，不回退当前 UI 配置或 system provider。
- 抽取并复用正常战报的 Provider/channel 解析；将 provider unavailable、upstream/output、timeout 分别映射为稳定的 503、502、504。
- 先覆盖 Web 无 AI secrets 而 Hono 有配置、生成后切换 UI Provider、BYOK 精确绑定、owner/provenance mismatch、错误映射、manifest/DR parity 的失败测试。

验证：Hosted API/runtime、apps/api adapter、Web hook/route 及 Hosted DR contract targeted tests。

原子提交：`fix(arena): 将角色修复归位 Hosted 生成通道`

## 3. 浏览器一致性与 CSP

- Zod v4 统一启用 `jitless`，从源头避免 `Function(...)`，不得加入 `unsafe-eval`。
- 对 Arena 的 Zustand persist store 使用显式客户端 rehydrate，确保 SSR 与首次 hydration 使用同一默认快照。
- 增加 CSP 构建产物扫描与 SSR/rehydrate 回归测试；保留对浏览器扩展或 Cloudflare 注入导致非稳定 #418 的证据边界。

验证：Web targeted tests、production/build:cf，并扫描静态 chunk 不含可执行 eval 路径。

原子提交：`fix(web): 消除 Arena hydration 与 CSP eval 风险`

## 4. 完整交付门禁

- 运行受影响 workspace 的 test、lint、typecheck、build、route/contract generator drift checks。
- 运行仓库 `ci:verify`、生产 Web build 与 Hosted DR client preflight；能在本地安全运行时执行无生产写入的浏览器 smoke。
- 逐项处理 warning；无法在本地验证的生产外部状态单独列出，不执行 production deploy、远程 migration、secret 变更或切流。
- 每个可独立验收闭环完成后原子提交，最后确保 worktree 无意外修改且所有生成资产同步。
