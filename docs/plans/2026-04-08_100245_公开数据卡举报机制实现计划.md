# 公开数据卡举报机制 Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** 落地公开数据卡举报机制首版，让登录用户可举报公开数据卡，创作者可收到匿名化站内通知，并为 `feat/admin` 后台保留案件处理边界。

**Architecture:** 使用 `report_cases`、`reports`、`report_references` 三张 D1 表表达“同一卡单开放案件 + 多用户举报 + 结构化引用”。`lib/data-card-reports/*` 负责理由配置、DTO、规范化、去重、风控和通知编排；`pages/api/data-card-reports/*` 暴露用户侧查询、提交与撤回接口；`DataCardDetailsModal` 只接入 capability 和举报模态，不承担服务端权限判断。

**Tech Stack:** Next.js Pages Router、React 19、Cloudflare Edge Runtime、Cloudflare D1、Drizzle ORM、Tailwind 4、Bun test、`react-dom/server` 静态渲染测试。

Service rules:

- `GET` capability accepts logged-out users and returns `canReport: false` with `reportDisabledReason: '登录后可举报'`.
- POST/withdraw require authenticated user.
- Exact duplicate `noop_duplicate_payload` does not call rate limit dependency and does not update timestamps.
- New or changed payload must pass rate limit and basic screening before writing.
- Rate limit response maps to `rejected_rate_limited`; API layer will return HTTP 429.
- Basic screening rejection maps to `rejected_screened`; API layer will return HTTP 422.
- Creator notification uses `createUserMessageEntry` with `actorUserId: null`, `sourceEntityType: 'report_case'`, `sourceEntityId: caseId`.
