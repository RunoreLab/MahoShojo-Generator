## 3. 执行原则

1. **先建 gate model，再改数字和文案。** 不把一个 catch-all 拆成十个新的散落 `throw new Error()` 就算完成。
2. **先复用 canonical Arena 能力，再新增 multiplayer exception。** 每个例外必须有 reason/test。
3. **P0 correctness 优先于 UI polish。** 先让 0 角色建房、非原生角色和 limit source 正确，再完成术语清理。
4. **不牺牲安全边界。** secret/private/authority/exact-ref/frame/token gates 继续 fail closed。
5. **不重新制造第二套 Arena validation。** 优先抽取/复用现有 single Arena validator、resource budget、presentation 和 history semantics。
6. **每个切片完成后独立审查。** 重点防止为了“放宽限制”误删真正的 authority/privacy/resource gate。

## 4. GMR-10Q-A：Gate inventory 与 canonical registry

状态：`READY`

### Objective

建立当前所有多人门禁的机器可读/测试绑定清单，先分类再改实现。

### Scope

枚举至少：

- Room create/join/leave/close；
- Shared Config build/publish/apply；
- Proposal submit/resolve/withdraw；
- generation start/preflight/materialization；
- runtime resource funding/body/token/output；
- result persistence/action；
- Web 本地 validation；
- contracts schema/limits；
- Room state-machine capability-denied reasons。

每项记录：

```text
code / condition
-> gate layer
-> current source
-> single Arena equivalent
-> canonical product source
-> security/privacy/authority/resource reason
-> user action
-> current user message
-> desired user message key
-> test id
```

### Required findings to encode

- `combatants.min(1)` 当前错误地处于 Shared Config schema；
- multiplayer `MAX_COMBATANTS=10` 与 runtime `32` 漂移；
- aux/material `10` 与 canonical reference budget `256` 漂移；
- `combatant.isValid` 实际代表 origin signature；
- createRoom catch-all 丢失真实失败原因；
- member limit 与 proposal pending limit 等错误 reason 是否复用；
- Proposal/revision/BASE 等英文产品文案。

### Done

- 未分类 gate 视为测试失败；
- canonical limit drift 有回归测试；
- GMR-10Q-A 不要求立刻改所有 UI。

## 5. GMR-10Q-B：Room lifecycle 与 generation readiness 解耦

状态：`BLOCKED_BY_A`

### Objective

允许先建房再配置，彻底去掉“当前 Arena 必须已经可开战才能创建房间”的隐含条件。

### Scope

#### Contracts/core

- `ArenaRoomSharedConfigSchema.combatants` 允许空数组；
- 将“至少 1 个角色”移入 generation readiness evaluator；
- 审查其他 generation-only completeness 是否误放在 Shared Config schema；
- 保持 unique key/team referential integrity 等 shareability invariant。

#### Create flow

- Room create 只受 Room Lifecycle gate；
- 当前 host config 可安全 share 时可作为 seed；
- 当前 config 不能 share 时仍创建 room，以 canonical empty/draft config 启动；
- 不得静默丢弃：显示“房间已创建，但当前本地配置尚未同步” + issues；
- create unknown/idempotency/recovery 继续有效。

#### Generation start

- 0 角色时明确阻止 start；
- 指向 Arena roster 并提示至少添加 1 位角色；
- mode-specific completeness 同样留在 readiness。

### Required tests

- zero-character create/join/sync；
- create with unsynced local issue；
- zero-character start fail with actionable message；
- host add character -> publish -> start success；
- create unknown retry 仍不重复建房。

## 6. GMR-10Q-C：角色 validity / provenance 语义拆分

状态：`BLOCKED_BY_A`

### Objective

修复“无项目原生签名 = 无效角色 = 不能多人”的错误链路。

### Scope

- 追踪 `isValid` 所有 Arena 使用点；
- 明确 `verifyOrigin/verifySignature` 只表示 provenance/native verification；
- multiplayer `normalizeCombatant()` 不再以 `!combatant.isValid` 拒绝普通角色；
- 复用 single Arena 的 validator/compatibility rules；
- host-local materialization 继续做 payload/kind/type/digest hard validation；
- online/preset 继续 exact ref/version/permission validation；
- 严格排位若要求 native/verified，保留在严格排位自己的 gate。

### Migration preference

允许渐进式拆分字段：

- 不要求一次性全仓 rename；
- 新增代码不得再把 `isValid` 当 schema validity；
- 若兼容成本低，可新增 `originVerified`/`nativeSigned`；
- 对旧 persisted state 做向后兼容。

### Required tests

- unsigned valid local role works in room；
- signed/unsigned 对普通多人 eligibility 等价；
- invalid payload/type mismatch/digest mismatch 仍被拒绝；
- strict ranking 原有签名约束无回归。

## 7. GMR-10Q-D：数量限制与资源预算统一

状态：`BLOCKED_BY_A`

### Objective

删除无证据的 10/10/10 multiplayer-only product limits，与真实 Arena/runtime capability 对齐，同时保留 byte/frame/resource hard ceilings。

### Scope

#### Combatants

- canonical target：Hosted Arena runtime `maxCombatants=32`；
- multiplayer contract 不再单独固定 10；
- single UI 可以继续不显示固定上限，但生成 preflight 应反映真实 runtime 上限；
- 32 以后由 canonical source/equality test 防漂移。

#### Reference items

- 删除 aux scenario per-collection 10；
- 删除 material per-collection 10；
- 采用 canonical cumulative reference budget；
- 当前参考：`maxReferenceItemsSanity=256`；
- Room snapshot/control 仍受 64 KiB serialized frame；
- 若需要额外 count ceiling，用 worst-case/high-percentile serialization test 推导，不拍脑袋。

#### Dependency placement

不得让 `contracts -> hosted-api` 形成反向依赖。实现可：

- 抽 dependency-neutral canonical Arena capability；或
- 生成/同步常量 + equality test；或
- 采用现有合适 domain/config package。

选择前先检查仓库 package boundary 规则。

### Required tests

- 11、16、32 combatants room publish/start；
- 33 fail at canonical generation limit；
- >10 aux/material allowed until cumulative/byte limit；
- cumulative 256 boundary；
- 64 KiB frame boundary；
- no duplicated magic 10 remains in product path unless unrelated。

## 8. GMR-10Q-E：结构化错误与用户术语

状态：`BLOCKED_BY_A`

### Objective

把“无法安全共享”与英文协议术语替换为稳定机器错误 + 中文可行动 UX。

### Scope

#### Domain/API error taxonomy

至少区分：

- room metadata/auth/membership；
- member room capacity；
- config shareability；
- config/frame too large；
- version/ref stale/missing；
- host-local missing/mismatch；
- generation empty roster；
- generation capacity/resource；
- unresolved random；
- proposal pending/change/byte limit；
- authorization/capability；
- runtime/provider budget。

HTTP 可映射 RFC 9457-compatible problem details；WSS/control 使用同一稳定 domain code。

#### Web UX

- 删除 createRoom catch-all；
- 本地已知 issues 一次性列出；
- server issue 安全映射到中文；
- 已知修正方式时给建议；
- 可定位时提供“去处理”；
- 技术 code/ID 收进“技术详情”。

#### Terminology pass

至少清理：

- Proposal -> 提案/配置提案；
- typed diff -> 配置变更明细；
- BASE/CURRENT/PROPOSED -> 提案基准/当前房间值/建议值；
- revision -> 房间配置版本；
- same-target conflict -> 与当前房间修改冲突；
- incarnation/epoch -> 产品化重同步提示；
- host-local -> 房主本地内容；
- working copy -> 本地编辑内容。

### Accessibility

按 WCAG 2.2 3.3.1/3.3.3：

- 错误必须有文本；
- 明确错误对象；
- 已知时给修正建议；
- aria-live/alert/focus 行为与现有 modal a11y 基线一致。

### Security

- 不把 call stack、internal key/path、secret、private object existence 暴露给无权用户；
- detailed server logs 与 user-facing problem 分离。

## 9. GMR-10Q-F：默认单人一致性与叙事历史审计

状态：`BLOCKED_BY_A`

### Objective

把“规格未声明例外 -> 多人继承单人”从原则落实为测试 gate，避免未来再出现无意能力缩水。

### Scope

扩展 product parity coverage：

- generation semantic；
- editor capability；
- validation gate；
- capacity/limit source；
- error/terminology；
- history/current-state/narrative-history；
- order/reordering semantics；
- questionnaire/lore/adjudication deferred items。

### Narrative history audit

明确并测试：

- read/write 开关与 limit/unlimited 的单人语义；
- host 多人 generation 如何读取 host-local narrative history；
- Room 中只同步何种安全选择；
- result write 在 host/member 客户端的实际行为；
- 正文不因 parity 而广播；
- 任何差异都有 privacy/authority reason。

### Deferred policy

`deferred-with-reason` 不得无限期充当“多人不支持”的默认桶。

每个 deferred 至少要有：

- reason；
- 安全/架构前置；
- future trigger/next condition；
- 测试保证 UI 不假装支持后静默丢失。

## 10. GMR-10Q-G：综合验证与退出审计

状态：`BLOCKED_BY_B_C_D_E_F`

### Mandatory golden flows

#### Flow 1：先建房后配置

```text
host Arena = empty roster
-> create room succeeds
-> member joins
-> host adds unsigned custom character
-> update room config
-> member sees safe stub/ref
-> host starts generation
-> one authoritative result fan-out
```

#### Flow 2：limit parity

```text
11~32 combatants
-> room share succeeds if frame fits
-> generation follows canonical runtime budget
33 combatants
-> room may exist
-> start/preflight gives explicit 32-limit remediation
```

#### Flow 3：shareability vs readiness

```text
room exists
-> generation-only problem does not destroy/block room
-> publish-only problem blocks publish with target-specific issue
-> fixing issue allows publish
-> readiness then independently evaluated
```

#### Flow 4：error UX

逐一触发至少 8 类不同错误，证明：

- stable distinct code；
- Chinese actionable message；
- no catch-all；
- no secret/internal leakage；
- keyboard/screen-reader notification correct。

### Verification

至少执行：

- contracts tests；
- multiplayer-core tests；
- Web targeted interaction/a11y tests；
- API room/materializer/state-machine tests；
- loopback Redis room/generation verifier；
- package lint/typecheck/build；
- workspace `pnpm ci:verify`；
- product parity/gate readiness checker；
- `git diff --check`。

### Independent review

至少覆盖：

- product/UX；
- architecture/package boundaries；
- authorization/security/privacy；
- resource/DoS ceilings；
- failure/idempotency/recovery；
- accessibility/i18n；
- test sufficiency。

Critical/Important 必须为 0；Minor 若 deferred 必须有明确理由且不影响本规格 Done。

## 12. 实施时允许 Agent 自主决定的细节

无需再次向产品侧确认，Agent 可在调研、测试和 package boundary 审查后自主选择：

- canonical capability 常量具体落在哪个 dependency-neutral module；
- error domain 类型的具体 TypeScript 名称；
- create 携带 optional seed 还是 create 后紧接 publish；
- local issue aggregator 的模块拆分；
- UI “技术详情”具体组件形态；
- `isValid` 是渐进 rename 还是先新增明确字段并兼容旧字段；
- gate checker 是扩展现有 parity checker 还是新增一个窄 checker。

但不得自行改变以下已冻结产品结论：

- 0 角色可以创建房间；
- generation start 才要求至少 1 个角色；
- 普通多人不要求角色具有项目原生签名；
- multiplayer 不继续保留无证据的 10/10/10 数量限制；
- 角色当前目标上限与 runtime 32 对齐；
- aux/material 优先服从 canonical cumulative reference budget + serialized byte ceiling；
- 多人未特别规定之处默认继承单人 Arena；
- Proposal 等技术术语不应作为普通用户主文案；
- 真正的 privacy/authority/exact-ref/resource hard gates继续 fail closed。

## 13. 退出条件
