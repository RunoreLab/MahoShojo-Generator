# 生产部署切流前最后收口实施计划

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** 关闭当前分支合入默认分支前已由生产只读证据确认的 Hono 数据写入、日志安全与可回滚发布缺口，并明确区分仓库内可完成事项与需要外部授权的 stable control plane/管理面动作。

**Architecture:** 保持现有 Hono primary、Next/OpenNext DR、D1 Gateway 与 content-addressed release tuple 边界不变。战报角色明细按 D1 每语句最多 100 个绑定参数拆成不超过 7 行的语句，并通过同一次 D1 `batch()` 保持原子性；错误只向日志和持久化状态投影固定低基数代码。发布侧把 Node runtime digest 纳入 release-local Compose/deploy preflight，并在触碰 Docker 前校验 `.env.hono` 的 owner/mode。

**Tech Stack:** TypeScript、Vitest、Drizzle ORM/D1、Hono、POSIX shell、Docker Compose、GitHub Actions、Cloudflare Workers/D1。

## 当前证据与边界

- 2026-08-27 生产只读检查中，Hono `/api/health/ready` 的 Redis 与 D1 均为 ready；容器仅绑定 `127.0.0.1:8080`，重启策略为 `unless-stopped`。
- 最近 24 小时日志出现 106 次 `too many SQL variables`。失败 SQL 每行有 14 个绑定参数，9 行会产生 126 个参数并超过 D1 的 100 参数上限。
- 同一失败对象把 SQL 参数和用户内容带入日志；当前分支已有 AI runtime 固定低基数 logger，但战报角色明细 wrapper 仍把原始 Drizzle error/message 继续写入日志和 parent generation 状态。
- 生产仍是旧 root/legacy release 布局；当前分支的首次 content-addressed tuple 发布会负责纳管旧布局，尚未执行生产发布。
- `api.mahoshojo.colanns.me` 当前无 DNS；manifest 仍为 `provisioning=not-provisioned`、fallback `deferred`。因此 Cloudflare production build 会按 accepted gate 拒绝构建。这是外部控制面授权点，不得通过放宽 guard 绕过。
- `homura-admin.colanns.me` 当前直接返回 Arcane `200`，仓库/服务器 Caddy 未证明 Cloudflare Access；这是 Docker 控制面保护的外部授权点。
