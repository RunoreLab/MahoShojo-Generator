状态：源码与合成验收完成；[验收报告](../reports/2026-10-10_103200_DesktopHostedArena固定Next角色更新验收.md)记录独审及同源完整本地 CI。未生产部署、真实生成或更新

## 当前事实与范围

唯一阶段计划仍为 [Desktop 客户端阶段实施计划](./2026-09-30_160100_Desktop客户端阶段实施计划.md)。本片承接 C1/C2 普通单次 `/battle`、`/arena` 的 SSE / 完整非流报告。C1/C2 历史基线的 Native 和共享创建 schema 强制两个角色写开关为 false；Next 既有 `update-combatants-after-stream` 从 D1 检查 generation owner、完成终态及冻结效果清单，并在服务端验签、应用效果及重签。本片接通这条既有权威链，不新增模型调用或第二套角色匹配规则。

维护者已明确同意：原匿名生成恢复令牌仅由 Native 发送到固定 `https://mahoshojo.colanns.me/api/arena/update-combatants-after-stream`，用于验证同一生成归属。此授权仅产品代码与合成凭据，不授权读取真实凭据、真实账号/模型请求、生产更新或部署。

## 有界协议

- 角色更新协议为 `arena-reconciliation-v1`；固定 header `X-Mahoshojo-Arena-Reconciliation-Protocol`。Next 同一路径公开无凭据 GET 返回自身能力 `{ok:true,contractVersion,expectedUserIdAssertion:'v1',ownership:'generation-actor',effects:'frozen-manifest-v1'}`，只在自身 D1 与签名能力就绪时声明。Native 验证 Next；Hono readiness 不代替该证明。POST 也独立检查版本；没有该 header 的 Web 请求和响应保持兼容。
- 新 Desktop 创建显式带 `reconciliationVersion`，仅任一角色写开关为 true 时才要求创建前 Next 能力就绪；两者 false 仍可按原 Hono 生成纯报告，仅该版本允许冻结创建时用户选择的 `writeArenaHistory` / `writeCurrentState`。新恢复 pointer v3 同时冻结 delivery、原 actor、两个选择和协议。旧 C1/v1、C2/v2 保持 false，禁止恢复时追开权限。权威始终来自服务端原 generation 冻结值；本机 pointer 不是授权证据。
- 新 C2 完整报告任一写选择为 true 时，Native 还要求 Hono readiness 的同名 reconciliation 版本 header，并在 create-json POST 携带此 header。已安装 companion 服务必须自行声明该能力；旧 companion-v1 无新 header 仍严格要求 false/false。新 opt-in 只将选择交由原 generation finalization 冻结，完整报告/metadata/impacts 保留、updatedCombatants 仍为空；签名角色只由后续 Next 产生，不放大 C2 报告封套。
- Native 新窄操作 `reconcile` 只接受原 product/requestId/actor/generationId 与当前可读角色投影；无 URL、header、ProviderKey 或资金配置入口。经原 flight/原凭据绑定，登录态冻结 expectedUserId 并 fail closed，匿名不附加当前登录 cookie、不回退另一个匿名 actor。HTTP redirect 禁止，令牌不出 Native。
- Next opt-in 正常响应封套包含 version、generationId、success、updatedCombatants、warnings；每个更新按本次提交的可读角色下标映射；Native/TS 应用前拒绝重复、越界或非整数下标，并核对版本与 generationId。输入 12 MiB、32 角色沿 `arena-capabilities` 及既有 Desktop body；独立角色响应 16 MiB 是接收预算，不是所有合法输入的上界（开放 JSON 历史 id 可被旧 producer 的 `lastEntryId + 1` 复制放大）。超过预算只返回同步不可用，不截角色数据。Native/TS 完整检查后才提交，通过既有 64 KiB 文本片与 512 KiB IPC 封套预算传递。超过限制不截断角色，不修改已有 C2 完整报告预算。
- 服务端 effects manifest 64 KiB 不可用或终结尚待落库时，报告仍完成，角色同步单独明确失败/不可用。原卡与报告原件保留；仅按原 generation 重试 reconciliation，不重新生成、不补模型请求。

## 宿主生命周期与信任

- 复用现有 generation session、账号/凭据 epoch、原恢复/停止链，不发明 generation 状态机。角色同步有单一 flight 防重复，提交前后核对原报告、账号与当前角色快照；重排/编辑、关闭、换任务和晚响应不得覆盖新状态。
- SSE done / JSON end 可能早于 Native 调用返回与订阅 guard 释放；自动同步必须等待原创建/恢复 invoke 真正 settle，角色结果也须等待本次 invoke 成功才发布。即使已收到完整 JSON end，Native 后续 scope-changed/detached/传输拒绝仍令同步失败，不提升为签名可信结果。
- 新完成报告在原作用域内可按冻结选项同步；显式恢复报告后可显式同步新任务原权限。两个开关均关闭及旧任务不申请补开。停止生成沿现有服务端规则；停止本机角色接收不声称已撤销服务器响应。
- Web/Desktop 共用宿主无关 retry payload 和 response application 纯核，Web cookie/服务端匹配及 Native transport 留各宿主。
- 只有本次新鲜受检服务端响应可以形成官方签名证据。草稿/导入恢复数据中的 signature 只能标记未验证；不因已保存的 isValid 或 signature 字段重建官方证据。
- 更新只改活动工作副本；显式保存新本地卡，不覆盖源库卡。报告、角色同步与本地保存失败分别表达，签名信任和库容量保持既有边界。
