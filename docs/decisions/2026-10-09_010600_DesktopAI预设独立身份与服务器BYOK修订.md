## 取代关系与保留边界

本修订精确替代原 ADR 决策 2、4、5 中“预设必须保存为 Profile 才可生成”和“服务器 BYOK 延期”的限制，并替代 DESK-AIP-002/003 的相应预设身份/生成流程、DESK-AIP-005 的新模型输入上限及 AIP-6 的延期要求。既有实现记录保留历史含义，不改写成新方案已交付。

其余 SecretStore、原生可信出站、Strict/多人授权、签名真实性、取消、幂等、防重复派发、配置损坏 fail-closed、Web 安全与无损兼容规则继续有效。客户端自定义连接不变成任意服务器代理。此次不授权生产部署或任何真实用户凭据变更。

## AIP-R2-001：执行位置与目标身份

ProviderTarget 为显式 system / preset(providerId) / custom(profileId) 联合类型，执行位置独立保存。合法组合为客户端 preset/custom、服务器 system/preset。客户端不能执行 system；服务器不能执行 custom。

内置供应商是稳定预设身份，选中即消费项目目录中的模型；录入 Key 不创建 conn_* Profile。仅用户主动新建或复制为自定义连接才产生 Profile。旧 DirectProviderProfileV1 保留，不按相同 URL/名称自动认领预设。两个执行位置的选择独立记忆，切换不得清空对方目标、模型或参数。

预设端点、协议和受支持模型能力由现有 ai-core 目录单一事实源派生受检原生清单，生成脚本的 check 模式防漂移。Rust 独立按 providerId 查目录并校验 adapter/wire，拒绝 renderer 端点、未核验协议、已下架预设或不满足模型限定的请求。

## AIP-R2-002：Key 与生成旅程

选择预设、模型，填写或使用本机已保存 Key 后直接点击生成。尚未保存的 Key 仅驻留易失表单；生成前完成 SecretStore 写入及存在性验证，成功后继续一次生成，不必先建连接。设置提供同一预设的状态、更换、清除，不读回明文。

准备过程捕获目标/模型/输入及状态世代，禁止重复点击形成第二次保存或派发。旧异步结果不能在用户切换后激活另一目标；切换执行位置/供应商有未保存 Key 时提供明确保留/放弃处理。凭据写入或读取验证失败保留可重试输入、正确报告部分成功，不虚报可生成。

Native 在任何网络 await 前捕获真实执行目标及 Key，后续替换不得改变在途请求 Header。安全写入、派发准备与取消继续复用既有事务和请求登记机制，不为 UI 重构另建凭据版本数据库。空 Key 保持旧 Key 与显式清除是不同操作；合法无需 Key 的本机自定义服务保持可用。

## AIP-R2-003：固定入口服务器 BYOK

Desktop Hosted 增加与 systemConfig 互斥的受检预设配置，仅包含 providerId、modelId 与允许的生成参数。renderer 不携带 apiKey、secretRef、任意 Endpoint 或 customProvider。Native 从已确认预设安全存储取得 Key，注入与 Web 相同的服务端 BYOK 请求形状，通过既有固定 routeId/origin 发送。

服务器继续独立按可信供应商目录解析目的地；未知/下架供应商、任意 URL、额外请求字段 fail-closed。重定向不得把鉴权凭据转交目录外地址。请求日志、错误、审计和调试输出不得包含 Key 或完整敏感请求体。系统默认不要求 Key，不能因 BYOK 新增而退化。

服务器 BYOK 仍意味着 Key 会提供给项目生成服务并由该服务调用选定供应商；UI 的必要接收方披露须简洁准确。删除冗长的“服务器·云端”实现说明不等于隐瞒该传输边界。签名标签只根据实际服务许可与响应证明，不由执行位置或选用预设推断。

## AIP-R2-004：模型 ID 与旧配置

新手填模型 ID 共源规范化：trim、非空、最多 200 个与 Web 一致的字符串计数单位、拒绝控制字符，不要求先在设置登记。当前模型能力未知时诚实显示未知，协议或目录模型限定仍不能绕过。

既有合法 201–256 字符自定义 Profile/模型偏好必须可读、无损迁移并维持旧 Direct 执行兼容；不得截断、改名、删除或改选。新建/改填路径应用 200 上限；不借迁移向服务器 BYOK 放开旧长 ID。参数以带类型目标身份和模型隔离，避免 presetId 与 profileId 撞名。

升级现有 overlay，保留旧连接/模型/参数及悬空目标诊断；迁移整体受检并在持久化成功后发布。未知版本或损坏文档不自动重置，Secret 不进入 overlay/普通草稿。历史实现记录和旧 Profile 原文不重写。

## AIP-R2-005：先修 IPC，再验完整旅程

Profile 命令的 document 输入与读取输出必须遵循真实 Rust String / Option<String>：TS 写入/前置校验先 JSON 序列化，读取先 JSON 解析再 schema 校验。可选字段回显规则两端一致。测试引用实际命令签名及双向 wire 夹具，不让 mock 自行规定协议。

错误保留安全的命令名和类别，字符串/参数反序列化失败不能统一伪装成 store-failure；不得直接展示含凭据的原始异常。

按原子切片验证：IPC → 可信目标及迁移 → 预设 UI 与即时模型 → 固定 BYOK → 五页回归。五页覆盖 Direct / Hosted system / Hosted BYOK 以及页面真实支持的流式/非流式，不虚构 Direct 流式产物。异常覆盖 SecretStore 不可用、目录下架、损坏配置、模型协议不兼容、保存后读失败、未存 Key 切换、在途更换凭据及重复生成。

先本地模拟与可控假凭据协议测试，再真实 Tauri 的创建→保存→读取→重启恢复→选择→生成。真实环境缺失时明确区分自动测试与未完成实机验收，不用 mock 或源码检查冒称完成；真实外部 Provider 验证按授权及免费优先原则另行记录。
