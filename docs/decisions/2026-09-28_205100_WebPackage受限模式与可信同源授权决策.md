# Web Package 受限模式与可信同源授权决策

状态：`accepted`

日期：2026-09-28

决策标识：`ADR-web-package-trusted-same-origin-v1`

适用范围：Arena Web 包的浏览器执行权限、本地安全预检、用户授权与当前域名下的资源解析策略。

本 ADR 修订并覆盖下列旧口径中与 `allow-same-origin` 冲突的部分：

- `2026-09-22_142300_WebExperiencePackage上位抽象与单文件Overlay决策.md` §5；
- `2026-09-22_142300_WebExperiencePackageV1架构规格.md` §21；
- `2026-09-22_165900_WebPackage统一架构与后续开发规格.md` 中“Web 包不得使用 `allow-same-origin`”的绝对表述。

其它 Package identity、Prompt Projection、immutable Base + single-file Overlay、history provenance、source/resolver seam 等既有结论不变。

---

## 1. 背景

Web Package V1 已经具备：

- 标准 `web-package.json`；
- builtin / local 的统一 package identity；
- 本地 ZIP 导入与完整性验证；
- session staging / IndexedDB best-effort cache；
- Prompt Projection；
- 单文件 Overlay；
- exact / explicit compatibility replay；
- transport-neutral resource-space contract。

当前 generic renderer 的主要缺口是浏览器中的真实相对资源空间。既有实验已经确认：

- `sandbox="allow-scripts"` 且无 `allow-same-origin` 时，opaque iframe 与当前 Service Worker URL mount 组合不能可靠提供 generic package resource space；
- first-party `srcdoc` materializer 只能作为过渡适配器，不能成为任意用户 Web 包的通用语义；
- 立刻为 Web 包增加独立 sandbox subdomain 会增加部署、CSP、运维与迁移成本，当前尚无线上第三方包生态要求必须立即承担这项复杂度。

同时，用户明确接受一种更自由的 power-user 模型：默认仍以受限权限运行；对于自己制作、审查过或完全信任来源的 Web 包，可以在更强风险提示后显式授予同源权限。

---

## 2. 决策

### 2.1 V1 暂时继续使用当前站点域名

本阶段不新增专用 Web Package subdomain。

独立 subdomain / sandbox origin 继续保留为未来 transport 选项，尤其适用于：

- 第三方线上 Web 包库；
- 大规模公开作者生态；
- 希望缩小宿主 origin 爆炸半径时。

Package contract MUST NOT 绑定当前同域实现，因此未来迁移 origin 不得要求改写 manifest、package digest、Overlay 或 history artifact。

### 2.2 Web 包具有两个执行等级

默认等级为：

```text
Restricted Mode
sandbox="allow-scripts"
no allow-same-origin
```

可选高权限等级为：

```text
Trusted Same-Origin Mode
sandbox="allow-scripts allow-same-origin"
```

Trusted Same-Origin MUST 是用户针对风险明确授权后的额外权限，不得因为：

- 选择了 Web 包；
- 包声明 scripts；
- renderer 需要加载相对资源；
- builtin / local source kind；

而自动开启。

### 2.3 Same-Origin Permission 不是 transport dependency

这是本 ADR 的核心不变量：

> **拒绝 `allow-same-origin` 不得让本来可以在受限模式工作的 Web 包失去导入、生成、Overlay、历史、下载或受限执行能力。**

因此 generic Package Resource Resolver 必须把“如何加载包内资源”和“是否授予宿主同源权限”分离。

实现不得形成：

```text
为了让相对 JS / CSS / image 能加载
→ 所有 Web 包都必须 allow-same-origin
```

Restricted Mode 是 baseline。Trusted Same-Origin 只用于 Web 包主动依赖的额外同源能力。

某些 Web 包如果明确依赖宿主 origin 的 DOM / storage / authenticated API，用户拒绝该权限后其相关功能 MAY 降级或不可用；Host 应明确提示，而不是把整个 Package 判为导入失败或生成失败。

### 2.4 Trusted Same-Origin 按“第一方脚本执行”建模

在当前域名下，同时授予 scripts + same-origin 后，不再把 iframe sandbox 视为可靠的宿主隔离边界。

威胁模型按以下上限设计：

> **Trusted Same-Origin Web Package 近似于用户主动授权在当前站点 origin 内执行一段第一方 JavaScript / XSS 等级代码。**

它可能访问或影响：

- parent / top DOM；
- localStorage / sessionStorage / IndexedDB；
- 当前 origin 下可被脚本访问的认证数据；
- 同源 API；
- 页面状态与 UI；
- 当前用户有权执行的站内操作。

安全预检、CSP、Permissions Policy 与风险提示都属于 defense-in-depth，不得描述为能够证明 Web 包安全或重新建立强隔离。

## 3. 本地安全预检

### 3.1 预检是风险发现，不是安全认证

UI MUST 使用“安全预检”“风险扫描”“检测到的能力”等措辞。Base Package 扫描在浏览器本地完成，本地 ZIP bytes 不得为了预检上传服务器。

不得输出：

```text
安全
已认证安全
无风险
```

作为静态扫描结论。

混淆、动态执行、WASM、运行时拼接、间接调用与 Runtime 对数据的解释都可能绕过静态分析。

### 3.2 两阶段扫描

预检至少分为：

```text
Base Package Scan
        +
Generated Target Scan
        ↓
Effective Risk Profile
```

导入时扫描 immutable Base Package。

authoritative final 形成 Overlay 后，再扫描 generated target。

Trusted Same-Origin 的授权判断必须基于本次 Effective Risk Profile，而不能只依据 manifest 或 Base Package。

### 3.3 初始风险类别

V1 SHOULD 至少识别并展示：

- scripts / executable content；
- external network：`fetch`、XHR、WebSocket、EventSource、Beacon、外部 URL 等；
- host-page access：`parent`、`top`、`opener`、`frameElement` 等；
- site storage：localStorage、sessionStorage、IndexedDB、cookie、BroadcastChannel 等；
- dynamic execution：eval、Function、dynamic import、WASM、blob/data script 等；
- workers / background execution；
- Service Worker；
- navigation / popup / download；
- sensitive browser APIs：clipboard、camera、microphone、geolocation、notification 等。

Manifest `capabilities` 是作者声明；scanner findings 是宿主观察。二者 MAY 同时展示：

```text
作者声明
静态扫描检测到
未声明但检测到
```

capability declaration 继续不是权限授予。

### 3.4 AI 生成目标的不确定性

Generated target 可能改变 Effective Risk Profile。

UI MUST 明确区分：

- Base Package 已知能力；
- generated target 检测出的能力；
- 无法从静态扫描确定的部分。

至少：

- HTML / JavaScript / CSS / SVG 等可执行或可加载资源型 target MUST 标记“生成内容可能改变实际能力”；
- JSON / text / Markdown 等 target 也不得标记为“能力固定”，因为 Runtime 可能把其中字段解释为 URL、HTML、脚本片段或其它行为数据；
- schema 约束与 data-only 约定可以降低不确定性，但 V1 不因此宣称绝对安全。

每次 authoritative final 都应重新计算 generated-target findings。

## 4. Trusted Same-Origin 授权

### 4.1 与普通 Web consent 分离

现有普通 Web 执行授权只表示允许：

```text
sandbox="allow-scripts"
```

Trusted Same-Origin 必须使用独立 consent version / storage key / UI。

不得因为用户已经允许普通 Web 战报执行，而自动授予 same-origin。

### 4.2 风险说明必须更详细

授权界面必须明确说明：

- Web 包将以魔法少女生成器站点的同源权限运行；
- 它可能读取或修改本站浏览器存储；
- 它可能与宿主页面交互；
- 它可能以用户当前登录状态调用站内功能；
- 它可能把可访问数据发送到网络；
- 只有自己制作、审查过，或完全信任来源时才应授权。

当前 Effective Risk Profile 应在确认区域可见，不得只隐藏在二级说明中。

### 4.3 3 秒阅读门槛

首次授予 Trusted Same-Origin，或风险档案发生需要重新授权的扩大时：

- confirm action MUST 至少禁用 3 秒，计时从 Effective Risk Profile 已经渲染并可阅读后开始；切换 package / generated overlay / risk profile 后重新计时；
- “始终信任”默认不得勾选；
- 取消应立即回到 Restricted Mode；
- 不要求输入确认短语，避免过度设计。

倒计时只降低误触和条件反射式确认，不作为安全边界。

### 4.4 授权与 digest 绑定

V1 的 Trusted Same-Origin 授权状态 SHOULD 仅保存在当前浏览器本地，不做账号级跨设备同步。

授权不得只绑定 package id / version。

至少绑定：

```text
packageDigest
consentPolicyVersion
```

“仅本次允许” SHOULD 进一步绑定本次：

```text
generatedDigest
```

持久“始终信任此 Web 包版本” MAY 跨 generation 复用，但每次仍必须重新完成 generated-target scan。

### 4.5 风险扩大重新确认

持久授权应记录用户已接受的风险类别集合或等价 risk-profile version。

新的 authoritative Overlay 如果出现此前未接受的高风险类别，MUST 再次确认。

例如：

```text
已接受：
scripts
audio

新结果：
scripts
audio
external-network
host-page-access

→ 重新授权
```

scanner / consent policy 若发生会实质改变风险判断的版本升级，也 SHOULD 让既有授权失效或重新确认。

---

## 5. 拒绝授权后的行为

用户拒绝 Trusted Same-Origin：

- MUST NOT 删除或取消选择 Web 包；
- MUST NOT 阻止 generation；
- MUST NOT 使合法 Overlay 失效；
- MUST NOT 影响 target / ZIP 下载；
- MUST NOT 影响 history provenance；
- MUST NOT 阻止 Restricted Mode 下仍然可执行的 Web 包；
- MAY 使依赖同源宿主能力的特定功能降级。

UI 应显示类似：

> 当前以受限模式运行；此 Web 包的部分同源功能未获授权，因此可能不可用。

而不是：

> Web 包无法使用。

## 6. V1 额外安全边界

### 6.1 Service Worker

用户 Web Package V1 不提供注册 Service Worker 的产品能力。

安全预检 MUST 将相关行为标记为高风险。

Host SHOULD 通过可行的 CSP / resource host policy / namespace 限制避免用户包获得超出实例范围的持久 Service Worker 控制。

Host 自己为 Package Resource Resolver 使用 Service Worker 不受此条限制，但必须由宿主代码控制，不能把 registration authority 交给 Package。

### 6.2 Sensitive browser APIs

Host SHOULD 使用 iframe allow / Permissions Policy 等机制默认拒绝当前 Web Package 产品并不需要的敏感浏览器权限，例如 camera、microphone、geolocation 等。

授予 same-origin 本身不得自动授予这些能力。

### 6.3 服务器继续把浏览器视为不可信客户端

Trusted Same-Origin 不改变服务器 authorization。

服务端 API 继续必须独立执行：

- authentication；
- object-level authorization；
- role / owner 检查；
- quota / rate limit；
- mutation safety；
- idempotency / duplicate-dispatch protection（适用处）。

Web Package 用户确认不能作为服务器放宽鉴权的依据。

## 7. 爆炸半径

### Restricted Mode

主要风险限制在：

- iframe 内脚本；
- 包允许的外部网络；
- 页面卡死 / 高资源占用；
- 欺骗性内容；
- renderer / browser bug。

其设计目标仍是隔离宿主 DOM 与 host storage。

### Trusted Same-Origin Mode

客户端爆炸半径扩大到当前站点 origin。

当前实现中认证状态仍有 JavaScript-readable browser storage，因此恶意同源代码理论上可能读取可访问凭据并在页面关闭后继续造成账户级风险。

服务端爆炸半径原则上不应超过：

> 当前用户账号经公开 Web API 已被授予的 authority 与可消耗的平台资源。

未来将长期 bearer secret 迁移到 HttpOnly / Secure session 可降低“凭据被外传后长期复用”的风险，但不能阻止同源恶意脚本在当前会话内代表用户操作；该认证改造不是本 ADR 的交付 blocker。

---

## 8. 实施与迁移

本 ADR 不要求在同一个提交中立即启用 Trusted Same-Origin。

推荐顺序：

1. generic Restricted Mode resource resolver；
2. Base Package capability preflight；
3. generated target postflight / Effective Risk Profile；
4. 独立 Trusted Same-Origin consent UI 与本地授权存储；
5. same-origin renderer transport / execution mode；
6. browser matrix 与风险升级回归测试。

当前 first-party `srcdoc` adapter 可继续作为过渡路径，直到 generic restricted resolver 完成。

未来若迁移到专用 subdomain：

- Package identity 不变；
- manifest 不变；
- Overlay 不变；
- Prompt Projection 不变；
- history artifact 不变；
- risk scanner 与 consent model MAY 继续复用；
- 仅 renderer transport / origin policy 改变。

---

## 9. 延后事项

本轮不因为 Trusted Same-Origin 决策而提前建设：

- online Web Package library；
- local package multiplayer distribution；
- Host Bridge；
- filesystem bridge；
- arbitrary patch；
- multi-target generation；
- package dependency graph；
- npm / bundler / WebContainer；
- 独立 sandbox subdomain。

线上第三方 Web Package 是否允许 Trusted Same-Origin 必须在 online library 设计阶段重新评估，不得由本 ADR 自动授权。
