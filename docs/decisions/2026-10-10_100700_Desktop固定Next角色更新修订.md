# ADR：Desktop 固定 Next 角色更新修订

- 日期：2026-10-10
- 状态：accepted（维护者明确批准代码方案与合成凭据验证；不等于生产部署或实机通过）
- 决策标识：ADR-desktop-arena-reconciliation
- 范围：普通单次 `/battle`、`/arena` 的新 Hosted 任务

## 精确取代关系

本后继精确替代 DESK-095/096 对未来新任务的“角色写入固定 false”和“不授权新凭据目的地”限制。原 C1/v1、C2/v2 已创建任务及其 frozen policy 完全保留，不重写历史验收。固定 Hono 仍是唯一生成/查找/恢复/停止目的地；独立 Next reconciliation 不是生成 fallback、DR 接管或任意域代理。

## 决策

1. Native 可将原匿名任务已签发的恢复 token 或原账号 cookie 发送到固定 `https://mahoshojo.colanns.me/api/arena/update-combatants-after-stream`。只验证原生成归属与应用其冻结效果，无 ProviderKey、无 renderer URL/header、无当前身份回退；禁止 HTTP redirect。缺已签发匿名 token 时只可通过原 Hono request lookup 找回，否则不可用；Next 不新签发匿名 actor。
2. Next 的无凭据 GET 提供自身版本/能力证明，POST 必须独立验证版本、真实 expectedUserId/actor、D1 generation owner、完成终态与冻结 manifest。GET 不证明两 runtime 数据库一致；POST 的任务不存在/归属不符必须如实失败。
3. 新 create 显式 opt-in 并冻结两个用户写入选择；C2 写 true 还需 Hono companion 服务声明并接收 reconciliation 版本 header，仍仅交付完整报告与空 updatedCombatants，签名角色走独立 Next。旧无新 header 的 C2 保持 false-only；原两个 public pointer 键引入可判别 v3 双读，旧任务不自动迁移权限。Native 原两个秘密槽不增键，公开 pointer 不构成权限证据。
4. 共用 Web 角色重试投影、响应下标应用和结果展示，宿主只提供身份、HTTP、作用域与保存。报告完成、角色同步与本地保存分别表达；同步失败只重试已有 generation，不再次请求模型。
5. 32 角色与 12 MiB 请求沿当前 Arena canonical 资源门禁；16 MiB 为独立角色响应接收预算，并非所有合法输入的理论上界。超预算时保报告/原卡、明确同步不可用，不截断不扩容。effects manifest 64 KiB 门禁不变。后继[历战新增编号修复](../reports/2026-10-10_111500_历战新增编号共源与容量证据修正.md)已去除旧字符串 ID 复制放大；当前 producer 保真与合成传输边界证据分层，不改变此独立接收预算。
6. 官方签名证据仅来自本次受检新鲜服务端响应；本机草稿/导入仅可标记签名未验证。源库卡不覆盖，更新工作副本和新卡另存分别操作。
