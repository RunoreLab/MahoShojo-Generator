更新时间：2026-08-22

`docs/decisions/` 用来保存稳定单点决策。每份 ADR 应聚焦一个决定，适合作为稳定链接长期引用，并在被替代时留下取代关系。

## 状态约定

- `proposed`：已提出，尚未成为稳定口径。
- `accepted`：当前采用，可作为稳定引用地址。
- `superseded`：已被新 ADR 取代，仍保留历史价值。
- `deprecated`：不再建议新增依赖，但可能因兼容要求暂时存在。

## 每份 ADR 建议结构

1. 状态、日期和决策标识。
2. 背景。
3. 决定。
4. 影响。
5. 不采用的方案。
6. 关联文档。

## 与其他目录的关系

- `topics/` 汇总主题相关 ADR。
- `architecture/` 描述多个 ADR 组合后的目标系统。
- `specs/` 把 ADR 转换成可测试要求。
- `plans/` 安排实现顺序、门禁与回滚。
- `reports/` 保留推演过程和历史对比。
