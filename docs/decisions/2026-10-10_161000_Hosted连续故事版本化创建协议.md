- 决策标识：`ADR-hosted-arena-story-create-v1`
- 范围：现有 Hono `POST /api/arena/session/generate-next` 的显式版本化首章/线性续章创建
- 规范：[DESK-098](../specs/2026-09-30_160000_Desktop客户端实施规格.md#desk-098-hosted-连续故事版本化创建前置协议2026-10-10)
- 唯一实施入口：[Desktop 客户端阶段实施计划](../plans/2026-09-30_160100_Desktop客户端阶段实施计划.md#2026-10-10-hosted-连续故事版本化创建前置源码候选)

规范性词汇沿用 RFC 2119 / RFC 8174。本次只接受服务端协议前置片；状态不表示 Desktop 已可创建 Hosted 连续故事，也不表示真实模型、账号或 Windows/Tauri 已验收。

2026-10-10 窄后继：[Native 传输与创建围栏 ADR](./2026-10-10_180600_Hosted连续故事Native传输与创建围栏决策.md) / DESK-100 已另行接受同一 Native command 的故事 create/reconcile、耐久 claim 与同槽准入；其实现与验证仍为 PENDING。下文“不含 Native/存储/角色接线”继续记录本服务器前置片的范围，不能用于否定后继许可，也不改写本片历史验收；两页 owner/UI 与完整故事旅程仍未获本片开放。

## 1. 背景与精确修订范围

既有 Web 连续故事通过同一 Hono companion 入口提交 `recentChapters`，由服务端共源构造 Prompt、签名 internal guidance 并调用原 Arena generation；旧包装额外产出 `session_meta` / `chapter_digest`。Desktop Direct 已有共源章节窗口、Prompt、设备存储与线性故事候选，但普通单次 Hosted command 不能据此取得连续故事权限。

新协议需要将首章/续章身份纳入同一可恢复 generation 的语义指纹，并直接使用其原事件与 cursor，避免客户端把摘要投影冒充完整正文交给旧包装再次投影。只改变显式 opt-in 请求，不迁移旧 Web。

本 ADR 对 DESK-095 的“仅普通单次”作作用域澄清：该限制继续约束其已列举的 Native command 和客户端权限；本片仅允许服务器原路由新增版本化分支，**不授权未来 Native 新 command、IPC、ACL 或 Desktop capability**。DESK-096 普通非流报告和 DESK-097 普通单次固定 Next reconciliation 均保留；不借它们的既有许可开放故事客户端。此前报告、验收和历史计划片段不重写。

## 2. 同路由、显式 opt-in、严格 DTO

新请求 **MUST** 同时携带 `X-Mahoshojo-Arena-Story-Protocol: arena-story-v1` 与 JSON `version: 1`。未知 header 值、未知版本、未知协议对象字段或不一致线性上下文 **MUST** 在 producer dispatch 前拒绝，不能默默降到旧 Web 分支。

机器可读事实源为 [`contracts/arena-story`](../../packages/contracts/src/arena-story.ts)。字段合同如下；不是另建一份可独立漂移的 schema：

| 字段 | v1 合同 |
| --- | --- |
| `version` | 必须精确为 `1` |
| `generationRequestId` | 必填，沿既有 Arena request ID 形状；稳定标识同一次用户创建意图 |
| `sessionId` | 必填，故事本地身份；`[A-Za-z0-9_-]`、1–128 字符 |
| `action` | 仅 `start` / `continue`；不接受 `branch` / `rewrite` |
| `chapterIndex` | 必填正安全整数；无计划故事不因此被限制为 20 章 |
| `sourceChapterId` | `start` 必须缺省；`continue` 必须等于窗口最后一章 ID；ID 同 `sessionId` 形状 |
| `chapterPlan` | 可选严格对象，仅 `totalChapters`，1–20；有计划时本章不得越界，不强制所有故事带计划 |
| `seed` | 受检普通四模式、输入资料、语言、篇幅与既有读写设置；不接受客户端内部 authority 或任意端点 |
| `chapterContext` | 严格对象：必填 `workingCombatants`、`recentWindow`，可选 `sessionSummary` |
| `userGuidance` | 可选原字符串；沿既有共源 Prompt 规则，不另加新 UTF-8 文本限额 |
| `customProvider` | 可选服务端 wire carrier，必须通过现有严格 system/preset resolver；不是 Desktop renderer 的凭据输入权限 |

`recentWindow` **MUST** 直接使用共享 `BattleStoryPromptWindowItem` 投影：每项严格包含 `chapterId`、`chapterIndex`、`title`、`mode: full | digest`、`text`、`truncated`；最多十二项、ID 不重复、章节索引递增。首章要求空窗口及 `chapterIndex: 1`；续章要求非空窗口，本章索引为末项索引加一。服务端 **MUST** 使用现有共享 Prompt 构造，不得把 `text` 填进伪 `recentChapters[].markdown` 后再截取或重造摘要。

协议对象、seed/settings、window item 的未知字段 fail closed；角色卡与资料的内部 JSON 仍由各自现有权威 schema 校验，不能用“strict DTO”借机丢弃原卡扩展或改变正文 Unicode 域。客户端声明的故事身份、前情与摘要都是业务输入，不构成服务器保存过该故事、已验证完整历史或授予角色权威的证明。

## 3. 可信 parsed command 与语义指纹

通过新 schema 和线性关系校验后，服务端 **MUST** 在进程内的可信 parsed command 中附带故事身份，供原 generation 的 semantic fingerprint 使用。身份至少绑定协议版本、`sessionId`、`action`、`chapterIndex` 与规范化后的 `sourceChapterId`（首章为 `null`）；原 `generationRequestId` / 实际 actor 绑定继续有效。

同 actor/request 的相同语义重入仍只取得原 generation；故事身份或生成语义改变则按原冲突处理，**MUST NOT** 因新建另一 session、修改 source 或改写章节索引而复用不相干的旧生成。没有故事身份的旧创建继续使用原 hash 输入与兼容规则，不能给所有旧请求添加 `null` story 字段而静默改变 hash。

故事身份 **MUST NOT** 从普通 HTTP header 或 JSON 中直接升级成可信内部标记。普通 generation 路由即使收到伪造 story header、内部字段或相同形状 JSON，也不能获得这条进程内入口的权限。DTO 通过只允许服务器构造指定业务请求；原 internal-guidance 签名校验、实际账号/匿名 actor 解析、expected-user 断言、系统及预设 BYOK 校验、限流、付费防重和 durable finalization 全部保持。

Provider Key、Cookie、匿名恢复 token 与内部签名不进入故事身份或 semantic fingerprint，不新增持久秘密、故事权限表或绕过鉴权的客户端旗标。是否可用仍由既有可信服务装配和运行时依赖决定。

## 4. 原 generation SSE 与兼容

新分支 **MUST** 交付原 generation SSE 事件及原 cursor/ID，保持原 generation/request 身份、匿名凭据响应和终态。**MUST NOT** 追加 `session_meta` 或 `chapter_digest`，不另造一套回放 cursor，也不在服务端为响应包装累计整章正文。

查找、状态、续流、停止继续走原 generation 操作，使用原 actor、request/generation 与 cursor。断线、首响应未知或恢复不完整不能自动再次 POST、重开模型、改向 Next/DR 或 Direct；该协议不是 response cache，不保证旧 replay 或正文永不失效。

**无 story header** 时，原 Web DTO、`recentChapters`、分支/重写、`session_meta` / `chapter_digest` 包装、hash 及现有本地保存行为全部保持。仅在 JSON 中加 `version` 不启用新协议；旧分支仍按原解析行为处理，不借本片收紧旧请求域。

## 5. 独立资源门禁

- 原始 wrapper JSON 请求和经服务器 Prompt/Provider 投影展开的上游完整 JSON **MUST** 分别受 `12 * 1024 * 1024 = 12,582,912 bytes` 的精确限制；含各自 JSON 转义/封套开销，不能将 wrapper 的长度冒充展开后的长度
- 超限 **MUST** 在 producer dispatch 前拒绝，不截文、不删角色或资料、不以伪正文缩减输入；解析/尺寸失败不创建第二次模型调用
- 最终 Prompt 继续沿原资金通道的 token 预算；不新增最终 Prompt UTF-8 字节上限，不把窗口投影、请求字节和 token 三者混成同一个额度
- 原 canonical 角色/资料数量、输出与 generation 资源门禁保持；此 12 MiB 是请求门禁，不是总内存、响应或 Desktop 128 MiB 本地保存保证

字节与 canonical 数量的事实源仍为 [`arena-capabilities`](../../packages/contracts/src/arena-capabilities.ts) 和 [`arena-generation/resource-budget`](../../packages/hosted-api/src/arena-generation/resource-budget.ts)，不新增第二套预算登记表。

## 6. Readiness 与部署

公开 Hono readiness 仅在 **原 ready 成功、实际 route/service 已装配此协议** 时，独立声明 `X-Mahoshojo-Arena-Story-Protocol: arena-story-v1`。Next、未装配的测试/替代 service、只有同名路由或仅导入常量的进程不能声明。旧 readiness body、`arenaHosted`、companion/reconciliation 能力保持各自语义。

该 header 是新建前的协议能力证明，不是授权凭据、模型可用保证或 Desktop 功能开关；本片不增加客户端探测接线。后继客户端只用它门禁**新故事创建**，缺失/不兼容时不得发新 POST；撤回 story 能力不能锁住原任务的 lookup/status/resume/stop。它不用于 placement 选择，不改变 Hono primary-only，也不引入 Next/DR fallback。

本地源码和合成服务验证不代表公开 Hono 已支持协议。需要用户后续部署 Hono 后，按实际 readiness 和生成操作分别核验；本片不部署、不改生产、不使用真实账号/Key/模型。

## 7. 后继与未决事项

本片不实现 Native/IPC/ACL、Desktop 两页 capability、两个非秘密 durable pending、Hosted 故事客户端 owner、角色同步或本地保存接线。后继必须分别处理生成结果未知、角色同步未知和本地保存未知；不得用本片的标准 SSE 宣称三种未知已解决。

故事角色同步失败后的保存/续章语义仍待独立裁定。本片不将它改成“失败即丢章”，也不预设“直接沿旧角色继续成功保存”；旧 Web 当前保存行为不改。DESK-097 的普通单次权威协议保持有效，但不能直接充当故事旅程已完成的证据。

不新增服务器故事库、session/chapter/checkpoint 表、response cache、额外模型调用、自动摘要、分支/重写/删除、Strict/多人或 D4 内容执行。实施与后继顺序只在唯一 Desktop 计划维护。

## 8. 候选验收边界

候选须覆盖：strict/version/header 与首章/续章关系；真实共享 window→Prompt；可信 parsed 身份与同 request 冲突；伪造 header/内部 JSON 不能授予 authority；旧 Web 包装/hash 不变；原 SSE/cursor 及 actor/断言；wrapper 与展开 JSON 的精确边界/+1（包含转义放大）；原 token 门禁；readiness 的原 ready、实际装配、Next 不声明和不影响旧控制操作。
