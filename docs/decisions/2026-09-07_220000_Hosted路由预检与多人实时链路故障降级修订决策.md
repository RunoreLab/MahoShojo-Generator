# Hosted 路由预检与 Arena 多人实时链路故障降级修订决策

状态：`accepted`

日期：2026-09-07（2026-09-10 开始按本决策落地）

决策标识：`ADR-hosted-routing-preflight-and-arena-room-degradation-v2`

本决策修订 `ADR-hosted-dr-low-cost-client-preflight` / `SPEC-hosted-dr-client-preflight-v1` 中“哪些请求必须先做 primary probe”的范围；pre-dispatch selection、route pin、ambiguous outcome 与 dispatch 后禁止跨 runtime 重放继续有效。

## 决策

### 1. 分开三个故障域

- Arena Room HTTP command、session、ticket、snapshot、proposal、membership 与 WebSocket 继续固定进入 Hono primary；Room authority、Redis checkpoint、epoch/controlSeq 与 reconnect contract 不因 generation DR 改变。
- Hosted generation placement 只在当前 operation 存在多个合法 runtime 时做 pre-dispatch selection；selection 完成后固定唯一 placement。
- AI Provider execution 继续以 dispatch boundary 作为自动 retry/fallback 边界；已 dispatch 的 generation 不因慢首包、timeout、断线或未知 5xx 自动发往第二 Provider。本次实现不引入 Provider circuit breaker，按用户决策暂缓。

Readiness、Room WebSocket online 与 AI Provider 状态不能互相替代或被解释为同一层健康证明。

### 2. 按 Hono route/method 先分类

客户端在 `client-preflight` 模式下先使用 `config/hono-api-routes.json` 的公开 route/method inventory，再读取小型 `config/hosted-routing.json` 的 DR operation：

| 分类 | 条件 | 行为 |
| --- | --- | --- |
| `primary-only` | 已知 Hono route/method，但未声明可进入 Next DR，或 policy 不满足 DR eligibility | 不做 readiness probe，直接向 Hono primary 发送唯一业务请求 |
| `dr-selectable` | 已知 Hono route/method，且 operation 为 `safe-read` 或 `new-non-idempotent` | 单次 primary probe；primary 不 ready 时最多单次 DR probe；成功后 route-pin |
| `unknown` | Hono route/method 未知，或 routing inventory 与 DR operation 不一致 | 在业务 dispatch 前返回 `OPERATION_NOT_DECLARED`，不发送业务请求 |

核心约束是：如果某次 probe 的失败不可能导向另一个合法 placement，就不能把它设为该业务请求的强制 admission gate。不得为了实现 `primary-only` 而把所有 Hono route 复制进 DR manifest，也不得把 Arena Room route 机械声明为 DR operation。

### 3. 保留 dispatch 后 no-replay

业务 fetch 被调用即视为跨过 dispatch boundary。POST/stream 发生 transport error、未知 5xx、读取中断、SSE EOF-before-done 或取消时，只能投影为 `AMBIGUOUS_OPERATION_OUTCOME` 或既有明确终态；不得自动改发另一个 runtime。稳定 request/generation identity 的恢复继续使用 safe-read status/stream lookup 与 Room fence。

### 4. 观测采用低基数、失败不阻断

客户端 Hosted selection telemetry 记录 contract version、canonical route family、selection reason、primary/DR outcome、固定耗时 bucket、selected placement 与 terminal class；默认通过同源 best-effort intake 上报，失败静默，不携带 prompt、正文、query、Authorization、Cookie、API key、用户/房间/生成标识。

Hono readiness 在现有 runtime snapshot 内聚合 probe arrival、ready/not-ready、延迟 bucket、Redis/D1 ready boolean 与 D1 transport class；不恢复逐个成功 GET 的普通 console log。遥测接收或导出失败不得改变 readiness、业务结果或 Room authority。

## 非目标与暂缓

- 不引入 Cloudflare Load Balancing、Worker reverse proxy、DNS 切流或新的付费 SaaS。
- 不承诺 Arena Room 跨 Next/Hono 双活，不改变 auth、membership、authority、secret 或数据权威边界。
- 不实现 POST 后透明 failover，不因 AI BYOK/Provider 慢化自动重试第二 Provider；AI Provider circuit breaker 与慢首包 UX 留待有数据后的独立实施阶段。
- 不执行 production deploy、DNS/LB/Access/secret/data 写操作。
