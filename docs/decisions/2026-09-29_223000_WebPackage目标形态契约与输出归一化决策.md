# Web 包目标形态契约与输出归一化决策

状态：`accepted`

日期：2026-09-29

决策标识：`ADR-web-package-target-shape-and-normalization-v1`

适用范围：`web-package-target` 输出契约下的宿主提示形态、Arena control trailer 措辞、目标文件内容归一化、导入期作者体检与错误投影分层。

本 ADR 补充 [WebPackage 统一架构与后续开发规格](../specs/2026-09-22_165900_WebPackage统一架构与后续开发规格.md) §13 / §15，并在形态示例一项上收紧 [WebPackage 生成目标形态示例决策](./2026-09-29_152000_WebPackage生成目标形态示例决策.md) §2.1。Package identity、Overlay wire 语义、渲染器权限边界、授权模型与「不自动二次调用 Provider」条款均不变。

---

## 1. 背景

用真实第三方包 `.tmp/quequan-game-mahoshojo-web-package.zip`（`generation.target` = `static/events.json`，`mediaType` = `application/json`）在 `mode: daily` 下生成，Arena 返回「AI 生成的 Web 包目标文件未通过格式或 schema 校验」。用仓库自身的 `buildArenaGenerationPrompt` 复现出的宿主提示，逐条检查后得到三个彼此独立的原因。

### 1.1 宿主从未正面说明目标是 JSON

`buildWebPackagePromptFromProjection` 产出的 HOST block 共 9 行，全部是**禁止与信任边界声明**：

- 「只输出一个完整目标文件的原始文本」——格式中立，一篇散文完全满足；
- 「若存在 schema，目标 JSON 必须满足其 Draft 2020-12 数据约束」——条件句，且是约束不是定义；
- 其余各行都在声明 creator material 不可信。

`application/json` 这个词在整段 HOST block 里**从未出现**，只存在于被标注为「不可信包数据」的 creator JSON 内部。唯一的形态来源是 `generation.instructions`，而该包的 instructions 只有 263 字节的字段名列表。

同时，`compatibility-prompt` 的 `web-document` 分支里那段强硬的「直接输出一个完整 HTML5 document，从 `<!doctype html>` 开始」在 package 分支被整段跳过。结果是 **Web 包拿到的格式约束比无包 Web 战报更弱**。

### 1.2 创作人格与数据文件生成互斥，且没有 system role

`mode: daily` 的 system prompt 是「你是一位才华横溢的作家……创作一个有趣、温馨、深刻或日常的故事」，它是整条提示词中最长、最具支配力的一段，其后紧接着「请严格按照当前模式的逻辑进行创作」。没有任何一句把这个人格重定向到「填充某个数据结构」。

这段 system prompt 与 task prompt 被拼成单条字符串，最终作为**一条 `role: 'user'` 消息**发出：没有 system role，没有 `response_format`，没有 tool-calling。`node-executor` 只有 `structured-report` 分支会带 schema，`web-package-target` 一律走纯文本流。

Arena control trailer 指令进一步强化了散文心智模型：它要求 `report.headline` 与 `report.winner`「**与正文标题/胜利者保持一致**」。对 `events.json` 这类目标，"正文标题"和"胜利者"并不存在。

### 1.3 全链路没有输出归一化

`createWebPackageOverlayFromProjection` 对 JSON 类目标执行严格 `JSON.parse(generatedContent)`，失败即抛错并映射为 `ARENA_WEB_PACKAGE_TARGET_INVALID`。整条链路没有 fence 剥离、前导行剥离或 JSON 值提取。

### 1.4 实测证据

以 `agnes-3.0-flash`（OpenAI 兼容端点）、temperature 0.9、仓库自身构造的提示词，各 3 次：

| 场景 | 严格 `JSON.parse` 通过 | 归一化后通过 |
|---|---|---|
| quequan 包（有 instructions + schema） | 0/3 | 2/3 |
| 空壳包（无 instructions、无 schema） | 0/3 | 0/3 |

观察到的失败形态：

1. ` ```json ` 代码围栏（宿主已明令禁止，模型仍输出）；
2. 前导文件名行 `static/events.json\n[…]`；
3. 顶层形状错误：schema 要求数组，模型给出对象；
4. **纯散文**：`故事标题：《雨天的薄荷与焦糖》\n\n雨落在老式书店的玻璃橱窗上……`——出现在空壳包场景，即用户报告的症状。

另有两项决定方案取舍的实测结论：

- **只改提示词不可靠。** 追加 system role 并显式要求"第一个字符必须是 `[`、不得输出代码围栏"后，`agnes-3.0-flash` 仍输出 ` ```json ` 围栏。
- **不能依赖供应商的 json_schema 能力。** `response_format: { type: 'json_object' }` 正常，`{ type: 'json_schema', … }` 返回结构损坏的内容。这与 `structured-ai` 已有的 JSON-mode 降级口径一致。

## 2. 决策

### 2.1 宿主按 `target.mediaType` 给出正面形态契约

HOST block 新增一段**宿主权威**的输出形态定义，依据是 `projection.target.mediaType`：

- `application/json`：输出必须是一个可被 `JSON.parse` 直接解析的 JSON 文档；第一个字符必须是 `{` 或 `[`；不得出现前导文件名、说明、寒暄或 Markdown 代码围栏。
- `text/html`：复用当前被 package 分支跳过的 `web-document` 形态段。
- 其余 `text/*`：点明目标媒体类型，并要求首字符为对应文档起始标记。

这不破坏 §13 的 trust boundary：`target.mediaType` 是宿主侧已校验冻结的契约字段（`WebPackageManifestSchema` 交叉校验 target 与既有路径、媒体类型一致），不是 creator 自由文本；形态段描述的是**宿主如何校验这个文件**，不是替包作者描述它要什么。creator material 仍然不得改变 target 路径与媒体类型。

同时把 HOST block 中重复出现的格式禁令收敛为一处，避免同一约束散落成多条禁止句。

### 2.2 control trailer 措辞按目标类型分流

`writeCurrentState` / `writeArenaHistory` 段落里，`report.headline` 与 `report.winner` 的兜底说明改为按目标类型分流：

- 散文类目标（`web-document`、`stream-markdown`）：保持「与正文标题/胜利者保持一致」；
- 数据类目标（`web-package-target` 且 JSON 媒体类型）：改为「根据目标文件实际内容概括」，不再引用不存在的"正文标题"与"胜利者"。

`impacts` 数组要求位于 control trailer 内，与目标文件类型无关，保持不变。

### 2.3 JSON 类目标做确定性内容归一化

在 JSON 类目标进入 `JSON.parse` 之前执行**保守、有界、确定性**的归一化，顺序固定：

1. 剥离成对的外围 Markdown 围栏（``` 或 ~~~，允许语言标注）；
2. 剥离前导的目标路径行（如 `static/events.json`）；
3. 若仍不可解析，按字符串感知的括号平衡提取首个顶层 JSON 值。

归一化 MUST 保持保守：不改写值、不补字段、不截断内容、不猜测结构、不做任何语义修复。提取结果仍必须通过既有 `assertJsonSchema202012` 与字节预算检查。

**归一化对内容是幂等的**：已合法的 JSON 走原路径，字节不变。

### 2.4 digest 与 replay 口径

`generatedDigest` MUST 对应**归一化后**的字节。这是必要的：`verifyWebPackageOverlay` 与历史 replay 都以 digest 比对内容，若 digest 仍取归一化前的原始文本，同一份逻辑内容在重放时会校验失败。

影响面已核对：`generatedDigest` 不参与 package identity（后者由 manifest canonicalization 决定），不进入 Room Shared Config，也不参与授权判定。历史战报的 `generatedDigest` 是旧实现写入的原始文本 digest；由于这些历史 overlay 当时能通过校验，其原始文本必然已经是合法 JSON，归一化对其为恒等变换，digest 保持一致。**不存在需要迁移的历史数据。**

`formatWebPackageFallback` 与客户端展示路径使用同一归一化结果，避免「校验用的内容」与「展示给用户的内容」不一致。

### 2.5 不引入自动二次 Provider 调用

维持规格 §15「输出契约失败不自动调用第二次 Provider 生成完整 HTML」。归一化是确定性变换，不是重试。

### 2.6 导入期作者体检

在既有 `invalid-manifest-field` 作者向反馈机制（`import.ts`）上追加**不阻断**的生成可行性体检，仅对数据类目标（JSON 媒体类型）触发：

- `generation.instructions` 缺失或过短；
- `generation.schema` 缺失，或其 `required` 覆盖明显不足；
- 未提供 `generation.example`。

每条给出一句可执行动作。这些是提示，不会让本来能用的包导入失败。

### 2.7 错误投影分层

`ARENA_WEB_PACKAGE_TARGET_INVALID` 按失败阶段分为两个可区分的 code 与文案：

- 形态失败：归一化后仍不可解析为 JSON；
- schema 失败：可解析但不满足 schema。

诊断信息只回传归一化前后的首行片段与失败原因摘要，**不回传 creator material 原文**，避免包内容经错误通道外泄。

## 3. 结果

quequan 这类包在 `mode: daily` 下的实测通过率从 0/3 恢复到 2/3；剩余 1 次是模型把某个事件项漏写了 `accept` 字段——这是 schema 覆盖不足导致的真实内容缺陷，归一化不应、也不去修复它，错误投影会把它归入 schema 失败并给出可诊断信息。

## 4. 不采用的方案

- **只改提示词**：§1.4 已证明围栏与散文在强化指令后仍会出现。提示词优化是必要但不充分的。
- **对 JSON 目标启用 `response_format: json_schema`**：实测该能力在兼容端点上不可靠，且各供应商覆盖不一致；`json_object` 只保证是 JSON，不保证满足包自己的 schema。既有 `structured-report` 路径已按此口径降级，Web 包路径不应引入第二套假设。
- **归一化时自动补全缺失字段 / 猜测数组与对象的取舍**：这是内容决策，平台不代猜。它属于作者写好 schema 与 example 的责任（§5）。
- **自动二次 Provider 调用做格式修复**：见 §2.5。需要先修改规格 §15 的禁止条款，收益不足以现在动这条边界。
- **用固定散文模板拼装 JSON**：绕过创作质量，且把宿主变成内容生成器。

## 5. 仍然属于包作者的部分

平台侧保证「格式可解析」，不保证「内容对引擎有意义」。quequan 这类包要真正可用，还需要作者自己：

- 把 `generation.schema` 约束到**嵌套结构**。该包 schema 只约束了 5 个 `required`，`accept` / `reject` 的 `{attr1..attr4}` 增量结构完全没写——实测模型会把 `accept` 写成下一个事件节点而不是属性增减表，**渲染出来是坏的游戏，但校验通过**。
- 把 `generation.example` 指向 3–5 条小样本。
- 把 `generation.instructions` 写清楚。

「校验通过」不等于「内容对」这一点会写进用户向教程，见 [Web 战报与 Web 包创作百科]（`apps/web/public/encyclopedia/web-package-authoring.md`）。
