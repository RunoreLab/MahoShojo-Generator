# Web 包能力预检误报收紧决策

状态：`accepted`

日期：2026-09-29

决策标识：`ADR-web-package-preflight-precision-v1`

适用范围：本地能力预检（`packages/web-package/src/security.ts`）的风险规则精度、扫描对象范围与网络目的地提取；以及由此产生的扫描器版本与长期信任失效行为。

本 ADR 修订并扩展 [WebPackage 受限模式与可信同源授权决策](./2026-09-28_205100_WebPackage受限模式与可信同源授权决策.md) 与 [WebPackage ZIP 信封归一化与缺省导入决策](./2026-09-29_114500_WebPackageZIP信封归一化与缺省导入决策.md) 中关于启发式扫描的具体结论。Package identity、Prompt Projection、Overlay 语义、渲染器权限边界与授权模型本身不变。

---

## 1. 背景

`2026-09-29_114500` 的 §4 已经确立过一个原则：扫描是启发式提示而非执行边界，**漏报只损失一条警告，误报则消耗用户对全部警告的信任**。该轮只收紧了 `host-page-access`，其余规则没有跟进。

对内置预设「竞技场新闻」实测 `scanWebPackageBase` 得到：

```text
categories:      dynamic-execution, navigation, network, scripts, site-storage
externalOrigins: http://www.serif.com, http://www.w3.org
findings:        11 条
```

这个包完全离线：没有网络代码、没有存储、没有 `eval`、没有 `Worker`。误报来源逐条可归因：

- `externalOrigins` 与 `network` 来自 SVG 的 `xmlns="http://www.w3.org/2000/svg"`、`xmlns:xlink` 与 `xmlns:serif="http://www.serif.com/"`。XML 命名空间与 DOCTYPE 标识符是标识符，浏览器不会取回它们。后果最严重：这两个假 origin 会出现在同源授权对话框的「可见网络目的地」，并写入 `WebPackageTrustGrant.externalOrigins`，参与 `canReuseWebPackageTrust` 的比对。
- `dynamic-execution` 来自 SVG 内嵌的 `data:image/png;base64,…`。原规则 `/(?:blob|data):(?:text\/javascript|application\/javascript)?/u` 的末尾分组是**可选的**，因此裸 `data:` 即命中，等于任何带内嵌 base64 图片的包都会被报「动态执行」。
- `scripts` 规则 `/\bon\w+\s*=/` 实测命中 `oneTime = true`、`onboarding=enabled`、`data-one="1"` 这类普通标识符与带前缀的属性名。
- `site-storage` 规则把散文里的 `cookie`、`caches` 当成访问点，于是「本包不依赖 localStorage/cookie」这句话本身触发了警告。
- 11 条 findings 里有 5 条来自 `ai/instructions.md` 与 `ai/assets.json`。这两个文件是 **Prompt Projection 的输入**，只在生成时投影给模型，从不在浏览器里执行。它们的文本天然包含代码片段、URL 与「不要使用 X」之类的说明。

## 2. 决策

### 2.1 规则按「可被标记语言模仿」收紧

| 类别 | 原规则 | 收紧后 |
| --- | --- | --- |
| `scripts`（内联事件属性） | `\bon\w+\s*=` | 候选仍为 `\bon[a-z]+\s*=`，但必须**完整属性名就是 `on…` 且位于标签内**：前一个字符是空白、`<` 之后没有 `>`、`<tag …` 前缀匹配 |
| `dynamic-execution`（data/blob） | `(?:blob\|data):(?:…javascript)?` | 只匹配 `blob:`，或媒体类型为 `text/javascript`、`application/javascript`、`text/ecmascript` 的 `data:`/`blob:` URL |
| `site-storage` | 关键词 `cookie`/`caches` | 要求真实访问点：`document.cookie`、`caches.open/match/has/delete/keys`；`localStorage`、`sessionStorage`、`indexedDB`、`BroadcastChannel` 保持原样 |
| 网络目的地 | 文本中所有 `http(s)://` | XML 类文件先剔除 `xmlns*`/`xsi:schemaLocation` 属性值与 `<!DOCTYPE …>` 标识符再做规则匹配与 origin 提取 |

真实能力全部仍然命中：内联 `onclick`、跨行 `onmouseover`、`data:text/javascript`、`blob:`、`document.cookie`、`caches.open`、`Worker`、`serviceWorker`、`clipboard`、外链 `<script src="https://…">`。

### 2.2 提示投影输入与 Markdown 不按运行时能力扫描

`generation.instructions`、`generation.schema`、`generation.assetCatalog` 是 Prompt Projection 的输入，`text/markdown` 在浏览器里没有执行语义。把它们当作运行时代码扫描，得到的结论描述的不是这个包能做什么。

这三类文件不再参与能力规则与网络目的地提取。被跳过的文件数量写入 `uncertainty`，并在能力摘要中显式呈现，**不构成静默漏扫**：一个把可执行内容放进 `instructions` 的包，本来也没有任何机制会去执行它。

选择 Markdown 而不是 `text/plain` 作为文档信号：`text/plain` 是常见的 AI 生成数据目标，可能是 `fetch` 之后被解释的内容，扫描成本低且值得扫。

### 2.3 规则变更使长期信任失效

`WEB_PACKAGE_SCAN_VERSION` 由 1 提升为 2。`canReuseWebPackageTrust` 已按 scanner version 匹配，因此旧规则下签发的「始终信任此包版本」会重新走三秒确认。这是刻意的：预检结论变了，旧的确认依据就不再成立。

## 3. 结果

对内置预设「竞技场新闻」实测：

```text
categories:      navigation, scripts
externalOrigins: （空）
findings:        scripts/news.js 是 JavaScript 文件、scripts/news.js 使用 location.hash
uncertainty:     新增「包内 4 个提示词/说明文件未按运行时能力扫描……」
```

两条残留 findings 都是真实的：一个本地脚本文件，以及它的同文档 hash 路由。

## 4. 不采用的方案

- **不放宽为「宁可多报」**：与 `2026-09-29_114500` §4 的论证相反，且同源授权是本站脚本级权限，警告质量直接决定用户是否认真读它。
- **把提示投影输入当作运行时扫描后再人工过滤**：过滤规则本身就是误报来源，不如在语义层就不扫。
- **保留 `data:` 通配但降权**：分类只有"报/不报"两档，没有中间态；内嵌 base64 图片在任何真实包里都远多于可执行 `data:` URL。
- **不提升 scanner version**：会让旧规则的结论以"用户已确认"的形式继续生效。
