# Web 包 ZIP 信封归一化与缺省导入决策

状态：`accepted`

日期：2026-09-29

决策标识：`ADR-web-package-import-envelope-v1`

适用范围：用户提供的 Web 包 ZIP 的信封解析、文件表来源、manifest 缺省填充、错误可操作性与归档元数据处理。

本 ADR 不改变 Web Package 的 canonical manifest 契约、package identity、Overlay 语义、渲染器权限边界或安全预检与授权模型；既有结论继续有效。

---

## 1. 背景

`2026-09-22_165900_WebPackage统一架构与后续开发规格.md` §4 定义的 `files` 是 canonical manifest 的必填字段，`web-package.json` 位于归档根目录。实现阶段据此在导入路径上加了两道硬性约束：

- `web-package.json` 必须位于归档根目录；
- `files` 必须存在，且必须与归档内容逐条对应。

这两条约束在协议上自洽，但与真实用户的打包习惯不符。`git archive`、`zip -r`、VS Code 与 Windows 资源管理器的“压缩文件夹”都会产出一个顶层包裹目录；手工制作的包也很少愿意手工维护 SHA-256 文件表。实际结果是：绝大多数真实归档在进入协议校验之前就被拒绝，用户只看到一句干巴巴的“缺少 web-package.json”。

需要区分两件事：

- **canonical manifest 必须保留 `files`**：它承载 `mediaType`（渲染器据此判定脚本 MIME、CSS 重写与风险分类）、资源闭包、逐文件摘要，以及 `ref.digest` 的 canonical 输入。删掉它会改变 package identity。
- **authoring surface 不应要求 `files`**：仓库自身的预设生成器已经这么做了——`scripts/generate-web-package-presets.mjs` 明确拒绝源 manifest 枚举 `files`，由生成器按扩展名映射与 SHA-256 派生。ZIP 导入此前只是缺少同一套归一化。

## 2. 决策

### 2.1 信封宽容、内容严格

导入拆成两层：**信封层**（`src/archive.ts`）负责定位包根目录、剔除归档工具元数据、展开归档并约束解压规模；**语义层**（`src/import.ts`）负责文件表来源、manifest 缺省填充与最终 `verifyWebPackage` 校验。

信封层对**打包方式**宽容，对**内容**严格：

- 根目录已有 `web-package.json` → 整体作为包；
- 否则唯一一层子目录含 `web-package.json` → 剥离该目录（仅接受单个合法 portable 路径段）；
- 出现多个候选 → 明确报歧义，绝不猜测；
- `web-package.json` 位于一层以上 → 明确报嵌套错误，指出应打包 Web 包目录本身；
- 完全没有 `web-package.json` → 整个归档即包，作者路径原样保留（见 §2.4）；
- 包根目录之外的任何文件 → 拒绝；
- 归一化只发生一次，`packWebPackageZip` 仍只输出根布局，重新导出后即为 canonical 形态。

### 2.2 `files` 可派生，声明仍然权威

- `files` 存在 → 保持权威，执行既有「未声明即拒绝」「缺少即拒绝」与大小写冲突拒绝；
- `files` 缺失 → 按归档内容派生，媒体类型由共享扩展名映射（`src/media-types.ts`，预设生成器复用同一份）推断，**未知扩展名 fail closed**。

这不是安全降级。既有「拒绝未声明文件」防的是 manifest 与归档的分歧，而不是恶意；`files[].digest` 由提供字节的同一方自述，检测的是漂移而非敌意，全链路没有任何签名。派生之后 manifest 与归档在构造上不可能分歧，该不变量是被满足而不是被削弱。真正的安全边界在渲染器白名单、iframe sandbox 与可信同源授权、扫描与授权对话框，均不受影响。

### 2.3 只对「缺失」做缺省填充

**缺失**的字段按固定策略填充，**存在但非法**的字段一律显式失败。默认值不得覆盖作者已经表达过的意图。

| 字段 | 缺失时的缺省 |
| --- | --- |
| `format` / `formatVersion` | 常量；显式给出不同值仍判为不兼容并失败 |
| `id` | 由包内容派生的 `local.<sha256 前 32 位>`，重命名目录后保持稳定 |
| `version` | `1.0.0` |
| `name` | 包根目录名，回退到派生 ID |
| `entry` | 最浅的 `index.html`，否则最浅的 `*.html` |
| `generation.target` | 自动识别出的 `entry` |
| `generation.mode` | `replace`（V1 唯一模式） |
| `generation.mediaType` | `text/html` |
| `capabilities` | 空数组（schema 既有 default） |

因此一个不含 `web-package.json` 的普通站点目录也能导入为可生成、可渲染的完整 Web 包，且行为与「声明 `generation.target = index.html`」完全一致——这一形态已由内置预设与实际第三方包验证。

### 2.4 缺省填充必须可见

导入返回 `diagnostics`，逐条说明识别到的包根目录、被丢弃的归档元数据、以及每一项缺省填充。UI 必须展示，不能静默应用。用户在授权一个包之前，有权知道这个包的实际身份是怎么来的。

### 2.5 错误可操作

导入失败统一为 `WebPackageImportError`，携带稳定 `code` 与面向用户的 `hint`。UI 展示「发生了什么 + 该改什么」，不再回显裸校验器消息。`hint` 为必填——没有任何一条失败路径可以没有补救指引。

### 2.6 归档元数据按固定名单丢弃

`__MACOSX/`、`.DS_Store`、`Thumbs.db`、`desktop.ini` 按固定名单丢弃并计入 `diagnostics`，不做「忽略未知前缀」。任何其它多余条目仍是错误，因此文件表仍然不可能与归档分歧。由于文件表从「保留下来的条目」派生，digest 依旧诚实。

### 2.7 目录占位符按路径段匹配

`dir/` 只有在确有包内文件位于 `dir/` 之下时才被容忍。原先的字符串前缀比较会让 `assetsX/` 通过 `assets/foo.png` 的检查，已改为段感知比较。

### 2.8 解压规模保护不是产品体积限制

`packages/web-package/README.md` 已接受「不增加产品级硬限制」。本 ADR 不推翻该结论，改为在 `unzipSync` 的 `filter` 上按 `originalSize` 累加设一个解压保护上限（`MAX_ARCHIVE_EXPANDED_BYTES`）。理由是 fflate 在解压前先按 central directory 的 `originalSize` 预分配 `new Uint8Array(...)`，被伪造的尺寸字段是直接的内存耗尽向量；这与「Web 包可以有多大」是两个不同问题，提示文案中也明确区分。fflate 对被拒条目只做跳过而不抛错，因此溢出判定必须在解压返回后进行。

## 3. 与既有口径的关系

`2026-09-22_165900_WebPackage统一架构与后续开发规格.md` §11.2 的「不能宣称任意已有 HTML ZIP 无需适配即可运行」**继续有效**：它约束的是渲染能力（多文档导航、import map scopes、Worker、任意动态 CSSOM 内的相对资源重写），与本 ADR 的信封容错正交。本 ADR 只放宽**如何找到并信任包的身份**，不放宽**包被渲染时能做什么**。

`2026-09-28_205100_WebPackage受限模式与可信同源授权决策.md` 的预检、风险分类与授权模型继续有效。§2 中唯一涉及扫描器的变更是 `host-page-access` 规则的收紧，见 §4。

## 4. 附带修正：host-page-access 误报

`src/security.ts` 原规则为 `/\b(?:parent|top|opener|frameElement)\b/`，会把 CSS `top:30%`、`.top` 类名、`#top` 与 `--top` 判定为宿主页面访问。实测内置预设「竞技场新闻」因此长期带有一条例外证据为 CSS 的 `host-page-access` 警告。

扫描是启发式提示而非执行边界：漏报只损失一条警告，误报则消耗用户对全部警告的信任，与 ADR 所要求的风险措辞相悖。规则收紧为：限定 window/self/globalThis/frames 限定的访问，以及未被 `.`/`-`/`#` 前置的裸 `parent`/`opener`/`frameElement`；`top` 必须限定书写。

其余风险类别未作改动。

## 5. 结果

- `.tmp/danmaku-arena-web-package.zip`（顶层目录包裹 + 无 `files`）可直接导入、生成、渲染；
- 导入后重新导出为 canonical 根布局，二次导入诊断为空、identity 不变；
- 与内置预设的 ZIP 往返行为完全不变（诊断为空、ref 相同）。
