# Vitest 测试框架迁移决策

状态：`accepted`
日期：2026-05-29

## 背景

pnpm 第一阶段迁移后，包管理器和脚本调度入口已统一为 pnpm，但 `pnpm test` 仍调用 Bun 测试运行器。测试目录中大量文件依赖 `bun:test`，少量仓储测试依赖 `bun:sqlite`，导致“使用 pnpm”与“测试仍依赖 Bun runtime”之间仍存在工具链边界。

## 决定

将测试运行器迁移为 Vitest：

- `pnpm test` 执行 `vitest run`。
- `pnpm test:watch` 执行 `vitest`。
- 测试文件统一从 `vitest` 导入 `describe`、`test`、`it`、`expect`、`vi` 等 API。
- 原 `bun:sqlite` 仓储测试改用 `better-sqlite3` 与 `drizzle-orm/better-sqlite3`。
- 运维脚本中的 Bun 调用不纳入本阶段；后续迁移需单独验证路径别名、环境加载与 D1 行为。

## 后续状态

2026-05-29 后续迁移已将运维脚本入口统一为 `pnpm exec tsx scripts/<name>.ts`，Bun 不再作为当前推荐的脚本执行入口。

## 验证要求

迁移后至少执行：

```bash
pnpm test
pnpm lint
pnpm build
```

如果本地 pnpm 阻止 `better-sqlite3` native build，需要先批准并构建该依赖，否则 SQLite 仓储测试无法加载 native binding。
