# Desktop Tauri V1 运行时与本地安全边界决策

状态：`proposed`
日期：2026-09-30
决策标识：`ADR-desktop-tauri-v1`
取代范围：细化 [客户端运行时与发行决策](./2026-08-22_022400_客户端运行时与发行决策.md)、[本地库与数据所有权决策](./2026-08-22_022300_本地库与数据所有权决策.md) 与 [平台重整目标架构](../architecture/2026-08-22_022500_平台重整目标架构.md) 中尚未落到可执行门禁的部分；不改变它们已冻结的服务器权威、签名、排位与多人语义。

## 背景

[平台重整主题](../topics/2026-08-22_022000_平台重整与本地优先架构.md) 已把 Desktop/Mobile 冻结为 Local-first / Direct-first，并明确
"Desktop 可以在 Phase 2.5 后尽早做最小 Tauri PoC 验证共享边界，但完整 MVP 等 Web local-library/Direct
数据语义稳定后再展开"。截至本决策日，`apps/desktop` 尚不存在，而运行时中立契约已经就位：

- `@mahoshojo/contracts` 已有 `AiExecutionRequest`、`DirectProviderProfileV1`；
- `@mahoshojo/ai-core` 已有 `AiStreamEvent` 与结构化解析/repair；
- `@mahoshojo/ai-direct` 已有 `AiExecutionPort` 与 `SecureVault` port；
- `@mahoshojo/local-library` 已有 `LocalCardRecordV1`、`CardRepository`、迁移 runner 与 archive manifest。

因此本决策不再讨论"是否做桌面端"，而是冻结 **Desktop 作为独立本地 client runtime 的 V1 边界**，使
后续实现有唯一可验收的目标。

## 决定

### 1. 运行时与形态

Desktop 采用：

```text
Tauri 2 + Vite + React + TypeScript + Tailwind CSS
Rust 只承担平台适配、敏感执行与持久化机制
```

Desktop **MUST** 是独立本地 client runtime，**MUST NOT** 是 `apps/web` 的桌面壳：

- **MUST NOT** 加载 `mahoshojo.colanns.me` 或任何远端页面作为主 UI；
- **MUST NOT** 在 Desktop 内启动本地 Hono/Node server 复用 `apps/api`；
- **MUST** 复用 `domain` / `contracts` / `ai-core` / `local-library` / `web-package`，**MUST NOT** 复制它们的业务实现；
- **MUST NOT** 在 V1 内嵌模型运行时、GGUF 下载器或 GPU backend。

### 2. Tauri 版本下限

Desktop **MUST** 使用 `tauri >= 2.11.1`。该下限来自已修复的 origin 混淆问题
（GHSA-7gmj-67g7-phm9 / CVE-2026-42184，`is_local_url()` 在 Windows/Android 把自定义协议映射为
`http://<scheme>.localhost/`，使远端页面可调用仅限本地的 IPC 命令，受影响版本 `>=2.0, <=2.11.0`）。

本决策写下时锁定 `tauri = "2"` / `@tauri-apps/cli = "^2.12.0"`，并在 CI 中以实际 lockfile 版本为准。

### 3. capability 授权面

capability 文件 **MUST** 使用 `webviews` 字段并 **MUST NOT** 使用 `windows` 字段。原因来自 Tauri
自身 ACL 实现（`crates/tauri-utils/src/acl/capability.rs`）：一旦 window label 命中 `windows`，
该 capability 会启用到该 window 的**所有** webview，"regardless of the value of `Self::webviews`"；
官方因此建议 multiwebview window 优先只写 `webviews`。

由此冻结：

- 主 UI webview label 固定为 `main-ui`，只被一个 capability 覆盖；
- **MUST NOT** 使用 `windows: ["*"]` 或任何通配授权；
- 未匹配任何 capability 的 webview **MUST** 视为不可信渲染面：它完全无法进入 IPC；
- 同一 webview 命中多个 capability 时，权限是并集，因此 capability **MUST** 按最小授权拆分而不是叠加。

D0 **MUST NOT** 引入任何 Tauri 插件。renderer 在 V1 只能调用本应用自有 command。

### 4. 不可信内容隔离结论

已核验的 Tauri 行为（GHSA-57fm-592m-34r7 及官方 ACL 文档）表明：`invoke` 对跨源 iframe
不可达，**但在 Windows 上，当 iframe 与宿主窗口同源时例外**。`srcdoc` iframe 与宿主文档同源。

因此本决策直接冻结结论，Desktop **MUST NOT** 以任何形式在主 UI webview 内用 iframe 承载
Web Package：

- Desktop **MUST** 以独立、零 capability 的 webview（`WebviewWindow`）渲染 Web Package；
- 该 webview **MUST NOT** 匹配任何 capability，**MUST NOT** 获得 filesystem、shell、SQL、
  updater、vault 或通用 IPC；
- 该 webview **MUST** 在 `maho-webpkg://` resolver 就绪前不接受任何原生授权；
- macOS/Linux 上"iframe 不可达 IPC"不构成放宽理由，隔离形态在所有平台一致。

`WebviewWindow` 是 Tauri 2 的稳定 API；**MUST NOT** 把 V1 交付绑定到需要 `unstable` Cargo
feature 的同窗口 child webview。

### 5. Direct AI 执行链

Direct AI **MUST** 由 Rust 侧发起 HTTP，renderer **MUST NOT** 获得任意 URL fetch：

```text
React
  -> DesktopAiExecutionPort.stream(request, signal)
  -> invoke(streamDirectAi { profileId, request, onEvent: Channel<AiStreamEvent> })
  -> Rust: 读 Profile -> 取 secret -> transport policy -> provider adapter -> SSE
  -> Channel<AiStreamEvent>
  -> ai-core 归约
```

冻结细则：

- 出站 endpoint **MUST** 只来自用户显式保存的 `DirectProviderProfileV1`；请求 DTO **MUST NOT**
  携带临时 endpoint、baseUrl 或 header 字面量；
- secret **MUST** 只以 `secretRef` 形式出现在请求中；
- redirect 在 V1 **MUST** 默认禁用；若实现跟随，**MUST** 限制为同源且**MUST NOT** 跨 origin 携带凭据；
- **MUST NOT** 提供跳过证书校验的开关；如未来需要企业自签 CA，另立 ADR；
- 流式 **MUST** 使用 `Channel<AiStreamEvent>`，**MUST NOT** 使用全局 event 系统承载长流；
- **MUST** 实现 `requestId` + `cancelDirectAi(requestId)` + exactly-once terminal，取消**MUST**
  真正中止上游 HTTP body 并清理注册表，而不是仅停止 renderer 消费；
- **MUST NOT** 为每个微小 token delta 单独跨 IPC，**SHOULD** 在 Rust 侧按时间或大小聚合；
- 本地 Direct 生成**不适用** Web 的 300 秒上限，超时由用户配置且默认有界。

### 6. Secret 存储

V1 的持久 secret **MUST** 存放于操作系统凭据存储（Windows Credential Manager / macOS
Keychain / Secret Service），**MUST NOT** 使用 Stronghold JavaScript API。

冻结的安全目标是可验证的表述，而不是"secret 从不进入 renderer"：

- renderer **MAY** 在用户主动录入时短暂持有明文 secret；
- renderer **MUST NOT** 读回任何已持久化的 secret；
- secret **MUST NOT** 出现在 SQLite、localStorage、日志、崩溃报告、导出包、
  `AiExecutionRequest`、错误消息或普通 IPC response 中。

为此 `@mahoshojo/ai-direct` 的 vault port **MUST** 从 `set/get/delete` 收敛为 renderer 可见的
`set/has/delete`；读取明文的职责只存在于 Rust 侧 executor 内部，不通过 IPC 暴露。

Stronghold 暂不引入。若未来出现大量 credential、portable encrypted vault 或复杂 secret
lifecycle 需求，另立 ADR。

### 7. 本地库职责分层

Installed APP 的本地库 **MUST** 按以下分层实现，**MUST NOT** 把业务语义下沉到 Rust：

```text
TypeScript (@mahoshojo/local-library + apps/desktop 平台适配)
  记录组装 / schema 校验 / provenance / tombstone 规则 / 内容摘要去重 / 本地 ID 派生
        -> narrow typed IPC（只传已校验的 JSON 记录）
Rust (apps/desktop/src-tauri)
  SQLite schema 与 migration / 参数化查询 / WAL / 内容寻址 blob 原子写 / migration journal
```

理由：zod 与 serde 若各自实现同一 schema，会形成两份事实来源，并使既有 contract 测试失效。

同时冻结："Rust dumb store" **MUST NOT** 等于"Rust dumb trust boundary"：

- Rust **MUST** 自己产生所有落盘路径、文件名与 SQL 选择器；
- IPC **MUST** 是业务级的（如 `saveLocalCard`、`importLocalArchive`、`exportLocalArchive`），
  **MUST NOT** 暴露 `readFile` / `writeFile` / `query` / `fetch` 形态的通用能力。

### 8. 内容摘要语义的冻结与演进

`contentDigest` 与本地卡 ID 派生的当前实现位于
`apps/web/lib/local-library/data-card-digest.ts`，其 canonicalization 依赖 JS 字符串排序与
`JSON.stringify`，且该模块 import Web 内部模块，Desktop 无法合法复用。

因此：

- Desktop 在实现任何本地库持久化之前，**MUST** 先把现有 canonicalization 与 ID 派生下沉到
  `@mahoshojo/local-library`，**MUST** 保持与 Web 当前实现逐字节一致；
- **MUST** 建立跨运行时 golden fixture：同一组输入在 TypeScript 与 Rust 两侧得到相同摘要；
- **MUST NOT** 在该下沉过程中修改摘要算法。历史卡 ID、`lc_` 前缀与既有 archive 必须保持不变；
- 规范化升级（如 RFC 8785 JCS）**MUST** 作为显式版本化算法引入，不做静默替换。

该下沉是本地库阶段的硬前置，不是可选优化。

### 9. 构建与 CI 接线

- `apps/desktop` 的 workspace `build` 脚本 **MUST** 只做前端产物（`tsc --noEmit` + `vite build`），
  **MUST NOT** 包含 `tauri build`。原因是 `workspace:build` 会遍历所有 app，而现有 CI runner
  没有 Rust 工具链与 webkit 系统依赖；
- Rust 的 `fmt` / `clippy` / `test` **MUST** 走独立 workflow，并 **SHOULD** 配置为分支保护的
  required check，以避免出现回归窗口；
- `apps/*/src-tauri/target/` **MUST** 被忽略，且 workspace 边界检查 **MUST** 跳过该目录；
- 每个 workspace unit **MUST** 具备非空 `test` / `lint` / `build` 脚本，并 **SHOULD** 有
  `tests/workspace-structure.test.ts` 中的结构门禁。

### 10. 发行签名分层

V1 发行 **MUST** 区分两个独立信任层：

| 层 | 用途 | V1 范围 |
| --- | --- | --- |
| Tauri updater signing | 验证升级包真实性；签名不可关闭 | **MUST** |
| OS code signing | 操作系统信任（Windows SmartScreen / Authenticode；macOS signing + notarization） | 记录策略，V1 首发不阻塞 |

- updater 私钥 **MUST** 只存在于受保护发布环境，**MUST NOT** 提交仓库；`.env` 不生效，
  **MUST** 通过 `TAURI_SIGNING_PRIVATE_KEY` 环境变量注入；
- **MUST** 保留离线备份与丢失/泄漏预案；
- V1 首发平台为 Windows x64；macOS/Linux 在后续阶段扩展。

## 影响

### 正面影响

- 有一条唯一、可验收的 Desktop 目标，不再重复讨论桌面架构。
- Web Package 隔离从"期望"变成由已核验 Tauri 行为支撑的结构性约束。
- secret、SQLite、文件与出站 HTTP 的边界在第一版就固定，后续功能不会回退。
- 服务端减负口径可测：本地创建 + Direct 生成 + 本地保存对项目域名请求数为 0。

### 代价

- Desktop 需要 Rust adapter 与独立的跨平台打包 CI。
- 本地库落地被 digest 下沉这一前置阶段延后。
- Windows x64 首发，macOS/Linux 延后；代码签名策略需要额外决策。

## 不采用的方案

- **用 iframe 承载 Web Package**：Windows 上同源 iframe 继承宿主 IPC 能力。
- **照官方 Stronghold JS 示例把 vault password 交给 renderer**：与 secret 不可读回目标冲突。
- **把 `CardRepository` 语义整体重写为 Rust**：形成 zod/serde 双事实来源。
- **顺手把现有摘要算法换成 JCS**：会改变历史卡 ID 与内容摘要。
- **把 `tauri build` 放进 workspace build**：现有 CI 无 Rust 与系统依赖，会直接失败。
- **V1 内嵌模型运行时或做通用原生能力集**：与 YAGNI 和最小授权冲突。

## 待验证事项

以下两项在本决策为 `proposed` 期间必须以真实运行结果确认，确认后本决策转 `accepted` 并同步 spec：

1. **OS 凭据存储可用性**：`keyring` 类实现在 Windows 上对目标用户会话可用，且不需要额外
   交互式解锁即可在应用启动后读取。若不成立，需在 `keyring` 与 Stronghold+Rust-only 之间裁决。
2. **Web Package 零 capability webview 可行性**：以 `WebviewWindow` 加载 `srcdoc`/resolver 内容时，
   确认其确实无法进入 IPC，并确认 Tauri 2.12 的 WebView 权限请求处理器可用于默认拒绝
   camera/microphone 类浏览器权限。
