## 1. 取代与保留

本决策补充[产品共源 ADR](./2026-10-02_184000_Desktop产品架构与Web共源决策.md)和[线上整合 ADR](./2026-10-04_202000_Desktop线上本地整合与AI配置共源决策.md)。

精确调整：

- 首页功能元数据从“宿主各自提供目录”改为“共源产品目录 + 宿主可用性投影”。这不把完整 Web 目录变成 Desktop 已交付声明。
- 下一新业务页前先关闭当前已实现产品面的对齐差距；不再直接按旧表进入 Arena。保留 D5.1a–d 历史编号，插入 P/G/S/K/N/T 切片，D5.2 不改编号。
- `/me` 与双端 `/settings` 的职责及设置字段所有权统一。现代化不是另建一套 Desktop 视觉系统，也不是所有设置迁上云。
- 小型改进可纳入相应切片，但显式区分无行为变更抽取与产品行为变更，不以“重构”名义静默修改 Web。

继续保留：TS 领域/Rust 机制、现有端口、窄 native IPC、OS secret、D4 零 capability 渲染、本地与账号数据分离、Strict/多人权威、dispatch 后 no-replay、签名延期、备份边界。源码共源不意味着同步发行或下载远端主 UI。

## 2. 共源单位是完整产品区段

同一产品面的布局、文案、主要动作、错误/空态、样式及必要资源 **MUST** 按实际消费者共源。不能只搬 JSX，把对应 CSS、资源或选择状态留在一个宿主，也不能靠人工同步两份页面实现。

共享纯业务规则继续进入现有 domain/ai-core/contracts；React 交互和视图进入 ui-web 的 feature 子路径。仅 Router、认证、网络、持久化、文件处理、外部浏览器和窗口生命周期等真实边界由宿主适配。浏览器通用的交互 hook 可以共享；共享 UI 不自行发项目请求或读 Tauri/Next 全局。

不要求整个 Web 页面一次搬空。优先抽一个完整功能区段并让 Web 同一提交回用，随后 Desktop 接线。`/canshou` 是问卷模式的第二消费者，用它检验是否需要更高层复用；不得提前建设一个含所有生成族条件分支的万能页面或新服务定位器。

## 3. 首页、品牌与导航

产品目录共用稳定标识、名称、分类、资源和 canonical 路径。宿主声明路径是否已交付及动作是否可执行；未实现可以隐藏，已实现但暂时离线仍保留入口和原因。

TopBar 采用现有 favicon 圆形标志，首页 Hero 保留完整标题 Logo；避免额外默认文字品牌。欢迎语、新手推荐、功能网格、赞助、社群、作者、反馈、百科与仓库入口共源。本机工具可作为能力投影后的附加分组，不能替换整个产品首页。

当前产品仓库入口使用 `RunoreLab/MahoShojo-Generator`。历史报告、原作者署名、赞助关系、账号名称和其他项目 URL 不因仓库迁移批量改写。小改进只更新当前触达的权威产品资料。

外链由窄宿主能力交给系统浏览器。不得用远端 WebView 代替未迁移功能或放开任意文件/自定义协议。当前 native 只在登录流程内部（Rust 侧）打开授权 URL，renderer 没有可调用的打开命令；P1 应复用同一 Rust 打开机制，新增一个只接受校验后网页 URL 的窄命令，确有缺口再评估官方插件。Markdown/公告中外链也服从同一边界。

固定产品链接（仓库、赞助、社群、百科等按标识映射的目的地）直接打开。来自 Markdown、公告、卡片内容等的链接默认先显示目标域名并确认；用户可以在 Desktop 设置中关闭这一确认，但 native 的协议/凭据/路径校验始终不能关闭。Web 链接行为不变。

## 4. 离线启动与在线资料

r2 起不再要求「冷启动零项目请求」。某项功能若按业界成熟做法应自动联网（启动时校验会话、刷新资料、检查公告/消息），就自动进行，不为早期政策退化成全手动。自动请求遵守三条原则：

1. **离线可用**：首页、阅读、问卷填写、本地库、角色管理、本地保存与 Direct 生成 **MUST NOT** 依赖项目服务可达，也不等待任何在线请求完成；失败或断网只降级对应在线区域。
2. **不阻塞、有界**：自动请求在首屏可交互后后台发起；有 timeout、single-flight、对 429/5xx 退避；不在窗口隐藏时持续轮询，退出登录/离开能力后释放。
3. **不泄漏**：本地创作内容、问卷答案、本地卡与 Direct 的请求/Key **MUST NOT** 随任何自动请求发往项目服务；自动请求只携带该能力所需的会话与参数。不新增统计/遥测（如需另行决策）。

带网络副作用的是宿主的获取/订阅 adapter，共享视图本身不发请求。静态 Footer 与本地公告并非 Web-only。公开库仍按需捕获、不预取全库，理由是服务端成本与缓存契约，不是冷启动政策。

公告内容进入共源 content 后随各自产物分发；Desktop 先显示内置或最近成功保存的快照。默认在每次启动后检查一次固定公告资源（`on-launch`），失败保留旧快照、不重试循环、不阻塞启动；用户也可以改为只在手动刷新时联网（`manual`）。显示来源/更新时间；只声称对应平台已实现功能，Web 发布公告可作为标明平台的历史资料。默认不自动加载远程图片/视频，不通过刷新下载 JS、CSS 或可执行配置。

存在已保存的登录凭据时，应用启动后在后台校验会话并刷新头像、昵称、徽章等非秘密资料，结果写入缓存；没有凭据时不发账号请求。**缓存不是登录证明**：本地读取可呈现“上次账号 / 尚未验证”，不可复用 signed-in 状态赋予操作权限。账号确定 active 后才开放需要认证的动作。退出清除相应账号缓存，切账号立即隔离；设备所有数据不删除。头像为空、尚未加载和刷新失败须区分。

会话 active 后，消息摘要沿用 Web `useTopBarMessages` 的刷新模型：首次进入/缓存过期时查询，窗口回到前台且缓存过期时再查，本地消息变更时刷新；不做固定高频轮询，窗口隐藏期间不查询，退出登录即停止并清理。未读未知不冒称零或“全部已读”，无消息页实现时不显示可点击死入口。

## 5. 个人页与设置的信息架构

`/me` 承担个人展示、资料卡与历史入口；`/settings` 承担设置。两处指向同一资料编辑区段，不各维护一份表单。共同分组：

| 分组 | 所有权 | 双端差异 |
| --- | --- | --- |
| 个人资料与账号 | 服务器账号资料、头像、个性签名、账号安全 | 资料展示/编辑共源；密码/找回/账号迁移等敏感流程首期仍由系统浏览器完成 |
| 外观与交互 | 当前浏览器/当前设备偏好 | 名称、组件和行为共享；不暗中同步到账号 |
| AI 与生成 | 宿主本地偏好、连接/模型选择；秘密另存 | Web 保留预设端点+自填 modelId；Desktop 自定义连接/客户端执行按既有规则 |
| 数据与存储 | 本地库、账号库、缓存分别标注 | Web 站点存储、Desktop 文件/备份功能按宿主能力显示；清理操作范围不混淆 |
| 高级与关于 | 诊断及产品版本资料 | Desktop 配置文件/更新等只在 Desktop；网站专属项只在 Web |

`scope` 与可用状态来自明确宿主事实，不散落 `isDesktop` 条件。永久不适用的条目隐藏；该宿主已支持但当前需登录/离线/失败的条目保留解释。共同设置页壳不得为展示设备设置而先触发账号查询。

首批可配置项只针对已有真实行为，每个字段一个 owner（登记表见 DESK-SET-007）：

- **生成默认偏好**：各生成页已有的记忆偏好（流式/非流式、语言、图片/JSON 保存方式、面板展开等），可在设置中集中查看与重置。owner 仍是各页现有偏好存储，设置页通过同一 adapter 读写，不另建一份全局默认与页面竞争。
- **交互与动效**：结果自动定位开关；减少动态效果（跟随系统 / 始终减少）。双端共享，与 color-mode 一样存为当前设备偏好，不同步到账号。
- **Desktop 专属**：公告检查策略（§4）、外链打开确认（§3）、Esc 快捷菜单开关（§8）、公开库缓存策略（缓存 ADR §4），都写入 §6 的 `config.json`。Web 不渲染这些条目。

采用既有设计 tokens、控件与模态框，改善分组、焦点、窄屏和保存反馈；不引入新设计系统。云端资料明确保存成功后才显示成功，离线草稿不冒称已同步。旧 `/me?tab=settings` 和账号恢复参数须保留适配，Legacy 认证不借机下线。

## 6. 可手工编辑的 Desktop 配置

首版采用 **JSON**、显式版本、native 解析的固定应用配置目录下 `config.json`。JSON 与现有 TS/serde_json 生态一致；本轮不同时支持 TOML/JSONC，也不为了配置增加通用插件。

配置只承载已经实现、非秘密的可调整设置；无 UI 的合法字段也可手工编辑。后续 UI 使用同一读取/校验/写入服务。每个字段只有一个持久化 owner；既有 AI overlay、Provider Profile、SecretStore 不被原样复制到文件形成双权威。若迁移旧字段，先定义兼容映射再切换 owner。

首版启动读取和显式重载，不做文件 watcher。写入校验、冲突检查、同目录临时文件及原子替换；非法/未来格式保留原文件并报告，不能自动覆盖为默认文件。无害展示偏好可以使用明确标注的默认/上次有效值；AI 选择、权限和执行边界不能因配置错误静默回落。

配置不是安全逃生门：不接受密钥明文、项目服务 origin、任意 header/文件访问、CSP、ACL、Strict/多人权威、签名/兼容门禁覆盖。用户的合法 Direct 自定义端点继续通过已有 Profile 管理，不因此收窄能力。

## 7. 迁移与交付

先完成现有产品面对齐，再迁 `/canshou`；通用生成、Creator、Sublimation 和本地工具按真实依赖安排。账号资料/消息/设置可以独立提前；历史等依赖对应数据/渲染能力。服务器依赖不构成永久 Web-only 理由，低频治理入口暂用系统浏览器是阶段选择而非功能退休。

现代化拆为“共享壳与字段所有权”及“资料/安全/高级功能接线”，不一次重写所有设置。公开库长期离线缓存按[专项 ADR](./2026-10-06_084300_Desktop公开库持久缓存与离线降级决策.md)和[缓存规格](../specs/2026-10-06_084400_Desktop公开库离线缓存规格.md)冻结；其保留/更新/预算策略不影响正式本地库或 Web 既有缓存，不把缓存工程作为所有本地页面的前置。

所有新增 slice 用普通行为测试、构建/类型边界及必要截图对照验收。实机工作按维护者集中验收并保留 PENDING。不得引入源码 SHA 门禁、审查 marker、全站 inventory verifier；遵守[复杂度预算 ADR](./2026-09-01_193200_平台复杂度预算与故障降级决策.md)。

不要求所有长尾能力完成才发布。D5.2 只验收该发行版声称支持的能力和其真实安全/数据门禁。

## 8. Desktop Esc 快捷菜单与统一 Escape 层级

参考现代桌面应用的 System Menu 实践，Desktop 增加 **Esc 快捷菜单**：没有更高层弹出物时按 Esc，打开一个可以快速回到首页、本地库、百科或设置的轻量菜单。只借鉴层级与「Back 不等于业务取消」的原则，不搬运游戏化架构或全套协调器。

- **范围**：菜单视图放在 ui-web shell 共享，只有 Desktop 装配启用；默认开启，可在设置中关闭。Web 中 Esc 有浏览器含义，不启用。
- **统一层级**：当前各组件（BaseModal 栈、CardLibraryModal、移动抽屉、下拉选择等）各自监听 Escape。启用菜单前须把它们纳入同一「最高层优先」顺序，以扩展 BaseModal 已有的弹窗栈为准，不新建通用输入框架。一次 Esc 至多由一层消费；菜单是最低层，只在没有任何层消费时才打开。这同时偿还计划中 TopBar 下拉 Escape dismiss 与抽屉焦点约束的既有债务。
- **非破坏**：Esc 和菜单都不取消生成、不放弃草稿、不触发保存或网络请求。菜单内跳转经既有路由离开守卫；被守卫拦下时按既有提示处理，不绕过。
- **可达性**：菜单动作 **MUST** 同样能通过可见 UI（TopBar 等）到达，Esc 只是加速器。菜单为模态对话框：初始焦点在「继续」，Esc 关闭，焦点返回原处。只列出 Desktop 已交付的路由。
- **首版动作**：继续、首页、本地库、百科、设置。退出应用不在首版：需要为 main-ui 新增窗口关闭 capability，另行评估。
