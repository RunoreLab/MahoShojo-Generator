## 1. 范围与取代关系

Desktop 是本地优先的完整产品客户端，不是离线功能分叉。首页、TopBar、问卷、线上库、个人页与 Arena 多人以既有 Web 产品为基线，按实际依赖逐步共源；本地启动、编辑、保存仍不依赖项目服务器。

本决策补充[产品共源 ADR](./2026-10-02_184000_Desktop产品架构与Web共源决策.md)，精确修订其“自动切换”范围：**用户主动启用严格排位或进入多人生成场景，可以在 dispatch 前将有效执行位置锁为服务器**；失败后的跨执行者自动重试仍禁止。`DESK-PROD-004/005/011` 按配套规格解释。

D4a/D4b 的自有命令 ACL、独立零 capability WebView、resolver、权限和实机门禁不变。本次仅冻结文档，不实现在线功能，不关闭任何运行期门禁，不授权推送、发布、生产修改或新增签名服务。

较早 Desktop 文档将 `/battle`、`/arena` 称为旧 PVP，是路由误称；本轮明确它们属于保留的 Arena 产品，按 D5 接入单人/严格排位/多人能力，不恢复 D3.3 旧迁移任务。真正退休的 `/pvp` 及专属功能仍遵守[PVP 退休规格](../specs/2026-10-04_150000_PVP卡牌对决退休规格.md)。

## 2. 执行位置与 Provider 分开

界面采用 **「AI 执行：客户端｜服务器」**；不改动既有「流式｜非流式」控件的含义，也不以流式能力决定执行位置。视觉上这两项同用共源 `SegmentedControl`，在各对应 Web 页面生成设置区段相邻，仍各自保存独立语义与偏好（详见 DESK-AIP-009）。

| 用户选择 | 实际链路 | 领域语义 |
| --- | --- | --- |
| 客户端 · 本机 | Desktop → 本机模型服务 | `direct-local` |
| 客户端 · 远程直连 | Desktop → 用户选择的远端供应商 | `direct-remote`；仍需网络 |
| 服务器 · 系统默认 AI | 客户端 → 项目生成服务 → 项目侧选择上游 | `hosted`，玩法要求时使用既有权威流程 |
| 服务器 · 预设渠道 BYOK | 客户端 → 项目生成服务 → 预设供应商，使用用户 Key | 保留现有服务端流程；资格仍由服务器判定 |

`AiExecutionMode`、`AiExecutionPort` 已有，优先复用，不另建同义四值 enum 或通用路由框架。界面展示执行位置，内部将其与玩法约束解析成既有 mode；`authoritative` 不必成为普通用户的选项。

**执行位置、AI 连接、数据来源/存储、服务器权威是独立维度。** 浏览线上库不改变 AI 执行偏好；使用服务器不等于自动获得官方原生性或排位资格；将结果保存本地也不撤销其已有来源事实。

Desktop 新用户默认客户端；未配置渠道时引导配置而非静默切服务器。普通场景手动切换，分别保留客户端与服务器的选项。Web 当前生成路径仍为服务器，不因组件共源新增浏览器直连能力。

## 3. System Default 是服务端策略，不是可直连连接

系统默认 AI 的公开显示项与项目侧执行策略分离，**MUST NOT** 解析为客户端可调用的项目上游连接，**MUST NOT** 向客户端分发项目 Key、秘密 header 或内部完整调度配置。

公开模型名称、已公开能力描述和既有响应中的安全模型元数据可以保留；不是把所有 Provider 名称都当秘密。保护依赖服务端鉴权/资格、限流、预算和业务输入校验，不能靠隐藏 URL 或“官方安装包”防止反代滥用。

服务端继续接受产品业务请求，并自行组装/校验可信规则；不为 Desktop 增加带项目 Key 的通用模型代理，不接受客户端指定任意 endpoint、header 或绕过领域约束的任意 Prompt。现有公开/匿名能力的认证策略不因本决策被统一改成强制登录。

迁移时兼容旧 `providerId = system`、既有公开模型选择与服务端 wire；先增加语义映射再移出普通连接目录，不能直接删项破坏旧 Web 配置或已安装客户端。

## 4. 共源 AI 配置，宿主能力不同

复用 `packages/ai-core/src/provider-catalog.ts` 作为公开知识源，逐步分离以下职责；这些是概念边界，不要求每项都建一个包或表：

| 概念 | 所有权与行为 |
| --- | --- |
| Registry / Preset | 项目随版本维护的名称、协议、默认端点、链接和模型信息；用户可隐藏/恢复，不可删除或原位改核心连接字段 |
| Preset Preference | 用户拥有的可见性、选择与模型参数偏好；不含 Key 明文 |
| Custom Connection | Desktop 用户可在选择器内直接用可 Direct 预设配置并保存为自有 Profile，或空白新建、编辑、删除；名称/endpoint/adapter 只能修改用户 Profile，不能回写内置预设 |
| Model Offering | 以连接身份 + 实际 `servedModelId` 区分；预设模型可隐藏，Desktop 自定义模型可增删改 |
| AI Configuration | 连接、模型与非秘密参数的有效选择；沿用现有 profile/request，必要的所有权迁移另有明确映射 |
| SecretStore | Desktop 使用 OS 凭据存储，与普通配置分离；设置页和生成页不维护两套 Key/配置 |

复制预设产生用户自有身份，不随之后的预设更新覆盖；不默认复制或共享 Key。隐藏只是选择器可见性，不删除凭据、历史或中断在途请求；当前已选隐藏项可继续明确显示，删除正在被引用的自定义项须显式解除/替换引用，不暗换另一供应商。

Web 与 Desktop 共用 Registry、解析规则及选择器展示，**不等于拥有相同权限**。2026-10-08 起 Desktop 允许从可 Direct 预设在选择器内「保存并使用」直接建立用户 Profile；原 §4 的「先去设置复制」为历史流程，不再是产品必经步骤。Web 本轮仍只开放项目预设供应商及其固定 endpoint，但继续保留既有的自定义 `modelId` 能力：用户既可选择预设模型，也可在当前预设供应商下填写其他受该端点支持的模型 ID。Web 不开放任意 endpoint、自定义供应商实体管理或浏览器本机模型。该能力属于“预设连接下的模型选择”，不是用户自定义 Provider Connection。

预设是否可用取决于当前宿主 adapter 与执行路径，不能把 Web 的转发端点自动当作 Desktop 直连端点。Google/Anthropic 等协议与高级参数需真实 adapter 支持，未知或未实现能力必须说明；不为显示一致伪造支持。目录不复制服务器运行时或秘密。

## 5. 切换发生在请求前，失败后不偷偷重发

一键严格排位、多人第一版在 dispatch 前锁定服务器并展示原因。退出约束场景后恢复用户原偏好，不持久覆盖普通生成设置，也不继承其他房间的强制状态。用户看到锁定结果后再发起生成；进入房间、勾选选项本身不上传草稿或调用 AI。

严格排位还需要服务器重新检查卡片身份、模型、参数、签名与其他资格；仅切到服务器不足以满足资格。多人第一版复用现有服务器 generation 和 Room 广播/恢复，不实现客户端生成后上传或房主流式中继。

开始后冻结当前输入、执行选择及请求身份。失败、断线、重挂载不切换执行者，不自动二次付费生成；先按现有 request lookup/status/cancel/replay 处理未知状态。确需改用客户端时，是用户明确发起的新尝试，原服务器请求可能仍在执行的风险必须说明。

超时等项目链路特有问题可以建议客户端执行；上游 Key 错误、配额、内容拒绝不能一律推荐换执行位置。Direct 默认无应用层硬超时的既有决定不变，但不承诺网络或上游永远不会中断。

## 6. 共源已有产品，而非另造 Desktop UI

`GlobalTopBar`、首页、`AiProviderSelector`、`DetailsPage`、`BattleDataModal` 及相关详情/问卷/包选择模态框，从现有 Web 实现按切片提取展示、交互和可复用控制逻辑。Web 在抽取时同步回用；Next、认证、网络、文件、存储与 native 关闭等由宿主适配。

`BattleDataModal` 已整合本地/线上来源，**不是待新建功能**。保留现有多页签、筛选、分页、详情、选择与不同来源动作，不改造成第二套“两页签库”。Web 包继续使用独立的包选择模态框，不混成数据卡。

Desktop TopBar/首页用本地产物立即渲染，在线查询只在用户进入相应能力后按需启动；不因共源带入 Web 的账号探测、消息/公告轮询或统计。`/details` 沿用成熟问卷/结果交互逐步补齐，而不是永久保留仅默认问卷的另一套产品。

本地数据与账号缓存分开；注销/切换账号不删本地库和草稿。上传/下载副本是显式操作，不引入自动同步。线上数据仍经服务器按权限、审核、卡槽和领域规则重验。

## 7. 线上通路与兼容

Direct Provider、固定项目在线 API、不可信可执行内容保持三条独立信任通路。此处服务器 BYOK 仍是后续目标：截至 2026-10-08 的 Desktop Hosted 代码只实现 System Default，不能把目标描述成当前已交付或将其混入本次 Direct 选择器切片。普通资料/卡库/消息 API 不接收 Provider Key；用户主动选择服务器 BYOK 时，仅专用生成适配向固定服务发送选定 Key，明示接收方，不读回给 renderer、不写入日志、持久化请求或 Room DTO。

认证先验证实际 Legacy/Better Auth 与原生会话边界。系统浏览器授权是优先方向；采用 OAuth 授权码时使用 PKCE，不假定当前已有该端点/refresh token。需要新增交换协议时先明确协议与兼容，不借本轮改造替换全站登录或停用 Legacy。

最小 capability/协议兼容信息只服务真实在线操作，复用既有版本字段；不要求每次离线启动握手，不另建大型 manifest/evidence 平台。旧客户端不兼容时限制对应在线操作、提示升级，不损坏本地数据。

## 8. 非目标、公开资料与依据

首轮不做多人客户端生成、Web 任意自定义供应商、模型下载/训练管理、全站一次搬迁、自动双向同步、任意 JSON 签名、远端主 UI 热更新或通用 Provider 插件平台。D5 不改变 D4b 工作范围，也不把所有在线长尾变成本地 MVP 发行前置。

公开仓库文档、提交、示例、测试数据与截图 **MUST NOT** 包含未公开项目的名称、仓库 owner/URL、内部路径、commit 或可反向定位的引用。经验可表述为“临近项目”，通常直接说明本设计理由即可；不得复制私有资产。

外部依据（2026-10-04 核验；是设计参考，不是本仓已实现证明）：
- [RFC 8252](https://www.rfc-editor.org/info/rfc8252/) §4、§8.1、§8.12：原生 OAuth 的系统浏览器和 PKCE 边界。
- [Tauri capabilities](https://v2.tauri.app/security/capabilities/)：WebView 授权边界；具体 D4 约束仍以本仓现行运行时 ADR/spec 为准。
