# Web 包生成目标形态的作者可控示例决策

状态：`accepted`

日期：2026-09-29

决策标识：`ADR-web-package-target-example-v1`

适用范围：Prompt Projection 中目标文件结构示例的来源、预算与信任层级；以及 Arena 宿主提示中对"字数要求"的适用范围。

本 ADR 修订 [WebPackage 统一架构与后续开发规格](../specs/2026-09-22_165900_WebPackage统一架构与后续开发规格.md) §13 的 projection 形状。Package identity、Overlay 语义、渲染器权限边界与授权模型不变。

### 修订记录

**2026-09-29 修订（`ADR-web-package-example-as-reference-v1`）**：原 §2.1 把 `example` 定义为「结构示例」并给它 32 KiB 预算。评估结论是这一定义过窄：给 AI 一份**完整可运行的参考实现**（例如一个可玩的弹幕射击游戏），它可以沿用机制与架构、按角色重写内容，而 32 KiB 装不下任何真实引擎。现改为「小结构样本**或**完整参考实现」共用一个字段，预算提到 128 KiB，宿主措辞同步放宽。宿主**不自动注入 base target** 的结论不变，理由（占位页、历史数据会被照抄）依旧成立。详见 §2.3。

---

## 1. 背景

第三方包 `quequan-game` 的 `generation.target` 是 `static/events.json`，包内同时带了一份 36KB、65 条真实事件的 `static/events.json`，而 `generation/instructions.md` 只有 263 字节，字段列表之外没有任何形态说明；`generation/schema.json` 只约束了 5 个 required 字段，`accept`/`reject` 的 `{attr1..attr4}` 结构完全没写。

这种情况下模型很可能输出战报纯文本或 HTML，而不是事件 JSON。一种直觉做法是"把包自带的默认目标文件当示例传给模型"。实测该直觉不可用：

- 内置竞技场新闻的 base `index.html` 只有 387 字节，内容是「这里等待 AI 生成完整新闻网站。本包提供可选的样式、交互脚本、组件示例及素材，不含预制网站。」。自动注入等于教模型复现占位页。
- quequan 的 `static/events.json` 有 36KB。全量注入是一笔可观的上下文成本，而且模型可能直接照抄作者的原始事件，而不是按本场战斗重写。

## 2. 决策

### 2.1 `generation.example` 由作者显式声明

manifest 新增可选 `generation.example`（包内文件路径），语义与 `instructions` / `schema` / `assetCatalog` 一致：必须在包内存在、投影进 Prompt Projection、byte budget 之外直接拒绝。**不得指向 `entry`**——入口一定会执行，把提示字段指向它等于让一段会执行的代码以"提示文本"的名义逃过风险扫描。

宿主 block 新增一句：`example`（若存在）是这个目标文件的一份参照，可以是一小段结构样本，也可以是一份完整可运行的参考实现；机制、架构、接口与代码组织方式可以尽量贴近它，但角色、情节、台词、命名与全部具体内容必须按本场实际重新创作。

`example` 落在 untrusted creator material 块内，与其余 creator 字段同级——它没有引入新的信任面，只是多了一份同类的不可信文本。规格 §13 的 projection 形状与 trust boundary 图同步更新，并写明宿主 MUST NOT 自动注入 base target。

### 2.2 数据类目标不再收到"字数要求"

Arena 宿主提示在 `web-package-target` 合约下仍然附加【字数要求】「请将故事正文的长度控制在 约600字 左右」。这条要求描述的是散文正文；当唯一输出是一份 JSON 数据文件时，它和包自己的 instructions 正面冲突，是把模型推向"输出战报纯文本"的一个直接诱因。

现在：当 output contract 是 `web-package-target` **且** target mediaType 是 `application/json` 时，不发出【字数要求】。`text/html`、`text/markdown`、`text/plain` 目标不受影响——新闻页、故事页确实需要长度指引。

【角色更新元数据】段落保留：其中的 `impacts` 数组位于 Arena control trailer 内，与目标文件是什么类型无关。

### 2.3 `example` 承担两种用途，预算按较大的那一种定

`example` 同时是**小结构样本**（几条记录）和**完整可运行的参考实现**（几十 KiB 代码）。差别不在作者意图，而在长度：前者几百字节，后者几十万字节。

原 32 KiB 上限只够前者。实测 `.tmp/danmaku-arena-web-package.zip` 里的弹幕引擎是 79,405 字节 / 约 20k token，而它的全部价值恰恰在于「这是一个跑得通的弹幕游戏，AI 可以沿用它的机制」——32 KiB 只装得下 41%。

预算提到 **128 KiB**（约 33k token，占 `hosted-system` 的 128k prompt 额度 26%）。真正的闸门不是这个数，而是 Arena 已有的 `evaluateArenaPromptBudget`，超了直接 413。per-field 上限只是纵深防御，作用是让过大的范例在导入期就被拒绝，而不是拖到生成时才失败。

仍然**不裁剪**，理由见 §3。拒绝优于裁剪。

代价是真实的，并已实测：79 KiB 范例产出 65 KiB / 约 2.8 万 token 的目标文件，流式生成耗时 **299 秒**。范例有多长，目标文件通常就要产出多长。因此导入期体检对超过 48 KiB 的 `example` 给出提示，建议精简到「仍可运行、但不含可删的样式与内容」的最小形态。

`example` 是提示投影输入，不按运行时资源扫描——这一点原本漏了它，导致参考实现里的 `fetch` / `localStorage` 会在授权对话框里被报成包自己的能力。现在 `isPromptProjectionFile` 收录 `example`，但**对 `entry` 与 `generation.target` 不豁免**。后者还带出一个既有逃逸：把 `instructions` / `example` 指向 `entry` 可让入口完全不进风险档案（实测 `categories` 为空），而授权判定正是基于那份档案；现在 manifest 校验与扫描器各自独立地堵住了它。

## 3. 不采用的方案

- **自动注入 base target**：见 §1，对内置预设是负收益。
- **自动注入 base target 的截断片段**：截断后的 JSON 不是合法 JSON，作为形态示例反而会教出坏格式；截断 HTML 更无从判断边界。同一理由适用于 `example` 超过预算时的处理。
- **把 `example` 拆成 `sample` 与 `reference` 两个字段**：两者对作者都是「给我一个可参照的东西」，拆开的收益要等真的出现两种包才能兑现；代价是 manifest 契约与投影 wire shape 都要动，而 wire shape 的改动应当留给 `formatVersion` 2。
- **对所有 `web-package-target` 一律取消字数要求**：会削弱竞技场新闻这类散文型目标的质量，且没有必要。
- **在宿主 block 里复述包的目标结构**：宿主不应解释包要什么，那正是 creator material 的职责。

## 4. 仍然属于包作者的部分

平台侧到此为止。quequan 这类包要真正好用，还需要作者自己：把 `instructions` 写清楚、把 `schema` 加强到约束 `accept`/`reject` 的结构、把 `example` 指向一份 3–5 条的样本。平台不代猜这些内容——它们是创作决策，不是可以自动推断的元数据。

弹幕类包有另一条同样成立的路：**引擎留在 base 里不被替换，AI 只生成一份引用符卡接口的小数据文件**（弹幕包 README 里 `pattern-contract.json` 的 F00–F14 就是这个接口）。这条路的输出只有几百字节，稳定且便宜；把整台引擎交给 AI 重写，则要付出上面那个 299 秒。两种都是正确设计，平台不替作者选。
