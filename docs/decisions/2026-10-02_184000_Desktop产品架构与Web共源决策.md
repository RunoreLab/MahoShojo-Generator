## 背景

D0–D2 已建立 Tauri、Direct AI、凭据与本地库的运行基础，但只冻结了局部机制，没有定义用户打开 Desktop 后的完整产品旅程。继续直接实现 D3 容易形成另一套问卷、角色管理和竞技场，偏离已有 [Monorepo 决策](./2026-08-22_022200_Monorepo与应用边界决策.md) 中的共享 React DOM UI 目标。

[现状与技术栈调研](../reports/2026-10-02_183712_Desktop产品共源与技术栈调研.md) 核对了 Web 的薄 route、页面内的 Next/网络/存储耦合、Desktop 临时面板、临近仓库的路由实践，以及正式版发布信息。本决策接受产品共源方向，不把调研中尚未验证的路由候选当成已采用的生产依赖。

## 1. 适用与取代范围

本决策补充上位产品设计，并与 [Desktop Tauri V1 决策](./2026-09-30_160000_DesktopTauriV1运行时与本地安全边界决策.md) 同时生效。

- 保留：独立本地运行时、Tauri/Vite/React/TypeScript、OS secret、窄 IPC、Direct transport、SQLite/blob、摘要与归档语义、Web Package 独立渲染、服务器权威和发行签名。
- 澄清：“不是 Web 壳”禁止远端主 UI、内嵌服务器和 app-to-app 源码导入，**不禁止共享产品页面和 React DOM 组件**。
- 精确修订：`DESK-003` 不再禁止用户主动使用在线能力时的数据读取；继续禁止远端主 UI 脚本/样式替换和本地旅程对项目服务器的依赖。
- 补齐：产品导航、页面复用、运行能力、数据所有权、失联状态、生命周期和版本交付；对应要求见[产品规格](../specs/2026-10-02_184000_Desktop产品一致性与本地优先规格.md)。
- 阶段调整：原 D0–D2 工作及未完成验收保留，增加 D2.5 并扩展 D3/D5。阶段依赖以修订后的[实施计划](../plans/2026-09-30_160100_Desktop客户端阶段实施计划.md)为唯一执行入口，不建立第二套施工顺序。

本决策不取消 Web 已有官方签名，不升级签名算法，不创建新服务器签名接口，不调整严格排位或多人信任规则。

## 2. 同一产品、两个运行时

Desktop 与 Web **MUST** 以同一产品的信息架构、名称、主要操作和视觉风格为基线。首页、问卷、竞技场、角色管理、百科等已迁移的功能 **MUST** 优先消费共享实现，**MUST NOT** 因运行时不同长期复制一套业务 UI。

一致性是功能语义与主要交互一致，不是像素相等或所有在线功能首发齐全。平台文件操作、窗口生命周期、安全隔离和明确不适合复用的旧实现 **MAY** 不同；差异 **MUST** 有真实原因和对应验收，不以“桌面专属”为理由另造产品体系。

Desktop 主入口 **MUST** 是熟悉的产品首页，而不是 Provider/运行时调试面板。调试与配置面板逐步归入设置；本地浏览、编辑与导入 **MUST NOT** 以登录或预先配置 AI 为前提。

### 2026-10-03 旧 PVP 迁移记录与 2026-10-04 路由纠正

旧记录把 `/battle`、`/arena` 误称为 PVP；二者实际属于保留的 Arena 产品。真正的 `/pvp` 已按[退休规格](../specs/2026-10-04_150000_PVP卡牌对决退休规格.md)移除。D3.3 旧迁移任务不恢复；本轮已明确将 Arena 单人/严格排位/多人能力纳入 D5 的线上本地整合规划，不据旧误称永久排除 Desktop 支持。历史数据和领域权限不因客户端规划改变。

## 3. 共享代码与平台适配

依赖方向保持 `apps -> packages`、`packages !-> apps`。`apps/desktop` **MUST NOT** import `apps/web`，也 **MUST NOT** 通过路径别名绕过该约束。

- `domain`、`contracts`、`ai-core`、`ai-direct`、`local-library`、`web-package` 继续承担各自现有职责。
- `ui-web` 按真实消费者逐步提取 React DOM 页面、组件、功能 hooks、主题与静态产品资源；使用显式 feature subpath，不成为 `common/shared` 倾倒包。
- 纯规则 **MUST NOT** 因页面共享而反向依赖 React；UI 公共模块 **MUST NOT** 直接导入 Next、Tauri、服务器 runtime 或秘密模块。
- 路由、存储、Direct/Hosted transport、在线认证、文件导入导出、Web 内容渲染在应用组合入口注入。已有 `AiExecutionPort`、`CardRepository` 等端口 **MUST** 优先复用，**MUST NOT** 仅为统一名称再造等价接口。
- 平台检测 **MAY** 存在于 bootstrap 和 adapter；共享业务组件 **MUST NOT** 散落 `isDesktop` 分支决定数据所有权或执行权威。

首次抽取 **MUST** 同时让 Web 回用共享实现并保持行为，不能只复制一份给 Desktop，再承诺以后合并。迁移按垂直切片进行，不以一次搬空 `apps/web/components` 为目标。

## 4. 本地优先与在线能力

Desktop 的本地启动、内置资源、问卷、卡片编辑、本地库与已保存历史 **MUST NOT** 依赖项目服务器。Direct-local 使用用户的本机模型服务；Direct-remote 直接访问用户配置的远端供应商。两者都不使用项目服务，但 Direct-remote **不是全离线**。

线上库、账号、消息、排行榜、Hosted AI 与多人权威状态是可在 Desktop 内使用的在线能力，不应仅因服务器参与而强制成为 Web-only。它们 **MUST** 走独立、显式的项目服务适配；**MUST NOT** 混入 Direct Profile、共享 Provider 凭据或变成泛化 HTTP 代理。

能力可用状态只负责产品展示和调度，**不是** Tauri capability 授权，也不是服务器授权。服务端继续把所有客户端视为不可信。

**MUST NOT** 因失败自动跨 Direct/Hosted 重试，或无提示上传用户内容。切换执行者、费用承担方或数据接收方需明确用户意图；用户主动启用严格排位或多人场景时，允许在 dispatch 前锁为服务器并显示原因，退出后恢复普通偏好。选项变化本身不触发生成或上传。任意在线能力故障不得阻止无关的本地阅读、编辑、保存与导出。

## 5. 官方数据卡签名首期延期

Desktop V1 **MUST NOT** 新建数据卡签名申请机制、手动申请按钮或无实现的签名开关；签名不是本地生成、保存或 Desktop 首发的前置条件。

已有签名数据 **MUST** 按既有契约保留。本地导入和 schema 合法不等于签名已验证；无法离线验证时须显示未验证/未知，不得伪造官方有效性。现有服务器 HMAC 验证秘密不进入客户端。

未来真正引入时，产品方向为**设置默认关闭、启用后在符合条件的流程中自动请求**，而非逐卡手动申请。实现前另立协议规格，至少满足：

- 可信依据由服务器独立确认，并绑定用户、操作与精确输出；客户端的“官方 app”“未修改”“本地校验通过”或自行生成的证据不构成可信证明。
- Direct 本地或自定义供应商的结果不因该设置而获得官方原生权益；需要新的、可服务端验证的信任协议，不能提供任意 JSON 盖章接口。
- 用户知悉请求发送的数据与网络行为；仅开一个开关不能授权与签名无关的上传。
- 签名失败不删除本地结果、不改判已成功的生成，也不自动重发 AI 生成；签名请求本身须定义幂等、失效与重试边界。

以上只冻结未来方向，不预建 endpoint、队列、设备证明体系或持久化字段。**数据卡签名、Tauri updater 签名和 OS code signing 是三个独立概念**；本次延期不影响既有 updater 真实性校验要求。

## 6. 技术选择与版本

现有 Tauri/Vite/React/TypeScript/Tailwind 与 Vitest/ESLint **继续使用**。只有当前切片确有缺口时才引入新依赖；参考临近仓库的方法，但不把其整套构建、测试、游戏 UI 或私有资产复制进来。

新增依赖 **SHOULD** 选择当时最新正式且兼容的版本；**MUST** 核对官方发布与 registry、维护状态、许可证、peer/engine、目标 WebView、构建和测试兼容性，并以锁文件固定解析结果。不能把 `latest` 标签或邻仓锁定版本当作已通过本项目验证。

涉及 React、TypeScript、Zod 等跨包编译/运行语义的升级 **MUST** 评估所有消费者，不允许 Desktop 单方面用更严格配置使共享包产生隐性迁移。Node 发行构建使用受支持的 LTS。Rust、npm API/CLI 分别核验，不混用版本号。

Desktop 路由优先验证 TanStack Router，具体版本、history 类型和依赖接线在 D2.5 验证后记录；共享 UI 不依赖该选型，因此后续更换不会要求重写业务页面。无证据不迁 Rsbuild/Rstest/Biome，不引入 TanStack Start、额外状态框架或通用插件注册系统。

## 7. 隔离、发行与兼容

Web Package/生成 HTML 与可信产品 UI **MUST** 分开。共享 Prompt、结果契约、overlay 和展示控件不要求共享 Web 的 iframe 传输方式。Desktop 继续使用独立零 capability 渲染面；创建第二个 webview 前须先收紧所有自有 command 的 AppManifest ACL。

“Web 更新后 Desktop 同步”指共享源码随下一次 Desktop 构建和发布进入安装包，**MUST NOT** 解释为运行期下载主 UI JS 或执行远端热更新。已安装旧版的在线 API 兼容与升级失败保护独立验收；不是两个应用必须同步发布。

## 影响与不采用的方案

收益是减少双份 UI、规则与修复漂移，保留用户熟悉的路径和本地自主性。代价是抽取现有 Next、auth、存储耦合，维护两个组合入口，并分别验收浏览器与原生宿主。

不采用远端网站壳、内嵌服务器、全站静态导出、大批复制组件、一次全栈升级、自动云同步、默认自动签名、把客户端可信性当服务端签发依据，以及以 UI 一致为由放松 IPC/secret/服务器权威边界。
