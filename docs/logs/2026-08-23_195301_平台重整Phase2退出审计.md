## Phase 2 优先收口核对

- 通用 card/provider/API/error contracts 已建立：线上数据卡类型、审核状态与可见性；Direct Provider Profile；AI execution request/result/error；通用 API version/success/error envelope。完整业务卡 payload schema 仍归各领域，不将当前元数据契约描述成所有卡内容的统一 schema。
- 最小 `packages/domain` 已建立，并由现有 Web/API/Arena/数据库生产路径消费角色分类与旧数据模板推断。
- `packages/ai-core`、Direct contract、`AiExecutionPort`、`SecureVault` 已建立；具体 Provider、HTTP/IPC、Native/Main executor 与平台 Vault adapter 未提前实现。
- `packages/local-library` 的 record/migration/archive contract 与 `CardRepository` 已建立；真实本地数据库和文件操作留给对应 runtime。
- `packages/cloud-client`、`FilePort`、`UpdatePort` 按需延期：当前没有需要这些公共面的真实 consumer，实施计划明确不要求为凑齐目标目录创建职责不清的空 package。Phase 2.5 的稳定 API seam、Phase 4 的真实 import/export、Phase 5A 的在线只读与文件 adapter 开工时，必须重新检查 `cloud-client` / `FilePort` 是否出现两个消费者、跨 runtime 复用或依赖倒置价值；`UpdatePort` 在 Desktop MVP update 工作进入实现前重检。
- 至少一个现有 Web 路径真实消费已满足，实际存在 AI、data-card API/UI/database 和 domain 多条消费路径。

## 阶段边界与下一步

Phase 2 完成只表示共享协议、领域纯逻辑和最小能力端口通过本阶段门禁，不表示下列目标已经完成：

- 不表示 MONO-002 完成：生产 Web、Hono API 与 D1 Gateway 仍主要位于 legacy root/server，`apps/*` 尚未成为真实应用集合；
- 不表示 `apps/web`、`apps/api`、`apps/d1-gateway` 或其他 runtime 已搬迁，也不表示 Phase 2.5 已通过；
- 不表示 Web IndexedDB 本地库、Installed APP SQLite/文件 adapter、Direct Provider executor、Desktop/Mobile、Arena Room runtime 已实现；
- 不表示 Phase 4 Web local-library 或 Phase 5 Desktop 已完成。

下一步按 accepted 计划进入 **Phase 2.5A**：将当前 `server/d1-gateway` 行为等价迁移为真实 `apps/d1-gateway` workspace project，以独立 manifest、test/lint/build、环境说明和部署入口验证第一个真实 app lifecycle。不得借目录迁移改变 D1 binding、HMAC/Access、health、部署或回滚语义。
