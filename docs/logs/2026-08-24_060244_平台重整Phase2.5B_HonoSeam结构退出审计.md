## 1. Objective 与裁决

本批完成 G25B-5 所定义的 Phase 2.5B 结构退出 stopping condition，而不是把旧 G25B-3..5 中拟议的 14 条异构业务 route 全部伪装成 shared-service 迁移完成：

- 保留 10 条已经具有 shared application service、Next/Hono adapter contract 和明确 Hosted runtime 价值的 Hono capability；
- 将其余 14 条没有充分双 runtime 收益、且包含签名/history/finalize、Arena 写入结算或 Tavern/Tea Party 状态副作用的 capability 明确登记为 exited；
- 删除 Hono generator、生成 registry 和 route adapter type 中的 `legacy-next` 动态导入能力；
- 机械保证退出 route 继续使用同源 Next surface，Hono 返回 404，Next handler 未被删除或改写；
- 不改变 Legacy/Better Auth、Arena v1 authority/wire、原生签名、数据所有权或非幂等不盲目重放语义。

最终 machine-readable inventory 为 `10 shared-service / 14 exited / 0 legacy-next`。Phase 2.5B 因此完成结构退出；`apps/api` 激活、AI/D1/Redis telemetry、Docker/CI/deploy ownership 和整个 Phase 2.5 仍未完成。

## 2. Retained 与 exited capability

### 2.1 Retained shared-service（10）

- `generate-magical-girl`
- `generate-game-card`
- `generate-free` / `generate-free-stream`
- `generate-scenario` / `generate-scenario-stream`
- `creator/generate` / `creator/generate-stream`
- `generate-canshou` / `generate-canshou-stream`

这些能力已经在首条 Hono seam、G25B-1 和 G25B-2 中形成 `@mahoshojo/hosted-api` shared business core，并具有 Next/Hono contract、鉴权/Provider/安全/签名/活动记录/stream 语义的 review 与回归证据。继续保留它们不会要求 Hono runtime 动态导入 Next route module。

### 2.2 Exited：详情与升华（4）

- `generate-magical-girl-details`
- `generate-magical-girl-details-stream`
- `generate-sublimation`
- `generate-sublimation-stream`

这组能力包含 DataCard/questionnaire、原生签名校验与重签、Arena history retention、finalize 和流式状态语义。当前没有证据证明为它们维持双 runtime 足以抵消 shared composition 重构和 replay 风险，因此安全退出 Hono、继续由 Next 同源执行。

### 2.3 Exited：Arena、session、battle 与 regenerate（5）

- `arena/generate`
- `arena/generate-stream`
- `arena/session/generate-next`
- `generate-battle-story`
- `me/battle-reports/[generationId]/regenerate`

这组能力涉及 auth actor、稳定 generation/session identity、数据库/R2 写入、评分结算、签名与非幂等副作用。在 operation/replay contract 和 runtime 收益没有充分证据前，不维持可能产生重复生成或结算的双 runtime 面；退出 Hono 不改变 Arena v1 wire 或服务器权威。

### 2.4 Exited：Magic Tavern / Tea Party（5）

- `magic-tavern/generate-choices`
- `magic-tavern/generate-stream`
- `magic-tea-party/generate-choices`
- `magic-tea-party/generate-stream`
- `magic-tea-party/generate-updates`

这组能力包含 session state、choices/update 写入、重复调用及 stream cancel/error 副作用。当前没有独立 Hono runtime 必要性，继续由 Next 同源执行比保留 legacy handler 动态导入更符合 app boundary 和非幂等保护要求。

退出只移除物理 Hono 执行面，不删除公开 Next path。未来任一能力重新进入 Hono，必须另行证明 runtime 收益，并同时补齐 shared seam、auth/authority、compatibility 和 side-effect/replay 证据。

## 3. 实现与机械门禁

- `config/hono-api-routes.json` 新增精确的 `exitedRouteIds`，与 retained、legacy 三组规范化、互斥且无重复；
- `scripts/generate-hono-route-manifest.mjs` 要求三组清单存在，验证 retained/exited 对应的 Next surface，并在 `legacyRouteIds` 非空时 fail closed；
- generator 只生成 `shared-service` definition，不再生成 `../../app/api/*` import 或 `legacy-next` adapter；
- `server/routes/types.ts` 的 `RouteAdapter` 只允许 `shared-service`；
- `lib/hono-api-routing.ts` 只将 retained shared route 视为 Hono route，退出 capability 保持同源 Next URL；
- contract tests 精确冻结 10 retained 与 14 exited，证明 Hono 对退出 route 返回 404、Next POST surface 仍存在，并覆盖实际客户端 fetch 的同源 credentials/header 行为；
- workspace boundary 与生成 registry 扫描继续禁止 Hono adapter 回导 `app/api` / `pages/api`。

Builder self-review 还确认：从 G25B-2 完成态到本批 HEAD，14 条退出 capability 的 Next handler 目录没有被修改；当前生产 source 中不存在 `legacy-next` adapter 或 Hono 对 `app/api` / `pages/api` 的 runtime import。generator 读取 legacy root 只用于当前迁移期的 inventory surface 校验，尚未完成的 G25C 会把 generator/source/lifecycle 迁入真实 `apps/api` 并去除该构建期 root scan。
