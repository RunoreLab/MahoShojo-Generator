## 1. Objective、基线与实际范围

启动时以当前 code/manifest/accepted 文档重新核对，而不是沿用提示词状态：machine-readable inventory 是
`10 shared-service / 14 exited / 0 legacy-next`，`arena/generate-stream` 仍由约 1,952 行 legacy Next handler
同时持有请求 signal、Provider、R2 与终态副作用；Web parser 不消费 SSE `id:`，没有稳定 request identity、
status/resume/cancel 或刷新恢复。

原 accepted 插入计划估计 G25R-1、G25R-2 各约 4–5 小时。实际 dependency tracing 证明还必须抽取 prompt、
actor、Provider、签名、安全、D1/R2、ranking/history/finalization 的 server runtime，建立真实 Redis 7 backend、
终态回退和多 runtime telemetry。实施计划据此把单个阻断纵切重估为 `12–16h`，并拆成四个可逆 checkpoint；
没有缩减 stopping condition。

实际 objective 是：

1. 以稳定 `generationRequestId`、actor scope 与 semantic payload hash 创建或复用唯一 generation；
2. 服务器而非 subscriber 拥有 Provider/R2 lifecycle，只有显式 cancel 可以中止 generation；
3. Redis 7 reservation/snapshot/Streams 承担跨实例短期 replay，D1/R2 承担 terminal authority/fallback；
4. Next/OpenNext 与 Hono 调用同一 Arena runtime，不建立 app-to-app 或 Hono-to-legacy-root 深层导入；
5. Web 对无字节断线、流中断、切网、刷新和首个 POST 响应丢失恢复同一 generation；
6. rating/history/finalization 具备 generation-scoped 幂等门；
7. fault/parity/config gate 通过后，仅让 `arena/generate-stream` 与三个必要 control surface 进入 Hono manifest。

## 2. 关键设计与实现

### 2.1 Runtime-neutral lifecycle

`@mahoshojo/hosted-api` 新增窄 `GenerationReplayStore`、`ArenaGenerationExecutor`、
`ArenaTerminalResultStore` 与 observer ports，提供 create/resume/status/cancel application service：

- request reservation 对相同 actor/request/hash 复用，对 payload drift 返回 conflict；reservation 不可用时
  fail closed，Provider start count 保持 0；
- producer 使用 generation-owned `AbortController`；subscriber close/cancel 只释放该订阅；
- delta 按时间/字节双阈值 batch，cursor 严格递增且 heartbeat 不推进 cursor；
- replay window 丢失只允许 snapshot bootstrap、terminal fallback 或显式 degraded，不重启 Provider；
- lease 失联对账为 `producer_lost`，不透明启动第二次 generation；
- explicit cancel 幂等，并用 owner heartbeat 把跨实例取消传播到实际 producer。

### 2.2 Redis replay 与 terminal fallback

`apps/api` 使用版本化 `mahoshojo:gen:v1:*` key、Lua reservation/CAS、Redis Stream `XADD/XREAD`、
bounded `MAXLEN`、state/snapshot TTL 与命令 timeout/响应校验。actor key 只保存 hash；request body、prompt、
Provider、credential 和 BYOK key 不进入 key/value/telemetry。

Redis 是 transient generation lifecycle authority，不是长期业务数据库：actor/request/hash reservation、producer
token/lease、running/finalizing、snapshot、Streams 与 cancel/finalization 排序全部以 Lua CAS 完成。generationId 由
actor/request 确定性派生；Redis 不可用时 create 在 Provider 前 fail closed，不能回退 D1 占位行或 process memory。

completed output 先写确定性 R2 key，再以现有 `battle_report_generations` 主键 `INSERT OR IGNORE` 写
`completed | failed | aborted` 终态，并用有界 `extra_json` finalization flags 完成幂等结算；Redis 已过期时
status/stream 从 D1/R2 恢复。producer token/lease 与任何 in-flight 状态不进入 D1。lease expiry 只有取得 Redis
reaper CAS 后才可写最小 producer_lost/failed 终态。

中途评估过新增 reservation/effect 表，但它会把短期 producer ownership 错放进 D1，并增加持续行写、索引与
清理责任，因此在最终实现前完整撤销：不存在 `drizzle/0014_arena_resumable_generation.sql`，schema 也没有新增表。
最终不增加 lifecycle/heartbeat/reservation 的 D1 行或索引；每个终态 generation 仍复用既有战报行与对象索引。
成本变化来自有界 `extra_json` 增量、finalization 状态更新，以及每次新 Redis reservation 后用主键排除既有 D1
terminal 的一次查询（Redis 丢失/终态恢复还会有额外 lookup）；完整正文仍按既有设计长期占用 R2，
`battle_report_generations`/`large_objects` 也仍是长期记录。本 Goal 未新增自动 retention，因此这些既有终态数据的
生命周期和 Cloudflare D1/R2 成本应继续按现行数据保留策略单独治理。

具体资源上限是：create body 12 MiB（认证后按原始字节流增量读取，首个超限字节即取消）、combatants 32；
D1 `extra_json` 96 KiB、local reconciliation
64 KiB、terminal combatant rows 32，完整正文只进 R2。这使单次 generation 的 D1 写放大有硬上界，
且 heartbeat/replay/reservation 不产生 D1 行。Cloudflare 当前 D1 计费与 rows read/written 及 storage 相关，
R2 与 storage 及 Class A/B operation 相关；因此每个真实终态仍会有既有的长期 D1/R2 占用，
但本 Goal 没有新增随 active lifecycle 时长累加的 D1 计费资源。核对依据：
<https://developers.cloudflare.com/d1/platform/pricing/>、<https://developers.cloudflare.com/r2/pricing/>。

### 2.3 Server runtime 与权限边界

`@mahoshojo/hosted-runtime` 持有 Arena prompt compatibility、actor resolution、Provider executor、D1/R2
terminal store、season context 与 finalizer。精确 prompt golden fixture 覆盖四种 mode；BYOK secret 只在
Provider port 边界出现，不参与 semantic hash、prompt、Redis 或审计。

actor 链保持既有兼容：Better Auth trusted origin、legacy bearer authkey、activity actor、signed anonymous 与
bootstrap credential upgrade。连续战报的嵌套 Arena 请求也透传并返回同一 actor credential。排位 season context
缺失时 fail closed。Hono 到 Next internal finalization 使用独立
`ARENA_FINALIZATION_HMAC_SECRET`，生产预检禁止它复用签名、D1 Gateway 或 Better Auth secret。
内部签名包含 60 秒时间窗与 nonce，当前不另建持久 nonce cache：HTTPS origin 严格限定，而窗口内
重放仍受确定性 R2 key、D1 generation PK/CAS、rating event 与 finalization flags 的幂等门限，不能重复
权威副作用。其余风险是密钥/内网已泄露前提下 60 秒内可重复触发有界幂等查询；永久 nonce
存储会新增一套寿命周期状态，对本 Goal 的权威正确性没有实质收益，故作为 non-blocking Minor
明确接受，不以新 schema/cache subsystem 扩张 G25R。

Arena v1 compatibility remediation 还把 raw materials 规范化、原生角色签名验证与严格排位模型 fallback 收回
shared runtime；客户端声称原生但缺少/携带无效签名时只能降级，服务器不得按客户端声明补签或提升信任。
fallback/blacklist canonical 常量归 `@mahoshojo/domain`，根 Web 只保留兼容出口。
Provider URL 只接受可信 HTTPS origin（非生产本机 HTTP 例外），可用 allowlist 进一步收窄，URL 不进入 telemetry。

### 2.4 Web resume 与副作用幂等

Web 在首次 POST 前保存稳定 request ID、actor token、generation ID 与完整 SSE block cursor：

- 首个响应丢失时只以相同 request body/request ID/actor token 重试 create；
- 一旦得到 generation ID，后续网络恢复只执行 GET stream/status，不用 POST 猜测重放；
- parser 消费 `id:` 和多行 `data:`，忽略重复 cursor，snapshot replace、delta append；
- bounded exponential backoff + jitter，并用 `online`/`visibilitychange` 做低频提前唤醒；
- user stop 发送 authenticated explicit cancel；组件卸载与 reader cancel 只取消 subscriber；
- pending handshake 与已知 generation 分别持久化；状态按 endpoint + semantic body hash 使用 session-scoped key，
  多 tab/不同意图不会互相窃取 request ID；anonymous actor token 独立保存在 localStorage/in-memory fallback；
- public transport 固定为 fetch-SSE，历史 `plain-stream` preference 单调迁移为 SSE，不留下绕过 resume contract 的选择器；
- 浏览器 effect ledger 使用 `generationId + baseRevisionHash` 做 Web Locks/进程内 coalescing；服务器在现有
  `battle_report_generations.extra_json` 冻结有界 report/impacts/roster/base hash/write flags。reconciliation 先验证
  generation owner、completed terminal、roster 与卡片基线，再执行可安全重入的签名 transformation；客户端伪造的
  report/impacts/write flags 被忽略，完整 `updatedCombatants` 不持久化到 D1。

## 3. Fault matrix 与 Provider/side-effect 证据

| 场景 | 预期与证据 |
| --- | --- |
| 首次 fetch 无字节断线 / POST response header 丢失 | 重试同一 request ID；server reservation 复用 generation；Provider start count 1 |
| 流中断、5–30s 断网、反复 offline/online、visibility wake | 后续只 GET resume；cursor 单调；重复事件丢弃；Provider start count 1 |
| 刷新恢复 | 持久 request/generation/cursor 继续同一 stream，不创建新 generation |
| subscriber reader cancel / 组件卸载 | 只结束 subscriber；generation-owned signal 保持 active |
| explicit user stop | authenticated cancel 幂等；仅对应 producer abort |
| 双 tab / 重复 create | actor/request/hash reservation 与 in-flight/effect ledger 合并；Provider 和终态副作用各一次 |
| cursor trim / replay window lost | snapshot bootstrap 或 terminal fallback；无第二 Provider |
| blocking `XREAD` 与精确 trim 交错 | 唤醒后 Lua 二次验证 cursor；已裁剪则 `window-lost`，不跳读 |
| Redis replay write 失败 | generation 可显式 degraded，但 stable reservation 不允许第二 Provider |
| Redis reservation failure | fail closed，Provider start count 0 |
| producer kill / lease expiry | 对账为 `producer_lost`，不自动重发 Provider |
| R2 与 D1 terminal 连续故障 | Redis 保持 `finalizing`；lease 到期由 reaper 修复；Provider count 1 |
| 超大 body/roster/manifest | Provider 前 413；D1 manifest/rows 截断于固定预算 |
| Redis terminal TTL 到期 | D1/R2 status/final snapshot 回退 |
| Hono/DR 同 request、Redis owner 不可见 | Redis 不可用时 create fail closed；已有确定性 D1 terminal 可恢复，不启动 Provider |
| cancel/finalization race | Redis CAS 排序；先赢 finalization 不被 cancel 中止，先赢 cancel 只允许 aborted terminal |
| duplicate rating/history/finalization/local-card reconciliation | D1 terminal PK/rating event、generation marker 与 generationId+baseRevisionHash ledger 保证语义幂等 |

最终 `tests/arena-generation-fault-injection.test.ts` 用 `caseId=1..14` 建立统一、机器可审计的实际证据表。
Web 场景通过真实 resumable client → service bridge 注入 5 秒断网、两次切网、刷新、accepted POST header 丢失、
reader cancel、双 tab 与 cursor replay；backend 场景用 observation probe 从实际 request body、derive/header、SSE、
Redis state、D1/R2 ports 与 side-effect counters 采集字段。producer kill 顺序固定为 upstream failure → Redis
`finalizing` → lease expiry → reaper `producer_lost`；14 行的 Provider count 均不超过 1，重复 resume 的
storage/claim/combatants/impacts/ratings/complete 均为 1，trim 场景记录了非零 snapshot bytes。
