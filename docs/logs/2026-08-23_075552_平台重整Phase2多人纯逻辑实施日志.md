# 平台重整 Phase 2 多人纯逻辑实施日志

日期：2026-08-23

## 本批完成

- 新增 `@mahoshojo/multiplayer-core`，沿用 workspace source-export/bundler 约定，并声明显式根 exports、test/lint/build 脚本。
- 实现 Arena Room Shared Config 的逐层白名单投影与 schema 验证；线上引用、host-local combatant/scenario/material stub 均只保留 contract 允许字段，完整 payload、provider、credential、运行态和战报字段不会进入投影。
- 实现严格 wire config 解析、深度 detached working copy、确定性 typed Proposal diff、selection closure/atomic group 校验、typed expectedBase 冲突检测与不可变 selected Proposal apply/revision 逻辑。
- `ArenaRoomNormalizedSource` 明确了投影边界；本包只接收 normalized source，不猜测真实 `BattleStoreState` 字段映射。Web adapter 尚未实现，stable host-local key/versionToken 映射需另批接入。
- 对 combatant/aux scenario/material 新增位置及 team assignment 顺序执行实际 append/remove apply 语义校验；重复 `dependsOn` 返回稳定结构化 issue。
- `applyArenaProposal` 收紧为唯一的 `(state, proposalInput, selectedChangeIds?)` 入口；state 的 revision 使用 `RoomRevisionSchema` 严格验证，非法 state/revision fail closed 抛 `invalid-input`，malformed proposal、非 submitted status 和空 selection 返回结构化 issue。
- 将实施计划中的冲突检测签名同步为 `detectProposalConflicts(current, changes)`；三方比较的 BASE 直接来自 change 自带的 typed `expectedBase`，无需另传或保存完整 base snapshot。
- 覆盖角色、引导、team assignment、battle mode、scenario（含 null）、aux scenario、material、user guidance、story length/custom length、history settings、stale/version drift、部分接受、冲突拒绝、schema/不存在 target、immutability 和 v1 fixture 回归。
