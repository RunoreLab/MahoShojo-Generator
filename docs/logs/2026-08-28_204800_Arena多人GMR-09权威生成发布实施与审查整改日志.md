## 1. Objective 与 stopping condition

本 Goal 在既有 Hono + Redis Room authority 与 G25R durable Arena generation 上完成 host-only start、冻结 snapshot、
Room reservation-before-provider、single producer、服务器进程内 story publisher、成员 allowlist projection、Web gap/resync 与
authoritative terminal 读取。客户端 refresh/reconnect/GET 不自动重发 provider POST；unknown 只允许 host 显式使用同一进程内
原始 request 与同一 `generationRequestId` retry。

实际 stopping condition 以 accepted GMR-09 设计第 7 节和 Goal 指南为准。本日志不把 production activation、生产 SLA、
multi-instance continuity、完整 `ACCEPT-014`/`ACCEPT-018` 或 GMR-11 go/no-go 写成当前 Goal 的 PASS。

## 2. 关键实现与权威边界

- contract/core：strict start/view DTO；冻结 Room revision/config/ref/participants/collaborative influence；opaque reservation/
  publisher capability；exact epoch/request/generation/attempt fence；authority ledger 只新增 redacted `generationPayloadDigest`，
  不进入 public snapshot/WSS/member response。
- coordinator：host/epoch/revision/ref verify 后先 Redis checkpoint reservation，再调用既有 Hosted service。重复 start 先读
  durable projection；只有 starting/running、相同摘要且权威 `not-found` 的显式同请求才可恢复 provider。terminal、legacy
  missing digest、payload mismatch 与 unavailable 均 fail closed。
- authority/secret：PVP context、multiplayer snapshot 与 internal guidance 均由服务器覆盖/签名；client 同名字段不获信任。
  Room 与 Hosted preflight 共用 Node canonicalizer；legacy defaults、valid/forged signature 与 native authority 先统一再摘要。
  Provider credential 和完整 generation payload 只存在 Request/调用栈；Room/Redis verifier 使用 secret canary 检查未持久化。
- publisher/WSS：typed markdown batch 转连续 transient `story.delta`，reasoning/telemetry 不广播；RoomActor serialized queue 再
  验证 current generation 与 frame budget。重挂从 transient cursor 继续，reader 退出时 cancel；真实 Node upgrade 客户端已接收
  story frame。slow consumer 继续由既有 deterministic gateway 256 KiB queue/1013 测试覆盖。
- terminal/data：Hosted memory/Redis replay store 在一次 mutation/Lua 中提交 terminal marker/event/snapshot；D1/R2 terminal
  仍是 durable final authority。lease reaper 的 producer_lost 也必须持久化 marker/error event/snapshot 并重读；mutation 失败
  返回 503。active/created Redis state 已有 D1 terminal 时同样使用 owner/reaper token 提交并读回 marker/event/
  `lastEventId`；并发 terminal claim 重读 D1 + Redis evidence。R2 unavailable 的 D1 preview 不写 completed Redis snapshot，
  重复 status/projection/resume 都显式 unavailable。Redis 整体不可用时只允许读取已验证 D1/R2 terminal fallback，不启动
  Provider、不声称 Redis 已提交。失败/取消/producer_lost 的终态正文若超过 snapshot budget，会在同一次 terminal CAS 中写入
  有界空终态 snapshot 或清除旧 running snapshot，绝不把 partial 当成 failed final。D1 terminal 与 Redis state/readback 会完整比对
  generation/request/payload identity；Room terminal 与 active Hosted projection 的短窗口通过重新读取并 fail closed 处理。
  terminal mutation 强制携带 terminal event 且只能在原子 snapshot/clear 中二选一；所有 Redis terminal 读取按
  exact event ID 逐项校验 marker/event/status/code/resultRef/lease/snapshot。动态 replay/cancel fallback 也复核冻结
  request/payload identity。非 completed 的 SSE/D1/Room projection 清空 markdown/reasoning/resultRef；已原子完成的
  completed Redis snapshot 作为 accepted 权威只读副本，不要求每次 GET 重新探测 R2。
- release/rollback：machine-readable gate 固定 reader-first/current writer disabled；gate metadata 进入 content-addressed release
  tuple，strict JSON schema validator 也进入同一摘要。候选激活、pending recovery 与 rollback 分别执行 schema validation、failed
  tuple 重验和 target reader contract 校验；历史 `legacy-layout + gate` tuple 被拒绝，旧/disabled writer 保持兼容。
- Web：lifted Room controller 维护独立 generation cursor；contiguous append、duplicate ignore、gap single-flight GET resync、
  terminal authoritative replace。普通 start 在 active/unknown 锁定；retry 是独立 host action，并受 session identity/epoch fence。
  Room view 只在 reserved/running/finalizing 采用 publisher progress；completed 只读 authoritative projection，其他终态
  markdown 与 `nextChunkSeq` 清空，避免存活 publisher partial 覆盖 durable terminal 的竞态。

## 5. Independent review

首次只读独立审查：architecture `C0/I4/M0`，security/authority `C0/I2/M0`，compatibility/replay/data/test
adequacy `C0/I3/M1`。所有 Important 已进入上述三个整改 checkpoint；Minor 的真实 WebSocket story 证据已补，localhost 真 socket
难以稳定制造 backpressure，因此 slow-consumer 继续复用 deterministic fake-socket queue test，不伪造真实网络背压结论。

整改后多轮复审关闭 shared digest、terminal retry、跨进程 durable fact、真实 rollback target-reader gate，以及 legacy
adoption 冒认、manifest 外 gate 注入、长事件流 terminal readback 与异常 marker-only terminal。最终 architecture、
security/authority、compatibility/replay/data/test-adequacy 三路
独立审查均为 `Critical 0 / Important 0 / Minor 0`。真实网络 slow-consumer load harness 明确进入 GMR-10；GMR-09 已有
deterministic bounded queue/1013 resync-required 与双真实 peer 证据，不把未测真实背压描述成当前 PASS。

退出复审又发现并关闭：动态 fallback identity、marker-only/stale snapshot、failed D1 preview/Room partial、
Room terminal 被存活 publisher 进度覆盖、D1 cancelled adoption 丢失 exact cancel code，以及真实 batching 组合链和首次
cleanup sentinel 证据缺口。安全复审一度提出“已成功提交 completed Redis snapshot 后仍应每次强制探测
R2”；核对 accepted spec 后撤回，因该 snapshot 是明确允许的权威只读副本，不应将后续 R2 瞬时不可用反向变成
Room 读故障。最后一轮 test-adequacy 在 `14d0e58d` 上复核为 `C0/I0/M0`，当前 HEAD 的
`pnpm ci:verify` 也已 `exit 0`。
