## 1. 裁决与完成结论

`.tmp/G25H-1审查.md` 的三项核心事实均属实，但 legacy stats 的严重度和处理方式需要按仓库事实校准：

1. non-stream companion 的 `report.article.analysis` 永久为空是用户可见兼容回归，已恢复 reporter
   section、统一 projector、Markdown 持久恢复和旧内容降级；
2. 可信 PVP Provider 前拒绝缺少 durable generation 关联是审计缺口，已用窄 typed rejection、
   no-provider terminal fence 和 D1 幂等 recorder 修复，没有把非法或 operational rejection 伪装为
   generation，也没有启动 Provider 或成功副作用；
3. legacy stats 默认关闭，不能按默认 UI 无条件回归处理；由于项目没有既有退休决定且旧 writer
   非幂等，本次正式退休其配置、UI、公开 route、repository 和 writer，同时保留历史 schema/data，
   不影响现行 rating/ranking。

整改后的 PVP consumer 只关联显式标记的 durable terminal ID；purpose-domain HMAC 绑定完整最终 payload，
包括 companion 重建加入的 `forceStreamMeta`。completed fallback snapshot 在服务端与浏览器都是
authoritative replace；只有 `{ ok: true, status: completed }` 的 `done` 可判定成功，两级 SSE consumer
在此前 EOF 都 fail closed。

## 3. 数据、安全与依赖边界

- rejected terminal 只保存脱敏 code/stage、受信 PVP context 与 identity metadata；不保存 prompt、敏感
  原文、custom Provider key、签名或完整请求体；
- D1 recorder 使用确定性 generation ID、`INSERT OR IGNORE` 和 identical-existing reconciliation；
  materialization 直接把已有 reservation ownership 转成 terminal，禁止 release→re-reserve race；
- failed rejection 不写 R2、combatant、rating、history，DR 无共享 Redis identity 时 fail-soft 且不暴露 ID；
- `characters`、`battles` schema 和历史行未修改；新增门禁扫描所有 server runtime 的 SQL/Drizzle writer
  与 migration `DROP`/`DELETE`/`TRUNCATE`；
- 未新增 app→app、package→app、跨 runtime 深层 import 或 client→server secret 依赖。
