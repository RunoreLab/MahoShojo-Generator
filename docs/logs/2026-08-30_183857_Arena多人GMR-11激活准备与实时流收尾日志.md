## 1. 范围与结论

本切片把 Arena 多人从“只能在 protected target 永久拒绝开启”推进到“具备默认关闭、reader-first、tuple-bound、
可回滚的激活路径”。tracked source gate 继续保持 `writerActivation=disabled`，Hosted DR 的
`controlPlane.provisioning=not-provisioned` 也没有改变；Room 使用独立 origin manifest，Preview 已 provision 并完成
Hono writer 激活，production 仍为 `not-provisioned`。没有执行 production deploy、DNS/TLS/Caddy、secret、
GitHub variables、production Redis/D1 写入或发布动作。

仓库侧完成结果：

- production/preview 的 Hono 与 Web 都必须同时满足 writer tuple、兼容 reader contract、独立 go/no-go 和已
  provision 的逻辑 Room origin，缺少任一证明即 fail closed；Room provisioning 与 Hosted DR provisioning 分离，
  Room v1 明确排除在 Cloudflare DR 外；
- Hono release tuple 是 writer activation 的唯一注入源，`.env.hono` 不能伪造 writer 状态；writer-disabled
  tuple 即使保留 request flag 也会安全关闭多人入口；
- Hono 激活在 Web 公开开关之前，发布后用无鉴权、无写入的 Room HTTP/WSS 探针验证路由、exact Origin/CORS、
  Upgrade 与认证 fail-closed contract；production 首次启用还要求 Hono 完成后的手工 dispatch 确认；
- generation delta 默认从 `75 ms / 1024 bytes` 调整为 `40 ms / 512 bytes`，没有采用成本更高的
  `25 ms / 256 bytes`；running snapshot 改为 `250 ms / 4096 bytes` 摊销，terminal snapshot 仍同步完整持久化；
- blocking `XREAD` 使用上限 32 条连接的独立 Redis pool，避免和 `EVAL`/`GET`/append/snapshot 共用单连接造成
  head-of-line blocking；3 秒 socket inactivity timeout 防止失联命令永久占用 lease，readiness 同时 ping main/pool；
  不存在 Stream key 时也可由首个 `XADD` 唤醒，空读后的附加等待最多 50 ms；
- 应用 SSE 保持 `text/event-stream` 与 `Cache-Control: no-cache, no-transform`。Caddy 当前没有 response buffer，
  `text/event-stream` 会按流 flush；公网 Cloudflare rule 仍必须通过授权 canary 验证，不能用本地测试冒充。

## 2. 实现边界

### 2.1 激活与回滚

- `apps/api/src/config.ts`：protected target 的有效开关为
  `ARENA_MULTIPLAYER_ENABLED && tuple writerActivation=enabled`；writer 首次开启还要求 exact reader contract、
  `approved` go/no-go 与 canonical HTTPS logical origin。
- `config/arena-room-origins.json` 与 generated client projection：公开 bundle 只接受 Room manifest 中的
  stable/preview origin；Preview `provisioned`，production `not-provisioned`，不会再错误复用 Hosted DR control-plane
  provisioning。manifest 固定 Hono/Redis single-writer authority 与 `cloudflareDr=excluded`。
- `apps/api/deploy/deploy-bundle.sh` 与 `compose.yml`：candidate validation、runtime validation、activation、rollback
  都从 content-addressed release tuple 读取 writer 状态；writer-enabled candidate 缺少 attestation 会在容器替换前失败。
- production Cloudflare workflow 在 Web build 前验证 Room HTTP/WSS；preview workflow 保持 Hono 先发布、Web 后发布，
  最终 Web deploy 前也逐一验证三个 exact Preview Web origins 的 Room HTTP/WSS。HTTP 要求 401 error code 与 ACAO；
  WSS 使用合法 RFC 6455 key 和 canonical subprotocol，并要求未带 ticket 时返回 401。production public flag
  为 true 时，普通 push 会 fail closed，必须在 Hono 激活后以 `arena_room_backend_ready=true` 手工 dispatch。

### 2.2 实时流与 Redis

原实现的主要风险不是 `40 ms` 与 `75 ms` 的差异，而是 blocking replay 和写命令共用一条 node-redis connection：
`XREAD BLOCK 1000` 可能阻塞首个 `XADD`，Stream 尚不存在时还会轮询，造成短生成接近 terminal 才一次显现。

本切片先隔离 blocking connection，再降低 delta 阈值。一次 delta flush 仍需要 durable replay append，但不再为每个
小 delta 重写累计全文 snapshot；snapshot 写失败不会清空待持久化预算，terminal 路径继续强制完整 snapshot。因此新参数
提升了视觉细腻度，同时限制 Redis 写放大、累计 JSON 编码、RoomActor fan-out、浏览器更新频率和 replay window 收缩。

`40 ms / 512 bytes` 是首发折中：相较旧默认，时间驱动最多约 `1.875x`、字节驱动最多 `2x`；
`25 ms / 256 bytes` 会分别达到约 `3x` 与 `4x`，在尚无生产 P95/P99 指标前不采用。

## 3. 安全与兼容性

- Room 继续只由一个 room-capable Hono writer 和 Redis authority 承载；没有增加 multi-instance lock、DO、D1 directory
  或 Cloudflare Room DR。
- 没有 wire/schema/persistence migration；reader contract 仍为
  `arena-room-authority-v2-generation-payload-digest-v1`。
- HTTP/WSS 发布探针只发送未认证请求；HTTP 期待 `ROOM_AUTHENTICATION_REQUIRED`，WSS 则要求合法握手在未带
  ticket 时返回 401（Node upgrade 拒绝路径不依赖 JSON body）；
  不创建 Room、不生成内容、不写远程数据库或 Redis。
- 回滚到 writer-disabled tuple 可立即使 server 有效开关为 false；回滚到 writer-enabled target 时仍要求先关闭
  generation request flag，避免把旧 reader 重新暴露为 writer。

## 5. 部署层 buffering 口径

仓库内链路没有发现“累计数千字后一次返回”的 whole-body buffer：provider projector、Hosted service SSE、Hono adapter
和 telemetry wrapper 都逐块转发；stream projector 仅为 meta marker 有意保留末尾最多 256 个 JS 字符。Caddy 当前配置
只有 `encode` 与 `reverse_proxy`，没有 `response_buffers`；response 的 `no-transform` 会禁止编码转换。

仍未闭合的是携带真实 provider 输出的 production stable/physical 双路径公网时序。只读审查确认 Preview Web 的 API
placement 与 logical API 都是 `homura-preview`，不存在可代表未来 production routing 的第二条 stable proxy；此时运行
Provider 只会重复验证同一物理链路，并永久增加共享 D1 terminal 记录，不能关闭 production stable rule 的风险。

因此按用户“非必要即可略过”的决定，现在不执行 Preview Provider canary。待 `api.mahoshojo.colanns.me` provision 后，
若用户另行授权 production Provider/Redis/D1 写入，推荐用同一匿名 actor 与同一 generation 同时订阅 stable/physical，
两边各收到至少两个不同网络 read 的 markdown delta 后立即取消。两边 generation ID 相同、取消返回 202、最终收到同一
cancelled terminal，且 `Content-Type`/`no-transform`/`CF-Cache-Status` 均符合预期，才记为强 PASS；Provider 只产生一个
chunk 时只能记 `INCONCLUSIVE`。这项体验 canary 不是 Room authority、数据兼容或回滚安全的机械门禁。
