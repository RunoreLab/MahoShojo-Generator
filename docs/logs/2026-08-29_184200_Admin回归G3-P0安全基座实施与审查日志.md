### 2.2 独立 Admin app 与信任边界

新增 `apps/admin` Cloudflare Worker/Web Standards app：

- 独立 manifest、generated Worker binding types、test/lint/typecheck 和 Wrangler dry-run build；
- `workers_dev: false`，无 route/custom domain、assets、数据库/存储 binding 或自动部署；仓库只提交
  `.invalid` issuer/JWKS、无效 audience 与空 principal 清单；
- 只有 `/health/live`、Worker 渲染的静态安全壳和最小 `/api/admin/session`；没有业务 read model/mutation；
- 浏览器只访问 same-origin Worker/BFF，不持有 D1、Gateway、JWT signing 或平台 credential。

Access validator 只接受 RS256，验证 token 大小、issuer/audience/expiration 和 Cloudflare Access `type=app`
语义：human 必须有非空 `sub`；service 必须为空 `sub` 并使用 `common_name`。JWKS 必须与 issuer 同源，
verifier/JWKS cache 按配置有界复用。验证后的 `issuer + subject + human/service kind` 才可映射内部 stable
principal；email 不作 key；unknown/disabled principal 与缺 capability 均 fail closed。

route registry 显式固定 method/path、read/mutation、action、capability、audit 要求，拒绝未注册 route 和 GET
mutation。future mutation seam 同时要求 exact Origin、`Sec-Fetch-Site: same-origin`、custom CSRF header 和 JSON。
服务器安全响应统一使用 CSP/no-store 等 header，不开放 CORS；不可信 text/URL seam 有恶意 fixture，text escape
明确只适用于 HTML text node。

audit envelope 的 actor、authn safe ref、capability/action、event/request ID、timestamp 都从 verified server context、
registered policy 与 runtime 派生；调用者只能提交 strict allowlist outcome，result 固定为
`success/denied/conflict/failed`，错误使用 safe code，拒绝 secret/control character。G3-P0 没有真实 mutation，
所以没有伪造 durable audit sink 已完成的证据。

### 2.3 机械边界与 workspace 编排

当时根 workspace 新增 `check:admin-inventory` 和 `check:admin-boundary`；前者已随一次性 inventory 退役，后者继续
纳入 `workspace:verify`/`ci:verify`。
`scripts/check-admin-security-boundary.mjs` 结构化检查：

- Wrangler 顶层键、deny-all vars、无 route/assets/binding；
- Admin package name 及 `dev/types/test/lint/build/deploy` 全脚本精确值，拒绝 lifecycle/alias 漂移；
- Admin source 不得 app-to-app import，不得出现 credential/private-key material；
- fresh dry-run build 后扫描 dist，拒绝 client/browser/public/assets/static artifact 与 credential；
- G3-P0 workflow 不得直接引用 Admin，包括 command、working-directory、matrix、step action 和 job-level
  reusable workflow；只允许没有 Admin 字面引用的 root workspace orchestration。

`apps/admin` build 顺序固定为 generated types check、TypeScript typecheck、Wrangler dry-run 生成 dist、产物后
boundary scan。根新增 `yaml@2.9.0` 仅用于 workflow 的结构化检查。
