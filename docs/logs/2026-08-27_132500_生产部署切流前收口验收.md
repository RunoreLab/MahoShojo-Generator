## 1. 结论

仓库内可独立完成的生产前收口已完成：D1 战报角色明细不会再因 9–32 行单条 INSERT 超过 100 个绑定参数；

release-local Compose 与 runtime preflight 使用同一 Node 22 Alpine digest；runtime env 在创建部署锁和触碰 Docker 前

当前分支尚不能安全合入默认分支后期待所有 GitHub Actions 成功：Cloudflare production build 会因 stable control
plane 与 production fallback placement 均未就绪而 fail closed；Hono 与 Cloudflare workflow 相互独立，直接合并会有

## 2. 根因与代码收口

### 2.1 D1 参数上限与错误泄露

生产最近 24 小时只读日志计数为：`too many SQL variables` 106 次、`requestBodyValues` 2276 次、`status: 500`
333 次，未发现 unhandled/uncaught 进程异常。失败链定位到
`battle_report_generation_combatants` 的 Drizzle 多行 INSERT：每行 14 个绑定参数，9 行即 126 个，超过 D1 单语句
100 个变量的限制；API 最大允许 32 个 combatant，原实现会产生 448 个参数。

`8ea87c37` 将映射后的行按 7 行分块，32 行形成 `[98, 98, 98, 98, 56]` 五条 statement，并通过同一次
`db.batch()` 保持原子性。数据库 wrapper 对写入和读取失败只使用固定低基数
`combatants-write-failed` / `combatants-read-failed`，测试以 canary 证明日志和返回值不包含原始错误内容。

### 2.2 可重复 runtime 与 secret 文件门禁

生产只读 `RepoDigest` 为
`node@sha256:c610fcdfb1d5b4740dd70c284ed3cb16bb857e0f7166196e36a5501df7a3aa32`。`d6b45dc8`
把 Dockerfile 两个 stage、release-local Compose 与 deploy runtime config check 同步锁定到该 digest；release tuple
checksum 会覆盖 Compose 与部署脚本。更新 digest 必须同步三处并通过 contract test，禁止从 Arcane 单独更新 Hono 容器。

部署脚本现要求 `id`、`stat`，并在 lock/metadata/Docker 之前验证 `.env.hono` owner UID 等于部署 UID 且 mode 精确为
`0600`。0644 与 owner mismatch fault fixture 均在 Docker command log 产生前失败。

## 6. 外部 blocker 与授权条件

### 6.1 Stable control plane / DR placement

在合入默认分支前，需要用户确认变更窗口、控制面方案、观察 owner 与回滚 owner。推荐让
`api.mahoshojo.colanns.me` 成为独立于香港主机的 Cloudflare 受管 stable origin：primary 指向
`homura.colanns.me`，DR 必须先部署包含 readiness/shared adapter 的 Next/OpenNext artifact；health 只用 synthetic
safe/read probe，任何非幂等 operation 均不得透明跨 runtime retry。只有 DNS/control plane、primary/DR readiness、
CORS、D1 binding/session、secret/binding、no-retry 与 cutback runbook 获得真实证据后，才可将 manifest 与 production
evidence 激活，并重跑 production Web build 与安全演练。

### 6.2 Arcane / Docker 控制面

至少需要 Cloudflare Access；不能只依赖 Arcane 登录页。Arcane 继续只绑定 loopback，
docker-socket-proxy 继续只在内部网络，后续还应独立评估 privileged 与 API allowlist 最小化。未经授权不得修改 DNS、
Access、Caddy、firewall、Arcane 或 Docker socket proxy。

## 7. 发布与回滚

- 不建议在上述 blocker 未关闭时合入默认分支：Hono/Cloudflare workflow 独立，可能形成 Hono 已发布、Web 构建失败的
  半发布状态；

- 首次 Hono 新版发布会把精确旧布局复制为带 checksum 的 legacy rollback baseline。candidate config/runtime/local/public
  readiness 或 retained route contract 任一失败，部署事务恢复 previous release-local tuple；信号中断回滚，强制终止则由
  next-start journal recovery 恢复；
