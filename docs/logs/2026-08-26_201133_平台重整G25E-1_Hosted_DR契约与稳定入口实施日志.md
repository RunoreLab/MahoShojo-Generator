## 1. Objective 与 stopping condition

本 Goal 建立长期 Hosted DR 的可维护 contract 面，而不伪造已启用的生产容灾：

- versioned machine-readable manifest 最终覆盖 `23 shared-service / 6 exited / 0 legacy-next`；
- Hono primary 与 Cloudflare native D1 binding/Sessions 实现同一 DatabaseProvider consistency/bookmark contract；
- `GET|HEAD /api/hosted/dr-readiness` 在 Hono/Next 复用同一 application service；
- Web 客户端只消费 stable-origin-only 投影，production Next route 统一 fail-closed guard/CORS policy；
- non-idempotent 已 dispatch/outcome unknown 不透明重放，外部控制面维持 `not-provisioned`。

实施前按 G25H-2 最终代码重估为 5–6 小时。所有 G25E-1 stopping condition 已满足；G25E-2 故障矩阵和
production control-plane activation 没有提前执行。

## 2. 关键设计与实现

### 2.1 Machine contract 与稳定入口

`config/hosted-dr-capabilities.json` 以 `schemaVersion=1`、`contractVersion=g25e1-v1` 登记 operation method、
request/replay class、secret/binding、双 provider、consistency、contract/drill 与 control-plane 状态。validator 双向
核对 route inventory、adapter、generated registry、test、guard、客户端投影和构建脚本；非法 replay、secret 值、
route drift、伪 production 或客户端物理 origin 泄漏均 fail closed。

Web 只导入生成的 `hosted-dr-client.generated.ts` 稳定入口投影；primary/DR origin 留在 server/tooling contract。
production `build` 与 `build:cf` 都先运行 `check:hosted-dr`。

### 2.2 DatabaseProvider 与 safe-read 双入口

Hono provider 复用现有 primary HTTP client、保留输入 bookmark lineage 且不伪造新 bookmark；只有 transport 原本
允许的 safe read 可以 retry。Cloudflare provider 使用原生 `DB.withSession()`：按 consistency 选择
`first-unconstrained` / `first-primary`，或以输入 bookmark 延续 session；缺 binding/Sessions 时 fail closed，
production 不回退 Hono Gateway/management API。非 production 本地开发保留显式 legacy HTTP adapter，但不伪装
provider ID，也不构成 DR PASS 证据。

readiness service 固定执行 `SELECT 1 AS ok`，返回最小公开 contract/placement/provider/consistency，HEAD 保持同 header
且无 body；provider/query 失败为固定 503。Hono readiness 绕过 Redis limiter，避免 Redis 故障污染 D1 capability 探针。

### 2.3 Authority、CORS 与 replay

23 条 shared Next route 均在 production service dispatch 前经过 capability guard。guard 拒绝未知/`fail-closed`
drMode、缺 secret、D1/R2 binding/provider/session 与非法 cross-origin 配置，不调用业务 handler，不 fallback/retry；
Scenario 要求原生签名 secret，Arena terminal 读取要求 D1 与 R2 logical binding。Hono/Next 共用 manifest 指定的
`HONO_CORS_ORIGINS` policy，production 拒绝空值、`*`、HTTP、localhost/loopback 与非法 origin，OPTIONS 与实际
response 使用同一规则。

runtime selector 是无 I/O 纯函数。safe read 可在 primary unavailable 且尚未 dispatch 时选择 DR；非幂等新请求只在
`not-dispatched` 时允许 `new-request-only`，`dispatched/unknown` 一律 fail closed。客户端、guard 和 provider 均不
实现跨 runtime 重放。

## 5. Builder self-review

Builder self-review 发现并在独立审查前关闭：

- 直接把完整 manifest 导入客户端可能携带物理 origin：改为生成 stable-origin-only 投影并扫描 chunk；
- readiness 若经过 Redis limiter 会把 Redis 故障误报成 D1 不可用：改为独立 safe-read adapter；
- malformed D1 result 不能视为成功：provider 返回 `success=false`；
- guard provider/session 抛错不能穿透为 500：统一固定 503；
- 新 fixture 改变 naming 数量：修复 fixture，workspace 基线恢复 1376；
- manifest/application contract version 可能漂移：新增机械一致性门禁。

- Architecture：初审 Important 为 Hono/Next CORS parity 和最终日志缺口；修复 shared policy、文档后复审又发现 wildcard
  宽松度漂移，`70aa1ab6` 关闭。最终 Critical 0、Important 0、Minor 0，stopping condition PASS。
- Security/authority：对 direct DR 新请求与 `NODE_ENV` 本地 bypass 提出质疑。复核确认前者仅允许控制面尚未 dispatch
  的新 operation，不是未知 POST replay；后者是 server/build-time 选择，不能由 HTTP 输入控制，并有 production
  default fail-closed 测试。补齐 unknown drMode 后，最终 Critical 0、Important 0、Minor 0，PASS。
- Compatibility/replay/data/test：初审 6 个 Important 中，CORS、Scenario signature、Arena R2、local HTTP fallback 与
  data-driven guard matrix 已关闭；外部控制面 no-retry/fault proof 按 accepted scope 明确 DEFERRED 到 G25E-2，
  `provisioning=not-provisioned`，不是 G25E-1 open finding。最终 Critical 0、Important 0。

兼容性复审保留 2 个不阻塞 Minor：validator 对 generated registry 只核对 capability ID，guard wrapper source gate
主要用静态字符串匹配。处置理由是 route generator 自身测试已锁定 import/method/adapter 形状，DR validator 的职责是
双向 ID coverage；运行时 data-driven matrix、精确 route ID、route generation、完整 API/Web tests 与 production builds
共同覆盖实际行为。为避免复制第二套易漂移 parser，本 Goal 不扩张该 Minor；G25E-2 总退出审计可在真实 fault harness
中重新评估。最终阻塞 finding 为 0。

随后针对当前 HEAD 的复审发现：production Next guard 只在请求带 `Origin` 时校验 CORS，会让无 `Origin` 的请求绕过
配置门禁并造成 readiness 假阳性；同时发现本日志对最终分支 push/preview deployment 的记录不完整，以及 production
evidence 只检查文件存在。前两项分别由 `7ceea461` 与本日志修订闭合，evidence gate 由 `f8e528bf` 闭合；当前
