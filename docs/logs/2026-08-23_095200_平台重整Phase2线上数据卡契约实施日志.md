- 实施范围：完成 Phase 2 的一个独立共享契约切片——建立线上数据卡类型、审核状态和可见性的 canonical wire contract，并接入现有 Web/API/数据库适配路径；未引入完整数据卡内容 schema，也未声称 Phase 2 整体完成。

## 本批完成

- 为 `@mahoshojo/contracts` 新增显式 `./data-cards` 子入口，同时从 package 根入口导出：
  - 线上类型：`character / scenario / history / questionnaire`；
  - 审核状态：`pending / approved / rejected`；
  - 可见性：`-1 / 0 / 1`，分别保持封禁、私有、公开的既有整数枚举语义。
- `app/api/data-cards` 创建入口使用共享 Zod schema 校验不可信 `type`，并把校验后的值传入问卷净化和数据库写入；错误状态与错误文案保持不变。
- `app/api/public-data-cards`、浏览器读取 mapper、公开卡缓存 mapper、Drizzle schema 与数据卡/审核/技术指数/收藏 repository 改为复用同一类型或 runtime schema。
- Web API 客户端和主要数据卡 UI 改为消费共享类型与枚举常量，移除线上四类型的并行 union 定义；`lib/schemas` 中还包含 `canshou/general` 的内容/模板类型刻意保留为独立内部边界。
- 可见性 compatibility mapper 继续接受历史 boolean 与数字字符串输入，但 normalized 数字只允许精确的 `-1/0/1`；其他整数与小数 fail-closed 为非公开，避免无效值继续传播。
- 创建/更新 API 会对写入可见性执行同样的严格校验，DB facade 与核心 repository 再次检查 invariant；契约外数字、小数和字符串请求统一返回 `400 无效的数据卡可见性`，不会落库。
- root manifest 以 `workspace:*` 显式声明 `@mahoshojo/contracts` 生产依赖，lockfile 已同步；`packages/README.md` 同步记录当前真实契约覆盖面。
