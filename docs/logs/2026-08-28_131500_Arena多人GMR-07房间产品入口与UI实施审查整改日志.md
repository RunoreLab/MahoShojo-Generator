## 3. 关键设计与权威边界

### 3.1 单入口与激活门禁

- 多人 UI 只挂载到既有 `/arena`；`/arena-stream` 明确关闭。
- `ARENA_MULTIPLAYER_ENABLED` 默认 `false`；production/preview 配置若尝试开启会在启动时拒绝。
- flag off 或未登录时不会调用 Room auth endpoint、HTTP client 或 WebSocket。

### 3.2 Server authority 与非幂等 unknown

- 所有 mutation 使用受信 actor、strict body、exact Origin/cookie guard、Redis fail-closed rate limit 与 `no-store`。
- create/join 从同一次已提交 authority state 直接返回 session，不在成功 checkpoint 后追加可失败读取。
- 网络异常、5xx 或无法解析的成功响应都映射为 `ROOM_RESULT_UNKNOWN`；客户端不自动重放 create/join。
- unknown create 会冻结后续 create，且不会因 discover、失败 join 或加入另一个房间被静默清除；只有显式 reset
  或 access transition 可以重新授权操作。unknown join 使用独立状态，不会污染 create fence。
- leave/close wire 必须携带 `expectedRoomEpoch`；service 与 actor command 使用同一 fence，旧 incarnation 的退出命令
  不能影响 recovered room。

### 3.3 Reconnect、role 与 safe projection

- ticket role hint 必须与 current membership 一致，且漂移检查发生在 jti 消费之前。
- reconnect 每次获取 fresh ticket，并携带最近 control cursor；不会自动重放业务 mutation。
- 只有已验证的 control frame 才重置 reconnect budget，反复 post-open `1013` 不会形成无限连接风暴。
- membership revoked 转 replacement；room epoch stale 重新取 session；其他 policy close 进入 degraded reconnect。
- Browser 只从 `ArenaRoomSharedConfig` 白名单生成/应用投影；完整本地/私有卡、`userProviderConfig`、API key、
  generation result 与 UI-only state 不进入 Room 请求、snapshot 或日志。
