## 1. Objective 与 stopping condition

本切片为 `apps/api` 建立当前官方 Hono Node + `ws` 的 Room WebSocket transport/security skeleton：versioned
path/protocol、独立 upgrade middleware、Origin/handshake/schema/bytes/rate/cap 防线、heartbeat/dead cleanup、有界发送
队列、slow-consumer close/resync，以及和既有 HTTP/RoomActor/Redis 一起工作的 graceful shutdown。

stopping condition 已闭合：真实 Node upgrade/fault regression、完整 API/contracts/workspace CI、production bundle/build
与三路独立终审均通过；最终 Critical/Important/Minor 为 `0/0/0`。本切片没有实现 ticket、membership、reconnect、
Room 产品 UI、production hostname/routing 或 production activation。

## 2. 关键设计与 authority 边界

- `packages/contracts` 增加严格 versioned transport envelope；client 当前只允许 `room.resync.request`，server skeleton
  只返回 `room.resync.required`，reason 使用 allowlist，raw UTF-8 bytes 在 JSON parse 前受 64 KiB 上限保护。
- Node 使用 `@hono/node-server` 当前 `serve/upgradeWebSocket` 与 `ws.WebSocketServer({ noServer: true })`；禁用
  `perMessageDeflate`，`maxPayload` 与 contract 上限一致，未引入 deprecated `@hono/node-ws`。
- Room WSS app 与既有 request metadata、secure headers、CORS、Redis HTTP rate middleware 隔离；dispatcher 仅按精确
  versioned path 分流，真实 upgrade 与普通 HTTP regression 共同验证。
- raw Node method、key/version、protocol grammar、canonical subprotocol、exact Origin 在 authorizer 前校验；Origin
  缺失只允许 installed client 继续进入 authority，不赋予任何信任。
- pre-upgrade grant 不进入 gateway pending map/cap；module-private brand 使其不可由客户端构造，claimed 状态保证只用
  一次，成功 `onOpen` 才同步检查并占用 active per-user cap。并发握手最多一个进入，超额连接以 1013 关闭。
- message 使用 strict schema、connection/user 双 rate window、binary/oversized/malformed 固定 close policy；outbound
  bytes 同时计入 `bufferedAmount` 与队列/in-flight，饱和后以 `resync-required` 关闭，不能无限缓存。
- 单一 process heartbeat sweep 发送 ping、等待 pong、终止 dead socket；shutdown 先停止/关闭 WSS，再等待 HTTP server
  close，活动连接收到 1012，超时后 terminate，避免 upgrade socket 卡住 server lifecycle。
- `main.ts` 使用空 browser Origin allowlist 与默认 deny authorizer。browser 固定 403、无 Origin client 固定 503；
  只有测试注入 authorizer 可以成功 upgrade，未提前实现或绕过 GMR-05 ticket/membership。

## 6. Independent review 与关闭状态

首轮三路独立审查发现：

- Important：`@hono/node-server` 重建 upgrade Request 时未保留原始 method，`POST + Upgrade` 会在底层 405 前调用
  authorizer 并占用 reservation；改为从 raw `IncomingMessage.method` 在 auth 前拒绝。
- Important：key/version/malformed protocol 等底层握手失败不会触发 Hono socket events，pending reservation 只能等
  TTL，攻击者可阻塞同用户合法重连；移除 gateway pending state，使用一次性私有 grant，并在 `onOpen` 原子占 cap。
- Minor：真实 cap 测试未覆盖 first socket close 后重连；新增真实 close event 等待与立即 reconnect。
