## 3. 关键设计与权威边界

### 3.1 Contract、actor 与 DataCard ownership

- submit/resolve/withdraw 仅接受 strict versioned DTO；room/author/status/time/account/role 由服务端派生，response 只返回
  对账所需的 room/epoch/seq/revision/proposal/status/result。
- service 只在 `await actor.execute` 成功后返回；Redis CAS conflict/failure/throw 不会产生过早 ack。save-result
  unknown 会 quarantine 旧 Actor，旧 Actor 不再服务 snapshot/session；下次权威读从 Redis 恢复新 epoch，
  不重放 mutation。
- D1 verifier 只选择 metadata，不读取/返回/记录 `data`；public approved 或 Room host-owned readable card
  才能通过。member private card 不因加入 Room 获得共享权限。resolve 在同 revision 上纯应用 selection 后重验
  resulting config 的全部 online refs。

### 3.2 Viewer projection、replay 与 public wire

- Redis checkpoint 保存 host review 所需的完整 typed Proposal；HTTP/WSS adapter 按 host/all、author/own、other/no-foreign
  投影。host-local/private full payload、Provider config 和 credential 不进入 public snapshot/event。
- replay entry 仅持有 terminal event 的最小 author projection context，不进入 wire/checkpoint。mixed replay 逐 event
  投影；foreign Proposal 转换为同 `controlSeq` filtered snapshot，不泄漏 ID/changes/expectedBase，也不吞掉
  author 自己的 terminal event。
- Room mutation 仅认 literal exact Origin allowlist，Hosted wildcard CORS 不授权 Room write。withdraw 对 foreign/
  absent/terminal 统一公开 `ROOM_PROPOSAL_NOT_FOUND`；`proposalId` 拒绝精确 `.`/`..` path identity。

### 3.3 Web working copy 与 no-blind-replay

- member 只编辑 `ArenaRoomSharedConfig` 白名单 working copy，preview 用 canonical diff/selection/dependency/atomic
  规则；client conflict 仅作提示。dirty draft 不被新 config event 静默覆盖。
- network/5xx/malformed 2xx 均进入 unknown，内部 fence 绑定 operation/proposalId。unrelated Proposal event 只推进
  projected snapshot/cursor，不解锁也不自动 retry。
- 显式 reconnect 在 WSS cursor 已 current 时先 `GET session` 取权威 projected snapshot，再使用 fresh ticket
  重连。snapshot 或同 ID 对应 control event 可完成对账，原 mutation 不重放。
