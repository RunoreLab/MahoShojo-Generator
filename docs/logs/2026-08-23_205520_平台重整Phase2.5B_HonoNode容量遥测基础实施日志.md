## 实施内容

- 新增 `HonoRuntimeTelemetry`，默认每 60 秒导出一行固定 `schemaVersion=1`、`event=hono.runtime.telemetry` 的 JSON。定时器使用 `unref()`，不会单独阻止进程退出；优雅退出时再导出一次最终快照。
- process 快照包含累计 user/system CPU 时间、采样间隔 CPU utilization、uptime、RSS、heap used/total/limit。
- event-loop 快照使用 Node `performance.eventLoopUtilization()` 与 `monitorEventLoopDelay()`，导出 utilization、active/idle 时间、delay samples/mean/p99/max。
- request 在 Hono middleware 进入时计数，无论 handler 成功或抛错都在 `finally` 释放；streaming response 在响应体消费完成、cancel 或读取异常时释放；Node socket 在 `close` 时释放。三者都记录 active 与当前采样周期 peak。
- stream 识别仅接受 `text/event-stream`，或成功响应中明确为 `stream` / `*-stream` 的 route segment；不使用宽泛 substring，也不把 stream route 的 JSON 错误响应计为活跃流。
- snapshot 只包含低基数系统指标，不包含 URL、request ID、用户标识、header、Prompt、输出或环境凭据；不增加公网 `/metrics` endpoint。
- Hono 进程只能确定自身 origin 是 `hono-node`，无法直接观测当前请求是否由入口层选中；因此 `runtime.selection` 明确为 `not-observed`，不用“目标角色是 primary”伪造“实际选择了 primary”。
- 日志 transport 导出失败会 fail-soft：记录本地错误但不影响 request handling、readiness 或 process liveness。内部采样周期拒绝小于 1 秒、`NaN` 或无穷值。

## TDD RED / GREEN 证据

- 在生产 module 存在前新增 `tests/server/runtime-telemetry.test.ts`，targeted Vitest 因 `@/server/telemetry/runtime` 不存在而 RED。
- 实现初版后，针对独立审查提出的三项风险再先改测试：要求 `selection=not-observed`、单行 JSON，并拒绝将 `upstream` 子串误判为 stream；测试按预期出现 3 个 RED，实现收紧后转绿。
- 针对 stream route 的 JSON 429 错误响应补先行测试，初版识别逻辑返回 `true` 而 RED；收紧为成功响应 route segment 后转绿。
- 针对无效采样周期与 fail-soft 导出补先行测试，初版未拒绝 `0` 而 RED；完成校验与错误隔离后转绿。
- 最终独立审查发现 sink 瞬时失败时若不 reset peak/delay，会与已经前移的 CPU/event-loop baseline 形成不一致采样窗口。新增“sink 失败后恢复”用例后复现下一周期 peak 仍为 `2` 的 RED；改为无论导出成败都在 fail-soft `finally` 中 reset 后，恢复周期 peak 为 `1` 并转绿。
- 测试同时覆盖 active/peak gauge、周期 start/stop 幂等、socket close/detach、stream complete/cancel/error 的 once 释放、环境 secret canary 不出现于导出内容。

## 未完成项与边界

- AI upstream active、TTFB/total duration、abort/timeout 尚未从统一 AI 调用 seam 接入。
- D1 round trips、latency、rows read/written、error class 尚未从 Gateway/provider adapter 接入。
- Redis latency、error、hit/miss、memory/eviction 尚未从 `RedisService` 与服务端 INFO 采样 seam 接入。
- runtime origin 已真实导出，但 DR selection/failover reason 必须由可信入口控制面传入，当前不做推断。
- 本批不设容量告警阈值。accepted 计划要求先记录真实生产基线，再冻结阈值；当前无基线时不凭空填写数字。
- 仓库自动测试已覆盖 Web `Response` 消费/cancel/error 与 `EventEmitter` socket 生命周期，但尚未固化一条真实 TCP + `@hono/node-server` 客户端 abort 集成用例；审查期间的临时验证已通过，后续可在不依赖 Redis/D1 的本地 server harness 中将其固化。
