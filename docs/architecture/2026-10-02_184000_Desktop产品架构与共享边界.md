## 1. 产品定位与当前差距

Desktop 是同一 MahoShojo 产品的本地运行时：熟悉的首页、问卷与角色卡，本机持有内容和 Direct AI 能力，按需访问服务器。它不是新游戏前端，也不是网站快捷方式。

截至 2026-10-04：`apps/desktop/src/app/App.tsx` 是产品壳组合入口，D0 的运行时/Provider 面板在 `/settings`；`packages/ui-web` 提供共源主题、产品导航、能力状态、壳、归档视图、首页展示、百科、问卷控件及角色结果正文。Desktop 已接入本地首页、百科目录/条目和 `/local-library` 整库导入导出及备份恢复；产品内容只跟踪 `content/`，由两端构建生成静态副本。D3.1 已接入 `/details` 默认问卷、Direct 生成/取消、显式草稿恢复及本地卡库保存；D3.2a 已在两端 `/local-library` 接入共源本地数据卡列表、详情与回收站；D3.2b 抽取共源字段编辑器（Web 角色管理回用），Desktop `/character-manager` 提供角色/情景卡本地编辑与单卡导入，模板转换、schema 校验、原生性与敏感词仍只在 Web。旧文档对 `/battle`、`/arena` 的 PVP 误称已纠正，二者的 Desktop 能力后续按 D5 接入；已退休的 `/pvp` 不恢复。`cloud-client` 仍未建立，真实 Provider 与 Tauri 完整生成旅程尚未验收。真机证据和精确进度以[阶段计划](../plans/2026-09-30_160100_Desktop客户端阶段实施计划.md)为准，不以代码落地代替验收。

首轮完整旅程是：打开首页 → 进入问卷 → 使用已配置模型生成 → 查看/编辑角色 → 保存本地。百科、本地库与设置支撑该旅程。无账号也能完成本地流程；未配置 AI 只影响生成，不封锁阅读、填写、导入与管理。D3 本地纵切不包含 Arena；Arena 的单人/严格排位/多人按 D5 另行验收。

## 2. 共享层与组合入口

```text
apps/web：Next route / metadata / Web bootstrap / 浏览器适配
       \
        +-- ui-web：页面、React DOM 组件、功能 hooks、主题、产品资源
       /          |                    |
apps/desktop      |                    +-- 按需注入的导航/在线/文件/渲染适配
Vite + Tauri      |
组合入口          +-- domain / contracts / ai-core / ai-direct
平台检测          +-- local-library / web-package
       |
       +-- Rust：受控 HTTP / OS secret / SQLite / blob / IPC ACL
```

这里的共享是源码归属，不是运行时共享内存、数据库或登录态。Web 和 Desktop 保持各自构建部署单元，不直接引用另一个 app 的目录。

### 共享的最小单元

`ui-web` 从真实切片生长，先承载主题、首页导航和百科所需的组件，再按 feature 子路径增加问卷与卡片；其他能力待实际消费者出现后提取。React/ReactDOM 版本由 workspace 协调，避免双份实例。框架专用 route loader、Next metadata、Tauri import 不进入共享模块。

纯 Prompt、schema、解析与修复进入已有 `ai-core`/`contracts`/`domain`；有 UI 生命周期的 hook 可以留在共享 feature。Rust 不重写这些业务规则，也不把服务器 `hosted-runtime` 打进桌面端。

不为每个按钮建立 port。只有访问运行时资源或信任边界的位置需要适配；端口名称与 DTO 尽量沿用现有公共 contract。需要多个实例或新消费者时才拆额外包，不先做服务定位器、插件注册表或全局任务平台。

### 代表性边界

| 边界 | 共享内容 | Web 适配 | Desktop 适配 |
| --- | --- | --- | --- |
| 导航 | canonical 路径、查询参数、导航展示、离开意图 | Next Link/router，SSR metadata 留 app | 本地 SPA router，native close 单独协调 |
| 本地卡/包 | 记录、摘要、归档、repository contract | 现有 IndexedDB | 现有 typed IPC + SQLite/blob |
| 生成 | 业务输入、Prompt、结果/错误/流事件及执行选择 | 原 Hosted / 预设 BYOK 接入保持 | 默认 `AiExecutionPort` → Rust Direct；D5 另接固定项目生成适配 |
| 线上服务 | 公开 DTO、错误与受支持能力 | 现有 Web auth/HTTP | 显式 cloud adapter，独立认证与凭据边界 |
| 文件 | 选择/确认/进度/结果展示 | input 与 downloadBlob | input 与受控导出；不扩成任意路径读写 |
| Web 战报 | 内容契约、执行许可文案、overlay、导出选择 | 既有 browser materialization/iframe | 独立零 capability webview + resolver |

产品的 capability 状态描述“可用、未配置、需登录、离线、尚未实现”等原因。它不授予 native 权限，不替代服务器校验，也不能只靠 CSS 隐藏敏感操作。共享 UI 不直接探测 Tauri 全局对象；bootstrap 选择 adapter 后，业务层只使用被提供的能力。

## 3. 页面与信息架构

下面是产品覆盖矩阵，不是复制全部路由注册表。已共用页面的 canonical route 与导航文案按真实切片提取为共享源；首页 renderer 与展示类型共享，功能 inventory 由宿主提供，不把 Web 全量功能清单提升为 Desktop 交付承诺。路径别名和旧链接兼容需按实际入口测试。

| 页面/旅程 | 共源目标 | Desktop 本地/在线边界 |
| --- | --- | --- |
| 首页 `/` | 品牌、功能分组、入口、亮暗主题、顶部导航 | 本地资源冷启动，不等待 auth/公告/统计；只显示真实可用入口或清晰说明 |
| `/details` 及后续生成页 | 问卷、条件题、批量答案、结果卡、取消/错误 | 草稿与结果本地；默认 Direct；未实现 Provider 模式说明原因 |
| `/character-manager` | 查看、编辑、导入导出、选择与保存 | 默认本地数据源；线上库以显式 tab/动作接入；不强制登录 |
| Arena `/battle`、`/arena` | 既有单人/严格排位/多人页面按 D5 抽共享 | 默认客户端；Strict/多人按规则锁服务器；已退休 `/pvp` 不复活 |
| `/encyclopedia` 与条目 | 目录、搜索、Markdown 展示、内容与链接 | 内置文本和必要资源随安装包发布；外部链接有明确联网含义 |
| 设置/库维护 | 复用可共享控件，不另建视觉体系 | Provider、凭据存在状态、导入导出、审计/备份等；调试信息不占首页 |
| 账号/线上库/排行榜/多人 | 按原产品布局逐项接入 | 在线与认证能力，失败不封锁本地功能；无签名申请页 |
| Creator/情景/自由生成/茶会/工坊等 | 总体遵循同一产品规则 | 按各 feature 的实际需求后续纵切，不将完整功能集硬塞入首期 |

已退休的功能不会因追求一致性复活。暂未接入的长尾在线页面可以显式用系统浏览器打开，但不能通过 remote WebView 获得主 UI 的 IPC，也不能把失效链接伪装成已经支持。

### 主题与静态资源

以 Web 已有品牌、`--app-*` 主题、蓝色问卷主题、控件与 Modal 体验为源。抽取后 Web 与 Desktop 同时消费；Desktop 临时 dark tokens 随对应切片退出，不制造两个需要人工同步的主题。

图片、百科、预设、样式与字体按真实依赖提取到有明确所有权的共享资源入口，只跟踪内容权威，生成副本由 Git 忽略并在开发/构建前复制打包，不运行时读取 `../web/public`。框架专属 SEO 文件留 Web。不得全量复制 public、`.local` 目录或临近仓库私有素材；检查资源许可、路径、打包体积与 Tailwind 对共享源码的扫描范围。

Web 的 `AppProviders` 不是可直接复用的产品壳：公告、账号探测、统计、云端徽章、远端图片与 Turnstile 必须按能力挂载。只共享导航外观并不能证明离线启动已达成。

## 4. 执行位置、AI 配置、数据与信任

```text
界面：AI 执行 = 客户端 | 服务器（与流式/非流式独立）
执行契约：既有 AiExecutionMode / AiExecutionPort
AI 配置：项目预设 + 用户偏好，或 Desktop 用户自定义连接 + 模型/参数
数据：device-owned | cloud-user-data；来源和存储位置分别表达
信任：既有 signature/provenance / 服务器资格，不由位置或 UI 选项授予
```

这些维度独立。下载到本地的卡不必丢失已有签名；本地模型的有效 JSON 不会因为上传成功而自动变成官方原生。卡槽、公开审核、权限和严格排位在服务器重新判断。

公开 Provider 知识继续来自 `ai-core`；预设不可原位改连接字段，复制为用户自定义项后才可修改。用户偏好/secretRef 与目录分离；一次解析后的执行配置不是第二份持久化权威。Web 本轮不开放自定义连接；Desktop 旧 Profile 的 ID/Key 引用按显式迁移保留。schema 和物理表的拆分只随实际切片确定。

System Default 是服务端策略而非 Direct Connection；旧 `system` wire 做兼容映射。服务器仍可接受预设 BYOK，专用生成适配是用户明确授权的 Key 传递边界，普通账号/库/消息适配不带 Provider Key；三条通路不合并成通用代理。

用户主动进入严格排位/多人场景时，在 dispatch 前锁服务器并显示原因，退出后恢复普通偏好；选择本身不生成/上传。单次生成开始时确定执行路径和输入快照；执行中不因连接失败、能力刷新或组件重挂载而切换 Provider、改用 Hosted 或重发付费请求。设置中的默认路径不是对任何自动回退的授权。错误展示应区分执行失败、取消、输出未校验通过、本地保存失败和附加在线操作失败，保留可恢复正文而不伪造成功。

### 复用既有数据源 UI

Web 的 `BattleDataModal` 已整合本地/线上来源；D5 提取其展示与可复用控制逻辑，保留调用方页签限制、筛选、分页、详情和动作集。数据源分别接 IndexedDB/SQLite 与项目在线适配，而不是重做 Desktop 库弹窗。Web 包仍走既有独立 `WebPackagePickerModal`，不混入数据卡契约。TopBar/首页/问卷遵循同样的提取路径；共享展示不携带宿主网络 bootstrap。

### 本地与云端副本

用户默认保存本地，可以显式上传/下载副本。首期不做自动双向同步、冲突合并、云端删除传播或持续 outbox。退出在线账号不删除设备所有的数据；切换账号时只清理对应在线会话/缓存，不能把用户本地库当缓存淘汰。

Web 浏览器站点存储和 Tauri 应用存储彼此独立，迁移使用已有 portable archive，不暗中读取浏览器 profile。不同数据源的同名记录不自动覆盖；既有摘要、ID、tombstone、归档 existing-wins 与服务器重验语义保留。

### 草稿、会话与历史不是自动完成的 D2 工作

D2 的本地卡/包存储不等于已迁移所有问卷草稿、Arena 历史、茶会会话与 UI 偏好。每个 feature 接入时先列明其持久化 owner、恢复入口与导出范围，复用既有语义，仅补需要的 adapter。存储初始化失败不能悄悄改写到另一数据库或降成易失内存后仍显示“已保存”。

备份/导出 UI 明确覆盖范围；未包含的会话或设置不得称已备份。Provider 明文与账号凭据继续排除在可移植归档之外。跨库一致性确有需要时再单独设计，不以“整体规划”为名预建全设备同步与迁移引擎。

## 5. 生命周期与原生体验

浏览器路由切换、刷新、窗口关闭与进程退出不是同一事件。共享页面定义是否有未保存内容/在途生成，宿主分别处理导航阻止和 native close；不能只依靠浏览器 `beforeunload` 声称原生关闭安全。

首期优先保证关闭前提示、取消真实中止上游、终态与可保留内容有一致归属。是否允许切页继续生成在对应 feature 切片中明确；在没有可恢复任务 owner 前不承诺后台继续、杀进程后续传或自动重试。无需预建托盘、全局快捷键、多窗口工作区或守护进程。

键盘导航、输入法、焦点返回、滚动恢复、窗口缩放与高 DPI 属于用户旅程验收。UI 共源不是只测 Chromium；Windows x64 是首发验收宿主，其余平台正式纳入时扩展系统 WebView 矩阵。

## 6. 不可信内容与在线接入

Markdown 的受控组件、模型原始文本与可执行 HTML 区分。Web Package 及原生 HTML 不进入主 UI DOM/iframe；Desktop 共享渲染控制和结果格式，但 native hosting 继续依照运行时安全规格。任意新增 webview（包括未来在线页面）都先验证自有 command ACL，不只检查 capability 文件名。

D4 的顺序是 AppManifest command 列举与主 UI 最小权限 → 独立零 capability webview → resolver 与浏览器权限默认拒绝 → 真机攻击面验收。包内资源不反向访问本地库、vault 或任意设备路径；共享 renderer 不向不可信内容泄露宿主引用。

在线功能通过独立的固定项目服务能力进入，不将项目域名加入 Direct Profile 来复用 AI transport。认证接入先验证实际 API、Origin/CSRF、挑战页、系统浏览器回跳与凭据持久化；不能假定 Next 同源 Cookie/localStorage 代码可原样搬入 Tauri。认证与 Provider secret 分开，取消登录、失联、注销不影响本地能力。尚无通过验证的认证路径时，可以保留明确的浏览器入口，不偷偷加载远端主 UI。

## 7. 签名、更新与发布

Desktop 首期无新数据卡签名机制，也无手动申请按钮。已有签名依照既有格式携带；未经服务器验证的来源不能显示为已验签。未来仅在独立可信协议成立后，按默认关闭的设置自动请求；签名失败不损失本地结果。这与 updater 校验和 OS code signing 完全分离。

源码共源带来的同步发生在构建/发行时，不是把 Web 的更新脚本热灌到已安装客户端。线上 API 使用已有版本化契约；旧客户端遇到不支持的能力要有可诊断结果，不能误提交不同语义的数据。升级回退涉及数据库兼容时遵循 D2/D5 的既有恢复与发行设计，不默认安全降级。

保留稳定安装包、数据与备份边界；不让未完成功能、自动签名、macOS/Linux 或所有社区页面成为 Windows 本地 MVP 的隐性前置。发行时必须明确本次支持范围、已关闭门禁与仍延期能力。

## 8. 迁移策略与非目标

从实际叶子功能开始：主题/导航/Home/百科 → `/details` 业务与 Direct → 本地角色管理 → 安全 Web 内容渲染 → 按需在线能力。每个切片先让 Web 回用共享源，再接入 Desktop，保留可构建/可回滚的提交。本轮 D5 纳入 Arena，旧 D3.3 取消记录保留；已退休 `/pvp` 不在迁移路线内。

D2 存储机制与只读共享壳可按依赖并行；D2.3d 使用的最小壳不要求 D2.4 先完成，避免循环依赖。完整用户生成旅程则必须关闭它实际使用的 D1/D2 门禁。具体阶段、交付与回滚只在实施计划维护。

非目标：换掉 Next、内嵌服务器、Rust 重写领域、一次抽取全部组件、额外设计系统、默认 Hosted/签名回退、自动同步、模型下载管理、远端 UI 热更新，以及照搬邻仓的完整技术栈与游戏架构。
