# 预览环境自动部署说明

## 发布边界

`preview` 分支的每次 push 都会触发 `.github/workflows/preview-deploy.yml`。合并 PR 到 `preview`
同样会产生 push，因此会进入流水线。流水线先运行完整测试并构建 Hono 与 Cloudflare bundle；只有
`config/preview-environment.json` 已切换为 `provisioned` 且所有专用资源/输入通过门禁后，才允许部署。
当前状态是 `not-provisioned`，所以 workflow 会在部署前 fail-closed，不会连接 VPS、发布 Worker 或写入数据。

生产与预览的运行边界如下：

| 配置 | 生产 | Preview |
| --- | --- | --- |
| Hono 域名 | `homura.colanns.me` | `homura-preview.colanns.me` |
| VPS 目录 | `/opt/mahoshojo-hono` | `/opt/mahoshojo-hono-preview` |
| 容器 | `mahoshojo-hono` | `mahoshojo-hono-preview` |
| 回环端口 | `8080` | `8081` |
| Redis 网络 | `mahoshojo-redis` | `mahoshojo-redis`（首期允许共享） |
| Redis key 前缀 | 空 | `preview` |
| D1 | `mahoshojo` | 未纳管；启用前必须使用独立 D1 |
| R2 / finalization / 签名 | 生产 authority | 启用前必须使用 preview 专用 authority 输入 |

## GitHub 首次配置

创建 GitHub Environment `hono-preview`，只允许 `preview` 分支部署，并添加 preview 专用输入：

- Variable `PREVIEW_VPS_HOST`、`PREVIEW_VPS_USER`（`PREVIEW_VPS_USER` 不得为 `root`）；
- Secret `PREVIEW_VPS_SSH_PRIVATE_KEY` 与 `PREVIEW_VPS_HOST_KEY`，不得复用生产部署 secret；
- Variable `PREVIEW_D1_DATABASE_ID`、`PREVIEW_REDIS_NETWORK_NAME`、`PREVIEW_REDIS_KEY_PREFIX=preview`；
- Variable `PREVIEW_DATA_ENVIRONMENT=isolated`、`PREVIEW_REDIS_ISOLATION=prefix`、
  `PREVIEW_ENV_FILE_PATH`。

现有 `preview` Environment 继续保存 Cloudflare 凭据和构建变量；公共 `NEXT_PUBLIC_*`、Turnstile site key、GA ID、
非敏感 feature flag，以及明确接受 quota/billing 耦合的 AI provider 输入可以共享。D1 Gateway authority、
签名、Arena finalization、R2 写入凭据仍按后果隔离，不能从 production `.env.hono` 复制。

## VPS 首次初始化

首次发布前必须准备与 production 分离的 preview runtime env 文件，且不能从 production `.env.hono` 复制：

```bash
install -d -m 755 /opt/mahoshojo-hono-preview/releases
install -m 600 /secure/preview/mahoshojo-hono-preview.env /opt/mahoshojo-hono-preview/.env.hono
```

首期不需要创建第二套 Redis。Preview 容器可以加入现有 `mahoshojo-redis` Docker 网络，但工作流必须传入
`REDIS_KEY_PREFIX=preview`，且应用 runtime 不暴露 `FLUSHALL`、`FLUSHDB`、任意 `sendCommand` 等 destructive
Redis port。该方式是逻辑隔离而不是权限隔离：Redis 可用性、容量、quota 仍与 production 耦合，后续可按风险升级到
Redis ACL、独立 container 或完全独立 Redis。限流键使用 `mahoshojo:rate-limit:preview:api:*` 和
`mahoshojo:rate-limit:preview:auth:*`；可恢复生成状态使用 `mahoshojo:gen:v1:preview:*`，不会与生产
限流窗口或进行中的生成状态碰撞。不得用无前缀 Redis key 读取、删除或改写生产状态。

Preview D1 必须在 `apps/web/wrangler.jsonc` 的 `env.preview.d1_databases` 中显式登记独立 ID，并同步
`config/preview-environment.json` 状态和 GitHub Environment variable；当前该数组为空，避免 Wrangler 继承
production binding。Preview Hono 的 `D1_GATEWAY_URL`、Gateway credential、
R2 bucket/credential、签名与 finalization secret 都必须指向 preview authority。AI provider 可在明确接受
quota/billing 运营耦合时共享，但不得因此共享 D1、R2 或 authority secret。

仓库中的 `apps/api/deploy/Caddyfile` 记录当前三个 Hono 相关站点。为 `homura-preview.colanns.me` 配置到
`38.76.205.9` 的 DNS 后，Caddy 会自动申请 TLS，并将其转发到：

```text
http://127.0.0.1:8081
```

流式接口需要关闭代理缓冲，并将读写超时设置为至少 600 秒。

## 数据库约束

Preview Worker 和 Hono 在完成专用 D1 纳管前不得获得生产 D1 binding 或 Gateway authority。自动发布流程不得
运行 D1 migration；数据库变更必须单独审核，并确保新旧版本同时兼容。仓库中的
`db:migrate:*:preview` 先执行 `check:preview:environment -- --require-provisioned`，因此当前
`not-provisioned` 状态会安全拒绝本地/远程 preview migration。

## 验证与回滚

工作流会验证：

1. 完整 Vitest 测试通过；
2. preview isolation gate 通过，且 D1、R2、authority secret 与 runtime env 已专用纳管；
3. Hono bundle 可构建并通过生产配置预检；
4. `https://homura-preview.colanns.me/api/health/ready` 返回成功；
5. Preview Hono 的 CORS 预检成功；
6. Cloudflare Preview Worker 发布后 Hono 仍处于 ready 状态。

Hono 新 release 两分钟内未就绪时，`deploy-bundle.sh` 会恢复上一个 release。部署脚本还会在目标目录
获取非阻塞文件锁，避免两个发布同时切换同一 preview 实例。
