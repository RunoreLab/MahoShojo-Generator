# 预览环境自动部署说明

## 发布边界

`preview` 分支的每次 push 都会触发 `.github/workflows/preview-deploy.yml`。合并 PR 到 `preview`
同样会产生 push，因此会自动发布。流水线先运行完整测试并构建 Hono，Hono 公网就绪后才构建和发布
Cloudflare Preview Worker。

生产与预览的运行边界如下：

| 配置 | 生产 | Preview |
| --- | --- | --- |
| Hono 域名 | `homura.colanns.me` | `homura-preview.colanns.me` |
| VPS 目录 | `/opt/mahoshojo-hono` | `/opt/mahoshojo-hono-preview` |
| 容器 | `mahoshojo-hono` | `mahoshojo-hono-preview` |
| 回环端口 | `8080` | `8081` |
| Redis 网络 | `mahoshojo-redis` | `mahoshojo-redis` |
| Redis key 前缀 | 空 | `preview` |
| D1 | `mahoshojo` | 同一个 `mahoshojo` |

## GitHub 首次配置

创建 GitHub Environment `hono-preview`，只允许 `preview` 分支部署，并添加：

- Secret `VPS_SSH_PRIVATE_KEY`：与生产相同的 `mahoshojo` SSH 私钥内容。

现有 `preview` Environment 继续保存 Cloudflare 凭据和构建变量。工作流固定使用
`root@38.76.205.9`，并固定校验仓库当前记录的 ED25519 host key。

## VPS 首次初始化

Preview 复用生产 `.env.hono` 中的 Redis、D1、AI 和签名配置。首次发布前执行：

```bash
install -d -m 755 /opt/mahoshojo-hono-preview/releases
install -m 600 /opt/mahoshojo-hono/.env.hono /opt/mahoshojo-hono-preview/.env.hono
```

不需要创建第二套 Redis。Preview 容器加入现有 `mahoshojo-redis` Docker 网络，工作流传入
`REDIS_KEY_PREFIX=preview`。限流键使用 `mahoshojo:rate-limit:preview:api:*` 和
`mahoshojo:rate-limit:preview:auth:*`；可恢复生成状态使用 `mahoshojo:gen:v1:preview:*`，不会与生产
限流窗口或进行中的生成状态碰撞。

仓库中的 `apps/api/deploy/Caddyfile` 记录当前三个 Hono 相关站点。为 `homura-preview.colanns.me` 配置到
`38.76.205.9` 的 DNS 后，Caddy 会自动申请 TLS，并将其转发到：

```text
http://127.0.0.1:8081
```

流式接口需要关闭代理缓冲，并将读写超时设置为至少 600 秒。

## 数据库约束

Preview Worker 和 Hono 都与生产共用 D1。自动发布流程不得运行 D1 migration；数据库变更必须单独审核，
并确保新旧版本同时兼容。Preview 中的新增、修改和删除均会立即影响生产数据，应用回滚不会回滚数据。

## 验证与回滚

工作流会验证：

1. 完整 Vitest 测试通过；
2. Hono bundle 可构建并通过生产配置预检；
3. `https://homura-preview.colanns.me/health/ready` 返回成功；
4. Preview Hono 的 CORS 预检成功；
5. Cloudflare Preview Worker 发布后 Hono 仍处于 ready 状态。

Hono 新 release 两分钟内未就绪时，`deploy-bundle.sh` 会恢复上一个 release。部署脚本还会在目标目录
获取非阻塞文件锁，避免两个发布同时切换同一 preview 实例。
