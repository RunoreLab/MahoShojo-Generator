# 预览环境自动部署说明

## 发布边界

`preview` 分支的每次 push 都会触发 `.github/workflows/preview-deploy.yml`。合并 PR 到 `preview`
同样会产生 push，因此会自动发布。流水线先运行完整测试并构建 Hono 与 Cloudflare bundle，Hono 公网就绪后才发布
Cloudflare Preview Worker。

生产与预览的运行边界如下：

| 配置 | 生产 | Preview |
| --- | --- | --- |
| Hono 域名 | `homura.colanns.me` | `homura-preview.colanns.me` |
| VPS 目录 | `/opt/mahoshojo-hono` | `/opt/mahoshojo-hono-preview` |
| 容器 | `mahoshojo-hono` | `mahoshojo-hono-preview` |
| 回环端口 | `8080` | `8081` |
| Redis 网络 | `mahoshojo-redis` | `mahoshojo-redis` |
| Redis key 前缀 | 空 | `preview` |
| D1 | `mahoshojo` | 同一个 `mahoshojo` |
| Hono runtime env | production `.env.hono` | production 配置的独立文件副本 |

## GitHub Environment

现有 GitHub Environment `hono-preview` 直接供部署 job 使用，无需增加 `PREVIEW_*` 变量：

- Secret `VPS_SSH_PRIVATE_KEY`；
- Variable `VPS_HOST`；
- Variable `VPS_USER`，当前允许使用 `root`；
- Variable `HONO_DEPLOY_ROOT=/opt/mahoshojo-hono-preview`；
- Variable `HONO_BIND_PORT=8081`；
- Variable `HONO_PUBLIC_ORIGIN=https://homura-preview.colanns.me`。

工作流继续使用仓库已固定的 ED25519 host public key 校验目标 VPS。现有 `preview` Environment 保存
Cloudflare 凭据和 Web 构建变量，两套 GitHub Environment 不要求使用相同的变量命名空间。

## VPS 初始化

Preview 复用 production `.env.hono` 中的 Redis、D1、AI、R2 和签名配置。首次发布前执行：

```bash
install -d -m 755 /opt/mahoshojo-hono-preview/releases
install -m 600 /opt/mahoshojo-hono/.env.hono /opt/mahoshojo-hono-preview/.env.hono
```

Hono CORS 不要求在该副本中重复配置；部署脚本会为 production 与 Preview 统一注入 canonical Web origin
`https://mahoshojo.colanns.me`，并用同一值执行启动前检查和公网 contract probe。

不需要创建第二套 Redis。Preview 容器加入现有 `mahoshojo-redis` Docker 网络，工作流传入
`REDIS_KEY_PREFIX=preview`。限流键使用 `mahoshojo:rate-limit:preview:api:*` 和
`mahoshojo:rate-limit:preview:auth:*`；可恢复生成状态使用 `mahoshojo:gen:v1:preview:*`，不会与 production
限流窗口或进行中的生成状态碰撞。

Preview Worker 在 `apps/web/wrangler.jsonc` 的 `env.preview.d1_databases` 中显式登记 production D1 ID，避免依赖
Wrangler 环境继承。Preview Hono 通过复制后的 runtime env 使用同一个 production D1 Gateway。

仓库中的 `apps/api/deploy/Caddyfile` 记录当前三个 Hono 相关站点。`homura-preview.colanns.me` 转发到：

```text
http://127.0.0.1:8081
```

流式接口需要关闭代理缓冲，并将读写超时设置为至少 600 秒。

## 数据库约束

Preview Worker 和 Hono 都与 production 共用 D1。自动发布流程不运行 D1 migration；数据库变更必须单独审核，
并确保新旧版本同时兼容。Preview 中的新增、修改和删除均会立即影响 production 数据，应用回滚不会回滚数据。

## 验证与回滚

工作流会验证：

1. 完整测试和仓库门禁通过；
2. Hono bundle 可构建并通过 runtime 预检；
3. `https://homura-preview.colanns.me/api/health/ready` 返回成功；
4. Preview Hono 的 CORS contract 成功；
5. Cloudflare Preview Worker 发布后 Hono 仍处于 ready 状态。

Hono 新 release 两分钟内未就绪时，`deploy-bundle.sh` 会恢复上一个 release。部署脚本还会在目标目录
获取非阻塞文件锁，避免两个发布同时切换同一 preview 实例。
