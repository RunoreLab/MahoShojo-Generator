# 角色生成（/name、/details、/canshou）

> 作者：[末伏之夜](https://github.com/notuhao)  
> 更新时间：2026-01-14

本站有三条“生成角色”的入口：它们**目标不同、产物也不同**。选对入口能少踩很多坑。

## 1) 三个入口分别适合谁？

### `/details`：奇妙妖精大调查（推荐作为“主力角色卡”）

- 适合：想认真写一张“能上场、能成长、能复盘”的魔法少女。
- 产物：**标准魔法少女数据卡（问卷生成）**，更完整、更可用于后续玩法。
- 常见用途：竞技场对战、长线历战、成长升华、保存到云端、公开分享等。
- 0.7.0 起：支持切换「流式/非流式」生成（见第 2 节）。

### `/canshou`：危险残兽大调查（生成宿敌/对手）

- 适合：需要“对手/反派/灾厄”类型的角色（残兽）。
- 产物：**标准残兽数据卡（问卷生成）**。
- 常见用途：竞技场对战、情景模式里的固定反派、作为升华素材等。
- 0.7.0 起：支持切换「流式/非流式」生成（见第 2 节）。

### `/name`：魔法少女生成器（基于名字，轻量趣味）

- 适合：想快速玩一下“你是什么魔法少女”，不想填问卷。
- 产物：**简化测试结果**（字段结构与本站“标准数据卡”不同）。

**重要提醒：`/name` 下载的 JSON 默认与大多数功能不兼容**（例如档案馆验证、竞技场上场、升华与排位等）。  
如果你希望把 `/name` 的结果变成可上场的角色卡：请优先使用 `/details` 重新生成；或把 `/name` 的设定要点整理后，转写到“通用角色/魔法少女数据卡”中再使用（见下方第 3 节）。

## 2) 新增：流式 / 非流式切换（0.7.0）

`/details` 与 `/canshou` 的“提交生成”前，都可以选择生成方式：

### 非流式（推荐：想要结构化字段/后续玩法）

- 一次性返回**结构化数据卡**（魔法少女/残兽完整字段）。
- 更适合：保存为“模板”、做成长升华、或希望字段结构更规整的创作流程。

### 流式（推荐：想要写长文/快速迭代）

- 实时输出 Markdown，前端会把正文包装为**通用角色卡（templateId=通用角色）**。
- 更适合：写小传、长线设定、快速迭代口吻/世界观/台词风格。
- 小提醒：流式产物通常不会包含 `signature`，因此会被视为**非原生卡**（详见：`/encyclopedia/native`）。

### 让“通用角色卡”更好用的小技巧

如果你在流式模式里很在意名字/代号的稳定性：

- 让输出靠前位置写明 `代号：...` / `名字：...`（或用 `# 标题` 开头）
- 名字解析失败时，系统会回退到你填写的名字/默认值

## 3) 推荐新手路线（不绕路）

1) 先用 `/details` 生成一张魔法少女（或用 `/canshou` 生成一只残兽）  
2) 下载 JSON 或登录后保存到云端  
3) 去 `/character-manager`（档案馆）完善名称、简介、标签、公开状态  
4) 去 `/arena` 选择参战者与模式，生成战报  

## 4) 如果你只有 `/name` 的结果，怎么“补救”成可用卡？

两种思路，按你愿意投入的成本选：

### 方式 A：重新走正道（推荐）

- 直接去 `/details`，把 `/name` 的花名/外观要素当作灵感写进问卷答案里。  
  这样得到的卡结构更标准，也更适合后续玩法。

### 方式 B：转写为“通用角色”（更省事，但需要你自己整理）

1) 打开 `/character-manager`  
2) 新建/转换为「通用角色」模板  
3) 把 `/name` 的结果（花名、外观、咒语、花语等）整理进 `content`（建议用 Markdown 写成小传）  
4) 保存到云端后再去竞技场使用

## 5) 常见问题

### 为什么“同样是生成”，结果差别这么大？

因为 `/details` 与 `/canshou` 生成的是“数据卡”（后续系统要读写、要计分、要保存、要继承），而 `/name` 更像“趣味测验结果”，并不以系统兼容为目标。

### 生成失败/跳转逮捕页怎么办？

通常是敏感词或内容安全策略拦截导致。建议先备份文本，再用更中性的表达改写。
