# 问卷系统与自定义问卷（问卷编辑器 / 云端问卷库）

> 作者：[末伏之夜](https://github.com/notuhao)  
> 更新时间：2026-02-01

本条目覆盖 v0.7.2 之后的问卷新能力：**自定义问卷、条件显示/跳题、云端问卷库、字数上限与可信 Logo**。如果你想把问卷当成“可维护的创作工具箱”，先从这里开始。

## 1) 新功能速览（v0.7.2）

- **问卷编辑器**：在 `/questionnaire-editor` 可视化创建/调整问卷，并导出 JSON 或保存为云端问卷数据卡。
- **条件显示 / 跳题**：支持按回答结果显示题目或跳转到指定题目/结束问卷。
- **条件可视化配置**：编辑器内可直接配置常用条件（复杂条件仍可用 JSON 扩展）。
- **云端问卷库**：问卷可保存为数据卡（公开/私有），在 `/details` 与 `/canshou` 直接挑选使用。
- **统一字数上限**：原生问卷答案统一上限 **500 字**；超过上限仍可生成，但**不再具备原生性**。
- **Logo 安全校验**：问卷 Logo 仅允许站内路径或可信 HTTPS 外链，不可信链接会被忽略。

---

## 2) 快速上手：从“自定义问卷”到“生成角色”

### A. 新建并保存自定义问卷

1) 打开 `/questionnaire-editor`
2) 选择问卷类型（魔法少女 / 残兽）并填写 **问卷 ID / 标题**
3) 添加题目、选项、灵感提示（可设置条件显示与跳题）
4) 点击 **“保存为云端问卷”**（需要登录），或 **复制 JSON** 本地保存

### B. 在问卷页加载自定义问卷

- `/details` 或 `/canshou` → **问卷设置** →
  - 选择 **预设问卷** / **上传问卷 JSON** / **从云端问卷库选择**
- 若开启 **允许同时回答多份问卷**，系统会按顺序串联出题

## 3) 问卷结构与常用参数（编辑器对应字段）

### 3.1 问卷级字段

- `id`：问卷 ID（用于匹配与引用，建议全局唯一）
- `kind`：问卷类型（`magical-girl` / `canshou`）
- `title`：问卷标题
- `description`：问卷描述（可选）
- `logoUrl`：Logo 图片（仅允许站内路径或可信 HTTPS 外链）
- `version`：版本号（可选，用于标记迭代）
- `nativeAllowed`：是否具备原生许可（自建问卷默认非原生）

### 3.2 题目级字段

- `id`：题目 ID（建议不重复）
- `question`：题干
- `type`：题型（`text` / `select`）
- `placeholder`：输入框提示
- `helperText`：补充说明
- `suggestions`：灵感按钮（多条）
- `options`：推荐选项（`label|value|disabled` 格式或纯文本）
- `allowCustom`：选择题是否允许自填
- `optionsFrom` / `suggestionsFrom`：引用其他题目的选项/灵感
- `maxLength`：题目字数上限（会与全局 500 上限取更小值）
- `required`：是否必填
- `displayIf`：条件显示（满足条件才出现）
- `jump`：跳题规则（满足条件直接跳到目标题）

> 编辑器支持常用字段的可视化填写；更复杂的条件/跳题规则，可在“额外字段 JSON”里扩展。

## 4) 条件显示 / 跳题的写法与建议

### 4.1 基本条件（编辑器支持）

- `equals` / `notEquals`：等于 / 不等于
- `includes` / `notIncludes`：包含 / 不包含
- `empty` / `notEmpty`：为空 / 不为空

**编辑器中多个条件值用 `|` 分隔**，会按“任意匹配”理解。

### 4.2 复杂条件（JSON 方式）

支持 `any` / `all` / `not` 组合，例如：

```json
{
  "displayIf": {
    "all": [
      { "questionId": "MG-03", "operator": "includes", "value": "誓约" },
      { "questionId": "MG-04", "operator": "notEmpty" }
    ]
  }
}
```

### 4.3 跳题规则（示例）

```json
{
  "jump": [
    {
      "when": { "questionId": "MG-05", "operator": "equals", "value": "毕业" },
      "to": { "questionId": "MG-10" }
    },
    {
      "when": { "questionId": "MG-06", "operator": "empty" },
      "toEnd": true
    }
  ]
}
```

**建议：**
- 跳题只在“当前题完成后”触发；复杂分支建议用多条规则串联。
- 多问卷模式下，若题目 ID 可能重复，推荐使用 `questionnaireId + questionId` 组合引用。

## 5) 云端问卷库与问卷数据卡

- 问卷保存到云端后，会以 **“问卷数据卡”** 形式进入档案馆
- 在 `/details`、`/canshou` 的“问卷设置”中可直接选择 **公开/私有** 问卷
- 需要登录才能查看私有问卷；公开问卷可被其他用户搜索并使用

**小提醒：**
- 云端容量有限；提示“已达上限”时需要先清理旧卡或扩容
- 自建问卷默认非原生，生成结果会标记为非原生卡

---

## 6) 字数上限与原生性

- **原生统一上限：500 字**
- 题目设置 `maxLength` 时，会与 500 字上限取**更小值**
- 超过上限不会阻止生成，但会**取消原生签名**（卡片变为非原生）

**建议：**用“关键事件 + 具体细节 + 情绪动机”写到位，不必堆字数。

## 7) 问卷创作进阶（做出更好用的问卷）

### 7.1 用“模块化”思路设计

- **主线问卷**：核心身份、动机、关系、能力
- **分支问卷**：阵营/势力/特殊经历
- 用多问卷串联，把“主线稳定 + 分支可选”变成常态

### 7.2 把“过长的必答题”改成分支题

- 先用一题判断是否进入某个世界线
- 只有在选中时才显示后续细节题

### 7.3 选项要“可替换”

- 选项用于**引导风格**，不是锁死答案
- 允许自填，能降低“被模板束缚”的感觉

### 7.4 世界观建议（重要）

- **尽量避免现实世界的国家、政治与争端**
- 如需借鉴现实概念，建议替换为 **魔法国度 / 调查院 / 宝石权杖** 等世界观内称呼

## 8) 错误排查与 FAQ

### Q1：提示“加载问卷失败 / 预设问卷加载失败”？
- 多数是网络波动或缓存异常；刷新页面或稍后重试
- 仍失败请看：`/encyclopedia/network-errors`

### Q2：提示“问卷 JSON 无法识别 / 解析失败”？
- 检查是否包含 `id / kind / title / questions` 等必填字段
- `questions` 必须是数组，每一题要有 `id` 与 `question`

### Q3：提示“当前没有可作答题目”？
- 常见原因：**条件显示把全部题隐藏**
- 逐条检查 `displayIf` 里的 `questionId` 与条件值是否匹配

### Q4：跳题不生效？
- 需要保证 `jump` 中的 **条件题目** 与 **目标题目** 都存在
- 若设置了 `toEnd`，将直接结束问卷

### Q5：选项引用为空？
- `optionsFrom` / `suggestionsFrom` 引用的题目没有选项/灵感
- 多问卷时题目 ID 重名，导致引用失败

### Q6：为什么生成后不是原生卡？
- 自建问卷默认非原生
- 或者已有答案超过 500 字上限（或题目上限）

### Q7：Logo 不显示？
- 不可信外链会被过滤；请改用站内路径或可信 HTTPS 图片
- 推荐使用编辑器提供的预设 Logo
