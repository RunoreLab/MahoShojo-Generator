# 创作工房（/creator）

> 作者：[末伏之夜](https://github.com/notuhao)  
> 更新时间：2026-04-03

`/creator` 是一个“组合式创作工作台”：它把**问卷回答**、**自由补充说明**与**规则车卡**放到同一个页面里，让你一次性组织素材，再生成更适合保存、继续扩写和后续联动的数据卡。

它不是单纯替代 `/details`、`/canshou` 或 `/free`，而是介于“标准问卷生成”和“完全自由提示词生成”之间的中间层。  
如果你想把多份问卷、额外写作要求和角色参数一起带进结果里，优先看这里。

## 1) 什么时候该用 `/creator`？

- 你不想只走一份固定问卷，而是想**拼接多份问卷**来组织角色设定
- 你想在问卷之外，再补一段**自由说明**，锁定风格、口吻、禁区或剧情目标
- 你想先按一套规则做**车卡/配点**，让角色带着更明确的参数再进入后续故事
- 你想直接产出更适合长文本创作的**通用角色卡 / 通用情景卡**

一句话概括：

- `/details` / `/canshou` 更像“单一路线的标准生成器”
- `/free` 更像“纯提示词驱动的自由生成器”
- `/creator` 更像“把多种输入拼起来的创作工作台”

## 2) 这个页面实际会吃进去哪些输入？

### A. 问卷回答

`/creator` 可以加载问卷，并把答案作为角色/情景创作的基础素材。你可以使用：

- 预设问卷
- 上传的问卷 JSON
- 云端问卷库里的问卷

如果你愿意，还可以把多份问卷叠加使用，让“核心设定”“补充设定”“世界观 lore”分层进入同一次创作。

### B. 自由补充说明

这是给创作者留的“额外约束区”。常见用法：

- 指定文风、叙述角度、语气
- 写“必须保留 / 必须避免”的设定
- 补充问卷里没覆盖到的背景、关系或桥段
- 告诉模型这次更想写成档案体、报告体、角色小传还是舞台设定

### C. 规则车卡

这是 `/creator` 和普通问卷页最大的区别之一。

页面里提供多套规则预设（例如魔法少女竞技场 TRPG、DND 5e、CoC 7e 的轻量车卡），你可以在这里先完成：

- 选择主规则
- 配点 / 选职业 / 选能力倾向
- 查看派生摘要
- 检查预算、缺项与必填块

它的作用不是把本站变成一个严格的数值战棋，而是把这些配点结果沉淀成**角色参数**，让角色后续进入卡面、档案馆和战报时都能继续带着这些信息。

## 3) 截至 2026-04-03，`/creator` 页面当前稳定接通了什么？

这是最容易混淆的地方，所以单独写清：

### 已稳定接通的输出

- **非流式**：`魔法少女（结构化）`
- **流式**：`通用角色卡（Markdown）`
- **流式**：`通用情景卡（Markdown）`

### 页面上能看到、但当前仍在分阶段接线的方向

- `残兽（结构化）`
- `情景（结构化）`

因此，如果你现在的目标是：

- 想生成**标准残兽卡**：当前仍优先使用 `/canshou`
- 想生成**结构化情景卡**：当前仍优先使用 `/scenario`

不要把页面上“能看到模板卡位”和“当前页面已经完整接通该模板”混为一谈。

## 4) 规则车卡和“角色参数”到底是什么关系？

这部分是 `/creator` 最关键的联动逻辑。

### 规则车卡不会直接变成“硬结算引擎”

它不会像纯规则跑团工具那样，单靠数值机械结算整场战斗。本站的战报仍然是 AI 叙事生成。

### 但规则结果会沉淀为卡上的“角色参数”

当你用 `/creator` 生成角色，并带上规则车卡结果后，这些规则结果会以“角色参数”的形式保存在角色卡里。

你之后在卡面或详情区里，可能会看到：

- 规则名
- 属性 / 配点摘要
- 派生值
- 初始 / 当前参数视图（取决于卡里保存了哪些来源）

### 这些“角色参数”会继续参与战报故事生成

这是已经接通的现有行为，不是未来计划。

当角色卡被拿去 `/arena` 或连续战报使用时，系统会把这部分规则结果作为**角色上下文**继续带进提示词里，并以“角色参数”的名义参与故事生成。

也就是说：

- 规则车卡得到的参数，不只是在 `/creator` 页面里看看
- 它会继续影响后续战报对这个角色的理解与描写
- 连续战报在续写、分支、重写章节时，也会继续承接这部分角色参数

同时，系统不会把原始的配点过程、原始 `creationInputs` 无差别原样暴露给后续生成链路；真正继续参与后续故事的，是整理后的“角色参数”快照。

## 5) 推荐使用流程

如果你是第一次用 `/creator`，建议按这个顺序来：

1. 先明确这次要的是“结构化魔法少女”，还是“通用角色 / 通用情景”
2. 选择 1 份主问卷；如果需要，再叠加补充问卷或 lore 问卷
3. 在“自由补充说明”里写本次最重要的风格要求与禁区
4. 如果你需要更明确的角色轮廓，再补规则车卡
5. 生成结果后，下载 JSON / 保存到云端
6. 去 `/character-manager` 整理卡片信息、公开状态、标签等
7. 去 `/arena` 让这张卡真正上场；如果想写长线，就继续使用连续战报

## 6) `/creator` 和其它入口怎么分工？

### 和 `/details` / `/canshou` 的区别

- `/details` / `/canshou`：更像“标准问卷 -> 标准结构化角色卡”
- `/creator`：更像“问卷 + 自由说明 + 规则车卡 -> 组合式创作结果”

如果你只是想快速得到一张标准问卷角色卡，还是优先 `/details` / `/canshou`。  
如果你想自己拼工作流，再加参数与额外写作要求，才更适合 `/creator`。

### 和 `/free` 的区别

- `/free`：更强调“你自己写提示词”
- `/creator`：更强调“把问卷与规则输入组织起来”

如果你手上已经有成熟提示词，不需要问卷和规则卡，`/free` 更直接。  
如果你想让创作输入更可维护、更分层，`/creator` 更合适。

### 和 `/scenario` 的区别

- `/scenario`：专门面向情景卡生成，尤其适合结构化情景
- `/creator`：目前更适合角色方向，以及流式的通用情景创作

## 7) 常见问题

### 为什么页面里能看到某些模板，但实际生成时提示没接通？

因为 `/creator` 现在还是分阶段接线。  
截至 `2026-04-03`，页面稳定接通的是：

- 非流式结构化魔法少女
- 流式通用角色卡
- 流式通用情景卡

其余模板卡位仍属于后续接线范围。

### 规则车卡会不会直接决定胜负？

不会。它更像“给角色补一套可读的参数骨架”，帮助后续战报把角色写得更稳定、更像同一个人。

### 角色参数会不会真的进入战报？

会。创作页生成出来并保存在卡里的角色参数，会进入竞技场与连续战报的故事生成上下文。

### 角色参数算不算“用户引导”？

不完全是一回事。  
它更接近“角色卡自带的信息层”，而不是临时写给这一局的额外引导词。具体差异可再看：`/encyclopedia/guidance`
