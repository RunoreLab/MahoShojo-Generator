# 连续战报会话（/arena）

> 作者：[末伏之夜](https://github.com/notuhao)  
> 更新时间：2026-03-12

连续战报会话是 `v0.8.1` 起加入竞技场的新模式。它不是把竞技场改成聊天，而是让你把“一次性战报”升级成“**按章节推进的长线战报**”。

`2026-03-12` 的补充更新，又为它补上了 **显式章节规划**：你现在可以在创建新会话前决定“这条故事准备写几章”，也可以让主情景直接提供建议值或固定值。

如果你想让同一批角色持续打下去、写赛后余波、做不同路线分支，这个功能比反复手动重新生成更合适。

## 它和普通竞技场、魔法茶会有什么区别？

### 和普通竞技场的区别

- 普通竞技场更像“一次请求 -> 一篇完整战报”
- 连续战报会话会把每一章保存成一条章节链，并允许继续往后写

### 和魔法茶会的区别

- 连续战报会话仍然属于 **竞技场体系**：输出还是战报，仍然围绕胜负、角色状态变化和战报卡片展开
- 魔法茶会更像 **自由对话/长期剧情容器**，不等价于竞技场战报

简化理解：

- 想写“竞技场的下一章 / 平行结局 / 赛后续篇”时，用连续战报
- 想做自由聊天、长期 RP、视觉小说式互动时，用 `/magic-tea-party`

## 快速上手

1. 先在 `/arena` 正常配置角色、模式、情景、问卷、读写设置与引导词
2. 在战报结果区下方找到 **连续战报会话** 面板
3. 先决定 **新会话章节规划**（自动 / 不限制 / 自定义）
4. 点击 **新建连续战报** 生成首章
5. 首章完成后按需使用：
   - **继续续写**：在当前结尾后继续写下一章
   - **创建分支**：复制当前故事链，再走另一条路线
   - **重写最后一章**：保留前文事实，只重做最后一章
6. 需要整理全文时，可导出整条会话的 Markdown

## 新建会话章节规划怎么用？

连续战报面板里的“新会话章节规划”只影响**下一次新建会话**，不会修改普通竞技场设置，也不会回写已经存在的会话。

你会看到 3 种模式：

- **自动**：优先继承当前主情景提供的章节规划；如果主情景没有提供，则等同于“不限制”
- **不限制**：按开放式会话运行，不预设总章节数，由你手动决定何时停止
- **自定义**：手动填写总章节数，当前范围是 `1-20` 章

达到章节上限后：

- **继续续写** 会被禁用
- **创建分支** 会被禁用
- **重写最后一章** 仍然可用

## 情景卡如何参与章节规划？

如果你在 **情景模式** 下创建连续战报，当前主情景可以提供 `_battle_story` 章节规划扩展。

情景卡目前支持两种口径：

- **建议值（`suggested`）**：面板默认采用情景卡给出的章节数，但用户仍可切成“不限制”或别的自定义数值
- **固定值（`fixed`）**：创建会话时强制继承情景卡章节数，用户不可改

这套扩展同时支持：

- 结构化情景卡
- 通用情景卡（Markdown）

如果你是创作者，可在 `/character-manager` 里编辑 `_battle_story`；这部分字段不参与原生签名，不会因为调整章节规划而直接丢失原生性。

## 会话里到底保存了什么？

会话创建时，会快照保存这一批基础信息：

- 参战角色与队伍
- 当前模式、语言、故事长度
- 主情景 / 辅助情景
- 已选问卷与 lore 注入
- 历战记录 / 当前状态 / 叙事历史的读写设置

之后每生成一章，系统还会维护：

- 最新章节链
- 当前会话的章节规划（如果有）
- 当前 working combatants（用于续写时承接角色状态）
- 会话摘要（章节变多后会在后台自动刷新）

这意味着：

- 角色的连续状态不会只靠“上一章正文”硬猜
- 长篇续写不需要每次都把全部旧章节原文重新塞回模型

## 四个核心操作怎么理解？

### 新建连续战报

从当前竞技场配置直接开始写第 1 章。

适合：

- 你已经配好了阵容与舞台
- 你想把这组配置变成一条可持续推进的故事线

### 继续续写

以当前会话最后一章为结尾，继续写下一章。

适合：

- 战斗还没打完，想继续推主线
- 想写“战后余波”“第二回合”“次日后续”

### 创建分支

复制当前已存在的章节链，然后从当前结尾处另开一条路线。

适合：

- 比较两种不同走向
- 不想破坏原本结局，但想尝试另一版发展

### 重写最后一章

只允许重写当前会话的最后一章，不会直接改更早章节。

这样设计是为了避免中间章节被改坏后，整条后续状态链一起失真。

如果你想改更早章节，建议做法是：

1. 先把当前结尾做成一个分支
2. 在分支上重新推进后续

## 摘要与上下文是怎么工作的？

连续战报不是简单把“所有历史全文”无脑回放给模型。

续写时，系统会综合：

- 会话创建时的基础快照
- 章节规划层（如果当前会话设置了总章节数）
- 当前 working combatants
- 最近若干章
- 后台维护的会话摘要
- 你当前页面里填写的引导词

这样做的目的，是尽量在长篇续写里同时兼顾：

- 连贯性
- 成本控制
- 稳定性

章节规划存在时，模型还能额外收到：

- 当前第几章 / 共几章
- 本章定位（开篇章 / 中段推进章 / 终局前章 / 终章）
- 剩余章节数

这会直接影响写法：

- **非终章**：更强调继续推进主线，不要提前把整条故事一次写完
- **终章**：更强调主线收束、角色余波与结局落点，不再强行留“下章继续”的空钩子

## 冷却、限流与刷新节奏

连续战报仍然遵守生成冷却：

- 使用系统公共 Key 时，正文生成默认冷却更长
- 使用自备 Key 时，冷却更短
- 同一会话不允许并发生成

另外，会话摘要也有单独的后台刷新节奏，不会每写一章都强制调用一次摘要模型。

如果你看到“请求过于频繁”，说明当前会话或当前 IP 触发了软限流，按提示等待后再试即可。

## 当前版本的限制

- **仅本地保存**：会话保存在当前浏览器 IndexedDB，清缓存、换浏览器、换设备都不会自动带过去
- **章节规划不追溯旧会话**：它只在“新建连续战报”时写入，不能批量回改旧故事链
- **章节上限范围为 1-20 章**：超出范围的自定义值不会生效
- **仅支持重写最后一章**：更早章节请通过“创建分支”处理
- **当前仍是竞技场战报，不是自由聊天**：如果你的目标是开放式互动剧情，优先使用 `/magic-tea-party`
