# 术语表（社区提案）

> 整理：末伏之夜  
> 来源：玩家社区提案（官方QQ群征集），2025-12-10 ～ 2025-12-14 
> 说明：本页包含社群语境下的“梗/术语”，不等同于官方设定。

## 核心运行态数据

### 历战记录（`arena_history.impact`）

故事生成结束后写入到每个角色卡的历战字段里的一段字符串，描述本次事件对角色的影响。通过明确指令可以控制它的内容、格式与数据结构；指令可能来自情景卡、随机判定、故事方向引导（userGuidance）等。

### 状态栏数据（`current_state.summary`）

每次生成结束后写入到状态栏里的“事件后角色状态综述”。它通常更短，适合承载“当前状态快照”与少量关键数据。

### 优先级（经典模式 1/2 号位）

社区经验认为：经典模式下，1 号位与 2 号位可能存在“叙事优先级差异”，从而在长期统计上出现轻微偏置（也有人认为代码杀卡会反过来）。 

## 卡片类型/社群用语

### 自设

以用户自己为原型制作的角色卡：可能是自我投射、自我认知，或“理想中的自己”。

### OC

自己原创的角色（Original Character）。与“自设”不同，OC 不一定以作者本人为原型。

### 日常卡

以日常叙事与人物性格为主，问卷回答（userAnswers）往往含量高、人物更“像活人”。社区经验是：日常卡（尤其原生）未必追求顶级强度，更偏“好玩/贴贴/剧情”。

### 历战王

历战数据非常多的角色卡，往往具有一定强度或叙事优势，但也通常更大、更耗 token。

## 社群梗/案例

### 八角笼

一种偏肉搏对战的情景/比赛范式：通过引导把参战者限制在较接近的强度区间，强调“更公平的拳脚比拼”。

### 牢九门

指一些在当前环境里较难形成“稳定强度体系”的方向（例如幻术、召唤、射击等）。该分类仍在讨论与归纳中。

### 残兽歧视 / 残兽骑士

社区对一种现象的描述：由于模型与叙事倾向，“残兽”可能更容易被压制，导致胜率偏低或日常表现不佳。  
该话题仍在讨论中，建议以具体战报与样本为准。

### K 台

指 Kouri（项目的 AI 能力供应商/平台）。具体接入以站内可用配置为准。

## 多人模式术语（v0.9.0+）

### 房主 / 成员

多人房间里的两种角色。房主拥有房间最终控制权：发布配置、审阅提案、发起/停止生成、管理成员；成员可以围观战报、编辑自己的工作副本并向房主提交提案。

### 提案

成员把自己对竞技场配置的修改（如新增角色、修改引导、切换模式）打包发送给房主审阅的机制。房主可以逐项接受或拒绝；**接受后修改才会进入房间配置**，未接受的提案不会影响本局生成。

### 房间配置（权威配置）

房间里公开给所有成员、并作为下一次生成共同输入的那份配置。房主发布的内容和被接受的提案都会更新这份配置；成员本地编辑的只是各自的副本。

### 配置版本

房间配置每更新一次，版本号就会递增。提案基于某个版本提交；如果房间配置已经走远，旧提案会提示过期或冲突，需要重新同步。

### 包含协作变更

房间历史战报里的标注，表示这一局的配置里含有被接受的成员提案带来的影响，方便区分“房主自己的普通局”和“多人协作局”。

## 本地库与 Web 战报术语（v0.10.0+）

### 本地库

保存在**用户自己浏览器**里的数据集合（数据卡 + Web 包），需要独立 IndexedDB `mahoshojo-local-library`。不需要登录、不上传、不随账号跨设备同步；清除本站数据会一并删除。相关取舍见 `/encyclopedia/local-library`。

### 仅本次会话

Web 包导入后**默认不落盘**时的状态：这次页面还可选，刷新页面就需要重新导入。勾选「导入时保存到本地库」才会长期保留。

### Web 战报

竞技场的一种战报格式（`Web（实验性）`）：AI 直接生成一份完整 HTML 页面而非 Markdown 文章，在浏览器隔离框架中展示，可切换普通显示 / Web 显示与沉浸显示。见 `/encyclopedia/web-report`。

### Web 包 / 生成目标

Web 包是「引擎 + 素材」的 ZIP（根目录 `web-package.json`），**AI 只生成包声明的那一个目标文件**，引擎留在包里不被替换。内置预设目前是「竞技场新闻」。

### 受限模式 / 可信同源模式

Web 包的两种运行权限。受限模式（默认）允许包内脚本、样式、模块与素材工作，但不给主站 DOM 与浏览器存储的同源权限；可信同源模式需要用户显式授权，接近本站自身脚本权限，风险扩大需重新确认，可随时撤销。

### 能力预检

对 Web 包做的静态扫描，报告它**真实具备**的能力、外部目的地与不确定性。「未检测到已知能力」不等于安全。
