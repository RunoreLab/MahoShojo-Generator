# 技术值（Tech Index）

> 作者：[末伏之夜](https://github.com/notuhao)  
> 更新时间：2026-02-05

技术值不是「强度值」，而是一个风险/风格提示：

- 该卡可能包含大量规则、提示词工程、结构化约束、元叙事、代码/伪代码等内容
- 该卡也可能包含更“竞技化”的战斗机制密度（属性/技能/状态/判定等）
- 这类内容可能更容易影响裁判，从而“看起来更强”，但这不是严格的因果关系（技术值≠强度）

## 稳定性口径

同一张卡在不同页面/不同调用链路下，技术值计算结果应一致。为此会做去噪与规范化：

- 只以卡本体 JSON（`data_cards.data` 或预设 JSON）为输入
- 忽略运行态上下文（如历战、裁判事件、当前状态等）
- 限制遍历深度、节点数与最大字符数，保证 Edge Runtime 友好

## 分数范围与校准

- 技术值最终稳定落在 `[0,100]`（不会越界）
- 为避免 `0~9（<10）` 区间长期空置、并缓解部分卡“顶格到 100”导致的区分度下降，技术值在最终落点会做一次整体下移校准（默认 `-10`，低于 0 则钳制到 0）

## 落库与过期重算

技术值会写入 `data_card_metrics`。当卡片更新时，会触发重算并异步回写。

## 和“代码杀”的关系

技术值高并不等于“代码杀”，但两者常有交集：  
当一张卡含有大量规则、提示词工程、裁判协议等内容时，技术值通常会上升，同时也更可能被归类为风险提示。
