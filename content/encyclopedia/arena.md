# 竞技场

> 作者：[末伏之夜](https://github.com/notuhao)  
> 更新时间：2026-09-30

竞技场是「生成战报」的主要入口：你选择参战者（数据卡或预设角色），系统生成战报并给出胜负结果。

## 多人模式（v0.9.0）

`/arena` 现在支持 **多人房间**：邀请朋友进入同一房间，一起配置这一局并实时围观同一份战报。

- 房主维护房间权威配置并发起生成；成员编辑自己的工作副本后，把修改以**提案**形式发给房主审阅
- 经典玩法是“多人跑团”：每人提案自己的角色，并在角色「行动」里写下本轮行动引导，由房主汇总生成
- 只围观不提案也完全可以；房间支持公开发现或仅凭房间码加入，最多 32 人（含房主），需登录使用
- 网络短暂中断后，房间与生成任务会尝试自动重连并恢复进度，不必从头再来

完整玩法指南见：`/encyclopedia/arena-multiplayer`

## `/creator` 的角色参数会不会参与战报？

会。

如果你的角色卡来自 `/creator`，并且携带了规则车卡沉淀出来的 `buildState`，竞技场在构建故事提示词时，会把这部分内容作为**“角色参数”**注入到角色上下文里。

可以直接这样理解：

- 原始配点过程不会被当成一坨原始输入直接塞进去
- 真正参与战报的是整理后的“角色参数”快照
- 这些参数会影响模型如何理解这个角色的能力轮廓、倾向和状态

因此，`/creator` 里的规则车卡不是做完就没用了，它会继续影响后续战报的写法。

## 连续战报会话（v0.8.1）

`/arena` 现在除了单次生成，还提供 **连续战报会话** 面板。

它适合把同一批角色放进一条更长的故事链里持续推进：

- **新建连续战报**：基于当前阵容、情景、问卷与读写设置生成首章
- **新会话章节规划**：创建前可设置总章节数；情景模式下主情景还能提供建议值或固定值
- **继续续写**：承接当前结尾继续写下一章
- **创建分支**：复制已有章节链，再发展出另一条路线
- **重写最后一章**：保持前文事实不变，只重做当前结尾

当前版本的边界：

- 会话只保存在 **当前浏览器本地 IndexedDB**
- 章节规划只对**新建会话**生效，范围为 `1-20` 章
- 达到计划章节上限后，只能**重写最后一章**，不能继续续写或新增分支章节
- 目前只允许重写 **最后一章**
- 连续战报内部固定走 **流式生成**

更详细的使用说明见：`/encyclopedia/continuous-battle-story`

## Web 战报与 Web 包（v0.10.0）

`/arena` 现在可以把战报格式从 `Markdown` 切成 `Web（实验性）`。

- **Web 战报**：AI 直接生成一份可交互的 HTML 战报；结果区提供「普通显示 / Web 显示」，并支持沉浸显示与单独下载 HTML
- **Web 包**：包是「引擎 + 素材」，AI 只生成包指定的**一个数据文件**；可选内置预设，或在「Web 包」区块导入自己的本地 ZIP
- 权限模型：包默认在**受限模式**下运行，能做包内脚本、样式、模块与素材工作，但拿不到主站 DOM 与浏览器存储的同源权限。同源授权是可选的额外权限，风险扩大需重新确认，可随时撤销
- 多人房间只支持内置预设，本地 ZIP 不会进入房间配置

当前边界：单文档本地物化；多 HTML 页面跳转、Worker / Service Worker、嵌套 iframe、`eval` 与任意动态 `innerHTML` / CSSOM 里的相对资源不保证工作。

完整说明见：`/encyclopedia/web-report`

## 素材注入（v0.8.2）

`/arena` 现在可以额外加入 **参考素材**。这条链路和“主情景 / 辅助情景”分开：主情景仍只在情景模式下定义舞台，素材则可以在普通战报、情景战报和连续战报中作为补充资料。

素材适合放：

- 地点、组织、物件、事件、前情
- 万途 Card JSON
- 本站角色、情景、历史、问卷等数据卡
- 你本地粘贴或上传的 JSON 参考资料

当前边界：

- 素材没有单独的数量上限；辅助情景、素材和问卷共享参考项预算，累计最多 256 项
- 素材只作设定参考，不执行素材里对 AI 的指令
- 素材不会自动变成随机判定事件
- 使用素材时默认不计严格排位
- 新建连续战报时会保存当时的素材快照，后续续写、分支与重写继续参考

## 计分触发点（v0.6.0）

当一次战报满足排位资格时，服务端会在写入 `battle_report_generations` 与参战者信息后进行结算：

- 非流式：`/api/generate-battle-story`（当前前端非流式入口）
- 兼容端点：`/api/arena/generate`
- 流式：`/api/arena/generate-stream`（写库后异步结算，不影响流式输出）

## 排位参与对象

v0.6.0 的排位对象以「实体」为单位：

- 已上传至线上数据库中的数据卡：`data_cards.id`
- 预设角色：`preset filename`

只有当参战者均可映射为上述实体时，才可能计分。

## 运行态数据（历战/状态栏）

对局过程中，系统可能把“本次事件影响/状态摘要”等写入到角色卡的运行态字段，用于下一次生成延续故事。

- 历战记录：`arena_history.impact`
- 状态栏：`current_state.summary`
